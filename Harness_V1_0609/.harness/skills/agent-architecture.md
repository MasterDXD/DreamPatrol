# AI Agent 工程化架构 (Agent Architecture Orchestrator)

## 概述

统一协调AI Agent工程化架构的六大设计原则：

1. **渐进式披露** — 按任务优先级分层暴露上下文，避免信息过载
2. **架构约束** — Prompt柔性建议 + 硬编码刚性约束 + Linter校验
3. **自验证循环** — 类TDD中间件钩子，执行前校验+执行后验证
4. **上下文隔离** — 多Agent记忆独立，禁止跨Agent记忆共享
5. **熵治理** — 自维护文档降噪，维持知识库简洁有序
6. **可拆卸性** — 模块化设计，能力按需插拔

## 使用方式

在对话中提及以下关键词触发：
- `agent-architecture` / `工程化架构` — 启动架构协调
- `渐进式披露` — 上下文分层管理
- `硬编码约束` / `Prompt驱动` — 约束体系
- `自验证` — 验证循环
- `熵治理` — 知识库清理

## 目标

统一协调AI Agent工程化架构的六大设计原则，确保多Agent系统以工程化、可维护的方式运行。通过渐进式披露、架构约束、自验证循环、上下文隔离、熵治理和可拆卸性六大机制的协调配合，实现Agent系统从原型到生产级的工程化落地。

## 步骤

1. 识别当前任务涉及的架构维度（上下文管理、约束执行、验证循环、隔离需求、熵治理、模块拆卸）
2. 根据任务阶段和角色，规划上下文披露策略，避免信息过载
3. 检查三层约束防线（Prompt建议层、代码约束层、运行时校验层）是否覆盖当前操作
4. 在关键决策点和阶段转换处插入验证门控，确保中间产物质量
5. 确认Agent间上下文隔离边界，必要时通过审批门控允许受控信息传递
6. 评估知识库信息价值，对低价值信息进行压缩或丢弃
7. 模块变更后执行完整性验证，确认无功能退化

## 验收

- 六大架构原则（渐进式披露、架构约束、自验证循环、上下文隔离、熵治理、可拆卸性）在任务执行中均有体现
- 上下文按阶段按角色分层暴露，无信息过载现象
- 关键节点有验证门控且通过质量检查
- Agent间上下文隔离边界明确，跨Agent信息传递经过审批
- 知识库信息价值密度不下降，低价值内容已被清理或压缩
- 模块变更后系统功能无退化
