# 安全与权限规则

## 权限决策流程
1. 工具调用前，检查Agent是否有该工具的使用权限
2. 敏感操作（如文件删除、系统命令、网络请求）需要用户确认
3. 记录所有工具调用和操作日志
4. 定期审计权限使用情况

## 敏感信息处理
- 所有敏感信息（如API密钥、密码、Token）必须加密存储
- 禁止在日志和输出中泄露敏感信息
- 敏感信息只能在需要时临时加载到上下文
- 敏感信息使用后立即从上下文中清除
- 配置文件中的敏感信息使用环境变量引用

## Hook干预机制
- 在关键节点插入Hook进行检查和干预
- Hook可以检查和修改Agent的行为
- 发现违规操作时，自动拦截并告警

### Hook节点
1. **工具调用前**：检查权限、参数合法性
2. **文件写入前**：检查路径合法性、内容安全性
3. **任务提交前**：检查交付物完整性、质量标准
4. **模型调用前**：检查Token预算、内容安全

### Hook执行规则
```json
{
  "hook_name": "pre-tool-call",
  "trigger": "before_tool_call",
  "checks": [
    "permission_check",
    "parameter_validation",
    "rate_limit_check"
  ],
  "action_on_fail": "block_and_alert"
}
```

## 文件操作安全
- 禁止操作系统目录和关键配置文件
- 禁止修改.harness目录下的系统文件（除sessions和checkpoints）
- 文件写入前必须确认路径在项目范围内
- 批量文件操作必须有回滚机制

## 网络安全
- 禁止访问内网地址和私有IP
- 外部API调用必须使用HTTPS
- 限制单次请求的数据量
- 网络请求超时设置（默认30秒）

## 并发安全
- 避免多个Agent同时修改同一个文件
- 使用乐观锁处理并发冲突
- 关键操作加锁，确保原子性
- 文件修改前检查最新版本

## 边界处理
- 处理空输入、非法输入、异常输出
- 处理网络中断、服务不可用等外部异常
- 处理用户中断、取消操作等情况
- 所有异常必须有明确的错误信息和恢复建议
