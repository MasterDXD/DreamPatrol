# 工具详解 — 工具层模块群

> 路径：`src/utils/`
> 版本：2.73.4
> 模块数量：30

工具层是整个 Harness 框架的基础设施层，为上层运行时引擎、权限执行器、TDD门禁等子系统提供通用工具函数、数据结构、安全防护和配置管理能力。所有模块均采用 CommonJS 规范，无外部依赖。

## constants.js — 全局常量定义

### 职责概述

定义六阶段流程常量、阶段转换规则、阶段Skill映射、YAML Frontmatter解析器、Token估算、危险键/命令模式、时间常量、长度限制、设计模式检测规则等全局共享常量与工具函数。是整个框架的"单一事实来源"。

### 核心API签名

| 导出 | 类型 | 说明 |
|------|------|------|
| `PHASES` | `string[]` | 六阶段流程序列 |
| `PHASE_TRANSITIONS` | `Object<string, string[]>` | 阶段转换规则（源阶段→允许目标列表） |
| `PHASE_TRANSITIONS_SET` | `Object<string, Set>` | 阶段转换规则的Set版本 |
| `PHASE_INDEX` | `Object<string, number>` | 阶段名→序号映射 |
| `PHASE_SKILLS` | `Object<string, string[]>` | 每阶段所需Skill列表 |
| `SESSION_ID_PATTERN` | `RegExp` | 会话ID格式校验正则 |
| `AGENT_ID_PATTERN` | `RegExp` | Agent ID格式校验正则 |
| `validateAgentId(agentId)` | `function → {valid, reason}` | 校验Agent ID合法性 |
| `validateProjectRoot(projectRoot, className?, ErrorClass?)` | `function → void` | 校验项目根路径 |
| `isNonEmptyString(value)` | `function → boolean` | 判断非空字符串 |
| `validateString(value, fieldName?)` | `function → {valid, reason}` | 校验字符串 |
| `validateNonEmptyString(value, fieldName?)` | `function → {valid, reason}` | 校验非空字符串 |
| `validateNumber(value, fieldName?, opts?)` | `function → {valid, reason}` | 校验数字（支持min/max/integer） |
| `validateObject(value, fieldName?)` | `function → {valid, reason}` | 校验对象 |
| `validateFunction(value, fieldName?)` | `function → {valid, reason}` | 校验函数 |
| `validateEnum(value, allowedValues, fieldName?)` | `function → {valid, reason}` | 校验枚举值 |
| `sanitizeString(value)` | `function → string` | 移除控制字符 |
| `estimateTokens(text)` | `function → number` | Token估算（英文/4，中文/1.5） |
| `parseFrontmatter(content)` | `function → Object\|null` | 解析Markdown YAML Frontmatter |

| `DANGEROUS_KEYS` | `Set` | 原型污染危险键集合 |
| `DANGEROUS_SHELL_PATTERNS` | `RegExp[]` | 危险Shell命令模式列表 |
| `PRIORITY_LEVELS` | `Object` | 优先级级别（CRITICAL/HIGH/NORMAL/LOW/IDLE） |
| `DEFAULT_TOKEN_BUDGET` | `number` | 默认Token预算（1,000,000,000） |
| `TOKEN_BUDGET_WARNING_RATIO` | `number` | Token预算预警比例（0.8） |
| `TOKEN_BUDGET_DANGER_RATIO` | `number` | Token预算危险比例（0.95） |

```javascript
const { PHASES, PHASE_TRANSITIONS, parseFrontmatter, estimateTokens } = require('./constants');

// 六阶段流程

// 阶段转换校验
const allowed = PHASE_TRANSITIONS['module-development']; // ['integration-testing', 'architecture-design']

// Frontmatter解析
const fm = parseFrontmatter('---\nname: test\nphase: dev\n---\n正文内容');
// => { name: 'test', phase: 'dev' }

// Token估算
const tokens = estimateTokens('这是一段中文文本 with English');
```

## config-validator.js — 配置验证器

### 职责概述

验证项目 `config.json` 的合法性，包括版本白名单校验、结构校验、Skill执行级别一致性检查、运行时配置合理性检查，以及敏感信息扫描与脱敏。

### 核心API签名

| 导出 | 类型 | 说明 |
|------|------|------|
| `validateConfig(projectRoot)` | `function → {valid, errors, warnings, securityFindings, skillEnforcements, config}` | 验证项目配置 |
| `maskConfigForLogging(config)` | `function → Object` | 脱敏配置对象（用于日志输出） |
| `VALID_VERSIONS` | `Set` | 合法版本号白名单 |
| `VALID_ENFORCEMENTS` | `Set` | 合法执行级别（strict/recommended/optional） |
| `_isSensitiveKey(key)` | `function → boolean` | 判断键名是否敏感 |
| `_maskSensitiveValue(value)` | `function → string` | 脱敏敏感值（首尾各保留3字符） |

### 使用示例

```javascript
const { validateConfig, maskConfigForLogging } = require('./config-validator');

const result = validateConfig('/path/to/project');
if (!result.valid) {
  console.error('配置错误:', result.errors);
}
if (result.securityFindings.length > 0) {
  console.warn('敏感信息:', result.securityFindings);
}

// 安全日志输出
const masked = maskConfigForLogging(config);
```

## debounced-persister.js — 防抖持久化器

### 职责概述

提供防抖写入、原子写入（tmp+rename）、崩溃恢复（清理陈旧tmp文件）、数据消毒（移除原型污染键）等持久化能力。支持同步/异步双模式，是框架中所有JSON文件写入的核心基础设施。

### 核心API签名

**DebouncedPersister 类**

| 方法/属性 | 签名 | 说明 |
|-----------|------|------|
| `constructor(options)` | `new DebouncedPersister({root, dir, filename, debounceMs?, serialize, onError?, maxRetries?})` | 创建实例 |
| `schedule()` | `() → void` | 调度防抖写入 |
| `persistNow()` | `() → void` | 立即同步持久化 |
| `persistNowAsync()` | `() → Promise<void>` | 立即异步持久化 |
| `flush()` | `() → void` | 刷新待写入数据（同步） |
| `flushAsync()` | `() → Promise<void>` | 刷新待写入数据（异步） |
| `destroy()` | `() → void` | 销毁实例（同步） |
| `destroyAsync()` | `() → Promise<void>` | 销毁实例（异步） |
| `isDirty` | `boolean` | 是否有未写入数据 |
| `persistFailCount` | `number` | 持久化失败次数 |

**静态方法**

| 方法 | 签名 | 说明 |
|------|------|------|
| `writeAtomic(filePath, data)` | `(string, Object) → void` | 原子写入JSON |
| `writeAtomicText(filePath, content, encoding?)` | `(string, string, string?) → void` | 原子写入文本 |
| `writeAtomicAsync(filePath, data)` | `(string, Object) → Promise<void>` | 异步原子写入JSON |
| `writeAtomicTextAsync(filePath, content, encoding?)` | `(string, string, string?) → Promise<void>` | 异步原子写入文本 |
| `readJson(filePath)` | `(string) → Object\|null` | 读取并消毒JSON文件 |
| `sanitize(data)` | `(Object) → Object` | 移除危险键的深拷贝 |
| `cleanupStaleTmp(dirPath)` | `(string) → void` | 清理陈旧tmp文件 |
| `createPersister(options)` | `(Object) → DebouncedPersister` | 工厂方法 |

### 使用示例

```javascript
const DebouncedPersister = require('./debounced-persister');

const persister = new DebouncedPersister({
  root: '/project',
  dir: 'sessions',
  filename: 'session-001.json',
  debounceMs: 500,
  serialize: () => sessionData,
  onError: (err) => console.error(err),
});

persister.schedule(); // 防抖写入
await persister.flushAsync(); // 立即刷新

// 原子写入
DebouncedPersister.writeAtomic('/path/to/file.json', { key: 'value' });
```

## safe-execute.js — 安全执行

### 职责概述

提供安全函数执行包装器，自动捕获异常并记录日志。包含同步/异步执行、EventEmitter错误发射、数值工具函数。

| 导出 | 类型 | 说明 |

```javascript

```

## structured-logger.js — 结构化日志器

### 职责概述

基于EventEmitter的结构化日志系统。支持分级日志（debug/info/warn/error/silent）、上下文注入（traceId）、子日志器、性能日志、查询过滤、统计信息。

### 核心API签名

**StructuredLogger 类（extends EventEmitter）**

| 方法/属性 | 签名 | 说明 |
|-----------|------|------|
| `constructor(options?)` | `new StructuredLogger({level?, maxEntries?, module?})` | 创建实例 |
| `setTraceId(traceId)` | `(string?) → this` | 设置追踪ID |
| `withTrace(traceId)` | `(string) → StructuredLogger` | 创建带追踪ID的子日志器 |
| `debug(message, meta?)` | `(string, Object?) → void` | 调试级别日志 |
| `info(message, meta?)` | `(string, Object?) → void` | 信息级别日志 |
| `warn(message, meta?)` | `(string, Object?) → void` | 警告级别日志 |
| `error(message, meta?)` | `(string, Object?) → void` | 错误级别日志 |
| `logPerformance(operation, durationMs, meta?)` | `(string, number, Object?) → void` | 性能日志 |
| `logOperation(operation, status, meta?)` | `(string, string, Object?) → void` | 操作日志 |
| `child(module)` | `(string) → StructuredLogger` | 创建子日志器（最多50个） |
| `query(filter?)` | `({level?, module?, since?, traceId?, type?, limit?}) → Entry[]` | 查询日志条目 |
| `getRecent(count?)` | `(number?) → Entry[]` | 获取最近N条日志 |
| `clear()` | `() → void` | 清空日志 |
| `export()` | `() → string` | 导出为JSON字符串 |
| `getStats()` | `() → Object` | 获取统计信息 |
| `isHealthy()` | `() → boolean` | 健康检查（错误率<50%） |
| `shutdown()` | `() → void` | 关闭日志器 |

### 使用示例

```javascript
const StructuredLogger = require('./structured-logger');

const logger = new StructuredLogger({ level: 'debug', module: 'app' });
const child = logger.child('session');

child.info('会话创建', { sessionId: 'sess-001' });
child.logPerformance('persist', 150);

const errors = logger.query({ level: 'error', limit: 10 });
```

## lru-cache.js — LRU缓存

### 职责概述

基于Map的LRU（最近最少使用）缓存实现。访问时自动将条目移到末尾，容量满时淘汰最久未访问的条目。

**LRUCache 类**

| `constructor(maxSize)` | `new LRUCache(number)` | 创建缓存（默认50） |

| `set(key, value)` | `(*, *) → void` | 设置键值对 |
| `has(key)` | `(*) → boolean` | 检查键是否存在 |
| `delete(key)` | `(*) → boolean` | 删除条目 |
| `size` | `number` | 当前条目数 |
| `clear()` | `() → void` | 清空缓存 |
| `keys()` | `() → Iterator` | 键迭代器 |
| `values()` | `() → Iterator` | 值迭代器 |
| `entries()` | `() → Iterator` | 条目迭代器 |
| `forEach(callback)` | `(function) → void` | 遍历 |
| `shutdown()` | `() → void` | 关闭缓存 |
| `isHealthy()` | `() → boolean` | 健康检查 |

### 使用示例

```javascript
const LRUCache = require('./lru-cache');

const cache = new LRUCache(100);
cache.set('key1', 'value1');
cache.get('key1'); // 'value1'
```

## keyed-debouncer.js — 键控防抖器

### 职责概述

按键防抖执行器，每个键独立维护防抖定时器。支持立即执行、批量刷新、按键删除。

### 核心API签名

**KeyedDebouncer 类**

| 方法/属性 | 签名 | 说明 |
|-----------|------|------|
| `constructor(options?)` | `new KeyedDebouncer({debounceMs?, label?})` | 创建实例 |
| `schedule(key, callback, immediate?)` | `(string, function, boolean?) → void` | 调度防抖执行 |
| `flush(keyCallbackProvider)` | `(function) → void` | 刷新所有待执行回调 |
| `delete(key)` | `(string) → void` | 取消指定键的防抖 |
| `clear()` | `() → void` | 清空所有防抖 |
| `has(key)` | `(string) → boolean` | 检查键是否有待执行回调 |
| `size` | `number` | 待执行回调数量 |
| `destroy()` | `() → void` | 销毁防抖器 |

### 使用示例

```javascript
const KeyedDebouncer = require('./keyed-debouncer');

const debouncer = new KeyedDebouncer({ debounceMs: 300, label: 'SessionPersist' });

debouncer.schedule('sess-001', () => persistSession('sess-001'));
debouncer.schedule('sess-002', () => persistSession('sess-002'));

// 刷新所有
debouncer.flush((key) => () => persistSession(key));
```

## capacity-config.js — 容量配置

### 职责概述

加载和管理系统容量配置，从 `config.json` 的 `runtime_config.capacity_config` 读取，合并默认值，校验范围。支持5分钟TTL缓存。

### 核心API签名

| 导出 | 类型 | 说明 |
|------|------|------|
| `loadCapacityConfig(projectRoot)` | `function → Object` | 加载容量配置（含缓存） |
| `getCapacity(key, projectRoot?)` | `function → number` | 获取单项容量值 |
| `clearCache()` | `function → void` | 清除配置缓存 |
| `DEFAULTS` | `Object` | 默认容量配置 |

**默认容量配置项**

| 键 | 默认值 | 范围 | 说明 |
|----|--------|------|------|
| `causal_memory_max` | 500 | 1-10000 | 因果内存最大条目数 |
| `causal_memory_ttl_days` | 30 | 1-365 | 因果内存TTL（天） |
| `causal_chain_max` | 200 | 1-5000 | 因果链最大长度 |
| `pending_outputs_max` | 50 | 1-1000 | 待处理输出最大数 |
| `skill_interfaces_max` | 100 | 1-1000 | Skill接口最大数 |
| `conflict_resolvers_max` | 20 | 1-500 | 冲突解决器最大数 |
| `execution_history_max` | 100 | 1-10000 | 执行历史最大数 |
| `deduplication_index_max` | 200 | 1-5000 | 去重索引最大数 |
| `module_instances_max` | 200 | 1-5000 | 模块实例最大数 |
| `goals_max` | 100 | 1-1000 | 目标最大数 |
| `sandboxes_max` | 50 | 1-500 | 沙箱最大数 |
| `custom_policies_max` | 100 | 1-1000 | 自定义策略最大数 |
| `handlers_max` | 50 | 1-500 | 处理器最大数 |
| `similarity_threshold` | 0.3 | 0-1 | 相似度阈值 |
| `conflict_similarity_threshold` | 0.7 | 0-1 | 冲突相似度阈值 |
| `decay_factor_per_day` | 0.98 | 0-1 | 每日衰减因子 |

### 使用示例

```javascript
const { loadCapacityConfig, getCapacity } = require('./capacity-config');

const config = loadCapacityConfig('/project');
// { causal_memory_max: 500, causal_memory_ttl_days: 30, ... }

const max = getCapacity('causal_memory_max', '/project'); // 500
```
