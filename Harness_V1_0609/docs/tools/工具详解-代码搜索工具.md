# 工具详解-代码搜索工具

> 版本：2.73.4 | 文件：src/utils/fs-utils.js（搜索相关函数）

---

## 模块概述

代码搜索工具集基于fs-utils模块的Markdown扫描、JSON批量读取和文件解析能力，为Agent提供项目内代码搜索和文档发现功能。在Harness框架中，Agent需要快速定位Skill定义、Agent角色配置、规则文件和项目文档，这些搜索能力是SkillRouter自动路由、RBACEnforcer权限加载和上下文管理的基础。

本文档聚焦fs-utils中与搜索发现相关的函数，以及它们在框架搜索场景中的应用模式。

## 搜索相关函数

### `scanMarkdownDirSync(dirPath)` / `scanMarkdownDirAsync(dirPath)`

扫描指定目录中的所有Markdown文件，返回文件名列表。这是框架中最基础的搜索原语，被多个核心模块使用。

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `dirPath` | string | 是 | 要扫描的目录路径 |

**返回值**：
- 同步版本：`Array<string>` — Markdown文件名列表
- 异步版本：`Promise<Array<string>>`

**搜索行为**：
- 仅扫描指定目录的顶层文件，不递归子目录
- 仅返回以`.md`结尾的文件
- 目录不存在时返回空数组
- 扫描失败时返回空数组（错误通过debug-logger记录）

### `readJsonDirSync(dirPath, options)` / `readJsonDirAsync(dirPath, options)`

批量读取目录中的JSON文件并解析，支持自定义文件过滤。

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `dirPath` | string | 是 | 目录路径 |
| `options.filter` | Function | 否 | 文件名过滤函数，默认匹配`.json`后缀 |
| `options.logLabel` | string | 否 | 日志标签，默认'fs-utils' |

**返回值**：
- 同步版本：`Array<{ filename: string, data: Object }>`
- 异步版本：`Promise<Array<{ filename: string, data: Object }>>`

**搜索行为**：
- 扫描目录中所有通过filter的文件
- 逐个读取并解析JSON内容
- 单个文件解析失败时跳过，不影响其他文件
- 目录不存在时返回空数组

### `parseMarkdownFile(filePath)` / `parseMarkdownFileAsync(filePath)`

解析Markdown文件的frontmatter元数据和正文内容，用于结构化搜索。

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `filePath` | string | 是 | Markdown文件路径 |

**返回值**：
- 同步版本：`{ content, frontmatter, body } | null`
- 异步版本：`Promise<{ content, frontmatter, body }>`

**解析结果**：

| 字段 | 类型 | 说明 |
|------|------|------|
| `content` | string | 原始文件完整内容 |
| `frontmatter` | Object | YAML frontmatter解析后的对象 |
| `body` | string | 去除frontmatter后的正文内容 |

### `loadJsonSync(filePath, sanitize)` / `loadJsonAsync(filePath, sanitize)`

加载单个JSON文件，用于精确路径搜索。

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `filePath` | string | 是 | JSON文件路径 |
| `sanitize` | Function | 否 | 消毒函数，默认使用debounced-persister.sanitize |

**返回值**：
- 同步版本：`Object | Array | null`
- 异步版本：`Promise<Object | Array | null>`

## 框架中的搜索场景

### 场景1：Skill发现与路由

SkillRouter使用`scanMarkdownDirSync`扫描`.harness/skills/`目录，发现所有可用的Skill定义：

```javascript
const { scanMarkdownDirSync, parseMarkdownFile } = require('../utils/fs-utils');

const skillFiles = scanMarkdownDirSync('/path/to/project/.harness/skills');

for (const file of skillFiles) {
  const parsed = parseMarkdownFile(`/path/to/project/.harness/skills/${file}`);
  if (parsed && parsed.frontmatter) {
    const skillId = file.replace(/\.md$/, '');
    const { enforcement, depends_on, applicable_agents, phase, priority } = parsed.frontmatter;
    console.log(`Skill: ${skillId}, 阶段: ${phase}, 优先级: ${priority}`);
  }
}
```

### 场景2：Agent角色发现

RBACEnforcer使用`scanMarkdownDirSync`扫描`.harness/agents/`目录，加载Agent角色定义：

```javascript
const { scanMarkdownDirSync, parseMarkdownFile } = require('../utils/fs-utils');

const agentFiles = scanMarkdownDirSync('/path/to/project/.harness/agents');

for (const file of agentFiles) {
  const parsed = parseMarkdownFile(`/path/to/project/.harness/agents/${file}`);
  if (parsed && parsed.frontmatter) {
    const agentId = file.replace(/\.md$/, '');
    const { role, available_skills, model, permissions } = parsed.frontmatter;
    console.log(`Agent: ${agentId}, 角色: ${role}, 模型: ${model}`);
  }
}
```

### 场景3：会话状态搜索

SessionManager使用`readJsonDirSync`批量加载会话状态文件：

```javascript
const { readJsonDirSync } = require('../utils/fs-utils');

const sessions = readJsonDirSync('/path/to/project/.harness/sessions', {
  filter: (f) => f.endsWith('-session.json'),
  logLabel: 'SessionManager',
});

for (const { filename, data } of sessions) {
  if (data.phase === 'module-development') {
    console.log(`活跃开发会话: ${filename}`);
  }
}
```

### 场景4：检查点搜索与恢复

CheckpointManager使用`readJsonDirAsync`异步搜索检查点文件：

```javascript
const { readJsonDirAsync } = require('../utils/fs-utils');

const checkpoints = await readJsonDirAsync('/path/to/project/.harness/checkpoints', {
  logLabel: 'CheckpointManager',
});

const latestCheckpoint = checkpoints
  .filter(({ data }) => data.taskId === targetTaskId)
  .sort((a, b) => b.data.timestamp - a.data.timestamp)[0];

if (latestCheckpoint) {
  console.log('找到最新检查点:', latestCheckpoint.filename);
}
```

### 场景5：规则文件发现

框架启动时扫描`.harness/rules/`目录，发现并加载所有规则定义：

```javascript
const { scanMarkdownDirSync, parseMarkdownFile } = require('../utils/fs-utils');

const ruleFiles = scanMarkdownDirSync('/path/to/project/.harness/rules');

for (const file of ruleFiles) {
  const parsed = parseMarkdownFile(`/path/to/project/.harness/rules/${file}`);
  if (parsed) {
    console.log(`规则文件: ${file}, 内容长度: ${parsed.body.length}`);
  }
}
```

### 场景6：文档体系搜索

搜索docs/目录下的项目文档，支持按层级发现：

```javascript
const { scanMarkdownDirSync, parseMarkdownFile } = require('../utils/fs-utils');

const docDirs = ['architecture', 'core', 'modules', 'tools', 'deep-dive', 'guides'];

for (const dir of docDirs) {
  const files = scanMarkdownDirSync(`/path/to/project/docs/${dir}`);
  for (const file of files) {
    const parsed = parseMarkdownFile(`/path/to/project/docs/${dir}/${file}`);
    if (parsed && parsed.frontmatter) {
      console.log(`[${dir}] ${file}: ${parsed.frontmatter.title || '(无标题)'}`);
    }
  }
}
```

## 搜索模式总结

| 搜索模式 | 使用函数 | 适用场景 |
|---------|---------|---------|
| 目录文件发现 | `scanMarkdownDirSync/Async` | 扫描.harness/子目录中的定义文件 |
| 结构化内容搜索 | `parseMarkdownFile` + frontmatter过滤 | 按元数据筛选Skill、Agent、规则 |
| 批量数据加载 | `readJsonDirSync/Async` | 加载会话、检查点、状态文件 |
| 精确路径读取 | `loadJsonSync/Async` | 加载已知路径的配置文件 |
| 内容全文搜索 | `parseMarkdownFile` + body文本匹配 | 在文档正文中搜索关键词 |

## 搜索性能考量

### 同步 vs 异步选择

| 场景 | 推荐API | 原因 |
|------|---------|------|
| 框架初始化 | 同步 | 启动阶段需要阻塞式加载，确保后续操作数据就绪 |
| 服务器运行时 | 异步 | 避免阻塞事件循环，保持服务响应能力 |
| CLI工具 | 同步 | 简化代码逻辑，CLI对性能不敏感 |
| 文件监控回调 | 异步 | 避免在回调中阻塞 |

### 大目录优化

- `scanMarkdownDirSync/Async`仅扫描顶层目录，不递归，性能可预测
- `readJsonDirSync/Async`逐文件解析，单文件失败不影响整体
- 对于大量文件，考虑使用`options.filter`缩小搜索范围
- `parseMarkdownFile`同步版本捕获异常，适合批量处理

### 搜索缓存建议

框架内部模块（如SkillRouter）对搜索结果实现了多层缓存：
- L1缓存：摘要信息
- L2缓存：完整指令
- L3缓存：关联资源

应用层搜索也应考虑缓存策略，避免重复扫描和解析。

## 与其他搜索工具的关系

fs-utils的搜索能力是框架内部的基础搜索，主要面向.harness/目录和docs/目录的结构化文件发现。对于源代码级别的搜索（如grep、符号查找），框架依赖外部工具或Agent的工具调用能力。

| 搜索类型 | 工具 | 说明 |
|---------|------|------|
| 定义文件发现 | fs-utils（本文档） | 扫描.harness/目录的Markdown/JSON文件 |
| 源代码搜索 | 外部grep/ripgrep | Agent通过工具调用执行代码搜索 |
| 文档全文搜索 | fs-utils + 文本匹配 | 解析Markdown后在body中搜索 |
| 语义搜索 | SkillRouter三层缓存 | 基于向量相似度的Skill匹配 |

---

## 注意事项

- `scanMarkdownDirSync/Async`不递归子目录，需要递归搜索时需自行实现
- `parseMarkdownFile`依赖`constants.parseFrontmatter`，frontmatter格式必须为YAML
- `readJsonDirSync/Async`不应用sanitize，如需消毒应在获取data后单独处理
- 异步版本的`parseMarkdownFileAsync`不捕获异常，调用方需try-catch
- 所有搜索操作应在项目根目录约束下进行，避免搜索系统目录
