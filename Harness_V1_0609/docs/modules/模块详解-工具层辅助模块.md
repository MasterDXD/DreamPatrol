## KeyedDebouncer

**文件**：`keyed-debouncer.js`

键控防抖器，按key独立管理定时器。`immediate=true`时先清除同key已有定时器再立即执行回调。`shutdown()`是`destroy()`的别名。

```javascript
class KeyedDebouncer {
  constructor(options)  // { debounceMs, label }
  schedule(key, callback, immediate)  // immediate=true时清除已有定时器后立即执行
  flush(keyCallbackProvider)          // 立即执行所有待处理回调
  delete(key)                         // 取消指定key的定时器
  clear()                             // 取消所有定时器
  has(key)
  get size()
  destroy()
  shutdown()  // destroy()的别名
}
```

| 配置 | 默认值 | 说明 |
|------|--------|------|
| debounceMs | DEFAULT_DEBOUNCE_MS | 防抖间隔（毫秒） |
| label | 'KeyedDebouncer' | 调试日志标签 |

## ParamValidator

**文件**：`param-validator.js`

统一参数验证器，支持两种模式：链式流畅API（收集错误后统一处理）和静态抛出助手（单参数快速验证，失败即抛出）。`throwIfInvalid`在Error构造函数不支持code参数时将code嵌入消息文本。

  requireNumber(value, fieldName, opts)  // opts: {min, max}
  requireObject(value, fieldName)
  requireFunction(value, fieldName)
  requireEnum(value, allowedValues, fieldName)
  requireArray(value, fieldName)
  requireNonEmptyArray(value, fieldName)
  requireBoolean(value, fieldName)
  requireTruthy(value, fieldName)
  requirePattern(value, pattern, fieldName)
  requireStringLength(value, maxLength, fieldName)
  requireNumberRange(value, min, max, fieldName)
  custom(condition, message)
  // 结果处理
  throwIfInvalid(ErrorClass, code)    // code嵌入消息（当Error不支持code参数时）
  returnResult()                      // {valid, errors}
  toReturnFalse()                     // boolean
  toReturnObject(errorKey)            // {success, [errorKey]}
  get errors()
  get hasErrors
  get firstError
  reset()
  // 静态抛出助手（失败即抛HarnessError）
  static requireString_(value, fieldName)
  static requireFunction_(value, fieldName)
  static requireObject_(value, fieldName)
  static requireArray_(value, fieldName)
  static requireNumber_(value, fieldName)
  static requireTruthy_(value, fieldName)
  static ensurePositiveNumber(value, fallback)
  static ensurePositiveInt(value, fallback)
  // 静态验证函数（返回{valid, reason}）
  static validateString
  static validateNonEmptyString
  static validateNumber
  static validateObject
  static validateFunction
  static validateEnum
}

  get isDirty

  static writeAtomicText(filePath, content, encoding)  // 同步原子写入文本
  static writeAtomicAsync(filePath, data)   // 异步原子写入JSON
  static writeAtomicTextAsync(filePath, content, encoding) // 异步原子写入文本

  static sanitize(data, depth)              // 深度克隆+移除危险键

## Round 8 缺陷修复记录

> 本轮修复涉及工具层6个模块的关键缺陷，涵盖DoS防护、异步异常统一处理、嵌套深度限制、URL编码路径处理、损坏JSON部分恢复和多次shutdown防护。

### safe-parse — 超大JSON DoS防护

**缺陷**：`safeParse()` 方法未限制输入字符串长度，恶意或错误构造的超大JSON字符串（如数GB）可直接进入`JSON.parse()`，导致内存耗尽和进程崩溃（DoS攻击向量）。

**修复**：新增`MAX_JSON_PARSE_LENGTH`常量（默认50MB），`safeParse()`在解析前检查输入字符串长度，超出限制时直接返回默认值而不尝试解析，防止超大JSON消耗内存。

**影响范围**：超大JSON输入不再导致内存耗尽或进程崩溃，解析前长度检查提供DoS防护。

### safe-execute — 同步/异步异常统一处理

**缺陷**：`safeExecute()` 方法仅捕获同步异常，若传入函数返回thenable（Promise-like对象）但未显式返回，异步拒绝（rejection）不会被捕获，导致未处理的Promise拒绝警告和潜在的错误静默丢失。

**修复**：新增thenable检测逻辑，当函数返回值具有`.then`方法时，自动附加`.catch()`处理异步拒绝，将异步错误统一纳入错误处理流程。同步异常和异步拒绝现在都能被正确捕获和返回。

**影响范围**：返回Promise的函数现在也能被安全执行，异步拒绝不再产生未处理的Promise拒绝警告，错误处理行为一致。

### param-validator — 嵌套对象深度限制

**缺陷**：`requireObject()` 方法未限制嵌套对象的递归深度，深度嵌套的对象（如循环引用或恶意构造的深层对象）可导致栈溢出崩溃。

**修复**：新增`requireMaxDepth()`方法和`DEFAULT_MAX_DEPTH`常量（默认10），验证对象嵌套深度不超过限制。深度超出时记录验证错误，防止栈溢出。

**影响范围**：深度嵌套对象不再导致栈溢出，对象深度验证提供安全边界。

### path-utils — URL编码路径处理

**缺陷**：路径处理函数未处理URL编码的路径段（如`%2e%2e`代表`..`），攻击者可通过双重或三重URL编码绕过路径遍历防护。

**修复**：新增`_decodePathSegment()`辅助方法，对路径段执行最多3轮URL解码，每轮解码后检查是否产生新的编码序列，防止编码绕过。解码后的路径段再进行路径遍历检测。

**影响范围**：URL编码的路径遍历攻击（如`%2e%2e%2f`、双重编码）现在能被正确检测和阻止。

### json-store-restorer — 损坏JSON部分恢复

**缺陷**：`_restore()` 方法在JSON文件损坏（如磁盘写入中断导致截断）时，完全放弃恢复，所有数据丢失。即使文件中仍有大量有效的键值对，也无法提取。

**修复**：新增损坏JSON部分恢复逻辑，使用正则表达式从损坏的JSON字符串中提取有效的键值对（匹配`"key": value`模式），将可恢复的数据写入新文件，最大化数据保留。完全无法解析时仍返回空对象。

**影响范围**：JSON文件损坏时不再完全丢失数据，部分恢复机制可提取有效键值对，减少数据损失。

### shutdown-mixin — 多次shutdown防护

**缺陷**：`shutdown()` 方法在多次调用时，第二次调用会重新执行关闭流程（包括关闭回调），可能导致已释放的资源被重复释放或已关闭的连接被再次关闭，引发异常。

**修复**：新增`_shuttingDown`中间状态标志，在关闭流程开始时设置为true，关闭完成后设置为false。`shutdown()`方法在`_shuttingDown`为true时直接返回（跳过），防止关闭流程被并发触发。`_isShutdown`仍标记最终关闭状态。

**影响范围**：多次调用`shutdown()`不再重复执行关闭流程，避免资源重复释放和并发关闭异常。

## R20 修复记录

### isHealthy()关闭状态检查修复（3处）

**缺陷**：`lru-cache.js`、`bounded-map.js`、`bounded-array.js`的`isHealthy()`方法未检查`_shutDown`标志，关闭后的实例仍报告为健康状态，可能被继续调用导致异常。

**修复**：三个模块均添加`_shutDown`标志，`isHealthy()`返回`!this._shutDown`，`shutdown()`方法中设置`this._shutDown = true`。

**影响范围**：关闭后的LRU缓存、有界Map、有界数组正确报告不健康状态，不再被误用。

### structured-logger.js — isHealthy()关闭检查与shutdown()标志

**缺陷**：`structured-logger.js`的`isHealthy()`方法未检查关闭状态，`shutdown()`方法未设置`_shutDown`标志，导致关闭后仍被报告为健康且可能被继续调用。

**修复**：`isHealthy()`添加`_shutDown`检查，`shutdown()`中添加`this._shutDown = true`标志设置。

**影响范围**：结构化日志器关闭后正确报告不健康状态，关闭流程更完整。
