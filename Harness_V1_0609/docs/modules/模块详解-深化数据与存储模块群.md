# 模块详解-深化数据与存储模块群

> 版本：2.73.4 | 文件：src/runtime/deepening/

---

## 模块群概述

深化数据与存储模块群是Harness深化子系统的数据层基础设施，负责深化推理过程中的状态快照、事件持久化、缓存管理、指标采集、报告生成、基准测试和审计追踪。该模块群包含10个核心模块，围绕"数据采集→存储→分析→输出"的流水线组织，为DeepeningOrchestrator和DeepeningPipeline提供完整的数据支撑能力。

模块群的设计理念是：**为深化推理提供全生命周期的数据管理，从状态快照到事件溯源，从指标采集到报告输出，确保推理过程可追溯、可回放、可度量**。

## 模块清单

| 模块 | 源文件 | 说明 |
|------|--------|------|
| DeepeningSnapshot | deepening-snapshot.js | 快照创建与比较，基于执行ID的状态快照管理 |
| DeepeningSnapshotStore | deepening-snapshot-store.js | 快照存储与版本管理，命名快照+版本链+容量控制 |
| DeepeningEventStore | deepening-event-store.js | 事件持久化与重放，环形缓冲+磁盘持久化+时间线查询 |
| DeepeningEventBus | deepening-event-bus.js | 事件发布/订阅，优先级+拦截器+通配符+死信队列 |
| DeepeningCache | deepening-cache.js | 深化缓存，质量分数感知+容量淘汰+模式失效 |
| DeepeningMetricsCollector | deepening-metrics-collector.js | 指标采集，时间序列+标签聚合+仪表盘 |
| DeepeningMetricsAggregator | deepening-metrics-aggregator.js | 指标聚合，注册制+P95/P99+自动刷盘 |

| DeepeningBenchmark | deepening-benchmark.js | 基准测试，吞吐量+延迟测量+预热机制 |
| DeepeningAuditTrail | deepening-audit-trail.js | 审计追踪，多维度索引+过滤器+合规报告 |

**数据流向**：

1. **状态流**：Orchestrator → Snapshot → SnapshotStore（状态快照链）
2. **事件流**：Orchestrator → EventBus → EventStore（事件溯源链）
3. **指标流**：Collector → Aggregator → ReportGenerator（指标到报告）
4. **缓存流**：任务执行前查询Cache → 执行后写入Cache（结果复用）
5. **审计流**：关键操作 → AuditTrail（合规追踪）
6. **基准流**：Pipeline → Benchmark（性能度量）

## 共同设计模式

### 1. DeepeningBase继承

所有10个模块均继承自`DeepeningBase`，自动获得：
- `attach*`依赖注入方法（27个可注入依赖）
- `isHealthy()`健康检查（默认`!_shutDown`）
- `getStats()`统计接口
- `EventEmitter`事件能力
- `ShutdownMixin`关闭生命周期

### 2. 有界容量控制

所有存储类模块均使用容量限制，防止内存泄漏：

| 模块 | 容器 | 默认容量 | 淘汰策略 |
|------|------|---------|---------|
| DeepeningSnapshot | BoundedMap | 100 | 最旧淘汰 |
| DeepeningSnapshotStore | BoundedMap | 50 | 最旧淘汰+大小追踪 |
| DeepeningEventStore | RingBuffer | DEFAULT_MAX_ENTRIES | 环形覆盖 |
| DeepeningEventBus | Map | 500（订阅数） | 最旧订阅淘汰 |
| DeepeningCache | BoundedMap | Infinity | LRU淘汰 |
| DeepeningMetricsCollector | Array | 1000（每类型） | 超出截断 |
| DeepeningMetricsAggregator | RingBuffer | 1000（每序列） | 环形覆盖 |
| DeepeningAuditTrail | RingBuffer | DEFAULT_MAX_ENTRIES | 环形覆盖+索引递减 |

### 3. 事件驱动通信

所有模块通过`emit()`发出生命周期事件，支持外部监听和集成：

| 模块 | 关键事件 |
|------|---------|
| DeepeningSnapshotStore | `captured`, `restored`, `deleted`, `deletedByName`, `cleared` |
| DeepeningEventStore | `event-recorded`, `event:{type}`, `persist-error`, `restore-error` |
| DeepeningEventBus | `subscribed`, `published`, `handler-error`, `interceptor-error` |
| DeepeningMetricsAggregator | `registered`, `recorded`, `flushed`, `unregistered` |
| DeepeningReportGenerator | `report-generated` |
| DeepeningBenchmark | `benchmark-complete` |
| DeepeningAuditTrail | `recorded`, `audit-recorded`, `filtered`, `filter-error`, `cleared` |

### 4. 参数验证

关键模块使用`param-validator`工具进行参数校验：

| 模块 | 验证规则 |
|------|---------|
| DeepeningSnapshotStore | `requireString_(name)` — 快照名称必须为非空字符串 |
| DeepeningEventBus | `requireFunction_(handler)` — 处理器必须为函数 |
| DeepeningMetricsAggregator | `requireString_(name)` — 指标名称必须为非空字符串；`ensurePositiveNumber(flushInterval)` — 刷盘间隔必须为正数 |
| DeepeningAuditTrail | `requireFunction_(fn)` — 过滤器必须为函数 |

## DeepeningSnapshot — 快照创建与比较

### 职责概述

DeepeningSnapshot提供轻量级的状态快照管理能力，支持按执行ID创建快照、恢复快照、按执行ID列出快照，以及两个快照间的状态差异比较。适用于深化推理过程中的中间状态捕获和回溯。

### 构造函数

```javascript
constructor(options)
```

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `options.maxSnapshots` | number | 100 | 最大快照数量，超出时淘汰最旧快照 |

### 核心API

| 方法 | 返回值 | 说明 |
|------|--------|------|
| `create(executionId, state)` | `Object` | 创建快照，返回`{ snapshotId, executionId, state, createdAt }` |
| `restore(snapshotId)` | `Object \| null` | 恢复快照，返回快照对象或null |
| `listByExecution(executionId)` | `Object[]` | 按执行ID列出所有快照 |
| `compare(snapshotId1, snapshotId2)` | `Object \| null` | 比较两个快照的状态差异 |
| `delete(snapshotId)` | `boolean` | 删除快照 |
| `get(snapshotId)` | `Object \| null` | 获取单个快照 |
| `getStats()` | `Object` | `{ totalSnapshots, maxSnapshots, healthy, shutDown }` |

### compare()返回结构

```javascript
{
  changed: string[],    // 变更的字段路径
  added: string[],      // 新增的字段路径
  diff: string[],       // changed + added 合并
  timeDiff: number,     // 两个快照的时间差（毫秒）
}
```

内部使用`compareStateObjects()`工具函数进行深度状态比较。

### 使用示例

```javascript
const DeepeningSnapshot = require('./src/runtime/deepening/deepening-snapshot');

const snapshot = new DeepeningSnapshot({ maxSnapshots: 50 });

const s1 = snapshot.create('exec-001', { score: 0.7, phase: 'analysis' });
const s2 = snapshot.create('exec-001', { score: 0.85, phase: 'design', coverage: 0.9 });

const diff = snapshot.compare(s1.snapshotId, s2.snapshotId);
// { changed: ['score', 'phase'], added: ['coverage'], diff: ['score', 'phase', 'coverage'], timeDiff: 1520 }

const all = snapshot.listByExecution('exec-001');
// [s1, s2]
```

### 与其他模块的交互关系

- **DeepeningSnapshotStore**：更高级的快照管理，支持命名快照和版本链，DeepeningSnapshot是轻量级替代
- **DeepeningOrchestrator**：在深化推理迭代中创建状态快照，用于回滚和比较
- **DeepeningEventStore**：快照创建事件可通过EventStore持久化

## DeepeningSnapshotStore — 快照存储与版本管理

### 职责概述

DeepeningSnapshotStore提供命名快照的持久化存储和版本管理能力。与DeepeningSnapshot的轻量级设计不同，SnapshotStore支持：命名快照（而非仅执行ID关联）、版本链（同一名称多版本）、大小追踪、容量淘汰和深拷贝隔离。

### 构造函数

```javascript
constructor(options)
```

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `options.maxSnapshots` | number | 50 | 最大快照数量 |
| `options.maxVersions` | number | 10 | 每个名称的最大版本数 |

### 核心API

| 方法 | 返回值 | 说明 |
|------|--------|------|
| `capture(name, state, metadata)` | `string` | 捕获命名快照，返回快照ID |
| `restore(id)` | `Object \| null` | 按ID恢复快照状态（深拷贝） |
| `restoreLatest(name)` | `Object \| null` | 恢复指定名称的最新版本快照 |
| `getVersions(name)` | `Object[]` | 获取指定名称的版本列表 |
| `getNames()` | `string[]` | 获取所有快照名称 |
| `get(id)` | `Object \| null` | 获取快照元信息（不含state） |
| `compare(id1, id2)` | `Object \| null` | 比较两个快照的状态差异 |
| `delete(id)` | `boolean` | 删除单个快照 |
| `deleteByName(name)` | `number` | 删除指定名称的所有快照，返回删除数量 |
| `clear()` | `boolean` | 清空所有快照 |
| `getStats()` | `Object` | 统计信息 |

### capture()参数说明

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `name` | string | 是 | 快照名称，必须为非空字符串 |
| `state` | any | 是 | 快照状态，不可为null/undefined |
| `metadata` | Object | 否 | 快照元数据 |

### capture()内部流程

1. 验证name为非空字符串，state不为null/undefined
2. 生成唯一ID（`counterId(ID_PREFIXES.DEEPENING_SNAPSHOT_STORE)`）
3. 计算版本号（当前名称版本数+1）
4. 使用`stableStringify()`计算状态大小
5. 使用`deepClone()`深拷贝状态（隔离原始对象）
6. 存入BoundedMap，更新大小追踪
7. 维护版本链，超出maxVersions时淘汰最旧版本
8. 发出`captured`事件

### get()返回结构

```javascript
{
  name: string,       // 快照名称
  version: number,    // 版本号
  metadata: Object,   // 元数据
  size: number,       // 状态大小（字节）
}
```

### getStats()返回结构

```javascript
{
  totalSnapshots: number,    // 当前快照总数
  totalNames: number,        // 快照名称数
  totalCreated: number,      // 累计创建数
  totalRestored: number,     // 累计恢复数
  totalSizeBytes: number,    // 总占用字节数
  maxSnapshots: number,      // 最大快照数
  maxVersions: number,       // 每名称最大版本数
  healthy: boolean,
  shutDown: boolean,
}
```

### 事件列表

| 事件名 | 触发时机 | 数据 |
|--------|---------|------|
| `captured` | 快照创建 | `{ name, version }` |
| `restored` | 快照恢复 | `{ id, name }` |
| `deleted` | 单个快照删除 | `{ id }` |
| `deletedByName` | 按名称删除 | `{ name, count }` |
| `cleared` | 清空所有快照 | — |

### 使用示例

```javascript
const DeepeningSnapshotStore = require('./src/runtime/deepening/deepening-snapshot-store');

const store = new DeepeningSnapshotStore({ maxSnapshots: 100, maxVersions: 5 });

const id1 = store.capture('auth-module', { users: 10, sessions: 5 }, { author: 'worker-1' });
const id2 = store.capture('auth-module', { users: 15, sessions: 8 }, { author: 'worker-2' });

const latest = store.restoreLatest('auth-module');
// { users: 15, sessions: 8 }（深拷贝）

const versions = store.getVersions('auth-module');
// [{ version: 1 }, { version: 2 }]

const diff = store.compare(id1, id2);
// { changed: [...], added: [...] }

console.log(store.getStats().totalSizeBytes);
// 状态序列化后的总字节数
```

### 与其他模块的交互关系

- **DeepeningSnapshot**：轻量级替代，SnapshotStore提供更丰富的版本管理
- **DeepeningOrchestrator**：在深化迭代中捕获中间状态，用于Checkpoint恢复
- **DeepeningEventStore**：快照事件可同步记录到EventStore
- **DeepeningAuditTrail**：快照操作可记录到审计追踪

## DeepeningEventStore — 事件持久化与重放

### 职责概述

DeepeningEventStore提供深化推理过程中的事件持久化、查询和重放能力。支持6种预定义事件类型、按类型/执行ID索引、时间范围查询、事件重放和磁盘持久化。是事件溯源（Event Sourcing）模式的核心实现。

### 构造函数

```javascript
constructor(options)
```

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `options.maxEvents` | number | DEFAULT_MAX_ENTRIES | 最大事件数量（环形缓冲） |
| `options.maxExecutionIds` | number | 500 | 最大执行ID追踪数 |
| `options.maxByExecutionKeys` | number | 500 | 按执行ID索引的最大键数 |
| `options.persistToDisk` | boolean | false | 是否持久化到磁盘 |
| `options.persistPath` | string | '' | 持久化目录路径 |

### 预定义事件类型

```javascript
static EVENT_TYPES = {
  EXECUTION_START:    'execution-start',
  EXECUTION_COMPLETE: 'execution-complete',
  ITERATION_COMPLETE: 'iteration-complete',
  CONVERGENCE_DETECTED: 'convergence-detected',
  CACHE_HIT:          'cache-hit',
  CACHE_MISS:         'cache-miss',
};
```

### 核心API

| 方法 | 返回值 | 说明 |
|------|--------|------|
| `record(type, data)` | `Object` | 记录事件，返回事件对象 |
| `recordExecutionStart(executionId, task)` | `Object` | 记录执行开始 |
| `recordExecutionComplete(executionId, result)` | `Object` | 记录执行完成 |
| `recordIterationComplete(executionId, iteration, score)` | `Object` | 记录迭代完成 |
| `recordConvergence(executionId, reason, iteration)` | `Object` | 记录收敛检测 |
| `recordCacheHit(taskId, score)` | `Object` | 记录缓存命中 |
| `recordCacheMiss(taskId)` | `Object` | 记录缓存未命中 |
| `getByType(type)` | `Object[]` | 按类型查询事件 |
| `getByExecution(executionId)` | `Object[]` | 按执行ID查询事件 |
| `getEventCountByType(type)` | `number` | 按类型统计事件数 |
| `getEventCountByExecution(executionId)` | `number` | 按执行ID统计事件数 |
| `getExecutionTimeline(executionId)` | `Object[]` | 获取执行时间线（同getByExecution） |
| `query(filters)` | `Object[]` | 高级查询 |
| `replay(executionId, callback)` | `number` | 重放执行事件，返回事件数 |
| `getDashboard()` | `Object` | 获取仪表盘数据 |
| `flush()` | `boolean` | 刷盘到磁盘 |
| `clear()` | `boolean` | 清空所有事件 |
| `getStats()` | `Object` | 统计信息 |

### record()内部流程

1. 递增序列号`_sequenceNumber`
2. 构建事件对象：`{ id: timestampId(), type, data, timestamp, sequence }`
3. 推入RingBuffer
4. 更新按类型索引`_byType`
5. 若data含executionId，更新执行ID集合和按执行索引`_byExecution`
6. 执行ID集合超出maxExecutionIds时淘汰最旧ID
7. 发出`event-recorded`事件和`event:{type}`类型特定事件

### query()过滤器

| 字段 | 类型 | 说明 |
|------|------|------|
| `filters.type` | string | 按事件类型过滤 |
| `filters.executionId` | string | 按执行ID过滤 |
| `filters.since` | number | 起始时间戳（含） |
| `filters.until` | number | 截止时间戳（含） |

### 磁盘持久化

- **存储路径**：`{persistPath}/deepening-events.json`
- **写入方式**：`writeAtomic()`原子写入
- **写入内容**：`{ events: [...], sequenceNumber }`
- **恢复流程**：`loadJsonSync()`加载 → 截断到maxEvents → 重建索引
- **支持异步**：`_writeToDiskAsync()`和`_loadFromDiskAsync()`
- **错误处理**：写入/加载失败时发出`persist-error`/`restore-error`事件

### getDashboard()返回结构

```javascript
{
  stats: Object,              // 统计信息
  recentEvents: Object[],     // 最近10条事件
  executionSummaries: {       // 按执行ID汇总
    [executionId]: { events: [] }
  },
}
```

### 事件列表

| 事件名 | 触发时机 | 数据 |
|--------|---------|------|
| `event-recorded` | 事件记录 | 事件对象 |
| `event:{type}` | 特定类型事件记录 | 事件对象 |
| `persist-error` | 持久化失败 | Error + `{ operation }` |
| `restore-error` | 恢复失败 | Error + `{ operation }` |

### 使用示例

```javascript
const DeepeningEventStore = require('./src/runtime/deepening/deepening-event-store');

const store = new DeepeningEventStore({
  maxEvents: 5000,
  persistToDisk: true,
  persistPath: '.harness/deepening',
});

store.recordExecutionStart('exec-001', '实现用户认证');
store.recordIterationComplete('exec-001', 1, 0.72);
store.recordIterationComplete('exec-001', 2, 0.88);
store.recordConvergence('exec-001', 'quality-threshold', 2);
store.recordExecutionComplete('exec-001', { success: true, bestScore: 0.88 });

const timeline = store.getExecutionTimeline('exec-001');
// 按时间顺序的5条事件

const recent = store.query({ since: Date.now() - 3600000, type: 'iteration-complete' });
// 最近1小时的迭代完成事件

const count = store.replay('exec-001', (event) => {
  console.log(`[${event.type}] ${JSON.stringify(event.data)}`);
});

store.flush();
```

### 与其他模块的交互关系

- **DeepeningEventBus**：EventBus负责事件分发，EventStore负责事件持久化，两者互补
- **DeepeningOrchestrator**：在深化推理各阶段记录事件
- **DeepeningMetricsCollector**：事件数据可作为指标采集的来源
- **DeepeningAuditTrail**：事件存储与审计追踪互补，前者关注推理过程，后者关注操作合规

## DeepeningEventBus — 事件发布/订阅

### 职责概述

DeepeningEventBus提供深化子系统内部的事件发布/订阅机制，支持优先级排序、拦截器、通配符匹配、死信队列和一次性订阅。注意：此类已标记为**已弃用**，推荐使用`runtime/infrastructure/event-bus`中的EventBus替代。

### 构造函数

```javascript
constructor(options)
```

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `options.maxDeadLetters` | number | 100 | 死信队列最大容量 |
| `options.maxInterceptors` | number | 50 | 最大拦截器数量 |
| `options.maxSubscriptions` | number | 500 | 最大订阅数量 |

### 核心API

| 方法 | 返回值 | 说明 |
|------|--------|------|
| `subscribe(topic, handler, options)` | `string` | 订阅主题，返回订阅ID |
| `subscribeOnce(topic, handler)` | `string` | 一次性订阅，触发后自动取消 |
| `unsubscribe(subId)` | `boolean` | 取消订阅 |
| `publish(topic, data)` | `Promise<number>` | 发布事件，返回投递数 |
| `addInterceptor(fn)` | `boolean` | 添加拦截器 |
| `removeInterceptor(fn)` | `boolean` | 移除拦截器 |
| `getSubscriberCount(topic)` | `number` | 获取订阅者数量 |
| `getDeadLetters()` | `Object[]` | 获取死信队列 |
| `clearDeadLetters()` | `number` | 清空死信队列，返回清除数量 |
| `getTopicNames()` | `string[]` | 获取所有主题名称 |
| `getStats()` | `Object` | 统计信息 |

### subscribe()参数说明

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `topic` | string | 是 | 主题名称，支持通配符 |
| `handler` | Function | 是 | 事件处理函数，支持async |
| `options.priority` | number | 否 | 优先级，数值越小越先执行，默认0 |
| `options.filter` | Function | 否 | 事件过滤函数 |

### 通配符匹配规则

| 模式 | 匹配规则 | 示例 |
|------|---------|------|
| `*` | 匹配所有主题 | `*` 匹配任何主题 |
| `prefix.*` | 匹配前缀开头的主题 | `deepening.*` 匹配 `deepening.iteration`、`deepening.convergence` |
| 精确字符串 | 精确匹配 | `deepening.convergence` 仅匹配自身 |

### publish()内部流程

1. 验证topic不为空
2. 构建事件对象：`{ topic, data, timestamp }`
3. 依次执行拦截器，任一返回`false`则中止发布
4. 收集匹配的订阅者（通配符+精确匹配+过滤器）
5. 按priority升序排序
6. 依次调用handler：
   - 同步handler：立即执行，异常则进入死信队列
   - 异步handler：`await`执行，异常则进入死信队列
7. 更新发布/投递统计
8. 发出`published`事件

### 拦截器机制

拦截器在事件分发前执行，可用于：
- 事件过滤：返回`false`阻止发布
- 事件转换：修改event对象
- 事件审计：记录所有事件

```javascript
bus.addInterceptor((event) => {
  if (event.topic.startsWith('internal.')) return false;
  return true;
});
```

### 死信队列

handler执行异常时，事件进入死信队列：

```javascript
{
  topic: string,       // 原始主题
  data: any,           // 原始数据
  timestamp: number,   // 原始时间戳
  error: string,       // 错误信息
}
```

### getStats()返回结构

```javascript
{
  totalSubscriptions: number,
  totalTopics: number,
  totalPublished: number,
  totalDelivered: number,
  wildcardSubs: number,
  deadLetters: number,
  interceptorCount: number,
  healthy: boolean,
  shutDown: boolean,
}
```

### 事件列表

| 事件名 | 触发时机 | 数据 |
|--------|---------|------|
| `subscribed` | 订阅创建 | `{ id, topic }` |
| `published` | 事件发布 | `{ topic, delivered }` |
| `handler-error` | handler异常 | Error + `{ topic, subscriptionId }` |
| `interceptor-error` | 拦截器异常 | Error + `{ topic }` |

### 使用示例

```javascript

const bus = new DeepeningEventBus({ maxSubscriptions: 200 });

bus.addInterceptor((event) => {
  console.log(`[拦截] ${event.topic}`);

bus.unsubscribe(subId);
```

## DeepeningCache — 深化缓存

### 职责概述

DeepeningCache提供深化推理过程中的任务结果缓存能力，支持质量分数感知的缓存更新、容量淘汰和模式失效。当相同任务再次执行时，可直接从缓存获取结果，避免重复计算。

### 构造函数

```javascript
constructor(options)
```

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `options.maxSize` | number | Infinity | 最大缓存条目数 |

### 核心API

| 方法 | 返回值 | 说明 |
|------|--------|------|
| `store(task, result, metadata)` | `boolean` | 存储缓存条目 |
| `retrieve(task)` | `Object \| null` | 检索缓存条目 |
| `invalidate(task)` | `boolean` | 失效指定缓存 |
| `invalidateByPattern(pattern)` | `number` | 按模式批量失效，返回失效数量 |
| `getEntries()` | `Object[]` | 获取所有缓存条目（按质量分数降序） |
| `clear()` | `void` | 清空缓存 |
| `getStats()` | `Object` | 统计信息 |

### 质量分数感知缓存

`store()`方法在存储时比较新条目与已有条目的质量分数：

```javascript
store(task, result, { qualityScore: 0.9 })
```

- 若已有条目的qualityScore ≥ 新条目的qualityScore，保留已有条目，返回`true`
- 若新条目的qualityScore更高，覆盖已有条目
- 这确保缓存始终保存最高质量的结果

### 缓存键生成

`_key(task)`方法将任务对象转换为缓存键：

1. 首先查询WeakMap缓存（`_keyCache`）
2. 未命中时使用`JSON.stringify(task)`序列化
3. 序列化失败时使用`String(task)`降级
4. 结果缓存到WeakMap（若task对象可作为WeakMap键）

### retrieve()返回结构

```javascript
{
  result: any,            // 缓存结果
  qualityScore: number,   // 质量分数
}
```

### invalidateByPattern()参数

| 字段 | 类型 | 说明 |
|------|------|------|
| `pattern.agentId` | string | 按Agent ID匹配metadata中的agentId |

### getStats()返回结构

```javascript
{
  hits: number,           // 缓存命中次数
  misses: number,         // 缓存未命中次数
  hitRate: number,        // 命中率（0~1）
  size: number,           // 当前缓存大小
  evictions: number,      // 淘汰次数
  healthy: boolean,
  shutDown: boolean,
}
```

### 使用示例

```javascript
const DeepeningCache = require('./src/runtime/deepening/deepening-cache');

const cache = new DeepeningCache({ maxSize: 200 });

cache.store(
  { task: 'code-review', file: 'auth.js' },
  { issues: 3, score: 0.82 },
  { qualityScore: 0.82, agentId: 'reviewer-1' }
);

const cached = cache.retrieve({ task: 'code-review', file: 'auth.js' });
// { result: { issues: 3, score: 0.82 }, qualityScore: 0.82 }

cache.store(
  { task: 'code-review', file: 'auth.js' },
  { issues: 1, score: 0.95 },
  { qualityScore: 0.95, agentId: 'reviewer-2' }
);
// 质量分数0.95 > 0.82，覆盖旧缓存

const invalidated = cache.invalidateByPattern({ agentId: 'reviewer-1' });
// 清除reviewer-1的所有缓存条目

console.log(cache.getStats());
// { hits: 1, misses: 0, hitRate: 1, size: 1, evictions: 0, ... }
```

### 与其他模块的交互关系

- **DeepeningOrchestrator**：在深化迭代前查询缓存，避免重复执行相同任务

## DeepeningMetricsAggregator — 指标聚合

### 职责概述

DeepeningMetricsAggregator提供注册制的指标聚合能力，支持指标注册、数据记录、P95/P99分位数计算、时间序列查询、自动刷盘和仪表盘。与MetricsCollector的轻量采集不同，Aggregator要求先注册指标再记录，提供更精确的统计计算。

```javascript
constructor(options)
```

| 参数 | 类型 | 默认值 | 说明 |

### 核心API

### register()参数说明

| 参数 | 类型 | 必填 | 说明 |

| 参数 | 类型 | 必填 | 说明 |

```javascript

  value: number,     // 最新值

| 字段 | 类型 | 说明 |
|------|------|------|

### flush()行为

- 指定name：刷盘单个指标，返回快照，重置该指标的数据和统计

| `registered` | 指标注册 | `{ name, type }` |

| `flushed` | 指标刷盘 | `{ name }` |
| `unregistered` | 指标注销 | `{ name }` |

### 使用示例

  since: Date.now() - 3600000,

const dashboard = aggregator.getDashboard();
// { totalMetrics: 2, totalRecorded: 4, metrics: { ... } }
```

### record()参数说明

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `action` | string | 是 | 操作名称，必须为非空字符串 |
| `options.actor` | string | 否 | 执行者标识 |
| `options.resource` | string | 否 | 操作资源 |
| `options.executionId` | string | 否 | 关联执行ID |
| `options.details` | any | 否 | 详细信息 |
| `options.result` | string | 否 | 操作结果（如`'success'`/`'failure'`） |
| `options.category` | string | 否 | 操作类别 |
| `options.severity` | string | 否 | 严重度，默认`'info'` |
| `options.metadata` | Object | 否 | 额外元数据 |

### record()内部流程

1. 验证action为非空字符串
2. 构建审计条目：`{ id, action, actor, resource, executionId, details, result, category, severity, metadata, timestamp }`
3. 执行过滤器链，任一过滤器返回false则拒绝记录（返回null）
4. 推入RingBuffer，若缓冲满则淘汰最旧条目
5. 淘汰时递减被淘汰条目的索引计数
6. 更新多维度索引：`_byResult`, `_byAction`, `_byActor`, `_byCategory`, `_bySeverity`
7. 追踪安全违规（action含`security`或`violation`）和失败计数
8. 发出`recorded`和`audit-recorded`事件

### 审计条目结构

```javascript
{
  id: string,           // 唯一ID（counterId(ID_PREFIXES.AUDIT)）
  action: string,       // 操作名称
  actor: string,        // 执行者
  resource: string,     // 操作资源
  executionId: string,  // 关联执行ID
  details: any,         // 详细信息
  result: string,       // 操作结果
  category: string,     // 操作类别
  severity: string,     // 严重度（info/warn/error/critical）
  metadata: Object,     // 额外元数据
  timestamp: number,    // Unix时间戳
}
```

### 过滤器机制

过滤器函数在记录前执行，返回`false`则拒绝记录：

```javascript
auditTrail.addFilter((entry) => {
  return entry.severity !== 'debug';
});
```

- 过滤器异常不阻断记录流程，仅记录debug日志
- 被过滤的条目发出`filtered`事件
- 过滤统计记录在`_totalFiltered`中

### 索引递减机制

当RingBuffer淘汰旧条目时，`_decrementIndices()`方法递减对应索引计数，确保统计准确性：

- 递减后计数≤0时删除该键
- 失败计数和安全违规计数递减时使用`Math.max(0, ...)`防止负数

## R38 修复记录

### `??` vs `||` 运算符误用系统性修复

**缺陷**：多个模块的数值配置参数使用`??`（空值合并）运算符提供默认值。对于计数型/容量型参数（如maxSize、maxHistory、limit等），`0`作为配置值通常无意义且可能导致功能异常（如容量为0导致所有数据被拒绝），应使用`||`运算符在`0`时也回退到默认值。

**修复**：将以下参数从`??`改为`||`运算符：

| 模块 | 参数 | 修复 |
|------|------|------|
| DeepeningSnapshot | maxSnapshots ?? 100 | maxSnapshots \|\| 100 |
| DeepeningEventStore | maxExecutionIds ?? 500 | maxExecutionIds \|\| 500 |
| DeepeningEventStore | maxByExecutionKeys ?? 500 | maxByExecutionKeys \|\| 500 |
| DeepeningMetricsCollector | maxPointsPerType ?? 1000 | maxPointsPerType \|\| 1000 |
| DeepeningMetricsAggregator | maxMetrics ?? 200 | maxMetrics \|\| 200 |
| DeepeningMetricsAggregator | maxSeriesLength ?? 1000 | maxSeriesLength \|\| 1000 |

**影响范围**：数值配置参数为0时正确回退到默认值，避免功能异常。
