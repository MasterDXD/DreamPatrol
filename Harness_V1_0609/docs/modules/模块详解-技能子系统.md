## 1. 子系统概述

技能子系统（Skill Subsystem）是 Harness Engineering 多Agent框架的核心知识驱动引擎，负责 Skill 的全生命周期管理——从发现、创建、路由匹配，到质量评估、反馈学习、持续优化和冗余精简。子系统由14个模块协同工作，形成"发现→路由→创建→评估→优化→演化→精简"的闭环：

| 模块 | 文件 | 核心职责 |
|------|------|---------|
| SkillRouter | skill-router.js | Skill自动发现、语义匹配、三层缓存路由 |
| SkillCreationEngine | skill-creation-engine.js | 从需求描述自动生成新Skill定义，模板化创建、验证、注册 |
| SkillCurator | skill-curator.js | 质量评估、冗余检测、推荐优化、使用统计、归档标记、快照管理 |

| SkillReducer | skill-reducer.js | 动态技能管理系统：三层缓存、动态分层、Top-K选择、任务驱动激活/卸载、过载检测、注意力压缩 |

| SkillEvolver | skill-evolver.js | 技能演化器、LLM驱动的自我改进、变异/聚合/执行三阶段演化 |
| EvolutionTriggerOrchestrator | evolution-trigger-orchestrator.js | 进化触发编排器、三种触发类型、四级严重度、四种进化决策、冷却机制 |

## 3. SkillRouter详解

**文件**：[skill-router.js](file:///e:/Harness_V1_0429/src/runtime/skill/skill-router.js) | **行数**：~1100行 | **核心类**：`SkillRouter extends EventEmitter`

SkillRouter 是技能子系统的核心枢纽，承担三大职责：**发现**（discover）、**匹配**（match）、**加载**（loadL2/loadL3）。

### 3.1 三层缓存架构

SkillRouter 采用三层渐进式缓存，按需加载，控制 Token 消耗：

| 层级 | 存储 | 内容 | 加载时机 | 缓存实现 |
|------|------|------|---------|---------|
| **L1 摘要层** | `this.skills` / `this.registry` | skill_id、name、summary、phase、priority 等元数据 | `discover()` 时全量加载 | 内存常驻 |
| **L2 指令层** | `this._l2Cache` (Map) | Skill Markdown文件的Body部分（完整指令内容） | `loadL2(skillId)` 按需加载 | Map + TTL淘汰 + LRU重排 |
| **L3 资源层** | `this._l3Cache` (Map) | Skill关联资源文件（如references/index.md） | `loadL3(skillId, resourcePath)` 按需加载 | Map + TTL淘汰 + LRU重排 |

**L2缓存机制**：

```javascript
loadL2(skillId) {
  // 1. 检查缓存命中
  const cached = this._getCachedL2(skillId);
  if (cached) { this._stats.l2Hits++; return cached; }

  // 2. 缓存未命中，从文件加载
  this._stats.l2Misses++;
  const skill = this.registry[skillId];
  const rawContent = fs.readFileSync(skill._filePath, 'utf-8');
  const instructionBody = extractMarkdownBody(rawContent); // 去除frontmatter

  // 3. 构建缓存条目
  const l2Entry = {
    skill_id: skillId,
    instruction: instructionBody,
    loadedAt: Date.now(),
    tokenEstimate: estimateTokens(instructionBody),
  };
  this._putL2Cache(skillId, l2Entry);
  return l2Entry;
}
```

**缓存淘汰策略**：
- 容量上限：`_cacheMax`（默认 `DEFAULT_CACHE_MAX`）
- TTL过期：`_cacheTTL`（默认 `DEFAULT_CACHE_TTL`）
- 淘汰算法：FIFO（最旧条目优先淘汰）+ LRU访问重排（`_getCachedFrom` 中 delete+set 实现访问时移到末尾）
- 统计追踪：`l2Hits`、`l2Misses`、`l2Evictions`、`l3Hits`、`l3Misses`、`l3Evictions`

### 3.2 语义匹配

SkillRouter 的匹配算法是多策略融合的：

```
match(context) 执行流程：
  1. 路由缓存查询 → 命中则直接返回
  2. _findMatchingSkills() → 遍历候选Skill
     ├── Agent过滤：仅匹配当前Agent适用的Skill
     ├── 因果输入检查：_checkCausalInputs()
     ├── 触发条件检查：_checkTriggerConditions()
     │   ├── 否定模式检测：_isNegated() → 用户明确拒绝则跳过
     │   ├── 关键词匹配：_matchKeywordsInConditions()
     │   ├── 语义匹配：_semanticMatch() → 基于SEMANTIC_GROUPS
     │   ├── 依赖满足：depends_on全部在completedSet中
     │   └── 自动触发：_checkAutoTrigger()
  3. Spec Boost排序：_applySpecBoost()
  4. 阶段+优先级排序：phase升序 → priority升序
  5. 依赖检查+学习增强：checkDependencies() + _enrichWithLearnings()
  6. 写入路由缓存
```

**SEMANTIC_GROUPS** 定义了17个语义分组，每组包含中英文同义词：

| 分组Key | 中文术语 | English Terms |
|---------|---------|---------------|
| tdd | 测试驱动、先写测试、red-green | tdd, test-driven, 测试优先 |
| architecture | 架构、设计、模块划分 | architecture, design, structure |
| deploy | 部署、上线、发布 | deploy, release, ship, publish |
| debug | 调试、排错、bug | debug, troubleshoot, fix |
| deepening | 深化、迭代精炼、循环深化 | deepening, iterate, refine |
| fusion | 融合、多Agent协同、输出融合 | fusion, merge, vote, cascade |
| ... | ... | ... |

### 3.3 否定模式检测

用户可通过自然语言拒绝特定Skill的触发：

```javascript
const NEGATION_PATTERN = /不需要\s*|不要\s*|跳过\s*|不使用\s*|不用\s*|no\s+|don'?t\s+|skip\s+|without\s+|not\s+/i;
```

检测逻辑：匹配到否定词后，检查否定词后面是否紧跟某个语义分组的术语。例如"不需要测试驱动"会阻止 `tdd-implement` 的触发。

### 3.4 内容去重

`_buildDeduplicationIndex()` 在discover时构建去重索引：

1. 将每个Skill的Body按双换行分段落
2. 过滤掉长度≤30字符的短段落
3. 对段落做归一化（trim + lowercase + 空格压缩）
4. 取前 `DEDUP_KEY_LENGTH` 字符作为去重Key
5. 相同Key出现多次则记录为重复组

`getDeduplicationReport()` 返回重复内容统计，供 SkillReducer 消费。

### 3.5 文件监听与热加载

`watchForChanges()` 支持 Skill 文件的实时热加载，采用三级降级策略：

1. **首选**：`fs.watch()` 原生文件监听（事件驱动，低延迟）
2. **降级1**：`_startMtimeFallbackPolling()` — 基于mtime的轮询（fs.watch失败时）
3. **降级2**：`_startAccessFallbackPolling()` — 基于access的轮询（mtime不可用时）

所有策略均使用防抖（`DEFAULT_PERSIST_DEBOUNCE_MS`）避免频繁重载。

### 3.6 Spec Boost机制

当存在活跃的规格说明（specification）时，SkillRouter 通过 `_applySpecBoost()` 调整匹配优先级：

| 条件 | Boost值 | 说明 |
|------|---------|------|
| Skill的specification_type在staleSpecs中 | -5 | 过时规格降权 |
| Skill的causal_outputs含specification_verified | +10 | 规格验证技能加权 |
| Skill的specification_type在activeSpecs中 | +5 | 活跃规格相关技能加权 |

### 3.7 Skill分类

```javascript
CORE_SKILLS = Set{'tdd-implement', 'module-development', 'code-review', ...}  // 17个核心技能
EXTENSION_SKILLS = Set{'taste-skill', 'better-icons', 'motion-ai-kit'}        // 3个扩展技能
```

`_classifySkill()` 将Skill分为 `core`、`extension`、`unknown` 三类。

## 4. SkillCreationEngine详解

**文件**：[skill-creation-engine.js](file:///e:/Harness_V1_0429/src/runtime/skill/skill-creation-engine.js) | **行数**：~284行 | **核心类**：`SkillCreationEngine extends EventEmitter`

SkillCreationEngine 实现了"从执行经验中提炼知识"的闭环——当任务执行足够复杂或包含错误恢复经验时，自动生成新的Skill定义。

### 4.1 任务评估逻辑

`evaluateTask(executionTrace)` 根据三个维度判断是否应创建新Skill：

| 维度 | 判断条件 | 含义 |
|------|---------|------|
| **isComplex** | `toolCalls >= COMPLEXITY_THRESHOLD (5)` | 任务复杂度足够，值得提炼为方法论 |
| **hasRecovery** | `hadError && recovered` | 包含错误恢复经验 |
| **hasCorrection** | `userCorrection === true` | 包含用户纠正的改进方法 |

三个条件均不满足时返回 `{ shouldCreate: false }`。

### 4.2 Skill名称生成

`_generateSkillName(trace)` 从任务描述生成Skill名称：

1. 取description字段，转小写
2. 移除非单词字符（保留中文`\u4e00-\u9fff`）
3. 空格替换为连字符
4. 截取前40字符
5. 添加`auto-`前缀

### 4.3 Skill文件生成

`createSkill(evaluation, content)` 将评估结果写入Markdown文件：

- 存储路径：`.harness/skills/auto-created/{skillName}.md`
- 安全检查：路径遍历防护（`isPathWithinDir`）、字符白名单校验
- 文件格式：YAML Frontmatter + Markdown Body
- 创建后自动触发 `skillRouter.discoverAsync()` 重新发现

生成的Frontmatter示例：

```yaml
skill_id: "auto-complex-refactor-task"
name: 自动创建-complex-refactor-task
applicable_agents: [task-worker, domain-analyst]
trigger: 复杂任务后自动提炼的方法论
auto_trigger: false
phase: module-development
priority: 5
enforcement: optional
auto_created: true
complexity: 7
```

### 4.4 AgentRuntime集成

通过 `attachToAgentRuntime(runtime)` 监听Agent运行时事件：

- `task:completed` → `_onTaskCompleted(trace)` → 评估并可能创建Skill
- `task:failed` → `_onTaskFailed(trace)` → 评估错误恢复经验

### 4.5 容量控制

- 最大自动创建Skill数：`MAX_AUTO_CREATED_SKILLS = 10000`
- `isHealthy()` 检查：`created < 10000`
- `deleteAutoCreatedSkill(skillName)` 支持删除自动创建的Skill

### 4.6 API参考

**核心属性**：

| 属性 | 类型 | 说明 |
|------|------|------|
| `_taskQueue` | Array | 待处理的创建任务队列 |
| `_results` | Map | 创建结果缓存（skillName → result） |
| `_stats` | Object | 统计信息（evaluated/created/rejected） |

**核心方法**：

| 方法 | 签名 | 说明 |
|------|------|------|
| `createFromRequirement` | `(requirement) → Promise` | 从需求描述自动生成新Skill定义，解析需求文本提取结构化信息 |
| `createFromTemplate` | `(templateId, overrides) → Promise` | 基于模板创建Skill，支持参数覆盖和定制化 |
| `validateDefinition` | `(definition) → {valid, errors}` | 验证Skill定义的完整性和合规性（frontmatter字段、必填项、命名规范） |
| `registerSkill` | `(definition) → {success, skillName}` | 将验证通过的Skill定义注册到SkillRouter，触发重新发现 |
| `getCreationHistory` | `() → Array` | 获取历史创建记录，包含每次创建的评估结果和最终状态 |
| `_onShutdown` | `() → void` | 关闭时分离AgentRuntime事件监听，清理任务队列 |

## 5. SkillCurator详解

**文件**：[skill-curator.js](file:///e:/Harness_V1_0429/src/runtime/skill/skill-curator.js) | **行数**：~347行 | **核心类**：`SkillCurator extends EventEmitter`

SkillCurator 是技能子系统的"策展人"，负责Skill的质量评估、使用统计追踪、归档标记和快照管理。

### 5.1 来源分类

`classifySkill(skillId, source)` 为每个Skill标记来源类型：

| 来源 | 说明 | 质量阈值 |
|------|------|---------|
| `builtin` | 框架内置Skill | 0.15（宽容，内置Skill经过验证） |
| `user` | 用户自定义Skill | 0.30 |
| `generated` | 自动生成的Skill | 0.30 |
| `evolved` | 经演化改进的Skill | 0.30 |

### 5.2 Pin机制

`pinSkill(skillId, reason)` 将Skill标记为"钉住"状态，策展流程会跳过被钉住的Skill，防止误归档：

```javascript
pinSkill('tdd-implement', '核心门禁技能，不可归档');
// runCuration() 中: if (this.isPinned(skill.skill_id)) continue;
```

### 5.3 使用统计追踪

`recordUsage(skillId, result)` 记录每次Skill执行的结果：

```javascript
{
  calls: number,        // 总调用次数
  successes: number,    // 成功次数
  failures: number,     // 失败次数
  lastUsed: timestamp,  // 最后使用时间
  totalDuration: number // 总耗时(ms)
}
```

容量限制：`MAX_USAGE_ENTRIES = 500`，超出时FIFO淘汰最旧条目。安全过滤：`DANGEROUS_KEYS` 集合中的skillId被拒绝记录。

### 5.4 自动策展

`runCuration()` 执行策展检查：

1. 遍历所有已发现Skill
2. 跳过被Pin的Skill
3. 跳过无使用记录的Skill
4. 计算成功率，低于阈值（builtin: 0.15, 其他: 0.30）且调用≥5次 → 发出 `skill-low-quality` 事件
5. 最后使用时间超过 `STALE_THRESHOLD_DAYS (30天)` → 发出 `skill-stale` 事件

`dryRunCuration()` 提供预览模式，不触发事件，仅返回 `wouldFlag` 列表。

### 5.5 智能策展

`startSmartCuration(options)` 结合空闲检测器，仅在系统空闲时执行策展，避免影响正常工作流。

### 5.6 快照管理

`createSnapshot()` 创建策展状态的完整快照，支持回滚：

```javascript
const snap = curator.createSnapshot();
// snap.id = 'snap_xxx'
// snap.data = { usageTracker, classifications, pins }

curator.rollbackToSnapshot(snap.id); // 恢复到快照状态
```

- 快照持久化：`.harness/skills/.snapshots/{id}.json`
- 最大快照数：`MAX_SNAPSHOTS_DEFAULT = 10`
- 溢出时自动删除最旧快照

### 5.7 API参考

**核心属性**：

| 属性 | 类型 | 说明 |
|------|------|------|
| `_qualityScores` | Map | Skill质量评分缓存（skillId → score） |
| `_classifications` | Object | Skill来源分类（skillId → 'builtin'/'user'/'generated'/'evolved'） |

## 8. SkillReducer详解

**文件**：[skill-reducer.js](file:///e:/Harness_V1_0429/src/runtime/skill/skill-reducer.js) | **行数**：~900行 | **核心类**：`SkillReducer extends EventEmitter`

SkillReducer 是技能子系统的动态技能管理系统，实现"按需加载，用完即藏"范式。它独立于SkillRouter实现了自己的三层缓存架构，并在此基础上提供动态分层、Top-K选择、任务驱动激活/卸载、过载检测和注意力压缩能力。

### 8.1 三层加载架构

SkillReducer 定义了三个层级常量：

| 层级 | 常量 | 值 | 说明 |
|------|------|---|------|
| LAYER_METADATA | `L1` | 1 | 元数据层（skill_id, name, summary, trigger_keywords, skill_layer） |
| LAYER_INSTRUCTION | `L2` | 2 | 指令层（完整Frontmatter + Body） |
| LAYER_RESOURCES | `L3` | 3 | 资源层（关联资源文件） |

与SkillRouter的区别：
- SkillReducer的L2缓存使用 `LRUCache`（而非原生Map）
- SkillReducer的L1使用 `Map` 注册表（`_l1Registry`）
- SkillReducer增加了 `trigger_keywords` 字段用于关键词匹配
- SkillReducer增加了 `skill_layer` 字段用于动态分层

### 8.2 动态技能分层

SkillReducer 将技能分为三个层级，实现差异化加载策略：

| 层级 | 常量 | 加载策略 | 说明 |
|------|------|---------|------|
| 核心层 | `SKILL_LAYER_CORE` | 常驻L2 | 15个核心技能（tdd-implement、code-review等），discover后自动预加载 |
| 领域层 | `SKILL_LAYER_DOMAIN` | 按需加载 | 非核心非基础设施技能，通过activateForTask()按需加载L2 |
| 基础设施层 | `SKILL_LAYER_INFRASTRUCTURE` | 排除匹配 | skill-router、session-start-hook等，不参与matchL1匹配 |

核心技能集合定义在 `constants.js` 的 `SKILL_REDUCER_CORE_SKILL_IDS`（Set类型，用于快速has()查找）。

**关键方法**：
- `classifySkillLayer(skillId)` — 查询技能层级
- `getSkillsByLayer(layer)` — 按层级获取技能ID列表
- `getLayerDistribution()` — 获取各层级数量分布
- `_preloadCoreSkills()` — discover后自动预加载核心技能到L2
- `unloadL2(skillId)` — 核心技能保护，不可卸载

### 8.3 Top-K技能选择

`matchTopK(context, k)` 从L1匹配结果中选择最相关的K个技能，核心技能优先占位：

1. 调用 `matchL1(context)` 获取全部匹配结果
2. 核心技能优先占位（最多K个）
3. 剩余槽位分配给领域技能
4. 当匹配结果数 > K 时递增 `topKTruncations` 统计

默认 K=3（`DEFAULT_TOP_K`），可通过构造函数选项 `topK` 配置。K<=0 时返回空数组。

### 8.4 任务驱动激活与自动卸载

**"按需加载，用完即藏"** 的核心执行流程：

1. **任务解析**：`activateForTask(taskSignature, context)` 自动匹配Top-K技能并加载L2
2. **执行与卸载**：`deactivateAfterTask(taskSignature, immediate)` 卸载领域技能（核心技能保留）
   - `immediate=true`：立即卸载，返回已卸载的技能ID列表（适用于任务失败场景）
   - `immediate=false`：延迟卸载（默认5秒），立即返回空数组（适用于任务成功场景）
3. **事件驱动**：`attachEventSource(emitter)` 监听 `task:completed`/`task:failed` 事件自动触发卸载

**关键事件**：
- `skills-activated` — 任务激活完成时触发，载荷 `{taskSignature, skillIds}`
- `skills-deactivated` — 任务卸载完成时触发，载荷 `{taskSignature, unloadedIds}`

### 8.5 技能过载检测

`detectOverload(tokenBudget)` 综合评估L2缓存占用率和Token预算消耗率：

| 级别 | 条件 | 说明 |
|------|------|------|
| none | 有效比率 < overloadThreshold | 正常运行 |
| warning | 有效比率 >= overloadThreshold（默认0.7） | 建议清理缓存 |
| critical | 有效比率 >= 0.95 | 必须立即清理 |

有效比率 = max(L2缓存占用率, Token消耗率)。tokenBudget为0或未提供时仅使用L2缓存率（避免除零错误）。

触发 `overload-detected` 事件，载荷 `{level, l2Cached, l1Count, contextTokens, l2Ratio, tokenRatio}`。

### 8.6 注意力压缩

`compressSkillSummary(summary)` 将技能摘要压缩为核心关键词：

- 自动检测中英文：中文按字符级提取，英文按词级提取并过滤停用词
- 去除标点符号和70+个英文停用词
- 压缩后最大长度40字符（`DEFAULT_COMPRESSED_SUMMARY_MAX_LENGTH`），超长截断加'...'

**相关方法**：
- `getCompressedL1Entries()` — 返回所有技能的压缩版L1条目
- `getCompressedContextEstimate()` — 估算压缩后的Token占用量及节省量

### 8.7 关键词提取

`_extractTriggerKeywords(fm)` 从Frontmatter中提取触发关键词：

1. 从 `trigger_conditions` 中提取引号内关键词
2. 从 `trigger_conditions` 中按 `or` 分割提取词组
3. 从 `trigger` 字段按逗号/空格分割提取
4. 去重并限制最多15个关键词

matchL1(context) {

## 10. SkillTreeDAG详解

**文件**：[skill-tree-dag.js](file:///e:/Harness_V1_0429/src/runtime/skill/skill-tree-dag.js) | **行数**：~147行 | **核心类**：`SkillTreeDAG`

SkillTreeDAG 是技能子系统的依赖图模块，以有向无环图（DAG）建模Skill之间的依赖关系，支持拓扑排序执行、种子技能自生长和循环依赖检测。与 SkillGraph 的关系建模定位不同，SkillTreeDAG 专注于执行顺序和演化树结构。

### 10.1 节点与边

**节点结构**（`addNode(skillId, metadata)` 创建）：

```javascript
{
  id: skillId,
  category: metadata.category ?? 'general',
  level: metadata.level ?? 0,
  status: metadata.status ?? 'active',
  seed: metadata.seed ?? false,
  createdAt: Date.now(),
  updatedAt: Date.now(),
}
```

**边结构**（`addEdge(from, to, type)` 创建）：

边存储在 `_edges` Map 中，key 为源Skill ID，value 为依赖目标ID数组。与 SkillGraph 的四种边类型不同，SkillTreeDAG 使用简化的依赖边，专注于执行顺序。

### 10.2 拓扑排序

`topologicalSort()`（即 `getExecutionOrder()`）使用DFS后序遍历实现拓扑排序：

```
getExecutionOrder() 执行流程：
  1. 遍历所有节点
  2. DFS访问每个未访问节点
  3. 递归访问其所有依赖节点
  4. 依赖节点访问完成后将当前节点加入结果
  5. 结果即为合法的执行顺序
```

### 10.3 循环依赖检测

`detectCycles()` 通过 `_wouldCreateCycle(skillId, dependsOnId)` 在添加边时实时检测：

1. 从 `dependsOnId` 开始BFS遍历
2. 如果遍历到 `skillId`，说明添加该边会形成环
3. 拒绝添加并返回 `false`

### 10.4 种子技能自生长

`growFromSeeds()`（即 `evolveFromSeed(seedId, newSkillId, metadata)`）支持从种子Skill派生新Skill：

```javascript
const dag = new SkillTreeDAG();
dag.addNode('tdd-implement', { seed: true, category: 'core' });
dag.evolveFromSeed('tdd-implement', 'tdd-advanced', { category: 'advanced' });
// tdd-advanced 自动依赖 tdd-implement，level = seed.level + 1
```

### 10.5 子树与层级查询

| 方法 | 返回 | 说明 |
|------|------|------|
| `getDependencies(skillId)` | string[] | 获取直接依赖（前驱节点） |
| `getDependents(skillId)` | string[] | 获取直接被依赖（后继节点） |
| `getRoots()` | string[] | 获取无依赖的根节点 |
| `getLeaves()` | string[] | 获取无后继的叶节点 |
| `getSubtree(skillId)` | string[] | 获取以某节点为根的完整子树 |
| `getSeedSkills()` | Node[] | 获取所有标记为seed的节点 |
| `getDepth()` | number | 获取DAG最大深度 |

### 10.6 API参考

**核心属性**：

| 属性 | 类型 | 说明 |
|------|------|------|
| `_nodes` | Map | 节点注册表（skillId → Node） |
| `_edges` | Map | 边注册表（skillId → dependencyId[]） |
| `_seedSkills` | Array | 种子Skill列表（通过 `getSeedSkills()` 从 `_nodes` 中过滤 `seed: true` 的节点） |

**核心方法**：

| 方法 | 签名 | 说明 |
|------|------|------|
| `addNode` | `(skillId, metadata) → Node` | 添加节点，已存在则更新metadata |
| `addEdge` | `(from, to, type) → boolean` | 添加依赖边，自动检测循环依赖 |
| `topologicalSort` | `() → string[]` | 拓扑排序，返回合法执行顺序 |

| `growFromSeeds` | `() → Node[]` | 从所有种子Skill触发自生长，派生新节点 |
| `getDependents` | `(skillId) → string[]` | 获取依赖该Skill的所有Skill |
| `getDependencies` | `(skillId) → string[]` | 获取该Skill依赖的所有Skill |
| `_onShutdown` | `() → void` | 关闭时清理节点和边（SkillTreeDAG不使用withShutdown，无事件监听需清理） |

**构造函数选项**：

| 选项 | 类型 | 默认值 | 说明 |
|------|------|--------|------|

## 12. SkillEvolver详解

**文件**：[skill-evolver.js](file:///e:/Harness_V1_0429/src/runtime/skill/skill-evolver.js) | **行数**：~379行 | **核心类**：`SkillEvolver extends EventEmitter`

SkillEvolver 是技能子系统的演化引擎，通过LLM驱动的三阶段流程（摘要→聚合→执行）实现Skill的自我改进。与 SkillImprovementLoop 基于经验统计的优化不同，SkillEvolver 利用大语言模型进行深度分析和内容生成，支持变异、选择、交叉等演化操作。

### 12.1 三阶段演化流程

`evolve(skillId, sessionTraces)` 执行完整的演化流程：

```
evolve() 执行流程：
  1. 前置检查
     ├── 关闭状态检查
     ├── LLM客户端检查
     ├── SkillRouter检查
     ├── 演化健康检查（_isEvolutionHealthy: evolutions < 10000）
     └── Token预算检查（remaining/total >= MIN_TOKEN_BUDGET_RATIO = 0.3）

  2. _summarize(skillId, traces)
     ├── 构建LLM Prompt：分析session traces提取成功/失败模式
     └── 返回 { patterns, failures }

  3. _aggregate(skillId, summary)
     ├── 构建LLM Prompt：识别不变量（invariants）和修改目标（modificationTargets）
     └── 返回 { invariants, modificationTargets }

  4. _execute(skillId, aggregation)
     ├── 构建LLM Prompt：基于聚合结果生成改进指令
     └── 返回 { refinedBody, newSkills }

  5. 补丁处理
     ├── 有 patchApproval → 提交审批流
     └── 无 patchApproval → 暂存到 _pendingEvolvedPatches，需人工审核
```

### 12.2 补丁应用

`applyEvolvedPatch(skillId, options)` 将演化结果写入Skill文件：

1. 解析补丁来源（审批通过 / 待处理）
2. 解析Skill文件路径
3. `_backupSkill()` → 备份原文件
4. 读取Skill Markdown文件
5. `_splitFrontmatter()` → 分离Frontmatter和Body
6. 查找 `EVOLUTION_MARKER`（`<!-- evolution-section -->`）
7. `_buildEvolutionSection()` → 构建演化内容
8. `writeAtomicTextAsync()` → 原子写入
9. `skillRouter.discoverAsync()` → 重新发现
10. 发出 `evolution-applied` 事件

### 12.3 演化内容格式

`_buildEvolutionSection(patch)` 生成的演化内容：

```markdown
> Evolved based on LLM analysis (2026-05-27)

[refinedBody内容]

### Invariants
- 保持TDD门禁的强制性
- 不修改核心触发条件

### Modification Targets
- 优化错误恢复步骤的描述
- 增加边界情况处理指引
```

### 12.4 Token预算保护

演化过程消耗大量Token，SkillEvolver通过TokenManager进行预算保护：

- 最低预算比例：`MIN_TOKEN_BUDGET_RATIO = 0.3`
- 剩余预算低于30%时跳过演化，返回 `{ skipped: true }`
- 演化上限：`MAX_EVOLUTIONS = 10000`

### 12.5 备份机制

`_backupSkill()` 与 SkillImprovementLoop 共享相同的备份策略：

- 备份路径：`.harness/skills/.backups/{skillId}.{timestamp}.md`
- 最大备份数：`MAX_BACKUPS_PER_SKILL = 5`
- 溢出时删除最旧备份

### 12.6 API参考

**核心属性**：

## R38 修复记录

### `??` vs `||` 运算符误用系统性修复

**缺陷**：多个模块的数值配置参数使用`??`（空值合并）运算符提供默认值。对于计数型/容量型参数，`0`作为配置值通常无意义且可能导致功能异常，应使用`||`运算符在`0`时也回退到默认值。

**修复**：将以下参数从`??`改为`||`运算符：

| 模块 | 参数 | 修复 |
|------|------|------|
| skill-tree-dag.js | `maxNodes ?? 200` | `maxNodes \|\| 200` |
| skill-tree-dag.js | `maxEdges ?? 1000` | `maxEdges \|\| 1000` |

**影响范围**：数值配置参数为0时正确回退到默认值，避免功能异常。

## R20 修复记录

### FSWatcher监听器泄漏修复

**缺陷**：`skill-router.js`的`_onShutdown()`方法仅关闭FSWatcher但未调用`removeAllListeners()`，导致watcher关闭后事件监听器仍残留，可能引发内存泄漏或回调异常。

**修复**：`_onShutdown()`中添加`removeAllListeners()`调用，确保关闭时彻底清理事件监听器。

**影响范围**：技能路由器关闭后不再残留FSWatcher事件监听器，消除内存泄漏风险。

## R60 Skills Refiner 增强记录

R60 为技能子系统引入 Skills Refiner 增强，扩展了 SkillObservability、SkillDiscoverUtils 和 SkillCanary 三个模块的能力，覆盖技能作用域评估、可移植性分析、合并精简、技能赞赏、断裂符号链接检测和金丝雀令牌注入六大功能。

### 1. Skill Scope Assessment — 技能作用域评估

**模块**：`skill-observability.js` | **方法**：`assessSkillScope(skillId)`

评估技能的作用域范围，识别过度窄化或宽化的技能定义：

| 作用域级别 | 常量 | 说明 |
|-----------|------|------|
| `local` | SCOPE_LOCAL | 仅适用于当前项目特定场景 |
| `project` | SCOPE_PROJECT | 适用于项目级别的通用场景 |
| `organization` | SCOPE_ORGANIZATION | 适用于组织内多项目共享 |
| `ecosystem` | SCOPE_ECOSYSTEM | 适用于整个生态系统 |

评估维度：触发条件通用性、依赖项可替换性、适用Agent范围、语义分组覆盖度。过度窄化的技能（仅1个Agent适用+1个触发条件）建议扩展；过度宽化的技能（5+语义分组+3+Agent）建议拆分。

### 2. Skill Portability Assessment — 技能可移植性评估

**模块**：`skill-observability.js` | **方法**：`assessSkillPortability(skillId)`

评估技能跨项目可移植性，分析依赖项和耦合度，生成移植建议：

```javascript
{
  skillId: 'tdd-implement',
  portabilityScore: 0.85,       // 0-1，越高越易移植
  dependencies: {
    total: 3,
    portable: 2,                // 可移植依赖数
    blocking: ['project-specific-config'],  // 阻塞移植的依赖
  },
  couplingScore: 0.15,          // 0-1，越低越松耦合
  suggestions: ['将project-specific-config参数化', '提取通用触发条件'],
}
```

耦合度分析维度：硬编码路径引用、项目特定配置依赖、Agent绑定数量、因果数据耦合。

### 3. Skill Consolidation — 技能合并精简

**模块**：`skill-observability.js` | **方法**：`findConsolidationCandidates()` + `_suggestConsolidatedName(group)`

检测功能重叠的技能组，生成合并建议，支持技能精简决策：

- `findConsolidationCandidates()` 基于触发条件重叠度、语义分组交集、适用Agent重叠度三个维度计算相似度
- 相似度 >= `CONSOLIDATION_SIMILARITY_THRESHOLD (0.6)` 的技能对归为候选组
- `_suggestConsolidatedName(group)` 从组内技能名称中提取公共前缀/语义核心，生成合并建议名称
- 返回结果包含每组候选的合并理由、预计Token节省量和风险评估

### 4. Skills Appreciation — 技能赞赏

**模块**：`skill-observability.js` | **方法**：`appreciateSkill(skillId, reason?)`

识别高价值技能并标记赞赏，激励技能贡献者，提升技能生态健康度：

```javascript
appreciateSkill('tdd-implement', '核心门禁技能，质量评分持续0.9+');
// → { appreciated: true, skillId, reason, appreciatedAt, totalAppreciations }
```

赞赏条件自动检测：
- 成功率 >= 0.9 且调用次数 >= 50 → 高可靠性赞赏
- 被依赖次数 >= 5 → 高影响力赞赏
- 学习记录 >= 20 条 → 高活跃度赞赏

赞赏数据纳入 `getHealthDashboard()` 的健康评分计算，被赞赏技能的策展优先级降低（防止误归档）。

### 5. Broken Symlink Detection — 断裂符号链接检测

**模块**：`skill-discover-utils.js` | **函数**：`detectBrokenSymlinks(skillsDir)`

- 仅扫描 `.md` 文件的符号链接

### 6. Canary Token Injection — 金丝雀激活令牌注入

**模块**：`skill-canary.js` | **方法**：`injectActivationCanary(skillId, token)` / `checkActivationCanary(skillId, token)` / `recordCanaryActivation(skillId, token, result)`

实现金丝雀激活令牌的注入、验证和记录，确保金丝雀发布链路完整性：

- `injectActivationCanary(skillId, token)` — 向金丝雀配置注入激活令牌，令牌用于标识和追踪金丝雀激活来源
- `checkActivationCanary(skillId, token)` — 验证令牌有效性，返回 `{ valid, expired, usedCount }`，防止令牌重放和伪造
- `recordCanaryActivation(skillId, token, result)` — 记录令牌激活结果，关联令牌与执行结果，支持金丝雀效果按令牌维度分析

令牌结构：

```javascript
{
  id: 'ct-xxxxxxxxx',
  skillId: 'tdd-implement-v2',
  injectedAt: Date.now(),
  expiresAt: Date.now() + 86400000,  // 默认24小时过期
  maxUses: 100,                       // 最大使用次数
  usedCount: 0,
}
```

安全机制：令牌过期自动失效、使用次数耗尽自动失效、令牌与skillId绑定不可跨技能使用。
