# 模块详解-架构边界守护模块群

> 源码路径：`src/gate/`
> 模块数量：5
> 核心职责：架构边界守护与代码质量防线

---

## 模块群概述

架构边界守护模块群是TDD门禁执行器（`src/gate/`）的核心防线层，负责从**模块依赖方向**、**层级边界约束**、**代码漂移追踪**、**历史错误预防**和**输出精简度管控**五个维度守护代码架构的完整性与质量。该模块群包含5个核心模块，均继承自 `EventEmitter`，是 `PhaseOrchestrator`、`TDDGate`、`FrameworkComplianceChecker` 等上层门禁模块的运行时依赖。

架构边界守护模块群的设计理念是：**在代码进入运行时之前，通过多维度静态分析和历史模式匹配，将架构偏离、层级违规、重复错误和冗余输出拦截在门禁阶段**。它通过 `ArchitectureBoundaryEnforcer` 强制模块依赖方向，通过 `LayerBoundaryGuard` 强制四层架构层级约束，通过 `CodeDriftDetector` 追踪架构偏离趋势，通过 `ErrorPreventionGuard` 预防历史错误重犯，通过 `OutputConcisenessGuard` 管控输出精简度，共同构成代码质量的"五道防线"。

## 模块清单

| 模块 | 源文件 | 说明 |
|------|--------|------|
| ArchitectureBoundaryEnforcer | architecture-boundary-enforcer.js | 架构边界执行器：模块级依赖方向约束、白名单覆盖、违规追踪 |
| LayerBoundaryGuard | layer-boundary-guard.js | 层级边界守卫：四层架构依赖方向强制、跨层导入检测 |
| CodeDriftDetector | code-drift-detector.js | 代码漂移检测器：违规快照追踪、增长率分析、趋势计算 |
| ErrorPreventionGuard | error-prevention-guard.js | 错误预防守卫：历史错误模式注册、模糊匹配、DreamEngine集成、Reflexion持久化 |
| OutputConcisenessGuard | output-conciseness-guard.js | 输出精简度守卫：五维度质量评估、综合评分、精简建议 |

## 共同设计模式

### 1. EventEmitter继承

5个模块中有4个（除 `OutputConcisenessGuard`）继承自 `EventEmitter`，可直接 `emit`/`on` 进行事件通知：

| 模块 | 事件机制 |
|------|---------|
| ArchitectureBoundaryEnforcer | `violation`、`whitelist:added` |
| LayerBoundaryGuard | `violation` |
| CodeDriftDetector | 无自定义事件 |
| ErrorPreventionGuard | `warnings-injected`、`reflection-recorded` |
| OutputConcisenessGuard | 无EventEmitter继承 |

### 2. 违规记录模式

`ArchitectureBoundaryEnforcer`、`LayerBoundaryGuard` 均采用相同的违规记录模式：

- 内部维护 `_violations` 数组
- `checkFile()` 方法检测违规并追加到数组
- 超过最大记录数时淘汰最旧记录（FIFO）
- 提供 `getViolations()` 和 `clearViolations()` 方法

### 3. 历史快照模式

`CodeDriftDetector` 和 `OutputConcisenessGuard` 均采用历史快照模式：

- 内部维护 `_history` 数组
- 超过最大容量时淘汰最旧快照
- 基于历史数据计算趋势或平均评分

### 4. 容量保护

所有带容量限制的模块在达到上限时执行淘汰策略：

| 模块 | 容量限制 | 淘汰策略 |
|------|---------|---------|
| ArchitectureBoundaryEnforcer | `maxViolations`（默认1000） | FIFO淘汰最旧违规 |
| LayerBoundaryGuard | `MAX_VIOLATIONS`（1000） | FIFO淘汰最旧违规 |
| CodeDriftDetector | `maxHistory`（默认10） | FIFO淘汰最旧快照 |
| ErrorPreventionGuard | `MAX_PATTERNS`（500）、`MAX_REFLECTION_ENTRIES`（200） | FIFO淘汰最旧模式/反思 |
| OutputConcisenessGuard | `_maxHistory`（50） | FIFO淘汰最旧评分 |

## ArchitectureBoundaryEnforcer详解

### 职责概述

架构边界执行器强制模块级依赖方向约束，使用可配置的规则矩阵（gate、permission、runtime、web、utils、errors），支持三种执行模式（strict、recommended、optional）、白名单覆盖和违规追踪。通过文件路径前缀映射到模块，检测跨模块依赖是否违反规则矩阵。

### 依赖规则矩阵

```
DEPENDENCY_RULES:
  gate       → [utils]
  permission → [utils]
  runtime    → [utils]
  web        → [gate, permission, runtime, utils]
  utils      → []           (无依赖，最底层)
  errors     → []           (无依赖，最底层)
```

### 构造函数参数

```javascript
new ArchitectureBoundaryEnforcer(options)
```

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `options.mode` | `'strict'\|'recommended'\|'optional'` | `'recommended'` | 执行模式 |
| `options.maxViolations` | number | 1000 | 最大违规记录数 |

### 核心方法

#### `getModuleForPath(filePath)`

根据文件路径判断所属模块。

- **参数**：`filePath` (`string`) — 文件路径
- **返回值**：`string | null` — 模块名称（gate/permission/runtime/web/utils/errors），无法识别时返回 `null`
- **说明**：路径分隔符自动归一化（`\` → `/`），按 `PATH_MODULE_MAP` 前缀匹配

#### `isDependencyAllowed(fromModule, toModule)`

检查从源模块到目标模块的依赖是否被允许。

- **参数**：
  - `fromModule` (`string | null`) — 源模块
  - `toModule` (`string | null`) — 目标模块
- **返回值**：`boolean`
- **判定逻辑**：同模块依赖允许 → 白名单匹配允许 → 规则矩阵 `allowedDeps` 包含目标模块则允许 → 否则拒绝；`null` 模块默认允许

#### `addWhitelistEntry(fromModule, toModule)`

添加白名单条目，允许特定模块间的依赖。

- **参数**：
  - `fromModule` (`string`) — 源模块
  - `toModule` (`string`) — 目标模块
- **返回值**：`void`
- **说明**：重复条目自动忽略

#### `checkFile(filePath, deps)`

检查文件的所有依赖是否违反架构边界规则。

- **参数**：
  - `filePath` (`string`) — 文件路径
  - `deps` (`string[]`) — 依赖路径列表
- **返回值**：`Array<{ fromModule: string, toModule: string, filePath: string, dependency: string }>` — 违规列表
- **说明**：每发现一条违规即追加到内部记录并发射 `violation` 事件

#### `getRules()`

获取依赖规则矩阵。

- **返回值**：`object` — `DEPENDENCY_RULES` 对象

#### `getViolations()`

获取所有违规记录的副本。

- **返回值**：`Array<object>` — 违规列表

#### `clearViolations()`

清空所有违规记录。

- **返回值**：`void`

### 事件列表

| 事件名 | 触发条件 | 数据 |
|--------|---------|------|
| `violation` | 检测到依赖违规 | `{ fromModule, toModule, filePath, dependency }` |
| `whitelist:added` | 白名单条目添加 | `{ from, to }` |

### 配置常量

| 常量 | 值 | 说明 |
|------|-----|------|
| `ENFORCEMENT_MODES.STRICT` | `'strict'` | 严格模式 |
| `ENFORCEMENT_MODES.RECOMMENDED` | `'recommended'` | 推荐模式 |
| `ENFORCEMENT_MODES.OPTIONAL` | `'optional'` | 可选模式 |
| `BOUNDARY_RULES.NO_UPWARD_IMPORT` | `'no_upward_import'` | 禁止向上导入 |
| `BOUNDARY_RULES.NO_CROSS_DOMAIN` | `'no_cross_domain'` | 禁止跨域依赖 |
| `BOUNDARY_RULES.NO_CIRCULAR` | `'no_circular'` | 禁止循环依赖 |
| `BOUNDARY_RULES.SINGLE_RESPONSIBILITY` | `'single_responsibility'` | 单一职责 |

### 使用示例

```javascript
const { ArchitectureBoundaryEnforcer } = require('./src/gate/architecture-boundary-enforcer');

const enforcer = new ArchitectureBoundaryEnforcer({
  mode: 'recommended',
  maxViolations: 500,
});

enforcer.on('violation', (v) => {
  console.log(`违规: ${v.fromModule} → ${v.toModule} (${v.filePath})`);
});

enforcer.addWhitelistEntry('gate', 'runtime');

const violations = enforcer.checkFile('src/gate/tdd-gate.js', [
  './utils/constants',
  '../runtime/skill/skill-router',
]);

console.log(enforcer.getModuleForPath('src/web/server.js'));
console.log(enforcer.getViolations());
enforcer.clearViolations();
```

### 与其他模块的交互关系

| 模块 | 交互方式 |
|------|---------|
| LayerBoundaryGuard | 两者互补：Enforcer检查模块级依赖方向，Guard检查层级级依赖方向 |
| CodeDriftDetector | Enforcer的违规数据通过 `snapshot()` 输入到DriftDetector进行趋势分析 |
| TDDGate | TDDGate在门禁检查时调用Enforcer验证代码依赖合规性 |
| FrameworkComplianceChecker | 框架合规检查时引用Enforcer的规则矩阵 |

## LayerBoundaryGuard详解

### 职责概述

层级边界守卫强制四层架构依赖方向（交互层→业务层→领域层→基础设施层），通过文件路径前缀映射到层级并检测跨层导入违规。高层可以依赖低层，同层可互相依赖，低层反向依赖高层视为违规。

### 四层架构映射

```
LAYER_ORDER (从高到低):
  interaction (level 3)  ← src/web/
  business    (level 2)  ← src/runtime/workflow/, src/runtime/collaboration/
  domain      (level 1)  ← src/runtime/agent/, causal/, context/, deepening/,
                            model/, quality/, session/, skill/, thought/, user/
  infrastructure (level 0) ← src/runtime/infrastructure/, src/utils/
```

### 构造函数参数

```javascript
new LayerBoundaryGuard(options)
```

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `options.strict` | boolean | `false` | 是否启用严格模式 |

### 核心方法

#### `getLayerForPath(modulePath)`

根据文件路径判断所属层级。

- **参数**：`modulePath` (`string`) — 模块文件路径
- **返回值**：`string | null` — 层级名称（interaction/business/domain/infrastructure），无法识别时返回 `null`
- **说明**：路径分隔符自动归一化，按 `PATH_PREFIX_MAP` 前缀匹配

#### `isDependencyAllowed(fromLayer, toLayer)`

检查从源层级到目标层级的依赖是否被允许。

- **参数**：
  - `fromLayer` (`string | null`) — 源层级
  - `toLayer` (`string | null`) — 目标层级
- **返回值**：`boolean`
- **判定逻辑**：同层依赖允许 → 高层依赖低层允许（`fromLevel >= toLevel`）→ 低层依赖高层拒绝；`null` 层级默认允许

#### `checkFile(filePath, deps)`

检查文件的所有依赖是否违反层级边界规则。

- **参数**：
  - `filePath` (`string`) — 文件路径
  - `deps` (`string[]`) — 依赖路径列表
- **返回值**：`Array<{ fromLayer: string, toLayer: string, filePath: string, dependency: string }>` — 违规列表
- **说明**：每发现一条违规即追加到内部记录并发射 `violation` 事件

#### `getViolations()`

获取所有违规记录的副本。

- **返回值**：`Array<object>` — 违规列表

#### `clearViolations()`

清空所有违规记录。

- **返回值**：`void`

#### `getLayers()`

获取层级定义。

- **返回值**：`object` — `LAYERS` 对象

#### `getOrder()`

获取层级排序。

- **返回值**：`string[]` — 层级名称数组（从高到低）

### 事件列表

| 事件名 | 触发条件 | 数据 |
|--------|---------|------|
| `violation` | 检测到层级违规 | `{ fromLayer, toLayer, filePath, dependency }` |

### 配置常量

| 常量 | 值 | 说明 |
|------|-----|------|
| `LAYERS.interaction.level` | 3 | 交互层级别 |
| `LAYERS.business.level` | 2 | 业务层级别 |
| `LAYERS.domain.level` | 1 | 领域层级别 |
| `LAYERS.infrastructure.level` | 0 | 基础设施层级别 |
| `VIOLATION_TYPES.CROSS_LAYER_IMPORT` | `'cross_layer_import'` | 跨层导入违规 |
| `VIOLATION_TYPES.CIRCULAR_DEPENDENCY` | `'circular_dependency'` | 循环依赖违规 |
| `VIOLATION_TYPES.UNREGISTERED_LAYER` | `'unregistered_layer'` | 未注册层级违规 |
| `VIOLATION_TYPES.DIRECTION_VIOLATION` | `'direction_violation'` | 方向违规 |

### 使用示例


## CodeDriftDetector详解

### 职责概述

代码漂移检测器跨时间追踪架构偏离，比较违规快照检测趋势，监控违规增长率和模块耦合度，并计算趋势方向（递增、递减、稳定）。通过定期记录违规快照，与基线对比，及时发现架构偏离趋势。

### 构造函数参数

```javascript
new CodeDriftDetector(options)
```

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `options.maxHistory` | number | 10 | 最大历史快照数 |
| `options.violationGrowthRate` | number | 0.5 | 违规增长率阈值 |
| `options.moduleCouplingScore` | number | 0.5 | 模块耦合度阈值 |

### 核心方法

#### `snapshot(violations, moduleStats, couplingStats)`

记录违规快照到历史记录。

- **参数**：
  - `violations` (`Array`, 可选) — 当前违规列表
  - `moduleStats` (`object`, 可选) — 模块统计信息
  - `couplingStats` (`object`, 可选) — 耦合度统计信息
- **返回值**：`void`
- **说明**：快照自动附加 `timestamp`，超过 `maxHistory` 时淘汰最旧快照

#### `detectDrift()`

检测代码漂移，分析违规增长率和模块耦合度。

- **参数**：无
- **返回值**：`{ drifting: boolean, trend: string, alerts: Array, reason: string }`
- **判定逻辑**：
  - 历史快照不足2个 → `{ drifting: false, reason: 'insufficient_history', trend: 'stable' }`
  - 违规从0增长到非0 → 漂移
  - 违规增长率超过 `violationGrowthRate` → 漂移
  - 任何模块耦合度超过 `moduleCouplingScore` → 漂移
  - 趋势由 `_computeTrend()` 计算：increasing / decreasing / stable

#### `getHistory()`

获取历史快照列表的副本。

- **返回值**：`Array<object>` — 历史快照列表

#### `setBaseline(baseline)`

设置基线快照，用于衡量偏离程度。

- **参数**：`baseline` (`object`) — 基线快照数据
- **返回值**：`void`

#### `getBaseline()`

获取基线快照。

- **返回值**：`object | null` — 基线快照数据

#### `getThresholds()`

获取当前阈值配置。

- **返回值**：`{ violationGrowthRate: number, moduleCouplingScore: number }` — 阈值配置

### 趋势计算算法

```
_computeTrend():
  历史快照 < 3 → 'stable'
  取首、中、末三个快照的违规计数
  末 > 中 > 首 → 'increasing'
  末 < 中 < 首 → 'decreasing'
  其他 → 'stable'
```

### 配置常量

| 常量 | 值 | 说明 |
|------|-----|------|
| `DRIFT_SEVERITY.LOW` | `'low'` | 低严重度 |
| `DRIFT_SEVERITY.MEDIUM` | `'medium'` | 中严重度 |
| `DRIFT_SEVERITY.HIGH` | `'high'` | 高严重度 |
| `DRIFT_SEVERITY.CRITICAL` | `'critical'` | 临界严重度 |
| `DRIFT_TYPES.ARCHITECTURE_VIOLATION` | `'architecture_violation'` | 架构违规漂移 |
| `DRIFT_TYPES.DEPENDENCY_DRIFT` | `'dependency_drift'` | 依赖漂移 |
| `DRIFT_TYPES.PATTERN_DRIFT` | `'pattern_drift'` | 模式漂移 |
| `DRIFT_TYPES.NAMING_DRIFT` | `'naming_drift'` | 命名漂移 |
| `DRIFT_TYPES.STRUCTURE_DRIFT` | `'structure_drift'` | 结构漂移 |

### 使用示例

```javascript
const { CodeDriftDetector } = require('./src/gate/code-drift-detector');

const detector = new CodeDriftDetector({
  maxHistory: 20,
  violationGrowthRate: 0.3,
  moduleCouplingScore: 0.4,
});

detector.setBaseline({ violations: [], moduleStats: {}, couplingStats: {} });

detector.snapshot(
  [{ fromModule: 'gate', toModule: 'runtime', filePath: 'src/gate/tdd-gate.js' }],
  { gate: 1, runtime: 0 },
  { 'gate→runtime': 0.6 },
);

const result = detector.detectDrift();
console.log('漂移:', result.drifting, '趋势:', result.trend);
console.log('告警:', result.alerts);
console.log('阈值:', detector.getThresholds());
console.log('基线:', detector.getBaseline());
```

| 模块 | 交互方式 |
|------|---------|
| ArchitectureBoundaryEnforcer | Enforcer的违规数据通过 `snapshot()` 输入到DriftDetector |
| LayerBoundaryGuard | Guard的违规数据通过 `snapshot()` 输入到DriftDetector |
| TDDGate | TDDGate定期调用 `detectDrift()` 检查架构偏离趋势 |
| DashboardServer | 通过 `/api/compliance` 端点暴露漂移检测结果 |

## ErrorPreventionGuard详解

### 职责概述

错误预防守卫主动预防重复错误，维护历史错误模式注册表并在任务执行前注入警告。支持模糊模式匹配、DreamEngine集成加载错误规避笔记、Reflexion式持久化失败模式记录与上下文注入。通过 `withShutdown` 混入支持优雅关闭。

### 构造函数参数

```javascript
new ErrorPreventionGuard(options)
```

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `options.dreamEngine` | object | `null` | DreamEngine实例，用于加载错误规避笔记 |
| `options.minConfidence` | number | 0.5 | 最低置信度阈值 |
| `options.maxHistory` | number | 100 | 最大警告历史记录数 |

### 核心方法

#### `registerErrorPattern(patternData)`

注册错误模式到模式注册表。

- **参数**：`patternData` (`object`)
  - `pattern` (`string`) — 模式文本（必需）
  - `description` (`string`, 可选) — 模式描述
  - `solution` (`string`, 可选) — 解决方案
  - `confidence` (`number`, 可选, 默认 1.0) — 置信度（0-1）
- **返回值**：`{ id: string | null }` — 注册结果，包含模式ID
- **说明**：模式注册表达到 `MAX_PATTERNS`（500）上限时淘汰最旧模式

#### `getPatternCount()`

获取已注册的错误模式数量。

- **返回值**：`number` — 模式数量

#### `check(context)`

检查任务上下文是否存在匹配的历史错误模式，并注入警告。

- **参数**：`context` (`object`, 可选)
  - `task` (`string`, 可选) — 任务描述文本
- **返回值**：`{ safe: boolean, warnings: Array<object> }` — `safe` 为 `true` 表示无警告
- **匹配逻辑**：精确包含匹配 + 模糊匹配（分词后50%以上词元命中视为匹配）
- **说明**：置信度低于 `minConfidence` 的模式跳过；匹配成功时发射 `warnings-injected` 事件

#### `loadFromDreamEngine()`

从DreamEngine加载错误规避笔记到模式注册表。

- **参数**：无
- **返回值**：`number` — 成功加载的模式数量
- **说明**：调用 `dreamEngine.getNotesByCategory('error-avoidance')`，自动去重

#### `removePattern(id)`

移除指定ID的错误模式。

- **参数**：`id` (`string`) — 模式ID
- **返回值**：`boolean` — 是否成功移除

#### `getWarningHistory()`

获取警告历史的副本。

- **返回值**：`Array<object>` — 警告历史列表

#### `getStats()`

获取统计信息。

- **返回值**：`{ checksPerformed, warningsInjected, patternsRegistered, errors, reflectionsRecorded, totalPatterns, totalReflections }` — 统计信息

#### `recordReflection(entry)`

记录反思条目，同时自动注册为错误模式。

- **参数**：`entry` (`object`)
  - `category` (`string`, 可选) — 分类（bugfix/codegen/refactor/test/deploy/config/general）
  - `pattern` (`string`, 可选) — 失败模式描述
  - `rootCause` (`string`, 可选) — 根本原因
  - `solution` (`string`, 可选) — 解决方案
  - `context` (`string`, 可选) — 上下文描述
- **返回值**：`object | null` — 记录的反思条目，输入无效时返回 `null`
- **说明**：反思自动以0.8置信度注册为错误模式；发射 `reflection-recorded` 事件

#### `getReflections(category)`

获取反思记录列表。

- **参数**：`category` (`string`, 可选) — 按分类过滤
- **返回值**：`Array<object>` — 反思记录列表

#### `getReflectionsAsContext(taskDescription)`

将与任务相关的反思记录格式化为上下文文本，用于注入到后续任务中。

- **参数**：`taskDescription` (`string`, 可选) — 任务描述
- **返回值**：`string` — 格式化的历史失败模式提醒文本，无相关记录时返回空字符串
- **说明**：最多返回5条相关反思

#### `isHealthy()`

健康检查。

- **返回值**：`boolean` — 错误数小于100

### 事件列表

| 事件名 | 触发条件 | 数据 |
|--------|---------|------|
| `warnings-injected` | 检查发现匹配的错误模式 | `{ warnings, context }` |
| `reflection-recorded` | 反思条目被记录 | `reflection` 对象 |

### 配置常量

| 常量 | 值 | 说明 |
|------|-----|------|
| `DEFAULT_MIN_CONFIDENCE` | 0.5 | 默认最低置信度阈值 |
| `DEFAULT_MAX_HISTORY` | 100 | 默认最大警告历史记录数 |
| `MAX_PATTERNS` | 500 | 最大错误模式注册数 |
| `MAX_REFLECTION_ENTRIES` | 200 | 最大反思记录数 |
| `REFLECTION_CATEGORIES` | `['bugfix','codegen','refactor','test','deploy','config','general']` | 反思分类列表 |

### 使用示例

```javascript
const { ErrorPreventionGuard } = require('./src/gate/error-prevention-guard');

const guard = new ErrorPreventionGuard({
  dreamEngine: dreamEngineInstance,
  minConfidence: 0.6,
  maxHistory: 200,
});

guard.on('warnings-injected', ({ warnings, context }) => {
  console.log(`注入 ${warnings.length} 条警告`);
});

guard.registerErrorPattern({
  pattern: 'circular dependency',
  description: '检测到循环依赖',
  solution: '使用依赖注入或事件总线解耦',
  confidence: 0.9,
});

const result = guard.check({ task: 'refactor module with circular dependency' });
console.log('安全:', result.safe, '警告:', result.warnings.length);

guard.recordReflection({
  category: 'bugfix',
  pattern: 'race condition',
  rootCause: '未使用锁保护共享资源',
  solution: '使用LockManager获取锁',
  context: '多Agent并发写入同一文件',
});

console.log(guard.getReflectionsAsContext('fix race condition in file write'));
console.log(guard.getStats());
```

### 与其他模块的交互关系

| 模块 | 交互方式 |
|------|---------|
| DreamEngine | 通过 `loadFromDreamEngine()` 加载错误规避笔记 |
| TDDGate | TDDGate在任务执行前调用 `check()` 注入历史错误警告 |
| PhaseOrchestrator | 阶段转换时调用 `check()` 预防阶段相关错误 |
| AgentDebugLoop | 调试闭环修复成功后调用 `recordReflection()` 记录失败模式 |
| DashboardServer | 通过 `/api/compliance` 端点暴露错误预防统计 |

## OutputConcisenessGuard详解

### 职责概述

输出精简度守卫提供五维度输出质量评估：Token数、行数、重复率、填充词率、代码注释率。计算综合精简度评分，追踪历史评分趋势，提供可操作的精简建议。支持可配置阈值和惩罚机制。

### 五维度评估体系

| 维度 | 指标 | 阈值 | 惩罚 |
|------|------|------|------|
| Token数 | `tokenEstimate`（字符数/4） | `maxTokens`（默认2000） | -0.3 |
| 行数 | `lineCount` | `maxLines`（默认100） | -0.2 |
| 重复率 | `repetitionRatio`（trigram重复占比） | `maxRepetitionRatio`（默认0.3） | -0.25 |
| 填充词率 | `fillerRatio`（填充词/总词数） | 0.1 | -0.15 |
| 代码注释率 | `codeCommentRatio`（注释行/代码行） | 0.5（且代码行>10） | -0.1 |

### 构造函数参数

```javascript
new OutputConcisenessGuard(options)
```

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `options.maxTokens` | number | 2000 | 最大Token数 |
| `options.maxLines` | number | 100 | 最大行数 |
| `options.maxRepetitionRatio` | number | 0.3 | 最大重复率 |
| `options.penaltyThreshold` | number | 0.7 | 惩罚阈值（低于此值视为不精简） |

### 核心方法

#### `check(output)`

检查输出文本的精简度，计算五维度指标和综合评分。

- **参数**：`output` (`string`) — 待检查的输出文本
- **返回值**：`{ concise: boolean, score: number, violations: Array, suggestions: Array, metrics: object }` — 精简度检查结果
- **评分逻辑**：基础分1.0，每项违规扣除对应惩罚分，最低0分；`score >= penaltyThreshold` 为精简
- **说明**：检查结果自动追加到历史记录

#### `getHistory()`

获取历史评分记录的副本。

- **返回值**：`Array<object>` — 历史评分列表

#### `getAverageScore()`

获取历史平均评分。

- **返回值**：`number` — 平均评分（0-1），无历史记录时返回1.0

### 重复率计算算法

```
_computeRepetition(words):
  words < 4 → 0
  构建trigram频率Map
  统计重复次数（count > 1 的 trigram 的 count-1 之和）
  repetitionRatio = repeated / max(trigrams.size, 1)
```

### 填充词检测模式

```
fillerPatterns:
  it's worth noting | as mentioned | in summary |
  it should be noted | needless to say | it goes without saying |
  importantly | basically | essentially | fundamentally
```

### 使用示例

```javascript
const { OutputConcisenessGuard } = require('./src/gate/output-conciseness-guard');

const guard = new OutputConcisenessGuard({
  maxTokens: 1500,
  maxLines: 80,
  maxRepetitionRatio: 0.25,
  penaltyThreshold: 0.6,
});

const result = guard.check(`
  It's worth noting that the implementation essentially follows
  the same pattern as before. Basically, the module handles
  configuration validation and essentially provides utility functions.
`);

console.log('精简:', result.concise, '评分:', result.score);
console.log('违规:', result.violations);
console.log('建议:', result.suggestions);
console.log('指标:', result.metrics);
console.log('历史平均:', guard.getAverageScore());
```

### 与其他模块的交互关系

| 模块 | 交互方式 |
|------|---------|
| TDDGate | TDDGate在代码审查时调用 `check()` 评估输出精简度 |
| QualityScorer | QualityScorer可引用精简度评分作为质量维度之一 |
| DashboardServer | 通过 `/api/compliance` 端点暴露精简度统计 |
| OutputConcisenessGuard | 自身无外部依赖，仅依赖标准库 |

## 模块间协作流程

### 边界检查流程

```
代码提交/审查
  │
  ├── 1. ArchitectureBoundaryEnforcer.checkFile()
  │     检查模块级依赖方向（gate→utils, web→gate+runtime等）
  │     输出：模块级违规列表
  │
  ├── 2. LayerBoundaryGuard.checkFile()
  │     检查层级级依赖方向（interaction→business→domain→infrastructure）
  │     输出：层级级违规列表
  │
  ├── 3. CodeDriftDetector.snapshot()
  │     将步骤1和2的违规数据记录为快照
  │
  ├── 4. CodeDriftDetector.detectDrift()
  │     分析违规增长率和耦合度趋势
  │     输出：漂移检测结果（drifting/trend/alerts）
  │
  └── 5. 汇总报告
        模块违规 + 层级违规 + 漂移趋势 → 架构健康报告
```

### 错误预防流程

```
任务执行前
  │
  ├── 1. ErrorPreventionGuard.loadFromDreamEngine()
  │     从DreamEngine加载历史错误规避笔记
  │
  ├── 2. ErrorPreventionGuard.check(context)
  │     匹配任务上下文与历史错误模式
  │     输出：警告列表（含解决方案）
  │
  ├── 3. 将警告注入任务上下文
  │
  └── 4. 任务执行后
        ├── 成功 → 无操作
        └── 失败 → ErrorPreventionGuard.recordReflection()
              记录失败模式，自动注册为错误模式
```

### 输出精简度检查流程

```
AI输出文本
  │
  └── OutputConcisenessGuard.check(output)
        ├── 计算五维度指标
        │     tokenEstimate / lineCount / repetitionRatio /
        │     fillerRatio / codeCommentRatio
        ├── 计算综合评分（1.0 - 违规惩罚）
        ├── 生成违规列表和精简建议
        └── 记录到历史，更新平均评分
```
