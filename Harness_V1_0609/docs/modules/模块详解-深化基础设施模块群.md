> 版本：2.73.4 | 文件：src/runtime/deepening/

## 模块群概述

深化基础设施模块群是深化子系统（Deepening Subsystem）的底层支撑层，提供熔断保护、速率限制、锁管理、资源分配、节流控制、背压管理、连接池、负载均衡、超时管理和健康监控等核心基础设施能力。该模块群包含10个核心模块，均继承自 [[模块详解-DeepeningBase深化基类]]，是深化管道（DeepeningPipeline）和深化编排器（DeepeningOrchestrator）的运行时依赖。

深化基础设施模块群的设计理念是：**为深化推理流程提供弹性、可控、可观测的基础能力，确保在高负载和异常场景下系统仍能稳定运行**。它通过CircuitBreaker实现故障隔离，通过RateLimiter实现流量控制，通过BackpressureManager实现流式反压，通过HealthMonitor实现运行时健康感知，共同构成深化子系统的"免疫系统"。

## 共同设计模式

### 1. DeepeningBase继承

所有10个模块均继承自 `DeepeningBase`，自动获得：

| 能力 | 来源 | 说明 |
|------|------|------|
| 事件机制 | `EventEmitter` | 所有模块可直接 `emit`/`on` |
| 关闭生命周期 | `ShutdownMixin` | `_onShutdown()` 钩子，`shutdown()` 触发 |
| 依赖注入 | `attach*` 方法 | 27个可注入依赖，链式调用 |
| 健康检查 | `isHealthy()` | 默认返回 `!this._shutDown` |
| 统计接口 | `getStats()` | 子类覆盖，返回运行时统计 |

### 2. 事件驱动

所有模块通过事件通知状态变更，遵循统一的命名风格：

- 状态变更事件：`stateChanged`、`pressureChanged`、`instanceHealthChanged`
- 操作事件：`acquired`、`released`、`created`、`removed`
- 异常事件：`rejected`、`denied`、`dropped`、`expired`、`throttled`

### 3. ShutdownMixin集成

每个模块均实现 `_onShutdown()` 方法，在关闭时：

- 清理定时器（`clearInterval`/`clearTimeout`）
- 清空内部Map/Array
- 拒绝等待中的Promise

### 4. 容量保护

所有带容量限制的模块在达到上限时执行淘汰策略：

| 模块 | 淘汰策略 |
|------|---------|
| CircuitBreaker | 淘汰closed状态的熔断器 |
| RateLimiter | 淘汰最旧的Agent限制 |
| BackpressureManager | 淘汰bufferSize为0的流 |
| ConnectionPool | 淘汰无活跃连接的池 |
| Throttle | 淘汰最旧的键 |

## DeepeningCircuitBreaker详解

### 职责概述

熔断器实现经典的Circuit Breaker模式，为深化推理中的外部调用和关键操作提供故障隔离。当连续失败次数达到阈值时自动"跳闸"（open），阻止请求通过；经过冷却期后进入半开状态（half_open），允许有限探测请求通过；探测成功后恢复闭合（closed）。

### 状态机

```
         failures >= threshold              resetTimeout到期
  CLOSED ──────────────────────► OPEN ──────────────────────► HALF_OPEN
    ▲                                 │                           │
    │                                 │  探测失败                  │ 探测成功
    │  successes >= threshold          │                          │
    └─────────────────────────────────┘◄─── failures >= 1 ───────┘
    │                                                                │
    └────────────────────────────────────────────────────────────────┘
                       successes >= successThreshold
```

### 构造函数参数

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `options.maxCircuits` | number | 100 | 最大熔断器数量 |
| `options.failureThreshold` | number | 5 | 触发跳闸的连续失败次数 |
| `options.successThreshold` | number | 3 | 半开状态恢复闭合的连续成功次数 |
| `options.resetTimeout` | number | 30000 | 冷却期（ms），open→half_open等待时间 |

### 核心API

| 方法 | 签名 | 返回值 | 说明 |
|------|------|--------|------|
| `create` | `(name: string, options?: object)` | `object` | 创建熔断器，返回circuit对象 |
| `createCircuit` | `(name: string, options?: object)` | `object` | `create`的别名 |
| `remove` | `(name: string)` | `boolean` | 移除熔断器 |
| `getState` | `(name: string)` | `string\|null` | 获取当前状态，自动检查冷却期 |
| `getCircuitInfo` | `(name: string)` | `object\|null` | 获取熔断器详情 |
| `getCircuitNames` | `()` | `string[]` | 获取所有熔断器名称 |
| `getByState` | `(state: string)` | `object[]` | 按状态筛选熔断器 |
| `recordSuccess` | `(name: string)` | `void` | 记录成功 |
| `recordFailure` | `(name: string)` | `void` | 记录失败 |
| `execute` | `(name: string, fn: Function)` | `Promise<any>` | 在熔断器保护下执行异步函数 |
| `forceOpen` | `(name: string)` | `boolean` | 强制跳闸 |
| `forceClose` | `(name: string)` | `boolean` | 强制闭合（重置失败计数） |
| `forceHalfOpen` | `(name: string)` | `boolean` | 强制半开 |
| `reset` | `(name: string)` | `boolean` | 重置单个熔断器 |
| `resetAll` | `()` | `boolean` | 重置所有熔断器 |

### create选项

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `failureThreshold` | number | 继承构造函数 | 该熔断器的失败阈值 |
| `successThreshold` | number | 继承构造函数 | 该熔断器的成功阈值 |
| `resetTimeout` | number | 继承构造函数 | 该熔断器的冷却期 |
| `maxHalfOpenCalls` | number | 1 | 半开状态最大探测请求数 |

### execute方法流程

```
execute(name, fn)
  │
  ├── 熔断器不存在 → throw HarnessError('DEEPENING_CIRCUIT_OPEN')
  │
  ├── state === 'open'
  │     ├── 冷却期已过 → 转为half_open, 继续执行
  │     └── 冷却期未过 → emit 'rejected', throw HarnessError
  │
  ├── state === 'half_open' && halfOpenCalls >= maxHalfOpenCalls
  │     └── emit 'rejected', throw HarnessError
  │
  ├── halfOpenCalls++
  │
  └── await fn()
        ├── 成功 → recordSuccess → 返回结果
        └── 失败 → recordFailure → 抛出异常
```

| `resetTimeout` | number | 30000 | 默认冷却期（ms） |

### 使用示例

```javascript
const DeepeningCircuitBreaker = require('./src/runtime/deepening/deepening-circuit-breaker');

const breaker = new DeepeningCircuitBreaker({
  failureThreshold: 3,
  successThreshold: 2,
  resetTimeout: 15000,
});

breaker.create('llm-api', { failureThreshold: 2, resetTimeout: 10000 });

breaker.on('circuit-state-change', ({ name, from, to }) => {
  console.log(`熔断器 ${name}: ${from} → ${to}`);
});

try {
  const result = await breaker.execute('llm-api', async () => {
    return await callLLMApi(prompt);
  });
} catch (e) {
  console.log('请求被熔断:', e.message);
}

console.log(breaker.getCircuitInfo('llm-api'));
console.log(breaker.getStats());
```

## DeepeningRateLimiter详解

### 职责概述

速率限制器提供三级限流能力：并发数限制、每分钟请求数限制、每小时请求数限制。同时内置令牌桶（Token Bucket）算法，支持按桶粒度的精细化流量控制。每个Agent可配置独立的限流参数。

### 构造函数参数

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `options.maxConcurrent` | number | 10 | 最大并发执行数 |
| `options.maxPerMinute` | number | 60 | 每分钟最大请求数 |
| `options.maxPerHour` | number | 1000 | 每小时最大请求数 |
| `options.maxAgentLimits` | number | 200 | 最大Agent限制配置数 |
| `options.defaultRate` | number | 10 | 令牌桶默认填充速率（每间隔） |
| `options.defaultCapacity` | number | 10 | 令牌桶默认容量 |
| `options.refillInterval` | number | 1000 | 令牌桶填充间隔（ms） |

### 核心API

#### 令牌桶操作

| 方法 | 签名 | 返回值 | 说明 |
|------|------|--------|------|
| `createBucket` | `(name: string, options?: object)` | `boolean` | 创建令牌桶 |
| `removeBucket` | `(name: string)` | `boolean` | 移除令牌桶 |
| `getBucketNames` | `()` | `string[]` | 获取所有桶名称 |
| `getBucket` | `(name: string)` | `object\|null` | 获取桶信息（自动补充令牌） |
| `tryConsume` | `(name: string, count?: number)` | `object` | 尝试消费令牌 |
| `resetBucket` | `(name: string)` | `boolean` | 重置桶 |
| `updateRate` | `(name: string, rate: number)` | `boolean` | 更新填充速率 |

#### createBucket选项

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `rate` | number | 继承defaultRate | 填充速率 |
| `capacity` | number | 继承defaultCapacity | 桶容量 |

#### tryConsume返回值

| 字段 | 类型 | 说明 |
|------|------|------|
| `allowed` | boolean | 是否允许 |
| `tokensRemaining` | number | 剩余令牌数（允许时） |
| `retryAfter` | number | 建议重试等待时间（ms，拒绝时） |

#### 并发限流操作

| 方法 | 签名 | 返回值 | 说明 |
|------|------|--------|------|
| `acquire` | `(executionId: string, agentId?: string)` | `boolean` | 获取执行许可 |
| `release` | `(executionId: string)` | `boolean` | 释放执行许可 |
| `setAgentLimit` | `(agentId: string, limits: object)` | `boolean` | 设置Agent专属限流 |
| `removeAgentLimit` | `(agentId: string)` | `boolean` | 移除Agent限流配置 |
| `getAvailability` | `()` | `object` | 获取可用配额 |

#### acquire限流流程

```
acquire(executionId, agentId)
  │
  ├── 已关闭 → return false
  │
  ├── 并发数 >= maxConcurrent → rejectedCount++, return false
  │
  ├── Agent分钟限流检查
  │     ├── 滑动窗口过期 → 重置计数
  │     └── count >= maxPerMinute → rejectedCount++, return false
  │
  ├── 小时限流检查
  │     └── count >= maxPerHour → return false
  │
  ├── 记录执行 → activeExecutions.set(executionId, {agentId, startTime})
  │
  └── acceptedCount++, return true
```

#### getAvailability返回值

```javascript
{
  concurrent: { available: number, max: number },
  perMinute:  { available: number, max: number },
  perHour:    { available: number, max: number },
}
```

### 事件列表

| 事件名 | 触发时机 | 数据 |
|--------|---------|------|
| `bucketCreated` | 桶创建 | `{ name, rate, capacity }` |
| `bucketRemoved` | 桶移除 | `{ name }` |
| `allowed` | 令牌消费成功 | `{ name, tokensRemaining }` |
| `denied` | 令牌消费失败 | `{ name, retryAfter }` |
| `bucketReset` | 桶重置 | `{ name }` |
| `rateUpdated` | 速率更新 | `{ name, newRate }` |

### 使用示例

```javascript
const DeepeningRateLimiter = require('./src/runtime/deepening/deepening-rate-limiter');

const limiter = new DeepeningRateLimiter({
  maxConcurrent: 5,
  maxPerMinute: 30,
  maxPerHour: 500,
  defaultRate: 5,
  defaultCapacity: 10,
});

limiter.createBucket('llm-calls', { rate: 3, capacity: 5 });

const result = limiter.tryConsume('llm-calls', 2);
if (result.allowed) {
  console.log('允许, 剩余令牌:', result.tokensRemaining);
} else {
  console.log('拒绝, 建议等待:', result.retryAfter, 'ms');
}

limiter.setAgentLimit('task-worker-1', { maxPerMinute: 20 });

if (limiter.acquire('exec-001', 'task-worker-1')) {
  try {
    await doWork();
  } finally {
    limiter.release('exec-001');
  }
}

console.log(limiter.getAvailability());
console.log(limiter.getStats());
```

## DeepeningLockManager详解

### 职责概述

锁管理器提供基于资源的分布式锁能力，支持可重入锁（同一owner可多次获取同一资源锁）、超时自动释放和过期锁清理。通过定期扫描机制自动释放超时锁，防止死锁。

### 构造函数参数

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `options.defaultTimeout` | number | `DEFAULT_PIPELINE_TIMEOUT_MS` | 锁默认超时时间（ms） |
| `options.maxLocks` | number | 1000 | 最大锁数量 |

### 核心API

| 方法 | 签名 | 返回值 | 说明 |
|------|------|--------|------|
| `acquire` | `(resourceId: string, ownerId: string, options?: object)` | `boolean` | 获取锁 |
| `release` | `(resourceId: string, ownerId: string)` | `boolean` | 释放锁（引用计数-1） |
| `forceRelease` | `(resourceId: string)` | `boolean` | 强制释放锁（忽略owner） |
| `isLocked` | `(resourceId: string)` | `boolean` | 检查资源是否被锁定 |
| `getLock` | `(resourceId: string)` | `object\|null` | 获取锁信息 |
| `getLocksByOwner` | `(ownerId: string)` | `object[]` | 获取owner持有的所有锁 |
| `getExpiredLocks` | `()` | `object[]` | 获取所有过期锁 |
| `releaseExpiredLocks` | `()` | `object[]` | 释放所有过期锁 |

### acquire选项

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `timeout` | number | 继承defaultTimeout | 该锁的超时时间（ms） |

### 可重入锁机制

```
acquire(resourceId, ownerId)
  │
  ├── 锁已存在 && ownerId相同 → refCount++, return true (可重入)
  │
  ├── 锁已存在 && ownerId不同 → emit 'denied', return false
  │
  ├── 锁数量 >= maxLocks → return false
  │
  └── 创建新锁 → { refCount: 1, acquiredAt, timeout }, emit 'acquired', return true
```

### release引用计数

```
release(resourceId, ownerId)
  │
  ├── 锁不存在 → return false
  │
  ├── ownerId不匹配 → return false
  │
  ├── refCount > 1 → refCount--, return true (仍持有)
  │
  └── refCount === 1 → 删除锁, emit 'released', return true (完全释放)
```

### 过期清理

- 清理间隔：`min(defaultTimeout / 2, DEFAULT_MIN_HEARTBEAT_MS)`
- 定时器调用 `unref()` 避免阻止进程退出
- `releaseExpiredLocks()` 自动扫描并释放过期锁

### 事件列表

| 事件名 | 触发时机 | 数据 |
|--------|---------|------|
| `acquired` | 锁获取 | `{ resourceId, ownerId, reentrant? }` |
| `denied` | 锁获取被拒 | `{ resourceId, ownerId }` |
| `released` | 锁释放 | `{ resourceId, ownerId }` 或 `{ resourceId, forced: true }` |
| `expired` | 锁过期自动释放 | `{ resourceId }` |

### 使用示例

```javascript
const DeepeningLockManager = require('./src/runtime/deepening/deepening-lock-manager');

const lockManager = new DeepeningLockManager({
  defaultTimeout: 60000,
  maxLocks: 500,
});

lockManager.on('acquired', ({ resourceId, ownerId, reentrant }) => {
  console.log(`锁获取: ${resourceId} by ${ownerId}${reentrant ? ' (可重入)' : ''}`);
});

lockManager.on('expired', ({ resourceId }) => {
  console.log(`锁过期: ${resourceId}`);
});

if (lockManager.acquire('file://config.json', 'worker-1', { timeout: 30000 })) {
  lockManager.acquire('file://config.json', 'worker-1');
  try {
    modifyConfig();
  } finally {
    lockManager.release('file://config.json', 'worker-1');
    lockManager.release('file://config.json', 'worker-1');
  }
}

console.log(lockManager.getLocksByOwner('worker-1'));
console.log(lockManager.getStats());
```

| 模块 | 交互方式 |
|------|---------|
| DeepeningResourceManager | LockManager保护资源互斥访问，ResourceManager管理资源容量 |
| DeepeningCircuitBreaker | 熔断器open时可配合LockManager阻止并发写入 |
| DeepeningPipeline | Pipeline在处理共享资源时通过LockManager避免冲突 |

## DeepeningResourceManager详解

### 职责概述

资源管理器提供双重资源管理能力：资源池（Pool）模式和容量分配（Allocation）模式。资源池支持工厂创建、验证、销毁和等待队列；容量分配支持注册资源、分配/释放/预留/取消预留，并追踪利用率。

### 构造函数参数

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `options.memoryCapacity` | number | — | 内存容量（bytes），自动注册memory资源 |
| `options.cpuCapacity` | number | — | CPU容量（percent），自动注册cpu资源 |
| `options.tokenCapacity` | number | — | Token容量，自动注册tokens资源 |
| `options.concurrentCapacity` | number | — | 并发容量（slots），自动注册concurrent资源 |

### 核心API

#### 资源池操作

| 方法 | 签名 | 返回值 | 说明 |
|------|------|--------|------|
| `createPool` | `(name: string, options?: object)` | `boolean` | 创建资源池 |
| `removePool` | `(name: string)` | `boolean` | 移除资源池 |
| `getPoolNames` | `()` | `string[]` | 获取所有池名称 |
| `getPoolInfo` | `(name: string)` | `object\|null` | 获取池信息 |
| `acquire` | `(name: string)` | `Promise<any>` | 从池中获取资源 |
| `release` | `(name: string, resource: any)` | `boolean` | 释放资源回池 |
| `destroy` | `(name: string, resource: any)` | `boolean` | 销毁资源 |
| `drainPool` | `(name: string)` | `boolean` | 排空池中空闲资源 |

#### createPool选项

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `maxSize` | number | 10 | 池最大资源数 |
| `minSize` | number | 0 | 池最小资源数（预创建） |
| `factory` | Function | null | 资源工厂函数 |
| `validate` | Function | null | 资源验证函数 |
| `destroy` | Function | null | 资源销毁函数 |
| `acquireTimeout` | number | 0 | 获取超时（ms），0=无限等待 |

#### acquire流程

```
acquire(name)
  │
  ├── 池不存在 → reject DeepeningError('RESOURCE_NOT_FOUND')
  │
  ├── 有空闲资源
  │     ├── validate检查 → 不通过 → destroy + factory创建新的
  │     └── 标记为inUse, emit 'acquired', resolve(resource)
  │
  ├── 无空闲但未达上限 → factory创建, 标记inUse, emit 'acquired', resolve
  │
  └── 已达上限
        ├── acquireTimeout > 0 → 排队等待，超时reject
        └── acquireTimeout === 0 → 排队等待，无超时
```

#### 容量分配操作

| 方法 | 签名 | 返回值 | 说明 |
|------|------|--------|------|
| `registerResource` | `(name: string, config?: object)` | `boolean` | 注册资源类型 |
| `getResourceInfo` | `(name: string)` | `object\|null` | 获取资源信息 |
| `allocate` | `(resource: string, amount: number)` | `string` | 分配资源，返回allocId |
| `releaseAlloc` | `(allocId: string)` | `boolean` | 释放分配 |
| `getAvailable` | `(resource: string)` | `number` | 获取可用量 |
| `getUtilization` | `(resource: string)` | `number` | 获取利用率（0-1） |
| `reserve` | `(resource: string, amount: number)` | `boolean` | 预留资源 |
| `unreserve` | `(resource: string, amount: number)` | `boolean` | 取消预留 |
| `getAllocationHistory` | `(filter?: object)` | `object[]` | 获取分配历史 |

#### registerResource配置

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `totalCapacity` | number | 100 | 总容量 |

#### allocate异常

- 可用量不足时抛出 `HarnessError('RESOURCE_EXHAUSTED')`
- 分配历史最大保留200条（`MAX_ALLOCATIONS`）

### 事件列表

| 事件名 | 触发时机 | 数据 |
|--------|---------|------|
| `poolCreated` | 池创建 | `{ name, maxSize, minSize }` |
| `poolRemoved` | 池移除 | `{ name }` |
| `acquired` | 资源获取 | `{ pool, resource }` |
| `released` | 资源释放 | `{ pool, resource }` |

### 使用示例

```javascript

const rm = new DeepeningResourceManager({
  memoryCapacity: 1024 * 1024 * 512,
  tokenCapacity: 100000,
  concurrentCapacity: 20,
});

rm.createPool('db-connections', {
  maxSize: 15,
  minSize: 3,
  factory: () => createDbConnection(),
  validate: (conn) => conn.isConnected(),
```

## DeepeningThrottle详解

### 职责概述

节流控制器提供基于键的计数限流能力。每个键维护独立的计数器，当计数达到限制时拒绝新的获取请求。支持手动释放计数、自动清理过期键。

### 构造函数参数

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `options.limit` | number | 10 | 每键最大并发数 |
| `options.interval` | number | 10000 | 节流间隔（ms） |

### 核心API

| 方法 | 签名 | 返回值 | 说明 |
|------|------|--------|------|
| `acquire` | `(key?: string)` | `boolean` | 获取许可，超限返回false |
| `release` | `(key?: string)` | `boolean` | 释放许可 |
| `getCount` | `(key?: string)` | `number` | 获取当前计数 |
| `getRemaining` | `(key?: string)` | `number` | 获取剩余配额 |
| `isThrottled` | `(key?: string)` | `boolean` | 是否已被节流 |
| `resetKey` | `(key: string)` | `boolean` | 重置指定键 |
| `resetAll` | `()` | `boolean` | 重置所有键 |
| `reset` | `(key?: string)` | `boolean` | 重置（有key重置单个，无key重置全部） |

### 过期清理

- `acquire`时自动清理超过60秒未活跃的键
- 最大键数10000（`MAX_THROTTLE_KEYS`），超出时淘汰最旧键

### 事件列表

| 事件名 | 触发时机 | 数据 |
|--------|---------|------|
| `acquired` | 获取许可 | `{ key }` |
| `released` | 释放许可 | `{ key }` |
| `throttled` | 被节流 | `{ key }` |

### 使用示例

```javascript
const DeepeningThrottle = require('./src/runtime/deepening/deepening-throttle');

const throttle = new DeepeningThrottle({ limit: 5, interval: 10000 });

throttle.on('throttled', ({ key }) => {
  console.log(`键 ${key} 被节流`);
});

if (throttle.acquire('agent-1')) {
  try {
    doWork();
  } finally {
    throttle.release('agent-1');
  }
} else {
  console.log('agent-1 已达并发上限');
}

console.log('当前计数:', throttle.getCount('agent-1'));
console.log('剩余配额:', throttle.getRemaining('agent-1'));
console.log('是否节流:', throttle.isThrottled('agent-1'));
console.log(throttle.getStats());
```

| 模块 | 交互方式 |
|------|---------|
| DeepeningRateLimiter | RateLimiter提供时间维度限流，Throttle提供并发维度限流 |
| DeepeningBackpressureManager | Throttle限制入口速率，BackpressureManager管理缓冲区压力 |
| DeepeningConcurrencyController | Throttle是轻量级并发控制，ConcurrencyController提供更完整的排队/超时 |

## DeepeningBackpressureManager详解

### 职责概述

背压管理器实现流式反压（Backpressure）机制，通过高水位线（highWatermark）和低水位线（lowWatermark）控制数据流速率。当缓冲区达到高水位线时自动暂停流入，降至低水位线时自动恢复。支持四级压力等级和手动暂停/恢复。

### 压力等级

```
                    highWatermark
                       │
    low ──── medium ──┤│──── critical
                       │
              low + (high-low)/2
```

| 等级 | 判定条件 | 说明 |
|------|---------|------|
| `low` | bufferSize < lowWatermark | 低压力，正常流转 |
| `medium` | lowWatermark ≤ bufferSize < midpoint | 中等压力 |
| `high` | midpoint ≤ bufferSize < highWatermark | 高压力，接近暂停 |
| `critical` | bufferSize ≥ highWatermark | 临界压力，触发暂停 |

### 构造函数参数

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `options.maxStreams` | number | 50 | 最大流数量 |
| `options.defaultHighWatermark` | number | 100 | 默认高水位线 |
| `options.defaultLowWatermark` | number | 20 | 默认低水位线 |

### 核心API

| 方法 | 签名 | 返回值 | 说明 |
|------|------|--------|------|
| `registerStream` | `(name: string, options?: object)` | `boolean` | 注册流 |
| `getStreamNames` | `()` | `string[]` | 获取所有流名称 |
| `push` | `(name: string, amount?: number)` | `object` | 推入数据 |
| `ack` | `(name: string, amount?: number)` | `object` | 确认处理 |
| `getPressure` | `(name: string)` | `object` | 获取压力等级 |
| `isPaused` | `(name: string)` | `boolean` | 是否暂停 |
| `forcePause` | `(name: string)` | `boolean` | 强制暂停 |
| `forceResume` | `(name: string)` | `boolean` | 强制恢复 |
| `resetStream` | `(name: string)` | `boolean` | 重置流 |
| `unregisterStream` | `(name: string)` | `boolean` | 注销流 |

#### registerStream选项

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `highWatermark` | number | 继承defaultHighWatermark | 高水位线 |
| `lowWatermark` | number | 继承defaultLowWatermark | 低水位线 |
| `maxBufferSize` | number | 1000 | 最大缓冲区大小 |

#### push返回值

| 字段 | 类型 | 说明 |
|------|------|------|
| `accepted` | boolean | 是否接受（暂停后仍接受直到maxBufferSize） |
| `bufferSize` | number | 当前缓冲区大小 |
| `reason` | string | 拒绝原因（仅暂停溢出时） |

#### push流程

```
push(name, amount)
  │
  ├── 流不存在 → throw HarnessError('BACKPRESSURE_ERROR')
  │
  ├── 已暂停 && bufferSize + amount > maxBufferSize
  │     └── 丢弃数据, emit 'dropped', return { accepted: false, reason: 'paused_overflow' }
  │
  ├── bufferSize += amount
  │
  ├── 压力等级变更 → emit 'pressureChanged'
  │
  ├── bufferSize >= highWatermark && 未暂停
  │     └── 暂停流, emit 'paused'
  │
  └── return { accepted: !paused, bufferSize }
```

### 事件列表

| 事件名 | 触发时机 | 数据 |
|--------|---------|------|
| `streamRegistered` | 流注册 | `{ name, highWatermark }` |
| `streamUnregistered` | 流注销 | `{ name }` |
| `pressureChanged` | 压力等级变更 | `{ from, to }` |
| `paused` | 流暂停 | `{ name }` |
| `dropped` | 数据丢弃 | `{ count }` |
| `streamReset` | 流重置 | `{ name }` |

### 静态常量

| 常量 | 值 |
|------|-----|
| `PRESSURE_LEVELS.LOW` | `'low'` |
| `PRESSURE_LEVELS.MEDIUM` | `'medium'` |
| `PRESSURE_LEVELS.HIGH` | `'high'` |
| `PRESSURE_LEVELS.CRITICAL` | `'critical'` |

### 使用示例

```javascript
const DeepeningBackpressureManager = require('./src/runtime/deepening/deepening-backpressure-manager');

const bpm = new DeepeningBackpressureManager({
  maxStreams: 20,
  defaultHighWatermark: 50,
  defaultLowWatermark: 10,
});

bpm.registerStream('task-queue', { highWatermark: 100, lowWatermark: 20, maxBufferSize: 500 });

bpm.on('pressureChanged', ({ from, to }) => {
  console.log(`压力变更: ${from} → ${to}`);
});

bpm.on('paused', ({ name }) => {
  console.log(`流 ${name} 已暂停，停止推送`);
});

bpm.on('dropped', ({ count }) => {
  console.log(`丢弃 ${count} 条数据`);
});

const result = bpm.push('task-queue', 5);
console.log('接受:', result.accepted, '缓冲区:', result.bufferSize);

bpm.ack('task-queue', 3);
console.log('压力:', bpm.getPressure('task-queue'));
console.log(bpm.getStats());
```

### 与其他模块的交互关系

| 模块 | 交互方式 |
|------|---------|
| DeepeningThrottle | Throttle限制入口速率，BackpressureManager根据缓冲区压力动态调节 |
| DeepeningRateLimiter | RateLimiter拒绝超限请求，BackpressureManager暂停超压流 |
| DeepeningConnectionPool | 连接池满时可触发背压暂停 |
| DeepeningPipeline | Pipeline的各阶段间通过BackpressureManager协调流速 |

## DeepeningConnectionPool详解

### 职责概述

连接池管理器提供连接的获取、释放、空闲超时和错误标记能力。每个池维护active（使用中）和idle（空闲）两个队列，空闲连接超过idleTimeout自动清理。

### 构造函数参数

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `options.maxPools` | number | 50 | 最大连接池数量 |
| `options.defaultMaxConnections` | number | 10 | 默认最大连接数 |
| `options.defaultIdleTimeout` | number | `DEFAULT_CACHE_TTL_MS` | 默认空闲超时（ms） |

### 核心API

| 方法 | 签名 | 返回值 | 说明 |
|------|------|--------|------|
| `createPool` | `(name: string, options?: object)` | `boolean` | 创建连接池 |
| `getPoolNames` | `()` | `string[]` | 获取所有池名称 |
| `acquire` | `(name: string, options?: object)` | `object\|null` | 获取连接 |
| `release` | `(name: string, connectionId: string)` | `boolean` | 释放连接 |
| `markError` | `(name: string, connectionId: string)` | `boolean` | 标记连接错误 |
| `getPoolInfo` | `(name: string)` | `object\|null` | 获取池信息 |
| `drainPool` | `(name: string)` | `number` | 排空空闲连接，返回清理数量 |
| `removePool` | `(name: string)` | `boolean` | 移除连接池 |

#### createPool选项

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `maxConnections` | number | 继承defaultMaxConnections | 最大连接数 |
| `idleTimeout` | number | 继承defaultIdleTimeout | 空闲超时（ms） |

#### acquire选项

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `queue` | boolean | true | 池满时是否排队，false时抛出异常 |

#### acquire流程

```
acquire(name, options)
  │
  ├── 池不存在 → throw HarnessError('CONNECTION_FAILED')
  │
  ├── 清理过期idle连接
  │
  ├── 活跃数 >= maxConnections
  │     ├── queue === false → throw Error('Connection pool exhausted')
  │     └── return null (排队等待)
  │
  ├── 有idle连接 → 复用, useCount++, emit 'acquired'
  │
  └── 无idle连接 → 创建新连接, emit 'acquired'
```

#### acquire返回值

| 字段 | 类型 | 说明 |
|------|------|------|
| `connectionId` | string | 连接标识 |
| `state` | string | 连接状态（'active'） |
| `useCount` | number | 使用次数 |

### 连接状态

| 常量 | 值 | 说明 |
|------|-----|------|
| `CONNECTION_STATES.IDLE` | `'idle'` | 空闲 |
| `CONNECTION_STATES.ACTIVE` | `'active'` | 使用中 |
| `CONNECTION_STATES.ERROR` | `'error'` | 错误 |

### 事件列表

| 事件名 | 触发时机 | 数据 |
|--------|---------|------|
| `poolCreated` | 池创建 | `{ name, maxConnections }` |
| `poolRemoved` | 池移除 | `{ name }` |
| `acquired` | 连接获取 | `{ pool: name }` |
| `released` | 连接释放 | `{ pool: name }` |
| `idleTimeout` | 空闲连接超时 | `{ pool: name, connectionId }` |
| `rejected` | 连接被拒 | `{ pool: name }` |
| `connection-error` | 连接错误 | `{ connectionId }` |

### 使用示例

```javascript
const DeepeningConnectionPool = require('./src/runtime/deepening/deepening-connection-pool');

const pool = new DeepeningConnectionPool({
  maxPools: 10,
  defaultMaxConnections: 20,
  defaultIdleTimeout: 30000,
});

pool.createPool('postgres', { maxConnections: 5, idleTimeout: 30000 });

  console.log('连接ID:', conn.connectionId, '使用次数:', conn.useCount);
  try {
    await redisCommand(conn.connectionId);
  } finally {
    pool.release('redis', conn.connectionId);
  }
}

console.log(pool.getPoolInfo('redis'));
console.log(pool.getStats());
```

## DeepeningLoadBalancer详解

### 职责概述

负载均衡器提供四种实例选择策略，支持健康状态标记和连接计数追踪。每个负载均衡池独立配置策略，实例可标记为健康/不健康，选择时自动过滤不健康实例。

### 负载均衡策略

| 策略 | 常量 | 说明 |
|------|------|------|
| `round_robin` | `STRATEGIES.ROUND_ROBIN` | 轮询：按顺序依次选择 |

## DeepeningTimeoutManager详解

### 职责概述

超时管理器提供定时器创建、取消、完成追踪和函数包装能力。每个超时拥有唯一ID和名称，支持查询剩余时间和截止时间。`wrap`方法可自动为同步/异步函数添加超时追踪。

### 构造函数参数

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `options.defaultTimeout` | number | `DEFAULT_REQUEST_TIMEOUT_MS` | 默认超时时间（ms） |

### 核心API

| 方法 | 签名 | 返回值 | 说明 |
|------|------|--------|------|
| `setTimeout` | `(name: string, options?: object)` | `string` | 创建超时，返回超时ID |
| `cancel` | `(id: string)` | `boolean` | 取消超时 |
| `complete` | `(id: string)` | `boolean` | 标记完成（计算耗时） |
| `getRemaining` | `(id: string)` | `number` | 获取剩余时间（ms） |
| `getDeadline` | `(id: string)` | `number\|null` | 获取截止时间戳 |
| `getInfo` | `(id: string)` | `object\|null` | 获取超时信息 |
| `getActive` | `()` | `object[]` | 获取所有活跃超时（按截止时间排序） |
| `getActiveCount` | `()` | `number` | 活跃超时数量 |
| `cancelAll` | `()` | `number` | 取消所有超时，返回取消数量 |
| `wrap` | `(fn: Function, options?: object)` | `Function` | 包装函数，自动追踪超时 |

#### setTimeout选项

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `duration` | number | 继承defaultTimeout | 超时时长（ms） |
| `onTimeout` | Function | null | 超时回调 |

#### setTimeout流程

```
setTimeout(name, options)
  │
  ├── 生成唯一ID (counterId)
  │
  ├── 计算deadline = Date.now() + duration
  │
  ├── 创建global.setTimeout
  │     └── 到期 → 删除记录, 调用onTimeout, emit 'expired'
  │
  ├── 记录到_timeouts Map
  │
  └── emit 'created', return id
```

#### wrap方法

```javascript
const wrappedFn = timeoutManager.wrap(originalFn, { duration: 5000 });
const result = wrappedFn(arg1, arg2);
```

- 同步函数：执行后自动 `complete`
- 异步函数：Promise resolve后 `complete`，reject后 `cancel`
- 同步异常：`cancel` 后重新抛出

### 事件列表

| 事件名 | 触发时机 | 数据 |
|--------|---------|------|
| `created` | 超时创建 | `{ name, duration }` |
| `expired` | 超时到期 | `{ id, name }` |
| `cancelled` | 超时取消 | `{ id }` |
| `completed` | 超时完成 | `{ name, elapsed }` |
| `cancelledAll` | 全部取消 | `{ count }` |

### 使用示例

```javascript
const DeepeningTimeoutManager = require('./src/runtime/deepening/deepening-timeout-manager');

const tm = new DeepeningTimeoutManager({ defaultTimeout: 30000 });

tm.on('expired', ({ id, name }) => {
  console.log(`超时: ${name} (${id})`);
});

const id = tm.setTimeout('api-call', {
  duration: 10000,
  onTimeout: () => console.log('API调用超时!'),
});

try {
  const result = await callAPI();
  tm.complete(id);
} catch (e) {
  tm.cancel(id);
  throw e;
}

const safeFetch = tm.wrap(async (url) => {
  return await fetch(url);
}, { duration: 5000 });

console.log('活跃超时:', tm.getActiveCount());
console.log(tm.getStats());
```

## DeepeningHealthMonitor详解

### 职责概述

健康监控器提供周期性健康检查能力，支持注册自定义检查函数、四级聚合状态、历史记录和单次/批量检查。每个检查可配置超时和critical标志，critical检查不通过时整体状态升级为critical。

> **注意**：该模块已标记为deprecated，推荐使用 `runtime/infrastructure/health-checker` 中的 `HealthChecker`。当前版本仍可正常使用。

### 四级状态

| 状态 | 判定条件 | 说明 |
|------|---------|------|
| `healthy` | 所有检查通过 | 系统健康 |
| `degraded` | 部分检查不通过 | 降级运行 |
| `unhealthy` | 全部检查不通过 或 超过半数不通过 | 系统不健康 |
| `critical` | 任何标记为critical的检查不通过 | 关键故障 |

### 构造函数参数

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `options.historySize` | number | 100 | 历史记录容量 |
| `options.interval` | number | `DEFAULT_HEARTBEAT_INTERVAL_MS` | 周期检查间隔（ms） |
| `options.timeout` | number | `DEFAULT_MIN_HEARTBEAT_MS` | 单次检查超时（ms） |

### 核心API

| 方法 | 签名 | 返回值 | 说明 |
|------|------|--------|------|
| `register` | `(name: string, checkFn: Function, options?: object)` | `boolean` | 注册检查 |
| `registerCheck` | `(name: string, checkFn: Function, options?: object)` | `boolean` | 注册检查（参数验证更严格） |
| `unregister` | `(name: string)` | `boolean` | 注销检查 |
| `unregisterCheck` | `(name: string)` | `boolean` | 注销检查（别名） |
| `check` | `()` | `Promise<object>` | 执行所有检查 |
| `runCheck` | `(name: string)` | `Promise<object>` | 执行单项检查 |
| `runAllChecks` | `()` | `Promise<object>` | 执行所有检查（别名） |
| `getResult` | `(name: string)` | `object\|null` | 获取最近检查结果 |
| `getHistory` | `(limit?: number)` | `object[]` | 获取历史记录 |
| `getLastReport` | `()` | `object\|null` | 获取最近报告 |
| `start` | `()` | `boolean` | 启动周期检查 |
| `startPeriodicCheck` | `(interval?: number)` | `boolean` | 启动周期检查（可指定间隔） |

| `getModuleNames` | `()` | `string[]` | 获取所有检查名称 |

#### register选项

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `timeout` | number | 继承构造函数 | 该检查的超时时间 |
| `critical` | boolean | false | 是否为关键检查 |

#### check流程

```
check()
  │
  ├── 遍历所有注册的检查函数
  │     ├── Promise.race([checkFn(), timeout])
  │     │     ├── 成功 → normalizeResult (支持多种返回格式)
  │     │     └── 超时/异常 → { status: 'unhealthy', message }
  │     └── 结果推入results数组
  │
  ├── 计算聚合状态 (_computeStatus)
  │     ├── 全部healthy → 'healthy'
  │     ├── 部分unhealthy → 'degraded'
  │     ├── 全部unhealthy → 'unhealthy'
  │     ├── critical检查不通过 → 'critical'
  │     └── 超过半数unhealthy → 'unhealthy'
  │
  ├── 计算健康分数 (0-100)
  │
  ├── 记录到历史 (RingBuffer)
  │
  └── emit 'check'/'report'/'health-checked'
        └── status !== 'healthy' → emit 'health-degraded'
```

#### check返回值

| 字段 | 类型 | 说明 |
|------|------|------|
| `status` | string | 聚合状态 |
| `score` | number | 健康分数（0-100） |
| `results` | Array | 各检查结果 |
| `timestamp` | number | 检查时间戳 |
| `healthy` | boolean | 是否健康 |
| `moduleCount` | number | 检查模块总数 |
| `healthyCount` | number | 健康模块数 |
| `unhealthyCount` | number | 不健康模块数 |

| `health-degraded` | 状态非healthy | 完整报告对象 |

### 使用示例

```javascript

const monitor = new DeepeningHealthMonitor({
  historySize: 50,
  interval: 30000,
  timeout: 5000,
});

monitor.registerCheck('database', async () => {
  const ok = await db.ping();
  return { status: ok ? 'healthy' : 'unhealthy', message: ok ? 'DB connected' : 'DB down' };
}, { critical: true, timeout: 3000 });

  return await cache.isAvailable();
});

monitor.register('memory', () => {
  const used = process.memoryUsage().heapUsed;
  const limit = 512 * 1024 * 1024;

  console.log('健康降级:', report.status, '分数:', report.score);
  for (const r of report.results) {
    if (r.status !== 'healthy') console.log(`  - ${r.name}: ${r.message}`);
  }
});

const report = await monitor.check();
console.log('状态:', report.status, '分数:', report.score);

const history = monitor.getHistory(5);
console.log('最近5次检查:', history.length);

console.log(monitor.getStats());
```

## R38 修复记录

### `??` vs `||` 运算符误用系统性修复

**缺陷**：多个模块的数值配置参数使用`??`（空值合并）运算符提供默认值。对于计数型/容量型参数（如maxSize、maxHistory、limit等），`0`作为配置值通常无意义且可能导致功能异常（如容量为0导致所有数据被拒绝），应使用`||`运算符在`0`时也回退到默认值。

**修复**：将以下参数从`??`改为`||`运算符：

| 模块 | 参数 | 修复 |
|------|------|------|
| DeepeningCircuitBreaker | maxCircuits ?? 100 | maxCircuits \|\| 100 |
| DeepeningCache | maxSize ?? 1000 | maxSize \|\| 1000 |
| DeepeningBackpressureManager | defaultHighWatermark ?? 100 | defaultHighWatermark \|\| 100 |
| DeepeningBackpressureManager | maxBufferSize ?? 1000 | maxBufferSize \|\| 1000 |
| DeepeningHealthMonitor | historySize ?? 100 | historySize \|\| 100 |
| DeepeningRateLimiter | maxPerHour ?? 1000 | maxPerHour \|\| 1000 |
| DeepeningRateLimiter | maxAgentLimits ?? 200 | maxAgentLimits \|\| 200 |
| DeepeningRateLimiter | refillInterval ?? 1000 | refillInterval \|\| 1000 |
| DeepeningRateLimiter | maxBuckets ?? 100 | maxBuckets \|\| 100 |
| DeepeningLockManager | maxLocks ?? 1000 | maxLocks \|\| 1000 |
| DeepeningEventBus | maxDeadLetters ?? 100 | maxDeadLetters \|\| 100 |
| DeepeningEventBus | maxSubscriptions ?? 500 | maxSubscriptions \|\| 500 |
| DeepeningErrorHandler | retryDelay ?? 100 | retryDelay \|\| 100 |
| DeepeningErrorHandler | maxErrorLogSize ?? 500 | maxErrorLogSize \|\| 500 |
| DeepeningGracefulShutdown | this._timeout ?? 5000 | this._timeout \|\| 5000 |

**影响范围**：数值配置参数为0时正确回退到默认值，避免功能异常。

## R20 修复记录

### Map.get()参数遗漏BUG修复（2处）

**缺陷**：`deepening-validator.js`的`getSchema`、`deepening-event-replay.js`的`getEvent`、`deepening-retry-policy.js`的`getPolicy`、`deepening-service-registry.js`的`getService`、`deepening-feature-flags.js`的`getFlag`方法中，调用`Map.get()`时未将查询参数传入，导致`Map.get()`始终返回`null`，查询功能完全失效。

**修复**：将`Map.get()`调用补充正确的参数传递，确保查询键值正确传入Map查找。

**影响范围**：深化子系统Schema/事件/策略/服务/特性标志查询功能恢复正常，不再始终返回null。

### isHealthy()关闭状态检查修复

**缺陷**：`deepening-throttle.js`的`isHealthy()`方法覆盖了基类`DeepeningBase`的默认实现（`return !this._shutDown`），改为`return true`，丢失了关闭状态检查。关闭后的Throttle实例仍报告为健康状态，可能被继续调用。

**修复**：将`isHealthy()`修复为`return !this._shutDown`，恢复关闭状态检查。

**影响范围**：关闭后的DeepeningThrottle正确报告不健康状态，不再被误用。
