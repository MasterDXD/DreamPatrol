# 第一部分：架构概览

## 概述

梦境引擎子系统（Dream Engine Subsystem）是思维子系统的核心组件，负责在空闲时段对历史会话数据进行离线经验提炼。系统从会话中的错误、经验教训、关键决策和技能执行记录中提取三类模式——错误模式（error_patterns）、成功模式（success_patterns）和工作流模式（workflow_patterns），并将这些模式转化为结构化笔记（Dream Notes），通过相似度合并去重后持久化存储并同步到记忆系统。

子系统包含三个核心模块和一个桥接模块，协同完成"模式提取→笔记生成→效果追踪→反馈闭环"的完整生命周期：

- **DreamEngine**：核心引擎，执行做梦流程，分析会话、提取模式、生成笔记
- **DreamOutcomes**：闭环追踪，定义成功标准、评估达成情况、追踪笔记实际效果
- **DreamScheduler**：调度触发，周期性定时回顾和会话结束即时做梦
- **DreamBridge**（辅助桥接）：事件驱动的模块间自动数据传递，串联闭环

## 模块清单

| 模块 | 源文件 | 说明 |
|------|--------|------|
| DreamEngine | dream-engine.js | 做梦引擎主入口，会话分析、模式提取、笔记生成与合并、持久化与同步 |
| DreamOutcomes | dream-outcomes.js | Outcomes闭环，成功标准定义、加权评分评估、笔记效果追踪、反馈同步 |
| DreamScheduler | dream-scheduler.js | 做梦调度器，定时周期回顾、会话结束即时触发、SM2自适应间隔调整 |
| DreamBridge | dream-bridge.js | 模块间桥接器，7条自动桥接规则、事件驱动数据传递、内存泄漏防护 |

## 关键依赖关系

- **DreamScheduler** 是调度入口，持有DreamEngine引用，通过`startDreaming()`触发做梦
- **DreamEngine** 是核心引擎，可附加SqliteStore（持久化）、ThoughtMemoryStore（思维检索）、EmbeddingService（语义相似度）、BrainMemory和MemoryStore（记忆同步）
- **DreamOutcomes** 是闭环追踪器，可附加DreamEngine（反馈同步）和SkillImprovementLoop（改进飞轮同步）
- **DreamBridge** 是桥接层，将7个模块通过事件监听串联为闭环，无需上层业务手动编排

# 第二部分：架构设计详解

## DreamEngine 设计

### 核心职责

DreamEngine是梦境引擎子系统的核心，负责：

- 会话数据多源采集（errors、lessonsLearned、keyDecisions、completedSkills、output、artifacts）
- 三类模式提取（错误模式、成功模式、工作流模式）
- 笔记生成与相似度合并（Jaccard + 编辑距离混合相似度）
- 笔记持久化（SQLite）与记忆系统同步（BrainMemory + MemoryStore）
- 上下文相关笔记检索（关键词重叠 + 语义相似度混合评分）

### 做梦流程

```
startDreaming(sessionHistory)
    │
    ├── 1. 互斥检查（_dreaming标志防重入）
    ├── 2. 截取会话（maxSessionsPerDream限制）
    ├── 3. 模式提取（_analyzePatterns）
    │       ├── _extractErrorPatterns（ERROR_MARKERS匹配）
    │       ├── _extractSuccessPatterns（SUCCESS_MARKERS匹配）
    │       └── _extractWorkflowPatterns（WORKFLOW_MARKERS匹配）
    ├── 4. 笔记生成（_extractNotes）
    │       ├── error_patterns → error-avoidance笔记
    │       ├── success_patterns → best-practice笔记
    │       └── workflow_patterns → workflow-optimization笔记
    ├── 5. 笔记合并（_mergeWithExistingNotes）
    │       ├── 同类别+相似度≥threshold → 合并（取最高置信度、合并来源会话）
    │       └── 相似度<threshold → 新增
    ├── 6. 持久化（_persistToSqlite）
    ├── 7. 记忆同步（syncNotesToStores，置信度≥0.7）
    └── 8. 返回结果（dreamId、模式统计、笔记统计）
```

### 相似度计算

DreamEngine采用混合相似度算法，结合Jaccard词集重叠和编辑距离：

```
similarity = Jaccard × 0.6 + EditDistance × 0.4
```

- **Jaccard相似度**：两个文本词集的交集/并集比，衡量词汇重叠程度
- **编辑距离相似度**：`1 - levenshtein(a, b) / max(len(a), len(b))`，衡量字符级差异
- 当相似度 ≥ `similarityThreshold`（默认0.75）且类别相同时，执行笔记合并

### 笔记检索评分

`getRelevantNotes(context)`采用关键词重叠和语义相似度混合评分：

```
relevance = keywordScore × 0.6 + semanticScore × 0.4
```

- **关键词重叠**：查询词集与笔记内容词集的交集/查询词集大小比
- **语义相似度**：通过EmbeddingService计算余弦相似度（可选，未附加时为0）
- 额外搜索ThoughtMemoryStore中的相关思维链，去重后合并到结果中
- 返回relevance > 0.1的笔记，按相关度降序排列，最多20条

### 笔记合并与裁剪

- 合并策略：同类别笔记相似度达标时，取最高置信度、合并来源会话集合、递增merge_count
- 容量控制：笔记总数超过`maxNotes`（默认500）时，按置信度降序保留Top-N
- 事务安全：合并过程出错时回滚到合并前快照

## DreamOutcomes 设计

### 核心职责

DreamOutcomes是梦境引擎的闭环追踪模块，负责：

- 为任务/会话/技能定义结构化成功标准
- 加权评分评估任务结果是否达成Outcomes
- 追踪DreamEngine笔记的实际使用效果
- 将评估结果反馈同步到DreamEngine和SkillImprovementLoop

### 加权评分模型

```
score = Σ(ratio_i × weight_i) / Σ(weight_i)
achieved = score >= 0.8
```

- 对每个metric，计算达成比率 `ratio = min(actual / target, 1)`
- 支持`direction: 'minimize'`指标（如错误数），此时 `ratio = min(target / actual, 1)`
- 0.8阈值遵循帕累托原则——80%加权达成率即视为成功

### 笔记效果追踪

```
笔记生成 → 使用(recordNoteUsage) → 效果评估(recordNoteOutcome) → 低效清理(getLowEffectivenessNotes)
```

- 有效率 = effective / (effective + ineffective)
- 低于阈值（默认0.3）的笔记标记为低效，供清理决策
- 容量上限MAX_NOTE_USAGE=500，超出时LRU淘汰

### 反馈闭环

两条反馈路径形成"评估→提炼→改进"的循环：

1. **→ DreamEngine**：评估结果映射为会话输入（达成→lessonsLearned，未达成→errors）
2. **→ SkillImprovementLoop**：评估结果映射为learning记录（达成→whatWorked，未达成→whatFailed）

## DreamScheduler 设计

### 核心职责

DreamScheduler是梦境引擎的调度组件，负责：

- 定时周期回顾（按配置间隔自动触发DreamEngine）
- 会话结束即时做梦（会话关闭时立即提炼当前会话思维数据）
- SM2自适应间隔调整（根据做梦效果动态调整回顾频率）

### 双触发模式

| 模式 | 方法 | 触发条件 | 说明 |
|------|------|---------|------|
| **定时周期** | `start()` / `_periodicReview()` | 按intervalMs间隔 | 调用sessionHistoryProvider获取历史会话，触发DreamEngine |
| **会话结束** | `onSessionEnd()` | 会话关闭时 | 将当前会话思维数据直接传递给DreamEngine |

### SM2自适应间隔

DreamScheduler引入SM2间隔重复算法，根据做梦效果动态调整回顾频率：

| 效果表现 | 性能评分 | 稳定性调整 | 间隔影响 |
|---------|---------|-----------|---------|
| 优秀 | ≥ 0.9 | stability × 1.3 × 2.5 | 大幅延长（低频回顾） |
| 良好 | 0.6 ~ 0.9 | stability × 2.0 | 适度延长 |
| 较差 | < 0.6 | stability × 0.8 | 缩短（高频回顾） |

- 稳定性范围：[1, 365]天
- 最小间隔：1分钟
- 目标保持率：0.9（90%）

## 1. DreamEngine — 做梦引擎

**源文件**：[dream-engine.js](../../src/runtime/thought/dream-engine.js)

### 职责概述

做梦引擎是梦境引擎子系统的核心，编排会话分析、模式提取、笔记生成与合并、持久化与记忆同步的完整流程。

### 构造函数参数

```javascript
new DreamEngine(options)
```

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `options.maxNotes` | `number` | `500` | 笔记最大容量，超出时按置信度裁剪 |
| `options.maxSessionsPerDream` | `number` | `20` | 单次做梦最大处理会话数 |
| `options.similarityThreshold` | `number` | `0.75` | 笔记合并相似度阈值 |
| `options.minPatternFrequency` | `number` | `2` | 模式最低出现频率，低于此值的模式被过滤 |
| `options.minConfidence` | `number` | `0.6` | 最低置信度阈值，低于此值的模式被过滤 |

**静态属性**：`DreamEngine.DEFAULT_CONFIG`、`DreamEngine.NOTE_CATEGORIES`、`DreamEngine.PATTERN_TYPES`

### 公共方法签名

| 方法 | 签名 | 返回值 | 说明 |
|------|------|--------|------|
| `attachSqliteStore` | `attachSqliteStore(sqliteStore: object\|null)` | `void` | 附加SQLite存储，自动恢复已有笔记 |
| `attachThoughtMemoryStore` | `attachThoughtMemoryStore(store: object\|null)` | `void` | 附加思维记忆存储，用于检索相关思维链 |
| `attachEmbeddingService` | `attachEmbeddingService(service: object\|null)` | `void` | 附加嵌入服务，用于语义相似度计算 |
| `attachBrainMemory` | `attachBrainMemory(brainMemory: object\|null)` | `void` | 附加脑记忆实例，用于笔记同步 |
| `attachMemoryStore` | `attachMemoryStore(memoryStore: object\|null)` | `void` | 附加记忆存储，用于笔记同步 |
| `startDreaming` | `async startDreaming(sessionHistory: Array)` | `object\|null` | 启动做梦流程，分析会话并提取笔记 |
| `getNotes` | `getNotes(category?: string, minConfidence?: number)` | `Array<object>` | 获取笔记，可按类别和置信度过滤 |
| `getRelevantNotes` | `getRelevantNotes(context: string)` | `Array<object>` | 根据上下文检索相关笔记 |
| `syncNotesToStores` | `syncNotesToStores(minConfidence?: number)` | `{synced, errors}` | 同步笔记到BrainMemory和MemoryStore |
| `getStats` | `getStats()` | `object` | 获取统计信息 |
| `isHealthy` | `isHealthy()` | `boolean` | 健康检查（未关闭且错误数<100） |

### startDreaming返回值结构

```javascript
{
  dreamId: 'drm-xxxx',          // 做梦唯一标识
  sessionsAnalyzed: 15,         // 分析的会话数
  patternsFound: {              // 发现的模式
    error_patterns: [...],
    success_patterns: [...],
    workflow_patterns: [...]
  },
  notesCreated: 8,              // 新创建的笔记数
  notesMerged: 3,               // 合并到已有笔记的数量
  notesAdded: 5,                // 新增的笔记数量
  totalNotes: 42,               // 笔记总数
  dreamedAt: '2026-06-03T...',  // 做梦时间
  notesSynced: 30,              // 同步到记忆系统的笔记数
  syncErrors: 0                 // 同步错误数
}
```

### 事件列表

| 事件名 | 载荷 | 触发时机 |
|--------|------|----------|
| `dream-complete` | 做梦结果对象 | 做梦流程成功完成 |
| `dream-error` | `{error, dreamCount}` | 做梦流程出错 |
| `notes-synced` | `{synced, errors, threshold}` | 笔记同步到记忆系统完成 |
| `semantic-score-error` | `{error}` | 语义评分计算出错 |

### 使用示例

```javascript
const DreamEngine = require('./src/runtime/thought/dream-engine');

const engine = new DreamEngine({
  maxNotes: 500,
  maxSessionsPerDream: 20,
  similarityThreshold: 0.75,
  minPatternFrequency: 2,
  minConfidence: 0.6,
});

engine.attachSqliteStore(sqliteStore);
engine.attachEmbeddingService(embeddingService);
engine.attachBrainMemory(brainMemory);
engine.attachMemoryStore(memoryStore);

const result = await engine.startDreaming(sessionHistory);
if (result) {
  console.log(`Dream ${result.dreamId}: analyzed ${result.sessionsAnalyzed} sessions`);
  console.log(`Patterns: ${result.patternsFound.error_patterns.length} errors, ` +
    `${result.patternsFound.success_patterns.length} successes, ` +
    `${result.patternsFound.workflow_patterns.length} workflows`);
  console.log(`Notes: ${result.notesCreated} created, ${result.notesMerged} merged`);
}

const relevantNotes = engine.getRelevantNotes('database connection timeout error');
console.log(`Found ${relevantNotes.length} relevant notes`);

const stats = engine.getStats();
console.log(`Total dreams: ${stats.totalDreams}, Notes: ${stats.totalNotes}`);
```

### 事件列表

| 事件名 | 载荷 | 触发时机 |

# 三阶段记忆巩固流水线（v2.72.0融合OpenClaw 4.5 Dreaming）

> 版本：v2.72.0 | 源文件：[dream-phase-pipeline.js](../../src/runtime/thought/dream-phase-pipeline.js)

## 概述

DreamPhasePipeline是v2.72.0融合OpenClaw 4.5 Dreaming架构引入的三阶段记忆巩固流水线，借鉴OpenClaw 4.5的Light/Deep/REM三阶段Dreaming架构，实现记忆从短期到长期的结构化晋升。该模块与DreamEngine无缝集成，通过`attachPhasePipeline`注入后，DreamEngine即可使用`startDreamingWithPhases`方法执行三阶段流水线做梦流程。

## 三阶段流水线说明

### Light Sleep（浅睡阶段）

- **职责**：扫描近期会话，标记候选记忆
- **输入**：历史会话数组（sessionHistory）
- **输出**：候选记忆列表（candidates）
- **处理逻辑**：
  1. 从会话中提取文本条目（errors/lessonsLearned/keyDecisions/completedSkills/output/artifacts）
  2. 规范化文本并去重（BoundedArray + BoundedMap，上限500条）
  3. 根据标记词分类候选记忆类别（preference/fact/correction/workflow/decision/noise）
  4. 计算6维初始信号值

### Deep Sleep（深睡阶段）

- **职责**：6维加权评分 + 3门控阈值过滤
- **输入**：Light阶段产出的候选记忆 + 已有长期记忆笔记
- **输出**：晋升（promoted）/ 拒绝（rejected）/ 更新（updated）结果
- **处理逻辑**：
  1. 噪音类别（noise）永远不晋升
  2. 计算6维加权综合评分
  3. 检查3个门控阈值
  4. 与已有笔记进行冲突检测（相似度≥0.6视为冲突）
  5. 冲突时合并（取最高评分、合并来源会话），无冲突时晋升

### REM Sleep（快速眼动阶段）

- **职责**：提取主题和反思信号
- **输入**：Deep阶段晋升的记忆 + 所有长期记忆笔记
- **输出**：主题列表（themes）+ 反思信号列表（reflections）
- **处理逻辑**：
  1. 基于关键词共现提取主题（最少2次共现，最多50个主题）
  2. 从主题和类别分布中生成反思信号（最多20条）
  3. 反思类型：cross_pattern（跨模式关联）、category_dominance（类别主导）

## 6维加权评分机制

借鉴OpenClaw 4.5的6维评分体系，对候选记忆进行综合评估：

| 维度 | 权重 | 说明 | 计算方式 |
|------|------|------|---------|
| Frequency | 0.24 | 出现频率 | 在会话中出现的频率（归一化到0-1） |
| Relevance | 0.30 | 相关性 | 基于文本长度和内容丰富度的初始估计 |
| QueryDiversity | 0.15 | 查询多样性 | 不同来源/上下文数量 |
| Recency | 0.15 | 新鲜度 | 时间衰减评分（半衰期7天） |
| Consolidation | 0.10 | 巩固程度 | 多日复发累积值（初始为0） |
| ConceptualRichness | 0.06 | 概念丰富度 | 概念标签密度（标签数/8） |

**综合评分公式**：

```
score = frequency×0.24 + relevance×0.30 + queryDiversity×0.15 + recency×0.15 + consolidation×0.10 + conceptualRichness×0.06
```

评分范围：[0, 1]，保留4位小数。

## 3个门控阈值

候选记忆必须同时通过3个门控阈值才能晋升为长期记忆：

| 阈值 | 默认值 | 说明 |
|------|--------|------|
| `minScore` | 0.5 | 最低综合评分，低于此值的候选记忆被拒绝 |
| `minRecallCount` | 2 | 最低被召回次数（来源会话数），确保记忆跨会话出现 |
| `minUniqueQueries` | 1 | 最低不同查询数（queryDiversity信号值），确保记忆有多样化上下文 |

## 候选记忆类别

| 类别 | 常量值 | 分类依据 |
|------|--------|---------|
| PREFERENCE | `'preference'` | 偏好标记词（prefer/like/推荐/首选等） |
| FACT | `'fact'` | 事实标记词（uses/runs on/使用/基于等） |
| CORRECTION | `'correction'` | 纠正标记词（error/fix/错误/修复等）或errors来源字段 |
| WORKFLOW | `'workflow'` | 工作流标记词（step/process/步骤/流程等） |
| DECISION | `'decision'` | 决策标记词（decided/chose/决定/选择等）或keyDecisions来源字段 |
| NOISE | `'noise'` | 噪音标记词（hello/ok/你好/谢谢等）或无法归类时降级 |

## 向后兼容说明

- **startDreaming()不受影响**：原有的`startDreaming`方法保持不变，继续执行模式提取→笔记生成→合并→持久化→同步的经典流程
- **startDreamingWithPhases()为新增方法**：仅在通过`attachPhasePipeline`注入DreamPhasePipeline实例后方可使用
- **DreamPhasePipeline可独立使用**：不依赖DreamEngine，可单独调用`executePipeline`/`executeLightPhase`/`executeDeepPhase`/`executeRemPhase`
- **默认行为不变**：未注入PhasePipeline时，DreamEngine的行为与v2.72.0之前完全一致
