# 模块详解-质量子系统

> 版本：2.73.4 | 文件：src/runtime/quality/ | 组件数：13

---

## 1. 概述

质量子系统（Quality Subsystem）是Harness框架中负责全方位质量评估、监控与治理的核心子系统，位于 `src/runtime/quality/` 目录下，包含13个核心组件。

### 设计目标

质量子系统围绕"证据验证"和"TDD强制"两大原则构建，将质量保障从单一的事后检查升级为**事前预防—事中监控—事后治理**的立体化质量防线：

| 阶段 | 核心组件 | 职责 |
|------|---------|------|
| **事前预防** | ComprehensionDebtTracker、ContextDriftMonitor | 理解债务追踪、上下文漂移检测 |
| **事中监控** | QualityScorer、SelfReflection、AdversarialReview、AiCodeTrustScorer、DeliveryEfficiencyMeter | 五维评分、自反思、对抗审查、代码可信度、效率度量 |
| **事后治理** | SelfEvolutionGovernor、DocFreshnessGuard、FeedbackCredibility、AutoReinLearningLoop、PostTaskReviewer、AgentGoldenTest | 自演化治理、文档新鲜度、反馈可信度、自增强学习、任务后审查、黄金回归测试 |

### 架构分层

质量子系统内部可划分为四个功能层：

- **评估层**（QualityScorer、AiCodeTrustScorer、EvaluationCalibrator）—— 负责产出物的量化评估（五维评分、8项风险指标检测、偏差校准）
- **审查层**（SelfReflection、AdversarialReview）—— 负责产出物的深度审查与反思
- **监控层**（DocFreshnessGuard、ComprehensionDebtTracker、ContextDriftMonitor、DeliveryEfficiencyMeter、FeedbackCredibility、AgentGoldenTest）—— 负责持续监控质量信号
- **治理层**（SelfEvolutionGovernor、AutoReinLearningLoop、PostTaskReviewer、DeliveryAccelerationOrchestrator）—— 负责基于质量信号驱动系统自改进和交付加速

**关键依赖关系**：

- **SelfEvolutionGovernor** 是治理中枢，通过心跳采集 QualityScorer、SelfReflection、HealthChecker 等模块的观测信号
- **PostTaskReviewer** 是任务后自动审查钩子，串联 SelfReflection → AutoReinLearningLoop → MemoryPipeline → DreamBridge
- **AutoReinLearningLoop** 连接反思→规则生成，将 IronRuleEngine 和 ErrorPreventionGuard 桥接
- **QualityScorer** 的五维评分供 SelfReflection、SelfEvolutionGovernor 消费
- **FeedbackCredibility** 为 QualityScorer 和 AdversarialReview 的反馈信号提供可信度加权
- **AiCodeTrustScorer** 与 FeedbackCredibility 形成"反馈可信度+代码可信度"双保险
- **AgentGoldenTest** 提供回归测试能力，确保 Agent 输出稳定性
- **ContextDriftMonitor** 在长任务中检测上下文漂移，与 ComprehensionDebtTracker 互补

### 3.1 QualityScorer — 质量评分器

#### 职责与定位

QualityScorer 是质量子系统的评估入口，负责对任务产出进行五维加权质量评估，输出0-1总分与等级判定。使用 RingBuffer 保留最近300条评分历史，支持 SignalPersistence 持久化。

#### 五维评估体系

| 维度 | 常量 | 权重 | 说明 |
|------|------|------|------|
| **completeness** | `DIMENSIONS.COMPLETENESS` | 0.25 | 完整性，需求覆盖度和输出字段丰富度 |
| **correctness** | `DIMENSIONS.CORRECTNESS` | 0.30 | 正确性，结果正确状态和期望匹配度 |
| **consistency** | `DIMENSIONS.CONSISTENCY` | 0.15 | 一致性，输出结构一致性和元数据完整性 |
| **coverage** | `DIMENSIONS.COVERAGE` | 0.15 | 覆盖率，测试通过率和字段覆盖度 |
| **clarity** | `DIMENSIONS.CLARITY` | 0.15 | 清晰度，描述完整性和表达质量 |

#### 等级判定阈值

| 等级 | 阈值 | 说明 |
|------|------|------|
| **excellent** | ≥ 0.9 | 优秀 |
| **good** | ≥ 0.75 | 良好 |
| **acceptable** | ≥ 0.6 | 可接受 |
| **poor** | ≥ 0.4 | 较差 |
| **failing** | < 0.4 | 不合格 |

#### 关键API

**构造函数**

```javascript
new QualityScorer(options)
```

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `options.weights` | `Object` | `DIMENSION_WEIGHTS` | 各维度权重覆盖 |
| `options.thresholds` | `Object` | `{excellent:0.9, good:0.75, acceptable:0.6, poor:0.4}` | 等级阈值覆盖 |
| `options.maxHistory` | `number` | 300 | 评分历史最大条数 |
| `options.signalPersistence` | `object` | `null` | 信号持久化实例 |

**公共方法**

| 方法 | 参数 | 返回值 | 说明 |
|------|------|--------|------|
| `score(result, task)` | `result`: 待评估产出（对象/字符串）; `task`: 关联任务（含id/requirements/expectedOutput/scope） | `{total, dimensions, grade, taskId, timestamp}` | 五维加权质量评分 |
| `getHistory(limit)` | `limit`: 最大记录数 | `Array<object>` | 获取评分历史 |
| `getStats()` | — | `{totalScores, averageScore, gradeDistribution}` | 获取统计摘要 |
| `attachSignalPersistence(sp)` | `sp`: SignalPersistence实例 | `this` | 附加信号持久化 |

**score()返回值详情**

| 字段 | 类型 | 说明 |
|------|------|------|
| `total` | `number` | 0-1加权总分，保留3位小数 |
| `dimensions` | `object` | 各维度评分 `{completeness, correctness, consistency, coverage, clarity}` |
| `grade` | `string` | 等级：excellent/good/acceptable/poor/failing |
| `taskId` | `string\|undefined` | 关联任务ID |
| `timestamp` | `string` | ISO格式时间戳 |

#### 事件

| 事件名 | 触发时机 | 载荷 |
|--------|---------|------|
| `scored` | 评分完成 | `{total, dimensions, grade, taskId, timestamp}` |

#### 配置项

| 常量 | 值 | 说明 |
|------|-----|------|
| `DIMENSION_WEIGHTS` | `{completeness:0.25, correctness:0.30, consistency:0.15, coverage:0.15, clarity:0.15}` | 默认维度权重 |
| `maxHistory` | 300 | RingBuffer容量 |

#### 使用示例

```javascript
const QualityScorer = require('./src/runtime/quality/quality-scorer');

const scorer = new QualityScorer({
  weights: { completeness: 0.3, correctness: 0.3, consistency: 0.15, coverage: 0.15, clarity: 0.1 },
  thresholds: { excellent: 0.85, good: 0.7 },
});
scorer.attachSignalPersistence(signalPersistence);

const result = scorer.score(
  { success: true, coverage: 0.92, tests: [{ passed: true }, { passed: true }], description: '完成' },
  { id: 'task-001', requirements: ['认证', '授权'], expectedOutput: { success: true } },
);
console.log(result.total, result.grade, result.dimensions);
console.log(scorer.getStats());
```

### 3.2 SelfReflection — 自反思引擎

#### 职责与定位

SelfReflection 实现输出质量自评与改进建议生成，支持五维度反思（边界条件/一致性/安全性/性能/完整性）和证伪维度反思。根据质量趋势判定 improving/stable/degrading，推荐 continue/deepen-analysis/rollback-and-revise 动作。内置5种反思模板。

#### 5种反思模板

| 模板 | artifactType | 核心问题 |
|------|-------------|---------|
| **code** | `'code'` | 边界条件、架构一致性、安全隐患、性能瓶颈、最可能被挑出的问题 |
| **design** | `'design'` | 需求覆盖、过度设计/设计不足、依赖关系、可扩展性 |
| **test** | `'test'` | 关键路径覆盖、测试依赖、误判风险、数据代表性 |
| **documentation** | `'documentation'` | 实现状态准确性、示例充分性、术语一致性、已知限制 |
| **decision** | `'decision'` | 证伪信号、假设有效性、反谄媚检查、证据强度、替代方案覆盖 |

#### 质量趋势判定

| 条件 | 趋势 | 建议动作 |
|------|------|---------|
| 前后质量均为null | `initial` | `proceed-with-caution` |
| 非有限数值 | `unknown` | `re-evaluate` |
| delta < -improvementThreshold | `degrading` | `rollback-and-revise` |
| delta > improvementThreshold | `improving` | `continue` |
| 其他 | `stable` | `deepen-analysis` |

#### 关键API

**构造函数**

```javascript
new SelfReflection(options)
```

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `options.maxReflections` | `number` | 3 | 最大反思次数 |
| `options.improvementThreshold` | `number` | 0.05 | 改进阈值 |
| `options.qualityWeights` | `Object` | `{completeness:0.25, correctness:0.30, consistency:0.15, security:0.15, clarity:0.15}` | 各维度权重 |
| `options.autoTriggerOnQualityDrop` | `boolean` | true | 质量下降时自动触发 |
| `options.persistResults` | `boolean` | true | 持久化反思结果 |
| `options.maxHistory` | `number` | 500 | 反思历史最大条数 |
| `options.signalPersistence` | `object` | `null` | 信号持久化实例 |

**公共方法**

| 方法 | 参数 | 返回值 | 说明 |
|------|------|--------|------|
| `reflect(context)` | `context`: {agentId(必填), skillId(必填), artifactType, previousQuality, currentQuality, result, dimensionScores} | `{reflectionId, questions, qualityTrend, recommendedAction, selfCheckPrompt, dimensions}` | 执行自反思 |
| `recordImprovement(reflectionId, improvement)` | `improvement`: {dimension, description, beforeScore, afterScore} | `{recorded, improvement}` | 记录改进条目 |
| `getReflection(reflectionId)` | — | `object\|null` | 获取完整反思记录 |
| `getAgentReflections(agentId)` | — | `Array<object>` | 获取Agent反思记录（按时间降序） |
| `getStats()` | — | `{totalReflections, totalImprovements, avgImprovement, activeReflections}` | 统计摘要 |
| `shouldTriggerReflection(context)` | `context`: {currentQuality, previousQuality, evidenceCompleteness, iterationCount} | `boolean` | 判断是否应触发反思 |
| `falsificationReflection(output, context)` | — | `{type, output, context, falsificationPrompts, antiSycophancyCheck, timestamp}` | 证伪维度反思 |
| `attachSignalPersistence(sp)` | — | `this` | 附加信号持久化 |

#### 事件

| 事件名 | 触发时机 | 载荷 |
|--------|---------|------|
| `reflection-created` | 反思创建 | `{reflectionId, agentId, qualityTrend, recommendedAction}` |
| `improvement-recorded` | 改进记录 | `{reflectionId, dimension}` |

#### 使用示例

```javascript
const SelfReflection = require('./src/runtime/quality/self-reflection');

const reflection = new SelfReflection({ improvementThreshold: 0.05 });

const result = reflection.reflect({
  agentId: 'task-worker',
  skillId: 'tdd-implement',
  artifactType: 'code',
  previousQuality: 0.7,
  currentQuality: 0.85,
});
console.log(result.qualityTrend, result.recommendedAction);

const falsification = reflection.falsificationReflection('采用微服务架构可提升系统可扩展性');
console.log(falsification.falsificationPrompts);
console.log(falsification.antiSycophancyCheck);
```

### 3.3 AdversarialReview — 对抗审查器

#### 职责与定位

AdversarialReview 实现故意寻找缺陷和漏洞的决策对抗模式，采用魔鬼代言人角色与证伪实验设计。提供三种审查模式：双审查者多轮对抗、决策对抗、证伪检验。

#### 关键API

**构造函数**

```javascript
new AdversarialReview(options)
```

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `options.maxRounds` | `number` | 3 | 最大对抗审查轮次 |
| `options.reviewTimeout` | `number` | 30000 | 每个审查者超时时间（毫秒） |

**公共方法**

| 方法 | 参数 | 返回值 | 说明 |
|------|------|--------|------|
| `review(subject, reviewerA, reviewerB)` | `subject`: 待审查对象; `reviewerA/B`: `async (subject, context) => {approved, feedback, suggestions}` | `Promise<{consensus, rounds, details, finalFeedback}>` | 双审查者多轮对抗审查 |
| `decisionAdversarial(proposal, options)` | `proposal`: 决策提案; `options.roles`: 角色列表（默认`['cfo','investor','veteran']`） | `Promise<{type, proposal, attacks, falsification, antiSycophancyCheck, timestamp}>` | 决策对抗审查 |
| `falsificationCheck(conclusion, context)` | `conclusion`: 待证伪结论 | `{conclusion, whyItMightNotWork, prerequisitesForSuccess, falsificationSignals, minimumViableExperiment, confidenceLevel}` | 证伪检验 |

**5种对抗角色**

| 角色键 | 角色名 | 审查焦点 |
|--------|--------|---------|
| `cfo` | 冷静的CFO | 成本、ROI、现金流风险 |
| `investor` | 挑剔的投资人 | 市场规模、竞争壁垒、退出路径 |
| `veteran` | 行业老手 | 行业潜规则、隐性成本、监管风险 |
| `engineer` | 悲观工程师 | 技术可行性、复杂度、维护成本 |
| `ux_fanatic` | 用户体验偏执狂 | 用户学习成本、使用障碍、流失风险 |

#### 事件

| 事件名 | 触发时机 | 载荷 |
|--------|---------|------|
| `round-complete` | 每轮审查完成 | `{round, reviewerA, reviewerB}` |
| `review-complete` | 审查流程结束 | `{consensus, rounds, details, finalFeedback}` |

#### 使用示例

```javascript
const AdversarialReview = require('./src/runtime/quality/adversarial-review');

const reviewer = new AdversarialReview({ maxRounds: 3 });

const result = await reviewer.review(
  { proposal: '引入缓存层提升查询性能' },
  async (subject, ctx) => ({ approved: false, feedback: '缓存一致性未考虑', suggestions: ['添加缓存失效策略'] }),
  async (subject, ctx) => ({ approved: true, feedback: '方案可行', suggestions: [] }),
);

const adversarial = await reviewer.decisionAdversarial('采用微服务架构重构系统', {
  roles: ['cfo', 'engineer', 'ux_fanatic'],
});
```

### 3.4 DocFreshnessGuard — 文档新鲜度守卫

#### 职责与定位

DocFreshnessGuard 检测过时文档并提醒更新。异步构建文档索引，提取代码引用，监听源码变更自动标记关联文档为 stale。区分普通文档（7天阈值）与规格文档（3天阈值），规格文档采用 active 活跃策略并支持再验证队列。

#### 文档分类与阈值

| 文档类型 | 新鲜度阈值 | 存活策略 | 说明 |
|---------|-----------|---------|------|
| **普通文档** | 7天 | passive | 被动检测，超时后标记stale |
| **规格文档** | 3天 | active | 主动检测，超时后加入再验证队列 |

#### 关键API

**构造函数**

```javascript
new DocFreshnessGuard(options)
```

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `options.projectRoot` | `string` | `null` | 项目根目录 |

**公共方法**

| 方法 | 参数 | 返回值 | 说明 |
|------|------|--------|------|
| `attachProjectRoot(projectRoot)` | 项目根目录绝对路径 | `this` | 延迟附加项目根目录 |
| `startWatching()` | — | `void` | 启动源码目录文件监听 |
| `stopWatching()` | — | `void` | 停止监听 |
| `handleCodeChange(filePath, changeType)` | `filePath`: 变更文件绝对路径 | `Array<object>` | 手动处理代码变更，返回被标记stale的文档 |
| `getStaleDocs()` | — | `Array<{path, reason, lastVerifiedAt, references}>` | 获取所有stale文档 |
| `markDocVerified(docPath)` | `docPath`: 文档路径 | `boolean` | 标记文档已验证 |
| `getDocIndex()` | — | `Array<{path, referenceCount, stale, staleReason, lastVerifiedAt}>` | 获取文档索引摘要 |
| `getFreshnessStats()` | — | `{totalDocs, staleDocs, freshDocs, totalReferences, freshnessRate, watching}` | 新鲜度统计 |
| `validateFreshness()` | — | `{valid, newlyStale, totalStale}` | 验证所有文档新鲜度 |
| `getReverificationQueue()` | — | `Array<{path, entry, stalenessAge}>` | 获取规格文档再验证队列 |
| `triggerReverification(docPath)` | — | `{triggered, specType, attempt}` | 手动触发规格文档再验证 |
| `drainReverificationQueue()` | — | `Array` | 清空并返回再验证队列 |

**属性**

| 属性 | 类型 | 说明 |
|------|------|------|
| `ready` | `Promise<void>` | 索引构建完成的Promise |

#### 事件

| 事件名 | 触发时机 | 载荷 |
|--------|---------|------|
| `index-built` | 索引构建完成 | `{entries}` |

### 3.6 FeedbackCredibility — 反馈可信度评估器

#### 职责与定位

FeedbackCredibility 基于反馈源的历史准确率，动态计算各反馈源的可信度评分，并提供加权聚合能力。支持信任评分的时间衰减机制，确保长期未更新的反馈源评分逐步回归默认值。

#### 职责与定位

AiCodeTrustScorer 基于7项风险指标检测AI生成代码的可信度，按来源追踪可信度趋势，支持指数衰减。包含特有的 ALMOST_CORRECT（"似对非对"）模式检测。

#### 7项风险指标

| 指标 | 常量 | 权重 | 检测条件 | 默认严重度 |
|------|------|------|---------|-----------|

| **spec-violation** | `RISK_INDICATORS.SPEC_VIOLATION` | 0.13 | `specCompliant === false` | 0.8 |
| **almost-correct** | `RISK_INDICATORS.ALMOST_CORRECT` | 0.14 | `almostCorrect === true` 或 `subtleBugCount > 0` 或 `passesBasicTests && !edgeCasesHandled && !errorHandlingComplete` | 0.6-0.9 |

| 等级 | 常量 | 阈值 | 说明 |
|------|------|------|------|
| **none** | `DRIFT_LEVELS.NONE` | < 0.2 | 无漂移 |
| **low** | `DRIFT_LEVELS.LOW` | ≥ 0.2 | 低度漂移 |
| **medium** | `DRIFT_LEVELS.MEDIUM` | ≥ 0.4 | 中度漂移 |
| **high** | `DRIFT_LEVELS.HIGH` | ≥ 0.6 | 高度漂移 |
| **critical** | `DRIFT_LEVELS.CRITICAL` | ≥ 0.8 | 严重漂移 |

#### 关键API

**构造函数**

```javascript
new ContextDriftMonitor(options)
```

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `options.lowThreshold` | `number` | 0.2 | 低度漂移阈值 |
| `options.mediumThreshold` | `number` | 0.4 | 中度漂移阈值 |
| `options.highThreshold` | `number` | 0.6 | 高度漂移阈值 |
| `options.criticalThreshold` | `number` | 0.8 | 严重漂移阈值 |
| `options.checkIntervalMs` | `number` | 60000 | 周期性检查间隔（毫秒） |

**公共方法**

| 方法 | 参数 | 返回值 | 说明 |
|------|------|--------|------|
| `registerConstraint(constraint)` | `{id, text/description, category, priority, source}` | `object\|null` | 注册约束 |
| `registerConstraints(constraints)` | `Array` | `Array` | 批量注册约束 |
| `removeConstraint(id)` | — | `boolean` | 移除约束 |
| `startTask(taskId, initialConstraints)` | — | `string` | 开始任务监控，返回任务ID |
| `stopTask()` | — | `void` | 停止任务监控 |
| `checkDrift(currentContext)` | 当前上下文（字符串或对象） | `{driftScore, level, violatedConstraints, lostConstraints, totalConstraints, taskId}` | 检测漂移 |
| `getDriftHistory()` | — | `Array` | 获取漂移历史快照 |
| `getActiveConstraints()` | — | `Array` | 获取活跃约束列表 |
| `getDriftTrend()` | — | `{trend, snapshots, recentViolationRatio}` | 获取漂移趋势 |
| `getStats()` | — | `{snapshotsTaken, driftsDetected, constraintsRegistered, constraintsLost, highestDriftScore, activeConstraints, currentTaskId, snapshotCount, driftTrend}` | 获取统计信息 |

**checkDrift()检测逻辑**

- 将约束文本与当前上下文进行匹配（精确包含或模糊匹配）
- 模糊匹配：对非否定性约束，70%以上显著词匹配即视为存在
- 否定性约束（含no/not/never/without等词）要求精确包含
- 违反3次以上的约束标记为"丢失"（lostConstraints）
- 漂移分数 = 违反约束的优先级加权和 / 总约束数

| `task-stopped` | 任务监控停止 | `{taskId}` |

| `snapshot-taken` | 快照采集 | 快照对象 |

#### 容量限制

| 常量 | 值 | 说明 |
|------|-----|------|
| `MAX_SNAPSHOTS` | 100 | 最大快照数 |
| `MAX_CONSTRAINTS` | 200 | 最大约束数 |

### 3.12 AutoReinLearningLoop — 自增强学习循环

#### 职责与定位

AutoReinLearningLoop 连接反思→规则生成，从任务结果中提取错误模式和反思改进候选，自动生成铁律规则并注册到 IronRuleEngine，同时将错误模式注册到 ErrorPreventionGuard。内置5个规则模板。

#### 5个内置规则模板

| 模板键 | 检测模式 | 说明 | 严重度 | 类别 |
|--------|---------|------|--------|------|
| **null-check** | `(\w+)\.\w+\(\)` | 方法调用前缺少null检查 | warning | reliability |
| **error-handling** | `await \w+\(...\)` 后无catch | 异步操作缺少错误处理 | warning | reliability |
| **resource-cleanup** | `new (Server\|Connection\|Stream\|Socket)` | 资源创建无清理计划 | info | reliability |
| **unbounded-collection** | `new (Map\|Set\|Array)()` | 无界集合缺少大小限制 | warning | reliability |
| **hardcoded-delay** | `setTimeout(..., \d{4,})` | 硬编码长延迟 | info | maintainability |

#### 关键API

**构造函数**

```javascript
new AutoReinLearningLoop(config)
```

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `config.maxHistorySize` | `number` | 500 | 学习历史最大容量 |
| `config.maxRuleTemplates` | `number` | 100 | 规则模板最大容量 |
| `config.minConfidenceForRule` | `number` | 0.6 | 规则生成最低置信度 |
| `config.autoRegisterPatterns` | `boolean` | true | 是否自动注册错误模式 |

**Attach方法**（4个，均返回 `this`）

| 方法 | 依赖 | 用途 |
|------|------|------|
| `attachIronRuleEngine(engine)` | IronRuleEngine | 铁律规则注册 |
| `attachErrorPreventionGuard(guard)` | ErrorPreventionGuard | 错误模式注册 |
| `attachSkillMemoryStore(store)` | SkillMemoryStore | 技能记忆存储 |
| `attachSkillImprovementLoop(loop)` | SkillImprovementLoop | 技能改进学习记录 |

**公共方法**

| 方法 | 参数 | 返回值 | 说明 |
|------|------|--------|------|
| `processTaskResult(taskResult)` | `taskResult`: {taskId, skillId, agentId, errors, error, violations, reflection, result, whatWorked, whatFailed, ...} | `Promise<{processed, rulesGenerated, patternsRegistered, learningsRecorded}>` | 处理任务结果，提取规则和模式 |
| `addRuleTemplate(key, template)` | `template`: {pattern(RegExp), description, solution, severity, category} | `boolean` | 添加自定义规则模板 |
| `removeRuleTemplate(key)` | — | `boolean` | 移除规则模板 |
| `getRuleTemplates()` | — | `Object` | 获取所有规则模板 |
| `getStats()` | — | `{rulesGenerated, patternsRegistered, learningsRecorded, reviewsCompleted}` | 获取统计信息 |
| `getHistory()` | — | `Array` | 获取学习历史 |

**processTaskResult()处理流程**

1. 从 `taskResult.errors`/`error`/`violations` 提取错误模式
2. 从 `taskResult.reflection` 提取改进候选（improvements、qualityTrend=degrading、needsAttention维度）
3. 对每个错误模式匹配规则模板，生成铁律规则注册到 IronRuleEngine
4. 对每个错误模式注册到 ErrorPreventionGuard
5. 若有 skillId，记录学习到 SkillImprovementLoop

#### 事件

| 事件名 | 触发时机 | 载荷 |
|--------|---------|------|
| `task-processed` | 任务处理完成 | `{id, taskId, errorCount, ruleCandidatesCount, rulesGenerated, patternsRegistered, learningsRecorded, timestamp}` |
| `rule-generated` | 规则生成 | `{ruleId, pattern, source}` |
| `pattern-registered` | 错误模式注册 | `{patternId, pattern}` |

#### 使用示例

```javascript
const AutoReinLearningLoop = require('./src/runtime/quality/auto-rein-learning-loop');

const loop = new AutoReinLearningLoop({ autoRegisterPatterns: true });
loop.attachIronRuleEngine(ironRuleEngine);
loop.attachErrorPreventionGuard(errorPreventionGuard);
loop.attachSkillImprovementLoop(skillImprovementLoop);

const result = await loop.processTaskResult({
  taskId: 'task-001',
  skillId: 'tdd-implement',
  agentId: 'task-worker',
  errors: [{ message: 'Cannot read property of null', description: 'Missing null check' }],
  reflection: {
    qualityTrend: 'degrading',
    improvements: [{ dimension: 'correctness', description: 'Add null check before method call' }],
    dimensions: { boundary_conditions: { needsAttention: true, score: 0.4 } },
  },
});
console.log(result.rulesGenerated, result.patternsRegistered);
```

### 3.13 PostTaskReviewer — 任务后自动审查钩子

#### 职责与定位

PostTaskReviewer 是任务完成后的自动审查钩子，串联 SelfReflection → AutoReinLearningLoop → MemoryPipeline → DreamBridge 四个阶段。当发现显著问题（规则生成数+错误数 ≥ 阈值）时自动触发 DreamBridge。

#### 关键API

**构造函数**

```javascript
new PostTaskReviewer(config)
```

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `config.maxQueueSize` | `number` | 200 | 审查队列最大容量 |
| `config.significantFindingsThreshold` | `number` | 2 | 触发DreamBridge的显著发现阈值 |
| `config.autoStoreMemory` | `boolean` | true | 是否自动存储记忆 |

**Attach方法**（4个，均返回 `this`）

| 方法 | 依赖 | 用途 |
|------|------|------|
| `attachAutoReinLoop(loop)` | AutoReinLearningLoop | 自增强学习循环 |
| `attachSelfReflection(reflection)` | SelfReflection | 自反思引擎 |
| `attachMemoryPipeline(pipeline)` | MemoryPipeline | 记忆管道 |
| `attachDreamBridge(bridge)` | DreamBridge | 梦境桥接器 |

**公共方法**

| 方法 | 参数 | 返回值 | 说明 |
|------|------|--------|------|
| `reviewAfterTask(taskResult)` | `taskResult`: {taskId, agentId, skillId, artifactType, previousQuality, currentQuality, result, dimensionScores, errors, ...} | `Promise<{reviewId, reflected, rulesGenerated, memoriesStored, dreamBridgeTriggered}>` | 执行任务后审查 |

**reviewAfterTask()处理流程**

1. **反思阶段**：若已附加 SelfReflection 且 taskResult 含 agentId/skillId，调用 `reflect()` 生成反思
2. **规则生成阶段**：若已附加 AutoReinLearningLoop，调用 `processTaskResult()` 提取规则和模式
3. **记忆存储阶段**：若已附加 MemoryPipeline 且 autoStoreMemory=true，调用 `write()` 存储审查记录
4. **DreamBridge触发**：若 `rulesGenerated + errors.length ≥ significantFindingsThreshold`，向 DreamBridge 发射 `significant-findings` 事件

#### 事件

| 事件名 | 触发时机 | 载荷 |
|--------|---------|------|
| `review-complete` | 审查完成 | `{reviewId, reflected, rulesGenerated, memoriesStored, dreamBridgeTriggered}` |

#### 使用示例

```javascript
const PostTaskReviewer = require('./src/runtime/quality/post-task-reviewer');

const reviewer = new PostTaskReviewer({ significantFindingsThreshold: 2 });
reviewer.attachSelfReflection(selfReflection);
reviewer.attachAutoReinLoop(autoReinLoop);
reviewer.attachMemoryPipeline(memoryPipeline);
reviewer.attachDreamBridge(dreamBridge);

const result = await reviewer.reviewAfterTask({
  taskId: 'task-001',
  agentId: 'task-worker',
  skillId: 'tdd-implement',
  artifactType: 'code',
  previousQuality: 0.7,
  currentQuality: 0.5,
  errors: [{ message: 'Test failed' }],
});
console.log(result.reflected, result.rulesGenerated, result.dreamBridgeTriggered);
```

| 系统自改进 | SelfEvolutionGovernor | 心跳驱动提案生成，人工审批后执行 |
| 反馈源可靠性 | FeedbackCredibility | 加权聚合，防止低质量反馈干扰决策 |
| AI代码审查 | AiCodeTrustScorer | 7项风险指标，特别关注ALMOST_CORRECT模式 |
| 理解不足追踪 | ComprehensionDebtTracker | 任务前/中追踪理解债务 |
| 交付效率分析 | DeliveryEfficiencyMeter | 6阶段时间分布，瓶颈检测 |
| 长任务漂移检测 | ContextDriftMonitor | 约束注册+周期性检查 |
| Agent输出回归 | AgentGoldenTest | 黄金用例比对，4种匹配策略 |
| 错误模式学习 | AutoReinLearningLoop | 反思→规则→错误预防闭环 |
| 任务后自动审查 | PostTaskReviewer | 串联反思→规则→记忆→DreamBridge |

### 注意事项

1. **SelfEvolutionGovernor 的依赖注入**：10个attach方法均为可选依赖，但缺少SignalPersistence将无法采集趋势观测信号，缺少HealthChecker将无法采集健康状态。建议至少注入SignalPersistence和AuditLogger。

2. **PostTaskReviewer 的触发时机**：应在每个任务完成后立即调用 `reviewAfterTask()`，它是质量闭环的自动触发点。若不调用，SelfReflection和AutoReinLearningLoop将无法自动执行。

3. **ContextDriftMonitor 的约束设计**：约束文本应简洁明确，避免过于宽泛的描述导致误匹配。否定性约束（含no/not/never等词）采用精确匹配，应确保措辞准确。

4. **AgentGoldenTest 的容差设置**：数值类型默认容差为 `|expectedValue| × 5%`，对于需要精确匹配的场景，应设置 `tolerance: 0`。

5. **AutoReinLearningLoop 的规则生成**：规则自动注册到IronRuleEngine需要先通过 `attachIronRuleEngine()` 注入，否则规则仅生成不注册。同理，ErrorPreventionGuard也需要先attach。

6. **DocFreshnessGuard 的异步初始化**：构造函数中异步构建索引，必须 `await guard.ready` 后再调用其他方法，否则可能获取空数据。

7. **FeedbackCredibility 的衰减调用**：`decayTrustScores()` 不会自动执行，需由外部定时调度（如每日调用一次），否则信任评分不会衰减。

8. **AiCodeTrustScorer 的ALMOST_CORRECT检测**：这是最独特的风险指标，检测"看起来正确但存在微妙Bug"的代码。当 `passesBasicTests=true` 但 `edgeCasesHandled=false` 且 `errorHandlingComplete=false` 时自动触发。

9. **DeliveryEfficiencyMeter 的吞吐量失衡**：`getReviewThroughputImbalance()` 是检测"代码生成速度远超审查速度"的关键指标，当失衡比率 ≥ 2.0 时标记为high级别，≥ 4.0 时标记为critical。

10. **ComprehensionDebtTracker 的容量管理**：最大1000条债务，超出时优先淘汰已解决的最早债务。对于长期运行的项目，建议定期检查 `calculateDebtScore()` 并主动解决高严重度债务。

### 性能考量

| 组件 | 潜在性能影响 | 建议 |
|------|-------------|------|
| DocFreshnessGuard | 文件监听和索引构建 | 使用 `unref()` 避免阻止进程退出；大项目考虑限制索引范围 |
| SelfEvolutionGovernor | 心跳间隔过短导致CPU占用 | 心跳间隔不低于 `MIN_HEARTBEAT_INTERVAL_MS` |
| AgentGoldenTest | 大量用例的批量运行 | 使用 `outputProvider` 异步获取输出，避免阻塞 |
| ContextDriftMonitor | 周期性检查间隔 | 默认60秒，可根据任务长度调整 |
| AutoReinLearningLoop | 规则匹配的RegExp性能 | 自定义规则模板避免过于复杂的正则表达式 |
