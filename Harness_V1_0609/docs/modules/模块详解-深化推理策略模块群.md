## 模块群概述

深化推理策略模块群是深化推理引擎的核心决策层，负责控制推理深度、检测收敛状态、管理迭代过程、分配Token预算，以及维护推理流程的状态与依赖关系。该模块群围绕"**策略驱动的迭代深化**"这一核心思想，将推理过程拆解为策略决策、收敛检测、深度控制、迭代精化、渐进深化、循环调度、预算感知、状态管理、依赖解析和可视化等独立关注点，每个模块各司其职、协同工作。

模块群的核心设计目标：

- **策略可插拔**：5种内置策略（固定深度/自适应/收敛驱动/预算感知/质量优化），通过策略插件机制支持扩展
- **收敛可检测**：多信号收敛检测（质量阈值/稳定性/维度平衡/质量退化），避免无效迭代
- **深度可自适应**：根据任务复杂度动态调整推理深度（quick/standard/deep/intensive四级）
- **预算可感知**：Token预算约束下的深化策略，防止资源耗尽
- **状态可追踪**：状态机+状态管理器双重机制，完整记录推理流程的状态变迁历史
- **依赖可解析**：DAG依赖图+环检测+拓扑排序，确保推理任务按正确顺序执行
- **过程可可视化**：执行图/收敛图/时间线/健康仪表盘，直观呈现推理过程

## 共同设计模式

### 1. 策略模式（Strategy Pattern）

`DeepeningStrategyPlugin` 是策略模式的典型实现。5种策略封装为独立方法，通过配置切换，客户端代码无需感知策略细节。所有策略方法签名统一：`(ctx) → { shouldContinue, depthLevel, reason }`。

### 2. 模板方法模式（Template Method）

`ProgressiveDeepening` 和 `IterativeRefinement` 采用模板方法模式：定义执行骨架（迭代循环→执行→审查→判定），具体执行逻辑由外部注入的 `agent`/`executor`/`reviewer` 提供。

### 3. 状态机模式（State Machine）

`DeepeningStateMachine` 和 `DeepeningStateManager` 分别实现了两种状态机：
- **DeepeningStateMachine**：预定义状态的固定FSM，适合标准化流程
- **DeepeningStateManager**：动态可配置的状态机，支持守卫条件和回调

### 4. 观察者模式（Observer）

所有模块继承自 `DeepeningBase → EventEmitter`，通过 `emit` 发布事件，上层模块通过 `on` 订阅事件，实现松耦合通信。

### 5. 依赖注入（Dependency Injection）

通过 `DeepeningBase` 的 `attach*()` 方法注入外部依赖，支持延迟绑定和链式调用。

## 1. DeepeningStrategyPlugin — 深化策略插件

> 源码：[deepening-strategy-plugin.js](file:///e:/Harness_V1_0429/src/runtime/deepening/deepening-strategy-plugin.js)

### 职责概述

策略模式核心实现，提供5种内置深化策略，根据上下文信息决定是否继续迭代、推荐深度级别和终止原因。被 `DeepeningOrchestrator` 通过 `attachStrategyPlugin()` 注入使用。

### 核心API

#### 构造函数

```javascript
constructor(name, config)
```

| 参数 | 类型 | 说明 |
|------|------|------|
| `name` | `string` | 策略名称，默认 `'default'` |
| `config` | `object` | 策略配置对象 |
| `config.type` | `string` | 策略类型，取值见 `STRATEGY_TYPES`，默认 `'fixed-depth'` |
| `config.enabled` | `boolean` | 是否启用，设为 `false` 时 `decide()` 返回 `null` |
| `config.maxIterations` | `number` | 最大迭代次数，各策略默认值不同 |
| `config.depthLevel` | `string` | 固定深度策略使用的深度级别 |
| `config.qualityThreshold` | `number` | 质量/收敛策略的质量阈值 |

#### 静态属性

| 属性 | 值 | 说明 |
|------|------|------|
| `STRATEGY_TYPES.FIXED_DEPTH` | `'fixed-depth'` | 固定深度策略 |
| `STRATEGY_TYPES.ADAPTIVE` | `'adaptive'` | 自适应策略 |
| `STRATEGY_TYPES.CONVERGENCE_DRIVEN` | `'convergence-driven'` | 收敛驱动策略 |
| `STRATEGY_TYPES.BUDGET_AWARE` | `'budget-aware'` | 预算感知策略 |
| `STRATEGY_TYPES.QUALITY_OPTIMIZED` | `'quality-optimized'` | 质量优化策略 |

#### 公共方法

| 方法 | 签名 | 返回值 | 说明 |
|------|------|--------|------|
| `decide` | `decide(context)` | `Promise<DecisionResult \| null>` | 根据当前策略类型和上下文做出迭代决策。`config.enabled === false` 时返回 `null` |
| `getStats` | `getStats()` | `object` | 返回统计信息，含 `name`、`executionCount`、`successCount` |

**DecisionResult 结构**：

```javascript
{
  shouldContinue: boolean,   // 是否继续迭代
  depthLevel: string,        // 推荐深度级别：'quick'/'standard'/'deep'/'intensive'
  reason: string             // 决策原因
}
```

#### 5种策略详解

| 策略 | 默认maxIterations | 终止条件 | 深度级别逻辑 |
|------|-------------------|----------|-------------|
| `fixed-depth` | 4 | 迭代次数达到上限 | 固定为 `config.depthLevel` 或 `'standard'` |
| `adaptive` | 6 | 质量达标且改善率<0.05，或迭代次数达到上限 | quality<0.5→`'intensive'`，quality<阈值→`'deep'`，否则→`'standard'` |
| `convergence-driven` | 10 | 收敛状态为已收敛，或迭代次数达到上限 | 固定 `'standard'` |
| `budget-aware` | 4 | 剩余Token不足预算10%，或迭代次数达到上限 | 剩余>预算50%→`'deep'`，否则→`'standard'` |
| `quality-optimized` | 5 | 质量达到阈值（默认0.9），或迭代次数达到上限 | 固定 `'intensive'`（追求最高质量） |

**context 参数结构**：

```javascript
{
  iteration: number,           // 当前迭代次数
  qualityScore: number,        // 当前质量分数
  improvementRate: number,     // 改善率（adaptive策略使用）
  convergenceStatus: object,   // 收敛状态（convergence-driven策略使用）
  tokensRemaining: number,     // 剩余Token数（budget-aware策略使用）
  tokensBudget: number         // Token总预算（budget-aware策略使用）
}
```

### 事件列表

本模块不直接发射事件。

### 配置选项

| 选项 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `type` | `string` | `'fixed-depth'` | 策略类型 |
| `enabled` | `boolean` | `true` | 是否启用 |
| `maxIterations` | `number` | 策略相关 | 最大迭代次数 |
| `depthLevel` | `string` | `'standard'` | 固定深度策略的深度级别 |
| `qualityThreshold` | `number` | 策略相关 | 质量阈值（adaptive: 0.85, quality-optimized: 0.9） |

### 使用示例

```javascript
const DeepeningStrategyPlugin = require('./src/runtime/deepening/deepening-strategy-plugin');

const plugin = new DeepeningStrategyPlugin('my-strategy', {
  type: 'adaptive',
  maxIterations: 8,
  qualityThreshold: 0.9
});

const result = await plugin.decide({
  iteration: 3,
  qualityScore: 0.75,
  improvementRate: 0.12
});
console.log(result);
// { shouldContinue: true, depthLevel: 'deep', reason: 'within-iterations' }
```

### 与其他模块的交互关系

| 模块 | 交互方式 | 说明 |
|------|----------|------|
| DeepeningOrchestrator | 被 `attachStrategyPlugin()` 注入 | 编排器每轮迭代调用 `decide()` 判断是否继续 |
| ConvergenceDetector | 间接协作 | `convergence-driven` 策略消费收敛检测器的结果 |
| TokenAwareDeepening | 间接协作 | `budget-aware` 策略消费Token预算信息 |

## 2. ConvergenceDetector — 收敛检测器

> 源码：[convergence-detector.js](file:///e:/Harness_V1_0429/src/runtime/deepening/convergence-detector.js)

### 职责概述

多信号收敛检测器，通过质量阈值、稳定性方差、维度平衡、质量退化等多维度信号判断推理过程是否已收敛。维护每个执行ID的历史数据，支持停滞检测和早停策略。

### 核心API

#### 构造函数

```javascript
constructor(options)
```

| 参数 | 类型 | 说明 |
|------|------|------|
| `options` | `object` | 配置选项，与 `DEFAULT_CONFIG` 合并 |
| `options.maxHistoryExecutions` | `number` | 最大历史执行数，默认 `100`，超出时淘汰最旧记录 |

#### 静态属性

| 属性 | 说明 |
|------|------|
| `SIGNAL_TYPES.QUALITY_SCORE` | 质量分数信号 `'quality-score'` |
| `SIGNAL_TYPES.IMPROVEMENT_RATE` | 改善率信号 `'improvement-rate'` |
| `SIGNAL_TYPES.STABILITY` | 稳定性信号 `'stability'` |
| `DEFAULT_CONFIG` | 默认配置（见配置选项表） |

#### 公共方法

| 方法 | 签名 | 返回值 | 说明 |
|------|------|--------|------|
| `check` | `check(executionId, data)` | `ConvergenceResult` | 执行收敛检测。传入执行ID和当前数据，返回收敛状态 |
| `reset` | `reset(executionId)` | `boolean` | 重置指定执行ID的历史数据 |
| `getStats` | `getStats()` | `object` | 返回 `activeExecutions`、`config` 等统计信息 |

**ConvergenceResult 结构**：

```javascript
{
  converged: boolean,         // 是否已收敛
  reason: string,             // 收敛/未收敛原因
  signals: object,            // 各信号检测结果
  recommendation: string      // 建议：'sufficient'/'increase-depth'/'decrease-depth'
}
```

**收敛原因（reason）**：

| 原因 | 说明 | recommendation |
|------|------|----------------|
| `'quality-threshold-met'` | 质量分数达到阈值 | `'sufficient'` |
| `'max-iterations-reached'` | 达到最大迭代次数 | `'increase-depth'` |
| `'stable-and-sufficient'` | 稳定且质量接近阈值 | `'sufficient'` |
| `'plateau-detected'` | 停滞检测（稳定但质量不够） | `'increase-depth'` |
| `'quality-degrading'` | 质量退化 | `'decrease-depth'` |
| `'not-converged'` | 未收敛 | `'increase-depth'` |
| `'missing-data'` | 缺少必要数据 | — |

**data 参数结构**：

```javascript
{
  qualityScore: number,       // 当前质量分数
  dimensions: {               // 各维度分数（可选）
    [key: string]: number
  }
}
```

#### 收敛检测逻辑

1. **质量阈值检测**：`qualityScore >= qualityThreshold` → 收敛
2. **最大迭代检测**：历史记录数 >= `maxIterations` → 收敛
3. **稳定性检测**：最近 `stabilityWindow` 次的方差 < `stabilityVariance` 且均值 >= 阈值×0.9 → `stable-and-sufficient`
4. **停滞检测**：方差 < `stabilityVariance` 但均值不够 → `plateau-detected`
5. **质量退化检测**：当前分数 < 上次分数 - `qualityDegradationThreshold` → `quality-degrading`
6. **维度平衡检测**：当 `dimensions` 含2+维度时，最大与最小维度差 <= `dimensionBalanceThreshold` → 通过

### 事件列表

| 事件名 | 参数 | 说明 |
|--------|------|------|
| `convergence-checked` | `{ signals: object }` | 每次收敛检测完成后触发 |

### 配置选项

| 选项 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `qualityThreshold` | `number` | `0.85` | 质量收敛阈值 |
| `maxIterations` | `number` | `10` | 最大迭代次数 |
| `minImprovementRate` | `number` | `0.01` | 最小改善率 |
| `stabilityVariance` | `number` | `0.01` | 稳定性方差阈值 |
| `stabilityWindow` | `number` | `3` | 稳定性检测窗口大小 |
| `coverageThreshold` | `number` | `0.8` | 覆盖率阈值 |
| `dimensionBalanceThreshold` | `number` | `0.3` | 维度平衡阈值 |
| `qualityDegradationThreshold` | `number` | `0.1` | 质量退化阈值 |
| `maxHistoryExecutions` | `number` | `100` | 最大历史执行数 |

### 使用示例

```javascript
const ConvergenceDetector = require('./src/runtime/deepening/convergence-detector');

const detector = new ConvergenceDetector({
  qualityThreshold: 0.9,
  stabilityWindow: 5
});

for (let i = 0; i < 10; i++) {
  const result = detector.check('exec-001', {
    qualityScore: 0.7 + i * 0.025,
    dimensions: { correctness: 0.85, completeness: 0.8 }
  });
  if (result.converged) {
    console.log('收敛原因:', result.reason, '建议:', result.recommendation);
    break;
  }
}
```

### 与其他模块的交互关系

| 模块 | 交互方式 | 说明 |
|------|----------|------|
| DeepeningOrchestrator | 被 `attachConvergenceDetector()` 注入 | 编排器每轮迭代后调用 `check()` 判断收敛 |
| DeepeningStrategyPlugin | 间接协作 | `convergence-driven` 策略消费 `check()` 的 `convergenceStatus` |
| RecurrentDeepeningScheduler | 可被注入 | 调度器可使用收敛检测替代简单阈值判定 |

## 3. AdaptiveDepthController — 自适应深度控制器

> 源码：[adaptive-depth-controller.js](file:///e:/Harness_V1_0429/src/runtime/deepening/adaptive-depth-controller.js)

### 职责概述

根据任务描述中的关键词信号评估任务复杂度，动态推荐推理深度级别。将任务分为quick/standard/deep/intensive四个深度等级，通过加权评分模型（范围×0.35 + 风险×0.35 + 推理×0.2 + 依赖×0.1）计算综合复杂度分数。

### 核心API

#### 构造函数

```javascript
constructor(options)
```

| 参数 | 类型 | 说明 |
|------|------|------|
| `options` | `object` | 配置选项（继承自 DeepeningBase） |

#### 静态属性

| 属性 | 值 | 说明 |
|------|------|------|
| `DEPTH_LEVELS.QUICK` | `1` | 快速深度 |
| `DEPTH_LEVELS.STANDARD` | `2` | 标准深度 |
| `DEPTH_LEVELS.DEEP` | `3` | 深度推理 |
| `DEPTH_LEVELS.INTENSIVE` | `4` | 强化推理 |

#### 公共方法

| 方法 | 签名 | 返回值 | 说明 |
|------|------|--------|------|
| `assessComplexity` | `assessComplexity(task)` | `ComplexityResult` | 评估任务复杂度，返回分数、级别和深度 |
| `getRecommendedDepth` | `getRecommendedDepth(task)` | `number` | 获取推荐深度数值（1-4） |
| `getRecommendedLevel` | `getRecommendedLevel(task)` | `string` | 获取推荐深度级别名称 |
| `getStats` | `getStats()` | `object` | 返回 `totalAssessments` 等统计信息 |

**ComplexityResult 结构**：

```javascript
{
  score: number,              // 综合复杂度分数 [0, 1]
  level: string,              // 深度级别：'quick'/'standard'/'deep'/'intensive'
  depth: number,              // 深度数值：1/2/3/4
  signals: {
    scope: number,            // 范围信号 [0, 1]
    risk: number,             // 风险信号 [0, 1]
    reasoning: number,        // 推理信号 [0, 1]
    dependencyDepth: number   // 依赖深度信号 [0, 1]
  }
}
```

#### 复杂度评分模型

| 信号维度 | 权重 | 关键词（中文） | 关键词（英文） | 每匹配增量 |
|----------|------|---------------|---------------|-----------|
| 范围(scope) | 0.35 | 构建、系统、平台、架构、重构 | design, system, platform, refactor | +0.4，上限1 |
| 风险(risk) | 0.35 | 安全、关键、生产、合规 | security, critical, production, compliance | +0.45，上限1 |
| 推理(reasoning) | 0.2 | 推理、分析、优化、决策 | reasoning, analysis, optimize, decision | +0.4，上限1 |
| 依赖深度(dependencyDepth) | 0.1 | — | — | `deps.length × 0.2`，上限1 |

**深度映射**：

| 复杂度分数 | 深度级别 | 深度值 |
|-----------|---------|--------|
| [0, 0.25) | `quick` | 1 |
| [0.25, 0.5) | `standard` | 2 |
| [0.5, 0.75) | `deep` | 3 |
| [0.75, 1] | `intensive` | 4 |

**task 参数结构**：

```javascript

  prompt: string,             // 替代描述字段

```

当 `task` 为 `null`/`undefined`/`string` 时，返回默认复杂度 `{ score: 0.3, level: 'standard', depth: 2 }`。

### 事件列表

| 事件名 | 参数 | 说明 |
|--------|------|------|
| `complexity-assessed` | `{ score: number }` | 每次复杂度评估完成后触发 |

### 配置选项

本模块无额外配置选项，使用 DeepeningBase 默认配置。

### 使用示例

  description: '重构系统架构，确保安全合规',

// { score: 0.91, level: 'intensive', depth: 4,
//   signals: { scope: 0.8, risk: 0.9, reasoning: 0, dependencyDepth: 0.6 } }

## 4. IterativeRefinement — 迭代精化器

> 源码：[iterative-refinement.js](file:///e:/Harness_V1_0429/src/runtime/deepening/iterative-refinement.js)

### 职责概述

执行"执行→审查→反馈→再执行"的迭代精化循环。每轮执行后由审查者评估质量，若未达标则将反馈注入任务上下文继续下一轮，直到质量达标或达到最大精化轮次。

### 核心API

#### 构造函数

```javascript
constructor(options)
```

| 参数 | 类型 | 说明 |
|------|------|------|
| `options` | `object` | 配置选项 |
| `options.maxRefinements` | `number` | 最大精化轮次，默认 `5` |
| `options.qualityThreshold` | `number` | 质量通过阈值，默认 `0.8` |

#### 静态属性

| 属性 | 值 | 说明 |
|------|------|------|
| `DEFAULT_MAX_REFINEMENTS` | `5` | 默认最大精化轮次 |
| `DEFAULT_QUALITY_THRESHOLD` | `0.8` | 默认质量阈值 |

#### 公共方法

| 方法 | 签名 | 返回值 | 说明 |
|------|------|--------|------|
| `refine` | `refine(executor, task, reviewer)` | `Promise<RefinementResult>` | 执行迭代精化循环 |
| `getStats` | `getStats()` | `object` | 返回 `activeRefinements` 等统计信息 |

**RefinementResult 结构**：

```javascript
{
  success: boolean,           // 是否成功完成（非错误终止）
  rounds: number,             // 实际执行轮次
  converged: boolean,         // 是否提前收敛（rounds < maxRefinements）
  error: string               // 错误信息（仅失败时存在）
}
```

**参数说明**：

| 参数 | 类型 | 说明 |
|------|------|------|
| `executor` | `object` | 执行器，必须实现 `execute(task)` 方法 |
| `task` | `object` | 任务对象，精化过程中会被扩展 `_ar` 和 `refinementInstructions` 属性 |
| `reviewer` | `function` | 审查函数，签名为 `async (result, task) → ReviewResult`。为 `null` 时只执行一轮 |

**ReviewResult 结构**：

```javascript
{
  approved: boolean,          // 是否直接通过
  qualityScore: number,       // 质量分数（与 qualityThreshold 比较）
  feedback: string            // 改进反馈（注入下一轮任务）
}
```

#### 精化循环流程

```
for i = 0 to maxRefinements:
  1. executor.execute(task) → result
  2. 若无 reviewer → 终止
  3. reviewer(result, task) → review
  4. 若 review.approved 或 review.qualityScore >= threshold → 终止
  5. 将 review.feedback 注入 task._ar 和 task.refinementInstructions
  6. 继续下一轮
```

### 事件列表

| 事件名 | 参数 | 说明 |
|--------|------|------|
| `refinement-round` | `{ round: number }` | 每轮精化完成后触发 |

### 配置选项

| 选项 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `maxRefinements` | `number` | `5` | 最大精化轮次 |
| `qualityThreshold` | `number` | `0.8` | 质量通过阈值 |

### 使用示例

```javascript
const IterativeRefinement = require('./src/runtime/deepening/iterative-refinement');

const refiner = new IterativeRefinement({
  maxRefinements: 3,
  qualityThreshold: 0.85
});

const result = await refiner.refine(
  { execute: async (task) => generateCode(task) },
  { prompt: '实现用户认证模块' },
  async (result, task) => ({
    qualityScore: 0.9,
    approved: false,
    feedback: '请增加输入验证和错误处理'
  })
);
console.log(result);
// { success: true, rounds: 2, converged: true }
```

### 与其他模块的交互关系

| 模块 | 交互方式 | 说明 |
|------|----------|------|
| DeepeningOrchestrator | 可被调用 | 编排器可使用迭代精化作为执行策略 |
| ConvergenceDetector | 互补 | 收敛检测器提供全局收敛判定，迭代精化提供单任务级精化 |
| ProgressiveDeepening | 互补 | 渐进深化关注深度级别，迭代精化关注反馈循环 |

## 6. RecurrentDeepeningScheduler — 循环深化调度器

> 源码：[recurrent-deepening-scheduler.js](file:///e:/Harness_V1_0429/src/runtime/deepening/recurrent-deepening-scheduler.js)

### 职责概述

循环执行深化推理任务，每轮由评估器打分，追踪质量分数变化，当分数达到收敛阈值时提前终止。与 `IterativeRefinement` 的区别在于：调度器侧重于"评估→收敛"循环，不涉及反馈注入；迭代精化侧重于"执行→审查→反馈"循环。

### 核心API

#### 构造函数

```javascript
constructor(options)
```

| 参数 | 类型 | 说明 |
|------|------|------|
| `options` | `object` | 配置选项 |
| `options.maxIterations` | `number` | 最大迭代次数，默认 `4` |
| `options.convergenceThreshold` | `number` | 收敛阈值，默认 `0.85` |
| `options.minImprovement` | `number` | 最小改善量，默认 `0.05` |

#### 静态属性

| 属性 | 值 | 说明 |
|------|------|------|
| `DEFAULT_MAX_ITERATIONS` | `4` | 默认最大迭代次数 |
| `DEFAULT_CONVERGENCE_THRESHOLD` | `0.85` | 默认收敛阈值 |
| `DEFAULT_MIN_IMPROVEMENT` | `0.05` | 默认最小改善量 |

#### 公共方法

| 方法 | 签名 | 返回值 | 说明 |
|------|------|--------|------|
| `execute` | `execute(agent, task, evaluator)` | `Promise<ScheduleResult>` | 执行循环深化调度 |
| `getStats` | `getStats()` | `object` | 返回 `maxIterations`、`convergenceThreshold`、`minImprovement` 等配置信息 |

**ScheduleResult 结构**：

```javascript
{
  success: boolean,           // 是否成功
  iterations: number,         // 实际迭代次数
  converged: boolean,         // 是否达到收敛阈值
  qualityScore: number,       // 最终质量分数
  qualityScores: number[],    // 每轮质量分数历史
  error: string               // 错误信息（仅失败时存在）
}
```

**参数说明**：

| 参数 | 类型 | 说明 |
|------|------|------|
| `agent` | `object` | 执行代理，必须实现 `execute(task)` 方法 |
| `task` | `object` | 任务对象（第2轮起注入 `_ar.iteration`） |
| `evaluator` | `function` | 评估函数，签名为 `async (result, task) → number \| { qualityScore, score }` |

#### 调度循环流程

```
for i = 0 to maxIterations:
  1. 若 i > 0，注入 task._ar = { iteration: i }
  2. agent.execute(task) → lastResult
  3. evaluator(lastResult, task) → score
  4. 记录 qualityScores
  5. 若 score >= convergenceThreshold → converged = true, 终止
```

### 事件列表

| 事件名 | 参数 | 说明 |
|--------|------|------|
| `iteration-complete` | `{ iteration: number, qualityScore: number }` | 每轮迭代完成后触发 |

### 配置选项

| 选项 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `maxIterations` | `number` | `4` | 最大迭代次数 |
| `convergenceThreshold` | `number` | `0.85` | 收敛阈值 |
| `minImprovement` | `number` | `0.05` | 最小改善量 |

### 使用示例

```javascript
const RecurrentDeepeningScheduler = require('./src/runtime/deepening/recurrent-deepening-scheduler');

const scheduler = new RecurrentDeepeningScheduler({
  maxIterations: 6,
  convergenceThreshold: 0.9
});

const result = await scheduler.execute(
  { execute: async (task) => solve(task) },
  { prompt: '优化数据库查询性能' },
  async (result, task) => result.performanceScore
);
console.log(result);
// { success: true, iterations: 3, converged: true, qualityScore: 0.92, qualityScores: [0.6, 0.78, 0.92] }
```

### 与其他模块的交互关系

| 模块 | 交互方式 | 说明 |
|------|----------|------|
| ConvergenceDetector | 互补 | 调度器使用简单阈值收敛，收敛检测器提供多信号收敛判定 |

- **最大迭代次数**：`Math.min(Math.floor(remaining / 2000), maxIterationCap)`，下限为1

| 选项 | 类型 | 默认值 | 说明 |

| `minBudgetRemaining` | `number` | `1000` | 最低剩余预算（比例或绝对值） |
| `maxIterationCap` | `number` | `10` | 最大迭代次数上限 |

  })

## 9. DeepeningStateManager — 深化状态管理器

> 源码：[deepening-state-manager.js](file:///e:/Harness_V1_0429/src/runtime/deepening/deepening-state-manager.js)

### 职责概述

通用状态机管理器，支持动态定义状态、转换规则、守卫条件（guard）和回调函数（onEnter/onExit）。与 `DeepeningStateMachine` 的区别在于：状态机是预定义的固定FSM，状态管理器是可编程的动态FSM框架。此外还提供独立的KV状态存储。

#### 转换执行流程

```
1. 查找转换规则（fromState → targetState）
2. 若未找到 → 抛出 HarnessError('STATE_MACHINE_ERROR')
3. 若有 guard 且 guard(context) 返回 false → 抛出 HarnessError
4. 执行 fromState 的 onExit 回调
5. 更新 currentState
6. 记录历史
7. 执行 toState 的 onEnter 回调
8. 触发 'state-transition' 事件
```

### 事件列表

| 事件名 | 参数 | 说明 |
|--------|------|------|
| `state-transition` | `{ machineId, from, to }` | 状态转换完成时触发 |
| `callback-error` | `{ machineId, callback, from/to, error }` | onEnter/onExit 回调异常时触发 |
| `state-changed` | `{ key, value }` | KV状态变更时触发 |

### 配置选项

本模块无额外配置选项，使用 DeepeningBase 默认配置。

### 使用示例

```javascript
const DeepeningStateManager = require('./src/runtime/deepening/deepening-state-manager');

const manager = new DeepeningStateManager();

manager.create('workflow-1', { initialState: 'draft' });
manager.addState('workflow-1', 'draft');
manager.addState('workflow-1', 'review', { onEnter: () => console.log('进入审查') });
manager.addState('workflow-1', 'approved', { final: true });
manager.addTransition('workflow-1', 'draft', 'review', {
  event: 'submit',
  guard: (ctx) => ctx && ctx.hasContent
});
manager.addTransition('workflow-1', 'review', 'approved', {
  event: 'approve'
});

await manager.transition('workflow-1', 'review', { hasContent: true });
await manager.transitionByEvent('workflow-1', 'approve');

console.log(manager.getCurrentState('workflow-1')); // 'approved'

manager.setState('lastApprover', 'alice');
console.log(manager.getState('lastApprover')); // 'alice'
```

## 10. DeepeningDependencyResolver — 深化依赖解析器

> 源码：[deepening-dependency-resolver.js](file:///e:/Harness_V1_0429/src/runtime/deepening/deepening-dependency-resolver.js)

### 职责概述

DAG（有向无环图）依赖解析器，管理深化推理任务之间的依赖关系。支持节点增删、依赖添加/移除、环检测、拓扑排序、传递依赖查询和执行顺序计算。当存在环时，拓扑排序和执行顺序计算会抛出异常。

### 核心API

#### 构造函数

```javascript
constructor()
```

无参数。内部初始化节点Map、正向邻接表、反向邻接表和边计数器。

#### 公共方法

| 方法 | 签名 | 返回值 | 说明 |
|------|------|--------|------|
| `addNode` | `addNode(id, data)` | `true` | 添加节点。若 `id` 为空则抛出 `DeepeningError('MISSING_PARAMETER')` |
| `removeNode` | `removeNode(id)` | `true` | 删除节点及其所有关联边 |
| `getNode` | `getNode(id)` | `Node \| null` | 获取节点信息（含实时计算的 `dependents`） |
| `addDependency` | `addDependency(from, to)` | `true` | 添加依赖边（from → to）。节点不存在时抛出 `HarnessError` |
| `removeDependency` | `removeDependency(from, to)` | `true` | 移除依赖边 |
| `getDependencies` | `getDependencies(id)` | `string[]` | 获取直接依赖列表（正向邻接） |
| `getDependents` | `getDependents(id)` | `string[]` | 获取直接被依赖列表（反向邻接） |
| `detectCycles` | `detectCycles(maxDepth)` | `string[][]` | 检测环，返回环路径列表。`maxDepth` 默认 `1000` |
| `topologicalSort` | `topologicalSort()` | `string[]` | 拓扑排序。存在环时抛出 `HarnessError('DEPENDENCY_CYCLE')` |
| `getExecutionOrder` | `getExecutionOrder()` | `string[]` | 获取执行顺序（等同于 `topologicalSort()`） |
| `getTransitiveDependencies` | `getTransitiveDependencies(id, depth)` | `string[]` | 获取传递依赖。`depth` 默认 `10` |
| `getStats` | `getStats()` | `object` | 返回 `totalNodes`、`totalEdges`、`cycles` 等统计信息 |

**Node 结构**：

```javascript
{
  id: string,                 // 节点ID
  data: any,                  // 节点数据
  dependents: string[]        // 被依赖列表（实时计算）
}
```

#### 环检测算法

采用DFS（深度优先搜索）+ 着色法：`visited` 集合标记已访问节点，`stack` 集合标记当前路径上的节点。当遇到 `stack` 中的节点时，检测到环。

#### 拓扑排序算法

采用Kahn算法（BFS）：计算入度，入度为0的节点入队，依次出队并减少后继入度，直到所有节点处理完毕。

### 事件列表

| 事件名 | 参数 | 说明 |
|--------|------|------|
| `dependency` | `{ from, to }` | 添加依赖边时触发 |

### 配置选项

本模块无配置选项。

### 使用示例

```javascript
const DeepeningDependencyResolver = require('./src/runtime/deepening/deepening-dependency-resolver');

const resolver = new DeepeningDependencyResolver();

resolver.addNode('A', { name: '数据采集' });
resolver.addNode('B', { name: '数据清洗' });
resolver.addNode('C', { name: '特征工程' });
resolver.addNode('D', { name: '模型训练' });

resolver.addDependency('A', 'B');
resolver.addDependency('B', 'C');
resolver.addDependency('C', 'D');
resolver.addDependency('A', 'C');

console.log(resolver.getExecutionOrder());
// ['A', 'B', 'C', 'D']

console.log(resolver.getTransitiveDependencies('A'));
// ['B', 'C', 'D']

console.log(resolver.detectCycles());
// [] — 无环

resolver.addDependency('D', 'A');
console.log(resolver.detectCycles());
// [['A']] — 检测到环

try {
  resolver.topologicalSort();
} catch (e) {
  console.log(e.message); // 'cycle detected'
}
```

## R38 修复记录

### `??` vs `||` 运算符误用系统性修复

**缺陷**：多个模块的数值配置参数使用`??`（空值合并）运算符提供默认值。对于计数型/容量型参数（如maxSize、maxHistory、limit等），`0`作为配置值通常无意义且可能导致功能异常（如容量为0导致所有数据被拒绝），应使用`||`运算符在`0`时也回退到默认值。

**修复**：将以下参数从`??`改为`||`运算符：

| 模块 | 参数 | 修复 |
|------|------|------|
| DeepeningOrchestrator | convergenceThreshold ?? 0.85 | convergenceThreshold \|\| 0.85 |
| DeepeningStrategyPlugin | qualityThreshold ?? 0.85 | qualityThreshold \|\| 0.85 |
| DeepeningStrategyPlugin | qualityThreshold ?? 0.9 | qualityThreshold \|\| 0.9 |
| ProgressiveDeepening | earlyStopThreshold ?? 0.95 | earlyStopThreshold \|\| 0.95 |
| TokenAwareDeepening | budget ?? 1000000000 | budget \|\| 1000000000 |
| DeepeningEventReplay | speed ?? 1 | speed \|\| 1 |
| DeepeningDependencyResolver | maxDepth ?? 1000 | maxDepth \|\| 1000 |

**影响范围**：数值配置参数为0时正确回退到默认值，避免功能异常。
