> 版本：2.73.4 | 模块：src/permission/

---

## 概述

权限执行引擎是框架的安全核心，由三个模块组成，形成"授权→守卫→审计"的完整闭环：

- **RBACEnforcer** — 基于角色的访问控制，解决"谁能做什么"
- **PermissionGuard** — 文件/命令安全守卫，解决"操作是否安全"
- **AuditLogger** — 链式哈希审计日志，解决"做了什么留痕"

```
RBACEnforcer (授权) → PermissionGuard (守卫) → AuditLogger (审计)
     │                      │                        │
     ├─ Agent能否执行Skill? ├─ 文件路径是否安全?      ├─ 记录所有权限决策
     ├─ Skill执行级别?      ├─ 文件锁冲突?            ├─ 链式哈希防篡改
     └─ 双向权限验证        ├─ 命令是否危险?           └─ 查询/统计/导出
                            └─ 操作确认过期?
```

## 一、RBACEnforcer — 基于角色的访问控制

> 源文件：src/permission/rbac-enforcer.js

### 类结构

`RBACEnforcer` 继承自 `EventEmitter`，通过 `withShutdown()` 混入优雅关闭能力。

### 构造函数

```javascript
constructor(projectRoot)
```

| 参数 | 类型 | 说明 |
|------|------|------|
| `projectRoot` | `string` | 项目根目录路径（必须通过 `validateProjectRoot` 校验） |

### 核心API

| 方法 | 签名 | 说明 |
|------|------|------|
| `load` | `load(): { agentsLoaded, skillsLoaded, errors, busy }` | 从 `.harness/agents/` 和 `.harness/skills/` 加载权限定义 |
| `canExecute` | `canExecute(agentId, skillId): boolean` | 双向权限检查 |
| `getAgentModel` | `getAgentModel(agentId): string` | 获取Agent配置的模型名称 |
| `startWatching` | `startWatching(): void` | 启动文件监视器，自动热重载 |
| `stopWatching` | `stopWatching(): void` | 停止文件监视器 |
| `isHealthy` | `isHealthy(): boolean` | 健康检查 |

### 双向权限验证

`canExecute()` 执行两个方向的验证：

1. **Agent→Skill**：Agent的 `available_skills` 中是否包含该Skill
2. **Skill→Agent**：Skill的 `applicable_agents` 中是否包含该Agent

两个方向都通过才允许执行。同时对ID做格式校验（禁止路径特殊字符、长度不超过128）。

### 执行级别（Enforcement）

| 级别 | 值 | 行为 |
|------|-----|------|
| 严格 | `strict` | 必须显式授权，未列出即禁止 |
| 推荐 | `recommended` | 默认允许，未列出时警告但不阻止 |
| 可选 | `optional` | 完全可选，仅记录日志 |

### Agent定义格式

Agent定义存储在 `.harness/agents/` 目录下的Markdown文件中，通过frontmatter描述：

```yaml
---
agent_id: task-worker
role: executor
available_skills:
  - tdd-implement
  - module-development
  - bug-fix
auto_route: true
tdd_enforced: true
model: gpt-4
level: 2
permissions:
  file_write: true
  file_delete: false
  command_execute: true
---
```

### Skill定义格式

Skill定义存储在 `.harness/skills/` 目录下的Markdown文件中，通过frontmatter描述：

```yaml
---
skill_id: tdd-implement
enforcement: strict
depends_on:
  - requirement-analysis
applicable_agents:
  - task-worker
  - domain-analyst
phase: module-development
priority: high
---
```

### 热重载机制

| 参数 | 值 | 说明 |
|------|-----|------|
| `RELOAD_DEBOUNCE_MS` | `1000` | 重载防抖时间 |
| `COOLDOWN_MS` | `30000` | 重载冷却时间 |
| `MAX_RELOAD_COUNT` | `100` | 单次会话最大重载次数 |

超过100次重载后暂停监视器30秒冷却。加载失败时保留旧数据不覆盖。

### 配置常量

| 常量 | 值 | 说明 |
|------|-----|------|
| `MAX_LOAD_ERRORS` | `200` | 最大加载错误数 |
| `MAX_ID_LENGTH` | `128` | ID最大长度 |
| `MAX_FILE_SIZE` | `1MB` | 单文件最大大小 |
| `VALID_PERMISSION_KEYS` | 6个键 | 有效权限键集合 |
| `VALID_ENFORCEMENTS` | strict/recommended/optional | 有效执行级别 |

### 事件

| 事件名 | 触发时机 | 载荷 |
|--------|---------|------|
| `load-warnings` | 加载有错误 | `Array<LoadError>` |
| `watching-started` | 监视器启动 | `{ directories }` |
| `permissions-reloaded` | 热重载后 | `{ eventType, filename, agentsLoaded, skillsLoaded, errors }` |
| `reload-stopped` | 重载超限 | `{ reason: 'too_many_reloads' }` |
| `watcher-resumed` | 冷却期过后 | `{ reason: 'cooldown_expired' }` |
| `reload-error` | 重载异常 | `Error` |

## 二、PermissionGuard — 文件操作权限守卫

> 源文件：src/permission/permission-guard.js

### 类结构

`PermissionGuard` 继承自 `EventEmitter`，通过 `withShutdown()` 混入优雅关闭能力。

### 构造函数

```javascript
constructor(projectRoot)
```

| 参数 | 类型 | 说明 |
|------|------|------|
| `projectRoot` | `string` | 项目根目录路径 |

### 核心API

#### 文件操作检查

| 方法 | 签名 | 说明 |
|------|------|------|
| `checkFileWrite` | `checkFileWrite(filePath, agentId): { allowed, reason? }` | 文件写入权限检查 |
| `checkFileDelete` | `checkFileDelete(filePath, agentId?): { allowed, reason?, requiresConfirmation? }` | 文件删除权限检查 |
| `checkFileRead` | `checkFileRead(filePath, agentId?): { allowed, reason? }` | 文件读取权限检查 |
| `enforceFileWrite` | `enforceFileWrite(filePath, agentId): true` | 强制版写入检查，不允许时抛出PermissionError |
| `enforceCommand` | `enforceCommand(command, agentId): true` | 强制版命令检查，危险命令时抛出PermissionError |

#### 命令安全检查

| 方法 | 签名 | 说明 |
|------|------|------|
| `checkCommand` | `checkCommand(command, agentId?): { allowed, reason?, requiresConfirmation? }` | 命令安全检查 |

#### 文件锁管理

| 方法 | 签名 | 说明 |
|------|------|------|
| `acquireLock` | `acquireLock(filePath, agentId): boolean` | 获取文件锁 |
| `releaseLock` | `releaseLock(filePath, agentId): boolean` | 释放文件锁 |
| `getLockHolder` | `getLockHolder(filePath): string\|null` | 获取锁持有者 |

#### 确认管理

| 方法 | 签名 | 说明 |
|------|------|------|
| `recordConfirmation` | `recordConfirmation(agentId, action, target): boolean` | 记录操作确认 |
| `isConfirmationValid` | `isConfirmationValid(agentId, action, target): boolean` | 检查确认是否有效 |
| `setConfirmationExpiry` | `setConfirmationExpiry(ms): PermissionGuard` | 设置确认过期时间（链式调用） |

### 路径遍历防护

`_isWithinProject()` 方法实现多层防护：

1. **字符串前缀检查**：路径必须以项目根目录开头
2. **真实路径验证**：`fs.realpathSync` 解析符号链接
3. **父目录回退**：文件不存在时验证父目录
4. **边界检查**：`path.relative` 确认路径不超出项目范围

### 系统文件保护

| 文件/目录 | 权限 |
|----------|------|
| `.harness/config.json` | 只读 |
| `.harness/agents/` | 只读 |
| `.harness/skills/` | 只读 |
| `.harness/rules/` | 只读 |
| `.harness/workspace/` | 只读 |
| `.harness/sessions/` | 可写 |
| `.harness/checkpoints/` | 可写 |

### 危险命令检测

`DANGEROUS_SHELL_PATTERNS` 包含50+条正则模式，覆盖：

- 系统破坏：`rm -rf /`、`format`、`del /s`
- 权限提升：`sudo`、`chmod 777`、`chown`
- 网络危险：`curl | sh`、`wget | bash`
- 进程操控：`kill -9 1`、`pkill init`
- 数据泄露：`cat /etc/shadow`、`cat /etc/passwd`

安全命令白名单：`ls`、`pwd`、`echo`、`cat`、`head`、`tail`、`wc`、`git status/log/diff/branch`

### 文件锁机制

| 参数 | 值 | 说明 |
|------|-----|------|
| `MAX_LOCKS` | `10000` | 最大锁数量 |
| `DEFAULT_LOCK_TIMEOUT_MS` | `5分钟` | 锁默认超时 |
| `MAX_LOCK_RENEWALS` | `10` | 最大续期次数 |

- 同一Agent可重入（续期），最多10次
- 锁总数超限时先驱逐过期锁
- 超时锁自动释放

### 持久化机制

- **存储路径**：`.harness/permission/guard-state.json`
- **写入方式**：`writeAtomic` 原子写入
- **防抖策略**：5秒轮询式持久化
- **恢复机制**：构造时通过 `JsonStoreRestorer.loadSync()` 恢复

### 配置常量

| 常量 | 值 | 说明 |
|------|-----|------|
| `MAX_CONFIRMATIONS` | `5000` | 最大确认记录数 |
| `MAX_CONFIRMATION_EXPIRY_MS` | `24小时` | 确认最大过期时间 |
| `DEFAULT_CONFIRMATION_EXPIRY_MS` | `5分钟` | 确认默认过期时间 |
| `MAX_JSON_FILE_SIZE` | `10MB` | JSON文件最大大小 |

### 事件

| 事件名 | 触发时机 | 载荷 |
|--------|---------|------|
| `confirmation-recorded` | 确认记录 | `{ agentId, action, target, confirmedAt }` |
| `persist-error` | 持久化失败 | `Error` |
| `restore-error` | 恢复失败 | `Error` |

## 三、AuditLogger — 链式哈希审计日志

> 源文件：src/permission/audit-logger.js

### 类结构

`AuditLogger` 继承自 `EventEmitter`，通过 `withShutdown()` 混入优雅关闭能力。

### 构造函数

```javascript
constructor(projectRoot, options)
```

| 参数 | 类型 | 说明 |
|------|------|------|
| `projectRoot` | `string?` | 项目根目录，提供时启用持久化 |
| `options.maxEntries` | `number?` | 最大日志条目数，默认10000 |

### 核心API

| 方法 | 签名 | 说明 |
|------|------|------|
| `log` | `log(event): void` | 记录审计日志 |
| `verifyIntegrity` | `verifyIntegrity(): { total, tampered, tamperedIndices, valid }` | 验证链式哈希完整性 |
| `query` | `query(filter?): Object[]` | 查询日志，支持agent/action/result/target/responsibility过滤 |
| `getRecent` | `getRecent(count?): Object[]` | 获取最近N条日志 |
| `getStats` | `getStats(): Object` | 统计信息 |
| `clear` | `clear(authorizedBy): void` | 清空日志（需授权） |
| `export` | `export(): string` | 导出为JSON字符串 |
| `flush` | `flush(): void` | 刷新持久化缓冲区 |

### 链式哈希机制

每条日志通过SHA-256哈希链式连接，确保不可篡改：

```
hashData = encodeURIComponent([index, timestamp, agent, action, target, result, reason, details, responsibility, prevHash].join('&'))
hash = SHA-256(hashData)
```

篡改任何一条日志都会导致后续所有日志的哈希校验失败。

### 日志事件结构

```javascript
{
  agent: 'task-worker',         // 执行者
  action: 'file-write',         // 操作类型
  target: '/src/auth.js',       // 操作目标
  result: 'allowed',            // 结果：allowed/denied
  reason: 'permission-check',   // 原因
  details: '...',               // 详细信息（最大10000字符）
  responsibility: 'system'      // 责任归属
}
```

### 完整性验证

`verifyIntegrity()` 遍历所有条目，重新计算每条哈希并与存储的 `_hash` 比对：

```javascript
const result = auditLogger.verifyIntegrity();
// result = { total: 150, tampered: 0, tamperedIndices: [], valid: true }
```

### 恢复与自愈

恢复时执行三重校验：

1. **必需键校验**：必须包含 timestamp/agent/action/target/result/_hash
2. **危险键检测**：包含 `__proto__`/`constructor`/`prototype` 等的条目直接丢弃
3. **哈希完整性**：不匹配的条目跳过，自动重新计算 `_lastHash`

### 持久化机制

- **存储路径**：`.harness/audit/audit-log.json`
- **写入方式**：`createPersister` 防抖持久化器 + `writeAtomic` 原子写入
- **防抖间隔**：500ms
- **文件上限**：50MB

### 配置常量

| 常量 | 值 | 说明 |
|------|-----|------|
| `MAX_LOG_ENTRIES` | `10000` | 最大日志条目数 |
| `MAX_DETAIL_LENGTH` | `10000` | 详情字段最大长度 |
| `MAX_FIELD_LENGTH` | `1000` | 普通字段最大长度 |
| `MAX_AUDIT_LOG_FILE_SIZE` | `50MB` | 审计日志文件最大大小 |
| `DEFAULT_PERSIST_DEBOUNCE_MS` | `500` | 持久化防抖间隔 |

### 事件

| 事件名 | 触发时机 | 载荷 |
|--------|---------|------|
| `persist-error` | 持久化失败 | `Error` |
| `restore-error` | 恢复失败 | `Error` |
| `integrity-violation` | 检测到哈希不一致 | `{ total, tampered, tamperedIndices, valid }` |
| `shutdown` | 关闭 | — |

## 四、三模块集成使用

### 初始化流程

```javascript
const RBACEnforcer = require('./src/permission/rbac-enforcer');
const PermissionGuard = require('./src/permission/permission-guard');
const AuditLogger = require('./src/permission/audit-logger');

const projectRoot = '/path/to/project';

// 1. 初始化审计日志（最先启动，记录所有操作）
const auditLogger = new AuditLogger(projectRoot, { maxEntries: 10000 });

// 2. 初始化权限守卫
const permissionGuard = new PermissionGuard(projectRoot);

// 3. 初始化RBAC执行器
const enforcer = new RBACEnforcer(projectRoot);
const { agentsLoaded, skillsLoaded, errors } = enforcer.load();

// 4. 启动文件监视（可选）
enforcer.startWatching();
```

### 权限检查流程

```javascript
// 步骤1：RBAC检查 — Agent是否有权执行Skill
if (!enforcer.canExecute('task-worker', 'tdd-implement')) {
  auditLogger.log({
    agent: 'task-worker',
    action: 'skill-execute',
    target: 'tdd-implement',
    result: 'denied',
    reason: 'rbac-check-failed'
  });
  throw new PermissionError('PERMISSION_SKILL_NOT_ALLOWED', 'Agent not authorized');
}

// 步骤2：文件操作守卫 — 检查文件写入权限
const writeCheck = permissionGuard.checkFileWrite('/src/auth.js', 'task-worker');
if (!writeCheck.allowed) {
  auditLogger.log({
    agent: 'task-worker',
    action: 'file-write',
    target: '/src/auth.js',
    result: 'denied',
    reason: writeCheck.reason
  });
  throw new PermissionError('PERMISSION_FILE_PROTECTED', writeCheck.reason);
}

// 步骤3：命令安全检查
const cmdCheck = permissionGuard.checkCommand('npm test', 'task-worker');
if (!cmdCheck.allowed) {
  auditLogger.log({
    agent: 'task-worker',
    action: 'command-execute',
    target: 'npm test',
    result: 'denied',
    reason: cmdCheck.reason
  });
  return;
}

// 步骤4：记录允许的操作
auditLogger.log({
  agent: 'task-worker',
  action: 'skill-execute',
  target: 'tdd-implement',
  result: 'allowed',
  reason: 'all-checks-passed'
});
```

### 关闭流程

```javascript
// 按逆序关闭
await enforcer.shutdown();      // 停止监视器
await permissionGuard.shutdown(); // 持久化锁和确认状态
await auditLogger.shutdown();    // 刷新审计日志
```

## 五、安全设计原则

### 纵深防御

权限执行引擎采用三层防御：

1. **授权层**（RBACEnforcer）：从角色维度控制"谁能做什么"
2. **守卫层**（PermissionGuard）：从操作维度控制"什么操作是安全的"
3. **审计层**（AuditLogger）：从事后维度记录"做了什么"

### 最小权限原则

- Agent默认无任何权限，必须显式授权
- `strict` 执行级别下，未列出的操作一律禁止
- 文件锁确保同一时间只有一个Agent可修改文件

### 不可抵赖性

- 链式哈希确保审计日志不可篡改
- 每条日志包含完整的操作上下文
- `clear()` 操作本身也被记录

### 故障安全

- RBAC加载失败时保留旧数据，不降级为"允许所有"
- 持久化失败时重试5次，最终放弃但标记脏数据
- 路径遍历检查多层防护，任一层失败即拒绝
