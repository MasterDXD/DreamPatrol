# 模块详解 — 适配器子系统

> **文件路径**：`src/runtime/adapter/`
> **组件数量**：9个
> **依赖关系**：依赖基础设施子系统（EventEmitter、BoundedMap/BoundedArray、debug-logger、safe-assign、safe-parse）和思维子系统（ProviderAdapterBase）
> **核心定位**：为Harness多Agent框架提供外部服务适配能力，涵盖媒体生成提供商抽象、演示文稿生成、CMA云端会话备份、成果桥接、会话代理和密钥管理

---

## 一、概述

适配器子系统是Harness Engineering多Agent框架的外部服务集成层，位于`src/runtime/adapter/`目录下，包含9个核心组件。该子系统遵循"接口-基类-实现"三层抽象和"适配器模式"，将外部服务（媒体生成API、CMA云服务、Vault密钥服务等）统一封装为标准化的内部接口，使上层业务逻辑无需关心外部服务的协议细节。

### 设计原则

1. **统一接口抽象**：MediaProviderInterface定义媒体生成提供商的统一协议，所有Provider适配器必须实现此接口
2. **基类复用**：MediaProviderBase在接口基础上提供重试、超时、并发控制、指标追踪等通用能力，子类只需关注业务逻辑
3. **路由与故障转移**：MediaProviderRouter支持多种路由策略和自动故障转移，确保服务高可用
4. **离线降级**：所有CMA相关适配器在无API Key时自动进入离线模式，不影响本地功能
5. **容量限制**：所有集合类使用BoundedMap/BoundedArray，防止内存泄漏
6. **优雅关闭**：所有组件实现`_onShutdown()`方法，确保资源正确释放

### 组件分类

| 分类 | 组件 | 说明 |
|------|------|------|
| 媒体提供商框架 | MediaProviderInterface、MediaProviderBase、MediaProviderRouter、index.js | 统一接口、基类、路由器与入口 |
| 媒体提供商实现 | PresentationProvider | 演示文稿生成适配器 |
| CMA云服务适配 | CloudSessionBackup、CMAOutcomesBridge、CMASessionProxy | 会话备份、成果桥接、会话代理 |
| 密钥管理 | VaultSecretProvider | Vault密钥读写与缓存 |

## 三、核心组件详解

### 3.1 MediaProviderInterface

**文件**：`media-provider/media-provider-interface.js`

#### 职责与定位

媒体生成提供商统一接口，借鉴OpenClaw 4.5的Provider统一接口设计，支持视频/音乐/图像生成。所有媒体Provider适配器必须实现此接口。定义了连接管理、健康检查、任务生成/查询/取消和能力查询的标准协议，通过`withShutdown`混入实现优雅关闭。

#### 关键API

| 方法 | 说明 | 返回值 |
|------|------|--------|
| `connect()` | 连接到Provider服务 | `Promise<{connected: boolean, provider: string}>` |
| `disconnect()` | 断开Provider连接 | `Promise<void>` |
| `healthCheck()` | 健康检查 | `Promise<{healthy: boolean, latency: number}>` |
| `generate(request)` | 生成媒体内容（子类必须实现） | `Promise<{taskId: string, status: string, provider: string}>` |
| `getTaskStatus(taskId)` | 查询任务状态（子类必须实现） | `Promise<{taskId: string, status: string, result?: Object, error?: string}>` |
| `cancelTask(taskId)` | 取消任务（子类必须实现） | `Promise<{cancelled: boolean}>` |
| `getCapabilities()` | 获取Provider支持的模式和能力 | `{modes: string[], maxDuration: number, maxResolution: string, provider: string}` |
| `isConnected()` | 检查Provider是否已连接 | `boolean` |

**generate请求参数**：

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `request.prompt` | string | 是 | 文本描述 |
| `request.mode` | string | 否 | 生成模式：`'generate'`/`'imageToVideo'`/`'videoToVideo'` |
| `request.options` | Object | 否 | Provider特定选项 |

#### 事件

| 事件名 | 触发时机 | 数据 |
|--------|---------|------|
| `connected` | 连接成功 | — |
| `disconnected` | 断开连接 | — |
| `health-changed` | 健康状态变更 | `{healthy: boolean, latency: number}` |
| `error` | 发生错误 | — |
| `task-created` | 任务创建 | — |
| `task-completed` | 任务完成 | — |
| `task-failed` | 任务失败 | — |

#### 配置项

| 常量 | 值 | 说明 |
|------|-----|------|
| `PROVIDER_EVENTS.CONNECTED` | `'connected'` | 连接成功事件 |
| `PROVIDER_EVENTS.DISCONNECTED` | `'disconnected'` | 断开连接事件 |
| `PROVIDER_EVENTS.HEALTH_CHANGED` | `'health-changed'` | 健康状态变更事件 |
| `PROVIDER_EVENTS.ERROR` | `'error'` | 错误事件 |
| `PROVIDER_EVENTS.TASK_CREATED` | `'task-created'` | 任务创建事件 |
| `PROVIDER_EVENTS.TASK_COMPLETED` | `'task-completed'` | 任务完成事件 |
| `PROVIDER_EVENTS.TASK_FAILED` | `'task-failed'` | 任务失败事件 |

#### 使用示例

```javascript
const MediaProviderInterface = require('./media-provider-interface');

// MediaProviderInterface是抽象类，通常不直接实例化
// 子类必须实现 generate(), getTaskStatus(), cancelTask()
class MyProvider extends MediaProviderInterface {
  get name() { return 'my-provider'; }
  async generate(request) {
    return { taskId: 'task-1', status: 'processing', provider: this.name };
  }
  async getTaskStatus(taskId) {
    return { taskId, status: 'completed', result: {} };
  }
  async cancelTask(taskId) {
    return { cancelled: true };
  }
}
```

### 3.2 MediaProviderBase

**文件**：`media-provider/media-provider-base.js`

#### 职责与定位

媒体生成提供商适配器基类，在MediaProviderInterface基础上增加重试机制、请求超时、并发控制和指标追踪等网络通信能力。子类只需覆盖`_doConnect`、`_doGenerate`、`_doGetTaskStatus`、`_doCancelTask`等钩子方法即可完成具体Provider适配。

#### 关键API

| 方法 | 说明 | 返回值 |
|------|------|--------|
| `connect()` | 连接到Provider服务（带重试机制） | `Promise<{connected: boolean, provider: string}>` |
| `disconnect()` | 断开Provider连接 | `Promise<void>` |
| `healthCheck()` | 健康检查（带请求超时） | `Promise<{healthy: boolean, latency: number, error: string\|null}>` |
| `generate(request)` | 生成媒体内容（带重试、超时和并发控制） | `Promise<{taskId: string, status: string, provider: string}>` |
| `getTaskStatus(taskId)` | 查询任务状态（带超时） | `Promise<{taskId: string, status: string, result?: Object, error?: string}>` |
| `cancelTask(taskId)` | 取消任务（带超时） | `Promise<{cancelled: boolean}>` |
| `getStats()` | 获取请求度量统计 | `Object` |

**getStats返回值**：

| 字段 | 类型 | 说明 |
|------|------|------|
| `totalRequests` | number | 总请求数 |
| `successfulRequests` | number | 成功请求数 |
| `failedRequests` | number | 失败请求数 |
| `totalRetries` | number | 总重试次数 |
| `activeTasks` | number | 活跃任务数 |
| `connected` | boolean | 是否已连接 |
| `provider` | string | Provider名称 |
| `byErrorType` | Object | 按错误类型统计 |

#### 子类需覆盖的钩子方法

| 方法 | 说明 | 默认行为 |
|------|------|---------|
| `_doConnect()` | 实际连接逻辑 | 抛出错误，必须实现 |
| `_doDisconnect()` | 实际断开逻辑 | 空实现 |
| `_doHealthCheck()` | 实际健康检查逻辑 | 返回`{healthy: true}` |
| `_doGenerate(request)` | 实际生成逻辑 | 抛出错误，必须实现 |
| `_doGetTaskStatus(taskId)` | 实际状态查询逻辑 | 抛出错误，必须实现 |
| `_doCancelTask(taskId)` | 实际取消逻辑 | 抛出错误，必须实现 |

#### 错误分类体系（ERROR_TYPES）

| 类型 | 值 | 触发条件 |
|------|-----|---------|
| `NETWORK` | `'network'` | ECONNREFUSED/ECONNRESET/ETIMEDOUT/ENOTFOUND |
| `AUTH` | `'auth'` | HTTP 401/403 |
| `RATE_LIMIT` | `'rate-limit'` | HTTP 429 |
| `SERVER` | `'server'` | HTTP 5xx |
| `TIMEOUT` | `'timeout'` | 超时 |
| `UNKNOWN` | `'unknown'` | 无法分类 |

#### 事件

继承MediaProviderInterface的全部事件，额外增加：

| 事件名 | 触发时机 | 数据 |
|--------|---------|------|
| `connection-error` | 连接失败 | 错误消息字符串 |

#### 配置项

| 配置 | 默认值 | 说明 |
|------|--------|------|
| `maxRetries` | 3 | 最大重试次数 |
| `retryDelayMs` | 1000 | 重试基础延迟（毫秒） |
| `requestTimeoutMs` | 300000 | 请求超时（毫秒，默认5分钟） |
| `maxConcurrentTasks` | 5 | 最大并发任务数 |
| `taskHistorySize` | 100 | 任务历史记录大小 |

#### 使用示例

```javascript
const MediaProviderBase = require('./media-provider-base');

class VideoProvider extends MediaProviderBase {
  get name() { return 'video-provider'; }

  async _doConnect() {
    // 实际连接逻辑
    const resp = await fetch('https://api.video.com/health');
    if (!resp.ok) throw new Error('Connection failed');
    return { connected: true, provider: this.name };
  }

  async _doGenerate(request) {
    // 实际生成逻辑，自动享受重试/超时/并发控制
    const resp = await fetch('https://api.video.com/generate', {
      method: 'POST',
      body: JSON.stringify(request),
    });
    return resp.json();
  }

  async _doGetTaskStatus(taskId) {
    const resp = await fetch('https://api.video.com/tasks/' + taskId);
    return resp.json();
  }

  async _doCancelTask(taskId) {
    await fetch('https://api.video.com/tasks/' + taskId + '/cancel', { method: 'POST' });
    return { cancelled: true };
  }
}

const provider = new VideoProvider({ maxRetries: 5, requestTimeoutMs: 60000 });
await provider.connect();
const result = await provider.generate({ prompt: '生成一段日落视频', mode: 'generate' });
console.log(provider.getStats());
```

### 3.3 MediaProviderRouter

**文件**：`media-provider/media-provider-router.js`

#### 职责与定位

媒体生成提供商路由器，自动选择最优Provider，支持多种路由策略和故障转移。管理多个Provider的生命周期，根据请求类型和可用性将媒体请求分发到合适的Provider。不使用withShutdown混入，而是实现独立的shutdown方法。

#### 关键API

| 方法 | 说明 | 返回值 |
|------|------|--------|
| `registerProvider(provider)` | 注册Provider（无效Provider或缺少name时抛出Error） | `void` |
| `unregisterProvider(name)` | 注销Provider | `boolean` |
| `route(request)` | 路由请求到最优Provider（支持故障转移） | `Promise<{taskId: string, status: string, provider: string}>` |
| `checkAllHealth()` | 健康检查所有Provider | `Promise<Object.<string, {healthy: boolean, latency: number}>>` |
| `getStats()` | 获取路由统计 | `Object` |
| `getProviders()` | 获取所有已注册Provider | `Object[]` |
| `getProvider(name)` | 获取指定名称的Provider | `Object\|null` |
| `guardShutdown()` | 检查是否已关闭，已关闭时抛出Error | `void` |
| `isHealthy()` | 检查路由器是否健康 | `boolean` |
| `shutdown()` | 关闭路由器，断开所有Provider连接 | `void` |

**属性**：

| 属性 | 类型 | 说明 |
|------|------|------|
| `strategy` (get/set) | string | 路由策略，设置无效策略时抛出Error |

**getStats返回值**：

| 字段 | 类型 | 说明 |
|------|------|------|
| `totalRouted` | number | 总路由请求数 |
| `byProvider` | Object | 按Provider统计请求数 |
| `fallbacks` | number | 故障转移次数 |
| `strategy` | string | 当前路由策略 |
| `providerCount` | number | 已注册Provider数 |

#### 路由策略（ROUTING_STRATEGIES）

| 策略 | 值 | 选择逻辑 |
|------|-----|---------|
| `COST_OPTIMAL` | `'cost-optimal'` | 选择列表最后一个Provider（默认策略） |
| `QUALITY_OPTIMAL` | `'quality-optimal'` | 选择列表第一个Provider |
| `SPEED_OPTIMAL` | `'speed-optimal'` | 选择健康检查延迟最低的Provider |
| `ROUND_ROBIN` | `'round-robin'` | 轮询选择 |
| `FAILFAST` | `'failfast'` | 首选Provider失败后直接抛出异常，不进行故障转移 |

#### 事件

| 事件名 | 触发时机 | 数据 |
|--------|---------|------|
| `provider-registered` | Provider注册 | `{provider: string}` |
| `provider-unregistered` | Provider注销 | `{provider: string}` |
| `routed` | 请求路由成功 | `{provider: string, taskId: string}` |
| `fallback` | 故障转移 | `{from: string, to: string}` |

#### 使用示例

```javascript
const { MediaProviderRouter, ROUTING_STRATEGIES } = require('./media-provider-router');
const router = new MediaProviderRouter({ strategy: ROUTING_STRATEGIES.SPEED_OPTIMAL });

// 注册多个Provider
router.registerProvider(presentationProvider);
router.registerProvider(videoProvider);

// 路由请求（自动选择最优Provider）
const result = await router.route({
  prompt: '生成产品介绍PPT',
  mode: 'generate',
});

// 故障转移：首选Provider失败时自动切换到备选Provider
// FAILFAST策略除外：失败后直接抛出异常

// 健康检查所有Provider
const healthResults = await router.checkAllHealth();

// 切换路由策略
router.strategy = ROUTING_STRATEGIES.ROUND_ROBIN;

// 关闭路由器
router.shutdown();
```

### 3.4 PresentationProvider

**文件**：`media-provider/presentation-provider.js`

#### 职责与定位

演示文稿生成适配器，融合Presenton开源项目（开源版Gamma）的设计理念，通过API生成专业PPT。继承MediaProviderBase，复用重试/超时/并发控制/指标追踪等基础设施。支持API远程生成和本地降级生成两种模式。

#### 生成模式（PRESENTATION_MODES）

| 模式 | 值 | 说明 |
|------|-----|------|
| `GENERATE` | `'generate'` | 文本→PPT，从文本描述生成完整演示文稿 |
| `TEXT_TO_SLIDES` | `'textToSlides'` | 文本→幻灯片，将长文本拆分为多页幻灯片 |
| `OUTLINE_TO_PRESENTATION` | `'outlineToPresentation'` | 大纲→PPT，从结构化大纲生成演示文稿 |

#### 关键API

| 方法 | 说明 | 返回值 |
|------|------|--------|
| `generate(request)` | 生成演示文稿（继承自基类，带重试/超时/并发控制） | `Promise<Object>` |
| `getCapabilities()` | 获取支持的模式和能力 | `{modes: string[], maxSlides: number, supportedFormats: string[], provider: string}` |
| `getTemplates()` | 获取可用模板列表 | `Array<Object>` |
| `getStats()` | 获取统计信息（含缓存和API状态） | `Object` |

**generate请求选项**：

| 参数 | 类型 | 说明 |
|------|------|------|
| `request.prompt` | string | 文本描述或大纲内容（必填，最大5000字符） |
| `request.mode` | string | 生成模式，默认`'generate'` |
| `request.options.template` | string | 模板ID，默认`'professional'` |
| `request.options.theme` | string | 主题（`'light'`/`'dark'`），默认`'light'` |
| `request.options.format` | string | 输出格式（`'pptx'`/`'pdf'`/`'html'`），默认`'pptx'` |
| `request.options.maxSlides` | number | 最大幻灯片数，默认50 |
| `request.options.language` | string | 内容语言，默认`'en'` |

**getStats返回值**（扩展基类）：

| 字段 | 类型 | 说明 |
|------|------|------|
| `cachedTasks` | number | 缓存任务数 |
| `apiEndpoint` | string | API端点状态（`'configured'`/`'local'`） |

#### 默认模板（DEFAULT_TEMPLATES）

| 模板ID | 名称 | 分类 |
|--------|------|------|
| `professional` | Professional | business |
| `creative` | Creative | design |
| `technical` | Technical | engineering |
| `minimal` | Minimal | general |

#### 配置项

| 配置 | 默认值 | 说明 |
|------|--------|------|
| `apiEndpoint` | `''` | Presenton API端点URL（空则使用本地模式） |
| `apiKey` | `''` | API密钥 |
| `defaultTemplate` | `'professional'` | 默认模板ID |
| `defaultTheme` | `'light'` | 默认主题 |
| `maxSlidesPerPresentation` | 50 | 每个演示文稿最大幻灯片数 |
| `maxPromptLength` | 5000 | 最大提示词长度 |
| `supportedFormats` | `['pptx', 'pdf', 'html']` | 支持的输出格式 |
| `taskCacheSize` | 200 | 任务缓存大小 |

#### 安全改进

PresentationProvider在所有HTTP响应处理中添加了响应大小限制，防止恶意或异常的大体积响应导致内存耗尽：

| 安全常量 | 值 | 说明 |
|---------|-----|------|
| `MAX_RESPONSE_SIZE` | 10MB (10485760 bytes) | HTTP响应最大大小限制 |

**4处HTTP响应处理均添加了大小检查**：

| 位置 | 方法 | 处理方式 |
|------|------|---------|
| `_doConnect()` | 健康检查响应 | 累计bodySize超过10MB时调用 `res.destroy()` 销毁连接并reject |
| `_generateViaApi()` | API生成响应 | 累计dataSize超过10MB时调用 `res.destroy()` 销毁连接并reject |
| `_doGetTaskStatus()` | 任务状态查询响应 | 累计dataSize超过10MB时调用 `res.destroy()` 销毁连接并reject |
| `_doCancelTask()` | 取消任务响应 | 累计dataSize超过10MB时调用 `res.destroy()` 销毁连接并resolve为失败 |

**超限处理策略**：

- 检测到响应超过 `MAX_RESPONSE_SIZE` 时，立即调用 `res.destroy()` 销毁底层连接，停止接收数据
- 写操作（connect/generate/getTaskStatus）返回reject并携带错误信息：`'Response too large (max 10485760 bytes)'`
- 取消操作（cancelTask）返回resolve `{ cancelled: false, error: 'Response too large' }`，避免因安全限制导致取消操作本身抛出异常

## 六、端到端示例

以下展示一个完整的媒体生成→会话备份→成果同步→密钥管理的工作流，体现适配器子系统组件间的协作关系：

```javascript
// ===== 阶段1：媒体生成 =====

// 1.1 创建Provider实例
const PresentationProvider = require('./media-provider/presentation-provider');
const presentationProvider = new PresentationProvider({
  apiEndpoint: 'https://presenton.example.com',
  apiKey: 'presenton-api-key',
});

// 1.2 创建路由器并注册Provider
const { MediaProviderRouter, ROUTING_STRATEGIES } = require('./media-provider/media-provider-router');
const router = new MediaProviderRouter({ strategy: ROUTING_STRATEGIES.SPEED_OPTIMAL });
router.registerProvider(presentationProvider);

// 1.3 连接并生成
await presentationProvider.connect();
const result = await router.route({
  prompt: '产品发布会演示文稿',
  mode: 'generate',
  options: { template: 'professional', maxSlides: 15 },
});

// 1.4 查看统计
console.log('路由统计:', router.getStats());
console.log('Provider统计:', presentationProvider.getStats());

// ===== 阶段2：会话备份 =====

const { CloudSessionBackup } = require('./cloud-session-backup');
const backup = new CloudSessionBackup({
  apiKey: 'sk-ant-xxx',
  agentId: 'agent-001',
  environmentId: 'env-prod',
});

await backup.initialize();

// 备份当前会话状态
await backup.backup('session-001', {
  task: '产品发布会PPT生成',
  result: result,
  progress: 100,
});

// 启动自动备份
backup.startAutoBackup('session-001', () => ({
  task: '产品发布会PPT生成',
  lastUpdate: Date.now(),
}));

// ===== 阶段3：成果同步 =====

const { CMAOutcomesBridge } = require('./cma-outcomes-bridge');
const bridge = new CMAOutcomesBridge({
  apiKey: 'sk-ant-xxx',
  syncIntervalMs: 30000,
});

await bridge.initialize();

// 推送本地成果
bridge.pushOutcome({
  id: 'outcome-ppt-001',
  sessionId: 'session-001',
  type: 'presentation-generation',
  quality: 0.95,
  metadata: { slides: 15, template: 'professional' },
});

// 启动自动同步
bridge.startAutoSync();

// ===== 阶段4：密钥管理 =====

const { VaultSecretProvider } = require('./vault-secret-provider');
const vault = new VaultSecretProvider({
  apiKey: 'sk-ant-xxx',
  vaultId: 'vault-001',
  cacheTtlMs: 60000,
});

await vault.connect();

// 存储API密钥
await vault.write({
  key: 'presenton-api-key',
  value: 'presenton-api-key',
  metadata: { service: 'presenton', env: 'production' },
});

// 读取密钥（带缓存）
const secretResult = await vault.recall('presenton-api-key');

// ===== 阶段5：远程任务执行 =====

const { CMASessionProxy } = require('./cma-session-proxy');
const proxy = new CMASessionProxy({
  apiKey: 'sk-ant-xxx',
  agentId: 'agent-001',
  environmentId: 'env-prod',
});

await proxy.initialize();

// 委托远程Agent执行任务
const remoteResult = await proxy.execute(
  '根据以下PPT内容生成配套的演讲稿',
  { model: 'claude-sonnet-4-6' }
);

// ===== 阶段6：优雅关闭 =====

backup.stopAutoBackup('session-001');
bridge.stopAutoSync();
router.shutdown();
```

## 七、最佳实践与注意事项

### 7.1 媒体提供商扩展

- **必须实现抽象方法**：继承MediaProviderBase时，`_doConnect()`、`_doGenerate()`、`_doGetTaskStatus()`、`_doCancelTask()`必须实现，否则调用时抛出错误
- **不要覆盖公共方法**：`connect()`、`generate()`等方法已包含重试/超时/并发控制逻辑，应覆盖`_do*`钩子方法
- **使用`_recordTask()`追踪任务**：在钩子方法中调用`_recordTask()`记录任务状态，确保统计信息准确
- **认证错误不重试**：MediaProviderBase的`_withRetry`遇到AUTH类型错误直接抛出，不会重试

### 7.2 路由策略选择

- **COST_OPTIMAL适合成本敏感场景**：选择列表最后一个Provider，通常是最便宜的
- **SPEED_OPTIMAL适合延迟敏感场景**：根据健康检查延迟选择最快的Provider
- **FAILFAST适合不可重试场景**：失败后直接抛出异常，不进行故障转移
- **ROUND_ROBIN适合负载均衡**：均匀分配请求到各Provider

### 7.3 CMA适配器使用

- **API Key是必须的**：CloudSessionBackup、CMAOutcomesBridge、CMASessionProxy在无API Key时自动进入离线模式，功能受限
- **自动备份/同步需手动启动**：`startAutoBackup()`和`startAutoSync()`不会自动调用，需在初始化后手动启动
- **MAX_BACKUP_SESSIONS=50**：自动备份会话数上限，超出后新会话无法启动自动备份
- **MAX_PENDING_OUTCOMES=1000**：待同步成果队列上限，超出后最旧的成果被丢弃

### 7.4 Vault密钥管理

- **优先使用缓存**：recall()优先从本地TTL缓存获取，减少网络请求
- **缓存TTL默认5分钟**：超过TTL的缓存条目自动失效，下次recall会重新从Vault获取
- **离线模式仅缓存**：无API Key时write()仅写入本地缓存，recall()仅能读取已缓存的数据
- **继承ProviderAdapterBase**：VaultSecretProvider继承思维子系统的ProviderAdapterBase，遵循recall/write标准接口

### 7.5 错误处理

- **错误分类是自动的**：MediaProviderBase根据错误码、HTTP状态码和错误消息自动分类错误类型
- **指数退避避免雪崩**：重试延迟按`retryDelayMs * 2^attempt`计算，不要在外部再添加固定间隔重试
- **并发控制是硬限制**：超过maxConcurrentTasks时generate()直接抛出异常，不会排队等待

### 7.6 网络安全

- **响应大小限制**：所有CMA适配器内置10MB响应大小限制，防止内存溢出
- **请求超时保护**：所有网络请求均有超时设置，超时后自动中断连接
- **settled标志防重复**：HTTP请求使用settled标志确保Promise只resolve/reject一次

### 7.7 优雅关闭

- **MediaProviderInterface使用withShutdown**：通过混入实现guardShutdown()和_onShutdown()
- **MediaProviderRouter使用独立shutdown()**：不使用withShutdown，手动管理关闭流程
- **CMA适配器使用_shutDown标志**：关闭后所有操作返回失败结果，不抛出异常
- **关闭时清理定时器**：CloudSessionBackup和CMAOutcomesBridge关闭时自动清理所有定时器
