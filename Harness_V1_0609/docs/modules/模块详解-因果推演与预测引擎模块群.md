## 1. 概述

因果推演与预测引擎是 Harness Engineering 框架的标志性创新模块群，将因果推理从"事后追溯"提升到"事前预测"的新高度。该模块群在因果子系统（CausalDataBus等基础组件）之上，构建了三层递进能力：

1. **前向因果推演层**（SimulationEngine）：从给定初始状态和动作列表，通过BFS分支构建和置信度衰减剪枝，推演出未来可能的因果链分支，支持反事实推理（"如果当时做了X会怎样？"）和因果链前向预测
2. **多世界线管理层**（WorldLineManager）：管理推演产生的多条世界线，支持分支创建、4种合并策略、概率连乘计算、步骤回滚和时间线报告生成
3. **蒙特卡洛预测层**（ScenarioPredictor）：定义预测场景，执行大规模蒙特卡洛模拟，输出概率分布、风险指标（VaR/ES/最大回撤）和敏感性分析

同时，因果记忆存储（CausalMemoryStore）和因果向量索引（CausalVectorIndex）为推演提供历史因果模式检索能力，因果缓冲管理器（CausalBufferManager）提供因果感知的上下文压缩策略，因果配置验证器（ConfigCausalValidator）和因果一致性检查器（CausalConsistencyChecker）确保系统配置与运行时状态的一致性。

### 核心价值

| 能力维度 | 传统方法 | 因果推演与预测引擎 |
|---------|---------|------------------|
| 决策支持 | 基于经验判断 | 基于因果链前向推演的量化分析 |
| 风险评估 | 单一场景分析 | 蒙特卡洛模拟 + VaR/ES风险指标 |
| 假设分析 | 无法系统化 | 反事实推理 + 多世界线对比 |
| 因果发现 | 事后归因 | 因果链追踪 + 冲突检测 + 一致性验证 |
| 上下文管理 | 均等压缩 | 因果注意力权重驱动的差异化压缩 |

**数据流说明**：

- SimulationEngine 通过 `attachCausalMemoryStore()` 和 `attachCausalDataBus()` 连接基础设施，`forwardPredict()` 从CausalMemoryStore检索历史因果模式

- ScenarioPredictor 独立运行蒙特卡洛模拟，其结果可被WorldLineManager引用
- CausalBufferManager 依赖CausalDataBus和SkillRouter计算注意力权重
- CausalConsistencyChecker 横向检查CausalDataBus、CausalMemoryStore、ConfigCausalValidator三者一致性

## 3. 各模块详解

### 3.1 SimulationEngine — 前向因果推演引擎

**源文件**：`src/runtime/causal/simulation-engine.js`

**概述**：SimulationEngine 是因果推演的核心引擎，从给定初始状态和动作列表推演未来因果链。支持三种推演模式：前向模拟（simulate）、反事实推理（counterfactual）和因果链前向预测（forwardPredict）。

**核心API**：

| 方法 | 说明 | 返回值 |
|------|------|--------|
| `simulate(initialState, actions, options)` | 执行前向模拟，BFS构建分支树 | `{simulationId, branches, summary}` |
| `counterfactual(actualState, actualAction, alternativeAction, depth)` | 反事实推理，对比实际与替代动作 | `{actualOutcome, counterfactualOutcome, divergence, insight}` |
| `forwardPredict(cause, depth)` | 从原因前向预测效果（异步） | `Promise<{predictions, consensusConfidence}>` |
| `getSimulation(simulationId)` | 获取指定模拟结果 | 模拟记录或null |
| `listSimulations(limit)` | 列出最近模拟结果 | 模拟记录数组 |
| `generateReport(simulationId)` | 生成Markdown格式模拟报告 | 报告字符串或null |
| `getStats()` | 获取引擎统计信息 | 统计对象 |
| `isHealthy()` | 健康检查 | boolean |
| `attachCausalMemoryStore(store)` | 挂载CausalMemoryStore | this（链式） |
| `attachCausalDataBus(bus)` | 挂载CausalDataBus | this（链式） |

**配置参数**：

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `maxDepth` | 5 | 最大推演深度 |
| `maxBranches` | 10 | 最大分支数（每层保留的高置信度分支） |
| `confidenceThreshold` | 0.3 | 置信度阈值，低于此值的分支被剪枝 |
| `timeHorizon` | 1000 | 时间视野（毫秒） |

**常量**：

| 常量 | 值 | 说明 |
|------|----|------|
| `DECAY_FACTOR` | 0.85 | 置信度随深度衰减因子 |
| `CONVERGENCE_THRESHOLD` | 0.05 | 分支收敛判定阈值 |
| `MAX_SIMULATIONS` | 100 | 最大存储模拟结果数 |
| `MAX_COUNTERFACTUALS` | 50 | 最大存储反事实推理数 |
| `MAX_FORWARD_PREDICTIONS` | 50 | 最大存储前向预测数 |
| `MAX_HEALTHY_TOTAL` | 50000 | 健康检查总操作数上限 |

**事件**：

| 事件名 | 触发时机 | 数据 |
|--------|---------|------|
| `simulation-started` | 模拟开始 | `{simulationId}` |
| `simulation-completed` | 模拟完成 | `{simulationId, branchCount, avgConfidence}` |
| `counterfactual-completed` | 反事实推理完成 | `{id, divergenceMagnitude}` |
| `forward-prediction-completed` | 前向预测完成 | `{id, predictionCount, consensusConfidence}` |
| `branch-diverged` | 分支分叉 | `{action, depth}` |
| `branches-converged` | 分支收敛 | `{branchCount, paths}` |

### 3.2 WorldLineManager — 多世界线管理器

**源文件**：`src/runtime/causal/world-line-manager.js`

**概述**：WorldLineManager 管理推演产生的多条世界线，支持创建、分支、合并、步骤推进、回滚和概率计算。每条世界线维护完整的步骤历史，形成可追溯的因果时间线。

**核心API**：

| 方法 | 说明 | 返回值 |
|------|------|--------|
| `createWorldLine(name, initialState, parentLineId)` | 创建世界线 | 世界线对象 |
| `getWorldLine(worldLineId)` | 获取世界线信息 | 世界线对象或null |
| `listWorldLines(status)` | 列出世界线（可按状态过滤） | 世界线数组 |
| `removeWorldLine(worldLineId)` | 删除世界线 | boolean |
| `branchFrom(worldLineId, branchName, divergencePoint)` | 从指定世界线创建分支 | 新世界线对象 |
| `mergeWorldLines(sourceId, targetId, strategy)` | 合并两条世界线 | 合并后状态 |
| `advanceStep(worldLineId, action, result)` | 推进一步 | 更新后状态 |
| `rollbackToStep(worldLineId, stepIndex)` | 回滚到指定步骤 | 回滚后状态或null |
| `getStateAtStep(worldLineId, stepIndex)` | 获取指定步骤状态快照 | 状态快照或null |
| `computeProbability(worldLineId)` | 计算概率（连乘） | `{probability, pathLength, confidenceInterval}` |
| `compareWorldLines(lineId1, lineId2)` | 比较两条世界线 | `{variableDifferences, probabilityRatio, divergenceStep}` |
| `getBranchTree(worldLineId)` | 获取分支树 | 树形结构 |
| `generateTimeline(worldLineId)` | 生成时间线报告 | Markdown字符串 |
| `getStats()` | 获取统计信息 | 统计对象 |
| `isHealthy()` | 健康检查 | boolean |

**配置参数**：

| 参数 | 值 | 说明 |
|------|----|------|
| `MAX_WORLD_LINES` | 500 | 最大世界线数量 |

**事件**：

| 事件名 | 触发时机 | 数据 |
|--------|---------|------|
| `world-line-created` | 世界线创建 | `{worldLineId, name, parentLineId, depth}` |
| `world-line-branch-created` | 分支创建 | `{sourceId, branchId, branchName, divergencePoint}` |
| `world-lines-merged` | 世界线合并 | `{sourceId, targetId, strategy, mergedKeys}` |
| `step-advanced` | 步骤推进 | `{worldLineId, step, actionName}` |
| `step-rolled-back` | 步骤回滚 | `{worldLineId, stepIndex}` |
| `world-line-removed` | 世界线删除 | `{worldLineId}` |

### 3.3 ScenarioPredictor — 场景预测器

**源文件**：`src/runtime/causal/scenario-predictor.js`

**概述**：ScenarioPredictor 定义预测场景并执行蒙特卡洛模拟，输出统计摘要、概率分布和风险指标。支持3种采样方法、场景对比和敏感性分析。

**核心API**：

| 方法 | 说明 | 返回值 |
|------|------|--------|
| `defineScenario(name, description, variables, constraints)` | 定义预测场景 | 场景对象 |
| `getScenario(scenarioId)` | 获取场景 | 场景对象或null |
| `listScenarios()` | 列出所有场景 | 场景数组 |
| `removeScenario(scenarioId)` | 删除场景 | boolean |
| `runMonteCarlo(scenarioId, options)` | 执行蒙特卡洛模拟 | `{runId, scenarioId, iterations, results, riskMetrics, completedAt}` |
| `getMonteCarloResult(runId)` | 获取模拟结果 | 结果对象或null |
| `listMonteCarloResults(scenarioId, limit)` | 列出场景的模拟结果 | 结果数组 |
| `compareScenarios(scenarioId1, scenarioId2, metric)` | 对比两个场景 | 对比结果 |
| `sensitivityAnalysis(scenarioId, targetVariable)` | 敏感性分析 | `{variable, sensitivities}` |
| `generatePredictionReport(scenarioId, runId)` | 生成预测报告 | Markdown字符串 |
| `getStats()` | 获取统计信息 | 统计对象 |
| `isHealthy()` | 健康检查 | boolean |

**配置参数**：

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `iterations` | 1000 | 蒙特卡洛迭代次数 |
| `timeSteps` | 10 | 时间步数 |
| `confidenceLevel` | 0.95 | 置信水平 |
| `samplingMethod` | `'random'` | 采样方法 |

**常量**：

| 常量 | 值 | 说明 |
|------|----|------|
| `MAX_MC_RESULTS` | 200 | 最大存储模拟结果数 |
| `MAX_SCENARIOS` | 5000 | 最大场景数 |
| `DISTRIBUTION_BINS` | 20 | 概率分布直方图分箱数 |

**事件**：

| 事件名 | 触发时机 | 数据 |
|--------|---------|------|
| `scenario-defined` | 场景定义 | `{scenarioId, name}` |
| `monte-carlo-started` | 模拟开始 | `{scenarioId, iterations, samplingMethod}` |
| `monte-carlo-completed` | 模拟完成 | `{runId, scenarioId, iterations, validCount}` |
| `scenarios-compared` | 场景对比 | `{scenarioId1, scenarioId2, metric, winner}` |
| `sensitivity-analysis-completed` | 敏感性分析完成 | `{scenarioId, targetVariable, variableCount}` |

### 3.4 CausalBufferManager — 因果缓冲管理器

**源文件**：`src/runtime/causal/causal-buffer-manager.js`

**概述**：CausalBufferManager 基于因果链和注意力衰减计算上下文压缩策略。通过CausalDataBus获取技能间因果依赖，结合SkillRouter的技能元数据，为每个技能计算注意力权重并决定压缩策略（full/summary/discard）。同时提供写入缓冲、刷盘策略和溢出处理。

**核心API**：

| 方法 | 说明 | 返回值 |
|------|------|--------|
| `attachCausalDataBus(causalDataBus)` | 附加CausalDataBus | this |
| `attachSkillRouter(skillRouter)` | 附加SkillRouter | this |
| `attachStorage(storage)` | 附加持久化存储 | this |
| `write(entry)` | 写入缓冲区 | boolean |
| `computeAttentionWeights(currentSkillId)` | 计算注意力权重映射 | `Map<string, number>` |
| `getCompressionStrategy(skillId, currentSkillId)` | 获取压缩策略 | `'full'/'summary'/'discard'` |
| `invalidateAttentionCache()` | 使注意力缓存失效 | void |
| `getBufferStats()` | 获取缓冲统计 | 统计对象 |

**配置参数**：

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `attentionDecay` | 0.7 | 注意力衰减系数（0-1） |
| `maxCausalDistance` | 5 | 最大因果距离（1-10） |
| `maxBufferSize` | 1000 | 缓冲区最大条目数 |

**压缩策略映射规则**：

| 注意力权重 | 压缩策略 | 说明 |
|-----------|---------|------|
| ≥ 0.7 | `full` | 保留完整上下文 |
| ≥ 0.3 | `summary` | 压缩为摘要 |
| < 0.3 | `discard` | 丢弃 |

**事件**：

| 事件名 | 触发时机 |
|--------|---------|
| `flush-failed` | 连续5次刷盘失败后 |
| `flush-partial-failure` | 部分条目刷盘失败 |
| `flush-error` | 刷盘异常 |

### 3.6 CausalConsistencyChecker — 因果一致性检查器

**源文件**：`src/runtime/causal/causal-consistency-checker.js`

**概述**：CausalConsistencyChecker 执行双层一致性检查：运行时接口与静态配置的一致性（checkRuntimeVsStatic），以及内存存储与运行时因果链的一致性（checkMemoryVsRuntime）。

**核心API**：

| 方法 | 说明 | 返回值 |
|------|------|--------|
| `attachCausalDataBus(bus)` | 附加CausalDataBus | void |
| `attachCausalMemoryStore(store)` | 附加CausalMemoryStore | void |
| `attachConfigCausalValidator(validator)` | 附加ConfigCausalValidator | void |
| `checkRuntimeVsStatic()` | 运行时vs静态一致性检查 | `{consistent, issues}` |
| `checkMemoryVsRuntime()` | 内存vs运行时一致性检查（异步） | `Promise<{consistent, issues}>` |
| `checkFullConsistency()` | 完整一致性检查（异步） | `Promise<{consistent, totalIssues, highIssues, mediumIssues, lowIssues, issues}>` |

**问题严重度分级**：

| 严重度 | 说明 | 示例 |
|--------|------|------|
| `high` | 高严重度 | — |
| `medium` | 中严重度 | 有静态依赖但无运行时接口 |
| `low` | 低严重度 | 内存条目置信度低于0.3 |

**事件**：

| 事件名 | 触发时机 |
|--------|---------|
| `attach-error` | 附加组件失败 |
| `runtime-vs-static-checked` | 运行时-静态检查完成 |
| `memory-vs-runtime-checked` | 内存-运行时检查完成 |
| `full-consistency-checked` | 完整一致性检查完成 |

## 4. SimulationEngine详解

### 4.1 BFS分支构建算法

SimulationEngine 的核心算法是广度优先搜索（BFS）分支构建。算法流程如下：

```
输入：初始状态 variables、约束 constraints、动作列表 actions、选项 opts
输出：分支列表 branches

1. 初始化 current = [{path:[], state:variables, probProduct:1.0, confidence:1.0}]
2. 对于每一层深度 d = 0 到 maxDepth-1:
   a. 初始化 next = []
   b. 对于 current 中每个分支 branch:
      - 尝试对每个 action 展开:
        i.   检查前置条件 _checkPreconditions(branch.state, action.preconditions)
        ii.  应用动作效果 _applyAction(branch.state, action) → newState
        iii. 计算路径概率 newProb = branch.probProduct × action.probability
        iv.  计算置信度 confidence = baseConfidence × DECAY_FACTOR^depth
        v.   若 confidence < confidenceThreshold，剪枝（跳过）
        vi.  否则加入 next，触发 branch-diverged 事件
      - 若无任何action可展开，将branch加入completed
   c. 若 next 为空，跳出循环
   d. 按 confidence 降序排序 next
   e. 保留 top maxBranches 个分支 → current
3. 合并 completed + current → allBranches
4. 为每个分支创建世界线 _makeWorldLine()
5. 检测收敛 _detectConvergence()，触发 branches-converged 事件
6. 返回 branches + summary
```

**关键设计决策**：

- **逐层剪枝**：每层只保留置信度最高的maxBranches个分支，避免组合爆炸
- **置信度衰减**：`confidence = baseConfidence × 0.85^depth`，越深的推演置信度越低
- **前置条件检查**：支持数值阈值（`{key: minValue}`）和范围约束（`{key: {min, max, exists}}`）
- **动作效果运算符**：支持`+`（加）、`-`（减）、`*`（乘）、`=`/`set`（赋值）四种运算

### 4.2 置信度衰减剪枝

置信度衰减是控制推演复杂度的核心机制。公式为：

```
pathConfidence = baseProbability × DECAY_FACTOR^pathLength
```

其中：
- `baseProbability` = 路径上所有动作概率的连乘
- `DECAY_FACTOR` = 0.85（经验值）
- `pathLength` = 动作路径长度

当 `pathConfidence < confidenceThreshold`（默认0.3）时，该分支被剪枝。这意味着：
- 深度为5时，置信度衰减为 `0.85^5 ≈ 0.44`，仍可能保留
- 深度为10时，置信度衰减为 `0.85^10 ≈ 0.20`，必然被剪枝
- 低概率动作（如probability=0.3）在深度2时即被剪枝：`0.3 × 0.85^2 ≈ 0.22 < 0.3`

### 4.3 反事实推理算法

反事实推理（Counterfactual Reasoning）回答"如果当时做了X会怎样"的问题：

```
输入：实际状态 actualState、实际动作 actualAction、替代动作 alternativeAction、推演深度 depth
输出：实际结果、反事实结果、分歧度、洞察

1. 对 actualAction 执行单步模拟 → actualOutcome
2. 对 alternativeAction 执行单步模拟 → counterfactualOutcome
3. 计算分歧度 _computeDivergence():
   - 遍历所有状态变量，计算 |actual - counterfactual|
   - 总分歧度 magnitude = Σ|diff|
   - 最大分歧点 point = argmax|diff|
4. 生成洞察 _generateInsight():
   - 若 magnitude=0："No divergence: X produces the same outcome as Y"
   - 否则："If X had been chosen instead of Y, var would be cf_value instead of actual_value (difference: diff)"
```

### 4.4 因果链前向预测

`forwardPredict()` 从CausalMemoryStore检索历史因果模式，递归推演未来效果：

```
输入：原因描述 cause、推演深度 depth
输出：预测列表 predictions、共识置信度 consensusConfidence

1. 从CausalMemoryStore搜索相似因果模式（limit=5）
2. 对每个匹配模式:
   - 计算置信度 = pattern.confidence × pattern.similarity × DECAY_FACTOR^pathLength
   - 若置信度 ≥ 阈值，加入结果
   - 递归以 pattern.effect 为新的 cause 继续推演
3. 按置信度降序排序，取Top 10
4. 共识置信度 = Top 10 平均置信度
```

**防环机制**：使用 `visited` Set 避免对同一描述重复推演。

## 5. WorldLineManager详解

### 5.1 四种分支合并策略

WorldLineManager 支持4种合并策略，通过 `MERGE_STRATEGIES` 常量导出：

| 策略 | 常量 | 算法 | 适用场景 |
|------|------|------|---------|
| **并集** | `UNION` | 合并所有键，数组类型concat | 需要保留所有信息 |
| **交集** | `INTERSECTION` | 只保留两条世界线共有的键 | 只关注共识部分 |
| **加权平均** | `WEIGHTED_AVERAGE` | 数值型键取平均值，非数值取target | 需要平滑合并 |
| **最新胜** | `LATEST_WINS` | target覆盖source（默认策略） | 时间优先级明确 |

合并算法实现（`_mergeStates`）：

```javascript
// UNION: 合并所有键，数组concat
merged = {...sourceState, ...targetState};
for (key in sourceState) {
  if (isArray(source[key]) && isArray(target[key])) {
    merged[key] = source[key].concat(target[key]);
  }
}

// INTERSECTION: 只保留共有键
for (key in sourceState) {
  if (targetState[key] !== undefined) merged[key] = targetState[key];
}

// WEIGHTED_AVERAGE: 数值取平均
for (key in allKeys) {
  if (isNumber(source[key]) && isNumber(target[key])) {
    merged[key] = (source[key] + target[key]) / 2;
  }
}

// LATEST_WINS: target覆盖source
merged = {...sourceState, ...targetState};
```

合并后源世界线状态变为 `'merged'`，目标世界线接收合并结果。

### 5.2 概率连乘计算

`computeProbability()` 计算世界线到达当前状态的路径概率：

```
probability = Π(step.probability)  // 对所有步骤概率连乘
```

置信区间使用正态近似：

```
margin = 1.96 × √(probability × (1 - probability) / pathLength)
confidenceInterval = [max(0, probability - margin), min(1, probability + margin)]
```

其中 `1.96` 对应95%置信水平的Z值。

### 5.3 世界线分支与回滚

**分支创建**（`branchFrom`）：
1. 从源世界线的当前状态复制为新世界线的初始状态
2. 可指定分歧点（divergencePoint），从源世界线的历史步骤恢复状态
3. 新世界线的 depth = source.depth + 1
4. 触发 `world-line-branch-created` 事件

**步骤回滚**（`rollbackToStep`）：
1. 截断步骤数组：`steps = steps.slice(0, stepIndex + 1)`
2. 恢复状态为目标步骤的 `stateAfter`
3. 触发 `step-rolled-back` 事件

**世界线比较**（`compareWorldLines`）：
- 变量差异：遍历所有键，计算delta
- 概率比：`probabilityRatio = prob2 / prob1`
- 分歧步骤：从步骤0开始，找到第一个action.name或action.effects不同的步骤

## 6. ScenarioPredictor详解

### 6.1 蒙特卡洛模拟流程

```
输入：场景ID scenarioId、选项 options
输出：模拟结果 mcResult

1. 从场景定义获取变量和约束
2. 生成样本 _generateSamples(variables, iterations, samplingMethod)
3. 对每个样本:
   a. 模拟轨迹 _simulateTrajectory(sample, variables, timeSteps)
      - 每个时间步：next[var] = current[var] × (1 + drift) + perturbation × 0.1
      - 限制在变量范围内
   b. 检查约束 _checkConstraints(trajectory, constraints)
      - hard约束违反 → 丢弃轨迹
      - soft约束违反 → 惩罚（最终状态 × (1 - softPenalty × 0.1)）
4. 收集有效轨迹的最终状态
5. 计算统计量 _computeStatistics()
   - 均值、中位数、标准差
   - 百分位：P5, P25, P50, P75, P95
   - 置信区间
   - 概率分布直方图（20个分箱）
6. 计算风险指标 _computeRiskMetrics()
7. 存储结果，触发事件
```

### 6.2 三种采样方法

| 方法 | 算法 | 特点 |
|------|------|------|
| **random** | 每个变量独立随机采样 | 最简单，收敛最慢 |
| **latin-hypercube** | 拉丁超立方采样 | 分层采样，覆盖更均匀 |
| **sobol** | 准随机Sobol序列（近似） | 低差异序列，收敛最快 |

**拉丁超立方采样**（latin-hypercube）：
```
bins = ceil(sqrt(iterations))
for i = 0 to iterations-1:
  binIndex = i % bins
  binWidth = (range[1] - range[0]) / bins
  sample[var] = range[0] + binIndex × binWidth + random() × binWidth
```

**Sobol序列**（近似实现）：
```
for i = 0 to iterations-1:
  t = (i + 0.5) / iterations
  for j = 0 to variables.length-1:
    offset = (t × (j+1) × 0.618033988749895) % 1  // 黄金比例
    sample[var] = range[0] + offset × (range[1] - range[0])
```

**变量分布类型**：

| 分布 | 采样方法 |
|------|---------|
| `uniform` | `min + random() × (max - min)` |
| `normal` | Box-Muller变换：`mean + z × stdDev`，其中 `z = √(-2ln(u1)) × cos(2πu2)` |
| `empirical` | 同uniform（待扩展） |

### 6.3 风险指标

| 指标 | 英文 | 计算方法 |
|------|------|---------|
| **VaR 95%** | Value at Risk | `mean - sortedValues[floor(n×0.05)]` |
| **VaR 99%** | Value at Risk | `mean - sortedValues[floor(n×0.01)]` |
| **ES** | Expected Shortfall | 底部5%损失的平均值 |
| **最大回撤** | Maximum Drawdown | `max((peak - valley) / |peak|)` 遍历排序序列 |

**VaR（风险价值）**：在给定置信水平下，投资组合可能遭受的最大损失。VaR 95%表示有95%的概率损失不会超过此值。

**ES（期望损失/条件VaR）**：超过VaR阈值时的平均损失，比VaR更好地捕捉尾部风险。

**最大回撤**：从峰值到谷值的最大跌幅，衡量最坏情况下的损失幅度。

### 6.4 场景对比与敏感性分析

**场景对比**（`compareScenarios`）：
- 支持4种对比指标：`mean`、`median`、`risk`（VaR95）、`distribution`
- 计算绝对差异 `delta` 和相对差异 `relativeDelta`
- 自动判定胜者（risk指标越小越好，其他越大越好）
- 对比置信度基于差异幅度计算

**敏感性分析**（`sensitivityAnalysis`）：
- 对每个输入变量计算与目标变量的相关系数
- 输出贡献度（`contribution = correlation²`），归一化后总和为1
- 按贡献度排序，识别关键驱动因素

```javascript
const cfResult = engine.counterfactual(
  { variables: { revenue: 100, cost: 80 } },
  { name: 'maintain', effects: { revenue: { operator: '+', value: 5 } }, probability: 0.9 },
  { name: 'expand', effects: { revenue: { operator: '+', value: 20 }, cost: { operator: '+', value: 15 } }, probability: 0.6 },
  3
);
// cfResult.insight: "If expand had been chosen instead of maintain, revenue would be 120 instead of 105 (difference: 15)"
```

```javascript
const checker = new CausalConsistencyChecker({
```

### 7.3 容错与自愈

| 故障场景 | 处理策略 |
|---------|---------|
| SimulationEngine操作总数超限 | `isHealthy()` 返回false，拒绝新操作 |
| WorldLineManager世界线数超限 | 抛出 `DeepeningError('CAPACITY_EXCEEDED')` |
| ScenarioPredictor场景数超限 | 抛出 Error |
| CausalBufferManager连续刷盘失败 | 5次失败后熔断，触发 `flush-failed` 事件 |
| CausalMemoryStore TTL过期 | 置信度降级为50%，标记 `_degraded` |
| CausalVectorIndex embed失败 | 降级到词哈希向量生成 |
| CausalConsistencyChecker组件缺失 | 返回 `{consistent: true, reason: 'missing_components'}` |
| ConfigCausalValidator配置缺失 | 返回空依赖图，errors包含 `config_missing` |

所有模块均通过 `withShutdown` 混入支持优雅关闭，`_onShutdown()` 清理所有内部状态。

## 补充摘要：因果推演与因果子系统的集成架构

因果推演与预测引擎模块群（Causal Prediction Engine Group）是因果子系统（Causal Subsystem）的上层推理层。因果子系统提供 CausalDataBus（因果数据总线）、因果记忆存储（CausalMemoryStore）和因果向量索引（CausalVectorIndex）等基础组件，负责因果事件的发布、存储和检索。因果推演引擎在此基础上构建三层递进能力：SimulationEngine 的前向因果推演依赖 CausalMemoryStore 检索历史因果模式作为推演种子；WorldLineManager 管理推演产生的时间线分支，可被 CausalConsistencyChecker 验证一致性；ScenarioPredictor 的蒙特卡洛模拟输出风险指标（VaR/ES），为高层次决策提供量化依据。

该模块群与深化推理子系统（Deepening Subsystem）之间存在"预测—验证"协作关系：深化推理的 AdaptiveDepthController 可依据 ScenarioPredictor 的风险等级调整推理深度，ConvergenceDetector 的收敛结果可反馈至 WorldLineManager 用于分支合并决策。同时，ConfigCausalValidator 和 CausalConsistencyChecker 为整个因果链路提供配置验证和运行时一致性保障，确保自上而下的因果推演数据完整可靠。

核心源文件位于 `src/runtime/causal/` 目录下，包括 simulation-engine.js、world-line-manager.js、scenario-predictor.js、causal-buffer-manager.js、causal-config-validator.js、causal-consistency-checker.js、causal-memory-store.js 和 causal-vector-index.js 八个核心模块。
