# 模块详解-会话子系统

> 版本：2.73.4 | 文件：src/runtime/session/

---

## 子系统概述

会话子系统（Session Subsystem）负责管理Harness框架中会话的全生命周期，包括会话创建、阶段转换、Token预算管控、检查点创建与恢复、会话持久化与恢复。该子系统包含2个核心模块，协同完成从会话初始化到优雅关机的完整会话生命周期管理。

会话子系统是Harness多Agent架构的基础运行时组件，支撑了"流程管控"和"容错自愈"原则下的会话状态追踪与恢复能力。它将六阶段执行流程的状态变迁从无状态操作转化为有状态追踪，通过防抖持久化和检查点机制确保进程崩溃后可恢复，通过Token预算管控实现成本控制，通过因果WAL协调实现检查点回滚时的一致性保障。

## 模块清单

| 模块 | 源文件 | 说明 |
|------|--------|------|
| SessionManager | session-manager.js | 会话状态管理器，跟踪阶段、Skill、Token用量，防抖持久化，TTL过期清理 |
| CheckpointManager | checkpoint-manager.js | 检查点管理器，创建/恢复/删除检查点，因果WAL回滚协调 |

**关键依赖关系**：
- **SessionManager** 是会话子系统的核心入口，管理所有活跃会话的状态和生命周期
- **CheckpointManager** 依赖SessionManager的会话数据创建检查点，提供恢复能力
- SessionManager 可选注入 **PhaseContextInjector**（阶段转换时自动注入上下文）和 **CausalDataBus**（Skill完成时发布因果输出事件）
- CheckpointManager 可选注入 **CausalDataBus**（恢复时协调WAL回滚）
- 两者均通过 **withShutdown** 混入实现优雅关机，确保进程退出前数据完整持久化

## SessionManager — 会话状态管理器

### 核心职责

SessionManager是会话子系统的核心组件，负责：
- 会话的创建、查询和容量管理（最大100个活跃会话）
- 六阶段流程的阶段转换验证与推进
- 已完成Skill的记录与裁剪
- Token使用量追踪与预算预警（80%/95%/100%三级阈值）
- 深化推理状态追踪（迭代计数、质量分数、收敛历史）
- 熵状态追踪（先验丰富度、收敛轮次）
- Agent操作历史记录
- 防抖持久化到.harness/sessions/目录
- 会话TTL过期自动清理（默认24小时）
- 配置文件热重载（fs.watch + 指数退避重试）
- 优雅关机与信号处理（SIGINT/SIGTERM）

### 会话数据结构

```javascript
{
  id: string,
  currentPhase: string,
  completedSkills: string[],
  tokensUsed: number,
  status: 'active' | 'completed' | 'expired',
  createdAt: string,
  lastActivityAt: string,
  agentHistory: AgentAction[],
  deepeningState: {
    totalIterations: number,
    totalDeepeningExecutions: number,
    bestQualityScore: number,
    convergenceHistory: Array<{ qualityScore: number, timestamp: string }>,
    agentAffinities: Object,
  },
  entropyState: {
    currentLevel: string,
    firstMessageRichness: { score, level, signals } | null,
    convergenceTurns: number,
  },
}
```

### 阶段转换规则

SessionManager使用`PHASE_TRANSITIONS_SET`定义合法的阶段转换：

```
requirement-exploration → requirement-analysis
requirement-analysis → architecture-design
architecture-design → module-development
module-development → integration-testing
integration-testing → deployment
```

非法转换将抛出`SessionError('INVALID_PHASE_TRANSITION')`。相同阶段转换（from === to）为空操作，直接返回当前会话。

### Token预算管控

三级预警机制：

| 阈值 | 常量 | 值 | 触发行为 |
|------|------|-----|---------|
| 80%预警 | `TOKEN_BUDGET_WARNING_RATIO` | 0.8 | 发出`budget-warning`事件 |
| 95%危险 | `TOKEN_BUDGET_DANGER_RATIO` | 0.95 | 发出`budget-warning`事件 |
| 100%耗尽 | — | 1.0 | 发出`budget-warning`事件，`exhausted: true` |

预算来源：`.harness/config.json`中的`token_budget`字段，默认为`DEFAULT_TOKEN_BUDGET`。

### 防抖持久化机制

SessionManager使用`KeyedDebouncer`实现防抖持久化：

- 默认防抖间隔为`DEFAULT_DEBOUNCE_MS`
- 每个会话独立防抖（按sessionId为键）
- `immediate=true`时跳过防抖立即写入（用于create、advancePhase、completeSkill等关键操作）
- 仅当内存中的session对象仍为当前对象时才写入磁盘（防止旧数据覆盖新数据）
- 持久化时移除`_arContext`内部字段
- 使用`writeAtomic`原子写入，防止部分写入导致数据损坏

### TTL过期清理

- 默认TTL为24小时（`MS_PER_DAY`）
- 清理间隔为5分钟（`TTL_CLEANUP_INTERVAL_MS`）
- 定时器调用`unref()`避免阻止进程退出
- 过期会话从内存删除，异步删除磁盘文件
- 无效时间戳的会话直接清除

### 配置热重载

SessionManager通过`fs.watch`监控`.harness/config.json`的变更：

- 变更事件经500ms防抖后重载配置
- 重载时验证`token_budget`为非负有限数
- 阶段预算分配变更时发出`budget-config-changed`事件
- Watcher错误时指数退避重试（基础5秒，最大120秒，最多10次）

### 容量管理

| 参数 | 值 | 说明 |
|------|-----|------|
| `MAX_SESSIONS` | 100 | 最大活跃会话数 |
| `MAX_COMPLETED_SKILLS` | 500 | 已完成Skill列表上限 |
| `COMPLETED_SKILLS_TRIM_TO` | 400 | 裁剪后保留数量 |
| Agent操作历史上限 | 500条 | 超出裁剪至400条 |
| 收敛历史上限 | 200条 | 超出裁剪至150条 |

### 核心API

| 方法 | 返回值 | 说明 |
|------|--------|------|
| `create(sessionId, options?)` | `Session` | 创建新会话，sessionId需匹配`[a-zA-Z0-9_-]`且最长64字符 |
| `get(sessionId)` | `Session \| null` | 获取会话快照（深拷贝），不存在返回null |
| `advancePhase(sessionId, newPhase)` | `Session` | 推进到新阶段，验证转换合法性 |
| `completeSkill(sessionId, skillId)` | `Session` | 记录已完成Skill，发布因果输出事件 |
| `addTokenUsage(sessionId, tokens)` | `void` | 增加Token使用量，触发预算检查 |
| `checkBudget(sessionId)` | `BudgetStatus` | 检查预算使用情况，返回预警状态和使用比例 |
| `recordAgentAction(sessionId, agentId, action)` | `void` | 记录Agent操作到会话历史 |
| `updateEntropyState(sessionId, priorRichness)` | `void` | 更新会话熵状态，记录先验丰富度信息 |
| `recordDeepeningIteration(sessionId, data?)` | `Session \| null` | 记录深化推理迭代信息，更新质量分数和收敛历史 |
| `recordDeepeningConvergence(sessionId, data?)` | `void` | 记录深化推理收敛事件 |
| `getDeepeningState(sessionId)` | `Object \| null` | 获取深化推理状态快照 |
| `getStats()` | `Object` | 获取统计信息（活跃会话数、总Token用量、阶段分布） |
| `getPreviousSessionContext()` | `Promise<Object \| null>` | 获取最近会话的上下文摘要，用于会话恢复 |
| `attachPhaseContextInjector(injector)` | `this` | 挂载阶段上下文注入器（需实现injectForPhase方法） |
| `attachCausalDataBus(causalDataBus)` | `this` | 挂载因果数据总线（需实现publishOutput方法） |
| `flush()` | `void` | 强制刷新所有待写入会话到磁盘 |
| `registerShutdownHooks()` | `this` | 注册SIGINT/SIGTERM信号处理器 |

| `session-created` | 会话创建 | `{ sessionId, session }` |
| `phase-change` | 阶段转换 | `{ sessionId, from, to }` |

## CheckpointManager — 检查点管理器

### 核心职责

CheckpointManager负责会话检查点的创建、恢复和管理，提供：
- 检查点的同步和异步创建（保存会话状态快照）
- 检查点恢复（返回可恢复的状态快照）
- 因果WAL回滚协调（恢复时同步回滚因果数据总线）
- 单调时间戳强制递增（防止时间戳冲突）
- 容量管理（最大50个检查点，FIFO淘汰）
- 持久化到.harness/checkpoints/目录
- 优雅关机（同步/异步两种模式）

### 检查点数据结构

```javascript
{
  id: string,
  sessionId: string,
  phase: string,
  completedSkills: string[],
  tokensUsed: number,
  agentHistory: Array,
  causalWalSequence: number,
  metadata: Object,
  createdAt: string,
}
```

### 单调时间戳机制

CheckpointManager在创建检查点时强制时间戳递增：

```
当前时间戳 ≤ _lastTimestamp → _lastTimestamp + 1
当前时间戳 > _lastTimestamp → 使用当前时间戳
```

这确保了即使在同一毫秒内创建多个检查点，每个检查点的时间戳也是唯一的，用于排序和版本追踪。

### 因果WAL回滚协调

`restoreWithCausalRollback(checkpointId, causalDataBus)`方法在恢复检查点时协调因果数据总线的WAL回滚：

1. 调用`restore(checkpointId)`获取恢复的状态快照
2. 若提供了`causalDataBus`且检查点记录了`causalWalSequence > 0`
3. 调用`causalDataBus.rollbackToSequence(causalWalSequence)`执行WAL回滚
4. 将回滚结果附加到恢复快照的`causalRollback`字段

这确保了检查点恢复时，因果数据总线的状态与会话状态保持一致，避免因果不一致问题。

### 容量管理

| 参数 | 值 | 说明 |
|------|-----|------|
| `MAX_CHECKPOINTS` | 50 | 最大检查点数量 |
| 淘汰策略 | FIFO | 超出容量时删除最早创建的检查点 |

### 核心API

| 方法 | 返回值 | 说明 |
|------|--------|------|
| `create(sessionId, data)` | `Object \| null` | 同步创建检查点，sessionId需匹配`[a-zA-Z0-9_-]`且不超过128字符 |
| `createAsync(sessionId, data)` | `Promise<Object \| null>` | 异步创建检查点 |
| `get(checkpointId)` | `Object \| null` | 获取检查点快照（深拷贝），不存在返回null |
| `list(sessionId?)` | `Object[]` | 列出检查点，可按sessionId过滤，按创建时间降序排列 |
| `restore(checkpointId)` | `Object \| null` | 从检查点恢复会话状态，返回可恢复的状态快照 |
| `restoreWithCausalRollback(checkpointId, causalDataBus?)` | `Object \| null` | 恢复检查点并协调因果WAL回滚 |
| `remove(checkpointId)` | `boolean` | 删除指定检查点，返回是否成功 |
| `getLatest(sessionId?)` | `Object \| null` | 获取指定会话的最新检查点 |

### 事件

CheckpointManager继承EventEmitter，当前未定义自定义事件。所有操作通过返回值传递结果。

### 配置项

CheckpointManager无外部配置文件，所有参数通过常量定义：

| 常量 | 值 | 说明 |
|------|-----|------|
| `MAX_CHECKPOINTS` | 50 | 最大检查点数量 |
| `SAFE_ID_RE` | `/^[a-zA-Z0-9_-]+$/` | 合法ID正则 |

## 模块间协作流程

### 会话创建与初始化流程

```
1. SessionManager.create(sessionId, options)
   ├── 验证sessionId格式（SESSION_ID_PATTERN）
   ├── 检查会话是否已存在
   ├── 检查容量 → 超出时淘汰最旧会话（_evictOldest）
   ├── 创建Session对象（初始阶段=PHASES[0]）
   ├── 立即持久化到磁盘（immediate=true）
   └── 发出session-created事件
```

### 阶段转换流程

```
1. SessionManager.advancePhase(sessionId, newPhase)
   ├── 验证会话存在
   ├── 验证阶段转换合法性（PHASE_TRANSITIONS_SET）
   ├── 更新currentPhase和lastActivityAt
   ├── 立即持久化（immediate=true）
   ├── 发出phase-change事件
   ├── 注入自回归上下文（AR.inject）
   └── 调用PhaseContextInjector.injectForPhase（如已挂载）
```

### Skill完成流程

```
1. SessionManager.completeSkill(sessionId, skillId)
   ├── 验证skillId为非空字符串
   ├── 验证会话存在
   ├── 添加到completedSkills（去重+裁剪）
   ├── 立即持久化（immediate=true）
   ├── 发出skill-complete事件
   ├── 注入自回归上下文（AR.inject，source=SKILL_COMPLETE）
   └── 发布因果输出事件（CausalDataBus.publishOutput，如已挂载）
```

### 检查点创建与恢复流程

```
1. CheckpointManager.create(sessionId, data)
   ├── 验证sessionId格式和长度
   ├── 生成检查点ID（cp-前缀）
   ├── 强制时间戳递增
   ├── 构建检查点对象
   ├── 存入内存Map → 超出容量时淘汰最旧
   └── 异步持久化到磁盘

2. CheckpointManager.restoreWithCausalRollback(checkpointId, causalDataBus)
   ├── 调用restore()获取状态快照
   ├── 检查causalWalSequence > 0
   ├── 调用causalDataBus.rollbackToSequence()协调WAL回滚
   └── 返回恢复快照（含causalRollback字段）
```

### 优雅关机流程

```
1. SessionManager._onShutdown()
   ├── flush() — 刷新所有待写入会话
   ├── 销毁防抖器
   ├── 清除TTL清理定时器
   ├── 关闭配置文件Watcher
   ├── 清除所有防抖定时器
   ├── 释放外部引用（CausalDataBus、PhaseContextInjector）
   ├── 清理会话内部_arContext
   └── 移除信号处理器

2. CheckpointManager._onShutdown()
   ├── 同步持久化所有检查点
   ├── 清空内存Map
   └── 移除所有事件监听器
```

## 与其他子系统的交互

### 与因果子系统（Causal Subsystem）的交互

- **SessionManager** 通过 `attachCausalDataBus()` 挂载 `CausalDataBus`，在Skill完成时调用 `publishOutput()` 发布因果输出事件
- **CheckpointManager** 通过 `restoreWithCausalRollback()` 在恢复检查点时协调 `CausalDataBus` 的WAL回滚，调用 `rollbackToSequence()` 确保因果一致性

### 与上下文子系统（Context Subsystem）的交互

- **SessionManager** 通过 `attachPhaseContextInjector()` 挂载 `PhaseContextInjector`，在阶段转换时调用 `injectForPhase()` 自动注入与当前阶段相关的上下文信息
- **SessionManager** 在阶段转换和Skill完成时通过 `AutoregressiveContextSchema.inject()` 注入自回归上下文，记录前驱结果和迭代信息

### 与工作流子系统（Workflow Subsystem）的交互

- **PhaseOrchestrator** 调用 `SessionManager.advancePhase()` 推进阶段转换
- **CommandRouter** 通过 `SessionManager` 获取当前会话状态以路由斜杠命令
- **GoalExecutor** 通过 `SessionManager.completeSkill()` 记录Skill完成，通过 `SessionManager.addTokenUsage()` 记录Token消耗

### 与深化推理子系统（Deepening Subsystem）的交互

- **DeepeningOrchestrator** 调用 `SessionManager.recordDeepeningIteration()` 记录每次深化迭代的质量分数
- **DeepeningOrchestrator** 调用 `SessionManager.recordDeepeningConvergence()` 记录收敛事件
- **ConvergenceDetector** 通过 `SessionManager.getDeepeningState()` 获取历史收敛信息辅助判定

### 与思维子系统（Thought Subsystem）的交互

- **MemoryPrefetcher** 监听 `SessionManager` 的 `phase-change` 事件，在阶段变更时预取相关记忆
- **DreamEngine** 通过 `SessionManager.getPreviousSessionContext()` 获取最近会话上下文用于经验提炼

### 与模型子系统（Model Subsystem）的交互

- **TokenManager** 通过 `SessionManager.addTokenUsage()` 和 `SessionManager.checkBudget()` 实现Token使用量追踪和预算管控
- **ModelSelector** 可通过 `SessionManager.getStats()` 获取Token使用统计辅助模型选择决策

### 与质量子系统（Quality Subsystem）的交互

- **QualityScorer** 可通过 `SessionManager.getDeepeningState()` 获取质量分数历史辅助评分
- **SelfReflection** 监听 `SessionManager` 的 `entropy-updated` 事件，在熵状态变化时触发自反思

### 与基础设施子系统（Infrastructure Subsystem）的交互

- **SharedInfrastructure** 中的 `SqliteStore` 可作为 `SessionManager` 的替代持久化后端
- **EventBus** 可转发 `SessionManager` 的事件到全局事件流
- **HealthChecker** 可通过 `SessionManager.getStats()` 获取会话健康指标

## 补充摘要：会话生命周期与检查点集成

会话子系统管理会话从创建到过期/完成的完整生命周期：会话创建（`create()`）→ 六阶段执行流转（`advancePhase()`）→ Skill 完成记录（`completeSkill()`）→ Token 消耗追踪（`addTokenUsage()`）→ 深化推理状态追踪（`recordDeepeningIteration()`）→ 会话过期或完成。整个生命周期中，会话状态通过防抖持久化（`KeyedDebouncer` + 原子写入）实时保存至 `.harness/sessions/` 目录，TTL 清理器按 5 分钟间隔清除过期会话。

CheckpointManager 与会话管理的集成形成完整的容错恢复链路：在关键阶段转换点或 Skill 完成时，外部组件（如 PhaseOrchestrator）调用 `CheckpointManager.create()` 创建会话状态快照；当进程崩溃后重启，`restoreWithCausalRollback()` 恢复最新检查点并协调 CausalDataBus 的 WAL 回滚，确保因果数据与会话状态的一致性。检查点容量上限 50 个，FIFO 淘汰策略确保不会无限增长。

源文件：`src/runtime/session/session-manager.js`、`src/runtime/session/checkpoint-manager.js`。
