# 第一部分：架构概览

## 概述

记忆管线子系统（Memory Pipeline Subsystem）是思维子系统的核心集成层，负责管理Agent在多轮协作中产生的知识存储、跨源检索、存储间同步与预测性预取。系统采用Hermes三阶段管道架构——**Recall**（召回）→ **Sync**（同步）→ **Prefetch**（预取），通过`MemoryPipeline`作为统一入口自动布线8+组件，屏蔽底层复杂性。

核心设计理念：
- **分层存储**：BrainMemory（工作记忆+长期记忆）与MemoryStore（知识条目+会话摘要）提供不同粒度的存储
- **多源联合召回**：UnifiedMemoryRecaller跨7种存储源并行/顺序检索，去重+置信度排序
- **预测性预取**：MemoryPrefetcher基于5种信号提前加载可能需要的记忆
- **跨存储同步**：MemorySyncCoordinator协调多存储间数据一致性，支持3种冲突策略
- **因果记忆**：CausalMemoryStore管理因果关系条目，支持语义搜索与因果链追踪
- **对话上下文**：ConversationContextStore管理对话轮次持久化与自动压缩

## 模块清单

| 模块 | 源文件 | 说明 |
|------|--------|------|
| MemoryPipeline | `thought/memory-pipeline.js` | 记忆管线主入口，Hermes三阶段管道编排，自动布线8+组件 |

# 第二部分：核心组件详解

## MemoryPipeline 设计

### 核心职责

MemoryPipeline是记忆管线的顶层集成组件，实现Hermes三阶段管道的统一接入和自动布线。模块在初始化时自动创建MemoryPrefetcher、UnifiedMemoryRecaller、MemorySyncCoordinator三个子组件，通过`attachComponent()`接收外部组件引用，在`initialize()`时自动完成8+组件的布线连接。

### Hermes三阶段管道

| 阶段 | 组件 | 说明 |
|------|------|------|
| **Recall** | UnifiedMemoryRecaller | 跨7源联合召回，去重+置信度排序 |
| **Sync** | MemorySyncCoordinator | 跨存储数据同步，冲突检测与解决 |
| **Prefetch** | MemoryPrefetcher | 5种信号驱动预测性记忆加载 |

### 自动布线机制

`initialize()`时依次执行5步布线：

1. **_wirePrefetcher()**：将BrainMemory/MemoryStore/StructuredIntent/AffinityLearner/PhaseContextInjector/UserModelManager/LLMWiki/DreamEngine附加到预取器
2. **_wireRecaller()**：将7种召回源附加到召回器（含Prefetcher自身作为缓存源），设置优先级
3. **_wireSyncCoordinator()**：将4种同步存储注册到同步协调器
4. **_wireDreamEngine()**：反向注入BrainMemory/MemoryStore/ThoughtStore/EmbeddingService/SqliteStore到DreamEngine
5. **_wireProviders()**：根据配置自动实例化外部记忆提供商（mem0/honcho/hindsight）

### 外部记忆提供商

通过`providers`配置启用外部记忆服务：

| 提供商 | 适配器类 | 说明 |
|--------|---------|------|
| mem0 | Mem0Adapter | 云端/自托管记忆服务，REST API集成 |
| honcho | HonchoAdapter | AI原生记忆平台，用户级/会话级记忆管理 |
| hindsight | HindsightAdapter | 本地部署记忆服务，记忆蒸馏 |

## BrainMemory 设计

### 核心职责

BrainMemory是核心记忆存储，实现分层记忆架构（工作记忆+长期记忆），提供关键词+语义混合检索、TF-IDF评分、周期性记忆整合、TTL过期和LRU淘汰。

### 混合检索模式

| 模式 | 方法 | 权重 | 说明 |
|------|------|------|------|
| **keyword** | `_retrieveKeyword()` | 0.4 | TF-IDF关键词匹配，含标签加权 |
| **semantic** | `_retrieveSemantic()` | 0.6 | 余弦相似度语义匹配（需EmbeddingService） |
| **hybrid** | `_fuseResults()` | 0.4+0.6 | 融合关键词与语义结果，双路去重合并 |

### TF-IDF评分

`_computeTfIdf(query, content)`计算TF-IDF分数：
- **分词**：支持中英文（`\u4e00-\u9fff`），去除标点
- **TF**：词频/最大词频归一化
- **IDF**：`log((totalDocs + 1) / (df + 1)) + 1`，平滑处理
- **倒排索引**：`_documentFreq` Map，容量上限`maxDocumentFreqTokens`（默认50000），超出按频率淘汰低频词

### 记忆整合

`consolidate()`执行三步整合：

1. **移除过期记忆**：`expiresAt < now`的条目
2. **移除失效记忆**：`stale === true`的条目
3. **合并相似记忆**：嵌入余弦相似度 > `similarityThreshold`（默认0.8）时合并，保留高置信度条目，合并标签

整合定时器间隔：`consolidationInterval`（默认3600000ms = 1小时）

### LRU淘汰

容量满时（`maxMemories`默认2000），`_evictOldest()`优先淘汰`stale`条目，否则淘汰`updatedAt`最早的条目。

## MemoryStore 设计

### 核心职责

MemoryStore管理长期知识条目和会话摘要的持久化，支持原子JSON写入、规格资产索引、容量裁剪和语义查询。

### 知识条目结构

```javascript
{
  id: 'mem-xxxx',              // 自动生成ID
  category: string,            // 类别（必填，最大256字符）
  title: string,               // 标题（可选，最大256字符）
  content: string,             // 内容（必填，最大1MB）
  tags: string[],              // 标签（最多100个）
  source: string,              // 来源
  specificationType: string,   // 规格类型（null或字符串）
  livenessStatus: string,      // 存活状态（'alive'/'orphaned'/null）
  relatedCodePaths: string[],  // 关联代码路径
  lastVerifiedAgainstCode: number|null,
  createdAt: string,           // ISO时间戳
  updatedAt: string,
}
```

### 容量裁剪策略

`_trimKnowledge()`在条目超过`MAX_KNOWLEDGE_ENTRIES`（500）时按优先级裁剪：

1. 优先移除非规格条目（`!specificationType`）
2. 其次移除孤立条目（`livenessStatus === 'orphaned'`）
3. 规格条目受保护，不会被裁剪

### 规格资产索引

`_specAssetIndex`维护`specificationType → [id]`的映射，支持按规格类型快速检索资产条目。

### 持久化机制

- **存储路径**：`.harness/knowledge/knowledge.json` + `.harness/knowledge/summaries.json`
- **防抖写入**：`DEFAULT_DEBOUNCE_MS`间隔，避免频繁IO
- **异步恢复**：构造时自动从磁盘恢复，`ready` Promise标识恢复完成
- **原子写入**：`writeAtomic()`确保数据完整性

## MemoryPrefetcher 设计

### 核心职责

MemoryPrefetcher实现Hermes Prefetch阶段，基于5种信号预测性加载可能需要的记忆，减少召回延迟。

### 5种预取信号

| 信号 | 常量 | 触发方法 | 数据源 |
|------|------|---------|--------|
| **阶段变更** | `PHASE_CHANGE` | `onPhaseChange()` | BrainMemory + LLMWiki + DreamEngine |
| **高熵意图** | `HIGH_ENTROPY` | `onIntentParsed()` | BrainMemory + MemoryStore |
| **任务亲和** | `TASK_AFFINITY` | `onTaskAssigned()` | BrainMemory + AffinityLearner |
| **用户模式** | `USER_PATTERN` | `onUserInteraction()` | UserModelManager |
| **周期性** | `PERIODIC` | `_performPeriodicPrefetch()` | BrainMemory（基于近期访问模式） |

### 预取流程

1. 信号触发 → 检查并发限制（`maxConcurrentPrefetches`默认3）
2. 检查缓存是否命中且未过期（`prefetchTTL`默认300000ms）
3. 从对应数据源检索记忆
4. 存入BoundedMap缓存（`maxPrefetchedEntries`默认50）
5. 发出`prefetch-completed`事件

### 访问模式记录

`_accessPatterns`（BoundedArray，容量200）记录所有信号事件，供周期性预取分析近期访问模式。

## MemorySyncCoordinator 设计

### 核心职责

MemorySyncCoordinator协调跨存储数据一致性，支持3种同步策略、3种冲突解决策略和队列化同步。

### 同步策略

| 策略 | 常量 | 说明 |
|------|------|------|
| **事件驱动** | `ON_EVENT` | 数据变更时立即触发同步 |
| **周期性** | `PERIODIC` | 定时全量同步（`syncIntervalMs`默认300000ms） |
| **手动** | `MANUAL` | 显式调用`syncAll()`触发 |

### 冲突解决策略

| 策略 | 常量 | 说明 |
|------|------|------|
| **最新胜** | `LATEST_WINS` | 比较timestamp，保留更新的数据 |
| **置信度合并** | `CONFIDENCE_MERGE` | 合并所有字段，置信度取最大值，标签取并集 |
| **源优先级** | `SOURCE_PRIORITY` | 按注册时的priority决定保留哪个源的数据 |

### 同步队列

`enqueueSync()`将同步项入队（BoundedArray，`maxSyncQueueSize`默认100），`enableAutoSync`时自动处理队列。队列处理按`batchSize`（默认10）批量执行。

### 自适应方法发现

`getDefaultSyncFn()`/`getDefaultWriteFn()`/`getDefaultQueryFn()`自动探测存储实例的方法名，适配不同存储接口：

- **读取**：`queryKnowledge` → `search` → `getNotes` → `retrieve`
- **写入**：`addKnowledge` → `store` → `createEntry`
- **查询**：`getKnowledge` → `get` → `getById` → `retrieve` → `queryKnowledge` → `search`

## UnifiedMemoryRecaller 设计

### 核心职责

UnifiedMemoryRecaller实现Hermes Recall阶段，跨7种存储源联合召回，支持并行/顺序双模式、去重、置信度排序和查询缓存。

### 7种召回源

| 源 | 常量 | 默认召回方法 | 优先级 |
|----|------|-------------|--------|
| **BrainMemory** | `BRAIN_MEMORY` | `retrieve(query, opts)` | 1 |
| **MemoryStore** | `MEMORY_STORE` | `queryKnowledge(query)` | 2 |
| **ThoughtStore** | `THOUGHT_STORE` | `search(query, opts)` | 1 |
| **LLMWiki** | `LLM_WIKI` | `search(query)` | 3 |
| **DreamEngine** | `DREAM_ENGINE` | `getRelevantNotes(query, opts)` | 1 |
| **CausalStore** | `CAUSAL_STORE` | `searchByCausalSimilarity(query, opts)` | 1 |
| **Prefetcher** | `PREFETCHER` | `getPrefetched(query)` | 1 |

### 召回流程

```
query → 缓存检查 → 源收集(并行/顺序) → 结果归一化 → 去重 → 置信度排序 → 截断 → 缓存写入 → 返回
```

### 并行 vs 顺序模式

| 模式 | 配置 | 说明 |
|------|------|------|
| **并行** | `enableParallelRecall: true`（默认） | `Promise.allSettled()`并发查询所有源，超时保护 |
| **顺序** | `enableParallelRecall: false` | 按优先级降序逐源查询，高优先级源先返回 |

### 去重算法

`_deduplicateResults()`按`key`字段去重（key来源：`item.key || item.id || item.causalId || source:content[:100]`），相同key保留高置信度结果。

### 排序规则

1. 置信度差 > 0.1时，高置信度优先
2. 置信度接近时，源优先级高的优先

### 源超时保护

每个源查询设置`sourceTimeoutMs`（默认5000ms）超时，超时后返回空结果，不影响其他源。

## CausalMemoryStore 设计

### 核心职责

CausalMemoryStore管理因果记忆的存储、检索和衰减，支持关键词搜索、语义向量搜索、语义分组、上下文链和因果链追踪。

### 因果记忆条目结构

```javascript
{
  id: 'cm_xxxx',           // UUID前缀
  cause: string,            // 因
  effect: string,           // 果
  context: string,          // 上下文描述
  confidence: number,       // 置信度(0~1)
  temporalScope: string,    // 时间范围：'session'
  category: string,         // 分类
  tags: string[],           // 标签（最多20个）
  source: string,           // 来源
  createdAt: number,        // Unix时间戳（秒）
  updatedAt: number,
  verifiedAt: number|null,
}
```

### 搜索模式

| 模式 | 方法 | 说明 |
|------|------|------|
| **关键词搜索** | `searchByCausalSimilarity(query, {mode:'keyword'})` | Jaccard相似度排序 |
| **语义向量搜索** | `searchByCausalSimilarity(query, {mode:'semantic'})` | 余弦相似度排序（需EmbeddingService） |
| **自动选择** | `searchByCausalSimilarity(query, {mode:'auto'})` | 有EmbeddingService时用语义，否则关键词 |
| **语义分组** | `searchBySemanticGroup(query, opts)` | 基础搜索+category/tags/confidence过滤+时间衰减 |
| **上下文链** | `searchByContextChain(query, completedSkills, opts)` | 语义分组+已完成Skill扩展查询 |
| **因果链追踪** | `traceCausalChain(effectKeyword, opts)` | BFS沿cause字段反向追踪（最大深度5） |

### 时间衰减

```
衰减置信度 = max(0.01, 原始置信度 × decayFactor^ageDays)
```

- `decayFactor`默认0.98（每天衰减2%）
- 30天后约45%衰减，最小值0.01防止归零

### 因果冲突检测

`detectCausalConflicts()`检测相似原因但不同结果的记忆条目（原因相似度 ≥ 0.7，结果相似度 < 0.3）。

## ConversationContextStore 设计

### 核心职责

ConversationContextStore管理对话轮次的持久化、检索和自动压缩，支持SQLite WAL模式持久化、FTS5全文搜索和JSON文件降级。

### 对话轮次角色

| 角色 | 常量 | 说明 |
|------|------|------|
| **user** | `TURN_ROLES.USER` | 用户消息 |
| **assistant** | `TURN_ROLES.ASSISTANT` | AI回复 |
| **tool** | `TURN_ROLES.TOOL` | 工具调用结果 |
| **system** | `TURN_ROLES.SYSTEM` | 系统消息（含压缩摘要） |

### 持久化层

| 层级 | 条件 | 说明 |
|------|------|------|
| **SQLite** | SqliteStore可用 | WAL模式，FTS5全文索引，预编译语句 |
| **JSON文件** | SqliteStore不可用 | `.harness/conversations/{sessionId}.json` |

### SQLite表结构

- **conversation_turns**：turn_id(PK) / session_id / role / content / timestamp / sequence / metadata
- **conversation_sessions**：session_id(PK) / summary / started_at / last_activity_at / turn_count / metadata / ended
- **conversation_turns_fts**：FTS5虚拟表，content列全文索引

### 自动压缩

`compressSession()`在轮次数超过`compressionThreshold`（默认200）时触发：

1. 保留最近`compressionThreshold / 2`条轮次
2. 对较早轮次生成摘要（提取Topics/Decisions/Errors/Completed/Preferences）
3. 插入压缩摘要轮次（role=system, type=compression-summary）
4. 删除已压缩的旧轮次
5. 估算Token节省量

### 会话容量管理

- 单会话最大轮次：`MAX_TURNS_PER_SESSION`（500），超出时FIFO淘汰
- 最大会话数：`MAX_SESSIONS`（100），超出时优先淘汰已结束的旧会话
- 摘要最大长度：`MAX_SUMMARY_LENGTH`（2200字符）

const causalStore = CausalMemoryStore.fromConfig(sqliteStore, '/path/to/project');

const conversationStore = new ConversationContextStore({
  sqliteStore,
  compressionThreshold: 200,
});

// 2. 创建并初始化记忆管线
const pipeline = new MemoryPipeline({
  enablePrefetch: true,
  enableRecall: true,
  enableSync: true,
  prefetchConfig: { maxPrefetchedEntries: 100 },
  recallConfig: { maxResults: 20, enableParallelRecall: true },
  syncConfig: { conflictStrategy: 'confidence-merge' },
});

pipeline
  .attachComponent('brain-memory', brainMemory)
  .attachComponent('memory-store', memoryStore)
  .attachComponent('llm-wiki', llmWiki)
  .attachComponent('dream-engine', dreamEngine)
  .attachComponent('thought-store', thoughtStore)
  .attachComponent('affinity-learner', affinityLearner)
  .attachComponent('user-model-manager', userModelManager)
  .attachComponent('structured-intent', structuredIntent)
  .attachComponent('causal-store', causalStore)
  .attachComponent('embedding-service', embeddingService)
  .attachComponent('sqlite-store', sqliteStore);

pipeline.initialize();

// 3. 存储记忆
brainMemory.store('arch-pattern', '分层架构设计原则：Interaction→Business→Domain→Infrastructure', {
  category: 'architecture',
  tags: ['pattern', 'layered'],
  confidence: 0.9,
});

memoryStore.addKnowledge({
  category: 'coding-standards',
  title: 'TDD强制规则',
  content: '先写测试后写代码，RED-GREEN-REFACTOR循环',
  tags: ['tdd', 'testing'],
  source: 'project-rules',
});

await causalStore.addCausalMemory({
  cause: '需求变更',
  effect: '架构调整',
  context: '用户认证需求从OAuth改为JWT',
  confidence: 0.9,
  category: 'requirement-change',
  tags: ['auth', 'architecture'],
});

// 4. 记录对话上下文
conversationStore.startSession('session-001', { agent: 'team-lead' });
conversationStore.recordTurn({ role: 'user', content: '请帮我设计用户认证模块' });
conversationStore.recordTurn({ role: 'assistant', content: '建议采用JWT方案...' });
conversationStore.recordToolCall('code-search', 'auth module', 'found 3 files', 150);

// 5. 统一召回
const recallResult = await pipeline.recall('用户认证架构设计');
console.log(`召回 ${recallResult.results.length} 条结果`);
for (const r of recallResult.results) {
  console.log(`  [${r.source}] conf=${r.confidence.toFixed(2)}: ${r.key}`);
}

// 6. 预取信号
pipeline.onPhaseChange({ phase: 'module-development' });
pipeline.onIntentParsed({ intent: 'implement-auth', priorRichness: { entropy: 0.8 } });
pipeline.onTaskAssigned({ type: 'coding', skillId: 'tdd-implement' });

// 7. 跨存储同步
const syncResult = await pipeline.syncAll();
console.log(`同步: ${syncResult.synced}条, 冲突: ${syncResult.conflicts}条`);

// 8. 压缩对话
const compression = conversationStore.compressSession('session-001');
console.log(`压缩: 移除${compression.turnsRemoved}轮, 节省${compression.tokensSaved} tokens`);

// 9. 搜索对话
const turns = conversationStore.searchTurns('认证', { limit: 5 });
console.log(`搜索到 ${turns.length} 条相关轮次`);

// 10. 因果链追踪
const chain = await causalStore.traceCausalChain('架构调整', { maxDepth: 3 });
for (const link of chain) {
  console.log(`  ${link.cause} → ${link.effect} (conf=${link.confidence})`);
}

// 11. 健康检查与统计
console.log('Pipeline healthy:', pipeline.isHealthy());
console.log('Stats:', pipeline.getStats());

// 12. 优雅关闭
conversationStore.endSession('会话完成');
await pipeline.shutdownAsync();
