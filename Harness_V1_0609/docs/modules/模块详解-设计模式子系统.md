# 设计模式子系统

## 子系统概述

设计模式子系统（`src/runtime/patterns/`）是 Harness Engineering 多Agent框架的核心增强层，融合了 Google Agentic Design Patterns、Harness Engineering 约束方法论、Plan-then-Execute 范式、多智能体系统工程控制和 ReAct 推理模式五大设计模式体系。该子系统为智能体工作流提供质量保障、容错路由、并行加速、自我改进、上下文管理、约束防御、规划执行和迭代控制等关键能力。

### 架构定位

```
用户请求 → SkillRouter(路由匹配)
    → AgenticPatterns(质量验证+回退路由+并发控制+反思循环)
    → HarnessEngineering(渐进披露+三重防线+验证循环)
    → PlanExecuteEnhancer(滚动规划+需求边界+模板固化+记忆桥接)
    → MultiAgentControl(迭代守卫+上下文压缩+完成标准+洋葱模型)
    → ReActAgent(推理→行动→观察迭代循环)
```

## 模块清单

| 模块 | 文件 | 核心能力 |
|------|------|---------|
| AgenticPatterns | agentic-patterns.js | Google Agentic 8大核心模式增强：验证门禁+回退路由+并发控制+反思循环 |
| HarnessEngineering | harness-engineering.js | 驾驭工程6大约束增强：渐进披露+三重防线+验证循环 |
| PlanExecuteEnhancer | plan-execute-enhancer.js | 先规划后执行双架构：滚动规划+需求边界+模板固化+记忆桥接 |
| MultiAgentControl | multi-agent-control.js | 多智能体系统工程控制：迭代守卫+上下文压缩+完成标准+洋葱模型 |
| ReActAgent | react-agent.js | 标准ReAct推理模式：think→act→observe迭代循环 |

## 模块详解

### 1. AgenticPatterns — 智能体设计模式集合

**源文件**：`src/runtime/patterns/agentic-patterns.js`

融合 Google Agentic Design Patterns 分析中的4个最高优先级增强，组合四大子组件为智能体工作流提供完整的增强能力。

#### 子组件

| 子组件 | 功能 | 对应模式 |
|--------|------|---------|
| ValidationGate | 链式步骤中间质量验证 | Prompt Chaining |
| FallbackRouter | 无匹配回退路由策略 | Routing |
| ConcurrencyController | 信号量模式并发控制 | Parallelization |
| ReflectionLoop | 反思修订循环 | Reflection |

#### 核心 API

##### ValidationGate

| 方法 | 签名 | 说明 |
|------|------|------|
| `validate` | `validate(output, stepName) → { passed, score, reason }` | 验证步骤输出质量，优先使用自定义验证函数，否则使用默认评分逻辑 |
| `registerValidator` | `registerValidator(stepName, validatorFn)` | 注册自定义步骤验证函数，签名为 `(output) => { passed, score, reason }` |

**属性**：`qualityThreshold`（质量阈值，默认0.7）、`maxRetries`（最大重试次数，默认2）

##### FallbackRouter

| 方法 | 签名 | 说明 |
|------|------|------|
| `handleNoMatch` | `handleNoMatch(query, candidates) → { resolved, strategy, result }` | 处理无匹配情况，按优先级尝试：宽松匹配→回退处理器→澄清请求 |
| `registerFallback` | `registerFallback(handlerFn)` | 注册回退处理函数，签名为 `(query, candidates) => result\|null` |

**属性**：`clarificationPrompt`（澄清提示模板）

**回退策略顺序**：(a) 宽松匹配（大小写不敏感子串匹配）→ (b) 注册的回退处理器 → (c) 澄清请求

##### ConcurrencyController

| 方法 | 签名 | 说明 |
|------|------|------|
| `executeAll` | `executeAll(tasks, executeFn) → Promise<Array>` | 并发执行所有任务，返回全部结果（含重试信息） |

**属性**：`maxConcurrency`（最大并发数，默认5）、`runningCount`（当前运行任务数）、`queuedCount`（等待队列长度）

**特性**：信号量模式控制并发、失败任务支持指数退避重试（基数500ms）

##### ReflectionLoop

| 方法 | 签名 | 说明 |
|------|------|------|
| `execute` | `execute(initialOutput) → Promise<{ finalOutput, iterations, converged, qualityHistory }>` | 执行反思-修订循环，直到收敛或达到最大迭代次数 |

**属性**：`maxIterations`（最大迭代次数，默认5）、`convergenceThreshold`（收敛阈值，默认0.85）

**构造参数**：`reflectionFn`（反思函数，必需）、`revisionFn`（修订函数，必需）、`replanFn`（重新规划函数，可选）

##### AgenticPatterns 便捷方法

| 方法 | 委托目标 | 说明 |
|------|---------|------|
| `validate(output, stepName)` | ValidationGate | 验证步骤输出质量 |
| `registerValidator(stepName, validatorFn)` | ValidationGate | 注册步骤验证函数 |
| `handleNoMatch(query, candidates)` | FallbackRouter | 处理无匹配查询 |
| `registerFallback(handlerFn)` | FallbackRouter | 注册回退处理器 |
| `executeAll(tasks, executeFn)` | ConcurrencyController | 并发执行任务 |
| `initReflectionLoop(options)` | ReflectionLoop | 初始化反思循环（需传入 reflectionFn 和 revisionFn） |
| `reflect(initialOutput)` | ReflectionLoop | 执行反思循环 |

#### 事件类型

| 事件名 | 来源 | 触发时机 |
|--------|------|---------|
| `validation-passed` | ValidationGate | 验证通过 |
| `validation-failed` | ValidationGate | 验证失败 |
| `fallback-triggered` | FallbackRouter | 回退策略触发 |
| `fallback-resolved` | FallbackRouter | 回退策略解决 |
| `task-started` | ConcurrencyController | 任务开始执行 |
| `task-completed` | ConcurrencyController | 任务成功完成 |
| `task-failed` | ConcurrencyController | 任务最终失败 |
| `task-retried` | ConcurrencyController | 任务重试 |
| `reflection-iteration` | ReflectionLoop | 每次反思迭代完成 |
| `convergence-detected` | ReflectionLoop | 检测到收敛 |
| `replan-triggered` | ReflectionLoop | 触发重新规划 |

#### 配置项

```javascript
const patterns = new AgenticPatterns({
  validationGate: { qualityThreshold: 0.8, maxRetries: 3 },
  fallbackRouter: { clarificationPrompt: '自定义澄清提示' },
  concurrencyController: { maxConcurrency: 10, retryOnFailure: true, maxRetries: 3 },
  reflectionLoop: { maxIterations: 10, convergenceThreshold: 0.9 },
});
```

#### 使用示例

```javascript
const AgenticPatterns = require('./src/runtime/patterns/agentic-patterns');

const patterns = new AgenticPatterns({
  validationGate: { qualityThreshold: 0.8 },
  concurrencyController: { maxConcurrency: 5 },
});

// 注册自定义验证器
patterns.registerValidator('code-generation', (output) => {
  const hasTests = output.includes('test(');
  return { passed: hasTests, score: hasTests ? 0.9 : 0.3, reason: hasTests ? '包含测试' : '缺少测试' };
});

// 验证步骤输出
const result = patterns.validate(generatedCode, 'code-generation');

// 处理无匹配查询
const fallback = patterns.handleNoMatch('用户查询', skillCandidates);

// 并发执行任务
const results = await patterns.executeAll(tasks, async (task) => {
  return await processTask(task);
});

// 初始化并执行反思循环
patterns.initReflectionLoop({
  reflectionFn: async (output) => ({ score: evaluateQuality(output), feedback: '...', recommendedAction: 'continue' }),
  revisionFn: async (output, feedback) => reviseOutput(output, feedback),
  replanFn: async (output, feedback) => replanFromScratch(output, feedback),
});
const reflection = await patterns.reflect(initialOutput);
```

### 2. HarnessEngineering — 驾驭工程增强

**源文件**：`src/runtime/patterns/harness-engineering.js`

融合 Harness Engineering 分析中的3个最高优先级增强，组合三大子组件为工程流程提供上下文管理、约束防御和质量验证能力。

#### 子组件

| 子组件 | 功能 |
|--------|------|
| ProgressiveDisclosureOrchestrator | 渐进式上下文披露编排，按阶段控制上下文披露粒度 |
| TripleDefenseCoordinator | 三重防线协调（软约束→硬编码→Linter），自动检测覆盖缺口 |
| VerificationLoop | 自验证循环，前置验证→执行→后置验证→修复循环 |

#### 核心 API

##### ProgressiveDisclosureOrchestrator

| 方法 | 签名 | 说明 |
|------|------|------|
| `registerPhaseTransition` | `registerPhaseTransition(fromPhase, toPhase, transitionFn)` | 注册阶段转换规则，签名为 `(context) => { keep, compress, discard }` |
| `onPhaseTransition` | `onPhaseTransition(fromPhase, toPhase, context) → { keep, compress, discard }` | 阶段转换回调，应用转换规则 |
| `getDisclosurePlan` | `getDisclosurePlan(phase, tokenBudget) → { phase, tokenBudget, disclosureItems, estimatedTokens }` | 获取当前阶段的上下文披露计划 |
| `linkSkillRouter` | `linkSkillRouter(skillRouter)` | 关联技能路由器，用于 L1/L2/L3 渐进加载 |
| `linkTokenManager` | `linkTokenManager(tokenManager)` | 关联令牌管理器，用于预算驱动披露 |

**属性**：`currentPhase`（当前阶段）、`phases`（阶段列表，默认6阶段：brainstorming→design→implementation→testing→review→deployment）

**内置转换规则**：
- brainstorming→design：保留想法，丢弃探索笔记
- design→implementation：保留架构，丢弃备选方案
- implementation→testing：保留代码，丢弃设计草稿

##### TripleDefenseCoordinator

| 方法 | 签名 | 说明 |
|------|------|------|
| `registerConstraint` | `registerConstraint(ruleName, layers)` | 注册约束规则，layers 包含 soft/hard/linter 三层函数 |
| `checkCoverage` | `checkCoverage() → { total, fullyCovered, partiallyCovered, uncovered, details }` | 检查约束覆盖情况 |
| `enforce` | `enforce(ruleName, context) → { ruleName, results, allPassed }` | 执行三层约束（软→硬→Linter） |
| `reportViolation` | `reportViolation(ruleName, layer, details)` | 报告约束违反，软约束违反3次自动建议加强为硬约束 |
| `getConstraintReport` | `getConstraintReport() → { constraints, coverage }` | 获取所有约束的完整报告 |

**属性**：`constraintCount`（已注册约束数量）

**三层防御体系**：
- **软约束**（soft）：提示引导，违反3次建议加强为硬约束
- **硬约束**（hard）：代码强制执行
- **代码检查**（linter）：自动化检查

##### VerificationLoop

| 方法 | 签名 | 说明 |
|------|------|------|
| `registerPreValidator` | `registerPreValidator(name, validatorFn)` | 注册前置验证器，签名为 `(context) => { passed, reason }` |
| `registerPostValidator` | `registerPostValidator(name, validatorFn)` | 注册后置验证器，签名为 `(result, context) => { passed, reason }` |
| `execute` | `execute(taskFn, context) → Promise<{ result, preValidation, postValidation, repairAttempts, success }>` | 执行完整验证循环 |
| `validateInputs` | `validateInputs(context) → { passed, failures }` | 运行所有前置验证器 |
| `validateOutputs` | `validateOutputs(result, context) → { passed, failures }` | 运行所有后置验证器 |

**属性**：`maxRepairIterations`（最大修复迭代次数，默认3）

**执行流程**：前置验证 → 执行任务 → 后置验证 → 修复循环 → 跨文件一致性检查

#### 事件类型

| 事件名 | 来源 | 触发时机 |
|--------|------|---------|
| `phase-transition` | ProgressiveDisclosureOrchestrator | 阶段转换 |
| `disclosure-plan-updated` | ProgressiveDisclosureOrchestrator | 披露计划更新 |
| `context-discarded` | ProgressiveDisclosureOrchestrator | 上下文被丢弃 |
| `constraint-violated` | TripleDefenseCoordinator | 约束被违反 |
| `coverage-gap-detected` | TripleDefenseCoordinator | 检测到覆盖缺口 |
| `constraint-strengthened` | TripleDefenseCoordinator | 约束被加强 |
| `pre-validation-passed` | VerificationLoop | 前置验证通过 |
| `pre-validation-failed` | VerificationLoop | 前置验证失败 |
| `post-validation-passed` | VerificationLoop | 后置验证通过 |
| `post-validation-failed` | VerificationLoop | 后置验证失败 |
| `repair-attempted` | VerificationLoop | 修复尝试 |

#### 配置项

```javascript
const he = new HarnessEngineering({
  progressiveDisclosure: { phases: ['design', 'build', 'test'] },
  tripleDefense: { constraintMapPath: './constraints.json' },
  verificationLoop: { maxRepairIterations: 5, preValidators: [...], postValidators: [...] },
});
```

#### 使用示例

```javascript
const HarnessEngineering = require('./src/runtime/patterns/harness-engineering');

const he = new HarnessEngineering();

// 注册阶段转换规则
he.registerPhaseTransition('design', 'implementation', (ctx) => ({
  keep: ctx.architecture,
  compress: [],
  discard: ctx.alternatives,
}));

// 注册三重防线约束
he.registerConstraint('no-direct-db-access', {
  soft: (ctx) => ctx.hasDBImport ? { passed: false, reason: '禁止直接DB访问' } : { passed: true },
  hard: (ctx) => !ctx.hasDBImport,
  linter: (ctx) => ({ passed: !ctx.code?.includes('require("database")'), reason: '检测到DB直接引用' }),
});

// 执行验证循环
const result = await he.execute(async (ctx) => {
  return await performTask(ctx);
}, { taskData: '...' });
```

### 3. PlanExecuteEnhancer — 先规划后执行双架构增强

**源文件**：`src/runtime/patterns/plan-execute-enhancer.js`

融合4个核心子组件，为规划-执行范式提供滚动规划、需求边界锁定、规划模板固化和长期记忆反馈能力。

#### 子组件

| 子组件 | 功能 |
|--------|------|
| RollingPlanner | 小步规划+快速执行的滚动规划器，planningHorizon默认3步 |
| RequirementBoundary | 需求解析与边界锁定，边界锁定后不可修改 |
| PlanSchema | 标准化规划输出格式，P0/P1/P2优先级+risks/resources字段 |
| PlanMemoryBridge | 执行反馈学习桥，从历史执行结果中提取规划模式 |

#### 核心 API

##### RollingPlanner

| 方法 | 签名 | 说明 |
|------|------|------|
| `planNextBatch` | `planNextBatch(context) → Promise<{ steps, remainingObjectives }>` | 规划下一批步骤，基于当前上下文和剩余目标 |
| `onStepCompleted` | `onStepCompleted(stepResult) → Promise<void>` | 步骤执行完成回调 |
| `replanOnFailure` | `replanOnFailure(failedStep, failureReason, executionHistory) → Promise<{ steps, remainingObjectives, replanCount }>` | 失败时重新规划 |
| `getPlanStatus` | `getPlanStatus() → { plannedSteps, executedSteps, remainingObjectives, replanCount }` | 获取当前规划状态 |

**属性**：`planningHorizon`（前瞻步数，默认3）、`maxReplanCount`（最大重规划次数，默认5）

##### RequirementBoundary

| 方法 | 签名 | 说明 |
|------|------|------|
| `parseRequirements` | `parseRequirements(rawInput) → Promise<{ requirements, rawInput, parsedAt }>` | 解析原始输入为结构化需求 |
| `defineBoundary` | `defineBoundary(objective, inclusions, exclusions) → { boundaryId, objective, inclusions, exclusions, definedAt }` | 定义需求边界 |
| `lockBoundary` | `lockBoundary(boundaryId) → Object\|null` | 锁定边界，锁定后不可修改 |
| `isLocked` | `isLocked(boundaryId) → boolean` | 检查边界是否已锁定 |
| `assessCompleteness` | `assessCompleteness(requirements) → { score, needsClarification, clarificationPrompts }` | 评估需求完整性 |
| `getBoundary` | `getBoundary(boundaryId) → Object\|undefined` | 获取边界定义 |

**属性**：`completenessThreshold`（完整性阈值，默认0.8）

##### PlanSchema

| 方法 | 签名 | 说明 |
|------|------|------|
| `createPlan` | `PlanSchema.createPlan(params) → Object` | 创建标准化计划对象 |
| `createStep` | `PlanSchema.createStep(params) → Object` | 创建标准化步骤对象 |
| `validatePlan` | `PlanSchema.validatePlan(plan) → { valid, errors }` | 验证计划是否符合标准 schema |
| `createFromTemplate` | `PlanSchema.createFromTemplate(template, variables) → Object` | 从工作流模板实例化计划 |

**步骤优先级**：P0（核心）→ P1（重要）→ P2（可选）

##### PlanMemoryBridge

| 方法 | 签名 | 说明 |
|------|------|------|
| `recordExecutionOutcome` | `recordExecutionOutcome(planId, outcome)` | 记录计划执行结果 |
| `extractPlanningPatterns` | `extractPlanningPatterns(taskType) → Promise<{ taskType, successRate, commonSteps, failurePatterns, recommendation }>` | 提取规划模式 |
| `getRecommendedPlan` | `getRecommendedPlan(taskType, objective) → Promise<Object\|null>` | 获取推荐计划模板 |
| `registerPlanTemplate` | `registerPlanTemplate(taskType, planTemplate)` | 注册已验证的计划模板 |

**属性**：`brainMemory`（大脑记忆引用）

#### 事件类型

| 事件名 | 来源 | 触发时机 |
|--------|------|---------|
| `batch-planned` | RollingPlanner | 新批次步骤规划完成 |
| `step-completed` | RollingPlanner | 步骤执行完成 |
| `replan-triggered` | RollingPlanner | 失败触发重新规划 |
| `boundary-defined` | RequirementBoundary | 边界定义完成 |
| `boundary-locked` | RequirementBoundary | 边界锁定 |
| `clarification-needed` | RequirementBoundary | 需求完整性不足需要澄清 |
| `outcome-recorded` | PlanMemoryBridge | 执行结果记录 |
| `pattern-extracted` | PlanMemoryBridge | 规划模式提取 |
| `template-registered` | PlanMemoryBridge | 模板注册 |

#### 配置项

```javascript
const enhancer = new PlanExecuteEnhancer({
  rollingPlanner: { planningHorizon: 5, maxReplanCount: 10 },
  requirementBoundary: { completenessThreshold: 0.9 },
  planMemoryBridge: { brainMemory: brainMemoryInstance },
});
```

#### 使用示例

```javascript
const PlanExecuteEnhancer = require('./src/runtime/patterns/plan-execute-enhancer');

const enhancer = new PlanExecuteEnhancer({ rollingPlanner: { planningHorizon: 3 } });

// 解析需求并定义边界
const parsed = await enhancer.parseRequirements('实现用户认证模块；支持JWT和OAuth2');
const boundary = enhancer.defineBoundary('用户认证', ['JWT', 'OAuth2'], ['LDAP']);
enhancer.lockBoundary(boundary.boundaryId);

// 创建标准化计划
const plan = enhancer.createPlan({
  objective: '实现用户认证',
  boundaries: { inclusions: ['JWT', 'OAuth2'], exclusions: ['LDAP'] },
  steps: [{ description: '设计认证接口', priority: 'P0' }],
  risks: [{ description: 'Token过期处理', severity: 'medium' }],
});

// 滚动规划
const batch = await enhancer.planNextBatch({ remainingObjectives: ['步骤1', '步骤2', '步骤3'] });
await enhancer.onStepCompleted({ stepId: batch.steps[0].id, status: 'completed' });

// 记录执行结果并提取模式
enhancer.recordExecutionOutcome(plan.planId, { success: true, taskType: 'auth-module' });
const patterns = await enhancer.extractPlanningPatterns('auth-module');
```

### 4. MultiAgentControl — 多智能体系统工程控制

**源文件**：`src/runtime/patterns/multi-agent-control.js`

组合迭代守卫、上下文压缩管道、完成标准和洋葱模型协调器，为多Agent协作提供统一的工程控制框架。

#### 子组件

| 子组件 | 功能 |
|--------|------|
| IterationGuard | 统一迭代限制+熔断器框架，closed→open→half-open三态熔断 |
| ContextPipeline | Agent间上下文压缩管道，三层Token分配（长期40%/阶段35%/即时25%） |
| DefinitionOfDone | 量化完成标准+4类终止条件 |
| OnionModelCoordinator | 洋葱模型协调器，核心层(DoD)→中间层(流程+Token控制)→外层(人工接管) |

#### 核心 API

##### IterationGuard

| 方法 | 签名 | 说明 |
|------|------|------|
| `registerComponent` | `registerComponent(componentId, config) → { componentId, guard }` | 注册组件，返回守卫句柄 |
| `checkIteration` | `checkIteration(componentId) → { allowed, current, max }` | 检查迭代是否允许，递增计数器 |
| `checkRollback` | `checkRollback(componentId) → { allowed, current, max }` | 检查回滚是否允许，递增计数器 |
| `reportFailure` | `reportFailure(componentId, error)` | 报告失败，用于熔断器跟踪 |
| `reportSuccess` | `reportSuccess(componentId)` | 报告成功，重置失败计数器 |
| `isCircuitOpen` | `isCircuitOpen(componentId) → boolean` | 检查熔断器是否开路 |
| `getCircuitState` | `getCircuitState(componentId) → 'closed'\|'open'\|'half-open'` | 获取熔断器状态 |
| `resetCircuit` | `resetCircuit(componentId)` | 手动重置熔断器 |
| `getStats` | `getStats(componentId) → Object` | 获取组件统计信息 |
| `reset` | `reset(componentId)` | 重置组件所有计数器 |

**熔断器状态机**：closed（正常）→ open（熔断，拒绝请求）→ half-open（试探性放行）→ closed

##### ContextPipeline

| 方法 | 签名 | 说明 |
|------|------|------|
| `compressForTransfer` | `compressForTransfer(context, targetAgentId) → Object` | 压缩上下文以传输给目标Agent |
| `buildLayeredContext` | `buildLayeredContext(fullContext, currentPhase) → { longTerm, phase, immediate }` | 构建分层上下文 |
| `generateStructuredSummary` | `generateStructuredSummary(executionLog) → { confirmedFacts, unresolvedIssues, nextSteps, metrics }` | 生成结构化摘要 |
| `estimateTokens` | `estimateTokens(text) → number` | 估算文本令牌数（CJK: 2字符/token，其他: 4字符/token） |
| `getCompressionStats` | `getCompressionStats() → { totalCompressions, averageRatio, tokensSaved }` | 获取压缩统计 |

**三层Token分配**：长期40%（confirmedFacts/architecture/constraints/goals）、阶段35%（currentPhase/phaseProgress/phaseDecisions/phaseErrors）、即时25%（currentTask/recentActions/pendingItems/lastResult）

##### DefinitionOfDone

| 方法 | 签名 | 说明 |
|------|------|------|
| `defineDoD` | `defineDoD(taskId, criteria)` | 定义任务的完成标准 |
| `evaluateDoD` | `evaluateDoD(taskId, currentMetrics) → { met, score, details, overallScore }` | 评估当前指标是否满足DoD |
| `checkTermination` | `checkTermination(taskId, context) → { shouldTerminate, reason, details }` | 检查4类终止条件 |
| `recordProgress` | `recordProgress(taskId, metrics)` | 记录进度，用于停滞检测 |
| `getDoD` | `getDoD(taskId) → Object\|null` | 获取DoD定义 |
| `getTerminationHistory` | `getTerminationHistory(taskId) → Array` | 获取终止原因历史 |

**4类终止条件**：(1) DoD满足 (2) 预算耗尽（时间/成本/令牌） (3) 无进展（停滞检测） (4) 边界越限（迭代次数超限）

##### OnionModelCoordinator

| 方法 | 签名 | 说明 |
|------|------|------|
| `executeWithOnionModel` | `executeWithOnionModel(taskId, executionFn, options) → Promise<{ result, terminationReason, iterationsUsed, circuitState }>` | 使用洋葱模型保护执行任务 |
| `configureEscalation` | `configureEscalation(taskId, config)` | 配置升级规则 |
| `getOnionStatus` | `getOnionStatus(taskId) → { core, middle, outer }` | 获取洋葱模型层级状态 |

**三层保护结构**：
- **核心层**：执行任务，每次迭代后检查DoD
- **中间层**：DoD未满足时，检查迭代限制/回滚限制/熔断器
- **外层**：中间层触发边界时，自动升级到人工审批

### 5. ReActAgent — 标准ReAct推理模式

**源文件**：`src/runtime/patterns/react-agent.js`

标准 ReAct（Reasoning + Acting）Agent 模式实现，通过 think→act→observe 迭代循环驱动智能体推理与行动。

#### 核心概念

ReAct 模式将智能体的推理过程分解为三个阶段的迭代循环：

1. **Think（思考）**：根据当前上下文和观察结果生成推理和行动决策
2. **Act（行动）**：执行选定的工具/动作
3. **Observe（观察）**：收集行动结果作为下一轮推理的输入

当思考阶段产生包含 `finish`/`final_answer`/`done`/`complete` 等关键词的动作时，循环终止并输出最终答案。

#### 核心 API

| 方法 | 签名 | 说明 |
|------|------|------|
| `run` | `run(input) → Promise<{ success, answer, iterations }>` | 启动 ReAct 循环，执行 think→act→observe 迭代直到收敛或超时 |
| `registerTool` | `registerTool(name, fn) → { success }` | 注册工具函数 |
| `getStats` | `getStats() → Object` | 获取运行统计信息 |
| `reset` | `reset()` | 重置Agent状态，回到idle |

**属性**：`state`（当前状态）、`iteration`（当前迭代次数）、`finalAnswer`（最终答案）、`scratchpad`（便签本内容）

#### 状态机

```
IDLE → THINKING → ACTING → OBSERVING → THINKING → ... → COMPLETED
                                                              → FAILED
```

| 状态 | 说明 |
|------|------|
| `idle` | 初始状态，等待输入 |
| `thinking` | 正在思考推理 |
| `acting` | 正在执行动作 |
| `observing` | 正在观察结果 |
| `completed` | 循环完成，已产出最终答案 |
| `failed` | 循环失败 |

#### 事件类型

| 事件名 | 触发时机 |
|--------|---------|
| `react-started` | ReAct循环启动 |
| `react-think` | 思考阶段完成 |
| `react-act` | 行动阶段完成 |
| `react-observe` | 观察阶段完成 |
| `react-completed` | ReAct循环完成 |
| `react-failed` | ReAct循环失败 |

#### 配置项

```javascript
const agent = new ReActAgent({
  maxIterations: 10,           // 最大迭代次数
  maxScratchpadSize: 50,       // 便签本最大条目数
  maxToolResults: 100,         // 工具结果最大缓存数
  thinkFn: customThinkFn,      // 自定义思考函数
  actFn: customActFn,          // 自定义行动函数
  observeFn: customObserveFn,  // 自定义观察函数
  tools: { search: searchFn }, // 工具注册
  convergenceCheck: (state) => state.iteration > 5, // 收敛检测
  timeoutMs: 300000,           // 超时时间（5分钟）
});
```

#### 使用示例

```javascript
const ReActAgent = require('./src/runtime/patterns/react-agent');

const agent = new ReActAgent({
  maxIterations: 10,
  timeoutMs: 60000,
  tools: {
    search: (query) => ({ output: `搜索结果: ${query}` }),
    calculate: (expr) => ({ output: eval(expr) }),
  },
});

// 监听事件
agent.on('react-think', ({ iteration, thought }) => {
  console.log(`[Think #${iteration}]`, thought.reasoning);
});
agent.on('react-act', ({ iteration, action }) => {
  console.log(`[Act #${iteration}]`, action);
});
agent.on('react-observe', ({ iteration, observation }) => {
  console.log(`[Observe #${iteration}]`, observation);
});

// 自定义思考函数
agent._options.thinkFn = async (context) => {
  const lastObs = context.scratchpad.filter(e => e.role === 'observation').pop();
  if (lastObs && lastObs.content.includes('答案')) {
    return { reasoning: '已找到答案', action: 'finish', actionInput: lastObs.content };
  }
  return { reasoning: '需要搜索更多信息', action: 'search', actionInput: '相关查询' };
};

// 运行
const result = await agent.run('请帮我查找并计算...');
console.log(result.answer);
```
