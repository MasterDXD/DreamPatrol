# 第一部分：架构概览

## 概述

深化子系统（Deepening Subsystem）通过多轮迭代精化提升AI输出质量，是Harness Engineering框架中"迭代深化推理"能力的核心实现。该子系统包含10个核心模块，涵盖管道编排、迭代执行、收敛检测、熔断容错、数据验证、负载均衡、健康监控、循环调度、Karpathy原则增强和Token预算感知，协同完成从任务接收到质量收敛的完整深化推理流程。

核心设计理念：
- **迭代精化**：通过多轮Agent执行逐步提升输出质量，直至收敛或达到预算上限
- **容错自愈**：熔断器模式保护深化执行免受级联故障影响
- **预算感知**：Token预算约束下动态调整深化深度和迭代次数
- **多维收敛**：质量阈值、改进率、稳定性方差、维度平衡、质量退化五维收敛检测

## 模块清单

| 模块 | 源文件 | 说明 |
|------|--------|------|
| DeepeningPipeline | deepening-pipeline.js | 深化管道主入口，串联7个子模块，4阶段管线（初始化→缓存检查→迭代执行→完成） |
| DeepeningOrchestrator | deepening-orchestrator.js | 深化推理编排器，迭代精化、质量评分、收敛检测，支持8种可挂载子模块 |
| DeepeningCircuitBreaker | deepening-circuit-breaker.js | 深化推理熔断器，Closed→Open→Half-Open三态转换，容错保护 |

## 关键依赖关系

- **DeepeningPipeline** 是核心入口，在`initialize()`中创建并挂载7个子模块到DeepeningOrchestrator
- **DeepeningOrchestrator** 是核心编排器，通过`attach*()`方法挂载8种子模块（指标采集/缓存/策略插件/报告生成/收敛检测/质量评分/事件存储/OODA闭环）
- **ConvergenceDetector** 被编排器在每轮迭代后调用，决定是否提前终止深化
- **DeepeningCircuitBreaker** 为深化执行提供熔断保护，独立于编排器使用
- **DeepeningLoadBalancer** 为多实例深化执行提供负载均衡，独立于编排器使用
- **DeepeningHealthMonitor** 监控深化子系统健康状态（已废弃，推荐`runtime/infrastructure/health-checker`中的HealthChecker）
- **TokenAwareDeepening** 根据Token预算为编排器推荐迭代次数和深度级别
- **RecurrentDeepeningScheduler** 独立的循环调度器，驱动单Agent反复执行直至收敛
- **KarpathyEnhancer** 位于`src/gate/`目录，增强TDD门禁规则，与深化子系统协同提升代码质量

# 第二部分：架构设计详解

## DeepeningPipeline 设计

### 核心职责

DeepeningPipeline是深化子系统的核心入口，负责：
- 4阶段管线编排（初始化→缓存检查→迭代执行→完成）
- 7个子模块的创建、挂载和生命周期管理
- 将任务和Agent委托给内部DeepeningOrchestrator执行
- 自动初始化和手动初始化两种模式

### 4阶段管线

| 阶段 | 常量 | 说明 |
|------|------|------|
| **INIT** | `PIPELINE_STAGES.INIT` | 初始化管道，创建并挂载所有子模块 |
| **CACHE_CHECK** | `PIPELINE_STAGES.CACHE_CHECK` | 编排器内部检查缓存是否命中 |
| **ITERATIVE_EXECUTION** | `PIPELINE_STAGES.ITERATIVE_EXECUTION` | 编排器执行多轮迭代推理 |
| **COMPLETE** | `PIPELINE_STAGES.COMPLETE` | 管道运行完成，返回结果 |

### 子模块挂载

`initialize()`方法创建以下7个子模块并挂载到编排器：

| 子模块 | 挂载方法 | 说明 |
|--------|---------|------|
| DeepeningOrchestrator | 直接创建 | 核心编排器 |
| DeepeningMetricsCollector | `attachMetricsCollector()` | 指标采集器 |
| DeepeningCache | `attachCache()` | 结果缓存 |
| DeepeningStrategyPlugin | `attachStrategyPlugin()` | 策略插件（默认fixed-depth） |
| DeepeningReportGenerator | `attachReportGenerator()` | 报告生成器 |
| ConvergenceDetector | `attachConvergenceDetector()` | 收敛检测器 |
| QualityScorer | `attachQualityScorer()` | 质量评分器 |

## DeepeningOrchestrator 设计

### 核心职责

DeepeningOrchestrator是深化推理的核心编排器，负责：
- 迭代精化：多轮Agent执行逐步提升输出质量
- 缓存命中：检查缓存中是否存在满足质量阈值的已有结果
- 多Agent路由：通过MultiAgentRouter筛选有效Agent列表
- 收敛检测：策略插件→收敛检测器→收敛阈值三级停止判断
- 思维检索循环：执行后通过ThoughtRetrieverCycle提炼思维
- OODA闭环：集成OODA决策闭环，支持态势感知和自适应决策

### 深化深度级别

| 级别 | 默认迭代次数 | 说明 |
|------|-------------|------|
| `quick` | 1 | 快速深化，仅执行一轮 |
| `standard` | 2 | 标准深化，默认级别 |
| `deep` | 2 | 深度深化 |
| `intensive` | 4 | 密集深化，最大迭代次数 |

### 迭代停止条件（优先级从高到低）

1. **策略插件决策**：`strategyPlugin.decide()`返回`shouldContinue: false`
2. **收敛检测器**：`convergenceDetector.check()`返回`converged: true`
3. **收敛阈值**：最新质量分数 ≥ `convergenceThreshold`（默认0.85）
4. **最大迭代次数**：达到深度级别对应的迭代上限
5. **OODA闭环中断**：威胁等级 > 0.8时触发reactive模式中断

### Agent执行模式

| 模式 | 触发条件 | 说明 |
|------|---------|------|
| **并行** | `parallelAgentExecution: true` | `Promise.allSettled`并行执行，单Agent失败不影响其他 |
| **串行** | 默认 | 逐个执行Agent，每轮执行后检查停止条件 |

## DeepeningCircuitBreaker 设计

### 核心职责

DeepeningCircuitBreaker为深化执行提供熔断器模式容错保护，负责：
- 命名熔断器管理（创建/移除/查询）
- 三态转换：Closed → Open → Half-Open
- 自动恢复：Open状态超时后自动转为Half-Open
- 安全执行包装：`execute()`方法在熔断器保护下运行异步函数

### 状态转换图

```
                    连续失败 ≥ failureThreshold
           ┌──────────────────────────────────────┐
           │                                      ▼
      ┌──────────┐                         ┌──────────┐
      │  Closed  │                         │   Open   │
      │ (正常通行) │                         │ (熔断拒绝) │
      └──────────┘                         └──────────┘
           ▲                                      │
           │                                      │ resetTimeout
           │  连续成功 ≥ successThreshold          │ 超时后自动
           │                                      ▼
           │                               ┌──────────┐
           └─────────────────────────────── │Half-Open │
              试探成功恢复                    │(试探放行) │
                                            └──────────┘
                                              │  │
                              试探失败 → 回到Open  └→ 成功 → 回到Closed
```

### 关键参数

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `maxCircuits` | 100 | 最大熔断器数量，超出时淘汰Closed状态的熔断器 |
| `failureThreshold` | 5 | 触发熔断的连续失败次数 |
| `successThreshold` | 3 | 半开状态恢复到关闭所需的连续成功次数 |
| `resetTimeout` | 30000ms | 打开状态自动恢复的超时时间 |
| `maxHalfOpenCalls` | 1 | 半开状态最大允许的试探调用数 |

## DeepeningValidator 设计

### 核心职责

DeepeningValidator是基于模式的数据验证器，负责：
- 模式注册和管理（最大100个模式）
- 三种验证级别控制边界违规行为
- 验证必填字段、类型、枚举、字符串模式、数值范围、自定义规则
- 正则编译缓存（容量200），含ReDoS危险模式检测
- 验证历史追踪和统计

### 验证级别

| 级别 | 常量 | 数值越界行为 | 额外属性行为 |
|------|------|-------------|-------------|
| `strict` | `VALIDATION_LEVELS.STRICT` | 产生错误 | 产生错误 |
| `moderate` | `VALIDATION_LEVELS.MODERATE` | 产生警告 | 产生警告 |
| `permissive` | `VALIDATION_LEVELS.PERMISSIVE` | 产生警告 | 产生警告 |

### 模式定义结构

```javascript
{
  required: ['name', 'qualityScore'],       // 必填字段
  properties: {
    name: { type: 'string', minLength: 1, maxLength: 200, pattern: '^[a-zA-Z]' },
    qualityScore: { type: 'number', minimum: 0, maximum: 1 },
    status: { type: 'string', enum: ['pending', 'running', 'completed'] },
    custom: { custom: (value) => value > 0 || 'Value must be positive' },
  },
  additionalProperties: false,              // 是否允许额外属性
}
```

### ReDoS防护

正则编译前进行两层安全检查：
1. **长度限制**：模式字符串超过200字符时拒绝编译
2. **危险嵌套检测**：匹配`(?:\([^)]*[+*][^)]*\))[+*{]`模式的危险量词嵌套

## DeepeningLoadBalancer 设计

### 核心职责

DeepeningLoadBalancer为深化管道提供跨实例池的工作负载分配能力，负责：
- 命名实例池管理（创建/移除，最大50个池）
- 四种负载均衡策略选择
- 实例健康状态追踪和活跃连接计数
- 不健康实例自动排除

### 负载均衡策略

| 策略 | 常量 | 说明 |
|------|------|------|
| 轮询 | `STRATEGIES.ROUND_ROBIN` | 按顺序循环选择健康实例 |
| 加权随机 | `STRATEGIES.WEIGHTED` | 按权重比例随机选择，高权重实例被选中概率更大 |
| 最少连接 | `STRATEGIES.LEAST_CONNECTIONS` | 选择当前活跃连接数最少的实例 |
| 随机选择 | `STRATEGIES.RANDOM` | 从健康实例中随机选择一个 |

### 实例生命周期

```
创建池 → 添加实例(设置权重) → select()选中 → 释放连接release()
                                    │
                              markUnhealthy() ← 健康检查失败
                                    │
                              markHealthy() ← 健康检查恢复
                                    │
                           removeInstance() → 移除实例
```

## DeepeningHealthMonitor 设计

### 核心职责

DeepeningHealthMonitor为深化子系统提供健康监测与周期性检查能力，负责：
- 注册命名健康检查函数（最大100个）

### 聚合状态计算规则

| 条件 | 聚合状态 |
|------|---------|
| 所有检查项健康 | `healthy` |
| 部分检查项不健康 | `degraded` |
| 全部检查项不健康 | `unhealthy` |
| 不健康检查项过半 | `unhealthy`（覆盖degraded） |
| 关键检查项（`critical: true`）不健康 | `critical`（最高优先级） |

### 健康评分

```
score = Math.round((healthyCount / totalChecks) * 100)
```

## ConvergenceDetector 设计

### 核心职责

ConvergenceDetector检测迭代深化过程的收敛状态，负责：
- 质量阈值判定：质量分数达到阈值时判定收敛
- 稳定性检测：窗口内质量分数方差低于阈值时判定稳定
- 质量退化检测：质量分数下降超过退化阈值时判定退化
- 维度平衡检测：多维度评分差异过大时发出信号
- 最大迭代次数检查

### 收敛检测流程

```
check(executionId, data)
    │
    ├─ 质量分数 ≥ qualityThreshold? → converged: true, reason: 'quality-threshold-met'
    │
    ├─ 历史长度 ≥ maxIterations? → converged: false, reason: 'max-iterations-reached'
    │
    ├─ 稳定性检测（窗口内方差 < stabilityVariance）
    │   ├─ 平均质量 ≥ qualityThreshold × 0.9 → converged: true, reason: 'stable-and-sufficient'
    │   └─ 平均质量 < qualityThreshold × 0.9 → converged: true, reason: 'plateau-detected'
    │
    ├─ 质量退化检测（下降 > qualityDegradationThreshold）→ converged: true, reason: 'quality-degrading'
    │
    └─ 以上均不满足 → converged: false, reason: 'not-converged'
```

### 信号类型

| 信号 | 常量 | 说明 |
|------|------|------|
| 质量分数 | `SIGNAL_TYPES.QUALITY_SCORE` | 当前质量分数及是否通过阈值 |
| 改进率 | `SIGNAL_TYPES.IMPROVEMENT_RATE` | 质量分数的改进速率 |
| 稳定性 | `SIGNAL_TYPES.STABILITY` | 质量分数的稳定性方差 |

### 默认配置

| 参数 | 默认值 | 说明 |

## RecurrentDeepeningScheduler 设计

### 核心职责

RecurrentDeepeningScheduler驱动Agent反复执行并评估质量，负责：
- 循环调度Agent执行任务
- 每轮通过评估器计算质量分数

execute(agent, task, evaluator)

## KarpathyEnhancer 设计

### 核心职责

KarpathyEnhancer基于Andrej Karpathy编码哲学，增强TDD门禁规则，负责：
- 6维度增强规则注入到现有规则集
- 6维度有效性指标测量和加权综合评分
- 返工区域追踪（最大500个区域）

### 6维度增强规则

| 维度 | 规则ID | 级别 | 说明 |
|------|--------|------|------|
| Diff卫生 | `diff-hygiene` | warn | Diff不得包含无关变更，干净diff比例低于阈值时触发 |
| 返工率 | `rework-rate` | warn | 同一区域修改超过阈值次数表明设计问题 |
| 澄清优先 | `clarification-first` | info | 编码任务应在实现前进行澄清 |
| 孤立代码率 | `orphan-code-rate` | warn | 无调用者的代码表示死代码或缺失集成 |
| 思维质量 | `thinking-quality` | warn | 编码前思维应包含假设、歧义和替代方案 |
| 强标准比例 | `strong-criteria-ratio` | info | 成功标准应以可验证的强标准为主 |

### 加权综合评分

```
overallScore = diffHygiene × 0.20
             + (1 - reworkRate) × 0.15
             + clarificationRate × 0.15
             + (1 - orphanRate) × 0.15
             + thinkingQuality × 0.20
             + strongCriteriaRatio × 0.15
```

### 默认配置

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `diffHygieneThreshold` | 0.8 | Diff卫生阈值 |
| `maxReworkCount` | 3 | 最大返工次数 |
| `minClarificationRate` | 0.5 | 最低澄清率 |
| `maxOrphanRate` | 0.05 | 最大孤立代码率 |
| `minThinkingQuality` | 0.6 | 最低思维质量 |
| `minStrongCriteriaRatio` | 0.7 | 最低强标准比例 |

## TokenAwareDeepening 设计

### 核心职责

TokenAwareDeepening根据剩余Token预算动态调整深化深度和迭代次数，负责：
- 根据Token预算计算最大迭代次数
- 检查当前预算是否足以支付指定Token消耗
- 记录每轮迭代的Token消耗和质量效率
- 根据任务复杂度推荐深化深度级别

### 深度级别推荐逻辑

| 任务复杂度 | 推荐深度级别 |
|-----------|-------------|
| < 0.25 | `quick` |
| 0.25 ~ 0.5 | `standard` |
| 0.5 ~ 0.7 | `deep` |
| > 0.7 | `intensive` |

### 预算检查逻辑

```
calculateMaxIterations(tokenManager, sessionId)
    │
    ├─ 无Token管理器 → maxIterations: 4
    │
    ├─ minBudgetRemaining为比例值(0~1)
    │   └─ 剩余比例 < minBudgetRemaining → maxIterations: 1, reason: 'budget-critical'
    │
    ├─ minBudgetRemaining为绝对值
    │   └─ 剩余 < minBudgetRemaining × 0.1 → maxIterations: 1, reason: 'budget-critical'
    │
    └─ 预算充足 → maxIterations: min(remaining/2000, maxIterationCap), reason: 'budget-ok'
```

### 效率指标

```
efficiency = qualityScore / tokensUsed
```

## 7. ConvergenceDetector — 收敛检测器

| `options.stabilityWindow` | `number` | `3` | 稳定性检测窗口大小 |
| `options.dimensionBalanceThreshold` | `number` | `0.3` | 维度平衡阈值 |
| `options.qualityDegradationThreshold` | `number` | `0.1` | 质量退化阈值 |

## 8. RecurrentDeepeningScheduler — 循环深化调度器

**源文件**：[recurrent-deepening-scheduler.js](../../src/runtime/deepening/recurrent-deepening-scheduler.js)

### 职责概述

循环深化调度器驱动Agent反复执行任务，每轮通过评估器计算质量分数，达到收敛阈值时提前停止。

### 构造函数参数

```javascript
new RecurrentDeepeningScheduler(options)
```

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `options.maxIterations` | `number` | `4` | 最大迭代次数 |
| `options.convergenceThreshold` | `number` | `0.85` | 收敛阈值 |
| `options.minImprovement` | `number` | `0.05` | 最小改进量 |

**静态属性**：`RecurrentDeepeningScheduler.DEFAULT_MAX_ITERATIONS` = `4`、`DEFAULT_CONVERGENCE_THRESHOLD` = `0.85`、`DEFAULT_MIN_IMPROVEMENT` = `0.05`

### 公共方法签名

| 方法 | 签名 | 返回值 | 说明 |
|------|------|--------|------|
| `execute` | `async execute(agent, task, evaluator?)` | `{success, iterations, converged, qualityScore, qualityScores}` | 执行循环深化调度 |
| `getStats` | `getStats()` | `{maxIterations, convergenceThreshold, minImprovement, activeExecutions}` | 获取统计信息 |

### 事件列表

| 事件名 | 载荷 | 触发时机 |
|--------|------|----------|
| `iteration-complete` | `{iteration, qualityScore}` | 每轮迭代完成 |
| `evaluator-error` | `{error, iteration}` | 评估器出错 |
| `iteration-error` | `{error, iteration}` | 迭代执行出错 |

### 使用示例

```javascript
const RecurrentDeepeningScheduler = require('./src/runtime/deepening/recurrent-deepening-scheduler');

const scheduler = new RecurrentDeepeningScheduler({
  maxIterations: 6,
  convergenceThreshold: 0.9,
});

const agent = {
  execute: async (task) => ({ output: 'refined result', score: 0.85 + Math.random() * 0.15 }),
};

const evaluator = (result, task) => result.score;

const result = await scheduler.execute(agent, { id: 'task-1' }, evaluator);
console.log(`Converged: ${result.converged}, Iterations: ${result.iterations}, Final: ${result.qualityScore}`);
```

## 10. TokenAwareDeepening — Token预算感知深化

**源文件**：[token-aware-deepening.js](../../src/runtime/deepening/token-aware-deepening.js)

### 职责概述

Token预算感知深化策略，根据剩余Token预算动态调整深化深度和迭代次数，跟踪每轮迭代的Token消耗和质量效率。

### 构造函数参数

```javascript
new TokenAwareDeepening(options)
```

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `options.minBudgetRemaining` | `number` | `1000` | 最低剩余Token数（绝对值或0~1比例） |
| `options.maxIterationCap` | `number` | `10` | 最大迭代次数上限 |

**静态属性**：`TokenAwareDeepening.DEFAULT_BUDGET_RATIO` = `0.7`、`DEFAULT_MIN_BUDGET_REMAINING` = `1000`

### 公共方法签名

| 方法 | 签名 | 返回值 | 说明 |
|------|------|--------|------|
| `calculateMaxIterations` | `calculateMaxIterations(tokenManager, sessionId)` | `{maxIterations, reason}` | 根据Token预算计算最大迭代次数 |
| `canAffordIteration` | `canAffordIteration(tokenManager, sessionId, tokenCost)` | `{canAfford, reason?}` | 检查预算是否足以支付指定Token消耗 |
| `recordIterationCost` | `recordIterationCost(sessionId, iteration, tokensUsed, qualityScore)` | `{sessionId, tokensUsed, efficiency}` | 记录单轮迭代的Token消耗和质量效率 |
| `getEfficiencyReport` | `getEfficiencyReport(sessionId)` | `{totalRecords, totalTokensUsed, averageQuality}` | 获取指定会话的Token效率报告 |
| `recommendDepth` | `recommendDepth(tokenManager, sessionId, complexity)` | `{recommendedLevel, maxIterations}` | 根据预算和复杂度推荐深度级别 |
| `getStats` | `getStats()` | `{totalRecords, healthy, shutDown}` | 获取统计信息 |

### 事件列表

| 事件名 | 载荷 | 触发时机 |
|--------|------|----------|
| `iteration-cost-recorded` | `{sessionId, tokensUsed, efficiency}` | 记录迭代消耗 |

### 使用示例

```javascript
const TokenAwareDeepening = require('./src/runtime/deepening/token-aware-deepening');

const tad = new TokenAwareDeepening({
  minBudgetRemaining: 0.15,  // 15%预算作为最低剩余
  maxIterationCap: 8,
});

const tokenManager = {
  getUsage: (sessionId) => ({ remaining: 50000, budget: 100000 }),
};

const calc = tad.calculateMaxIterations(tokenManager, 'session-1');
console.log(`Max iterations: ${calc.maxIterations}, Reason: ${calc.reason}`);

const afford = tad.canAffordIteration(tokenManager, 'session-1', 5000);
console.log(`Can afford: ${afford.canAfford}`);

tad.recordIterationCost('session-1', 1, 3000, 0.85);
tad.recordIterationCost('session-1', 2, 2500, 0.92);

const report = tad.getEfficiencyReport('session-1');
console.log(`Total tokens: ${report.totalTokensUsed}, Avg quality: ${report.averageQuality.toFixed(2)}`);

const depth = tad.recommendDepth(tokenManager, 'session-1', 0.6);
console.log(`Recommended: ${depth.recommendedLevel}, Max iterations: ${depth.maxIterations}`);
```
