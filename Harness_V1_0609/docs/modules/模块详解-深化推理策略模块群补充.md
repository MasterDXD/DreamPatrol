## DeepeningBase — 深化推理基类

所有深化模块的公共基类，提供：

- **EventEmitter** 事件发射能力
- **ShutdownMixin** 优雅关闭（`isHealthy()`、`guardShutdown()`、`shutdown()`、`_onShutdown()`）
- **依赖注入** 通过 `attach*()` 方法注入外部依赖（如SqliteStore、CausalDataBus、SkillRouter等，共27个可注入依赖）
- **统一统计** `getStats()` 返回 `{healthy, shutDown}`

```javascript
const DeepeningBase = require('./deepening-base');

class MyModule extends DeepeningBase {
  constructor(options) {
    super(options); // this._options = options || {}
  }
  _onShutdown() { /* 清理资源 */ }
}
```

## convergence-detector.js — 收敛检测器

### 职责概述

检测深化推理过程的收敛状态。通过质量分数阈值、稳定性方差、改进率、维度平衡、质量退化等多维信号判断迭代是否应该停止或调整深度。每个执行ID维护独立的历史记录。

### 构造函数参数

```javascript
new ConvergenceDetector(options?)
```

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `options.qualityThreshold` | `number` | `0.85` | 质量分数收敛阈值 |
| `options.maxIterations` | `number` | `10` | 最大迭代次数 |
| `options.minImprovementRate` | `number` | `0.01` | 最小改进率 |
| `options.stabilityVariance` | `number` | `0.01` | 稳定性方差阈值 |
| `options.stabilityWindow` | `number` | `3` | 稳定性检测窗口大小 |
| `options.coverageThreshold` | `number` | `0.8` | 覆盖率阈值 |
| `options.dimensionBalanceThreshold` | `number` | `0.3` | 维度平衡阈值（最大维度差） |
| `options.qualityDegradationThreshold` | `number` | `0.1` | 质量退化阈值 |
| `options.maxHistoryExecutions` | `number` | `100` | 最大历史执行数 |

### 公共方法

| 方法 | 签名 | 说明 |
|------|------|------|
| `check(executionId, data)` | `(string, {qualityScore?, dimensions?}) → {converged, reason, signals, recommendation}` | 检查收敛状态 |
| `reset(executionId)` | `(string) → boolean` | 重置指定执行的历史 |
| `getStats()` | `() → {activeExecutions, config, healthy, shutDown}` | 获取统计信息 |

**`check()` 返回值说明**

| reason | converged | recommendation | 含义 |
|--------|-----------|----------------|------|
| `quality-threshold-met` | `true` | `sufficient` | 质量分数达到阈值 |
| `max-iterations-reached` | `false` | `increase-depth-or-abort` | 达到最大迭代次数 |
| `stable-and-sufficient` | `true` | `sufficient` | 稳定且质量接近阈值（≥90%） |
| `plateau-detected` | `true` | `increase-depth` | 稳定但质量不足，需增加深度 |
| `quality-degrading` | `true` | `decrease-depth` | 质量退化，需减少深度 |
| `not-converged` | `false` | `increase-depth` | 未收敛，继续迭代 |
| `missing-data` | `false` | — | 缺少输入数据 |

### 事件列表

| 事件名 | 载荷 | 说明 |
|--------|------|------|
| `convergence-checked` | `{signals: {qualityScore?, dimensionBalance?}}` | 收敛检查完成 |

### 使用示例

```javascript
const ConvergenceDetector = require('./convergence-detector');

const detector = new ConvergenceDetector({
  qualityThreshold: 0.9,
  maxIterations: 15,
  stabilityWindow: 5,
});

detector.on('convergence-checked', ({signals}) => {
  console.log('收敛检查:', signals);
});

const result = detector.check('exec-001', {
  qualityScore: 0.87,
  dimensions: { correctness: 0.9, completeness: 0.85, clarity: 0.88 },
});
// { converged: false, reason: 'not-converged', recommendation: 'increase-depth', signals: {...} }

const result2 = detector.check('exec-001', {
  qualityScore: 0.91,
  dimensions: { correctness: 0.92, completeness: 0.90, clarity: 0.91 },
});
// { converged: true, reason: 'quality-threshold-met', recommendation: 'sufficient' }
```

## ooda-loop.js — OODA循环

### 职责概述

实现OODA（Observe-Orient-Decide-Act）决策循环，用于深化推理过程中的自适应决策。支持三种决策模式：反应式（Reactive）、审慎式（Deliberate）、创造式（Creative）。内置偏见检测和自动循环能力。

### 构造函数参数

```javascript
new OodaLoop(options?)
```

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `options.maxHistorySize` | `number` | `200` | 决策历史最大条目数 |
| `options.autoLoop` | `boolean` | `false` | 是否自动触发下一轮循环 |
| `options.threatThreshold` | `number` | `0.7` | 威胁级别阈值 |
| `options.opportunityThreshold` | `number` | `0.6` | 机会级别阈值 |
| `options.observationWindow` | `number` | `5` | 偏见检测观察窗口 |

### 公共方法

| 方法 | 签名 | 说明 |
|------|------|------|
| `observe(taskContext, agentState, environmentSignals)` | `(*, *, Array\|Object) → {timestamp, signals, confidence}` | 观察：收集信号 |
| `orient(observation)` | `(Object) → {threatLevel, opportunityLevel, biasDetected, recommendedFocus}` | 判断：分析态势 |
| `decide(orientation)` | `(Object) → {mode, action, confidence, reasoning}` | 决策：选择行动模式 |
| `act(decision, context?)` | `(Object, {cycleId?}?) → {success, feedback, cycleId, reason?}` | 行动：执行决策 |
| `execute(context?)` | `({taskContext?, agentState?, environmentSignals?}) → OodaCycle` | 执行完整OODA循环 |
| `reset()` | `() → true` | 重置历史和计数器 |
| `getStats()` | `() → {cycleCount, historySize, config, healthy, shutDown}` | 获取统计信息 |

**决策模式**

| 模式 | 触发条件 | 行动 |
|------|----------|------|
| `reactive` | 威胁级别 > 阈值 | `respond-immediately` |
| `creative` | 机会级别 > 阈值 | `explore-opportunity` |
| `deliberate` | 平衡态势或检测到偏见 | `analyze-further` / `review-bias` |

**`recommendedFocus` 取值**

| 值 | 触发条件 |
|----|----------|
| `threat-mitigation` | 威胁级别 > 阈值 |
| `opportunity-exploitation` | 机会级别 > 阈值 |
| `situational-awareness` | 平衡态势 |
| `gather-more-data` | 无信号输入 |

### 事件列表

| 事件名 | 载荷 | 说明 |
|--------|------|------|
| `ooda-observed` | `{signalCount, confidence}` | 观察完成 |
| `ooda-oriented` | `{threatLevel, opportunityLevel, biasDetected, recommendedFocus}` | 判断完成 |
| `ooda-decided` | `{mode, action, confidence, reasoning}` | 决策完成 |
| `ooda-acted` | `{success, feedback?, cycleId?, reason?}` | 行动完成 |
| `ooda-cycle-completed` | `OodaCycle` | 完整循环完成 |
| `ooda-auto-loop-triggered` | `{nextCycle}` | 自动循环触发 |
| `ooda-reset` | 无 | 重置完成 |

### 使用示例

```javascript
const OodaLoop = require('./ooda-loop');

const ooda = new OodaLoop({
  threatThreshold: 0.7,
  opportunityThreshold: 0.6,
  autoLoop: false,
});

ooda.on('ooda-cycle-completed', (cycle) => {
  console.log('循环完成:', cycle.decision.mode);
});

const cycle = ooda.execute({
  taskContext: { complexity: 'high' },
  agentState: { load: 0.8 },
  environmentSignals: [
    { type: 'quality', data: { improvement: true, opportunityLevel: 0.7 } },
  ],
});
// cycle.decision.mode === 'creative'
// cycle.decision.action === 'explore-opportunity'

// 分步执行
const observation = ooda.observe(taskCtx, agentState, envSignals);
const orientation = ooda.orient(observation);
const decision = ooda.decide(orientation);
const result = ooda.act(decision, { cycleId: 'custom-cycle' });
```

## recurrent-deepening-scheduler.js — 循环深化调度器

### 职责概述

循环执行深化推理任务，通过迭代精化逐步提升质量分数。支持收敛阈值检测和自定义评估器。每次迭代将迭代序号注入任务的 `_ar` 字段。

### 构造函数参数

```javascript
new RecurrentDeepeningScheduler(options?)
```

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `options.maxIterations` | `number` | `4` | 最大迭代次数 |
| `options.convergenceThreshold` | `number` | `0.85` | 收敛质量阈值 |
| `options.minImprovement` | `number` | `0.05` | 最小改进量 |

### 公共方法

| 方法 | 签名 | 说明 |
|------|------|------|
| `execute(agent, task, evaluator?)` | `(Object, Object, function?) → Promise<{success, iterations, converged, qualityScore, qualityScores}>` | 执行循环深化 |
| `getStats()` | `() → {maxIterations, convergenceThreshold, minImprovement, activeExecutions, healthy, shutDown}` | 获取统计信息 |

**`execute()` 参数说明**

| 参数 | 类型 | 说明 |
|------|------|------|
| `agent` | `Object` | 必须实现 `execute(task)` 方法 |
| `task` | `Object` | 任务对象，迭代时自动注入 `_ar.iteration` |
| `evaluator` | `function(result, task) → number\|{qualityScore, score}` | 可选评估器，返回质量分数 |

**`execute()` 返回值说明**

| 字段 | 类型 | 说明 |
|------|------|------|
| `success` | `boolean` | 是否成功完成 |
| `iterations` | `number` | 实际迭代次数 |
| `converged` | `boolean` | 是否收敛 |
| `qualityScore` | `number` | 最终质量分数 |
| `qualityScores` | `number[]` | 每轮迭代的质量分数 |

### 事件列表

| 事件名 | 载荷 | 说明 |
|--------|------|------|
| `iteration-complete` | `{iteration, qualityScore}` | 单次迭代完成 |
| `evaluator-error` | `{error, iteration}` | 评估器执行错误 |
| `iteration-error` | `{error, iteration}` | 迭代执行错误 |

### 使用示例

```javascript
const RecurrentDeepeningScheduler = require('./recurrent-deepening-scheduler');

const scheduler = new RecurrentDeepeningScheduler({
  maxIterations: 6,
  convergenceThreshold: 0.9,
});

scheduler.on('iteration-complete', ({iteration, qualityScore}) => {
  console.log(`迭代 ${iteration}: 质量分数 ${qualityScore.toFixed(2)}`);
});

const result = await scheduler.execute(
  { execute: async (task) => processTask(task) },
  { prompt: '优化这段代码' },
  (result, task) => computeQualityScore(result),
);
// { success: true, iterations: 4, converged: true, qualityScore: 0.92, qualityScores: [0.6, 0.75, 0.85, 0.92] }
```

## deepening-cache.js — 深化结果缓存

### 职责概述

缓存深化推理的结果，避免重复计算。基于任务对象的JSON序列化生成缓存键，支持质量分数优先级（仅缓存更高质量的结果）、按模式失效、命中率统计。

### 构造函数参数

```javascript
new DeepeningCache(options?)
```

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `options.maxSize` | `number` | `Infinity` | 最大缓存条目数 |

### 公共方法

| 方法 | 签名 | 说明 |
|------|------|------|
| `store(task, result, metadata?)` | `(*, *, {qualityScore?, agentId?}?) → boolean` | 存储结果（低质量不覆盖高质量） |
| `retrieve(task)` | `(*) → {result, qualityScore}\|null` | 检索缓存结果 |
| `invalidate(task)` | `(*) → boolean` | 失效指定任务缓存 |
| `invalidateByPattern(pattern)` | `({agentId?}) → number` | 按模式批量失效 |
| `getEntries()` | `() → Array` | 获取所有条目（按质量降序） |
| `clear()` | `() → void` | 清空缓存 |
| `getStats()` | `() → {hits, misses, hitRate, size, evictions, healthy, shutDown}` | 获取统计信息 |

### 事件列表

无自定义事件（继承DeepeningBase的shutdown事件）。

### 使用示例

```javascript
const DeepeningCache = require('./deepening-cache');

const cache = new DeepeningCache({ maxSize: 500 });

cache.store(
  { prompt: '优化代码', depth: 3 },
  { code: 'optimized...', score: 0.9 },
  { qualityScore: 0.9, agentId: 'analyst-1' },
);

const cached = cache.retrieve({ prompt: '优化代码', depth: 3 });
// { result: { code: 'optimized...', score: 0.9 }, qualityScore: 0.9 }

// 低质量结果不会覆盖高质量
cache.store(
  { prompt: '优化代码', depth: 3 },
  { code: 'worse...', score: 0.6 },
  { qualityScore: 0.6 },
);
// 仍返回0.9的结果

cache.invalidateByPattern({ agentId: 'analyst-1' }); // 按agentId失效
console.log(cache.getStats().hitRate); // 命中率
```

## deepening-visualizer.js — 深化可视化

### 职责概述

从事件存储中提取数据，生成可视化所需的结构化数据：执行图（节点+边）、收敛折线图、执行时间线、系统健康仪表盘。内部模块，无外部消费者。

### 构造函数参数

```javascript
new DeepeningVisualizer(eventStore)
```

| 参数 | 类型 | 说明 |
|------|------|------|
| `eventStore` | `Object` | 事件存储对象，需实现 `getEventsByExecution(id)` 或 `query(filter)` 方法 |

### 公共方法

| 方法 | 签名 | 说明 |
|------|------|------|
| `generateExecutionGraph(executionId)` | `(string) → {nodes, edges}` | 生成执行图（节点=source/target，边=action） |
| `generateConvergenceChart(executionId)` | `(string) → {type, data}` | 生成收敛折线图数据 |
| `generateExecutionTimeline(executionId)` | `(string) → Array` | 生成执行时间线（最多50条） |
| `generateSystemHealthDashboard()` | `() → {stats, recentEvents}` | 生成系统健康仪表盘数据 |
| `getStats()` | `() → {hasEventStore, healthy, shutDown}` | 获取统计信息 |

**数据结构说明**

`generateExecutionGraph` 返回：
```javascript
{
  nodes: [{id, label, type}],  // type: 'agent' | 'target'
  edges: [{source, target, label}],
}
```

`generateConvergenceChart` 返回：
```javascript
{
  type: 'line',
  data: {
    labels: ['iter-1', 'iter-2', ...],
    datasets: [{label: 'Quality Score', data: [0.6, 0.75, ...], borderColor: '#4CAF50', fill: false}],
  },
}
```

`generateExecutionTimeline` 返回：
```javascript
[
  {timestamp, type, source, action, data},
  ...
]
```

### 事件列表

无自定义事件。

### 使用示例

```javascript
const DeepeningVisualizer = require('./deepening-visualizer');

const viz = new DeepeningVisualizer(eventStore);

const graph = viz.generateExecutionGraph('exec-001');
// { nodes: [{id: 'agent-1', label: 'agent-1', type: 'agent'}], edges: [...] }

const chart = viz.generateConvergenceChart('exec-001');
// { type: 'line', data: { labels: ['iter-1', 'iter-2'], datasets: [...] } }

const timeline = viz.generateExecutionTimeline('exec-001');
// [{timestamp: 1717000000000, type: 'quality-score', source: 'agent-1', action: '', data: {...}}]

const dashboard = viz.generateSystemHealthDashboard();
// { stats: {...}, recentEvents: [...] }
```

## deepening-state-machine.js — 深化状态机

### 职责概述

管理深化推理执行的状态转换。定义了从 `idle` 到 `completed` 的完整生命周期，包含12个状态和严格的状态转换规则。支持暂停/恢复、取消、失败处理、状态历史记录。

### 构造函数参数

```javascript
new DeepeningStateMachine()
```

无配置参数。内部常量：`_maxExecutions = 500`，`_maxHistoryPerExecution = 200`。

### 状态转换图

```
idle ──→ initializing ──→ cache-check ──→ depth-assessment ──→ agent-routing
  ↑           │                │                  │                  │
  │           ↓                ↓                  ↓                  ↓
cancelled  cancelled       cancelled          cancelled          cancelled
  │           │                │                  │                  │
  │           ↓                ↓                  ↓                  ↓
  │         failed           failed             failed             failed
  │                                                  │
  │                                                  ↓
  │                              context-enrichment ──→ executing ←──┐
  │                                      │              │  │        │
  │                                      ↓              ↓  │        │
  │                                   cancelled   convergence-│     │
  │                                                  check ──→    │
  │                                                   │  │        │
  │                                                   ↓  │        │
  │                                          output-fusion←┘       │
  │                                               │                │
  │                                               ↓                │
  │                                           reporting            │
  │                                               │                │
  ↓                                               ↓                │
idle ←── completed                             cancelled/failed     │
  ↑                                                                  │
  └── paused ───────────────────────────────────────────────────────┘
```

### 公共方法

| 方法 | 签名 | 说明 |
|------|------|------|
| `createExecution(executionId)` | `(string) → {executionId, currentState}` | 创建执行（初始状态idle） |
| `transition(executionId, state)` | `(string, string) → {ok, error?}` | 状态转换 |
| `canTransition(executionId, state)` | `(string, string) → boolean` | 检查是否允许转换 |
| `getState(executionId)` | `(string) → string\|null` | 获取当前状态 |
| `pause(executionId)` | `(string) → {ok}` | 暂停执行 |
| `resume(executionId)` | `(string) → {ok, error?}` | 恢复执行（回到暂停前状态） |
| `cancel(executionId)` | `(string) → {ok, error?}` | 取消执行 |
| `fail(executionId, reason?)` | `(string, string?) → {ok}` | 标记失败 |
| `complete(executionId, result?)` | `(string, *) → {ok}` | 标记完成 |
| `reset(executionId)` | `(string) → {ok}` | 重置为idle |
| `getHistory(executionId)` | `(string) → Array<{to, from?, timestamp}>` | 获取状态历史 |
| `getStats()` | `() → {totalExecutions, stateCounts, healthy, shutDown}` | 获取统计信息 |

### 事件列表

| 事件名 | 载荷 | 说明 |
|--------|------|------|
| `state-transition` | `{executionId, from, to}` | 状态转换发生 |

### 使用示例

```javascript
const DeepeningStateMachine = require('./deepening-state-machine');

const sm = new DeepeningStateMachine();

sm.on('state-transition', ({executionId, from, to}) => {
  console.log(`${executionId}: ${from} → ${to}`);
});

sm.createExecution('exec-001');
// { executionId: 'exec-001', currentState: 'idle' }

sm.transition('exec-001', 'initializing');
sm.transition('exec-001', 'cache-check');
sm.transition('exec-001', 'depth-assessment');
sm.transition('exec-001', 'agent-routing');

sm.canTransition('exec-001', 'executing'); // false（需先经过context-enrichment）

sm.pause('exec-001');
sm.getState('exec-001'); // 'paused'

sm.resume('exec-001'); // 回到暂停前状态

sm.complete('exec-001', { qualityScore: 0.95 });
sm.getHistory('exec-001'); // [{to: 'idle', timestamp: ...}, ...]
```

## deepening-backpressure-manager.js — 背压管理器

### 职责概述

管理深化推理管道中的背压，防止下游处理速度跟不上上游生产速度导致内存溢出。基于高低水位线（high/low watermark）机制，支持多流管理、自动暂停/恢复、溢出丢弃。

### 构造函数参数

```javascript
new DeepeningBackpressureManager(options?)
```

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `options.maxStreams` | `number` | `50` | 最大流数量 |
| `options.defaultHighWatermark` | `number` | `100` | 默认高水位线 |
| `options.defaultLowWatermark` | `number` | `20` | 默认低水位线 |

### 公共方法

| 方法 | 签名 | 说明 |
|------|------|------|
| `registerStream(name, options?)` | `(string, {highWatermark?, lowWatermark?, maxBufferSize?}) → boolean` | 注册流 |
| `push(name, amount?)` | `(string, number?) → {accepted, bufferSize, reason?}` | 推入数据（触发背压） |
| `ack(name, amount?)` | `(string, number?) → {bufferSize}` | 确认处理（释放背压） |
| `getPressure(name)` | `(string) → {level, bufferSize}` | 获取压力级别 |
| `isPaused(name)` | `(string) → boolean` | 检查流是否暂停 |
| `forcePause(name)` | `(string) → boolean` | 强制暂停流 |
| `forceResume(name)` | `(string) → boolean` | 强制恢复流 |
| `resetStream(name)` | `(string) → true` | 重置流状态 |
| `unregisterStream(name)` | `(string) → boolean` | 注销流 |
| `getStreamNames()` | `() → string[]` | 获取所有流名称 |
| `getStats()` | `() → {totalStreams, streams, healthy, shutDown}` | 获取统计信息 |

**压力级别**

| 级别 | 条件 |
|------|------|
| `low` | bufferSize < lowWatermark |
| `medium` | bufferSize >= lowWatermark |
| `high` | bufferSize >= lowWatermark + (highWatermark - lowWatermark) / 2 |
| `critical` | bufferSize >= highWatermark |

### 事件列表

| 事件名 | 载荷 | 说明 |
|--------|------|------|
| `streamRegistered` | `{name, highWatermark}` | 流注册完成 |
| `pressureChanged` | `{from, to}` | 压力级别变化 |
| `paused` | `{name}` | 流被暂停 |
| `dropped` | `{count}` | 数据被丢弃 |
| `streamReset` | `{name}` | 流被重置 |
| `streamUnregistered` | `{name}` | 流被注销 |

### 使用示例

```javascript
const DeepeningBackpressureManager = require('./deepening-backpressure-manager');

const bpm = new DeepeningBackpressureManager({
  maxStreams: 20,
  defaultHighWatermark: 100,
  defaultLowWatermark: 20,
});

bpm.on('paused', ({name}) => console.log(`流 ${name} 已暂停`));
bpm.on('pressureChanged', ({from, to}) => console.log(`压力: ${from} → ${to}`));

bpm.registerStream('deepening-pipe', {
  highWatermark: 50,
  lowWatermark: 10,
  maxBufferSize: 200,
});

const r1 = bpm.push('deepening-pipe', 1); // {accepted: true, bufferSize: 1}
bpm.push('deepening-pipe', 50);           // 触发高水位线
bpm.isPaused('deepening-pipe');            // true

bpm.ack('deepening-pipe', 45);            // 释放背压
bpm.getPressure('deepening-pipe');         // {level: 'low', bufferSize: 6}
```

## deepening-event-replay.js — 事件回放器

### 职责概述

记录和回放深化推理过程中的事件，用于调试和时间旅行分析。基于RingBuffer存储事件，支持事件过滤、同步/异步回放、自定义过滤器注册。

### 构造函数参数

```javascript
new DeepeningEventReplay(options?)
```

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `options.maxSize` | `number` | `10000` | 最大事件存储数量 |
| `options.speed` | `number` | `1` | 异步回放速度（毫秒间隔） |

### 公共方法

| 方法 | 签名 | 说明 |
|------|------|------|
| `record(eventType, data?, metadata?)` | `(string, *, *) → string` | 记录事件，返回事件ID |
| `getEvents(filters?)` | `({type?, since?, until?, limit?}?) → Array` | 获取事件列表 |
| `getEvent(id)` | `(string) → Object\|null` | 按ID获取事件 |
| `getEventCount(type?)` | `(string?) → number` | 获取事件数量 |
| `getEventTypes()` | `() → string[]` | 获取所有事件类型 |
| `registerFilter(name, filterFn)` | `(string, function) → true` | 注册事件过滤器 |
| `unregisterFilter(name)` | `(string) → boolean` | 注销过滤器 |
| `replay(options?)` | `({type?, filters?, callback?}?) → number` | 同步回放事件 |
| `startReplay(options?)` | `({type?, filters?, callback?, speed?}?) → Promise<number>` | 异步回放事件 |
| `stopReplay()` | `() → true` | 停止异步回放 |
| `isPlaying()` | `() → boolean` | 是否正在回放 |
| `clear()` | `() → true` | 清空所有事件 |
| `getStats()` | `() → {totalEvents, maxSize, isPlaying, filtersRegistered, eventTypes, typeCounts, healthy, shutDown}` | 获取统计信息 |

**事件对象结构**

```javascript
{
  id: 'replay-1',        // 唯一ID（counterId生成）
  type: 'quality-score', // 事件类型
  data: {...},           // 事件数据
  metadata: {...},       // 事件元数据
  timestamp: 1717000000, // 时间戳
}
```

### 事件列表

| 事件名 | 载荷 | 说明 |
|--------|------|------|
| `recorded` | `Event` | 事件被记录 |
| `replay` | `Event` | 事件被回放 |
| `replayComplete` | `{count}` | 回放完成 |
| `cleared` | 无 | 事件被清空 |

### 使用示例

```javascript
const DeepeningEventReplay = require('./deepening-event-replay');

const replay = new DeepeningEventReplay({ maxSize: 5000, speed: 100 });

replay.on('recorded', (event) => {
  console.log('事件记录:', event.type, event.id);
});

// 记录事件
const id1 = replay.record('quality-score', { score: 0.75 }, { agentId: 'agent-1' });
const id2 = replay.record('quality-score', { score: 0.88 }, { agentId: 'agent-1' });
replay.record('convergence-check', { converged: false });

// 查询事件
const qualityEvents = replay.getEvents({ type: 'quality-score' });
console.log('质量事件数:', qualityEvents.length);

// 注册过滤器
replay.registerFilter('high-quality', (e) => e.data.score >= 0.8);

// 同步回放
const count = replay.replay({
  type: 'quality-score',
  callback: (event) => console.log('回放:', event.data.score),
});

// 异步回放（带延迟）
await replay.startReplay({
  speed: 200,
  callback: (event) => updateUI(event),
});

// 统计
console.log(replay.getStats());
// { totalEvents: 3, maxSize: 5000, isPlaying: false, filtersRegistered: 1, eventTypes: 2, typeCounts: {'quality-score': 2, 'convergence-check': 1} }
```

## 模块协作关系

```
                    DeepeningOrchestrator
                          │
            ┌─────────────┼─────────────┐
            │             │             │
            ▼             ▼             ▼
   ConvergenceDetector  OodaLoop   RecurrentDeepening
      (收敛判断)      (决策循环)    Scheduler (迭代调度)
            │             │             │
            │             │             │
            ▼             ▼             ▼
   DeepeningStateMachine ─────────────────────────
      (状态管理)                                     │
            │                                       │
            ▼                                       ▼
   DeepeningBackpressureManager ── DeepeningCache
      (背压控制)                      (结果缓存)
            │
            ▼
   DeepeningEventReplay ── DeepeningVisualizer
      (事件回放)              (可视化)
```

**典型协作流程**：

1. `RecurrentDeepeningScheduler` 驱动迭代执行
2. 每轮迭代后 `ConvergenceDetector` 检查收敛状态
3. `OodaLoop` 根据态势决定下一步策略
4. `DeepeningStateMachine` 管理执行状态转换
5. `DeepeningBackpressureManager` 控制数据流背压
6. `DeepeningCache` 缓存中间结果避免重复计算
7. `DeepeningEventReplay` 记录全链路事件
8. `DeepeningVisualizer` 从事件存储生成可视化数据
