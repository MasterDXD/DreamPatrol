# 模块详解 — 基础设施子系统

> **文件路径**：`src/runtime/infrastructure/`
> **组件数量**：27个
> **依赖关系**：被所有上层子系统（Agent、协作、思维、技能、工作流等）依赖
> **核心定位**：为Harness多Agent框架提供底层运行时基础设施，涵盖连接池、事件总线、持久化存储、通信协议、并发控制、健康检查、浏览器自动化、代码图谱、知识库、RL训练等能力

---

## 一、概述

基础设施子系统是Harness Engineering多Agent框架的基石层，位于`src/runtime/infrastructure/`目录下，包含27个核心组件。该子系统遵循"分层分责"原则，为上层Agent、协作、思维、技能、工作流等子系统提供统一的基础能力支撑。

### 设计原则

1. **withShutdown混入模式**：所有组件均通过`withShutdown`混入实现优雅关闭，确保资源正确释放
2. **EventEmitter事件驱动**：组件间通过事件总线解耦通信，支持发布/订阅模式
3. **防御性编码**：所有外部输入均经过校验，关键操作使用`safeExecute`/`safeCall`包装
4. **容量限制**：所有集合类使用`BoundedMap`/`BoundedArray`，防止内存泄漏
5. **SSRF防护**：网络相关组件（MCPClient、KnowledgeBasePipeline）内置DNS重绑定检测和私有IP阻断

### 组件分类

| 分类 | 组件 | 说明 |
|------|------|------|
| 核心基础设施 | SharedInfrastructure、EventBus、EventRegistrar、ModuleInitializer、InstanceBuilder | 框架启动与运行核心 |
| 存储与持久化 | SqliteStore、ConversationContextStore、SignalPersistence、AutoVersionTracker | 数据持久化与版本追踪 |
| 通信与协议 | MCPClient、CDPClient、BrowserUseAdapter、PlatformCoordinator | 跨进程与跨平台通信 |
| 并发与可靠性 | ConcurrencyController、RetryEngine、PriorityQueue、HealthChecker、HealthRegistrar | 并发控制与故障恢复 |
| 代码与知识管理 | CodeGraph、KnowledgeBasePipeline、GitWorktreeManager | 代码分析与知识管理 |
| AI与训练 | RLTrainingPipeline、AiDeveloperAnalytics、OpportunityDiscoveryPipeline | 强化学习与分析 |
| 服务与虚拟化 | ServiceFS、PluginManager | 服务抽象与插件扩展 |
| 会话与恢复 | SessionResumptionProtocol | 会话状态续接 |

## 三、核心组件详解

### 3.1 SharedInfrastructure

**文件**：`shared-infrastructure.js`

#### 职责与定位

SharedInfrastructure包含4个核心类，提供框架级别的共享资源管理能力：连接池管理、负载均衡、服务注册与发现、特性标志管理。这些类是框架运行的基础设施，被ModuleInitializer在启动时统一初始化。

#### 关键API

| 类名 | 方法 | 说明 | 返回值 |
|------|------|------|--------|
| SharedConnectionPool | `acquire(key)` | 获取指定键的连接 | `Promise<Object>` |
| SharedConnectionPool | `release(key, conn)` | 释放连接回池 | `void` |
| SharedConnectionPool | `getStats()` | 获取连接池统计 | `Object` |
| SharedLoadBalancer | `next(key)` | 获取下一个目标（轮询策略） | `Object\|null` |
| SharedLoadBalancer | `addTarget(key, target)` | 添加负载均衡目标 | `void` |
| SharedLoadBalancer | `removeTarget(key, targetId)` | 移除目标 | `boolean` |
| SharedServiceRegistry | `register(name, service)` | 注册服务 | `void` |
| SharedServiceRegistry | `lookup(name)` | 查找服务 | `Object\|null` |
| SharedServiceRegistry | `unregister(name)` | 注销服务 | `boolean` |
| SharedFeatureFlags | `isEnabled(flag)` | 检查特性标志是否启用 | `boolean` |
| SharedFeatureFlags | `enable(flag)` | 启用特性标志 | `void` |
| SharedFeatureFlags | `disable(flag)` | 禁用特性标志 | `void` |

#### 事件

| 事件名 | 触发时机 | 数据 |
|--------|---------|------|
| `connection-acquired` | 连接获取成功 | `{key}` |
| `connection-released` | 连接释放 | `{key}` |
| `target-added` | 负载均衡目标添加 | `{key, targetId}` |
| `target-removed` | 目标移除 | `{key, targetId}` |
| `service-registered` | 服务注册 | `{name}` |
| `service-unregistered` | 服务注销 | `{name}` |
| `flag-enabled` | 特性标志启用 | `{flag}` |
| `flag-disabled` | 特性标志禁用 | `{flag}` |

#### 配置项

| 配置 | 默认值 | 说明 |
|------|--------|------|
| `maxPoolSize` | 10 | 连接池最大连接数 |
| `poolIdleTimeoutMs` | 30000 | 连接空闲超时 |
| `lbBlockedHosts` | `['127.0.0.1', '0.0.0.0', ...]` | 负载均衡阻断主机列表（SSRF防护） |
| `registryMaxServices` | 100 | 服务注册表最大服务数 |
| `flagHistorySize` | 50 | 特性标志变更历史大小 |

#### 使用示例

```javascript
const { SharedConnectionPool, SharedLoadBalancer, SharedServiceRegistry, SharedFeatureFlags } = require('./shared-infrastructure');

// 连接池
const pool = new SharedConnectionPool({ maxPoolSize: 20 });
const conn = await pool.acquire('database');
try { /* 使用连接 */ } finally { pool.release('database', conn); }

// 负载均衡（内置SSRF防护）
const lb = new SharedLoadBalancer();
lb.addTarget('api', { id: 'server-1', url: 'https://api1.example.com' });
lb.addTarget('api', { id: 'server-2', url: 'https://api2.example.com' });
const target = lb.next('api'); // 轮询选择

// 服务注册
const registry = new SharedServiceRegistry();
registry.register('cache', { get: () => {}, set: () => {} });
const cache = registry.lookup('cache');

// 特性标志
const flags = new SharedFeatureFlags();
flags.enable('new-retry-logic');
if (flags.isEnabled('new-retry-logic')) { /* 使用新逻辑 */ }
```

### 3.2 EventBus

**文件**：`event-bus.js`

#### 职责与定位

框架级事件总线，提供模块间解耦通信的核心机制。支持中间件链、事件历史记录、命名空间隔离和一次性异步监听。是EventRegistrar事件转发的基础。

#### 关键API

| 方法 | 说明 | 返回值 |
|------|------|--------|
| `use(fn)` | 注册中间件，按注册顺序执行 | `EventBus` |
| `emit(event, data)` | 发射事件，经过中间件链后通知监听器 | `void` |
| `on(event, handler)` | 注册事件监听器 | `EventBus` |
| `once(event, handler)` | 注册一次性监听器 | `EventBus` |
| `onceAsync(event, timeoutMs)` | 异步等待下一个事件 | `Promise<Object>` |
| `getHistory(filter)` | 获取事件历史（支持过滤） | `Array` |
| `createNamespace(prefix)` | 创建命名空间隔离的事件发射器 | `Object` |
| `removeAllListeners(event?)` | 移除所有或指定事件的监听器 | `EventBus` |

#### 事件

| 事件名 | 触发时机 | 数据 |
|--------|---------|------|
| `middleware-error` | 中间件执行出错 | `{error, event, data}` |
| `listener-error` | 监听器执行出错 | `{error, event, data}` |

#### 配置项

| 常量 | 值 | 说明 |
|------|-----|------|
| `DEFAULT_MAX_HISTORY` | 1000 | 最大事件历史记录数 |

#### 使用示例

```javascript
const EventBus = require('./event-bus');
const bus = new EventBus({ maxHistory: 500 });

// 中间件：日志记录
bus.use(async (event, data, next) => {
  console.log(`[EventBus] ${event}`, data);
  await next();
});

// 监听器
bus.on('task:completed', (data) => {
  console.log('Task completed:', data.taskId);
});

// 命名空间隔离
const agentBus = bus.createNamespace('agent:');
agentBus.emit('started', { agentId: 'worker-1' }); // 实际发射 agent:started

// 异步等待
const result = await bus.onceAsync('deployment:done', 30000);

// 事件历史
const recentErrors = bus.getHistory(e => e.event.includes('error'));
```

### 3.3 EventRegistrar

**文件**：`event-registrar.js`

#### 职责与定位

事件注册编排器，负责将框架中所有子系统的事件进行统一转发、注册和审计。不是类，而是导出一系列函数和常量，由ModuleInitializer在初始化阶段调用。

#### 关键导出

| 导出名 | 类型 | 说明 |
|--------|------|------|
| `EVENT_FORWARD_MAP` | 常量 | 事件转发映射表 |
| `CONDITIONAL_EVENT_FORWARD_MAP` | 常量 | 条件事件转发映射 |
| `LAZY_DEEPENING_EVENT_MAP` | 常量 | 懒加载深化事件映射 |
| `AUDIT_PREFIXES` | 常量 | 审计事件前缀列表 |
| `_registerEventForwarding(ctx)` | 函数 | 注册事件转发规则 |
| `_initCausalModules(ctx)` | 函数 | 初始化因果子系统 |
| `_initEvolutionModules(ctx)` | 函数 | 初始化演化子系统 |
| `_registerSessionEvents(ctx)` | 函数 | 注册会话事件 |
| `_registerAuditMiddleware(ctx)` | 函数 | 注册审计中间件 |
| `_registerStructuredLogListeners(ctx)` | 函数 | 注册结构化日志监听 |
| `_wireChatChainEvents(ctx)` | 函数 | 连接ChatChain事件 |
| `shutdown()` | 函数 | 关闭清理 |

#### 使用示例

```javascript
const EventRegistrar = require('./event-registrar');

// 在ModuleInitializer中调用
EventRegistrar._registerEventForwarding(ctx);
EventRegistrar._initCausalModules(ctx);
EventRegistrar._registerAuditMiddleware(ctx);
EventRegistrar._registerSessionEvents(ctx);
EventRegistrar._registerStructuredLogListeners(ctx);
```

### 3.4 ModuleInitializer

**文件**：`module-initializer.js`

#### 职责与定位

模块初始化编排器，负责按依赖顺序初始化框架中34+个核心模块。提供同步和异步两种初始化路径，确保模块间的依赖关系正确解析和注入。是框架启动的核心入口。

#### 关键导出

| 导出名 | 说明 |
|--------|------|
| `_initCoreModules(projectRoot, validation, created)` | 同步初始化核心模块 |
| `_initCoreModulesAsync(projectRoot, validation)` | 异步初始化核心模块 |
| `_cleanup(created)` | 同步清理 |
| `_cleanupAsync(created)` | 异步清理 |

#### 内部模块注册表（SIMPLE_MODULES，34项）

| 模块类别 | 包含模块 |
|----------|---------|
| 存储类 | sqliteStore, conversationStore, signalPersistence, autoVersionTracker |
| 基础设施类 | eventBus, concurrencyController, healthChecker, priorityQueue, retryEngine |
| 质量类 | qualityScorer, selfReflection, adversarialReview, docFreshnessGuard |
| 思维类 | thoughtExtractor, thoughtDeduplicator, thoughtMemoryStore, thoughtRetrieverCycle |
| Agent类 | agentRuntime, agentMonitor, agentDeployment, agentChannel |
| 协作类 | pairChat, chatChain, outputFusion, devMetricsCollector |
| 技能类 | skillRouter, skillImprovementLoop, skillEvolver |

#### 使用示例

```javascript
const { _initCoreModulesAsync, _cleanupAsync } = require('./module-initializer');

// 异步初始化所有核心模块
const ctx = await _initCoreModulesAsync('/path/to/project', true);
// ctx 包含所有初始化后的模块实例

// 使用模块
ctx.sqliteStore.init();
ctx.eventBus.emit('system:ready', {});

// 清理
await _cleanupAsync(ctx);
```

### 3.6 SqliteStore

| `saveSessionSummary(sessionId, summary)` | 保存会话摘要 | `void` |

| `getSkillLearnings(skillId)` | 获取技能学习记录 | `Array` |
| `addMemory(target, content, options)` | 添加记忆条目 | `number` |
| `searchMemories(query, limit)` | 搜索记忆 | `Array` |
| `promoteMemory(id, toTier)` | 提升记忆层级 | `boolean` |
| `demoteMemory(id, toTier)` | 降低记忆层级 | `boolean` |

| `setUserPreference(key, value)` | 设置用户偏好 | `void` |
| `upsertAffinity(agentId, taskType, data)` | 更新亲和力记录 | `void` |
| `persistCausalEntry(entry)` | 持久化因果条目 | `number` |

### 3.7 ConversationContextStore

**文件**：`conversation-context-store.js`

#### 职责与定位

多会话对话上下文持久化存储，支持SQLite FTS5全文搜索、自动压缩、JSON降级持久化。管理对话轮次记录、工具调用记录和会话生命周期。

#### 关键API

| 方法 | 说明 | 返回值 |
|------|------|--------|
| `startSession(sessionId, metadata)` | 开始新会话 | `void` |
| `recordTurn(turn)` | 记录对话轮次 | `void` |
| `recordToolCall(toolName, params, result, durationMs)` | 记录工具调用 | `void` |
| `endSession(summary)` | 结束会话 | `void` |
| `getSessionContext(sessionId, options)` | 获取会话上下文 | `Object` |
| `searchTurns(query, options)` | 搜索对话轮次 | `Array` |
| `compressSession(sessionId)` | 压缩会话 | `Object` |
| `getActiveSession()` | 获取活跃会话 | `Object\|null` |
| `getStats()` | 获取统计信息 | `Object` |

#### 事件

| 事件名 | 触发时机 |
|--------|---------|
| `session-started` | 会话开始 |
| `session-restored` | 会话恢复 |
| `turn-recorded` | 轮次记录 |
| `compression-needed` | 需要压缩 |
| `session-compressed` | 会话压缩完成 |
| `session-ended` | 会话结束 |
| `session-evicted` | 会话淘汰 |
| `sqlite-attached` | SQLite附加 |

#### 配置项

| 常量 | 值 | 说明 |
|------|-----|------|
| `MAX_TURNS_PER_SESSION` | 500 | 每会话最大轮次 |
| `MAX_SESSIONS` | 100 | 最大会话数 |
| `COMPRESSION_THRESHOLD` | 200 | 压缩阈值（轮次数） |
| `TURN_ROLES` | `['user','assistant','system','tool']` | 合法轮次角色 |

#### 使用示例

```javascript
const ConversationContextStore = require('./conversation-context-store');
const store = new ConversationContextStore({ projectRoot: '/path/to/project' });

store.startSession('sess-001', { agent: 'team-lead' });
store.recordTurn({ role: 'user', content: '分析这个需求' });
store.recordTurn({ role: 'assistant', content: '需求分析如下...' });
store.recordToolCall('codeSearch', { query: 'auth' }, { files: [...] }, 150);

// 搜索历史对话
const results = store.searchTurns('认证流程', { limit: 10 });

// 压缩旧会话
store.compressSession('sess-001');
store.endSession('完成了需求分析任务');
```

## 五、最佳实践与注意事项

### 5.1 初始化顺序

- **严格遵循依赖顺序**：ModuleInitializer已内置34个模块的依赖排序，切勿绕过它直接初始化单个模块
- **SqliteStore必须先初始化**：多个组件依赖SqliteStore（ConversationContextStore、SignalPersistence等），必须最先调用`init()`
- **EventBus尽早创建**：EventRegistrar依赖EventBus进行事件转发，应在其他模块之前创建

### 5.2 并发控制

- **使用`run()`而非手动`acquire/release`**：`ConcurrencyController.run()`自动管理许可获取和释放，避免忘记释放导致死锁
- **设置合理的租约超时**：默认5分钟，长时间任务应适当调大`leaseTimeoutMs`
- **监控`rejected`事件**：频繁拒绝说明并发度不足，需调整`maxConcurrent`

### 5.3 重试策略

- **3级升级是递进的**：retry→replan→decompose，每级耗尽后才升级，不要跳级
- **指数退避避免雪崩**：RetryEngine内置指数退避+抖动，不要在外部再添加固定间隔重试
- **ABSOLUTE_MAX_RETRIES=100是硬上限**：即使配置了更大的maxRetries，也不会超过此值

### 5.4 存储与持久化

- **WAL模式是必须的**：SqliteStore使用WAL模式提高并发读写性能，不要切换到journal模式
- **FTS5搜索使用MATCH语法**：`store.ftsSearch('knowledge', '微服务 AND 架构', 10)`
- **记忆衰减需定期调用**：`decayMemoryImportance()`应由定时任务触发，否则记忆重要性不会自动降低
- **ConversationContextStore有容量限制**：MAX_SESSIONS=100，MAX_TURNS_PER_SESSION=500，超出自动淘汰最旧会话

### 5.5 网络安全

- **SSRF防护是内置的**：MCPClient和KnowledgeBasePipeline均内置DNS重绑定检测，不要禁用
- **命令白名单严格限制**：MCPClient只允许`MCP_ALLOWED_COMMANDS`中的命令，添加新命令需评估安全风险
- **危险参数自动过滤**：`--eval`、`-e`、`--exec`等参数会被MCPClient自动移除
- **CDP连接仅限本地**：CDPClient设计用于本地Chrome实例，不要暴露到公网

### 5.6 浏览器自动化

- **优先使用模板化提取**：`extractByTemplate()`比手动选择器更稳定，且有自愈能力
- **自愈策略是自动的**：操作失败时调用`selfHeal()`，会按策略顺序尝试替代方案
- **双模式选择**：CDP直连模式性能更好，MCP模式兼容性更强，按场景选择

### 5.7 健康检查

- **liveness vs readiness**：liveness=false应终止进程，readiness=false应拒绝流量但不终止
- **critical层级谨慎注册**：只有数据库、事件总线等核心组件才应注册为critical
- **健康检查函数应快速返回**：超过1秒的检查函数会影响探针响应时间

### 5.8 会话恢复

- **Token预算是硬限制**：MAX_RESUMPTION_TOKENS=4000，超出部分按优先级截断
- **5个上下文来源是可选的**：未附加的来源自动跳过，不会报错
- **恢复令牌是系统消息**：注入的上下文以system角色记录，Agent会优先参考

### 5.9 知识库管理

- **三层目录结构是强制的**：raw/→wiki/→outputs/，不要跳过中间层
- **Wiki编译前必须initialize**：未初始化调用compileWiki会抛出异常
- **容量限制需关注**：MAX_RAW_FILES=1000、MAX_WIKI_ENTRIES=500，达到上限会拒绝新摄入

### 5.10 Git工作树

- **maxWorktrees默认10**：超过限制时create()返回null，需处理此情况
- **autoCleanup=true**：进程关闭时自动清理所有worktree，确保不遗留
- **分支删除是best-effort**：worktree移除后尝试删除分支，失败不影响主流程

### 5.11 性能优化

- **PriorityQueue的序列号**：同优先级元素按入队顺序出队（FIFO），无需额外排序
- **SignalPersistence的防抖写入**：信号不会立即持久化，而是防抖批量写入，减少I/O
- **CodeGraph使用正则解析**：不是完整AST，速度快但精度有限，适合大规模扫描
- **AiDeveloperAnalytics的BoundedMap**：所有内部集合有容量限制，防止内存泄漏

### 5.12 错误处理

- **所有组件的guardShutdown()**：关闭后调用任何方法会抛出异常，调用方需捕获
- **safeExecute vs safeCall**：safeExecute返回默认值（不抛异常），safeCall完全吞没异常（仅日志）
- **EventBus的listener-error事件**：监听器异常不会中断事件传播，但会发射listener-error

### 5.13 扩展性

- **ServiceFS适配器接口**：5个方法（list/read/write/remove/exists）是必须实现的，缺少任何方法会抛出INVALID_INPUT
- **PluginManager钩子**：钩子按注册顺序执行，异步钩子需返回Promise
- **HealthChecker可动态注册**：运行时可register/unregister检查项，无需重启
