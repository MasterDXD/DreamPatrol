## 模块概述

AgentSkillsDiscipline模块实现了工程纪律强制执行插件，确保Agent按照严格的阶段顺序执行任务。模块定义了七个工程阶段（spec→plan→design→build→test→review→ship），每个阶段配备独立的验证器和执行器。核心机制包括：严格顺序执行（不可跳过阶段）、受控回滚（仅允许特定回退路径）、阶段上下文验证（每个阶段要求不同的输入字段）、转换日志记录，以及通过斜杠命令（/spec, /plan等）触发的阶段推进。

## 融合来源

融合自软件工程的SDLC（Software Development Life Cycle）流程管控思想和DevOps的CI/CD门禁机制。模块将软件开发的最佳实践——"先规格后计划、先设计后编码、先测试后发布"——转化为可强制执行的状态机。受控回滚机制借鉴了Git的分支策略，允许在特定阶段回退修正，但限制回退范围防止流程混乱。

## 核心API

| 方法 | 参数 | 返回值 | 说明 |
|------|------|--------|------|
| `execute(command, context)` | command: string, context: Object | `{ stage, status, output, nextStage, reason }` | 执行阶段命令，返回执行结果 |
| `canAdvanceTo(stage)` | stage: string | `boolean` | 检查是否可以推进到指定阶段 |
| `getState()` | 无 | `{ currentStage, completedStages, stageResults, stageTimestamps, transitionLog, config }` | 获取当前状态快照 |
| `reset()` | 无 | 无 | 重置所有阶段状态 |
| `getStats()` | 无 | `{ totalStages, completedStages, currentStage, progress, stageResultsCount, transitionLogSize, config }` | 获取统计信息 |

### 静态属性

| 属性 | 说明 |
|------|------|
| `STAGES` | 阶段列表：['spec', 'plan', 'design', 'build', 'test', 'review', 'ship'] |
| `STAGE_INDEX` | 阶段索引映射 |
| `STAGE_COMMANDS` | 阶段对应的斜杠命令 |
| `DEFAULT_CONFIG` | 默认配置 |

## 配置项

| 字段 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `strictOrder` | boolean | true | 是否强制严格顺序执行 |
| `allowRollback` | boolean | true | 是否允许回滚 |
| `requireCompletion` | boolean | true | 是否要求前置阶段完成才能推进 |

### 回滚规则

| 当前阶段 | 允许回滚到 |
|---------|-----------|
| review | build, test |
| test | build |
| build | design, plan |
| design | plan |
| plan | spec |

### 阶段验证要求

| 阶段 | 必需字段 |
|------|---------|
| spec | requirements 或 description |
| plan | spec 或 specId |
| design | plan 或 planId 或 modules |
| build | design 或 designId 或 implementation |
| test | build 或 buildId 或 tests |
| review | code 或 testResults 或 reviewTarget |
| ship | reviewPassed 或 approval 或 releaseReady |

## 事件

| 事件名 | 触发时机 | 数据 |
|--------|---------|------|
| `stage-completed` | 阶段执行成功 | `{ stage, status, output, nextStage }` |
| `stage-rejected` | 阶段执行被拒绝 | `{ stage, reason }` |
| `stage-validation-failed` | 阶段验证失败 | `{ stage, reason }` |
| `discipline-reset` | 状态重置 | `{ previousStage, timestamp }` |

## 使用示例

```javascript
const AgentSkillsDiscipline = require('./src/runtime/workflow/agent-skills-discipline');

const discipline = new AgentSkillsDiscipline({
  strictOrder: true,
  allowRollback: true,
  requireCompletion: true,
});

discipline.on('stage-completed', ({ stage, nextStage }) => {
  console.log(stage, '→', nextStage || 'DONE');
});

discipline.on('stage-rejected', ({ stage, reason }) => {
  console.warn('Rejected:', stage, reason);
});

let result = discipline.execute('/spec', {
  requirements: ['用户认证', '数据持久化'],
  description: '构建用户管理系统',
});
console.log(result.status, result.nextStage);

result = discipline.execute('/plan', {
  spec: result.output,
  specId: 'spec-001',
  tasks: ['设计数据库模型', '实现认证API'],
});
console.log(result.status, result.nextStage);

console.log('Can advance to build?', discipline.canAdvanceTo('build'));

const state = discipline.getState();
console.log('Progress:', state.completedStages);
```

## 与现有模块的集成点

- **CommandRouter**：斜杠命令路由器将`/spec`, `/plan`等命令路由到AgentSkillsDiscipline执行
- **PhaseOrchestrator**：阶段编排器利用AgentSkillsDiscipline的阶段状态机驱动六阶段执行流程
- **TDDGate**：TDD门禁在build和test阶段之间强制执行RED-GREEN-REFACTOR检测
- **VerificationBeforeCompletion**：完成前验证在ship阶段触发，确保所有前置条件满足
- **GoalExecutor**：目标执行器通过AgentSkillsDiscipline的阶段推进机制管理目标实现流程
- **RBACEnforcer**：权限执行器验证Agent是否有权执行特定阶段的操作
