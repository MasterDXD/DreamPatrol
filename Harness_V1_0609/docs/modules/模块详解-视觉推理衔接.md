# 模块详解-视觉推理衔接

> 版本：2.73.4 | 文件：src/runtime/agent/skill-wrapper.js | 行数：~311行

---

## 模块概述

SkillWrapper模块实现了视觉感知到技能推理的衔接层，将非结构化的视觉输入转化为结构化的谓词表示，再将谓词映射为技能可消费的输入格式。模块核心流程：inventPredicate（从视觉输入中发明谓词）→ bridgeToReasoning（将谓词桥接到推理链）→ validateBridge（验证桥接质量）。支持五种谓词类型（spatial/attribute/relational/temporal/existential），通过元素提取、空间关系提取和描述词提取三层谓词发明机制，构建从感知到行动的完整语义桥梁。

## 融合来源

融合自认知科学的"视觉-语言衔接"（Vision-Language Grounding）理论和AI领域的"谓词发明"（Predicate Invention）技术。模块模拟了人类从视觉场景中提取空间关系、属性特征和实体关联的认知过程，将这些感知信息转化为可被推理引擎消费的谓词逻辑表示。桥接机制借鉴了神经符号AI（Neuro-Symbolic AI）的"感知→符号→推理"管道思想。

## 核心API

## 使用示例

```javascript
const SkillWrapper = require('./src/runtime/agent/skill-wrapper');

const wrapper = new SkillWrapper({ maxPredicates: 15, minConfidence: 0.4 });

const visualInput = {
  description: '登录页面包含用户名输入框和密码输入框，提交按钮位于底部',
  elements: [
    { name: 'username-input', type: 'existential', properties: ['text', 'input'], confidence: 0.9 },
    { name: 'password-input', type: 'existential', properties: ['password', 'input'], confidence: 0.9 },
    { name: 'submit-button', type: 'existential', properties: ['button', 'submit'], confidence: 0.85 },
  ],
  spatialRelations: [
    { type: 'above', entities: ['username-input', 'submit-button'], confidence: 0.8 },
    { type: 'above', entities: ['password-input', 'submit-button'], confidence: 0.8 },
  ],
};

const { predicates, reasoning } = wrapper.inventPredicate(visualInput);
console.log('Invented', predicates.length, 'predicates');
console.log('Reasoning:', reasoning);

const { skillInputs, reasoningChain } = wrapper.bridgeToReasoning(
  predicates,
  '修复登录页面的表单验证',
);
console.log('Skill inputs:', Object.keys(skillInputs));
console.log('Reasoning chain:', reasoningChain.length, 'steps');

const validation = wrapper.validateBridge(predicates, skillInputs);
console.log('Valid:', validation.valid, 'Coverage:', validation.coverage.toFixed(2));
```

## 与现有模块的集成点

- **AgentRuntime**：Agent运行时在处理多模态输入时，通过SkillWrapper将视觉信息转化为技能可消费的输入格式
- **SkillRouter**：SkillRouter在匹配技能时，可参考SkillWrapper生成的谓词类型选择合适的技能
- **DeepeningOrchestrator**：深化推理编排器在处理复杂视觉任务时，通过SkillWrapper的桥接机制将感知信息注入推理链
- **OodaLoop**：OODA循环的observe阶段可通过SkillWrapper将环境视觉信号转化为结构化谓词
- **GoalExecutor**：目标执行器在分解涉及UI操作的目标时，利用SkillWrapper的谓词发明能力识别界面元素和操作目标

## 核心算法详解

### inventPredicate() 三层谓词发明机制

`inventPredicate()` 是模块的核心入口方法，接收 `visualInput` 对象并执行三层串行提取，最终输出结构化谓词数组及推理说明文本。

#### a) 元素提取层 — `_extractElementPredicates(elements, predicates)`

**职责**：从 `visualInput.elements` 数组中逐条提取存在性谓词（EXISTENTIAL类型为主），执行置信度过滤。

**处理流程**：
1. 遍历 `elements` 数组，受 `maxPredicates` 上限控制提前终止
2. 对每个元素提取三个字段：
   - `name`：元素名称字符串，非字符串时降级为 `'unknown'`
   - `type`：从元素自带 `type` 字段取值，若不在 `PREDICATE_TYPES` 枚举值内则降级为 `EXISTENTIAL`
   - `args`：取 `properties` 数组前5项，无属性时回退为 `[name]`
3. 置信度归一化：`confidence` 必须为有限数值，钳位至 [0, 1] 区间，默认值 0.7
4. **置信度门控**：仅当 `confidence >= minConfidence` 时将谓词加入结果集

**输出谓词结构**：
```javascript
{ name: 'submit-button', type: 'existential', arguments: ['button', 'submit'], confidence: 0.85 }
```

#### b) 空间关系提取层 — `_extractSpatialPredicates(spatialRelations, predicates)`

**职责**：从 `visualInput.spatialRelations` 数组中提取空间谓词（SPATIAL类型），含方向编码。

**处理流程**：
1. 遍历 `spatialRelations` 数组，同样受 `maxPredicates` 上限约束
2. 提取字段：
   - `name`：取 `relation.type` 字符串，默认 `'related'`
   - `args`：取 `relation.entities` 数组前5项（参与空间关系的实体标识列表）
   - `confidence`：置信度默认值 0.6（低于元素层的0.7，反映空间关系的推断性更强）
3. 置信度门控同上

**方向编码映射**（由上游视觉分析模块约定）：

| relation.type 含义 | 方向编码 | 示例 entities |
|---|---|---|
| `above` | 垂直上方 | `['A', 'B']` → A 在 B 上方 |
| `below` | 垂直下方 | `['A', 'B']` → A 在 B 下方 |
| `left-of` | 水平左侧 | `['A', 'B']` → A 在 B 左侧 |
| `right-of` | 水平右侧 | `['A', 'B']` → A 在 B 右侧 |
| `contains` | 包含关系 | `['container', 'child']` |
| `adjacent-to` | 相邻关系 | `['A', 'B']` → A 与 B 相邻 |

**输出谓词结构**：
```javascript
{ name: 'above', type: 'spatial', arguments: ['username-input', 'submit-button'], confidence: 0.8 }
```

#### c) 描述词提取层 — `_extractDescriptionPredicates(description, predicates)`

**职责**：从 `description` 文本中通过分词提取属性谓词（ATTRIBUTE类型）。

**处理流程**：
1. **空守卫**：`description` 为空字符串或已达到 `maxPredicates` 上限时直接返回
2. 分词：以空白字符 `\s+` 分割文本，过滤长度 ≤ 2 的词（去除停用词如"的"、"是"、"在"等）
3. 去重：使用 `Set` 去除重复词汇
4. 容量限制：截断至 `maxPredicates - predicates.length`（为前两层预留空间）
5. 生成谓词：每个唯一词生成一条 ATTRIBUTE 类型谓词，固定置信度 0.5（分词推断的置信度较低）

**输出谓词结构**：
```javascript
{ name: '登录', type: 'attribute', arguments: ['登录'], confidence: 0.5 }
```

### bridgeToReasoning() 谓词-技能映射算法

**职责**：将发明阶段产出的谓词数组按类型分组，映射到 `skillInputs` 对象的不同字段，同时构建推理链记录每步映射操作。

#### 谓词类型 → 技能输入字段映射表

| 谓词类型 (PREDICATE_TYPES) | 分组过滤条件 | 映射目标字段 | 推理链步骤类型 | 映射函数 |
|---|---|---|---|---|
| SPATIAL | `p.type === 'spatial'` | `skillInputs.spatialContext` | `spatial-mapping` | `_mapPredicateGroup()` |
| ATTRIBUTE | `p.type === 'attribute'` | `skillInputs.attributes` | `attribute-extraction` | `_mapPredicateGroup()` |
| RELATIONAL | `p.type === 'relational'` | `skillInputs.relations` | `relation-binding` | `_mapRelationalPredicates()` |
| 其他（TEMPORAL/EXISTENTIAL等） | 不属于以上三类 | `skillInputs.contextual` | `contextual-binding` | `_mapOtherPredicates()` |

#### 推理链构建规则

1. **顺序执行**：按 SPATIAL → ATTRIBUTE → RELATIONAL → OTHER 的固定顺序依次映射
2. **每组一步**：每种类型的谓词组在 `reasoningChain` 中生成一个步骤节点
3. **目标注入**：若 `taskGoal` 非空字符串，追加 `goal-alignment` 步骤将目标注入 `skillInputs.taskGoal`
4. **深度裁剪**：若推理链长度超过 `maxBridgeDepth`（默认3），截断尾部超出的步骤

**推理链节点结构**：
```javascript
{ step: 1, type: 'spatial-mapping', input: '2 spatial predicates', output: 'spatialContext mapped' }
```

**skillInputs 输出结构示例**：
```javascript
{
  spatialContext: [{ name: 'above', values: ['username-input','submit-button'], confidence: 0.8 }],
  attributes: [{ name: '登录', values: ['登录'], confidence: 0.5 }],
  relations: [],
  contextual: [],
  taskGoal: '修复登录页面的表单验证'
}
```

### validateBridge() 桥接验证算法

**职责**：量化评估谓词到技能输入的桥接质量，产出覆盖率、平均置信度和问题清单。

#### 验证流程

1. **空谓词检查**：`predicates` 为空数组时直接返回 `{ valid: false, coverage: 0, ... }`
2. **名称收集**：遍历 `skillInputs` 所有数组值，提取其中对象的 `name` / `relation` / `type` 字符串字段，汇总为 `Set<string>`（即已被映射的谓词名称集合）
3. **覆盖率计算**：
   ```
   coverage = coveredPredicates / totalPredicates
   其中 coveredPredicates = predicates 中 name 存在于 mappedNames Set 的数量
   ```
4. **平均置信度计算**：
   ```
   avgConfidence = Σ(p.confidence ?? 0) / totalPredicates
   ```
5. **问题收集**（`_collectValidationIssues`）：
   - `coverage < 0.5` → 报告低覆盖率警告
   - `avgConfidence < minConfidence` → 报告低平均置信度警告
   - 统计低于阈值的单条谓词数量 → 报告具体数量

6. **有效性判定**：`valid = issues.length === 0`

#### 返回值结构

```javascript
{
  valid: true,           // boolean — 是否通过全部检查
  coverage: 0.85,        // number [0,1] — 谓词覆盖率
  avgConfidence: 0.72,   // number [0,1] — 加权平均置信度
  issues: []             // string[] — 问题描述列表
}
```

## 谓词类型体系

SkillWrapper 定义五种谓词类型，覆盖视觉场景理解的核心语义维度：

| 谓词类型 | 枚举值 | 语义域 | 典型谓词名称 | 示例 | 来源层 |
|---|---|---|---|---|---|
| **SPATIAL** | `'spatial'` | 空间位置与方向关系 | `above`, `below`, `left-of`, `right-of`, `contains`, `adjacent-to` | `{ name:'above', arguments:['header','nav'], confidence:0.9 }` | 空间关系提取层 |
| **ATTRIBUTE** | `'attribute'` | 视觉属性与特征 | `color`, `size`, `shape`, `text-content`, `enabled`, `disabled` | `{ name:'blue', arguments:['blue'], confidence:0.5 }` | 描述词提取层 |
| **RELATIONAL** | `'relational'` | 结构层级与实体关联 | `parent-child`, `sibling`, `ancestor-descendant` | `{ name:'parent-child', arguments:['form','input'], confidence:0.8 }` | 元素提取层 |
| **TEMPORAL** | `'temporal'` | 时间顺序与并发关系 | `before-after`, `concurrent-with`, `follows` | `{ name:'before-after', arguments:['load','click'], confidence:0.7 }` | 元素提取层 |
| **EXISTENTIAL** | `'existential'` | 实体存在性与可见性 | `exists`, `not-exists`, `present`, `absent` | `{ name:'submit-button', type:'existential', arguments:['button'], confidence:0.85 }` | 元素提取层（默认降级类型） |

### 各类型详细说明

**SPATIAL（空间谓词）**
- 编码两个实体间的二维/三维位置关系
- 由视觉分析引擎（上游）提供 `spatialRelations` 输入
- 置信度通常在 0.6–0.95 范围，取决于检测算法精度
- 方向性谓词（above/below/left-of/right-of）的 `arguments[0]` 为参照主体，`arguments[1]` 为目标客体

**ATTRIBUTE（属性谓词）**
- 描述实体的静态视觉特征或文本内容
- 主要来源为 `description` 文本的分词结果，也可来自元素的 `properties` 字段
- 分词产生的属性谓词置信度统一为 0.5（推断性质强）
- 元素自带的属性谓词置信度由上游标注决定

**RELATIONAL（关系谓词）**
- 描述 DOM 树或场景图中的结构化层级关系
- 通常由元素提取层的 `type` 字段显式指定为 `'relational'`
- 用于表达 UI 组件树中的父子、兄弟、祖先-后代关系

**TEMPORAL（时间谓词）**
- 描述事件或状态变化的时间先后顺序
- 适用于视频帧序列或交互日志的时间线分析
- 当前版本中主要由外部注入，内置提取逻辑暂未专门处理时间维度

**EXISTENTIAL（存在性谓词）**
- 断言某实体是否存在于当前视觉场景中
- 是元素提取层的**默认降级类型**：当元素 `type` 不在枚举范围内时自动归为此类
- 置信度最高（通常 0.7–0.95），因为存在性判断相对确定

## R58修复记录

### 问题：v2.7.139 新增 description 参数 null 类型守卫

**缺陷编号**：R58  
**影响版本**：v2.7.138 及之前  
**修复版本**：v2.7.139  
**严重程度**：Medium（导致运行时崩溃）

**问题描述**：
在 v2.7.138 及更早版本中，`inventPredicate()` 方法对 `visualInput.description` 参数的类型检查不充分。当调用方传入非字符串类型的 `description`（如 `null`、`undefined`、数字或对象）时，后续 [`_extractDescriptionPredicates`](file:///e:/Harness_V1_0429/src/runtime/agent/skill-wrapper.js#L106-L118) 方法在第108行调用 `.split(/\s+/)` 会触发 `TypeError: Cannot read property 'split' of null`，导致整个谓词发明流程崩溃。

**根因分析**：
原代码假设 `visualInput.description` 始终为字符串类型，但实际使用场景中（特别是多模态输入管道的上游模块可能返回部分缺失的数据），`description` 字段可能为 `null` 或其他 falsy 值。

**修复方案**：
在 [`invertPredicate()`](file:///e:/Harness_V1_0429/src/runtime/agent/skill-wrapper.js#L43-L71) 方法入口处（第49行）增加显式类型守卫：

```javascript
const description = typeof visualInput.description === 'string' ? visualInput.description : '';
```

该守卫确保 `description` 变量在任何情况下均为合法字符串（空字符串作为缺省值），使下游的 `.split()` 调用安全执行。当 `description` 为空字符串时，[`_extractDescriptionPredicates`](file:///e:/Harness_V1_0429/src/runtime/agent/skill-wrapper.js#L106-L118) 第107行的空守卫会提前返回，不会产生无效谓词。

**防御性编码一致性检查**：
同一方法中对 `elements` 和 `spatialRelations` 参数已有类似的 Array 类型守卫（第50-51行），此次修复补齐了对 `description` 的同等防护，保持参数防御的一致性。

**回归验证要点**：
- 传入 `description: null` → 应正常返回谓词数组（不含 attribute 类型谓词）
- 传入 `description: undefined` → 同上
