# 模块详解-跨会话学习引擎

> 版本：2.73.4 | 文件：src/runtime/thought/dream-engine.js | 行数：~880行

---

## 模块概述

DreamEngine模块实现了跨会话学习引擎，通过"做梦"机制在会话间隙对历史会话进行离线分析，提取错误模式、成功策略和工作流模式，生成可复用的学习笔记。模块采用标记词匹配（支持中英文）从会话中提取模式，通过Jaccard相似度+编辑距离的混合相似度算法进行笔记去重合并，支持基于关键词和语义向量的笔记检索，并可将笔记持久化到SQLite存储。

## 融合来源

融合自认知科学中的"睡眠学习"（Sleep Learning）理论和神经科学的"记忆巩固"（Memory Consolidation）机制。正如人类大脑在睡眠期间通过重放和整合日间经验来强化记忆、发现模式，DreamEngine在会话间隙对历史数据进行离线分析，将分散的经验转化为结构化的知识笔记，实现跨会话的知识积累与传递。

## 使用示例

```javascript
const DreamEngine = require('./src/runtime/thought/dream-engine');

const dream = new DreamEngine({ maxNotes: 300, minPatternFrequency: 3 });
dream.attachSqliteStore(sqliteStore);
dream.attachEmbeddingService(embeddingService);

dream.on('dream-complete', (result) => {
  console.log('Dream finished:', result.dreamId);
  console.log('Patterns found:', result.patternsFound);
  console.log('Notes created:', result.notesCreated);
});

const sessionHistory = [
  {
    sessionId: 'sess-1',
    errors: [{ message: 'TypeError: Cannot read property', resolution: 'Add null check' }],
    lessonsLearned: [{ content: 'Always validate input before processing', strategy: 'defensive programming' }],
    completedSkills: ['tdd-implement', 'code-review'],
  },
];

const result = await dream.startDreaming(sessionHistory);

const relevantNotes = dream.getRelevantNotes('处理空值异常');
console.log('Relevant notes:', relevantNotes.length);
```

## 与现有模块的集成点

- **SessionManager**：会话管理器在会话结束时将历史数据传递给DreamEngine进行离线分析
- **ThoughtMemoryStore**：思维记忆存储与DreamEngine共享记忆数据，DreamEngine的分析结果可写入长期记忆
- **EmbeddingService**：嵌入服务为笔记提供语义向量化能力，支持语义级别的笔记检索和去重
- **SqliteStore**：SQLite存储用于笔记的持久化，确保跨进程重启后笔记不丢失
- **BrainMemory**：Brain记忆系统可消费DreamEngine生成的笔记，将跨会话学习成果注入实时记忆检索
- **QualityScorer**：质量评分器可参考DreamEngine的历史模式分析结果，识别重复出现的质量问题

## 核心算法详解

### `startDreaming()` 做梦流水线

`startDreaming()` 是DreamEngine的核心入口方法，实现了完整的8阶段流水线处理：

```
会话输入 → [1]会话预处理 → [2]错误模式提取 → [3]成功模式提取 → [4]工作流模式提取
         → [5]笔记生成 → [6]去重合并 → [7]置信度评分 → [8]持久化
```

**阶段1：会话预处理**
- 输入校验：检查`_dreaming`互斥锁防止重入，检查`sessionHistory`是否为非空数组
- 截断控制：通过`maxSessionsPerDream`（默认20）限制单次分析的会话数量，防止内存溢出
- 互斥锁：设置`_dreaming = true`，确保同一时刻只有一个做梦流程在执行

**阶段2-4：模式提取**
- 调用`_analyzePatterns(sessions)`统一编排三类模式提取
- 每个会话依次经过`_extractErrorPatterns`、`_extractSuccessPatterns`、`_extractWorkflowPatterns`
- 提取结果通过`_filterPatterns()`过滤，仅保留频次≥`minPatternFrequency`且置信度≥`minConfidence`的模式

**阶段5：笔记生成**
- `_extractNotes(patterns)`将三类模式分别转化为对应类别的笔记：
  - `error_patterns` → `error-avoidance` 类别笔记
  - `success_patterns` → `best-practice` 类别笔记
  - `workflow_patterns` → `workflow-optimization` 类别笔记
- 每条笔记通过`_buildNote()`生成唯一ID（`dnote-`前缀）、记录来源会话、时间戳

**阶段6：去重合并**
- `_mergeWithExistingNotes(newNotes)`对新笔记与已有笔记进行相似度比对
- 合并前创建快照（snapshot），合并失败时回滚到快照状态
- 详见下方"笔记去重合并算法"

**阶段7：置信度评分**
- 置信度计算公式：`confidence = min(0.95, minConfidence + (frequency - minPatternFrequency) * 0.1)`
- 置信度上限为0.95，防止过度自信
- 频次越高，置信度线性递增，每多出现1次增加0.1

**阶段8：持久化**
- `_persistToSqlite()`将所有笔记写入SQLite存储（通过`upsert`操作）
- 若已附加BrainMemory或MemoryStore，调用`syncNotesToStores()`将高置信度笔记（≥0.7）同步到外部记忆系统
- 发射`dream-complete`事件，携带完整的分析结果

### 标记词匹配算法

DreamEngine使用预定义的中英文标记词库对会话文本进行模式匹配：

| 标记词类型 | 英文关键词 | 中文关键词 |
|-----------|-----------|-----------|
| `ERROR_MARKERS` | error, fail, bug, crash, exception, timeout, refused | 错误, 失败, 缺陷, 崩溃, 异常, 超时, 拒绝 |
| `SUCCESS_MARKERS` | success, completed, resolved, fixed, optimized, passed | 成功, 完成, 解决, 修复, 优化, 通过 |
| `WORKFLOW_MARKERS` | step, phase, process, workflow, pipeline, flow | 步骤, 阶段, 流程, 管道, 工作流 |

**匹配流程**：

1. **文本采集**：`_extractTextsFromSession(session)`从6个字段提取文本：
   - `errors`数组 → 提取message/text + resolution/fix
   - `lessonsLearned`数组 → 提取content + strategy/approach
   - `keyDecisions`数组 → 提取content + rationale
   - `completedSkills`数组 → 拼接为逗号分隔字符串
   - `output`字符串 → 按行分割，过滤长度≤10的行，最多取末尾500行
   - `artifacts`数组 → 提取content字段

2. **标记匹配**：`_collectFromSession(session, markers)`对每条文本执行`toLowerCase().includes(marker)`匹配，命中任一标记词即收录，同一文本不重复收录（break跳出标记词循环）

3. **模式归一化**：`_normalizePattern(text)`对匹配文本执行：
   - 转小写
   - 移除非单词、非空白、非CJK字符（`[^\w\s\u4e00-\u9fff]`）
   - 合并连续空白
   - 截断至`MAX_COMPARE_LENGTH`（500字符）

4. **频次统计**：相同归一化key的模式在`patternMap`中累加frequency，同时保留最多5条examples和5条solutions/strategies/steps

### 笔记去重合并算法

`_mergeWithExistingNotes()`使用Jaccard相似度与Levenshtein编辑距离的混合评分进行笔记去重：

**相似度计算**（`_computeSimilarity(a, b)`）：

```
finalSimilarity = jaccard × 0.6 + editDistanceSimilarity × 0.4
```

**Jaccard相似度**（权重0.6）：
- 将归一化后的文本按空白分割为词集合
- 计算集合交集大小 / 集合并集大小
- 适用于检测词汇层面的重叠，对词序不敏感

**编辑距离相似度**（权重0.4）：
- 使用Levenshtein距离算法（动态规划，O(m×n)复杂度，滚动数组优化空间至O(n)）
- 相似度 = `1 - levenshtein(a, b) / max(len(a), len(b))`
- 适用于检测字符级别的相似性，对词序和拼写差异敏感

**合并决策**：
- 若`finalSimilarity ≥ similarityThreshold`（默认0.75），执行合并：
  - 置信度取`max(existing, new)`
  - 来源会话取并集（去重）
  - 记录`merge_count`递增
  - 更新`updated_at`时间戳
- 若低于阈值，作为新笔记添加

**容错机制**：
- 合并前创建`_notes`快照（深拷贝，含source_sessions数组）
- 合并过程中任何异常触发回滚，恢复到快照状态

### `getRelevantNotes()` 混合检索

`getRelevantNotes(context)`实现了关键词精确匹配与embedding向量余弦相似度的加权融合检索：

**检索流程**：

1. **查询预处理**：对context文本执行`_normalize()`归一化，分割为词集合`queryWords`

2. **关键词精确匹配**（权重0.6）：
   - 对每条笔记的content归一化后分割为词集合
   - `_computeKeywordOverlap(queryWords, contentWords)` = 匹配词数 / 查询词数
   - 纯精确匹配，不涉及语义理解

3. **语义向量相似度**（权重0.4，需附加EmbeddingService）：
   - 调用`_computeSemanticScore(note, context)`
   - 通过`EmbeddingService.embed()`分别获取查询和笔记的向量表示
   - 调用`EmbeddingService.cosineSimilarity()`或内置`_cosineSimilarity()`计算余弦相似度
   - 注意：同步上下文不支持异步embedding，异步embed返回0分

4. **融合评分**：`relevance = keywordScore × 0.6 + semanticScore × 0.4`

5. **思维记忆补充检索**：
   - 若已附加ThoughtMemoryStore，调用`_searchThoughtMemory(context, queryWords)`
   - 从思维记忆中搜索最多5条结果，按关键词重叠度过滤（>0.1）
   - 去重：与已有结果content比对，避免重复

6. **结果排序与截断**：按relevance降序排列，返回前20条

## 笔记生命周期管理

DreamEngine中笔记从创建到淘汰经历完整的6阶段生命周期：

```
创建 → 缓存 → 去重 → 持久化 → 检索 → 淘汰
```

### 1. 创建阶段

笔记通过`_buildNote()`创建，包含以下字段：

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | string | 唯一标识，`dnote-`前缀的generateId |
| `category` | string | 类别：error-avoidance / best-practice / workflow-optimization |
| `content` | string | 笔记内容，由模式+解决方案/策略/步骤+频次拼接 |
| `confidence` | number | 置信度（0.6~0.95），3位小数精度 |
| `source_sessions` | string[] | 来源会话ID列表 |
| `created_at` | string | ISO时间戳 |

### 2. 缓存阶段

笔记存储在内存`_notes`（Map实例）中，以笔记ID为key。Map提供O(1)的查找和插入性能。实例化时若已附加SqliteStore，通过`_restoreFromSqlite()`从持久化存储恢复已有笔记到缓存。

### 3. 去重阶段

新笔记通过`_mergeWithExistingNotes()`与缓存中已有笔记进行相似度比对。同类别笔记间计算混合相似度（Jaccard 0.6 + Levenshtein 0.4），超过`similarityThreshold`（0.75）则合并，否则新增。合并操作包含快照回滚容错机制。

### 4. 持久化阶段

- `_persistToSqlite()`：每次做梦完成后，将所有笔记通过`upsert`写入SQLite的`dream_notes`表
- `syncNotesToStores(minConfidence=0.7)`：将置信度≥阈值的笔记同步到BrainMemory（`store`方法）和MemoryStore（`addKnowledge`方法），同步结果通过`notes-synced`事件通知
- 关闭时（`_onShutdown()`）自动调用`_persistToSqlite()`确保数据不丢失

### 5. 检索阶段

两种检索模式：

- **精确筛选**：`getNotes(category?, minConfidence?)`按类别和置信度过滤，结果按置信度降序排列
- **混合检索**：`getRelevantNotes(context)`基于关键词+语义向量加权融合，附加relevance评分，最多返回20条

### 6. 淘汰阶段

`_trimNotes()`在笔记数量超过`maxNotes`（默认500）时触发淘汰：

- 按置信度降序排列所有笔记
- 保留前`maxNotes`条高置信度笔记
- 其余笔记从缓存中清除
- 淘汰在每次合并操作后自动执行

淘汰策略为**置信度优先**（非LRU时序），确保保留最有价值的学习笔记。与DreamOutcomes闭环集成后，可通过`getLowEffectivenessNotes()`识别低效果笔记，实现基于实际使用效果的二次淘汰。

## DreamOutcomes闭环

DreamEngine通过DreamBridge桥接器与DreamOutcomes形成双向闭环，实现"学习→应用→评估→反馈"的完整循环。

### 闭环架构

```
                    ┌─────────────────────────────────────────────┐
                    │              DreamBridge 桥接器              │
                    │                                             │
  QualityScorer ────┤ 规则1: score-computed → evaluateOutcome  ────┤──→ DreamOutcomes
                    │                                             │
  SelfReflection ───┤ 规则2: reflection-completed → consumeInput ──┤──→ DreamEngine
                    │                                             │
  DreamOutcomes ────┤ 规则3: outcome-evaluated → syncToDreamEngine├──→ DreamEngine
                    │ 规则4: outcome-evaluated → syncToLoop       ├──→ SkillImprovementLoop
                    │                                             │
  DreamEngine ──────┤ 规则5: dream-complete → createEntry        ├──→ LlmWiki
                    └─────────────────────────────────────────────┘
```

### 5条自动桥接规则

| 规则 | 触发事件 | 源模块 | 目标模块 | 动作 |
|------|---------|--------|---------|------|
| 规则1 | `score-computed` | QualityScorer | DreamOutcomes | 质量评分≥0.6标记为achieved，调用`evaluateOutcome()` |
| 规则2 | `reflection-completed` | SelfReflection | DreamEngine | 将反思改进建议和策略传入`consumeReflectionInput()` |
| 规则3 | `outcome-evaluated` | DreamOutcomes | DreamEngine | 评估结果转化为会话数据，调用`syncToDreamEngine()`→`startDreaming()` |
| 规则4 | `outcome-evaluated` | DreamOutcomes | SkillImprovementLoop | 评估结果转化为学习记录，调用`syncToSkillImprovementLoop()`→`recordLearning()` |
| 规则5 | `dream-complete` / `dream-error` | DreamEngine | LlmWiki | 置信度≥0.8的笔记写入知识库，error-avoidance→troubleshooting类，其他→patterns类 |

### 闭环数据流详解

**正向流（DreamEngine → 外部）**：
1. DreamEngine完成做梦后发射`dream-complete`事件
2. DreamBridge监听该事件，将高置信度笔记（≥0.8）写入LlmWiki知识库
3. DreamEngine通过`syncNotesToStores()`将笔记同步到BrainMemory和MemoryStore
4. 笔记在后续会话中通过`getRelevantNotes()`被检索使用

**反向流（外部 → DreamEngine）**：
1. QualityScorer评分完成后，DreamBridge将评分结果传入DreamOutcomes评估
2. DreamOutcomes评估完成后，DreamBridge触发`syncToDreamEngine()`
3. 评估结果被转化为会话格式（成功→lessonsLearned，失败→errors），作为`startDreaming()`的新输入
4. DreamEngine从评估反馈中提取新的模式，形成"评估驱动学习"的闭环

**效果追踪流**：
1. DreamOutcomes通过`recordNoteUsage(noteId, context)`记录笔记被使用
2. DreamOutcomes通过`recordNoteOutcome(noteId, effective)`记录笔记使用效果
3. `getNoteEffectiveness(noteId)`返回单条笔记的有效率统计
4. `getLowEffectivenessNotes(threshold=0.3)`识别低效果笔记，为笔记淘汰提供数据支撑

### DreamBridge容错机制

- 所有桥接处理器均包裹在`safeExecute()`中，单条桥接失败不影响其他桥接
- 桥接统计：`_bridgeStats`记录每条规则的激活次数和失败次数
- 优雅关闭：`deactivate()`移除所有事件监听器，防止内存泄漏
- 事件驱动：桥接完全基于事件机制，无轮询，低开销
