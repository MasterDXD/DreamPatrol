# 模块详解-自进化搜索引擎

> 版本：2.73.4 | 融合来源：Sirchnunk开源搜索引擎 | 更新时间：2026年6月

---

## 概述

自进化搜索引擎模块融合了[Sirchnunk](https://github.com/sirchnunk)开源搜索引擎的核心设计理念，采用"MCP集成+原生增强"混合策略实现。Sirchnunk是一个无需向量数据库和预索引的进化搜索引擎，其核心优势在于知识集群自组织和IDF加权检索。本模块通过MCP协议与Sirchnunk Python SDK集成，同时使用Harness原生Node.js组件实现知识集群存储和搜索编排，确保与现有框架无缝集成。

### 融合策略

| 维度 | 评估结果 | 融合方案 |
|------|---------|---------|
| 语言兼容性 | Python vs Node.js（高风险） | MCP协议桥接，不直接嵌入Python代码 |
| 知识集群 | 核心特性，高度匹配 | 原生Node.js实现KnowledgeClusterStore |
| 搜索流程 | 五阶段流程，高度匹配 | 原生实现EvolvingSearchEngine |
| 蒙特卡洛抽样 | 依赖LLM，中等匹配 | 保留DEEP模式接口，暂不实现抽样算法 |
| ReAct代理 | 与现有Agent重叠，可复用 | 通过enableReactiveRefine配置启用 |

## 一、SirchnunkMcpAdapter

**源码**：`src/runtime/search/sirchnunk-mcp-adapter.js`

Sirchnunk MCP适配器，封装MCPClient调用Sirchnunk搜索引擎。通过MCP协议与Sirchnunk Python SDK通信，支持三种搜索模式。

### 常量

#### SEARCH_MODES

| 模式 | 值 | 说明 |
|------|-----|------|
| FILENAME_ONLY | `'FILENAME_ONLY'` | 仅文件名匹配，最快 |
| FAST | `'FAST'` | 快速模式，平衡速度与准确率 |
| DEEP | `'DEEP'` | 深度模式，最高准确率 |

#### DEFAULT_CONFIG

| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| mcpServerName | `'sirchnunk'` | MCP服务器名称 |
| defaultMode | `'FAST'` | 默认搜索模式 |
| maxConcurrentSearches | `3` | 最大并发搜索数 |
| resultCacheSize | `50` | 结果缓存容量 |
| searchHistorySize | `100` | 搜索历史容量 |
| defaultTopK | `20` | 默认返回结果数 |
| defaultMaxDepth | `10` | 默认最大搜索深度 |
| defaultMaxLoops | `10` | 默认最大循环数 |

### 类方法

| 方法 | 参数 | 返回值 | 说明 |
|------|------|--------|------|
| `constructor(options)` | `{mcpClient, mcpServerName, defaultMode, ...}` | 实例 | 创建适配器 |
| `attachMcpClient(client)` | MCPClient实例 | void | 附加MCPClient |
| `search(query, options)` | 查询字符串, 选项 | `Promise<object>` | 执行搜索 |
| `getHistory(limit)` | 数量限制 | `Array` | 获取搜索历史 |
| `getStats()` | — | `object` | 获取统计信息 |
| `clearCache()` | — | void | 清除结果缓存 |

### 事件

| 事件名 | 数据 | 说明 |
|--------|------|------|
| `search-complete` | `{query, mode, answer, confidence, ...}` | 搜索完成 |
| `search-error` | `{query, mode, error}` | 搜索失败 |

### 搜索选项

| 参数 | 类型 | 说明 |
|------|------|------|
| `mode` | string | 搜索模式 |
| `paths` | string[] | 搜索路径 |
| `topK` | number | 返回结果数 |
| `maxDepth` | number | 最大搜索深度 |
| `maxLoops` | number | 最大循环数 |
| `includePatterns` | string[] | 包含文件模式 |
| `excludePatterns` | string[] | 排除文件模式 |

### 搜索结果

```javascript
{
  query: '搜索查询',
  mode: 'FAST',
  answer: '搜索结果摘要',
  clusterId: 'kc-xxx' | null,
  confidence: 0.85,
  evidenceUnits: [{ content, confidence, ... }],
  tokensUsed: 1200,
  timestamp: 1717500000000
}
```

## 二、KnowledgeClusterStore

**源码**：`src/runtime/search/knowledge-cluster-store.js`

知识集群存储，借鉴Sirchnunk的KnowledgeCluster设计，使用Harness原生的BoundedMap+内存方案实现。支持6种分类、关键词匹配查找、证据添加和集群合并。

### 常量

#### CLUSTER_CATEGORIES

| 分类 | 值 | 说明 |
|------|-----|------|
| PERSON | `'person'` | 人物相关集群 |
| PROJECT | `'project'` | 项目相关集群 |
| MEMORY_TYPE | `'memory_type'` | 记忆类型集群 |
| TOPIC | `'topic'` | 主题集群 |
| DECISION | `'decision'` | 决策集群 |
| ERROR_PATTERN | `'error_pattern'` | 错误模式集群 |

#### DEFAULT_CONFIG

| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| maxClusters | `500` | 最大集群数 |
| maxEvidencePerCluster | `50` | 每集群最大证据数 |
| minConfidence | `0.5` | 最低置信度 |
| similarityThreshold | `0.75` | 相似度匹配阈值 |
| autoMergeThreshold | `0.85` | 自动合并阈值 |

### 类方法

| 方法 | 参数 | 返回值 | 说明 |
|------|------|--------|------|
| `constructor(options)` | `{sqliteStore, embeddingService, ...}` | 实例 | 创建存储实例 |
| `createCluster(clusterData)` | 集群数据对象 | `object` | 创建知识集群 |
| `findMatchingCluster(query, category)` | 查询文本, 可选分类 | `object\|null` | 查找匹配集群 |
| `addEvidence(clusterId, evidence)` | 集群ID, 证据数据 | `object\|null` | 添加证据 |
| `mergeClusters(sourceId, targetId)` | 源ID, 目标ID | `boolean` | 合并集群 |
| `getCluster(clusterId)` | 集群ID | `object\|null` | 获取集群 |
| `getAllClusters(category)` | 可选分类 | `Array` | 获取所有集群 |
| `getStats()` | — | `object` | 获取统计信息 |

### 事件

| 事件名 | 数据 | 说明 |
|--------|------|------|
| `cluster-created` | `{id, name, category, ...}` | 集群创建 |
| `cluster-reused` | `{clusterId, score, query}` | 集群复用 |
| `evidence-added` | `{clusterId, evidenceCount}` | 证据添加 |
| `clusters-merged` | `{sourceId, targetId}` | 集群合并 |

### 集群数据结构

```javascript
{
  id: 'kc-abc123',           // 自动生成ID
  name: '集群名称',           // 显示名称
  category: 'topic',          // 分类
  description: '描述',        // 详细描述
  evidence: [{                // 证据列表
    content: '证据内容',
    source: 'sirchnunk',
    confidence: 0.85,
    addedAt: 1717500000000
  }],
  keywords: ['关键词'],       // 关键词列表
  confidence: 0.85,           // 整体置信度
  sourceQueries: ['查询'],    // 来源查询
  createdAt: 1717500000000,   // 创建时间
  updatedAt: 1717500000000,   // 更新时间
  accessCount: 12             // 访问次数
}
```

### 匹配算法

使用关键词重叠度计算匹配分数：

```
score = 匹配的关键词数 / 查询关键词总数
```

当score >= similarityThreshold（默认0.75）时认为匹配成功。匹配成功时自动递增accessCount并触发`cluster-reused`事件。

## 三、EvolvingSearchEngine

**源码**：`src/runtime/search/evolving-search-engine.js`

自进化搜索引擎，融合Sirchnunk搜索流程设计，实现5阶段搜索：集群复用→平行探测→IDF排名→集群建设→反应精炼。

### 常量

#### SEARCH_PHASES

| 阶段 | 值 | 说明 |
|------|-----|------|
| CLUSTER_REUSE | `'cluster_reuse'` | 知识集群复用 |
| PARALLEL_PROBE | `'parallel_probe'` | 平行探测 |
| IDF_RANKING | `'idf_ranking'` | IDF加权排名 |
| CLUSTER_BUILD | `'cluster_build'` | 知识集群建设 |
| REACTIVE_REFINE | `'reactive_refine'` | 反应精炼 |

#### DEFAULT_CONFIG

| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| defaultMode | `'FAST'` | 默认搜索模式 |
| enableClusterReuse | `true` | 启用集群复用 |
| enableIdfRanking | `true` | 启用IDF排名 |
| enableReactiveRefine | `false` | 启用反应精炼 |
| minConfidenceForAnswer | `0.7` | 最低回答置信度 |
| maxRefineLoops | `3` | 最大精炼循环数 |

> **内存管理**：`_idfIndex` 使用 BoundedMap（容量5000），防止长期运行时词条索引无限增长。

### 类方法

| 方法 | 参数 | 返回值 | 说明 |
|------|------|--------|------|
| `constructor(options)` | `{mcpClient, knowledgeClusterStore, sirchnunkAdapter, ...}` | 实例 | 创建引擎 |
| `search(query, options)` | 查询字符串, 选项 | `Promise<object>` | 执行5阶段搜索 |
| `getStats()` | — | `object` | 获取统计信息 |

### 事件

| 事件名 | 数据 | 说明 |
|--------|------|------|
| `search-phase` | `{phase, hit, clusterId?}` | 搜索阶段执行 |
| `search-complete` | `{query, confidence, phases}` | 搜索完成 |

### 5阶段搜索流程

```
┌─────────────────────────────────────────────────────────────────┐
│  Phase 1: 知识集群复用                                          │
│  ┌─────────────────────────────────────────────────────────┐    │
│  │ findMatchingCluster(query)                              │    │
│  │ → 命中且confidence >= minConfidenceForAnswer            │    │
│  │ → 直接返回集群结果（秒级响应）                           │    │
│  └─────────────────────────────────────────────────────────┘    │
│                           ↓ 未命中                               │
│  Phase 2-3: 平行探测 + IDF排名                                  │
│  ┌─────────────────────────────────────────────────────────┐    │
│  │ sirchnunk.search(query, {mode})                         │    │
│  │ → MCP协议调用Sirchnunk执行搜索                           │    │
│  │ → IDF加权排名：idfScore = Σ log((N+1)/(df+1)) + 1      │    │
│  └─────────────────────────────────────────────────────────┘    │
│                           ↓                                     │
│  Phase 4: 知识集群建设                                          │
│  ┌─────────────────────────────────────────────────────────┐    │
│  │ confidence >= minConfidenceForAnswer                    │    │
│  │ → 已有相似集群(>=0.6) → addEvidence()                  │    │
│  │ → 无相似集群 → createCluster()                          │    │
│  └─────────────────────────────────────────────────────────┘    │
│                           ↓                                     │
│  Phase 5: 反应精炼（DEEP模式 + 置信度不足时）                    │
│  ┌─────────────────────────────────────────────────────────┐    │
│  │ enableReactiveRefine && mode === DEEP                   │    │
│  │ → 循环调用sirchnunk.search()提升置信度                  │    │
│  │ → 最多maxRefineLoops次                                  │    │
│  └─────────────────────────────────────────────────────────┘    │
└─────────────────────────────────────────────────────────────────┘
```

### IDF加权排名算法

对搜索结果的evidenceUnits使用逆文档频率（IDF）加权评分：

```
idfScore = Σ log((totalDocs + 1) / (docFreq + 1)) + 1
```

其中：
- `totalDocs`：包含该查询词的文档总数
- `docFreq`：包含该查询词的文档频率
- 对每个查询词，检查证据内容是否包含该词
- 最终按idfScore降序排列

### 降级策略

当Sirchnunk MCP服务不可用时，搜索引擎自动降级：

1. **集群复用优先**：先检查知识集群是否有匹配结果
2. **集群回退**：Sirchnunk调用失败时，使用低置信度的集群结果（confidence × 0.8）
3. **完全失败**：集群和Sirchnunk均不可用时，抛出异常

## 六、使用示例

### 基本搜索

```javascript
const { EvolvingSearchEngine } = require('./src/runtime/search/');

const engine = new EvolvingSearchEngine({
  mcpClient: mcpClientInstance,
});

const result = await engine.search('Agent协作模式最佳实践');
console.log(result.answer);
console.log(result.confidence);
console.log(result.source);  // 'sirchnunk' | 'cluster_reuse' | 'cluster_fallback'
```

### 深度搜索 + 反应精炼

```javascript
const engine = new EvolvingSearchEngine({
  mcpClient: mcpClientInstance,
  enableReactiveRefine: true,
  maxRefineLoops: 5,
});

const result = await engine.search('复杂查询', { mode: 'DEEP' });
console.log(result.refineLoops);  // 精炼循环次数
```

### 知识集群管理

```javascript
const { KnowledgeClusterStore, CLUSTER_CATEGORIES } = require('./src/runtime/search/');

const store = new KnowledgeClusterStore({ maxClusters: 1000 });

// 创建集群
const cluster = store.createCluster({
  name: 'Agent协作模式',
  category: CLUSTER_CATEGORIES.TOPIC,
  keywords: ['agent', '协作', '模式'],
  evidence: [{ content: '协作模式路由器支持6种模式', confidence: 0.9 }],
});

// 查找匹配
const match = store.findMatchingCluster('agent协作');
if (match) {
  console.log(match.score);      // 匹配分数
  console.log(match.cluster.id); // 集群ID
}

// 添加证据
store.addEvidence(cluster.id, {
  content: '新增证据内容',
  source: 'manual',
  confidence: 0.85,
});
```

### MCP适配器直接使用

```javascript
const { SirchnunkMcpAdapter, SEARCH_MODES } = require('./src/runtime/search/');

const adapter = new SirchnunkMcpAdapter({
  mcpClient: mcpClientInstance,
  defaultMode: SEARCH_MODES.DEEP,
});

const result = await adapter.search('查询内容', {
  mode: SEARCH_MODES.FAST,
  topK: 10,
  includePatterns: ['*.md', '*.js'],
});
```
