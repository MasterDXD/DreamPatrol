## 1. 概述

### 1.1 模型子系统概述

模型子系统（`src/runtime/model/`，11个文件）负责模型推理全链路的资源管理与优化，涵盖Token预算管控、模型智能选择、文本向量化、注意力机制优化、KV缓存压缩、推理结果缓存和CPU-GPU协作计算加速。该子系统是框架与LLM交互的底层支撑，确保在成本约束下最大化推理效率。

**核心能力**：

- **Token预算管控**：多会话隔离的Token使用量追踪，80%/95%/100%三级预警
- **模型智能选择**：基于Skill类型、任务复杂度和预算状态自动选择最优模型，支持降级策略
- **文本向量化**：本地哈希嵌入+LRU缓存，支持OpenAI/预计算提供者扩展
- **注意力优化**：TriAttention三维度评分（位置×重要性×时效性），支持Pre-RoPE校准
- **KV缓存压缩**：四维评分剪枝（距离偏好+向量幅度+时效性+访问频率），10倍+压缩
- **推理缓存**：Prompt+上下文复合键缓存，TTL过期+LRU淘汰
- **计算加速**：CPU/GPU后端自动选择，特性标志运行时切换

### 1.2 思维子系统概述

思维子系统（`src/runtime/thought/`，20+文件）是框架的认知核心，负责思维链提取、记忆管理、知识沉淀和经验提炼。该子系统实现了从原始思维提取到钻石级知识精炼的完整认知闭环，支持离线"做梦"经验提炼、跨存储统一召回和外部记忆服务集成。

**核心能力**：

- **思维提取与精炼**：5种思维类型提取→Jaccard+Levenshtein去重→四层钻石分级（RAW/CUT/POLISHED/DIAMOND）
- **结构化推理**：6种步骤类型的思维链，支持回溯和收敛检测
- **分层记忆架构**：BrainMemory（工作记忆+长期记忆）+ MemoryStore（知识库+会话摘要）+ ThoughtMemoryStore（思维存储）
- **Hermes三阶段管道**：Recall（7源统一召回）→ Sync（3策略跨存储同步）→ Prefetch（5信号预取）
- **离线经验提炼**：DreamEngine做梦引擎 + DreamScheduler SM-2调度 + DreamOutcomes闭环评估
- **知识图谱**：三元组存储 + 8种关系类型 + BFS多跳推理 + 双向最短路径
- **外部记忆集成**：Mem0/Honcho/Hindsight三适配器 + 熔断器健康检查 + 重试+限流

## 3. 核心组件详解 — 模型子系统

### 3.1 TokenManager

**职责与定位**：Token预算管控器。多会话Token使用量追踪、三级预警（80%/95%/100%）、分类统计和LRU会话淘汰。

**关键API**：

| 方法 | 参数 | 返回值 | 说明 |
|------|------|--------|------|
| `store(sessionId, amount)` | `string, number` | `number` | 累加Token使用量，超限触发预警 |
| `get(sessionId)` | `string` | `number` | 获取会话Token使用量 |
| `set(sessionId, amount)` | `string, number` | `number` | 直接设置Token使用量 |
| `validate(sessionId, budget?)` | `string, number?` | `Object` | 验证预算阈值状态 |
| `clear(sessionId)` | `string` | `void` | 清除指定会话数据 |
| `clearAll()` | — | `void` | 清除所有会话数据 |
| `addBreakdown(sessionId, category, amount)` | `string, string, number` | `Object` | 添加分类Token消耗明细 |
| `getBreakdown(sessionId)` | `string` | `Object` | 获取分类消耗明细 |
| `getAllBreakdowns(sessionId?)` | `string?` | `Object` | 获取全部或指定会话明细 |
| `getTotal(budget?)` | `number?` | `Object` | 获取全局Token总量及占比 |
| `formatTokens(n)` | `number` | `string` | 格式化为人类可读字符串 |
| `parseFormatted(formatted)` | `string` | `number` | 解析格式化字符串为数值 |
| `setGlobalBudget(budget)` | `number` | `number` | 设置全局预算上限 |
| `getGlobalBudget()` | — | `number` | 获取全局预算 |
| `listSessions()` | — | `string[]` | 列出所有会话标识 |
| `getUsage(sessionId, budget?)` | `string, number?` | `Object` | 获取使用详情 |
| `getStats(budget?)` | `number?` | `Object` | 获取全局统计 |

**事件**：

| 事件名 | 载荷 | 触发时机 |
|--------|------|----------|
| `token-warning-80` | `{sessionId, tokensUsed, budget}` | 使用量达80% |
| `token-warning-95` | `{sessionId, tokensUsed, budget}` | 使用量达95% |
| `token-exhausted` | `{sessionId, tokensUsed, budget}` | 使用量达100% |
| `token-reset` | `{sessionId}` | 会话数据清除时 |

**配置项**：

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `defaultBudget` | `DEFAULT_TOKEN_BUDGET` | 全局Token预算上限 |
| `maxSessions` | `1000` | 最大会话数，超限LRU淘汰 |

**使用示例**：

```javascript
const TokenManager = require('./src/runtime/model/token-manager');

const tm = new TokenManager({ defaultBudget: 1000000, maxSessions: 500 });

// 累加Token
tm.store('session-1', 5000);
tm.store('session-1', 3000);

// 添加分类明细
tm.addBreakdown('session-1', 'input', 3000);
tm.addBreakdown('session-1', 'output', 4000);
tm.addBreakdown('session-1', 'toolCall', 1000);

// 验证预算状态
const validation = tm.validate('session-1');
console.log(validation);
// { sessionId: 'session-1', tokensUsed: 8000, budget: 1000000,
//   ratio: 0.008, warning80: false, warning95: false, exhausted: false }

// 格式化
console.log(tm.formatTokens(1500000)); // '1.50M'
console.log(tm.parseFormatted('1.5M')); // 1500000

// 监听预警
tm.on('token-warning-80', (data) => {
  console.log(`会话 ${data.sessionId} Token使用达80%: ${data.tokensUsed}/${data.budget}`);
});
```

### 3.2 ModelSelector

**职责与定位**：模型智能选择器。根据Skill类型、任务复杂度和预算状态自动选择最优模型，支持Skill映射、复杂度评分、预算降级和成本追踪。

**关键API**：

| 方法 | 参数 | 返回值 | 说明 |
|------|------|--------|------|
| `selectModel(skillId, context?)` | `string, Object?` | `Object` | 自动选择最优模型 |
| `recordUsage(skillId, model, tokens?, cost?, sessionId?)` | 多参数 | `void` | 记录使用情况 |
| `attachTokenManager(tokenManager)` | `TokenManager` | `void` | 绑定TokenManager |
| `resetBudgetFlags()` | — | `void` | 重置预算约束标志 |
| `getCostEstimate(skillId)` | `string` | `Object` | 获取Skill预估成本 |
| `getTier(model)` | `string` | `string` | 查询模型层级 |
| `getStats()` | — | `Object` | 获取运行统计 |
| `isHealthy()` | — | `boolean` | 健康检查 |

**selectModel返回值**：

```javascript
{ model: 'gpt-4o', reason: '架构决策影响全局，需要顶级推理', tier: 'premium', source: 'skill-mapping' }
```

**事件**：

| 事件名 | 载荷 | 触发时机 |
|--------|------|----------|
| `model-downgraded` | `{skillId, from, to, reason}` | 模型降级时 |
| `usage-recorded` | `{skillId, model, tokens, cost}` | 使用记录时 |
| `budget-recovered` | `{wasConstrained, wasCritical, wasExhausted}` | 预算恢复时 |

**模型层级体系**：

| 层级 | 模型 | 成本乘数 | 适用场景 |
|------|------|----------|----------|
| `premium` | gpt-4o, claude-3-opus, deepseek-v3 | 1.0 | 架构设计、调试、安全审计 |
| `standard` | gpt-4o-mini, claude-3-sonnet | 0.15 | 编码实现、代码审查、自反思 |
| `economy` | gpt-3.5-turbo, deepseek-chat | 0.02 | 测试执行、部署、文档生成 |

**降级策略**：

- 预算80%（constrained）：premium → standard
- 预算95%（critical）：premium → standard, standard → economy
- 预算100%（exhausted）：强制economy
- 重试请求：economy → standard（升级）
- 简单任务：premium → standard

**使用示例**：

```javascript
const ModelSelector = require('./src/runtime/model/model-selector');
const TokenManager = require('./src/runtime/model/token-manager');

const selector = new ModelSelector({
  defaultModel: 'gpt-4o',
  enableAutoDowngrade: true,
  costBudgetPerSession: 10,
});

const tm = new TokenManager();
selector.attachTokenManager(tm);

// Skill映射选择
const result = selector.selectModel('architecture-design');
// { model: 'gpt-4o', reason: '架构决策影响全局，需要顶级推理', tier: 'premium', source: 'skill-mapping' }

// 复杂度评分选择
const result2 = selector.selectModel('custom-skill', { complexityScore: 0.8 });
// { model: 'gpt-4o', reason: 'Selected by complexity score: 0.80', tier: 'premium', source: 'complexity-based' }

// 记录使用
selector.recordUsage('architecture-design', 'gpt-4o', 5000, 0.05, 'session-1');

// 成本估算
const estimate = selector.getCostEstimate('tdd-implement');
// { model: 'gpt-4o-mini', tier: 'standard', costMultiplier: 0.15, estimatedCostPer1kTokens: 0.0015 }
```

### 3.3 EmbeddingService

**职责与定位**：文本向量化服务。支持本地哈希嵌入、OpenAI嵌入（预留）和预计算嵌入（预留），内置LRU缓存与余弦相似度计算。

**关键API**：

| 方法 | 参数 | 返回值 | 说明 |
|------|------|--------|------|
| `embed(text)` | `string` | `number[]` | 文本转向量 |

### 3.4 TriAttention

**职责与定位**：三重注意力权重计算器。综合位置、重要性和时效性三维度估算上下文条目注意力，裁剪低注意力条目以适配Token预算，支持Pre-RoPE空间三角级数校准。

**关键API**：

| 方法 | 参数 | 返回值 | 说明 |
|------|------|--------|------|
| `optimize(contextWindow, budget)` | `Object, Object` | `Object` | 优化上下文窗口 |
| `estimateAttention(entry, position, total)` | `Object, number, number` | `number` | 估算单条注意力 |
| `estimateAttentionAsync(entry, position, total)` | 同上 | `Promise<number>` | 异步估算 |
| `calibrate(qVectors, kVectors)` | `number[][], number[][]` | `Object` | 校准Q/K聚类中心 |
| `getCalibrationStats()` | — | `Object` | 校准统计 |
| `attachComputeAccelerator(accelerator)` | `ComputeAccelerator` | `this` | 绑定计算加速器 |
| `getStats()` | — | `Object` | 运行统计 |

**optimize返回值**：

```javascript
{
  optimized: [/* 保留的条目 */],
  pruned: [/* 裁剪的条目 */],
  tokensSaved: 1500,
  compressionRatio: 0.65
}
```

**事件**：

| 事件名 | 载荷 | 触发时机 |
|--------|------|----------|
| `optimized` | `{optimized, pruned, tokensSaved, compressionRatio}` | 优化完成时 |

**配置项**：

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `attentionThreshold` | `0.3` | 注意力阈值，低于此值的条目被裁剪 |
| `maxContextEntries` | `500` | 最大上下文条目数 |
| `recencyDecay` | `0.95` | 时效性衰减因子 |
| `enablePreRopeScoring` | `false` | 是否启用Pre-RoPE评分 |
| `calibrationCenter` | `null` | 校准中心配置 |
| `magnitudeWeight` | `0.5` | 向量幅度权重 |
| `concentrationThreshold` | `0.8` | 集中度阈值 |

**注意力计算公式**：

- 基础模式：`attention = sin(π × position / total) × importance × recency`
- Pre-RoPE模式：`attention = (distWeight × distanceScore + magWeight × magnitudeScore) × importance × recency`

**使用示例**：

```javascript

// 优化上下文窗口
const result = ta.optimize(
  {
    entries: [
      { content: '系统提示', importance: 0.9, recency: 0.3 },
      { content: '用户问题', importance: 0.8, recency: 1.0 },
      { content: '历史对话1', importance: 0.3, recency: 0.1 },
    ]
  },
  { maxTokens: 2000, reservedTokens: 500 }
);

// 校准
const calibration = ta.calibrate(queryVectors, keyVectors);
// { qCenter: [...], kCenter: [...], qConcentration: 0.85, kConcentration: 0.72 }
```

### 3.5 KVCacheManager

**职责与定位**：KV缓存压缩管理器。基于TriAttention校准的四维评分剪枝（距离偏好+向量幅度+时效性+访问频率），支持自适应权重调整，实现10倍+显存压缩。

**关键API**：

| 方法 | 参数 | 返回值 | 说明 |
|------|------|--------|------|
| `set(key, value, metadata?)` | `string, *, Object?` | `boolean` | 写入缓存 |
| `get(key)` | `string` | `*\|null` | 获取缓存值 |
| `has(key)` | `string` | `boolean` | 检查键是否存在 |
| `delete(key)` | `string` | `boolean` | 删除缓存条目 |
| `calibrateFromTriAttention()` | — | `void` | 从TriAttention校准调整权重 |
| `getStats()` | — | `Object` | 缓存统计 |

**事件**：

| 事件名 | 载荷 | 触发时机 |
|--------|------|----------|
| `pruned` | `{pruned, remaining, ratio}` | 缓存剪枝时 |

**配置项**：

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `maxCacheSize` | `10000` | 缓存最大条目数 |
| `compressionRatio` | `0.1` | 剪枝压缩比例 |
| `enableAdaptiveCompression` | `true` | 自适应压缩 |
| `headConcentrationThreshold` | `0.8` | 头部集中度阈值 |
| `magnitudeWeight` | `0.5` | 向量幅度权重 |
| `pruningBatchSize` | `100` | 剪枝批量大小 |

**四维评分公式**：

```
score = adaptiveDistWeight × distanceScore
      + adaptiveMagWeight × magnitudeScore
      + 0.1 × recencyScore
      + 0.1 × accessScore
```

**使用示例**：

```javascript
const KVCacheManager = require('./src/runtime/model/kv-cache-manager');
const TriAttention = require('./src/runtime/model/tri-attention');

const ta = new TriAttention();
const kvCache = new KVCacheManager(ta, { maxCacheSize: 5000, compressionRatio: 0.1 });

// 写入缓存
kvCache.set('key-1', { data: 'value' }, { source: 'inference' });
kvCache.set('key-2', [1, 2, 3]);

// 读取缓存
const val = kvCache.get('key-1');

// 从TriAttention校准调整权重
kvCache.calibrateFromTriAttention();

// 监听剪枝事件
kvCache.on('pruned', (data) => {
  console.log(`剪枝: 删除${data.pruned}条, 剩余${data.remaining}条, 压缩比${data.ratio}`);
});
```

**职责与定位**：结构化思维链引擎。6种步骤类型（observe/analyze/hypothesize/verify/conclude/reflect），4种深度级别，支持回溯和收敛检测。

| `addStep(chainId, stepData)` | `string, Object` | `Object` | 添加步骤 |
| `backtrack(chainId, toStepIndex)` | `string, number` | `Object` | 回溯到指定步骤 |
| `concludeChain(chainId, conclusion)` | `string, string` | `Object` | 结束思维链 |
| `getChain(chainId)` | `string` | `Object\|null` | 获取思维链 |
| `getActiveChain()` | — | `Object\|null` | 获取活跃链 |
| `getChainSteps(chainId)` | `string` | `Object[]` | 获取步骤列表 |
| `formatChainAsMarkdown(chainId)` | `string` | `string` | 格式化为Markdown |
| `attachQualityScorer(scorer)` | `QualityScorer` | `void` | 绑定质量评分器 |
| `attachConvergenceDetector(detector)` | `ConvergenceDetector` | `void` | 绑定收敛检测器 |
| `attachMemoryStore(store)` | `MemoryStore` | `void` | 绑定记忆存储 |
| `getStats()` | — | `Object` | 运行统计 |

**步骤类型**：

| 类型 | 说明 |
|------|------|
| `observe` | 观察：收集信息和数据 |
| `analyze` | 分析：拆解和评估 |
| `hypothesize` | 假设：提出假设 |
| `verify` | 验证：检验假设 |
| `conclude` | 结论：得出结论 |
| `reflect` | 反思：回顾和改进 |

**深度级别**：

| 级别 | 最大步骤数 | 适用场景 |
|------|-----------|----------|
| `quick` | 3 | 快速判断 |
| `standard` | 5 | 常规推理 |
| `deep` | 8 | 复杂分析 |
| `intensive` | 12 | 深度推理 |

**事件**：

| 事件名 | 载荷 | 触发时机 |
|--------|------|----------|
| `chain-started` | `{chainId, task}` | 链启动时 |
| `step-added` | `{chainId, stepIndex, type}` | 步骤添加时 |
| `chain-backtracked` | `{chainId, toStepIndex}` | 回溯时 |
| `chain-completed` | `{chainId, conclusion}` | 链完成时 |

**使用示例**：

```javascript
const ChainOfThought = require('./src/runtime/thought/chain-of-thought');

const cot = new ChainOfThought();

// 启动思维链
const { chainId } = cot.startChain('分析系统性能瓶颈', { depth: 'deep' });

// 添加步骤
cot.addStep(chainId, { type: 'observe', content: 'API响应时间P99达5秒' });
cot.addStep(chainId, { type: 'analyze', content: '数据库查询占比80%耗时' });
cot.addStep(chainId, { type: 'hypothesize', content: '缺少索引导致全表扫描' });
cot.addStep(chainId, { type: 'verify', content: 'EXPLAIN确认全表扫描', passed: true });

// 回溯（假设验证失败）
cot.backtrack(chainId, 2); // 回到分析步骤

// 结论
cot.concludeChain(chainId, '添加复合索引后查询性能提升10倍');

// 格式化
const md = cot.formatChainAsMarkdown(chainId);
```

## 6. 最佳实践与注意事项

### 6.1 模型子系统最佳实践

1. **Token预算设置**：根据项目规模合理设置`defaultBudget`，建议小型项目50万、中型项目100万、大型项目500万以上。

2. **模型选择策略**：
   - 始终启用`enableAutoDowngrade`，避免预算耗尽导致任务中断
   - 为自定义Skill配置`skillModelMap`映射，避免所有任务使用默认模型
   - 设置`costBudgetPerSession`防止单会话成本失控

3. **嵌入服务使用**：
   - 生产环境建议增大`cacheMaxSize`（如2000），减少重复计算
   - 向量维度128适用于大多数语义匹配场景，高精度场景可提升至256
   - 批量嵌入时控制`maxBatchSize`，避免内存峰值

4. **注意力优化**：
   - 长上下文场景启用`enablePreRopeScoring`并先调用`calibrate`校准
   - `attentionThreshold`建议0.3~0.5，过低保留太多冗余，过高丢失关键信息
   - 优化后务必检查`compressionRatio`，低于0.3可能过度裁剪

5. **KV缓存管理**：
   - 定期调用`calibrateFromTriAttention()`保持权重与注意力机制同步
   - `compressionRatio`建议0.1（10:1压缩），高精度场景可降至0.05
   - 监听`pruned`事件，异常频繁剪枝可能意味着缓存容量不足

6. **推理缓存**：
   - `ttlMs`根据业务场景设置：实时数据5分钟、稳定知识30分钟
   - `maxSize`建议100~500，过大增加内存压力
   - 对确定性高的查询（如格式转换、固定模板）优先使用缓存

7. **计算加速器**：
   - `auto`模式自动检测GPU，无需手动配置
   - 使用`setFeatureFlags`运行时切换后端，避免重启
   - GPU不可用时自动回退CPU，无需额外处理

### 6.2 思维子系统最佳实践

1. **思维提取**：
   - 5种思维类型中，`INSIGHT`和`DECISION`价值最高，优先保留
   - `CORRECTION`类型是错误预防的重要来源，不可丢弃
   - 提取后立即去重，避免冗余思维占用存储

2. **钻石分级**：
   - DIAMOND级（0.9+）思维可直接作为决策依据
   - POLISHED级（0.75~0.9）需要上下文验证后使用
   - RAW级（0~0.5）建议定期清理或重新评估

3. **记忆存储选择**：
   - `BrainMemory`：工作记忆，适合短期、高频访问的数据
   - `MemoryStore`：长期知识库，适合持久化、结构化的知识
   - `ThoughtMemoryStore`：思维链存储，适合推理过程记录
   - `KnowledgeGraphStore`：关系型知识，适合实体间依赖和推理

4. **Hermes管道**：
   - 初始化前挂载所有组件，`initialize()`自动布线
   - Recall阶段优先使用`parallel`模式，超时设置5秒
   - Sync阶段推荐`on-event`策略，减少不必要的同步开销
   - Prefetch信号中`phase-change`和`task-affinity`效果最显著

5. **做梦引擎**：
   - `DreamScheduler`默认30分钟间隔，SM-2会根据性能自适应调整
   - 会话结束时调用`onSessionEnd`触发即时做梦
   - `DreamOutcomes`闭环评估是持续改进的关键，务必定义成功标准
   - `DreamBridge`7条规则自动执行，激活后无需手动干预

6. **知识图谱**：
   - 先添加实体再添加关系，确保引用完整
   - `addTriple`是快捷方式，自动创建不存在的实体
   - `inferRelations`传递推理可能产生大量结果，建议限制深度
   - 定期`exportAsTriples`备份，防止数据丢失

7. **外部Provider**：
   - 始终使用`ProviderAdapterBase`子类，不要直接实现`MemoryProviderInterface`
   - `fallbackToLocal: true`确保远程服务不可用时系统继续运行
   - `ProviderHealthChecker`熔断器防止级联故障
   - API密钥通过配置文件传入，禁止硬编码

### 6.3 跨子系统注意事项

1. **EmbeddingService共享**：同一个`EmbeddingService`实例应被BrainMemory、MemoryStore、ThoughtMemoryStore、KnowledgeGraphStore等共享，确保向量空间一致性。

2. **Token预算联动**：`ModelSelector.attachTokenManager(tokenManager)`建立联动后，Token预警自动触发模型降级，无需手动处理。

3. **事件驱动集成**：`DreamBridge`和`MemoryNudge`通过EventBus自动触发，确保EventBus实例全局共享。

4. **关闭顺序**：系统关闭时按以下顺序：DreamBridge.deactivate() → DreamScheduler.stop() → MemoryPipeline关闭 → 各存储flush() → ComputeAccelerator关闭。

5. **容量管理**：所有带容量限制的组件（BoundedMap/BoundedArray/RingBuffer/LRUCache）都有自动淘汰机制，但建议定期监控`getStats()`输出，异常增长可能指示内存泄漏。

6. **并发安全**：多个Agent同时写入同一存储时，使用`ConcurrencyController`或文件级锁避免数据竞争。`MemorySyncCoordinator`的`confidence-merge`策略适合并发写入场景。

7. **持久化策略**：
   - ThoughtMemoryStore和MemoryStore使用防抖持久化（默认1秒间隔）
   - 关键数据变更后手动调用`flush()`确保立即写入
   - SQLite存储使用WAL模式，支持并发读写

8. **性能监控**：定期采集以下指标：
   - TokenManager: `ratio`（预算使用率）
   - ModelSelector: `savingsVsAllPremium`（成本节省率）
   - EmbeddingService: `cacheHits/totalEmbeddings`（缓存命中率）
   - TriAttention: `compressionRatio`（压缩比）
   - InferenceCache: `hitRate`（缓存命中率）
   - MemoryPipeline: 各组件`getStats()`汇总
