## 模块概述

CodeGraph模块实现了代码仓库的依赖关系图谱构建与分析。模块通过扫描项目目录，解析JavaScript文件的`require()`依赖和`module.exports`导出，以及Markdown文件的Wiki链接和标准链接，构建文件级的依赖关系图。核心分析能力包括：依赖图遍历（BFS）、反向依赖查找、孤立文件检测、循环依赖检测（DFS）、模块统计（最大依赖模块排行），以及紧凑视图生成（用于上下文压缩时的Token节省）。

## 融合来源

融合自软件工程中的静态分析（Static Analysis）技术和依赖图（Dependency Graph）理论。模块借鉴了IDE和构建工具中的依赖分析能力，将其轻量化为运行时可用的图谱服务。紧凑视图生成融合了上下文窗口优化思想，将完整的节点信息压缩为单行依赖描述，显著减少Token消耗。

## 使用示例

```javascript
const CodeGraph = require('./src/runtime/infrastructure/code-graph');

const codeGraph = new CodeGraph({
  maxDepth: 8,
  maxFiles: 300,
  ignorePatterns: ['node_modules', '.git', 'dist', '.harness', 'coverage'],
});

const scanResult = codeGraph.scanDirectory('./src');
console.log('Scanned:', scanResult.files, 'files,', scanResult.edges, 'edges');

const depGraph = codeGraph.getDependencyGraph('src/runtime/skill/skill-router.js', 3);
console.log('Dependencies:', depGraph.nodes.length, 'nodes');

const reverseDeps = codeGraph.getReverseDependencies('src/utils/debug-logger.js');

console.log('Circular deps:', stats.circularDependencies.length);
console.log('Largest modules:', stats.largestModules.slice(0, 5));

console.log('Token savings:', compact.tokenSavings);
```

## 核心算法详解

### scanDirectory() 的目录遍历算法

`scanDirectory()` 采用递归深度优先遍历策略，通过内部方法 `_walkDir()` 实现目录树的逐层扫描：

1. **入口校验**：验证 `dirPath` 非空且为字符串类型，否则抛出 `Error`；通过 `path.resolve()` 获取绝对路径后检查目录是否存在，不存在则发射 `scan-error` 事件并返回 `{ files: 0, edges: 0 }`
2. **状态重置**：每次扫描前清空 `_nodes`、`_edges`、`_adjacency`、`_reverseAdjacency` 四个核心数据结构，确保图谱数据的一致性
3. **递归扫描**：`_walkDir(dirPath, opts, depth, visitor)` 以递归方式遍历目录：
   - **深度限制**：`depth > opts.maxDepth` 时立即返回（默认 maxDepth=10），防止目录层级过深导致栈溢出
   - **ignorePatterns 过滤**：`_shouldIgnore()` 对每个目录/文件名进行匹配——支持精确匹配（`name === pattern`）和通配符后缀匹配（`pattern.startsWith('*')`），默认忽略 `node_modules`、`.git`、`dist`、`.harness`
   - **文件扩展名匹配**：仅处理 `opts.fileExtensions` 中列出的扩展名（默认 `.js`、`.json`、`.md`），其他文件类型直接跳过
   - **并发控制**：通过 `maxFiles` 限制（默认500）实现文件数量上限，`visitor` 回调中检查 `fileCount >= opts.maxFiles` 后停止处理
4. **文件处理**：对每个合格文件调用 `_processFile()`，解析依赖/导出/引用并更新图谱数据
5. **完成通知**：扫描完成后记录时间戳 `_scanTime = Date.now()`，发射 `scan-complete` 事件

```
算法伪代码：
function scanDirectory(dirPath, options):
    validate(dirPath)
    resetAllStructures()
    fileCount = 0
    walkDir(dirPath, options, depth=0, visitor=(filePath) => {
        if fileCount >= maxFiles: return
        fileCount++
        processFile(filePath)
    })
    emit('scan-complete', { rootDir, files, edges })
```

### getDependencyGraph() 的BFS依赖图遍历算法

`getDependencyGraph()` 采用广度优先搜索（BFS）从指定文件出发，沿依赖方向逐层扩展，提取依赖子图：

1. **路径规范化**：调用 `_normalizePath()` 将输入路径转换为图谱中存储的相对路径格式（支持反斜杠转换、扩展名补全）
2. **BFS队列初始化**：`queue = [{ path: normalizedPath, currentDepth: 0 }]`，`visited = Set([normalizedPath])`
3. **逐层扩展**：
   - 从队列头部取出节点 `queue.shift()`
   - 将节点路径加入结果集 `nodes`
   - **深度限制剪枝**：`currentDepth >= depth` 时跳过该节点的邻居扩展（默认 depth=3）
   - 从 `_adjacency` 正向邻接表获取所有出边，加入结果边集
   - 对未访问的邻居节点：标记为已访问，入队并深度+1
4. **循环检测**：`visited` 集合确保每个节点仅被访问一次，天然避免BFS中的循环路径
5. **结果组装**：返回 `{ nodes, edges }`，其中 nodes 数组中的每个元素从 `_nodes` Map 获取完整节点信息，若节点不在图谱中则降级为 `{ filePath: p }`

```
算法伪代码：
function getDependencyGraph(filePath, maxDepth=3):
    startPath = normalizePath(filePath)
    queue = [{ path: startPath, depth: 0 }]
    visited = { startPath }
    nodes = [], edges = []
    while queue not empty:
        current = queue.shift()
        nodes.add(current.path)
        if current.depth >= maxDepth: continue  // 剪枝
        for edge in adjacency[current.path]:
            edges.add(edge)
            if edge.to not in visited:
                visited.add(edge.to)
                queue.push({ path: edge.to, depth: current.depth + 1 })
    return { nodes, edges }
```

**时间复杂度**：O(V + E)，其中 V 为子图节点数、E 为子图边数；深度限制将实际遍历范围控制在 O(b^d)，b 为平均分支因子、d 为深度

### detectOrphans() 的孤立文件检测算法

`detectOrphans()` 基于图论中"孤立节点"的判定——在依赖图中既无入边也无出边的节点：

1. **遍历所有节点**：对 `_nodes` Map 中的每个 `[filePath, node]` 条目进行判定
2. **出边判定**：`this._adjacency.has(filePath) && this._adjacency.get(filePath).length > 0`——检查正向邻接表中是否存在以该文件为起点的边
3. **入边判定**：`this._reverseAdjacency.has(filePath) && this._reverseAdjacency.get(filePath).length > 0`——检查反向邻接表中是否存在以该文件为终点的边
4. **孤立条件**：`!hasOutEdges && !hasInEdges`——两者均为 false 时，该文件即为孤立文件

```
算法伪代码：
function detectOrphans():
    orphans = []
    for each [filePath, node] in _nodes:
        hasOutEdges = _adjacency[filePath].length > 0
        hasInEdges = _reverseAdjacency[filePath].length > 0
        if !hasOutEdges and !hasInEdges:
            orphans.add(node)
    return orphans
```

**时间复杂度**：O(V)，仅需遍历所有节点一次；每个节点的入边/出边判定为 O(1)（Map + length 检查）

**设计考量**：利用双向邻接表（`_adjacency` + `_reverseAdjacency`）实现 O(1) 的入边/出边查询，避免了遍历边集的 O(E) 开销

### toCompactView() 的紧凑视图生成算法

`toCompactView()` 将完整的节点信息压缩为单行依赖描述，用于上下文注入时节省Token：

1. **逐节点压缩**：对 `_nodes` Map 中的每个节点：
   - 合并 `dependencies` 和 `references` 为统一的依赖列表 `deps`
   - 若 `deps.length > 0`：生成 `filePath → dep1, dep2, ...` 格式的单行描述
   - 若 `deps.length === 0`：仅保留 `filePath` 本身
2. **Token节省计算**：
   - `fullSize`：累加每个节点 `JSON.stringify(node).length`（完整JSON序列化的字符数）
   - `compactSize`：累加每行压缩描述的 `line.length`
   - **Token估算公式**：`tokenSavings = Math.round((fullSize - compactSize) / 4)`
   - 其中除以4基于英文文本的Token比率近似值（1 Token ≈ 4 字符）
3. **结果字段**：
   - `view`：所有行以换行符连接的完整紧凑视图字符串
   - `lineCount`：行数（等于节点数）
   - `estimatedFullTokens`：`Math.round(fullSize / 4)`——完整视图的估算Token数
   - `estimatedCompactTokens`：`Math.round(compactSize / 4)`——紧凑视图的估算Token数
   - `tokenSavings`：节省的Token数

```
压缩示例：
完整节点: {"filePath":"src/runtime/skill/skill-router.js","dependencies":["./skill-discover-utils","./skill-graph"],...}  (~200字符)
紧凑行:   src/runtime/skill/skill-router.js → ./skill-discover-utils, ./skill-graph  (~80字符)
节省:     ~30 Tokens
```

**压缩率**：典型场景下紧凑视图可将Token消耗降低 50%-70%，具体取决于节点的 exports/references 等冗余字段占比

## 内部数据结构

### _nodes Map结构

核心节点存储，键为文件相对路径（正斜杠格式），值为节点对象：

```
_nodes: Map<string, NodeObject>
```

**NodeObject 结构**：

| 字段 | 类型 | 说明 |
|------|------|------|
| `filePath` | string | 相对于根目录的文件路径（正斜杠） |
| `absolutePath` | string | 文件绝对路径 |
| `extension` | string | 文件扩展名（如 `.js`、`.md`） |
| `dependencies` | string[] | JS文件的require依赖列表（相对路径或模块名） |
| `exports` | string[] | JS文件的导出名称列表 |
| `references` | string[] | MD文件的链接引用列表 |
| `size` | number | 文件内容字符数 |

**来源**：由 `_processFile()` 在扫描阶段创建并写入

### _adjacency Map结构

正向邻接表，存储每个节点的出边信息，用于依赖图正向遍历：

```
_adjacency: Map<string, Array<{ to: string, type: string }>>
```

- 键：文件相对路径
- 值：出边数组，每条边包含目标文件路径 `to` 和边类型 `type`（`'require'` 或 `'reference'`）

**来源**：由 `_addEdge()` 方法维护

### _reverseAdjacency Map结构

反向邻接表，存储每个节点的入边信息，用于反向依赖查询：

```
_reverseAdjacency: Map<string, Array<{ from: string, type: string }>>
```

- 键：文件相对路径
- 值：入边数组，每条边包含源文件路径 `from` 和边类型 `type`

**来源**：由 `_addEdge()` 方法与 `_adjacency` 同步维护

### _edges 数组结构

全局边集，按发现顺序存储所有依赖边：

```
_edges: Array<{ from: string, to: string, type: string }>
```

| 字段 | 类型 | 说明 |
|------|------|------|
| `from` | string | 依赖源文件路径 |
| `to` | string | 依赖目标文件路径 |
| `type` | string | 边类型：`'require'`（JS依赖）或 `'reference'`（MD引用） |

**来源**：由 `_addEdge()` 方法追加，与 `_adjacency` / `_reverseAdjacency` 同步写入

### 辅助字段

| 字段 | 类型 | 说明 |
|------|------|------|
| `_scanTime` | number \| null | 最近一次扫描完成的时间戳（`Date.now()`） |
| `_rootDir` | string \| null | 扫描根目录的绝对路径，用于模块路径解析 |
| `_config` | object | 合并后的配置对象（DEFAULT_CONFIG + 用户options） |

## 错误处理与防御机制

### 参数校验

- **`scanDirectory(dirPath, options)`**：`dirPath` 为空或非字符串时抛出 `Error('dirPath is required and must be a string')`，在方法入口处进行类型守卫
- **`getDependencyGraph(filePath, maxDepth)`**：`maxDepth` 为 `null`/`undefined` 时通过 `maxDepth ?? 3` 降级为默认值3
- **`getReverseDependencies(filePath)`**：`_reverseAdjacency.get(normalizedPath)` 返回 `undefined` 时通过 `?? []` 降级为空数组

### 文件系统容错

- **目录读取失败**：`_walkDir()` 中 `fs.readdirSync()` 包裹在 `try-catch` 中，失败时通过 `debug()` 记录日志并静默返回（不中断整体扫描）
- **文件读取失败**：`_processFile()` 中 `fs.readFileSync()` 包裹在 `try-catch` 中，失败时通过 `debug()` 记录日志并跳过该文件
- **目录不存在**：`scanDirectory()` 中 `fs.existsSync()` 检查目录存在性，不存在时发射 `scan-error` 事件并返回 `{ files: 0, edges: 0 }`（不抛出异常）

### 路径解析防御

- **`_normalizePath()`**：多级降级策略——先精确匹配原始路径，再尝试反斜杠转正斜杠，最后尝试补全扩展名（遍历 `fileExtensions`），确保路径规范化后能在 `_nodes` 中找到对应节点
- **`_resolveModulePath()`**：模块路径解析时依次尝试——精确匹配 → 补全扩展名 → `index.js` 目录入口，全部未命中时返回原始解析路径（不返回 null）

### 数据访问防御

- **邻接表空值守卫**：`_adjacency.get(currentPath) ?? []` 和 `_reverseAdjacency.get(normalizedPath) ?? []` 使用空值合并运算符，防止 Map 查询返回 `undefined` 导致后续 `.length` 或迭代报错
- **节点降级**：`getDependencyGraph()` 中 `this._nodes.get(p) || { filePath: p }`，当节点不在图谱中时降级为仅含 `filePath` 的最小对象，避免返回 `undefined`
- **`getReverseDependencies()`**：`this._nodes.get(dep.from) || null`，节点不存在时返回 `null` 而非 `undefined`

### 关闭状态防护

- 所有公共方法（`scanDirectory`、`getDependencyGraph`、`getReverseDependencies`、`detectOrphans`、`getModuleStats`、`toCompactView`）入口均调用 `this.guardShutdown()`，在实例已关闭时阻止操作
- `_onShutdown()` 清空所有内部数据结构（`_nodes.clear()`、`_edges = []`、`_adjacency.clear()`、`_reverseAdjacency.clear()`），防止关闭后数据泄漏

### 正则表达式安全

- 所有正则表达式（`REQUIRE_RE`、`EXPORTS_ASSIGN_RE`、`EXPORTS_PROP_RE`、`MD_WIKI_LINK_RE`、`MD_MARKDOWN_LINK_RE`）均为全局正则（带 `g` 标志），使用前显式重置 `lastIndex = 0`，防止状态残留导致的匹配错误

## 性能优化策略

### BFS剪枝

- **深度限制剪枝**：`getDependencyGraph()` 中 `currentDepth >= depth` 时跳过邻居扩展，将BFS的搜索空间从 O(V+E) 限制为 O(b^d)，其中 b 为平均分支因子、d 为指定深度（默认3）
- **visited集合**：BFS遍历中使用 `visited` Set 确保每个节点仅入队一次，避免重复处理和无限循环

### 双向邻接表

- **正向邻接表 `_adjacency`**：O(1) 查询出边，用于 `getDependencyGraph()` 的BFS扩展
- **反向邻接表 `_reverseAdjacency`**：O(1) 查询入边，用于 `getReverseDependencies()` 和 `detectOrphans()`
- **空间换时间**：虽然 `_edges` 数组与 `_adjacency` / `_reverseAdjacency` 存在数据冗余，但避免了每次查询时遍历边集的 O(E) 开销

### 文件数量限制

- `maxFiles`（默认500）在 `visitor` 回调中强制执行，当 `fileCount >= opts.maxFiles` 时停止处理新文件，防止大型仓库导致扫描时间过长和内存占用过高

### 深度限制

- `maxDepth`（默认10）在 `_walkDir()` 递归入口处检查，防止目录层级过深导致递归栈溢出

### 增量扫描预留

- 当前实现中 `scanDirectory()` 每次调用会清空所有数据结构后全量重建。模块预留了增量扫描的扩展点：
  - `_nodes.clear()` / `_edges = []` 等重置操作集中在 `scanDirectory()` 开头，可条件化跳过
  - `_processFile()` 是独立的文件处理单元，可单独调用于增量更新
  - `_addEdge()` 是独立的边添加方法，支持追加式构建

### 缓存策略

- **路径规范化缓存**：`_normalizePath()` 依赖 `_nodes` Map 的 O(1) 查询，多次调用同一路径时无需重复计算
- **扫描时间戳**：`_scanTime` 记录最近扫描时间，可用于缓存失效判断（外部模块可据此决定是否需要重新扫描）
- **模块路径解析缓存**：`_resolveModulePath()` 依赖 `_nodes` Map 查询已扫描文件，避免重复的文件系统访问

## R58修复记录

> v2.7.139 新增

### 问题描述

在代码审查中发现，模块内多处对外部数据（Map查询结果、正则匹配结果、文件系统返回值）的访问缺少 null/undefined 守卫，在边界条件下可能导致运行时异常。

### 修复内容

1. **邻接表空值合并**：`_adjacency.get(currentPath) ?? []` 和 `_reverseAdjacency.get(normalizedPath) ?? []`，统一使用 `??` 运算符替代直接访问，防止 Map 查询返回 `undefined` 时触发 `.length` 或迭代错误
2. **节点降级访问**：`this._nodes.get(p) || { filePath: p }` 和 `this._nodes.get(dep.from) || null`，节点不存在时提供最小降级对象而非 `undefined`
3. **正则 lastIndex 重置**：所有全局正则在使用前显式设置 `lastIndex = 0`，防止多次调用间状态残留
4. **错误消息安全拼接**：`err && err.message ? err.message : String(err)`，防止 `err` 为 `null`/`undefined` 时 `.message` 访问异常

### 防御性编程规范

此次修复确立了以下防御性编程规范，适用于所有运行时模块：

| 规范 | 模式 | 示例 |
|------|------|------|
| Map查询空值守卫 | `map.get(key) ?? defaultValue` | `_adjacency.get(path) ?? []` |
| 对象降级访问 | `obj || fallback` | `_nodes.get(p) \|\| { filePath: p }` |
| 全局正则重置 | `RE.lastIndex = 0` | `REQUIRE_RE.lastIndex = 0` |
| 错误消息安全提取 | `err && err.message ? err.message : String(err)` | debug日志中的错误拼接 |
| 方法入口类型校验 | `typeof param !== 'string'` → throw | `scanDirectory()` 的 dirPath 校验 |
| 关闭状态防护 | `this.guardShutdown()` | 所有公共方法入口 |
