# 模块详解-工作流核心模块群

> 源码路径：`src/runtime/workflow/`
> 模块数量：6
> 核心职责：工作流核心服务——DAG编排/模板复用/人工审批/计划持久化/RAG检索/Hook执行

---

## 模块群概述

工作流核心模块群是工作流子系统（`src/runtime/workflow/`）的核心服务层，负责从**DAG编排**、**模板复用**、**人工审批**、**计划持久化与防漂移**、**RAG检索增强**和**可编程Hook执行**六个维度为工作流引擎提供基础运行时支撑。该模块群包含6个核心模块，均继承自 `EventEmitter`，是 `PhaseOrchestrator`、`PipelineExecutor`、`GoalExecutor` 等上层编排模块的运行时依赖。

工作流核心模块群的设计理念是：**将工作流的编排结构、复用模式、审批管控、状态持久化、上下文检索和生命周期拦截解耦为独立服务，使上层编排器可以按需组合，而不必关心底层实现细节**。它通过 `WorkflowDAG` 提供有向无环图编排与拓扑执行，通过 `WorkflowTemplate` 提供参数化模板复用，通过 `HumanApprovalGate` 提供人工审批门控，通过 `PlanPersistence` 提供计划持久化与防漂移注入，通过 `RAGPipeline` 提供文档检索增强生成，通过 `ProgrammableHookExecutor` 提供可编程钩子执行与监控，共同构成工作流引擎的"六大核心服务"。

## 模块清单

| 模块 | 源文件 | 说明 |
|------|--------|------|
| WorkflowDAG | workflow-dag.js | 工作流DAG：有向无环图编排、环检测、拓扑排序、就绪节点计算、深化节点注入与后继重连 |
| WorkflowTemplate | workflow-template.js | 工作流模板管理器：参数化模板创建/存储/实例化、变量插值与注入消毒、磁盘持久化 |
| HumanApprovalGate | human-approval-gate.js | 人工审批门：审批请求生命周期管理、超时自动拒绝、有界待审队列、环形缓冲历史 |
| PlanPersistence | plan-persistence.js | 计划持久化管理器：执行计划CRUD、版本快照追踪、防漂移上下文注入、磁盘持久化与内存缓存 |
| RAGPipeline | rag-pipeline.js | RAG检索增强管道：文档摄入/分块/嵌入/向量检索、目录批量摄入、GraphRAG融合 |
| ProgrammableHookExecutor | programmable-hook-executor.js | 可编程钩子执行器：三种钩子类型（builtin/function/shell）、顺序执行阻塞中断、Shell沙箱、监控子系统 |

## 共同设计模式

### 1. EventEmitter继承

6个模块均继承自 `EventEmitter`，可直接 `emit`/`on` 进行事件通知：

| 模块 | 事件机制 |
|------|---------|
| WorkflowDAG | `node-started`、`node-completed`、`node-failed`、`deepening-node-added`、`deepening-partial-rewire` |
| WorkflowTemplate | 无自定义事件 |
| HumanApprovalGate | `approval-requested`、`approval-approved`、`approval-rejected`、`approval-timeout` |
| PlanPersistence | `plan-created`、`plan-updated`、`task-status-updated` |
| RAGPipeline | `document-indexed`、`document-removed`、`query-executed`、`error` |
| ProgrammableHookExecutor | `hook-registered`、`hook-unregistered`、`hook-executed`、`hook-rejected`、`hook-error`、`hook-late-rejection`、`slow-hook-detected` |

### 2. withShutdown混入

6个模块均通过 `withShutdown` 混入支持优雅关闭，实现 `_onShutdown()` 方法清理内部资源：

| 模块 | 关闭行为 |
|------|---------|
| WorkflowDAG | 清空节点和邻接表 |
| WorkflowTemplate | 持久化后清空模板Map |
| HumanApprovalGate | 拒绝所有待审批请求并清空 |
| PlanPersistence | 清空内存缓存和文件锁 |
| RAGPipeline | 清空文档/分块，关闭EmbeddingService和CausalVectorIndex |
| ProgrammableHookExecutor | 清理监控定时器，清空钩子注册和监控数据 |

### 3. 容量保护

所有带容量限制的模块在达到上限时执行淘汰策略：

| 模块 | 容量限制 | 淘汰策略 |
|------|---------|---------|
| WorkflowDAG | `MAX_DAG_NODES`（500）、`MAX_EDGES_PER_NODE`（50） | 拒绝新增 |
| WorkflowTemplate | `_maxTemplates`（200） | 拒绝新增 |
| HumanApprovalGate | `_maxPending`（200）、`_maxHistory`（500） | 拒绝新增/FIFO淘汰 |
| PlanPersistence | `_maxPlans`（50）、`_maxVersions`（10） | 淘汰最旧计划/版本文件 |
| RAGPipeline | `MAX_DOCUMENTS`（500）、`MAX_CHUNKS`（50000） | 淘汰最旧文档 |
| ProgrammableHookExecutor | `MAX_HOOKS_PER_EVENT`（50）、`MAX_TOTAL_HOOKS`（500） | 拒绝注册 |

## WorkflowDAG详解

### 职责概述

工作流有向无环图，管理工作流节点的依赖边、插入时环检测、拓扑排序、就绪节点计算（支持并行执行）、深化推理节点注入与后继自动重连，以及节点状态追踪（pending/running/completed/failed）。

### 构造函数参数

```javascript
new WorkflowDAG()
```

无参数。创建空的节点和邻接表Map。

### 核心方法

#### `addNode(id, config)`

添加工作流节点到DAG。

- **参数**：
  - `id` (`string`) — 节点唯一标识
  - `config` (`object`) — 节点配置
    - `config.phase` (`string`, 可选) — 执行阶段
    - `config.agent` (`string`, 可选) — 执行Agent
    - `config.skill` (`string`, 可选) — 执行技能
    - `config.deepening` (`object`, 可选) — 深化推理配置
- **返回值**：`boolean` — 是否添加成功
- **说明**：重复ID、节点数达到上限（500）时返回 `false`

#### `addEdge(from, to)`

添加依赖边，从 `from` 指向 `to`，表示 `to` 依赖 `from`。

- **参数**：
  - `from` (`string`) — 依赖源节点ID
  - `to` (`string`) — 依赖目标节点ID
- **返回值**：`boolean` — 是否添加成功
- **说明**：自环、已存在边、单节点边数达到上限（50）、插入后形成环时返回 `false`

#### `getReadyNodes()`

获取就绪节点（所有依赖已完成的pending节点）。

- **参数**：无
- **返回值**：`{ ready: Array, dependencyFailed: string[] }` — 就绪节点数组和依赖失败的节点ID列表
- **说明**：依赖失败的pending节点ID收集到 `dependencyFailed` 中，可传给 `markDependencyFailed()` 批量标记

#### `markDependencyFailed(nodeIds)`

将依赖失败的pending节点标记为failed。

- **参数**：`nodeIds` (`string[]`) — 待标记的节点ID数组
- **返回值**：`string[]` — 实际被标记的节点ID数组
- **说明**：标记后发射 `node-failed` 事件

#### `startNode(id)`

标记节点为运行中。

- **参数**：`id` (`string`) — 节点ID
- **返回值**：`boolean` — 是否标记成功
- **说明**：节点状态必须为 `pending`，标记后发射 `node-started` 事件

#### `completeNode(id, result)`

标记节点为已完成。

- **参数**：
  - `id` (`string`) — 节点ID
  - `result` (`any`, 可选) — 节点执行结果
- **返回值**：`boolean` — 是否标记成功
- **说明**：节点状态必须为 `running`，标记后发射 `node-completed` 事件

#### `failNode(id, error)`

标记节点为失败。

- **参数**：
  - `id` (`string`) — 节点ID
  - `error` (`string`, 可选) — 错误信息
- **返回值**：`boolean` — 是否标记成功
- **说明**：节点状态必须为 `running`，标记后发射 `node-failed` 事件

#### `topologicalSort()`

对DAG进行拓扑排序。

- **参数**：无
- **返回值**：`string[] | null` — 排序后的节点ID数组，存在环时返回 `null`
- **说明**：采用Kahn算法（BFS），基于入度表实现

#### `addDeepeningNode(parentId, deepeningConfig)`

添加深化推理节点，自动重连后继节点。

- **参数**：
  - `parentId` (`string`) — 父节点ID
  - `deepeningConfig` (`object`, 可选) — 深化配置
    - `deepeningConfig.agent` (`string`, 可选) — 执行Agent
    - `deepeningConfig.iteration` (`number`, 可选) — 迭代序号
    - `deepeningConfig.depthLevel` (`string`, 可选) — 深度级别
    - `deepeningConfig.qualityScore` (`number`, 可选) — 质量评分
    - `deepeningConfig.iterationCount` (`number`, 可选) — 迭代次数
- **返回值**：`string | null` — 新节点ID，添加失败返回 `null`
- **说明**：同一父节点最多10次深化；新节点自动插入父节点与后继之间，不会形成环的后继保持原边

#### `getDeepeningNodes(parentId)`

获取深化推理节点，可按父节点ID过滤。

- **参数**：`parentId` (`string`, 可选) — 父节点ID，不传则返回所有深化节点
- **返回值**：`Array<object>` — 深化节点数组

#### `getDeepeningChain(parentId)`

获取从指定节点开始的深化推理链。

- **参数**：`parentId` (`string`) — 起始父节点ID
- **返回值**：`Array<object>` — 深化链节点数组
- **说明**：沿前向邻接表遍历，仅跟踪含 `deepening` 属性的节点，带环检测

#### `getDeepeningStats()`

获取深化推理统计信息。

- **参数**：无
- **返回值**：`{ totalDeepeningNodes: number, totalDeepenedTasks: number, totalIterations: number, avgIterationsPerTask: number }`

#### `isComplete()`

检查所有节点是否已完成（completed或failed）。

- **返回值**：`boolean`

#### `hasFailures()`

检查是否存在失败节点。

- **返回值**：`boolean`

#### `getFailedNodes()`

获取所有失败节点。

- **返回值**：`Array<object>` — 失败节点数组

#### `getNode(id)`

获取指定节点。

- **参数**：`id` (`string`) — 节点ID
- **返回值**：`object | null` — 节点对象

#### `getAllNodes()`

获取所有节点。

- **返回值**：`Array<object>` — 节点数组

#### `getEdges()`

获取所有依赖边。

- **返回值**：`Array<{ from: string, to: string }>` — 边数组

#### `getStats()`

获取节点状态统计信息。

- **返回值**：`{ total: number, pending: number, running: number, completed: number, failed: number }`

#### `isHealthy()`

健康检查。

- **返回值**：`boolean` — DAG中是否存在节点

#### `static fromWorkflowDef(definition)`

从工作流定义对象创建DAG实例。

- **参数**：`definition` (`object`) — 工作流定义
  - `definition.steps` (`Array<object>`) — 步骤定义数组，每步含 `id`、`phase`、`agent`、`skill`、`needs` 字段
- **返回值**：`WorkflowDAG` — 构建的DAG实例
- **说明**：遇到重复步骤ID时抛出 `HarnessError('DUPLICATE_STEP')`

### 事件列表

| 事件名 | 触发条件 | 数据 |
|--------|---------|------|
| `node-started` | 节点标记为运行中 | `{ id, node }` |
| `node-completed` | 节点标记为已完成 | `{ id, node }` |
| `node-failed` | 节点标记为失败 | `{ id, node, error }` |
| `deepening-node-added` | 深化节点添加成功 | `{ parentId, deepeningId, iteration }` |
| `deepening-partial-rewire` | 深化节点部分后继重连 | `{ parentId, deepeningId, rewired, bypassed }` |

### 配置常量

| 常量 | 值 | 说明 |
|------|-----|------|
| `MAX_DAG_NODES` | 500 | DAG最大节点数 |
| `MAX_EDGES_PER_NODE` | 50 | 单节点最大边数 |

### 使用示例

```javascript
const WorkflowDAG = require('./src/runtime/workflow/workflow-dag');

const dag = new WorkflowDAG();

dag.on('node-completed', ({ id, node }) => {
  console.log(`节点完成: ${id}`);
});

dag.addNode('step1', { phase: 'planning', agent: 'analyst', skill: 'brainstorming' });
dag.addNode('step2', { phase: 'planning', agent: 'lead', skill: 'requirement-analysis' });
dag.addEdge('step1', 'step2');

const { ready } = dag.getReadyNodes();
dag.startNode('step1');
dag.completeNode('step1', { summary: '需求探索完成' });

const sorted = dag.topologicalSort();
console.log('拓扑排序:', sorted);
console.log('统计:', dag.getStats());
```

### 与其他模块的交互关系

| 模块 | 交互方式 |
|------|---------|
| PhaseOrchestrator | 编排器使用DAG管理工作流步骤的依赖关系和执行顺序 |

## WorkflowTemplate详解

### 职责概述

工作流模板管理器，创建、存储和实例化参数化工作流模板。模板包含有序步骤，步骤的 `goal` 和 `context` 字段支持 `{{variable}}` 占位符。插入值经过消毒处理防止注入，模板通过原子写入持久化到磁盘，启动时自动恢复。

### 构造函数参数

```javascript
new WorkflowTemplate(projectRoot)
```

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `projectRoot` | string | — | 项目根目录路径（必需） |

### 核心方法

#### `create(name, definition)`

创建工作流模板并持久化到磁盘。

- **参数**：
  - `name` (`string`) — 模板名称（唯一标识）
  - `definition` (`object`) — 模板定义
    - `definition.description` (`string`, 可选) — 模板描述
    - `definition.version` (`string`, 可选) — 模板版本
    - `definition.steps` (`Array<object>`) — 模板步骤列表，每步含 `goal` 和 `context` 字段
    - `definition.variables` (`Array<object>`, 可选) — 模板变量定义列表
- **返回值**：`object | null` — 创建的模板对象，参数无效或达到上限时返回 `null`

#### `get(name)`

获取指定名称的模板。

- **参数**：`name` (`string`) — 模板名称
- **返回值**：`object | null` — 模板对象

#### `list()`

列出所有模板的深拷贝列表。

- **返回值**：`Array<object>` — 模板对象数组

#### `instantiate(name, variables)`

实例化模板，将步骤中的 `{{variable}}` 占位符替换为传入的变量值。

- **参数**：
  - `name` (`string`) — 模板名称
  - `variables` (`object`, 可选) — 变量键值对
- **返回值**：`object | null` — 实例化结果，含 `templateName`、`steps`、`instantiatedAt`，模板不存在时返回 `null`
- **说明**：插入值经过 `_sanitizeValue()` 消毒（移除 `;{}\` 字符），`DANGEROUS_KEYS` 中的键名不替换

#### `remove(name)`

删除指定名称的模板。

- **参数**：`name` (`string`) — 模板名称
- **返回值**：`boolean` — 模板是否存在并被删除

### 变量插值机制

```
{{variable}} 占位符替换流程:
  1. 正则匹配 /\{\{(\w+)\}\}/g
  2. 检查键名是否在 DANGEROUS_KEYS 中 → 是则保留原占位符
  3. 检查 variables 中是否存在该键 → 不存在则保留原占位符
  4. 对值调用 _sanitizeValue() → 移除 ; { } \ 字符
  5. 替换占位符为消毒后的值
```

### 持久化机制

- **存储路径**：`.harness/workflow-templates/templates.json`
- **写入方式**：`writeAtomic()` 原子写入
- **恢复方式**：`JsonStoreRestorer.loadSync()` 启动时加载
- **关闭行为**：`_onShutdown()` 先持久化再清空

### 配置常量

| 常量 | 值 | 说明 |
|------|-----|------|
| `TEMPLATES_DIR` | `'workflow-templates'` | 模板存储目录名 |
| `_maxTemplates` | 200 | 最大模板数 |

### 使用示例

```javascript
const WorkflowTemplate = require('./src/runtime/workflow/workflow-template');

const tmpl = new WorkflowTemplate('/path/to/project');

tmpl.create('code-review-flow', {
  description: '代码审查工作流',
  version: '1.0.0',
  steps: [
    { goal: '审查{{module}}模块代码', context: '关注{{focus_area}}' },
    { goal: '生成审查报告', context: '输出到{{output_dir}}' },
  ],
  variables: [
    { name: 'module', description: '目标模块名' },
    { name: 'focus_area', description: '关注领域' },
    { name: 'output_dir', description: '输出目录' },
  ],
});

const instance = tmpl.instantiate('code-review-flow', {
  module: 'auth',
  focus_area: 'security',
  output_dir: 'reports',
});

console.log(instance.steps[0].goal);
```

| 模块 | 交互方式 |

| PipelineExecutor | 管道执行器基于模板实例化结果构建执行管道 |
| CommandRouter | 斜杠命令通过模板创建预定义工作流 |

## HumanApprovalGate详解

### 职责概述

人工审批门，管理审批请求的完整生命周期（创建→等待→批准/拒绝/超时），支持可配置超时、有界待审队列溢出保护、环形缓冲历史记录，以及优雅关闭时拒绝所有待审批请求。

### 构造函数参数

```javascript
new HumanApprovalGate(options)
```

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `options.timeout` | number | `DEFAULT_PIPELINE_TIMEOUT_MS` | 审批请求超时毫秒数 |
| `options.maxPending` | number | 200 | 最大待审批请求数 |

### 核心方法

#### `requestApproval(params)`

请求人工审批，创建审批条目并等待审批结果，超时自动拒绝。

- **参数**：`params` (`object`)
  - `params.agentId` (`string`) — 请求审批的Agent ID（必需）
  - `params.operation` (`string`) — 待审批的操作名称（必需）
  - `params.target` (`string`, 可选) — 操作目标
  - `params.reason` (`string`, 可选) — 审批原因
  - `params.metadata` (`object`, 可选) — 附加元数据
- **返回值**：`Promise<{ approved: boolean, requestId?: string, timedOut?: boolean, comment?: string }>` — 审批结果
- **说明**：缺少必需字段时抛出 `HarnessError('MISSING_FIELDS')`；待审队列满时抛出 `HarnessError('CAPACITY_EXCEEDED')`

#### `resolveApproval(requestId, result)`

解析审批请求。

- **参数**：
  - `requestId` (`string`) — 审批请求ID
  - `result` (`object`) — 审批结果
    - `result.approved` (`boolean`) — 是否批准
    - `result.resolver` (`string`, 可选) — 审批人标识
    - `result.comment` (`string`, 可选) — 审批备注
- **返回值**：`boolean` — 解析是否成功，请求不存在时返回 `false`

#### `approve(requestId, resolver, comment)`

批准审批请求。

- **参数**：
  - `requestId` (`string`) — 审批请求ID
  - `resolver` (`string`, 可选, 默认 `'human'`) — 审批人标识
  - `comment` (`string`, 可选) — 审批备注
- **返回值**：`boolean` — 批准是否成功

#### `reject(requestId, resolver, comment)`

拒绝审批请求。

- **参数**：
  - `requestId` (`string`) — 审批请求ID
  - `resolver` (`string`, 可选, 默认 `'human'`) — 审批人标识
  - `comment` (`string`, 可选) — 拒绝备注
- **返回值**：`boolean` — 拒绝是否成功

#### `getPending()`

获取所有待审批请求的摘要列表。

- **返回值**：`Array<{ requestId, agentId, operation, target, reason, createdAt, waitingMs }>` — 待审批列表，含等待时长

#### `getPendingCount()`

获取当前待审批请求数量。

- **返回值**：`number`

#### `getHistory(limit)`

获取审批历史记录。

- **参数**：`limit` (`number`, 可选, 默认 50) — 返回的最大条数（1-500）
- **返回值**：`Array<object>` — 审批历史记录数组

#### `requiresApproval(agentId, operation)`

判断指定Agent和操作是否需要人工审批。

- **参数**：
  - `agentId` (`string`) — Agent ID
  - `operation` (`string`) — 操作名称
- **返回值**：`boolean` — 默认始终返回 `true`

#### `getStats()`

获取审批门统计信息。

- **返回值**：`{ pending: number, totalResolved: number, approved: number, rejected: number, timedOut: number }`

#### `isHealthy()`

健康检查。

- **返回值**：`boolean` — 待审批数未达到上限时返回 `true`

### 审批生命周期

```
requestApproval()
  │
  ├── 生成 requestId (secureId)
  ├── 创建审批条目 (status: pending)
  ├── 发射 approval-requested 事件
  ├── 启动超时定时器
  │
  └── 等待 resolve:
       ├── approve() → status: approved → 发射 approval-approved → resolve({ approved: true })
       ├── reject()  → status: rejected → 发射 approval-rejected → resolve({ approved: false })
       └── timeout   → status: timeout  → 发射 approval-timeout → resolve({ approved: false, timedOut: true })
```

### 事件列表

| 事件名 | 触发条件 | 数据 |
|--------|---------|------|
| `approval-requested` | 审批请求创建 | 审批条目对象 |
| `approval-approved` | 审批请求被批准 | `{ requestId, agentId, resolver }` |
| `approval-rejected` | 审批请求被拒绝 | `{ requestId, agentId, resolver }` |
| `approval-timeout` | 审批请求超时 | `{ requestId, agentId }` |

### 配置常量

| 常量 | 值 | 说明 |
|------|-----|------|
| `DEFAULT_TIMEOUT_MS` | `DEFAULT_PIPELINE_TIMEOUT_MS` | 默认审批超时 |
| `DEFAULT_MAX_PENDING` | 200 | 默认最大待审批数 |
| `_maxHistory` | 500 | 最大历史记录数 |

### 使用示例

```javascript
const HumanApprovalGate = require('./src/runtime/workflow/human-approval-gate');

const gate = new HumanApprovalGate({ timeout: 30000, maxPending: 100 });

gate.on('approval-requested', (entry) => {
  console.log(`审批请求: ${entry.operation} by ${entry.agentId}`);
});

gate.on('approval-timeout', ({ requestId, agentId }) => {
  console.log(`审批超时: ${requestId}`);
});

const result = await gate.requestApproval({
  agentId: 'task-worker-1',
  operation: 'deploy',
  target: 'production',
  reason: '生产环境部署需要人工确认',
});

if (result.approved) {
  console.log('部署已批准');
}
```

### 与其他模块的交互关系

| 模块 | 交互方式 |
|------|---------|
| RiskApprovalGate | 高风险操作审批门内部使用HumanApprovalGate执行审批 |
| PhaseOrchestrator | 阶段转换时通过审批门确认关键决策 |
| DashboardServer | 通过API端点暴露待审批列表和审批历史 |

## PlanPersistence详解

### 职责概述

执行计划持久化管理器，管理计划生命周期（创建、更新、加载），支持版本化快照、任务状态更新、防漂移上下文注入、磁盘持久化存储（`.harness/workspace/plans/`），以及内存有界缓存与最旧计划淘汰。

### 构造函数参数

```javascript
new PlanPersistence(projectRoot, options)
```

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `projectRoot` | string | — | 项目根目录路径（必需） |
| `options.maxPlans` | number | 50 | 内存中最大计划数 |
| `options.maxVersions` | number | 10 | 每个计划最大版本快照数 |

### 核心方法

#### `createPlan(sessionId, plan)`

创建执行计划并持久化到磁盘。

- **参数**：
  - `sessionId` (`string`) — 关联的会话ID
  - `plan` (`object`) — 计划定义
    - `plan.objective` (`string`, 可选) — 计划目标
    - `plan.strategy` (`string`, 可选) — 执行策略
    - `plan.tasks` (`Array<object|string>`, 可选) — 任务列表
    - `plan.constraints` (`Array<string>`, 可选) — 约束条件
    - `plan.successCriteria` (`Array<string>`, 可选) — 成功标准
    - `plan.currentPhase` (`string`, 可选) — 当前阶段
- **返回值**：`object | null` — 创建的计划对象，参数无效时返回 `null`
- **说明**：自动生成 `planId`，规范化任务列表，发射 `plan-created` 事件

#### `updatePlan(planId, updates)`

更新执行计划，支持更新策略、任务、约束、成功标准、阶段和状态。

- **参数**：
  - `planId` (`string`) — 计划ID
  - `updates` (`object`) — 更新内容
    - `updates.strategy` (`string`, 可选) — 新策略
    - `updates.tasks` (`Array`, 可选) — 新任务列表
    - `updates.constraints` (`Array<string>`, 可选) — 新约束条件
    - `updates.successCriteria` (`Array<string>`, 可选) — 新成功标准
    - `updates.currentPhase` (`string`, 可选) — 新当前阶段
    - `updates.status` (`string`, 可选) — 新状态
- **返回值**：`object | null` — 更新后的计划对象，计划不存在时返回 `null`
- **说明**：每次更新自动递增版本号；使用文件级锁防止并发修改

#### `updateTaskStatus(planId, taskIndex, status, result)`

更新计划中指定任务的状态和结果。

- **参数**：
  - `planId` (`string`) — 计划ID
  - `taskIndex` (`number`) — 任务索引
  - `status` (`string`) — 新状态
  - `result` (`any`, 可选) — 任务结果
- **返回值**：`object | null` — 更新后的计划对象，计划或任务不存在时返回 `null`
- **说明**：发射 `task-status-updated` 事件

#### `loadPlan(planId)`

异步加载计划，优先从内存缓存读取，缓存未命中时从磁盘加载。

- **参数**：`planId` (`string`) — 计划ID
- **返回值**：`Promise<object | null>` — 计划对象

#### `getActivePlan(sessionId)`

获取指定会话的活跃计划。

- **参数**：`sessionId` (`string`) — 会话ID
- **返回值**：`object | null` — 活跃计划对象
- **说明**：先查内存缓存，再查磁盘文件

#### `injectContext(sessionId, currentContext)`

注入防漂移上下文，将当前计划的目标、策略、任务进度、约束和成功标准格式化为Markdown文本，拼接到当前上下文前面。

- **参数**：
  - `sessionId` (`string`) — 会话ID
  - `currentContext` (`string | object`) — 当前上下文内容
- **返回值**：`string` — 注入防漂移上下文后的完整文本
- **说明**：无活跃计划时原样返回当前上下文

#### `getPlanVersions(planId)`

获取计划的版本历史摘要列表。

- **参数**：`planId` (`string`) — 计划ID
- **返回值**：`Array<{ version: number, updatedAt: number, status: string }>` — 版本摘要列表

#### `getStats()`

获取持久化管理器的统计信息。

- **返回值**：`{ plansInMemory, created, updated, loaded, injected, maxPlans, maxVersions }`

### 防漂移注入格式

```
## 当前计划（防漂移注入）

目标: {objective}
策略: {strategy}
当前阶段: {currentPhase}

### 任务进度
✅ [1] 任务描述 (completed)
🔄 [2] 任务描述 (in_progress)
⬜ [3] 任务描述 (pending)

### 约束条件
- 约束1
- 约束2

### 成功标准
- 标准1
- 标准2

---
{原始上下文}
```

### 持久化机制

- **存储路径**：`.harness/workspace/plans/{planId}.json`
- **版本路径**：`.harness/workspace/plans/versions/{planId}-v{version}.json`
- **写入方式**：`writeAtomic()` / `writeAtomicAsync()` 原子写入
- **版本管理**：每次更新自动创建版本快照，超过 `maxVersions` 时删除最旧版本文件
- **并发控制**：`_acquireLock()` / `_releaseLock()` 文件级锁

### 事件列表

| 事件名 | 触发条件 | 数据 |
|--------|---------|------|
| `plan-created` | 计划创建成功 | `{ planId, sessionId }` |
| `plan-updated` | 计划更新成功 | `{ planId, version, status }` |
| `task-status-updated` | 任务状态更新 | `{ planId, taskIndex, status }` |

### 配置常量

| 常量 | 值 | 说明 |
|------|-----|------|
| `DEFAULT_MAX_PLANS` | 50 | 默认内存最大计划数 |
| `DEFAULT_MAX_VERSIONS` | 10 | 默认每计划最大版本数 |
| `SAFE_PLAN_ID_RE` | `/^[a-zA-Z0-9_-]+$/` | 计划ID安全正则 |

### 使用示例

```javascript
const PlanPersistence = require('./src/runtime/workflow/plan-persistence');

const pp = new PlanPersistence('/path/to/project', { maxPlans: 100, maxVersions: 20 });

pp.on('plan-created', ({ planId, sessionId }) => {
  console.log(`计划创建: ${planId}`);
});

const plan = pp.createPlan('session-001', {
  objective: '实现用户认证模块',
  strategy: 'TDD驱动开发',
  tasks: ['设计认证接口', '编写测试用例', '实现认证逻辑', '集成测试'],
  constraints: ['不使用外部认证服务'],
  successCriteria: ['测试覆盖率>90%', '无安全漏洞'],
});

pp.updateTaskStatus(plan.planId, 0, 'completed', { summary: '接口设计完成' });

const context = pp.injectContext('session-001', '请继续实现认证逻辑');
console.log(context);

console.log(pp.getStats());
```

### 与其他模块的交互关系

| 模块 | 交互方式 |
|------|---------|
| PhaseOrchestrator | 编排器通过 `injectContext()` 在阶段转换时注入防漂移上下文 |
| GoalExecutor | 目标执行器通过 `createPlan()` 创建执行计划并追踪进度 |
| SessionManager | 会话管理器通过 `getActivePlan()` 获取当前会话的活跃计划 |
| DashboardServer | 通过API端点暴露计划状态和版本历史 |

## RAGPipeline详解

### 职责概述

RAG检索增强生成管道，提供文档摄入、分块、嵌入和基于向量的检索管道，用于上下文增强生成。支持目录级批量摄入（含文件类型过滤）、可配置分块大小和重叠、通过 `CausalVectorIndex` 进行Top-K向量搜索，以及可选的GraphRAG集成（合并知识图谱结果与向量搜索结果）。

### 构造函数参数

```javascript
new RAGPipeline(projectRoot, options)
```

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `projectRoot` | string | — | 项目根目录路径 |
| `options.chunkSize` | number | 512 | 文本分块大小（字符数） |
| `options.chunkOverlap` | number | 64 | 连续分块重叠字符数 |
| `options.topK` | number | 5 | 向量搜索默认返回结果数 |

### 核心方法

#### `attachGraphRAG(graphRAG)`

附加GraphRAG实例，用于查询时合并知识图谱结果。

- **参数**：`graphRAG` (`object`) — GraphRAG实例，需实现 `query` 方法
- **返回值**：`RAGPipeline` — this（支持链式调用）

#### `ingestDocument(docPath, content, metadata)`

摄入单个文档，将文档分块、生成嵌入向量并索引。摄入操作串行排队执行。

- **参数**：
  - `docPath` (`string`) — 文档路径标识
  - `content` (`string`) — 文档文本内容
  - `metadata` (`object`, 可选) — 文档元数据
- **返回值**：`Promise<{ success: boolean, docId?: string, chunkCount?: number, error?: string }>` — 摄入结果
- **说明**：已存在的文档会先移除再重新索引；文档大小超过 `MAX_DOCUMENT_SIZE` 时拒绝

#### `ingestDirectory(dirPath, options)`

批量摄入目录下所有支持的文件类型。

- **参数**：
  - `dirPath` (`string`) — 相对于项目根目录的目录路径
  - `options` (`object`, 可选) — 摄入选项
    - `options.maxDepth` (`number`, 默认 10) — 最大递归深度
- **返回值**：`Promise<{ success: boolean, results: { ingested: number, failed: number, skipped: number } }>` — 批量摄入结果
- **说明**：递归遍历子目录，跳过隐藏目录和 `node_modules`；支持 `.md/.txt/.json/.js/.ts/.py/.go/.rs/.java/.jsx/.tsx` 文件类型

#### `query(queryText, options)`

执行RAG查询，先进行向量搜索，再合并GraphRAG结果。

- **参数**：
  - `queryText` (`string`) — 查询文本
  - `options` (`object`, 可选) — 查询选项
    - `options.topK` (`number`) — 返回的最大结果数
- **返回值**：`Promise<{ success: boolean, query?: string, results?: Array<{ id, score, text, metadata }>, error?: string }>` — 查询结果
- **说明**：GraphRAG结果以最高0.8的分数上限合并，避免图谱结果覆盖向量结果

#### `removeDocument(docId)`

移除指定文档及其所有分块。

- **参数**：`docId` (`string`) — 文档ID
- **返回值**：`boolean` — 文档是否存在并被移除

#### `getStats()`

获取RAG管道的统计信息。

- **返回值**：`{ documentsIndexed, chunksCreated, queriesExecuted, vectorIndexStats, embeddingStats }`

### 分块算法

```
_chunkText(text, chunkSize, overlap):
  text.length <= chunkSize → [text]
  overlap = min(overlap, chunkSize - 1)
  从 start=0 开始:
    end = start + chunkSize
    如果 end < text.length:
      在 end 附近找最后一个换行符
      如果换行符位置 > start + chunkSize * 0.5 → 在换行符处分割
    下一个 start = end - overlap
    如果 nextStart <= start → 终止
```

### 支持的文件类型

| 扩展名 | 说明 |
|--------|------|
| `.md` | Markdown文档 |
| `.txt` | 纯文本 |
| `.json` | JSON文件 |
| `.js` | JavaScript源码 |
| `.ts` | TypeScript源码 |
| `.py` | Python源码 |
| `.go` | Go源码 |
| `.rs` | Rust源码 |
| `.java` | Java源码 |
| `.jsx` | React JSX |
| `.tsx` | React TSX |

### 事件列表

| 事件名 | 触发条件 | 数据 |
|--------|---------|------|
| `document-indexed` | 文档摄入成功 | `{ docId, chunkCount }` |
| `document-removed` | 文档移除 | `{ docId }` |
| `query-executed` | 查询执行完成 | `{ query, resultCount }` |
| `error` | 发生错误 | 错误对象 |

### 配置常量

| 常量 | 值 | 说明 |
|------|-----|------|
| `DEFAULT_CHUNK_SIZE` | 512 | 默认分块大小 |
| `DEFAULT_CHUNK_OVERLAP` | 64 | 默认分块重叠 |
| `DEFAULT_TOP_K` | 5 | 默认Top-K |
| `MAX_DOCUMENT_SIZE` | `MAX_JSON_FILE_SIZE` | 单文档最大大小 |
| `MAX_DOCUMENTS` | 500 | 最大文档数 |
| `MAX_CHUNKS` | 50000 | 最大分块数 |

### 使用示例

```javascript
const RAGPipeline = require('./src/runtime/workflow/rag-pipeline');

const rag = new RAGPipeline('/path/to/project', {
  chunkSize: 1024,
  chunkOverlap: 128,
  topK: 10,
});

rag.on('document-indexed', ({ docId, chunkCount }) => {
  console.log(`文档已索引: ${docId}, 分块数: ${chunkCount}`);
});

await rag.ingestDocument('docs/api.md', '# API文档\n...', { category: 'api' });
await rag.ingestDirectory('docs/', { maxDepth: 5 });

const result = await rag.query('如何配置认证？', { topK: 3 });
console.log('查询结果:', result.results?.length);

console.log(rag.getStats());
```

### 与其他模块的交互关系

| 模块 | 交互方式 |
|------|---------|
| EmbeddingService | 内部创建实例用于文本向量化 |
| CausalVectorIndex | 内部创建实例用于向量索引和搜索 |
| GraphRAG | 通过 `attachGraphRAG()` 可选附加，查询时合并图谱结果 |
| PhaseOrchestrator | 编排器通过RAG管道检索相关上下文辅助决策 |

## ProgrammableHookExecutor详解

### 职责概述

可编程钩子执行器，在生命周期事件上注册和执行钩子（builtin/function/shell三种类型），采用顺序执行和阻塞中断语义。Shell钩子通过命令白名单、危险模式检测和上下文变量替换实现沙箱隔离。内置监控子系统追踪执行延迟、成功率、慢钩子检测和逐钩子统计。

### 构造函数参数

```javascript
new ProgrammableHookExecutor(projectRoot)
```

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `projectRoot` | string | — | 项目根目录路径（必需） |

### 核心方法

#### `register(event, action)`

注册钩子到指定事件。

- **参数**：
  - `event` (`string`) — 事件名称
  - `action` (`object`) — 钩子配置
    - `action.id` (`string`, 可选) — 钩子标识符，不传则自动生成
    - `action.type` (`string`) — 钩子类型：`'builtin'` / `'function'` / `'shell'`
    - `action.name` (`string`) — 钩子名称（builtin类型对应处理器名）
    - `action.handler` (`function`) — 函数处理器（function类型必需）
    - `action.command` (`string | Array`) — Shell命令（shell类型必需）
    - `action.timeout` (`number`, 可选) — Shell钩子超时毫秒数
    - `action.enabled` (`boolean`, 可选, 默认 `true`) — 是否启用
- **返回值**：`ProgrammableHookExecutor` — this（支持链式调用）
- **说明**：单事件钩子数达到50或总钩子数达到500时拒绝注册；重复ID忽略

#### `unregister(event, id)`

从指定事件中注销钩子。

- **参数**：
  - `event` (`string`) — 事件名称
  - `id` (`string`) — 钩子标识符
- **返回值**：`ProgrammableHookExecutor` — this（支持链式调用）

#### `execute(event, context)`

执行指定事件的所有已注册钩子，顺序执行，遇失败阻塞中断。

- **参数**：
  - `event` (`string`) — 事件名称
  - `context` (`object`) — 钩子执行上下文
- **返回值**：`Promise<Array<object>>` — 钩子执行结果列表
- **说明**：每个结果含 `id`、`type`、`name`、`passed`、`reason`、`message`、`elapsedMs`；钩子返回 `passed: false` 时中断后续钩子执行

#### `getRegisteredHooks(event)`

获取指定事件的已注册钩子列表。

- **参数**：`event` (`string`) — 事件名称
- **返回值**：`Array<{ id, type, name, enabled }>` — 钩子摘要列表

#### `loadFromConfig(config)`

从配置对象批量加载钩子定义。

- **参数**：`config` (`object`) — 钩子配置对象，包含 `hooks` 字段
- **返回值**：`ProgrammableHookExecutor` — this（支持链式调用）
- **说明**：配置格式为 `{ hooks: { eventName: { enabled, checks: [...] } } }`

#### `getStats()`

获取钩子执行器的统计信息。

- **返回值**：`{ totalHooks, hooksByEvent, builtinCount }`

#### `getHookMonitorData()`

获取钩子监控数据。

- **返回值**：`{ global: { calls, passes, failures, errors, successRate, avgLatencyMs, uptimeMs }, perHook: Array, recentExecutions, slowHooks, slowHookCount, thresholdMs }`

#### `getSlowHooks(limit)`

获取慢钩子记录。

- **参数**：`limit` (`number`, 可选, 默认 50) — 返回记录的最大数量
- **返回值**：`Array<object>` — 慢钩子记录列表

#### `getHookSuccessRates()`

获取各钩子的成功率统计。

- **返回值**：`object` — 钩子成功率映射，键为 `event:hookId`

#### `resetMonitorData()`

重置所有监控数据。

- **返回值**：`void`

#### `isHealthy()`

健康检查，基于全局成功率判断。

- **返回值**：`boolean` — 成功率 >= 70%（调用次数 < 5 时始终返回 `true`）

### Shell钩子沙箱机制

```
Shell钩子执行流程:
  1. 上下文变量替换 {{key}} → _sanitizeValue(value)
  2. 危险模式检测 (_checkDangerousPattern)
     → 匹配 DANGEROUS_SHELL_PATTERNS → 阻止执行
  3. 工作目录检查
     → cwd 不在 project_root 下 → 阻止执行
  4. 命令解析 (_parseShellCommand)
     → 数组格式: 直接取 [cmd, ...args]
     → 字符串格式: _splitShellCommand 解析（支持引号和转义）
  5. 命令白名单检查
     → cmd 不在 ALLOWED_COMMANDS → 阻止执行
  6. execFile 执行（shell: false, 无shell注入风险）
```

### 允许的Shell命令

```
git, echo, cat, ls, mkdir, cp, mv, test, true, false,
date, wc, head, tail, sort, uniq, diff, which, pwd, env
```

### 事件列表

| 事件名 | 触发条件 | 数据 |
|--------|---------|------|
| `hook-registered` | 钩子注册成功 | `{ event, id, type }` |
| `hook-unregistered` | 钩子注销 | `{ event, id }` |
| `hook-executed` | 钩子执行完成 | `{ event, hookId, passed, elapsedMs }` |
| `hook-rejected` | 钩子注册被拒绝 | `{ event, reason }` |
| `hook-error` | 钩子执行异常 | 错误对象 + `{ event, hookId, elapsedMs }` |
| `hook-late-rejection` | 异步钩子延迟拒绝 | `{ hookId, error }` |
| `slow-hook-detected` | 检测到慢钩子 | `{ event, hookId, name, type, elapsedMs, threshold, passed }` |

### 配置常量

| 常量 | 值 | 说明 |
|------|-----|------|
| `MAX_HOOKS_PER_EVENT` | 50 | 单事件最大钩子数 |
| `MAX_TOTAL_HOOKS` | 500 | 最大总钩子数 |
| `DEFAULT_HOOK_TIMEOUT_MS` | `2 * CENTRAL_HOOK_TIMEOUT_MS` | 默认钩子超时 |
| `SHELL_MAX_BUFFER` | 1024 * 1024 | Shell输出最大缓冲 |
| `SHELL_OUTPUT_TRUNCATE` | 500 | Shell输出截断长度 |
| `HEALTH_MIN_SUCCESS_RATE` | 0.7 | 健康检查最低成功率 |

### 使用示例

```javascript
const ProgrammableHookExecutor = require('./src/runtime/workflow/programmable-hook-executor');

const executor = new ProgrammableHookExecutor('/path/to/project');

executor.on('hook-executed', ({ event, hookId, passed, elapsedMs }) => {
  console.log(`钩子执行: ${hookId}, 通过: ${passed}, 耗时: ${elapsedMs}ms`);
});

executor.on('slow-hook-detected', ({ hookId, elapsedMs, threshold }) => {
  console.log(`慢钩子: ${hookId}, 耗时: ${elapsedMs}ms, 阈值: ${threshold}ms`);
});

executor.register('pre-commit', {
  type: 'builtin',
  name: 'path-validation',
});

executor.register('pre-commit', {
  type: 'function',
  id: 'custom-check',
  handler: (ctx) => {
    return { passed: true, message: '自定义检查通过' };
  },
});

executor.register('pre-deploy', {
  type: 'shell',
  command: ['git', 'diff', '--stat', '{{branch}}'],
  timeout: 10000,
});

const results = await executor.execute('pre-commit', { branch: 'main' });
console.log(results);

console.log(executor.getHookMonitorData());
console.log(executor.getHookSuccessRates());
```

## 模块间协作流程

### 工作流编排执行流程

```
任务请求
  │
  ├── 1. WorkflowTemplate.instantiate()
  │     从模板实例化工作流步骤（含变量插值）
  │
  ├── 2. WorkflowDAG.fromWorkflowDef()
  │     将步骤定义构建为DAG（含依赖边和环检测）
  │
  ├── 3. 循环执行:
  │     ├── DAG.getReadyNodes() → 获取就绪节点
  │     ├── DAG.markDependencyFailed() → 标记依赖失败节点
  │     ├── DAG.startNode() → 标记运行中
  │     ├── 执行节点任务
  │     ├── DAG.completeNode() / DAG.failNode()
  │     └── DAG.isComplete() → 判断是否全部完成
  │
  └── 4. 汇总结果
        DAG.getStats() → 执行统计
```

### 人工审批流程

```
高风险操作
  │
  ├── 1. HumanApprovalGate.requestApproval()
  │     创建审批请求，发射 approval-requested 事件
  │
  ├── 2. 等待审批
  │     ├── 人工批准 → approve() → 发射 approval-approved → 继续
  │     ├── 人工拒绝 → reject() → 发射 approval-rejected → 中止
  │     └── 超时 → 自动拒绝 → 发射 approval-timeout → 中止
  │
  └── 3. 根据审批结果决定是否继续执行
```

### 计划追踪与防漂移流程

```
会话开始
  │
  ├── 1. PlanPersistence.createPlan()
  │     创建执行计划（含目标、策略、任务、约束、成功标准）
  │
  ├── 2. 任务执行过程中
  │     ├── PlanPersistence.updateTaskStatus() → 更新任务状态
  │     ├── PlanPersistence.updatePlan() → 更新计划（自动版本快照）
  │     └── PlanPersistence.injectContext() → 注入防漂移上下文
  │
  └── 3. 计划完成
        PlanPersistence.updatePlan(planId, { status: 'completed' })
```

### RAG上下文增强流程

```
查询请求
  │
  ├── 1. RAGPipeline.query(queryText, { topK })
  │     ├── _vectorQuery() → CausalVectorIndex.search()
  │     │     向量相似度搜索，返回 Top-K 结果
  │     └── _mergeGraphRAGResults() → graphRAG.query()
  │           合并知识图谱结果（分数上限0.8）
  │
  └── 2. 返回增强上下文
        向量搜索结果 + 图谱结果 → 上下文增强
```

### 钩子执行流程

```
生命周期事件触发
  │
  ├── 1. ProgrammableHookExecutor.execute(event, context)
  │     顺序执行已注册钩子
  │
  ├── 2. 逐钩子执行:
  │     ├── builtin → 调用 BUILTIN_HANDLERS[name]
  │     ├── function → 调用 handler(ctx)
  │     └── shell → 沙箱执行（白名单+危险模式检测+上下文替换）
  │
  ├── 3. 结果判定:
  │     ├── passed: true → 继续下一个钩子
  │     └── passed: false → 阻塞中断，返回已执行结果
  │
  └── 4. 监控记录
        _recordMonitorData() → 更新全局/逐钩子统计
        慢钩子检测 → 发射 slow-hook-detected
```
