# 模块详解-技能图谱

> 版本：2.73.4 | 文件：src/runtime/skill/skill-graph.js | 行数：~520行

---

## 模块概述

SkillGraph模块实现了基于有向图的技能依赖关系建模与拓扑排序。模块将84个Skill建模为图节点，通过四种边类型（dependency/blocking/semantic/causal）建立Skill间的依赖、阻塞、语义关联和因果关系。核心能力包括：从Skill定义自动构建图谱、拓扑排序确定执行顺序、BFS最短路径查找、DFS环检测、语义分组匹配，以及基于任务描述的语义关键词匹配找出最小必需技能集。

## 融合来源

融合自AI Agent架构中的技能图谱（Skill Graph）概念，借鉴了知识图谱的实体-关系建模方法和编译器的依赖图分析技术。语义分组匹配机制融合了信息检索中的关键词匹配与领域本体分类思想，使Agent能够根据自然语言任务描述自动定位相关技能集群。

## 核心API

| 方法 | 参数 | 返回值 | 说明 |
|------|------|--------|------|
| `addNode(skillId, metadata)` | skillId: string, metadata: Object | `this` | 添加技能节点 |
| `addEdge(fromId, toId, edgeType, weight?)` | fromId/toId: string, edgeType: string, weight?: number | `this` | 添加边，权重自动限制在[0,1] |
| `buildFromSkills(skills)` | skills: Array | `this` | 从Skill定义数组批量构建图谱 |
| `findMinimalSkillSet(taskDescription, requiredSkills)` | taskDescription: string, requiredSkills: Array | `string[]` | 基于任务描述找出最小必需技能集（含依赖传递） |
| `getExecutionOrder(skillIds)` | skillIds: Array | `string[]` | 拓扑排序，按优先级排序同层级节点 |
| `getDependencies(skillId)` | skillId: string | `string[]` | 获取指定Skill的前置依赖 |
| `getDependents(skillId)` | skillId: string | `string[]` | 获取依赖指定Skill的后继节点 |
| `getShortestPath(fromId, toId)` | fromId/toId: string | `string[] \| null` | BFS最短路径查找 |
| `detectCycles()` | 无 | `string[][]` | DFS检测所有环 |
| `getStats()` | 无 | `{ nodeCount, edgeCount, avgDegree, componentCount }` | 图统计信息 |
| `attachSkillRouter(router)` | router: SkillRouter | `this` | 关联SkillRouter实例 |
| `attachSessionManager(sessionManager)` | sessionManager: SessionManager | `this` | 关联SessionManager实例 |

### 静态属性

| 属性 | 说明 |
|------|------|
| `DEFAULT_CONFIG` | 默认配置 |
| `EDGE_DEFAULT_WEIGHTS` | 边类型默认权重：dependency=1.0, blocking=0.8, semantic=0.5, causal=0.9 |
| `VALID_EDGE_TYPES` | 有效边类型集合 |

## 配置项

| 字段 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `maxNodes` | number | 200 | 最大节点数 |
| `maxEdges` | number | 1000 | 最大边数 |
| `semanticMatchThreshold` | number | 0.5 | 语义匹配阈值 |

## 事件

| 事件名 | 触发时机 | 数据 |
|--------|---------|------|
| `node-added` | 节点添加 | `{ skillId, node }` |
| `edge-added` | 边添加 | `{ fromId, toId, edgeType, weight }` |
| `graph-built` | 图谱构建完成 | `{ nodeCount, edgeCount }` |

## 使用示例

```javascript
const SkillGraph = require('./src/runtime/skill/skill-graph');

const graph = new SkillGraph({ maxNodes: 50, maxEdges: 500 });

graph.addNodes([
  { skill_id: 'tdd-implement', phase: 'development', priority: 5, depends_on: ['architecture-design'] },
  { skill_id: 'architecture-design', phase: 'design', priority: 8 },
  { skill_id: 'integration-testing', phase: 'testing', depends_on: ['tdd-implement'] },
]);

graph.buildFromSkills(skillsArray);

const order = graph.getExecutionOrder(['tdd-implement', 'integration-testing']);
console.log('Execution order:', order);

const minimal = graph.findMinimalSkillSet(
  '需要先写测试再实现代码',
  ['tdd-implement']
);
console.log('Minimal skill set:', minimal);

const cycles = graph.detectCycles();
if (cycles.length > 0) {
  console.warn('Circular dependencies detected:', cycles);
}
```

## 与现有模块的集成点

- **SkillRouter**：SkillGraph基于SkillRouter发现的Skill定义构建图谱，两者配合实现"发现→建模→排序→执行"的完整链路
- **PhaseOrchestrator**：阶段编排器利用SkillGraph的拓扑排序确定Skill执行顺序，确保依赖关系被满足
- **GoalExecutor**：目标执行器通过`findMinimalSkillSet()`根据目标描述自动确定需要激活的技能集
- **CommandRouter**：斜杠命令路由器在处理复合命令（如`/plan`）时，通过SkillGraph获取技能链的执行顺序
- **DeepeningPipeline**：深化管道在调度深化任务时参考SkillGraph的依赖关系避免循环调度
