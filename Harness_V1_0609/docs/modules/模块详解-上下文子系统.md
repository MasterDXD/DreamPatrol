# 模块详解-上下文子系统

> 版本：2.73.4 | 文件：src/runtime/context/

---

## 子系统概述

上下文子系统（Context Subsystem）负责管理Harness框架中上下文的压缩、隔离、注入和自回归生成，是"上下文管理"和"成本控制"原则的核心实现。该子系统包含5个核心模块，协同完成从上下文智能压缩到阶段感知注入、从Agent隔离执行到迭代自回归上下文传递的完整上下文生命周期管理。

上下文子系统解决的核心问题是：在Token预算有限的前提下，如何确保每个Agent在正确的时机获得正确的上下文信息。它通过四层机制实现这一目标：

1. **压缩层**（ContextCompressionEngine）：当Token使用量达到阈值时，根据技能类别和因果关联智能压缩上下文，将已完成阶段的技能从完整指令压缩为摘要或直接丢弃
2. **隔离层**（IsolatedContextManager）：为每个Agent任务创建独立的执行上下文，控制Agent间的上下文共享边界，防止跨任务上下文泄漏
3. **注入层**（PhaseContextInjector + LTIContextInjector）：根据执行阶段和任务迭代深度，自动注入相关规则、Agent定义和原始目标上下文
4. **自回归层**（AutoregressiveContextSchema）：在迭代深化推理中，将前驱结果、质量分数和反馈注入上下文，实现自回归式上下文传递

## 模块清单

| 模块 | 源文件 | 说明 |
|------|--------|------|
| ContextCompressionEngine | context-compression-engine.js | 上下文压缩引擎，智能分类（keep/summarize/discard）、Token估算、压缩计划 |
| IsolatedContextManager | isolated-context-manager.js | 隔离上下文管理器，Agent任务上下文隔离、工具集分配、访问控制 |
| LTIContextInjector | lti-context-injector.js | LTI上下文注入器，学习工具互操作上下文注入、目标信号计算 |
| PhaseContextInjector | phase-context-injector.js | 阶段上下文注入器，按执行阶段注入规则文件、Agent定义和核心身份 |
| AutoregressiveContextSchema | autoregressive-context-schema.js | 自回归上下文模式，迭代推理上下文字段注入、验证和兼容性检查 |

**关键依赖关系**：
- **ContextCompressionEngine** 是压缩层的核心，可选注入 **CausalConfigValidator** 和 **CausalBufferManager** 实现因果感知压缩
- **IsolatedContextManager** 为每个Agent任务创建隔离上下文，通过访问控制防止跨任务泄漏
- **PhaseContextInjector** 依赖项目根目录下的 `.harness/rules/` 和 `.harness/agents/` 文件系统结构
- **LTIContextInjector** 维护原始上下文注册表，在迭代深化时注入原始目标防止目标漂移
- **AutoregressiveContextSchema** 是纯函数模块（非类），被 SessionManager 和深化推理子系统调用
- ContextCompressionEngine、IsolatedContextManager、LTIContextInjector、PhaseContextInjector 均通过 **withShutdown** 混入实现优雅关机

## ContextCompressionEngine — 上下文压缩引擎

### 核心职责

ContextCompressionEngine是上下文子系统的压缩核心，负责：
- 根据技能类别和执行阶段对技能列表进行智能压缩（full/summary/discard三种策略）
- Token使用量估算（区分ASCII和非ASCII字符，中文按2倍计算）
- 压缩计划生成（预览哪些技能保留、哪些压缩及预估节省Token数）
- 增量跳过优化（状态哈希未变时复用上次压缩结果）
- 因果覆盖策略（通过CausalValidator和CausalBufferManager判断因果关联）
- 规格资产强制保留（含specification输出的技能始终保留）
- 文本输出压缩（去除填充词、冗余注释、超长截断）
- 工具输出压缩（行去重合并、正则过滤、对象截断）
- 压缩策略动态调整和统计信息追踪

### 压缩策略分类

| 类别 | 默认策略 | 说明 |
|------|---------|------|
| `current_phase` | `full` | 当前阶段技能，保留完整指令 |
| `completed_phase` | `summary` | 已完成阶段技能，压缩为摘要 |
| `future_phase` | `summary` | 未来阶段技能，压缩为摘要 |
| `unclassified` | `full` | 未分类技能，保留完整指令 |
| `specification_asset` | `full` | 含规格输出的技能，强制保留（不可更改） |
| `causal_upstream` | `full` | 因果上游技能，保留完整指令 |
| `causal_relevance_high` | `full` | 因果高关联技能，保留完整指令 |
| `causal_relevance_medium` | `summary` | 因果中关联技能，压缩为摘要 |
| `causal_relevance_low` | `discard` | 因果低关联技能，直接丢弃 |

### 增量跳过机制

ContextCompressionEngine通过状态哈希实现增量跳过：

1. 对上下文中的阶段、技能ID列表、已完成技能ID列表、规格资产ID计算哈希
2. 若哈希与上次相同且存在缓存结果，直接返回深拷贝
3. 深拷贝失败时降级为JSON序列化，再失败则重新计算
4. 任何配置变更或因果组件附加都会清除增量状态

### 因果覆盖策略

ContextCompressionEngine支持两种因果覆盖机制：

1. **CausalBufferManager**（优先）：调用 `getCompressionStrategy(skillId, currentSkillId)` 获取技能间压缩策略，返回 `full`/`summary`/`discard`
2. **CausalConfigValidator**（降级）：调用 `getDependencyGraph()` 获取依赖图，检查技能是否为当前阶段技能的因果上游

因果上游判断结果按 `skillId:currentPhase` 缓存，TTL为 `DEFAULT_PIPELINE_TIMEOUT_MS`，缓存上限500条，过期条目在容量不足时清理。

## IsolatedContextManager — 隔离上下文管理器

### 核心职责

IsolatedContextManager负责为每个Agent任务创建隔离的执行上下文，核心能力包括：
- 按Agent角色分配工具集（task-worker/domain-analyst/quality-assurance等5种预设角色）
- 上下文访问控制（基于Agent ID的ACL，每个上下文最多20个授权Agent）
- 上下文生命周期管理（创建→活跃→完成→释放）
- 上下文容量管理（最大20个上下文，LRU驱逐策略）
- 执行结果提交（输出、摘要、置信度、证据）
- 上下文注入内容大小限制（最大50000字符）
- 操作历史记录（RingBuffer，最大200条）

### 上下文数据结构

```javascript
{
  contextId: string,
  parentSessionId: string | null,
  agentId: string,
  taskDescription: string,
  toolSet: string[],
  systemPrompt: string,
  injectedContext: string,
  constraints: string[],
  successCriteria: string[],
  outputFormat: 'structured',
  createdAt: number,
  lastAccessedAt: number,
  status: 'active' | 'completed' | 'released' | 'failed',
  result: {
    output: any,
    summary: string,
    confidence: number,
    evidence: Array,
    completedAt: number,
  } | null,
  tokenEstimate: number,
}
```

### Agent角色与工具集映射

| Agent角色 | 默认工具集 |
|-----------|-----------|
| `task-worker` | read, write, search, run |
| `domain-analyst` | read, write, search, web |
| `quality-assurance` | read, search, run, web |
| `devops-engineer` | read, write, search, run |
| `technical-writer` | read, write, search |

未知角色降级为 `['read', 'search']`。自定义工具集通过 `customToolSets` 配置项合并覆盖。

### 驱逐策略

当上下文数量达到上限时，按以下优先级驱逐：

1. **已完成上下文**：优先驱逐 `lastAccessedAt` 最小的已完成上下文
2. **失效上下文**：驱逐状态为 `released` 或 `failed` 的上下文
3. **LRU驱逐**：驱逐 `lastAccessedAt` 最小的活跃上下文，并发出 `active-context-evicted` 事件

### 访问控制

每个上下文维护独立的ACL：

```javascript
{
  owner: string,
  allowedAgents: Set<string>,
}
```

- 创建时自动将Agent设为owner，owner始终拥有访问权限
- `grantContextAccess()` 授予其他Agent访问权限（上限20个）
- `revokeContextAccess()` 撤销Agent权限（不允许撤销owner）
- `getContext()` 传入 `requestingAgentId` 时进行ACL检查，无权限返回null并发出 `access-denied` 事件

### 核心API

| 方法 | 返回值 | 说明 |
|------|--------|------|
| `createIsolatedContext(config)` | `Object\|null` | 创建隔离上下文，`taskDescription`必填，按agentId分配默认工具集 |
| `getContext(contextId, requestingAgentId?)` | `Object\|null` | 获取上下文深拷贝，传入agentId时进行访问控制检查 |
| `grantContextAccess(contextId, agentId)` | `boolean` | 授予Agent访问权限，上限20个Agent |
| `revokeContextAccess(contextId, agentId)` | `boolean` | 撤销Agent访问权限，不允许撤销owner |
| `submitResult(contextId, result)` | `boolean` | 提交执行结果，上下文状态变为completed |
| `releaseContext(contextId)` | `boolean` | 释放上下文，从管理器中移除 |
| `getActiveContexts()` | `Array` | 获取所有活跃上下文摘要列表 |
| `getContextsBySession(sessionId, requestingAgentId?)` | `Array` | 按父会话ID查询关联上下文 |
| `getTotalTokenEstimate()` | `number` | 计算所有上下文的Token估算总和 |
| `getStats()` | `Object` | 获取统计信息（上下文数量、活跃数、完成数、Token估算等） |
| `isHealthy()` | `boolean` | 健康检查，上下文数量未达上限时返回true |

### 事件

| 事件名 | 触发时机 | 数据 |
|--------|---------|------|
| `context-created` | 上下文创建 | `{ contextId, agentId, taskDescription }` |
| `context-released` | 上下文释放 | `{ contextId, agentId }` |

## LTIContextInjector — LTI上下文注入器

### 核心职责

LTIContextInjector实现学习工具互操作（LTI）上下文注入，负责：
- 原始任务上下文注册与持久化（跨迭代保持上下文一致性）
- 将原始上下文注入到当前任务状态中（融合原始目标、约束和需求）
- 目标信号计算（当原始目标与当前目标重叠度低时注入原始目标，防止目标漂移）
- 注入历史追踪（记录每次注入的迭代深度、时间戳和目标信号状态）
- 中英文自适应重叠度计算（中文使用字符bigram Jaccard相似度，英文使用词级Jaccard相似度）

### 注入数据结构

注入后，当前任务对象上会附加 `_ltiContext` 字段：

```javascript
{
  _ltiContext: {
    originalGoal: string,
    originalConstraints: string[],
    iteration: number,
    mode: 'lti',
    injectedAt: string,
    goalSignal: string | null,
    originalRequirements: string[],
  },
}
```

### 目标信号计算

在LTI模式下，`_computeGoalSignal` 计算原始目标与当前目标的重叠度：

- **重叠度 ≥ 0.5**：目标一致，不注入目标信号（`goalSignal = null`）
- **重叠度 < 0.5**：目标漂移，注入原始目标作为目标信号（`goalSignal = originalGoal`）

重叠度计算区分中英文：

| 场景 | 计算方法 |
|------|---------|
| 包含中文字符 | 字符bigram Jaccard相似度（`_charBigrams`） |
| 纯英文 | 词级Jaccard相似度（空格分词） |
| 完全相同 | 直接返回1.0 |

### 核心API

| 方法 | 返回值 | 说明 |
|------|--------|------|
| `registerOriginalContext(taskId, context)` | `void` | 注册原始任务上下文，注册表超上限时淘汰最早条目 |
| `inject(taskId, currentTask, iteration?)` | `Object` | 将原始上下文注入当前任务，融合目标、约束和需求 |
| `getOriginalContext(taskId)` | `Object\|null` | 获取指定任务的原始注册上下文 |
| `getInjectionHistory(taskId)` | `Array` | 获取注入历史记录（迭代序号、时间戳、是否含目标信号） |
| `unregisterContext(taskId)` | `boolean` | 取消注册原始上下文及注入历史 |
| `getStats()` | `Object` | 获取统计信息（注册上下文数、总注入次数、追踪任务数、模式） |

### 事件

| 事件名 | 触发时机 | 数据 |
|--------|---------|------|
| `context-registered` | 原始上下文注册 | `{ taskId }` |
| `context-injected` | 上下文注入完成 | `{ taskId, iteration, mode }` |

### 配置项

| 配置项 | 类型 | 默认值 | 说明 |
|--------|------|--------|------|
| `mode` | `string` | `'lti'` | 注入模式 |
| `maxHistory` | `number` | 10 | 每个任务的注入历史上限 |

### 容量管理

| 常量 | 值 | 说明 |
|------|-----|------|
| `MAX_ORIGINAL_CONTEXTS` | 200 | 原始上下文注册表上限 |
| `MAX_INJECTION_HISTORY` | 500 | 注入历史追踪上限（按任务数） |
| `MAX_CONTEXT_HISTORY` | 10 | 每个任务的注入历史条目上限 |

## PhaseContextInjector — 阶段上下文注入器

### 核心职责

PhaseContextInjector根据当前执行阶段自动注入相关上下文，负责：
- 按阶段映射加载规则文件（从 `.harness/rules/` 目录）
- 按阶段映射加载Agent定义文件（从 `.harness/agents/` 目录）
- 提取核心身份文档（从 `CLAUDE.md`，排除Agent/规则/Skill章节，最多60行）
- 阶段技能列表查询（从 `PHASE_SKILLS` 常量）
- 注入结果缓存（TTL 60秒，按阶段缓存）
- Token消耗估算（平均每行15个Token）
- 同步和异步两种注入模式

### 阶段与规则映射

| 阶段 | 规则文件 |
|------|---------|
| `brainstorming` | context-management, cost-control, task-execution |
| `requirement-analysis` | context-management, cost-control, task-execution, document-standards |
| `architecture-design` | context-management, cost-control, task-execution, document-standards, best-practices |
| `module-development` | context-management, cost-control, task-execution, document-standards, best-practices, coding-standards, karpathy-principles, monitoring-fault-tolerance, security-permissions |
| `integration-testing` | context-management, cost-control, task-execution, best-practices, monitoring-fault-tolerance |
| `deployment` | context-management, cost-control, task-execution, security-permissions, monitoring-fault-tolerance |

### 阶段与Agent映射

| 阶段 | Agent角色 |
|------|-----------|
| `brainstorming` | team-lead, domain-analyst |
| `requirement-analysis` | team-lead, domain-analyst |
| `architecture-design` | domain-analyst, team-lead |
| `module-development` | task-worker, domain-analyst, quality-assurance, code-reviewer, test-writer |
| `integration-testing` | quality-assurance, domain-analyst |
| `deployment` | devops-engineer, team-lead, technical-writer |

### 注入结果数据结构

```javascript
{
  phase: string,
  coreIdentity: {
    content: string,
    lines: number,
  },
  rules: Array<{
    name: string,
    content: string,
    lines: number,
  }>,
  agents: Array<{
    name: string,
    content: string,
    lines: number,
  }>,
  phaseSkills: string[],
  estimatedTokens: number,
}
```

### 核心身份提取规则

从 `CLAUDE.md` 提取核心身份时，排除以下章节：

- `## Agent` / `## 角色` 开头的章节
- `## 全局规则` / `## Rules` 开头的章节
- `## Skill` / `## 技能` 开头的章节
- `@include` 开头的行

提取结果限制为最多60行（`CORE_IDENTITY_MAX_LINES`），避免Token浪费。

### 缓存机制

- 缓存键为阶段名称
- 缓存TTL为60秒（`CACHE_TTL_MS`）
- TTL内重复请求直接返回深拷贝的缓存结果
- `clearCache()` 方法可手动清除所有缓存
- 配置变更或关机时自动清除缓存

### 核心API

| 方法 | 返回值 | 说明 |
|------|--------|------|
| `injectForPhase(phase)` | `Object` | 同步注入阶段上下文，无效阶段降级为brainstorming |
| `injectForPhaseAsync(phase)` | `Promise<Object>` | 异步注入阶段上下文，适用于非阻塞IO场景 |
| `getInjectedTokenEstimate()` | `number` | 获取最近一次注入的Token估算值 |
| `getCurrentPhase()` | `string\|null` | 获取当前激活的阶段名称 |
| `getPhaseRulesMap()` | `Object` | 获取阶段与规则文件的映射表 |
| `getPhaseAgentsMap()` | `Object` | 获取阶段与Agent角色的映射表 |
| `getStats()` | `Object` | 获取统计信息（当前阶段、Token估算、已加载规则/Agent/技能数、缓存大小） |
| `clearCache()` | `void` | 清除所有阶段上下文缓存 |

### 事件

| 事件名 | 触发时机 | 数据 |
|--------|---------|------|
| `phase-context-injected` | 阶段上下文注入完成 | `{ phase, estimatedTokens, rulesCount, agentsCount }` |
| `cache-cleared` | 缓存手动清除 | 无 |

### 构造参数

| 参数 | 类型 | 说明 |
|------|------|------|
| `projectRoot` | `string` | 项目根目录路径（必填），用于定位 `.harness/rules/`、`.harness/agents/` 和 `CLAUDE.md` |

## AutoregressiveContextSchema — 自回归上下文模式

### 核心职责

AutoregressiveContextSchema是纯函数模块（非类），负责：
- 向目标对象注入自回归上下文字段（前驱结果、质量分数、反馈、迭代信息等）
- 危险键过滤（防止注入 `__proto__`、`constructor` 等原型链污染键）
- 字段数上限控制（最多20个字段）
- 字符串截断（超长字符串截断至2000字符）和大数组截断（超100元素截断）
- 版本号自动附加和更新时间戳
- 上下文数据验证（数值范围、数组类型、字符串类型检查）
- 版本兼容性检查（旧版本字段缺失检测、新版本不兼容警告）

### 自回归上下文字段

| 字段名 | 类型 | 说明 |
|--------|------|------|
| `previousResult` | `string` | 前驱结果描述 |
| `previousScore` | `number` | 前驱质量分数（0-1） |
| `qualityHistory` | `Array` | 质量分数历史 |
| `feedback` | `string` | 反馈信息 |
| `previousOutput` | `string` | 前驱输出内容 |
| `focusAreas` | `Array` | 聚焦领域 |
| `originalGoal` | `string` | 原始目标 |
| `iteration` | `number` | 当前迭代序号（≥0） |
| `maxIterations` | `number` | 最大迭代次数（1-100） |
| `iterationSummary` | `string` | 迭代摘要 |
| `source` | `string` | 来源标识 |

### 来源标识

| 常量 | 值 | 说明 |
|------|-----|------|
| `SOURCE_IDS.ORCHESTRATOR` | `'deepening-orchestrator'` | 深化推理编排器 |
| `SOURCE_IDS.REFINEMENT` | `'iterative-refinement'` | 迭代精化器 |
| `SOURCE_IDS.RECURRENT` | `'recurrent-deepening-scheduler'` | 循环深化调度器 |
| `SOURCE_IDS.SKILL_COMPLETE` | `'skill-complete'` | 技能完成 |
| `SOURCE_IDS.PHASE_ADVANCE` | `'phase-advance'` | 阶段推进 |

### 核心API

| 方法 | 返回值 | 说明 |
|------|--------|------|
| `inject(target, fields)` | `Object` | 向目标对象注入自回归上下文字段，过滤危险键，截断超长值，附加版本号和时间戳 |
| `extract(target)` | `Object\|null` | 从目标对象提取自回归上下文数据，排除 `_version` 和 `updatedAt` 元数据字段 |
| `merge(target, overrides)` | `Object` | 合并自回归上下文：提取现有上下文与覆盖字段合并后重新注入 |
| `validate(target)` | `{ valid, warnings }` | 验证上下文数据的数值范围和类型合法性 |
| `compatibilityCheck(target, requiredVersion?)` | `Object` | 检查上下文版本兼容性，旧版本检查字段缺失，新版本返回不兼容警告 |
| `strip(target)` | `Object` | 从目标对象移除 `_ar` 属性 |

### 导出常量

| 常量 | 值 | 说明 |
|------|-----|------|
| `AR_CONTEXT_KEY` | `'_ar'` | 自回归上下文在目标对象上的属性键 |
| `VERSION` | `1` | 当前上下文模式版本号 |
| `FIELDS` | `Object` | 所有合法字段名枚举 |
| `VERSION_FIELD_MAP` | `Object` | 版本→字段列表映射（v0=[], v1=全部字段） |
| `SOURCE_IDS` | `Object` | 来源标识常量集合 |

### 验证规则

`validate()` 方法检查以下约束：

| 字段 | 约束 |
|------|------|
| `previousScore` | 必须为数字，范围0-1 |
| `iteration` | 必须为数字，≥0 |
| `maxIterations` | 必须为数字，范围1-100 |
| `qualityHistory` | 若存在必须为数组 |
| `focusAreas` | 若存在必须为数组 |
| `previousResult` 等 | 若存在必须为字符串 |

### 兼容性检查规则

`compatibilityCheck()` 的判断逻辑：

| 场景 | 结果 |
|------|------|
| 目标无 `_ar` 属性 | `{ compatible: true, reason: 'no_ar_context' }` |
| 版本匹配 | `{ compatible: true, reason: 'version_match' }` |
| 上下文版本 > 所需版本 | `{ compatible: false, reason: 'newer_version_not_guaranteed_compatible' }` |
| 上下文版本 < 所需版本，无缺失字段 | `{ compatible: true, reason: 'older_version_compatible' }` |
| 上下文版本 < 所需版本，有缺失字段 | `{ compatible: false, reason: 'missing_fields_in_older_version' }` |

## 模块间协作流程

### 上下文压缩流程

```
1. SessionManager.addTokenUsage() → Token使用量增加
2. ContextCompressionEngine.shouldCompress({ tokensUsed, tokenBudget })
   ├── tokensUsed / tokenBudget >= threshold (0.8) → 需要压缩
   └── 否则 → 不需要压缩
3. ContextCompressionEngine.compress(context)
   ├── 计算状态哈希 → 与上次相同则增量跳过
   ├── 确定当前阶段索引（PHASE_INDEX）
   ├── 遍历技能列表 → _classifySkill()
   │   ├── _determineSkillCategory() → 判断技能类别
   │   │   ├── 检查因果覆盖（CausalBufferManager优先，CausalValidator降级）
   │   │   ├── 检查规格输出（specification_asset）
   │   │   └── 按阶段和完成状态分类
   │   └── _applyStrategy() → 应用压缩策略
   │       ├── full → 保留完整指令
   │       ├── summary → 压缩为摘要（摘要Token≥指令Token时降级为full）
   │       └── discard → 丢弃（Token节省=指令Token数）
   ├── 分类关键决策和会话状态
   ├── 保留规格资产
   ├── 更新统计信息
   └── 发出compression-complete事件
```

### 阶段上下文注入流程

```
1. PhaseContextInjector.injectForPhase(phase)
   ├── 验证阶段名（无效降级为brainstorming）
   ├── 检查缓存 → TTL内直接返回缓存结果
   ├── _buildPhaseContext(phase)
   │   ├── _extractCoreIdentity() → 从CLAUDE.md提取核心身份（排除Agent/规则/Skill章节）
   │   ├── _loadRulesForPhase(phase) → 加载阶段对应的规则文件
   │   ├── _loadAgentsForPhase(phase) → 加载阶段对应的Agent定义
   │   ├── 查询PHASE_SKILLS[phase] → 获取阶段技能列表
   │   └── _estimateTokens() → 估算Token消耗
   ├── 更新缓存
   └── 发出phase-context-injected事件
```

### Agent隔离上下文创建流程

```
1. IsolatedContextManager.createIsolatedContext(config)
   ├── 验证taskDescription必填
   ├── 截断超长注入上下文（>maxContextSize）
   ├── 检查容量 → 超出时驱逐最旧上下文（_evictOldest）
   ├── 生成上下文ID（ictx-前缀）
   ├── 按agentId分配默认工具集
   ├── 构建系统提示（_buildSystemPrompt）
   ├── 估算Token消耗
   ├── 创建ACL（owner=agentId）
   ├── 记录创建历史
   └── 发出context-created事件
```

### LTI上下文注入流程

```
1. LTIContextInjector.registerOriginalContext(taskId, context)
   ├── 克隆原始上下文
   ├── 存入注册表（超上限淘汰最早条目）
   └── 发出context-registered事件

2. LTIContextInjector.inject(taskId, currentTask, iteration)
   ├── 查找原始上下文 → 未注册则原样返回
   ├── _performInjection()
   │   ├── 深拷贝当前任务
   │   ├── 附加_ltiContext（原始目标、约束、迭代、模式）
   │   ├── LTI模式：计算目标信号
   │   │   ├── _computeGoalSignal() → _computeOverlap()
   │   │   ├── 重叠度 < 0.5 → goalSignal = originalGoal（目标漂移，注入原始目标）
   │   │   └── 重叠度 ≥ 0.5 → goalSignal = null（目标一致）
   │   ├── 补充缺失的description和goal
   │   └── 附加原始需求
   ├── 更新注入计数
   ├── 记录注入历史
   └── 发出context-injected事件
```

### 自回归上下文注入流程

```
1. AutoregressiveContextSchema.inject(target, fields)
   ├── 验证target和fields
   ├── 初始化target._ar
   ├── 遍历fields
   │   ├── 过滤危险键（DANGEROUS_KEYS）
   │   ├── 过滤未知字段（不在FIELDS中）
   │   ├── 检查字段数上限（MAX_AR_FIELDS=20）
   │   ├── 截断超长字符串（>2000字符）
   │   └── 截断超大数组（>100元素）
   ├── 附加版本号（_version=1）
   ├── 附加更新时间戳（updatedAt）
   └── 返回target
```

### 优雅关机流程

```
1. ContextCompressionEngine._onShutdown()
   ├── 清除压缩计划缓存
   ├── 清除增量状态
   ├── 释放因果组件引用
   └── 移除所有事件监听器

2. IsolatedContextManager._onShutdown()
   ├── 清除上下文Map
   ├── 清除访问控制Map
   ├── 清除操作历史
   └── 移除所有事件监听器

3. LTIContextInjector._onShutdown()
   ├── 清除原始上下文注册表
   ├── 清除注入历史
   └── 移除所有事件监听器

4. PhaseContextInjector._onShutdown()
   ├── 清除阶段缓存
   └── 移除所有事件监听器
```

## 与其他子系统的交互

### 与会话子系统（Session Subsystem）的交互

- **SessionManager** 通过 `attachPhaseContextInjector()` 挂载 `PhaseContextInjector`，在阶段转换时调用 `injectForPhase()` 自动注入阶段上下文
- **SessionManager** 在阶段转换和Skill完成时通过 `AutoregressiveContextSchema.inject()` 注入自回归上下文，记录前驱结果和迭代信息
- **SessionManager** 在Token使用量增加时，可调用 `ContextCompressionEngine.shouldCompress()` 判断是否需要压缩

### 与因果子系统（Causal Subsystem）的交互

- **ContextCompressionEngine** 通过 `attachConfigCausalValidator()` 挂载 `CausalConfigValidator`，在压缩时判断技能是否为当前阶段技能的因果上游
- **ContextCompressionEngine** 通过 `attachCausalBufferManager()` 挂载 `CausalBufferManager`，获取技能间因果关联的压缩策略
- **CausalDataBus** 的事件流为压缩引擎提供因果依赖信息，确保因果相关技能不被错误丢弃

### 与深化推理子系统（Deepening Subsystem）的交互

- **DeepeningOrchestrator** 通过 `AutoregressiveContextSchema.inject()` 在每次深化迭代中注入前驱结果和质量分数
- **IterativeRefinement** 使用 `AutoregressiveContextSchema.merge()` 合并迭代反馈到上下文中
- **RecurrentDeepeningScheduler** 通过 `AutoregressiveContextSchema` 的 `source=RECURRENT` 标识注入来源
- **LTIContextInjector** 在深化迭代中注入原始目标，防止迭代深化过程中的目标漂移

### 与工作流子系统（Workflow Subsystem）的交互

- **PhaseOrchestrator** 在阶段转换时触发 `PhaseContextInjector.injectForPhase()` 加载新阶段的规则和Agent定义
- **GoalExecutor** 通过 `IsolatedContextManager.createIsolatedContext()` 为子任务创建隔离执行上下文
- **CommandRouter** 通过 `PhaseContextInjector.getCurrentPhase()` 获取当前阶段信息辅助命令路由

### 与Agent子系统（Agent Subsystem）的交互

- **AgentRuntime** 通过 `IsolatedContextManager` 为每个Agent任务创建隔离上下文，分配工具集和系统提示
- **SubagentExecutor** 通过 `IsolatedContextManager.grantContextAccess()` 授予子Agent对父任务上下文的访问权限
- **AgentChannel** 在Agent间传递消息时，通过 `IsolatedContextManager` 的访问控制确保上下文隔离

### 与思维子系统（Thought Subsystem）的交互

- **MemoryPrefetcher** 监听 `PhaseContextInjector` 的 `phase-context-injected` 事件，在阶段上下文注入后预取相关记忆
- **DreamEngine** 通过 `AutoregressiveContextSchema.extract()` 提取自回归上下文用于经验提炼

### 与模型子系统（Model Subsystem）的交互

- **TokenManager** 通过 `ContextCompressionEngine.shouldCompress()` 和 `compress()` 实现Token预算约束下的上下文压缩
- **InferenceCache** 可利用 `ContextCompressionEngine.compressOutput()` 压缩缓存输出减少Token消耗

### 与基础设施子系统（Infrastructure Subsystem）的交互

- **EventBus** 可转发 `ContextCompressionEngine` 和 `IsolatedContextManager` 的事件到全局事件流
- **HealthChecker** 通过 `IsolatedContextManager.isHealthy()` 和 `getStats()` 获取上下文健康指标
- **ConcurrencyController** 通过 `IsolatedContextManager` 的容量管理限制并发上下文数量
