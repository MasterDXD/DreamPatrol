# 核心功能-上下文压缩引擎

> 版本：2.73.4 | 模块：src/runtime/context/context-compression-engine.js

---

## 概述

ContextCompressionEngine负责在Token使用率接近阈值时，智能压缩上下文内容，确保关键信息不丢失的同时减少Token消耗。引擎基于Skill分类体系和因果感知机制，对上下文中的每个Skill条目进行分类、策略匹配和压缩执行。

## 压缩策略

| 策略 | 说明 | 适用内容 |
|------|------|---------|
| **full** | 保留原文，不做压缩 | 当前阶段指令、规格资产、因果高相关Skill |
| **summary** | 摘要压缩，仅保留summary字段 | 已完成阶段、未来阶段、因果中等相关Skill |
| **discard** | 完全丢弃，compressedTokenEstimate=0 | 临时数据、因果低相关Skill |

> **注意**：策略名称为`full`（非`keep`），与代码中`VALID_STRATEGIES = new Set(['full', 'summary', 'discard'])`一致。

## Skill分类体系

引擎首先通过`_determineSkillCategory()`对每个Skill进行分类，分类结果决定所应用的压缩策略：

| 分类 | 说明 | 默认策略 |
|------|------|---------|
| **current_phase** | Skill的phase与当前执行阶段一致 | `full` |
| **completed_phase** | Skill的skill_id在completedSkills集合中 | `summary` |
| **future_phase** | Skill的phase在当前阶段之后 | `summary` |
| **unclassified** | 无法归入以上三类的Skill | `full` |
| **specification_asset** | Skill的causal_outputs中包含`specification`输出 | `full`（不可更改） |

### 分类优先级

分类逻辑按以下优先级执行：

1. **因果覆盖检测**（`_matchSkillPattern`）：若CausalBufferManager或ConfigCausalValidator返回覆盖结果，优先使用
2. **规格资产检测**（`_hasSpecificationOutput`）：若Skill的causal_outputs包含`specification`，标记为`specification_asset`
3. **阶段分类**：按current → completed → future → unclassified顺序判断

## 因果覆盖分类

当接入因果子系统后，已完成的Skill可能被重新分类为因果相关，覆盖默认的阶段分类：

| 因果覆盖分类 | 说明 | 策略 |
|-------------|------|------|
| **causal_relevance_high** | CausalBufferManager返回`full`策略（注意力权重≥0.7） | `full` |
| **causal_relevance_medium** | CausalBufferManager返回`summary`策略（注意力权重0.3~0.7） | `summary` |
| **causal_relevance_low** | CausalBufferManager返回`discard`策略（注意力权重<0.3） | `discard` |
| **causal_upstream** | ConfigCausalValidator检测到当前阶段Skill依赖此Skill | `full` |

### 因果覆盖检测流程

```
_matchSkillPattern(skill, isCompleted, currentPhase)
  ↓
1. CausalBufferManager已连接 且 Skill已完成 且 当前SkillId已设置？
   → getCompressionStrategy(skillId, currentSkillId)
   → 'full' → causal_relevance_high
   → 'summary' → causal_relevance_medium
   → 其他 → causal_relevance_low
  ↓ 否
2. ConfigCausalValidator已连接 且 Skill已完成？
   → _isCausalUpstream(skillId, currentPhase)
   → true → causal_upstream
  ↓ 否
返回 null（无覆盖，使用默认阶段分类）
```

## Token估算算法

`_estimateTokens(text)`方法估算文本的Token数量：

```
非ASCII字符数 = text.match(/[\x80-\uFFFF]/g).length
ASCII字符数 = text.length - 非ASCII字符数
Token数 = ceil((ASCII字符数 + 非ASCII字符数 × 2) / tokenCharsRatio)
```

- ASCII字符：每4个字符约1个Token（默认tokenCharsRatio=4）
- 非ASCII字符（中文等）：每2个字符约1个Token（权重×2）
- 此为近似估算，实际Token消耗取决于模型分词器

## 完整配置项

| 配置项 | 类型 | 默认值 | 说明 |
|--------|------|--------|------|
| `threshold` | number | `TOKEN_BUDGET_WARNING_RATIO`（0.8） | 触发压缩的Token使用率阈值 |
| `retainCurrentPhase` | boolean | `true` | 是否保留当前阶段上下文 |
| `retainKeyDecisions` | boolean | `true` | 是否保留关键决策 |
| `tokenCharsRatio` | number | `4` | Token估算的字符比率 |
| `retainSessionState` | boolean | `true` | 是否保留会话状态 |
| `maxSummaryLength` | number | `200` | 摘要最大长度（预留字段） |
| `strategies` | object | 见下表 | 各分类的压缩策略映射 |

### strategies默认值

```json
{
  "completed_phase": "summary",
  "future_phase": "summary",
  "current_phase": "full",
  "unclassified": "full",
  "specification_asset": "full"
}
```

## compress()返回值结构

`compress(context)`方法返回以下结构：

```javascript
{
  retainedSkills: [         // 保留的Skill列表
    {
      skill_id: string,
      phase: string,
      instruction: string,  // 原始指令（full策略）
      summary: string,
      retained: true,
      reason: string,       // 分类名（如'current_phase'）
      strategy: 'full'
    }
  ],
  compressedSkills: [       // 被压缩的Skill列表
    {
      skill_id: string,
      phase: string,
      summary: string,      // 摘要（summary策略）
      compressed: true,
      originalTokenEstimate: number,
      compressedTokenEstimate: number,
      reason: string,       // 分类名或'{category}_discarded'
      strategy: 'summary' | 'discard'
    }
  ],
  tokenSavings: number,              // 节省的Token数
  compressionRatio: number,          // 压缩比率（0~1，保留2位小数）
  originalTokenEstimate: number,     // 原始Token估算
  compressedTokenEstimate: number,   // 压缩后Token估算
  keyDecisions: Array,               // 关键决策（若retainKeyDecisions=true）
  sessionState: Object,              // 会话状态（若retainSessionState=true）
  retainedSpecAssets: [              // 保留的规格资产
    {
      asset_id: string,
      asset_type: string,
      retained: true,
      reason: 'specification_asset',
      strategy: 'full'
    }
  ]
}
```

## 因果感知压缩机制

### attachConfigCausalValidator(validator)

注入ConfigCausalValidator实例，用于检测因果上游关系。要求validator实现`getDependencyGraph()`方法。注入后自动清除增量状态缓存和计划缓存。

### attachCausalBufferManager(manager)

注入CausalBufferManager实例，用于获取注意力权重驱动的压缩策略。要求manager实现`getCompressionStrategy()`方法。注入后自动清除增量状态缓存和计划缓存。

### setCurrentSkillId(skillId)

设置当前正在执行的Skill ID，CausalBufferManager需要此信息来计算注意力权重。返回this以支持链式调用。

### _isCausalUpstream(skillId, currentPhase)

检测指定Skill是否为当前阶段的因果上游：

1. 从ConfigCausalValidator获取依赖图
2. 查找当前阶段所有Skill
3. 检查这些Skill的dependsOnSet是否包含目标skillId
4. 结果缓存到`_causalUpstreamCache`（TTL=DEFAULT_PIPELINE_TIMEOUT_MS，最大500条）

## 运行时策略修改

### setStrategy(category, strategy)

运行时修改指定分类的压缩策略：

```javascript
engine.setStrategy('completed_phase', 'discard'); // 将已完成阶段改为丢弃
```

**约束**：
- `category`必须是当前strategies配置中已存在的键
- `strategy`必须是`full`、`summary`、`discard`之一
- **`specification_asset`分类不可更改**（始终为`full`），尝试设置非full策略返回false
- 修改成功后自动清除增量状态缓存和计划缓存
- 触发`strategy-changed`事件

### getStrategies()

返回当前所有分类的策略映射（深拷贝）。

## 增量压缩与缓存

### 增量跳过

`compress()`方法通过`_computeStateHash()`计算上下文状态的哈希值。若哈希值与上次相同且存在缓存结果，直接返回深拷贝的缓存结果，跳过重复计算。统计中`incrementalSkips`计数器递增。

### 计划缓存

`getCompressionPlan()`方法使用`_planCache`（Map，最大50条）缓存压缩计划。缓存键由`currentPhase:skillCount:completedCount`组成。缓存命中时`cacheHits`计数器递增。

## 压缩流程

```
上下文输入 → 增量状态哈希检查 → 相同？→ 返回缓存结果
  ↓ 不同
Skill分类（_determineSkillCategory）
  → 因果覆盖检测 → 规格资产检测 → 阶段分类
  ↓
策略应用（_applyStrategy）
  → full: 保留原文
  → summary: 保留摘要
  → discard: 完全丢弃
  ↓
上下文分类（_classifyContext）
  → 关键决策/会话状态/规格资产
  ↓
统计更新 → 缓存结果 → 触发compression-complete事件
```

## 触发条件

- `shouldCompress(context)`返回true：Token使用率 ≥ threshold阈值
- 手动调用`compress()`方法

## 使用方式

```javascript
const { ContextCompressionEngine } = require('./src');

const engine = new ContextCompressionEngine({
  threshold: 0.8,
  retainCurrentPhase: true,
  retainKeyDecisions: true,
  tokenCharsRatio: 4,
  strategies: {
    completed_phase: 'summary',
    future_phase: 'summary',
    current_phase: 'full',
    unclassified: 'full',
    specification_asset: 'full',
  },
});

// 可选：接入因果子系统
engine.attachConfigCausalValidator(validator);
engine.attachCausalBufferManager(bufferManager);
engine.setCurrentSkillId('tdd-implement');

// 执行压缩
const compressed = engine.compress({
  currentPhase: 'module-development',
  skills: [...],
  completedSkills: ['brainstorming', 'requirement-analysis'],
  keyDecisions: [...],
  sessionState: {...},
  specificationAssets: [...],
  tokensUsed: 85000,
  tokenBudget: 100000,
});

// 运行时修改策略
engine.setStrategy('completed_phase', 'discard');
```

## 完整API列表

| 方法 | 返回值 | 说明 |
|------|--------|------|
| `compress(context)` | `Object` | 执行上下文压缩，返回压缩结果 |
| `shouldCompress(context)` | `boolean` | 判断是否应触发压缩 |
| `getCompressionPlan(context)` | `Object` | 获取压缩计划（不执行），含retain/compress/estimatedSavings |
| `setStrategy(category, strategy)` | `boolean` | 运行时修改策略，specification_asset不可更改 |
| `getStrategies()` | `Object` | 获取当前策略映射 |
| `setCurrentSkillId(skillId)` | `this` | 设置当前Skill ID（链式调用） |
| `attachConfigCausalValidator(validator)` | `this` | 注入因果配置验证器 |
| `attachCausalBufferManager(manager)` | `this` | 注入因果缓冲管理器 |
| `getConfig()` | `Object` | 获取当前配置（深拷贝） |
| `getStats()` | `Object` | 获取统计信息 |

### 事件

| 事件名 | 触发时机 | 数据 |
|--------|---------|------|
| `compression-complete` | compress()完成 | 压缩结果对象 |
| `strategy-changed` | setStrategy()成功 | `{ category, strategy }` |
| `invalid-phase` | currentPhase不在PHASE_INDEX中 | `{ currentPhase }` |
