# 核心功能-目标执行引擎

> 版本：2.73.4 | 模块：src/runtime/workflow/goal-executor.js

---

## 概述

GoalExecutor是框架的自主执行引擎，负责将复杂目标分解为可执行的子任务，并通过迭代收敛机制确保目标达成。支持自动分解子任务、因果数据发布、停滞检测和持久化恢复。

> 详细的API文档和状态机说明请参见 [模块详解-GoalExecutor目标执行器](../modules/模块详解-GoalExecutor目标执行器.md)

## 核心能力

| 能力 | 说明 |
|------|------|
| **自主迭代收敛** | 自动检测停滞并调整策略 |
| **自动分解子任务** | 将大目标拆分为可执行的原子任务 |
| **因果数据发布** | 通过CausalDataBus发布执行过程中的因果数据 |
| **停滞检测** | 检测执行停滞并触发策略调整 |
| **持久化恢复** | 支持从检查点恢复执行 |
| **超时与取消** | 基于AbortSignal的取消机制和超时控制 |
| **异步初始化** | `ready`属性提供初始化完成Promise，支持await等待异步恢复完成 |
| **关闭状态保留** | 关闭时将活跃目标持久化为PAUSED状态，确保重启后可恢复 |

## 执行流程

```
目标输入 → 分解子任务 → 执行子任务 → 评估结果 → 收敛？
                                                    │
                                           否 → 调整策略 → 重新执行
                                           是 → 输出结果
```

## 使用方式

```javascript
const GoalExecutor = require('./src/runtime/workflow/goal-executor');

const executor = new GoalExecutor({
  maxIterations: 10,
  convergenceThreshold: 0.85,
});

const { goalId } = executor.createGoal('实现用户认证模块', {
  successCriteria: ['登录功能正常', 'Token刷新正常'],
});

const result = await executor.execute(goalId, async (ctx, opts) => {
  return { success: true, qualityScore: 0.9 };
});
```

## 目标状态机

### 目标状态枚举（GOAL_STATUS）

| 状态 | 值 | 说明 |
|------|-----|------|
| `PENDING` | `'pending'` | 目标已创建，等待执行 |
| `DECOMPOSING` | `'decomposing'` | 正在自动分解子任务 |
| `EXECUTING` | `'executing'` | 目标正在执行中 |
| `ITERATING` | `'iterating'` | 迭代循环执行中 |
| `PAUSED` | `'paused'` | 目标已暂停，可恢复 |
| `COMPLETED` | `'completed'` | 目标已完成 |
| `FAILED` | `'failed'` | 目标执行失败 |
| `CANCELLED` | `'cancelled'` | 目标已取消 |
| `BLOCKED` | `'blocked'` | 目标被阻塞 |

### 子任务状态枚举（SUBTASK_STATUS）

| 状态 | 值 | 说明 |
|------|-----|------|
| `PENDING` | `'pending'` | 子任务待执行 |
| `RUNNING` | `'running'` | 子任务执行中 |
| `COMPLETED` | `'completed'` | 子任务已完成 |
| `FAILED` | `'failed'` | 子任务执行失败 |
| `SKIPPED` | `'skipped'` | 子任务已跳过 |
| `BLOCKED` | `'blocked'` | 子任务被阻塞（依赖未满足或循环依赖） |

### 状态转换规则

```
createGoal()
  └─→ PENDING

execute()
  PENDING ──→ EXECUTING ──→ DECOMPOSING ──→ ITERATING ──→ COMPLETED
                │                │               │              │
                │                │               │              └─→ FAILED（异常）
                │                │               │
                │                │               ├─→ PAUSED（pause / shutdown）
                │                │               └─→ CANCELLED（cancel）
                │                │
                │                ├─→ PAUSED（pause / shutdown）
                │                └─→ CANCELLED（cancel）
                │
                ├─→ PAUSED（pause / shutdown）
                └─→ CANCELLED（cancel）

pause()
  EXECUTING / ITERATING / DECOMPOSING ──→ PAUSED

resume()
  PAUSED ──→ ITERATING ──→ COMPLETED / PAUSED（未收敛时重新暂停）

cancel()
  任何非终态 ──→ CANCELLED

shutdown()
  EXECUTING / ITERATING / DECOMPOSING ──→ PAUSED（持久化后可恢复）
```

**终态**：`COMPLETED`、`FAILED`、`CANCELLED` — 进入终态后不可再转换。

**活跃状态**（计入并发限制）：`PENDING`、`EXECUTING`、`DECOMPOSING`、`ITERATING`、`PAUSED`

## 子任务分解策略

### 触发条件

当 `autoDecompose` 配置为 `true`（默认）且目标尚无子任务时，`execute()` 在进入迭代循环前自动触发 `_decomposeGoal()`。

### 分解流程

```
构建分解提示 → 调用executeFn(phase='decompose') → 解析结果 → 循环依赖检测
```

### 分解提示结构（decompositionPrompt）

```javascript
{
  objective: goal.objective,       // 目标描述
  constraints: goal.constraints,   // 约束条件
  successCriteria: goal.successCriteria, // 成功标准
  context: goal.context,           // 附加上下文
  _task: 'decompose',              // 任务类型标识
  _maxSubtasks: config.maxSubtasks // 最大子任务数限制
}
```

### 结果解析策略

| 返回类型 | 解析方式 | 示例 |
|---------|---------|------|
| `{ subtasks: Array }` | 逐项映射为子任务对象，支持 `id`、`description`/`name`、`dependencies`、`priority` 字段 | `{ subtasks: [{ id: 's1', description: '步骤1', dependencies: [] }] }` |
| `string` | 按换行符分割，自动剥离行首序号标记（`1.`、`-`、`*`） | `"1. 步骤一\n2. 步骤二"` |
| 异常 | 降级为单子任务，以目标描述作为唯一子任务 | — |

### 子任务对象结构

```javascript
{
  subtaskId: 'sub-xxxxx',   // 自动生成或自定义ID
  index: 0,                 // 顺序索引
  description: '...',       // 子任务描述
  status: 'pending',        // 初始状态
  dependencies: [],          // 依赖的其他子任务ID
  priority: 0,              // 优先级（默认等于索引）
  result: null,             // 执行结果
  startedAt: null,          // 开始时间
  completedAt: null         // 完成时间
}
```

### 循环依赖检测

分解完成后自动执行 `_detectCircularDependencies()`，基于DFS遍历依赖图：

1. 构建以 `subtaskId`/`index` 为节点的有向图
2. 使用迭代式DFS检测回边（back edge）
3. 发现循环时：将涉及子任务状态设为 `BLOCKED`，标记 `_circularDependency = true`
4. 触发 `circular-dependency-detected` 事件

### 子任务执行调度

| 场景 | 策略 |
|------|------|
| 无依赖子任务数 > 1 | `_executeSubtasksParallel()` — 并行执行，`Promise.allSettled()` 收集结果 |
| 无依赖子任务数 = 1 | `_executeOneSubtask()` — 串行执行 |
| 有未满足依赖的子任务 | 状态设为 `BLOCKED`，等待依赖完成后重新设为 `PENDING` 再执行 |

每个子任务执行时均受 `iterationTimeout` 超时控制和 `AbortSignal` 取消信号保护。

## 停滞检测机制

### 算法实现

```javascript
_isStagnant(qualityHistory) {
  if (qualityHistory.length < 5) return false;       // 不足5条记录，不判定停滞
  const recent = qualityHistory.slice(-5);            // 取最近5次迭代评分
  const scores = recent.map(r => r.score);
  const improvement = scores[4] - scores[0];          // 首尾改进量
  const lastScore = scores[4];
  if (lastScore >= 0.7) return improvement < 0.005;   // 高分区间：改进 < 0.5% 判定停滞
  return improvement < 0.02;                          // 低分区间：改进 < 2% 判定停滞
}
```

### 判定参数

| 参数 | 值 | 说明 |
|------|-----|------|
| 最小观察窗口 | 5 次迭代 | 质量历史不足5条时不判定停滞 |
| 内部收敛阈值 | `0.7` | 高于此分数进入"精化区间" |
| 高分停滞阈值 | `0.005`（0.5%） | 分数 ≥ 0.7 时，改进量低于此值判定停滞 |
| 低分停滞阈值 | `0.02`（2%） | 分数 < 0.7 时，改进量低于此值判定停滞 |

### 双阈值设计意图

- **低分区间**（< 0.7）：容忍度较高，2% 以下改进视为停滞，避免在低效方向上浪费迭代
- **高分区间**（≥ 0.7）：容忍度极低，0.5% 以下改进视为停滞，因为接近收敛时改进空间本就有限

### 停滞后的行为

检测到停滞时，`_runGoalLoop()` 立即退出迭代循环，返回当前最佳结果。此时目标状态仍为 `ITERATING`，由外层 `execute()` 方法将其标记为 `COMPLETED`（因为已有有效结果）。

## 因果数据发布

### 发布时机

目标执行完成（状态转为 `COMPLETED`）后，通过 `_publishCausalOutput()` 向 CausalDataBus 发布因果数据。

### 发布的数据结构

```javascript
this._causalDataBus.publishOutput('goal-executor', {
  goalId: goal.goalId,           // 目标ID
  objective: goal.objective,     // 目标描述
  iterations: goal.currentIteration, // 实际迭代次数
  qualityHistory: goal.qualityHistory, // 质量评分历史
  duration: goal.completedAt - goal.startedAt, // 执行耗时(ms)
});
```

### 数据字段说明

| 字段 | 类型 | 说明 |
|------|------|------|
| `goalId` | `string` | 唯一目标标识，格式 `goal-xxxxx` |
| `objective` | `string` | 目标描述文本 |
| `iterations` | `number` | 实际执行的迭代轮次 |
| `qualityHistory` | `Array<{iteration, score, timestamp}>` | 每轮质量评分记录，最多保留50条 |
| `duration` | `number` | 从 `startedAt` 到 `completedAt` 的毫秒数 |

### 依赖条件

因果数据发布依赖 `attachCausalDataBus()` 注入的 CausalDataBus 实例。未注入时 `_publishCausalOutput()` 静默跳过。发布失败时仅记录调试日志，不影响目标完成流程。

## 持久化与恢复

### 持久化机制

#### 存储路径

```
{projectRoot}/{persistPath}/{goalId}.json
```

默认路径为 `.harness/goals/`，路径遍历防护确保存储目录在项目根目录下。

#### 持久化触发点

| 触发场景 | 方法 | 同步/异步 |
|---------|------|----------|
| 创建目标后 | `_persistGoal()` | 异步 |
| 状态变更后 | `_persistGoal()` | 异步 |
| 每次迭代完成 | `_persistGoal()` | 异步 |
| 子任务完成/失败 | `_persistGoal()` | 异步 |
| 定时刷盘 | `_startPersistTimer()` → `_persistGoal()` | 异步 |
| 关闭时 | `_persistGoalSync()` | 同步 |

#### 持久化保护机制

| 机制 | 参数 | 说明 |
|------|------|------|
| 写入锁链 | `MAX_PERSIST_LOCKS = 1000` | 同一 goalId 的写入串行化，防止竞态 |
| 锁超时 | `DEFAULT_REQUEST_TIMEOUT_MS` | 防止锁永久阻塞 |
| 失败重试 | `MAX_PERSIST_RETRIES = 5` | 连续失败5次后跳过该目标的持久化 |
| 失败计数上限 | `MAX_PERSIST_FAIL_COUNTS = 500` | BoundedMap 限制，防止内存泄漏 |
| 原子写入 | `writeAtomicAsync()` | 防止写入中断导致文件损坏 |
| 恢复等待 | `_restorePromise` | 持久化操作等待恢复完成后再执行 |

#### 定时刷盘

通过 `_startPersistTimer()` 以 `persistInterval`（默认 `DEFAULT_METRICS_FLUSH_MS`）为间隔，定期对所有活跃目标执行持久化。定时器使用 `unref()` 避免阻止进程退出。

### 恢复机制

#### 恢复流程

```
构造函数 → _restoreGoals() → 读取persistDir下所有.json文件 → 逐文件恢复 → _initialized = true
```

#### 单目标恢复逻辑（`_restoreSingleGoal`）

1. **加载与消毒**：`loadJsonAsync()` 加载文件 → `sanitizeObject()` 原型链消毒
2. **字段验证**：`goalId` 必须为非空字符串，`objective` 必须为非空字符串，`status` 必须在 `VALID_GOAL_STATUSES` 中
3. **TTL过期检查**：若 `now - updatedAt > goalTTL`（默认7天），删除文件并跳过
4. **状态降级**：`EXECUTING`/`ITERATING`/`DECOMPOSING` 状态自动降级为 `PAUSED`（因为进程重启后无法继续执行）
5. **参数修正**：`_sanitizeRestoredGoal()` 修正越界参数

#### 恢复后参数修正

| 参数 | 修正规则 |
|------|---------|
| `maxIterations` | `clamp(1, 100, parseIntOrDefault)` |
| `convergenceThreshold` | `clamp01(parseFloatOrDefault)` |
| `subtasks` | 截断至 `maxSubtasks` 条 |
| `qualityHistory` | 截断至最近20条 |

#### 异步初始化

`ready` 属性返回 `_restorePromise`，调用方应 `await executor.ready` 确保恢复完成后再操作：

```javascript
const executor = new GoalExecutor({ projectRoot: '/project' });
await executor.ready; // 等待恢复完成
executor.createGoal('...'); // 安全操作
```

### 关闭时状态保留

`shutdown()` 流程：

1. 设置 `_shuttingDown = true`，阻止新迭代启动
2. 等待所有活跃循环（`_loopPromises`）结束，超时 `SHUTDOWN_WAIT_TIMEOUT_MS`
3. 轮询检查 `_executingGoals` 清空，间隔 `SHUTDOWN_POLL_INTERVAL_MS`（100ms）
4. 将 `EXECUTING`/`ITERATING`/`DECOMPOSING` 状态的目标持久化为 `PAUSED`
5. 清理超过1天的已完成/失败/取消目标

### 质量评分算法

```
最终评分 = baseScore × BASE_WEIGHT + criteriaScore × CRITERIA_WEIGHT
```

**baseScore 计算规则**：

| 条件 | baseScore |
|------|-----------|
| 有子任务结果 | `completedSubtasks / totalSubtasks` |
| `result.qualityScore` 为数字 | `result.qualityScore` |
| `result.success === true` | `0.8` |
| `result.success === false` | `0.2` |
| 其他 | `0.1` |

**criteriaScore 计算规则**：

从 `result.verification` 或 `result.goalVerification` 中检查每个 `successCriteria` 条目是否通过（`true` / `'passed'` / `{passed: true}`），计算通过率。

| `goal-decomposed` | 子任务分解完成 | `{ goalId, subtaskCount }` |

| `goal-iteration-complete` | 每轮迭代完成 | `{ goalId, iteration, score, bestScore }` |
| `goal-completed` | 目标执行完成 | `{ goalId, objective, iterations, duration }` |
| `goal-paused` | 目标暂停 | `{ goalId, iteration }` 或 `{ goalId, reason, bestScore }` |
| `goal-resumed` | 目标恢复执行 | `{ goalId, iteration }` |
| `goal-cancelled` | 目标取消 | `{ goalId, iteration }` |

### 异常事件

| 事件名 | 触发时机 | 载荷结构 |
|--------|---------|---------|
| `goal-failed` | 目标执行异常 | `{ message, code, context: { goalId } }`（via `emitError`） |
| `goal-iteration-error` | 单次迭代执行异常 | `{ goalId, iteration, error }` |
| `circular-dependency-detected` | 子任务存在循环依赖 | `{ cycles: Array<Array>, blockedCount }` |
| `persist-error` | 目标持久化失败 | `{ message, code, context: { goalId, phase? } }`（via `emitError`） |
| `init-error` | 初始化恢复阶段异常 | `{ message, code, context: { phase: 'init' } }`（via `emitError`） |
| `restore-error` | 目标恢复过程异常 | `{ error, operation: 'restoreGoals' }` |

### 关闭事件

| 事件名 | 触发时机 | 载荷结构 |
|--------|---------|---------|
| `shutdown` | 执行器关闭完成 | `{ signal }`（via `withShutdown` mixin） |

### 事件监听示例

```javascript
executor.on('goal-iteration-complete', ({ goalId, iteration, score, bestScore }) => {
  console.log(`目标 ${goalId} 第${iteration}轮：当前${score.toFixed(2)}，最佳${bestScore.toFixed(2)}`);
});

executor.on('circular-dependency-detected', ({ cycles, blockedCount }) => {
  console.warn(`检测到${cycles.length}个循环依赖，${blockedCount}个子任务被阻塞`);
});
```

## GraphRag — 知识图谱增强检索

> 模块：src/runtime/workflow/graph-rag.js

### 概述

GraphRAG是从文档中提取实体和关系、构建实体聚类、支持多跳子图查询的知识图谱RAG引擎。为目标执行提供上下文知识支撑，弥补传统向量检索在关联推理上的不足。

### 核心能力

| 能力 | 说明 |
|------|------|
| **实体提取** | 四类实体识别（PERSON/ORG/TECH/CONCEPT），支持中英文混合 |
| **关系推理** | 基于共现窗口和关键词的关系类型检测（DEPENDS_ON/PART_OF/RELATED_TO） |
| **实体聚类** | 基于连通分量的自动聚类，发现隐含的知识社区 |
| **多跳查询** | BFS子图扩展，支持可配置跳数的相关性检索 |
| **弱关系剪枝** | 低于minRelationWeight的弱关系自动剪枝 |
| **嵌入服务集成** | 可选挂载EmbeddingService和VectorIndex增强检索 |

### 实体类型

| 类型 | 标识 | 匹配规则 |
|------|------|---------|
| `PERSON` | 人名 | Mr./Mrs./Dr./Prof.等前缀 + 姓名 |
| `ORG` | 组织 | Inc/Corp/Ltd/University/Institute等后缀 |
| `TECH` | 技术 | .js/.ts后缀、API/SDK/CLI等大写缩写、驼峰命名 |
| `CONCEPT` | 概念 | 模型/架构/系统/引擎等中文技术术语后缀 |

### 关系类型

| 类型 | 标识 | 关键词 |
|------|------|--------|
| `DEPENDS_ON` | 依赖 | depends on / 依赖 / 需要 / 引用 / 调用 |
| `PART_OF` | 组成 | part of / 包含 / 属于 / 组成 |
| `RELATED_TO` | 关联 | related to / 相关 / 关联 / 连接 |

### API概览

| 方法 | 签名 | 说明 |
|------|------|------|
| `ingestDocument` | `ingestDocument(docId, content, metadata?)` | 导入文档，提取实体和关系 |
| `buildClusters` | `buildClusters()` | 基于连通分量构建实体聚类 |
| `query` | `query(question, options?)` | 图谱查询，支持topK/maxHops/minRelevance参数 |
| `getEntityGraph` | `getEntityGraph(entityId, depth?)` | 获取指定实体周围的子图 |
| `getClusters` | `getClusters()` | 获取所有聚类列表 |
| `getStats` | `getStats()` | 统计信息 |

### 配置参数

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `maxEntities` | `5000` | 最大实体数 |
| `maxRelations` | `10000` | 最大关系数 |
| `maxClusters` | `100` | 最大聚类数 |
| `maxDocuments` | `500` | 最大文档数 |
| `cooccurrenceWindow` | `'paragraph'` | 共现窗口 |
| `minRelationWeight` | `0.1` | 最小关系权重 |

### 查询评分算法

```
匹配实体：直接得分 = 1.0
非匹配实体：距离衰减得分 = 0.5 / distance
关系加成：+relation.weight × 0.3
```

### 事件

| 事件名 | 触发时机 |
|--------|---------|
| `document-ingested` | 文档导入完成 |
| `clusters-built` | 聚类构建完成 |
| `query-executed` | 查询执行完成 |
| `error` | 操作异常 |

### 使用示例

```javascript
const GraphRag = require('./src/runtime/workflow/graph-rag');

const graphRag = new GraphRag({ maxEntities: 3000 });

// 导入文档
graphRag.ingestDocument('api-docs', 'UserService依赖于AuthModule...');

// 构建聚类
graphRag.buildClusters();

// 图谱查询
const results = graphRag.query('用户认证依赖哪些模块？', {
  topK: 5,
  maxHops: 3,
  minRelevance: 0.3
});
```

## BusinessGoal — 业务目标管理

> 模块：src/runtime/workflow/business-goal.js

### 概述

BusinessGoal是业务目标管理器，追踪业务KPI、管理反馈源及可信度评分、计算目标达成率，确保目标执行与业务价值对齐。

### 核心能力

| 能力 | 说明 |
|------|------|
| **KPI定义与追踪** | 定义业务指标，实时更新当前值，自动计算达成率 |
| **反馈源管理** | 注册反馈源并关联可信度评分(0~1)，加权聚合反馈 |
| **业务反思维度** | 五维业务反思：业务影响/客户满意度/成本效率/合规性/反馈质量 |
| **反馈历史裁剪** | 超500条自动裁剪至400条，防止内存溢出 |

### 业务反思维度（BUSINESS_REFLECTION_DIMENSIONS）

| 维度 | 标识 | 说明 |
|------|------|------|
| 业务影响 | `business_impact` | 目标对核心业务指标的贡献度 |
| 客户满意度 | `customer_satisfaction` | 用户/客户反馈的满意程度 |
| 成本效率 | `cost_efficiency` | 资源投入与产出的效率比 |
| 合规性 | `compliance` | 是否符合法规和内部规范 |
| 反馈质量 | `feedback_quality` | 反馈来源的可靠性和有用性 |

### API概览

| 方法 | 签名 | 说明 |
|------|------|------|
| `defineKpi` | `defineKpi(kpiId, name, target, unit)` | 定义业务KPI指标，上限100个 |
| `updateKpi` | `updateKpi(kpiId, currentValue)` | 更新KPI当前值 |
| `measureGoalAchievement` | `measureGoalAchievement()` | 计算目标达成率 |
| `registerFeedbackSource` | `registerFeedbackSource(sourceId, meta)` | 注册反馈源 |
| `recordFeedback` | `recordFeedback(sourceId, feedback)` | 记录反馈 |
| `getBusinessDimensions` | `getBusinessDimensions()` | 获取五维反思维度 |
| `getKpiSummary` | `getKpiSummary()` | 获取KPI摘要 |
| `getFeedbackHistory` | `getFeedbackHistory(limit?)` | 获取反馈历史 |

### 目标达成率计算

```
达成率 = 已达标KPI数 / 总KPI数
达标条件：current >= target（target为0或null的KPI不计入）
```

### 事件

| 事件名 | 触发时机 |
|--------|---------|
| `kpi-defined` | KPI定义完成 |
| `kpi-updated` | KPI值更新 |
| `feedback-recorded` | 反馈记录完成 |

### 使用示例

```javascript
const BusinessGoal = require('./src/runtime/workflow/business-goal');

const biz = new BusinessGoal();

// 定义KPI
biz.defineKpi('coverage', '测试覆盖率', 80, '%');
biz.defineKpi('response-time', 'API响应时间', 200, 'ms');

// 更新KPI
biz.updateKpi('coverage', 75);
biz.updateKpi('response-time', 180);

// 计算达成率
const achievement = biz.measureGoalAchievement();
// achievement = 0.5 (1/2 KPI达标：response-time达标，coverage未达标)

// 注册反馈源并记录反馈
biz.registerFeedbackSource('user-survey', { type: 'survey', credibility: 0.8 });
biz.recordFeedback('user-survey', { dimension: 'customer_satisfaction', score: 0.85 });
```

## SprintCycle — 冲刺周期管理

> 模块：src/runtime/workflow/sprint-cycle.js

### 概述

SprintCycle是迭代冲刺周期管理器，按CODE→TEST→REVIEW→INTEGRATE四阶段迭代执行，直到质量达标或达到最大冲刺次数。可作为GoalExecutor子任务的具体执行策略。

### 核心能力

| 能力 | 说明 |
|------|------|
| **四阶段冲刺** | CODE→TEST→REVIEW→INTEGRATE标准流程 |
| **质量门禁** | 质量评分达到阈值(默认0.85)自动完成 |
| **快速失败** | 测试失败时可选快速失败(failFastOnTest) |
| **审查门禁** | 审查不通过时可选失败(requireReviewPass) |
| **暂停/恢复** | 支持冲刺周期暂停和恢复 |
| **历史裁剪** | 超50条自动裁剪至25条 |

### 冲刺阶段（SPRINT_PHASES）

| 阶段 | 值 | 说明 |
|------|-----|------|
| `CODE` | `'code'` | 编码阶段 |
| `TEST` | `'test'` | 测试阶段 |
| `REVIEW` | `'review'` | 审查阶段 |
| `INTEGRATE` | `'integrate'` | 集成阶段 |

### 冲刺状态（SPRINT_STATES）

| 状态 | 说明 |
|------|------|
| `IDLE` | 空闲，未开始 |
| `RUNNING` | 冲刺执行中 |
| `PAUSED` | 已暂停 |
| `COMPLETED` | 已完成（质量达标） |
| `FAILED` | 已失败 |

### API概览

| 方法 | 签名 | 说明 |
|------|------|------|
| `run` | `run(executePhaseFn, context?)` | 运行冲刺周期 |
| `pause` | `pause()` | 暂停冲刺 |
| `resume` | `resume()` | 恢复冲刺 |
| `abort` | `abort()` | 中止冲刺 |
| `getHistory` | `getHistory()` | 获取冲刺历史 |
| `getStats` | `getStats()` | 统计快照 |

### 配置参数

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `maxSprints` | `10` | 最大冲刺次数 |
| `qualityThreshold` | `0.85` | 质量达标阈值 |
| `failFastOnTest` | `true` | 测试失败时快速失败 |
| `requireReviewPass` | `true` | 审查不通过时失败 |
| `autoAdvance` | `true` | 自动推进下一冲刺 |
| `sprintTimeoutMs` | `300000` | 冲刺超时（5分钟） |

### 执行流程

```
run() → 循环 {
  sprint N:
    CODE → TEST → REVIEW → INTEGRATE
    │       │       │        │
    │       失败?   拒绝?    提取quality
    │       ↓       ↓        ↓
    │   failFast? requireReview? quality >= threshold?
    │   快速失败  审查失败    → COMPLETED
    │
    暂停检测 → PAUSED
    最大冲刺 → FAILED
}
```

### 事件

| 事件名 | 触发时机 |
|--------|---------|
| `sprint-start` | 冲刺开始 |
| `sprint-end` | 冲刺结束 |
| `phase-start` | 阶段开始 |
| `phase-end` | 阶段结束 |
| `phase-error` | 阶段执行异常 |
| `cycle-completed` | 周期完成 |
| `cycle-paused` | 周期暂停 |
| `cycle-resumed` | 周期恢复 |
| `cycle-aborted` | 周期中止 |

### 使用示例

```javascript
const { SprintCycle, SPRINT_PHASES } = require('./src/runtime/workflow/sprint-cycle');

const sprint = new SprintCycle({
  maxSprints: 5,
  qualityThreshold: 0.9,
  failFastOnTest: true
});

const result = await sprint.run(async (phase, ctx) => {
  switch (phase) {
    case SPRINT_PHASES.CODE:
      return { filesChanged: ['src/auth.js'] };
    case SPRINT_PHASES.TEST:
      return { passed: true, coverage: 0.88 };
    case SPRINT_PHASES.REVIEW:
      return { approved: true, issues: 0 };
    case SPRINT_PHASES.INTEGRATE:
      return { quality: 0.92, deployed: true };
  }
});

// result = { completed: true, sprints: 1, quality: 0.92, reason: 'quality-threshold' }
```

## 四模块协作关系

```
GoalExecutor (核心编排)
     │
     ├── GraphRag (知识图谱检索)
     │    └─ 为目标执行提供上下文知识支撑
     │
     ├── BusinessGoal (业务目标追踪)
     │    └─ 确保目标执行与业务价值对齐
     │
     └── SprintCycle (冲刺执行策略)
          └─ 作为子任务的具体执行策略
```

- **GoalExecutor** 是核心编排引擎，负责目标的完整生命周期管理
- **GraphRAG** 提供知识图谱增强检索能力，弥补传统向量检索在关联推理上的不足
- **BusinessGoal** 追踪业务层面的KPI达成率和反馈可信度，暴露五个反思维度供自评估系统使用
- **SprintCycle** 实现迭代冲刺执行模式，可作为GoalExecutor子任务的具体执行策略
