# 核心功能-深化推理引擎

> 版本：2.73.4 | 模块：src/runtime/deepening/（52个源文件）

---

## 1. 深化推理引擎概述

深化推理引擎（Deepening Reasoning Engine）是 Harness Engineering 框架中规模最大的子系统，承担"迭代精化、质量收敛"的核心职责。当单次 Agent 执行无法达到质量阈值时，引擎通过多轮迭代、自适应深度调整、收敛检测等机制，驱动输出质量逐步逼近目标。

### 为什么需要深化推理？

| 问题 | 深化推理的解决方式 |
|------|-------------------|
| 单次执行质量不足 | 多轮迭代精化，每轮基于上轮反馈改进 |
| 不同任务复杂度差异大 | AdaptiveDepthController 根据任务特征自动选择深度等级 |
| 无限迭代浪费资源 | ConvergenceDetector 检测收敛信号，及时终止 |
| Token 预算有限 | TokenAwareDeepening 在预算约束下规划迭代次数 |
| 迭代过程中缺乏策略 | StrategyPlugin 提供5种策略模式，动态决策是否继续 |
| 需要可观测性 | MetricsCollector + ReportGenerator 提供全链路指标与报告 |

### 核心能力一览

| 能力 | 说明 |
|------|------|
| **迭代精化** | 多轮执行-评审循环，逐步提升输出质量 |
| **自适应深度** | 根据任务复杂度自动选择 quick/standard/deep/intensive 四级深度 |
| **收敛检测** | 多信号收敛判定（质量阈值、稳定性、平台期、质量退化） |
| **渐进深化** | 从浅到深逐级执行，支持 Review 和 Adversarial Review |
| **循环调度** | 周期性深化任务调度，支持 evaluator 驱动的收敛判定 |
| **Token 感知** | 在 Token 预算约束下动态计算最大迭代次数 |
| **策略驱动** | 5种内置策略（fixed-depth/adaptive/convergence-driven/budget-aware/quality-optimized） |
| **容错保护** | Circuit Breaker、Rate Limiter、Backpressure 等基础设施保障 |

## 2. 核心概念

### 2.1 深度等级（Depth Level）

引擎定义四个深度等级，对应不同的迭代强度和资源消耗：

| 等级 | 深度值 | 迭代次数 | Review | Adversarial Review | 适用场景 |
|------|--------|---------|--------|-------------------|---------|
| `quick` | 1 | 1 | ✗ | ✗ | 简单查询、低风险任务 |
| `standard` | 2 | 2 | ✓ | ✗ | 常规开发任务 |
| `deep` | 3 | 3 | ✓ | ✗ | 复杂架构设计、安全相关 |
| `intensive` | 4 | 4 | ✓ | ✓ | 关键系统、合规要求、高复杂度推理 |

### 2.2 收敛（Convergence）

收敛是指迭代过程中输出质量达到可接受水平、继续迭代收益递减的状态。ConvergenceDetector 通过以下信号判定收敛：

| 信号 | 判定条件 | 收敛原因 |
|------|---------|---------|
| **质量阈值** | qualityScore ≥ 0.85（默认） | `quality-threshold-met` |
| **最大迭代** | 迭代次数 ≥ maxIterations | `max-iterations-reached` |
| **稳定性** | 最近3轮方差 < 0.01 且均值 ≥ 阈值×0.9 | `stable-and-sufficient` |
| **平台期** | 最近3轮方差 < 0.01 但均值不足 | `plateau-detected` |
| **质量退化** | 当前分数 < 上轮分数 - 0.1 | `quality-degrading` |

### 2.3 质量评分（Quality Score）

质量评分是收敛判定的核心输入，取值范围 0~1。来源包括：
- Agent 执行结果中的 `qualityScore` 字段
- Reviewer 返回的 `qualityScore`
- QualityScorer 子系统的多维度评估

### 2.4 精化（Refinement）

精化是迭代循环中的单轮改进过程：执行器产出结果 → 评审者评估并给出反馈 → 反馈注入下一轮任务上下文。关键机制：
- 评审者返回 `feedback` 后，引擎将其注入 `task.refinementInstructions`
- 评审者返回 `approved: true` 或 `qualityScore ≥ threshold` 时提前终止
- 最多执行 `maxRefinements`（默认5）轮

### 2.5 策略（Strategy）

StrategyPlugin 定义5种策略模式，控制迭代是否继续：

| 策略 | 决策逻辑 |
|------|---------|
| `fixed-depth` | 固定迭代次数，达到 maxIterations 即停止 |
| `adaptive` | 根据质量分数和改进率动态调整深度等级 |
| `convergence-driven` | 由收敛状态驱动，收敛即停 |
| `budget-aware` | Token 预算驱动，剩余不足10%即停 |
| `quality-optimized` | 高质量阈值（0.9）驱动，达标即停 |

## 4. 执行流程

### 4.1 Pipeline 完整执行流程

```
任务输入 + Agent列表
  ↓
DeepeningPipeline.run(task, agents)
  ↓
自动初始化（initialize）──→ 创建 Orchestrator + 7个模块 + 互相 attach
  ↓
Orchestrator.execute(task, agents, options)
  ↓
┌─ 检查 shutdown 状态
├─ 解析 depthLevel（options.depthLevel || defaultDepthLevel || 'standard'）
├─ 发射 execution-start 事件
├─ 记录 EventStore
  ↓
缓存检查（_checkCache）
  ├── 命中且 qualityScore ≥ convergenceThreshold → 直接返回缓存结果
  └── 未命中 → 继续
  ↓
Agent 路由（可选）
  ├── 若提供 multiAgentRouter → 路由筛选有效 Agent
  └── 否则 → 使用全部 Agent
  ↓
迭代执行（_runIterations）
  ├── maxIterations = depthLevel 映射（quick:1, standard:2, deep:3, intensive:4）
  ├── 每轮：执行所有 Agent（支持并行/串行）
  │     └── Agent 返回 qualityScore → 记入 qualityHistory
  ├── 每轮后检查是否应停止（_shouldStopIterating）
  │     ├── StrategyPlugin.decide() → shouldContinue=false → 停止
  │     ├── ConvergenceDetector.check() → converged=true → 停止
  │     └── qualityScore ≥ convergenceThreshold → 停止
  └── 计算 bestScore = max(qualityHistory)
  ↓
思维检索循环（_runThoughtCycle，可选）
  └── ThoughtRetrieverCycle.execute() → 蒸馏+存储思维链
  ↓
缓存结果 → 记录指标 → 生成报告
  ↓
发射 execution-complete 事件
  ↓
返回结果 { success, depthLevel, agentsUsed, totalAgentCalls, bestScore, qualityHistory }
```

### 4.2 收敛检测流程

```
ConvergenceDetector.check(executionId, data)
  ↓
记录历史（按 executionId 分组，最多 maxHistoryExecutions=100 条）
  ↓
计算信号：
  ├── qualityScore 信号 → score ≥ qualityThreshold(0.85)?
  └── dimensionBalance 信号 → max(dimValues) - min(dimValues) ≤ 0.3?
  ↓
收敛判定（按优先级）：
  1. qualityScore ≥ threshold → converged, reason: quality-threshold-met
  2. 迭代次数 ≥ maxIterations → converged, reason: max-iterations-reached
  3. 稳定性窗口（最近3轮）：
     a. 方差 < 0.01 且 均值 ≥ threshold×0.9 → converged, stable-and-sufficient
     b. 方差 < 0.01 → converged, plateau-detected（建议增加深度）
  4. 质量退化：当前 < 上轮 - 0.1 → converged, quality-degrading（建议降低深度）
  5. 以上均不满足 → not-converged（建议增加深度）
```

### 4.3 自适应深度评估流程

```
AdaptiveDepthController.assessComplexity(task)
  ↓
提取任务描述和依赖
  ↓
关键词匹配计算四维信号：
  ├── scope（范围）：构建/系统/平台/架构/重构 → +0.4/关键词, 上限1.0
  ├── risk（风险）：安全/关键/生产/合规 → +0.45/关键词, 上限1.0
  ├── reasoning（推理）：推理/分析/优化/决策 → +0.4/关键词, 上限1.0
  └── dependencyDepth（依赖深度）：depends_on.length × 0.2, 上限1.0
  ↓
加权计算复杂度分数：
  score = scope×0.35 + risk×0.35 + reasoning×0.2 + dependencyDepth×0.1
  ↓
映射深度等级：
  ├── score < 0.25 → quick (depth=1)
  ├── score < 0.50 → standard (depth=2)
  ├── score < 0.75 → deep (depth=3)
  └── score ≥ 0.75 → intensive (depth=4)
```

### 4.4 迭代精化流程

```
IterativeRefinement.refine(executor, task, reviewer)
  ↓
循环（最多 maxRefinements=5 轮）：
  ├── executor.execute(task) → 产出结果
  ├── reviewer(result, task) → 评审
  │     ├── approved=true 或 qualityScore ≥ 0.8 → 提前终止
  │     └── feedback → 注入 task.refinementInstructions → 下一轮
  └── reviewer 异常 → 终止迭代
  ↓
返回 { success, rounds, converged: rounds < maxRefinements }
```

### 4.5 渐进深化流程

```
ProgressiveDeepening.execute(agent, task, level, options)
  ↓
获取等级配置（LEVEL_CONFIGS）：
  ├── quick: 1轮, review=off, adversarial=off
  ├── standard: 2轮, review=on, adversarial=off
  ├── deep: 3轮, review=on, adversarial=off
  └── intensive: 4轮, review=on, adversarial=on
  ↓
执行迭代循环：
  ├── agent.execute(task)
  ├── 若 reviewEnabled 且有 reviewer → 评审
  │     └── qualityScore ≥ earlyStopThreshold(0.95) → 提前终止
  └── 下一轮
  ↓
若 adversarialEnabled 且有 adversarialReviewer → 对抗审查
  ↓
返回 { success, level, iterations, reviews?, adversarialResult? }
```

## 5. 关键组件详解

### 5.1 DeepeningOrchestrator

[源码](../../src/runtime/deepening/deepening-orchestrator.js)

编排器是深化推理的核心引擎，负责协调迭代执行、收敛判定、缓存和报告生成。

**核心方法：**

| 方法 | 说明 |
|------|------|
| `execute(task, agents, options)` | 主入口，执行完整的深化推理流程 |
| `attachMetricsCollector(mc)` | 注入指标收集器 |
| `attachCache(c)` | 注入缓存模块 |
| `attachStrategyPlugin(sp)` | 注入策略插件 |
| `attachReportGenerator(rg)` | 注入报告生成器 |
| `attachConvergenceDetector(cd)` | 注入收敛检测器 |
| `attachQualityScorer(qs)` | 注入质量评分器 |
| `attachEventStore(es)` | 注入事件存储 |
| `getExecutionLog()` | 获取执行日志（最近100条） |
| `getStats()` | 获取统计信息 |

**execute() 返回值结构：**

```javascript
{
  success: boolean,
  depthLevel: 'quick' | 'standard' | 'deep' | 'intensive' | 'cached',
  agentsUsed: string[],
  totalAgentCalls: number,
  bestScore: number,
  qualityHistory: number[],
  fromCache?: boolean,
  thoughtCycle?: {
    distilled: number,
    stored: number,
    cycleComplete: boolean,
    quality: number
  }
}
```

**关键设计决策：**
- 缓存命中条件：qualityScore ≥ convergenceThreshold（默认0.85），确保仅高质量结果被复用
- Agent 路由：可选接入 MultiAgentRouter，按任务特征筛选最合适的 Agent 子集
- 并行执行：`parallelAgentExecution` 选项控制 Agent 是并行还是串行执行
- 思维循环：可选接入 ThoughtRetrieverCycle，在迭代完成后蒸馏和存储思维链

> **v2.7.122 Round 7 修复说明**：
> （1）**运算符优先级修复**：`execute()` 方法中 `depthLevel` 解析从 `options.depthLevel || defaultDepthLevel || 'standard'` 改为 `options.depthLevel ?? defaultDepthLevel ?? 'standard'`。此前 `||` 运算符的 falsy 语义导致合法值 `0` 和 `""` 被错误跳过，改用 `??` 后仅 `null`/`undefined` 触发回退。
> （2）**空 agents 数组验证**：`execute()` 新增 `agents` 参数非空验证，空数组时抛出 `HarnessError`。此前空数组会进入迭代循环但零次执行，返回 `success: true` 的误导性结果。

### 5.3 ConvergenceDetector

[源码](../../src/runtime/deepening/convergence-detector.js)

收敛检测器通过多信号分析判定迭代是否应终止。

**信号类型（SIGNAL_TYPES）：**

| 信号 | 说明 |
|------|------|
| `quality-score` | 质量分数是否达到阈值 |
| `improvement-rate` | 改进率是否足够 |
| `stability` | 质量分数是否趋于稳定 |

**默认配置：**

| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| `qualityThreshold` | 0.85 | 质量收敛阈值 |
| `maxIterations` | 10 | 最大迭代次数 |
| `minImprovementRate` | 0.01 | 最小改进率 |
| `stabilityVariance` | 0.01 | 稳定性方差阈值 |
| `stabilityWindow` | 3 | 稳定性检测窗口大小 |
| `coverageThreshold` | 0.8 | 覆盖率阈值 |
| `dimensionBalanceThreshold` | 0.3 | 维度平衡阈值 |
| `qualityDegradationThreshold` | 0.1 | 质量退化阈值 |

**收敛原因与建议：**

| 原因 | recommendation | 含义 |
|------|---------------|------|
| `quality-threshold-met` | `sufficient` | 质量达标，迭代充分 |
| `max-iterations-reached` | `increase-depth` | 迭代用尽但未达标，建议增加深度 |
| `stable-and-sufficient` | `sufficient` | 稳定且接近阈值，迭代充分 |
| `plateau-detected` | `increase-depth` | 停滞不前，建议增加深度 |
| `quality-degrading` | `decrease-depth` | 质量下降，建议降低深度 |
| `not-converged` | `increase-depth` | 未收敛，继续迭代 |

### 5.4 AdaptiveDepthController

[源码](../../src/runtime/deepening/adaptive-depth-controller.js)

自适应深度控制器根据任务特征自动评估复杂度并推荐深度等级。

**复杂度评估维度：**

| 维度 | 权重 | 关键词/信号 | 单次贡献 |
|------|------|------------|---------|
| scope（范围） | 0.35 | 构建/系统/平台/架构/重构/design/system/platform/refactor | +0.4 |
| risk（风险） | 0.35 | 安全/关键/生产/合规/security/critical/production/compliance | +0.45 |
| reasoning（推理） | 0.20 | 推理/分析/优化/决策/reasoning/analysis/optimize/decision | +0.4 |
| dependencyDepth（依赖深度） | 0.10 | depends_on 数组长度 | ×0.2/依赖 |

**核心方法：**

| 方法 | 返回值 | 说明 |
|------|--------|------|
| `assessComplexity(task)` | `{ score, level, depth, signals }` | 评估任务复杂度 |
| `getRecommendedDepth(task)` | `number` | 获取推荐深度值（1-4） |
| `getRecommendedLevel(task)` | `string` | 获取推荐深度等级名 |

### 5.5 IterativeRefinement

[源码](../../src/runtime/deepening/iterative-refinement.js)

迭代精化器实现"执行-评审-反馈"循环，每轮将评审反馈注入任务上下文。

**精化流程关键点：**
- 评审者返回 `feedback` 后，通过 `Object.create(task)` 创建继承原任务的新对象
- 反馈注入 `taskWithContext.refinementInstructions = rev.feedback`
- 评审者批准（`approved: true`）或质量达标（`qualityScore ≥ 0.8`）时提前终止
- 评审者异常时安全终止，不会导致整体失败

**默认配置：**

| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| `maxRefinements` | 5 | 最大精化轮数 |
| `qualityThreshold` | 0.8 | 精化质量阈值 |

### 5.6 ProgressiveDeepening

[源码](../../src/runtime/deepening/progressive-deepening.js)

渐进深化器按深度等级逐步执行，支持 Review 和 Adversarial Review 两级评审机制。

**等级配置（LEVEL_CONFIGS）：**

```javascript
{
  quick:      { iterations: 1, reviewEnabled: false, adversarialEnabled: false },
  standard:   { iterations: 2, reviewEnabled: true,  adversarialEnabled: false },
  deep:       { iterations: 3, reviewEnabled: true,  adversarialEnabled: false },
  intensive:  { iterations: 4, reviewEnabled: true,  adversarialEnabled: true  },
}
```

**早停机制：** 当 reviewer 返回 `qualityScore ≥ earlyStopThreshold`（默认0.95）时，即使迭代未完成也提前终止。

**对抗审查：** 仅 `intensive` 级别启用，通过 `adversarialReviewer.review(result, reviewerA, reviewerB)` 进行对抗性质量审查。

### 5.7 TokenAwareDeepening

[源码](../../src/runtime/deepening/token-aware-deepening.js)

Token 感知深化器在 Token 预算约束下规划迭代策略，避免资源耗尽。

**核心方法：**

| 方法 | 说明 |
|------|------|
| `calculateMaxIterations(tokenManager, sessionId)` | 根据剩余预算计算最大迭代次数 |
| `canAffordIteration(tokenManager, sessionId, tokenCost)` | 判断是否负担得起一次迭代 |
| `recordIterationCost(sessionId, iteration, tokensUsed, qualityScore)` | 记录迭代成本，计算效率 |
| `getEfficiencyReport(sessionId)` | 获取效率报告 |
| `recommendDepth(tokenManager, sessionId, complexity)` | 综合预算和复杂度推荐深度 |

**预算计算逻辑：**

```
remaining = tokenManager.getUsage(sessionId).remaining
budget = tokenManager.getUsage(sessionId).budget

若 minBudgetRemaining 为比例值（0~1）：
  remaining/budget < minBudgetRemaining → maxIterations=1, budget-critical
若 minBudgetRemaining 为绝对值（默认1000）：
  remaining < minBudgetRemaining × 0.1 → maxIterations=1, budget-critical

正常情况：
  rawMax = floor(remaining / 2000)
  maxIterations = max(1, min(rawMax, maxIterationCap=10))
```

**效率指标：** `efficiency = qualityScore / tokensUsed`，每次迭代自动计算并记录。

### 5.8 RecurrentDeepeningScheduler

[源码](../../src/runtime/deepening/recurrent-deepening-scheduler.js)

循环深化调度器实现最简洁的深化模式：循环执行 Agent，由 evaluator 评分，达到收敛阈值即停。

**执行流程：**
1. 循环执行 `agent.execute(task)`
2. 每轮由 `evaluator(result, task)` 评分
3. `qualityScore ≥ convergenceThreshold`（默认0.85）→ 收敛终止
4. 最多执行 `maxIterations`（默认4）轮

**与 Orchestrator 的区别：** RecurrentDeepeningScheduler 是轻量级调度器，不依赖缓存、策略插件等基础设施，适用于简单场景或作为子组件嵌入其他流程。

> **v2.7.122 修复说明**：（1）新增 `maxCircuits` 限制执行，当断路器实例数超过上限时，采用回退淘汰策略（fallback eviction）移除最久未使用的实例，防止内存无限增长。（2）`halfOpenCalls` 计数器仅在 `half_open` 状态下递增，此前在 `closed` 状态下也会递增，导致计数器值虚高、半开探测误判。

## 11. Round 7 缺陷修复记录

> 本轮修复涉及深化推理引擎中6个模块的关键缺陷，与 [[模块详解-深化调度与执行模块群]] 中的 Round 7 记录对应，此处记录对核心架构的影响。

### 11.1 DeepeningOrchestrator — 运算符优先级与空agents验证

**运算符优先级修复**：`execute()` 方法中 `depthLevel` 解析逻辑从 `||` 改为 `??`，修复 falsy 值（`0`、`""`）被错误跳过的 bug。此修复影响 [4.1 Pipeline 完整执行流程](#41-pipeline-完整执行流程)中的"解析 depthLevel"步骤，确保所有合法深度值被正确传递。

**空 agents 数组验证**：`execute()` 新增 `agents` 非空验证，空数组时抛出 `HarnessError`。此修复影响 [4.1 Pipeline 完整执行流程](#41-pipeline-完整执行流程)中的"Agent 路由"步骤，在路由前即拦截无效输入。

### 11.2 DeepeningPipeline — initialize() 部分失败回滚

`initialize()` 新增部分失败回滚逻辑，初始化失败时清理已创建的模块实例。此修复影响 [5.2 DeepeningPipeline](#52-deepeningpipeline) 中描述的初始化过程，确保管道要么完全初始化成功，要么干净回退。

### 11.3 DeepeningStateManager — transition() await异步回调

`transition()` 中 onEnter/onExit 回调改为 `await`，并新增 `context` 参数透传。此修复影响状态机转换的时序一致性，确保异步回调完成后再继续转换流程。

### 11.4 DeepeningTaskScheduler — 并发限制deferred事件

并发限制触发时新增 `deferred` 事件发射。此修复影响 [模块详解-深化调度与执行模块群] 中 DeepeningTaskScheduler 的事件列表，新增 `deferred` 事件类型。

### 11.5 DeepeningCache — invalidateByPattern({}) 空pattern防护

空 pattern 对象防护，防止全量缓存意外失效。此修复影响 [6.2 缓存与存储] 中 DeepeningCache 的使用安全性。

### 11.6 DeepeningRateLimiter — tryConsume 负数计数验证

`tryConsume()` 新增 `count` 参数安全验证，拒绝负数和非有限数值。此修复影响 [6.1 容错与保护] 中 DeepeningRateLimiter 的限流安全性，防止限流机制被绕过。

## 12. InferenceCache缓存优化增强（v2.10.6融合OpenClaw 4.5）

> 源文件：[inference-cache.js](../../src/runtime/model/inference-cache.js)

InferenceCache在v2.10.6中融合OpenClaw 4.5缓存优化思路，引入四项关键增强：缓存键标准化策略、分层TTL策略、缓存-成本闭环反馈和增强统计字段。这些增强在保持原有LRU淘汰+TTL过期机制的基础上，显著提升缓存命中率和成本可控性。

### 12.1 缓存键标准化策略

语义相同但格式不同的Prompt和上下文请求，在标准化后产生相同的缓存键，从而提高命中率：

| 标准化步骤 | 说明 |
|-----------|------|
| Prompt空白压缩 | 多余空白字符合并为单个空格 |
| 引号统一 | 将弯引号（''""）和反引号统一为直引号 |
| JSON键排序 | 对对象类型Prompt/上下文按键名字母序排列，消除键序差异 |
| 易变字段过滤 | 上下文中以timestamp/date/time/updatedAt/createdAt/requestId结尾的键被移除 |
| 长键哈希 | 标准化后超过256字符的键使用SHA-256哈希压缩 |

**标准化流程**：

```
原始Prompt + 上下文
  → _normalizePrompt(prompt)     // 空白压缩 + 引号统一 + JSON键排序
  → _normalizeContext(context)   // 易变字段过滤 + JSON键排序
  → 拼接：normalizedPrompt + '\x00' + normalizedContext
  → 长度 > 256 ? SHA-256哈希 : 直接使用
```

### 12.2 分层TTL策略

缓存条目根据命中次数被分为三个层级，不同层级采用不同的TTL倍率：

| 分层 | 命中次数阈值 | TTL倍率 | 默认TTL（30分钟基础） | 说明 |
|------|------------|---------|---------------------|------|
| **hot** | ≥ 5 | 2× | 60分钟 | 高频访问，存活时间延长 |
| **warm** | ≥ 2 | 1× | 30分钟 | 中频访问，保持默认 |
| **cold** | < 2 | 0.5× | 15分钟 | 低频访问，加速淘汰 |

**分层动态调整**：每次缓存命中时，根据更新后的命中次数重新计算所属分层和生效TTL，实现"越热门越持久"的自适应缓存策略。

### 12.3 缓存-成本闭环反馈

缓存命中时将节省的Token数量反馈到TokenManager成本控制系统，形成"缓存命中→Token节省→成本降低"的闭环：

```
缓存命中 → get()返回tokensSaved
  → _reportSavings(tokensSaved)
    → TokenManager.store('__inference_cache_savings', tokensSaved)
      → 成本控制系统更新
```

- 通过`attachTokenManager(tokenManager)`关联TokenManager实例
- TokenManager记录失败时静默忽略，不影响缓存正常工作
- 累计节省Token总量（含已淘汰条目）通过`tokensSavedTotal`字段追踪

### 12.4 增强统计字段

`getStats()`返回值在原有字段基础上新增以下统计：

| 字段 | 类型 | 说明 |
|------|------|------|
| `tokensSavedTotal` | number | 累计节省Token总量（含已淘汰条目） |
| `costSavedEstimate` | number | 估算节省成本（美元），按$0.01/1K Token估算 |
| `hitRateByTier` | object | 按分层统计命中率 `{ hot: number, warm: number, cold: number }` |
| `keyNormalizationHits` | number | 标准化键命中次数 |

**完整统计返回值**：

```javascript
{
  size: 42,                    // 当前缓存条目数
  maxSize: 100,                // 缓存最大容量
  hits: 156,                   // 缓存命中次数
  misses: 43,                  // 缓存未命中次数
  hitRate: 0.78,               // 缓存命中率（0~1）
  evictions: 12,               // 缓存淘汰次数
  tokensSaved: 23400,          // 当前缓存条目累计节省Token
  tokensSavedTotal: 45600,     // 累计节省Token总量（含已淘汰）
  costSavedEstimate: 0.456,    // 估算节省成本（美元）
  hitRateByTier: {             // 分层命中率
    hot: 0.92,
    warm: 0.75,
    cold: 0.30
  },
  keyNormalizationHits: 28     // 标准化键命中次数
}
```

### 12.5 使用示例

```javascript
const { InferenceCache } = require('./src/runtime/model/inference-cache');

// 创建缓存实例
const cache = new InferenceCache({ maxSize: 200, ttlMs: 1800000 });

// 关联TokenManager启用缓存-成本闭环
cache.attachTokenManager(tokenManager);

// 写入缓存（Prompt标准化后自动去重）
cache.set('你好  世界', { text: '你好！' });       // 原始键
cache.set('你好 世界', { text: '你好！' });        // 标准化后命中同一键

// 读取缓存
const hit = cache.get('你好 世界');
// hit => { result: { text: '你好！' }, tokensSaved: 5, hitCount: 2 }

// 查看增强统计
const stats = cache.getStats();
console.log(`分层命中率: hot=${stats.hitRateByTier.hot}, warm=${stats.hitRateByTier.warm}`);
console.log(`累计节省Token: ${stats.tokensSavedTotal}`);
console.log(`估算节省成本: $${stats.costSavedEstimate}`);
```
