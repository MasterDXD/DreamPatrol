# 核心功能-成本控制机制

> 版本：2.73.4 | 模块：src/runtime/model/token-manager.js、src/runtime/session/session-manager.js、src/runtime/infrastructure/shared-infrastructure.js

---

## 概述

成本控制机制是Harness Engineering多Agent框架的资源管控体系，确保在多Agent并发执行场景下Token消耗可控、资源分配合理、预算超支可防。机制由三层防线构成：

- **Token预算管理** — 全局Token预算追踪、三级阈值预警（80%/95%/100%）、自动降级与暂停
- **会话级成本管控** — 单会话Token消耗追踪、预算检查、阶段转换验证
- **基础设施资源配额** — 连接池容量、服务注册上限、特性标志配额

三者协同实现"预算可控、消耗可追踪、超支可阻断"的成本治理目标。

## 核心概念

### Token预算三级阈值

```
0% ─────────── 80% ─────────── 95% ─────────── 100%
  正常运行区      预警区          危险区          耗尽区
                 warning80      warning95      exhausted
                 发射事件        切换低价模型    暂停所有任务
```

| 概念 | 说明 |
|------|------|
| **Token Budget** | 全局Token预算，默认1,000,000,000（1B） |
| **warning80** | 80%阈值，发射`budget-warning`事件，提醒各模块优化Token使用 |
| **warning95** | 95%阈值，自动切换到低价模型，减少高成本API调用 |
| **exhausted** | 100%阈值，暂停所有非关键任务，仅保留系统核心功能 |

### 会话级Token管控

每个会话维护独立的Token消耗记录，在阶段转换时执行预算检查：

```
会话创建 → 初始预算分配
  ↓
阶段转换 → 预算检查 → 通过/拒绝
  ↓
会话结束 → Token消耗记录持久化
```

### 基础设施资源配额

| 资源 | 默认上限 | 说明 |
|------|---------|------|
| 连接池最大连接数 | 10 | `SharedConnectionPool._maxConnections` |
| 负载均衡最大服务数 | 100 | `SharedLoadBalancer._maxServices` |
| 服务注册最大条目 | 200 | `SharedServiceRegistry._maxServices` |
| 特性标志最大数量 | 200 | `SharedFeatureFlags._maxFlags` |
| 特性标志历史记录 | 100 | `SharedFeatureFlags._maxHistory` |

## 成本控制流程

### 1. Token消耗记录

每次对话轮次结束后，通过`/api/token/record`端点记录Token消耗：

```javascript
// 请求格式
{
  sessionId: 'session-uuid',
  tokens: 1500,           // 总Token数
  inputTokens: 1000,      // 输入Token
  outputTokens: 500,      // 输出Token
  toolCallTokens: 200     // 工具调用Token（估算）
}

// 估算方法
// 英文：字符数 / 4
// 中文：字符数 / 2
// 每次工具调用：约200-500 Token
```

### 2. 预算检查时机

| 时机 | 检查内容 | 动作 |
|------|---------|------|
| 会话创建 | 全局预算是否耗尽 | 拒绝新会话 |
| 阶段转换 | 会话预算是否充足 | 阻断转换 |
| Skill执行前 | Token预算是否超过80% | 降级模型 |
| 任务调度前 | 全局预算是否超过95% | 暂停低优先级任务 |

### 3. 自动降级策略

当Token预算达到95%时，`ModelSelector`自动执行降级：

```
高级模型 → 标准模型 → 经济模型 → 本地模型
(gpt-4)   (gpt-3.5)  (低成本API)  (离线推理)
```

降级决策基于：
- 当前Token预算使用率
- Skill的复杂度评分
- 任务优先级
- 剩余预算估算

## TokenManager 详细API

### 构造参数

```javascript
const tokenManager = new TokenManager({
  defaultBudget: 1000000000,  // 全局Token预算，默认1B
  maxSessions: 1000           // 最大会话追踪数，超出时LRU淘汰
});
```

### 核心方法

| 方法 | 签名 | 返回值 | 说明 |
|------|------|--------|------|
| `store` | `store(sessionId, amount)` | `number` | 累加Token使用量，超限时触发预警事件 |
| `get` | `get(sessionId)` | `number` | 获取会话Token使用量，不存在返回0 |
| `set` | `set(sessionId, amount)` | `number` | 直接设置Token使用量（覆盖） |
| `validate` | `validate(sessionId, budget?)` | `ValidationResult` | 验证是否超出预算阈值 |
| `clear` | `clear(sessionId)` | `void` | 清除指定会话Token及分类明细 |
| `clearAll` | `clearAll()` | `void` | 清除所有会话Token及分类明细 |
| `addBreakdown` | `addBreakdown(sessionId, category, amount)` | `Object` | 添加分类Token消耗明细 |
| `getBreakdown` | `getBreakdown(sessionId)` | `Object` | 获取指定会话分类明细 |
| `getAllBreakdowns` | `getAllBreakdowns(sessionId?)` | `Object` | 获取全部或指定会话分类明细 |
| `getTotal` | `getTotal(budget?)` | `{ total, budget, ratio }` | 所有会话Token总使用量及占比 |
| `getUsage` | `getUsage(sessionId, budget?)` | `{ used, budget, remaining, ratio }` | 指定会话使用详情 |
| `getStats` | `getStats(budget?)` | `StatsResult` | 全局统计信息 |
| `setGlobalBudget` | `setGlobalBudget(budget)` | `number` | 设置全局预算上限 |
| `getGlobalBudget` | `getGlobalBudget()` | `number` | 获取当前全局预算 |
| `listSessions` | `listSessions()` | `string[]` | 列出所有已注册Token的会话 |
| `formatTokens` | `formatTokens(n)` | `string` | 格式化为可读字符串（如1.23B） |
| `parseFormatted` | `parseFormatted(formatted)` | `number` | 解析可读字符串为数值 |

### 关键类型定义

```typescript
interface ValidationResult {
  sessionId: string;
  tokensUsed: number;
  budget: number;
  ratio: number;
  warning80: boolean;   // ratio >= 0.8
  warning95: boolean;   // ratio >= 0.95
  exhausted: boolean;   // ratio >= 1.0
}

interface StatsResult {
  total: number;            // 全部会话Token总消耗
  budget: number;           // 全局预算
  ratio: number;            // 总消耗/预算
  maxSession: number;       // 单会话最大消耗
  activeSessions: number;   // 有消耗的会话数
  totalSessions: number;    // 总会话数
}
```

### 事件列表

| 事件名 | 触发条件 | 事件数据 |
|--------|---------|---------|
| `token-warning-80` | 会话Token使用率 ≥ 80% | `{ sessionId, tokensUsed, budget }` |
| `token-warning-95` | 会话Token使用率 ≥ 95% | `{ sessionId, tokensUsed, budget }` |
| `token-exhausted` | 会话Token使用率 ≥ 100% | `{ sessionId, tokensUsed, budget }` |
| `token-reset` | 会话Token被清除 | `{ sessionId }` |

### LRU淘汰机制

当会话数达到`maxSessions`（默认1000）且新会话不在已有记录中时，自动淘汰最早插入的会话记录：

```
_sessionTokens.size >= maxSessions && !_sessionBreakdowns.has(newSessionId)
  → 删除 _sessionTokens.keys().next().value（最早插入的key）
  → 同时清除该会话的分类明细
```

## 三层防线交互流程

### 协作链路总览

```
用户请求 → Skill执行 → Token消耗
    │
    ▼
┌─────────────────────────────────────────────────────┐
│ 第一层：TokenManager（全局预算追踪）                    │
│  store() → validate() → 事件发射                      │
│  token-warning-80 / token-warning-95 / token-exhausted│
└──────────────┬──────────────────────────────────────┘
               │ 事件监听
               ▼
┌─────────────────────────────────────────────────────┐
│ 第二层：SessionManager（会话级成本管控）                │
│  addTokenUsage() → checkBudget() → budget-warning事件 │
│  阶段转换验证 → 预算检查 → 通过/阻断                    │
└──────────────┬──────────────────────────────────────┘
               │ 预算状态联动
               ▼
┌─────────────────────────────────────────────────────┐
│ 第三层：SharedInfrastructure（基础设施资源配额）        │
│  连接池容量限制 → 负载均衡服务上限 → 服务注册上限        │
│  特性标志配额 → 预算约束时关闭非关键特性                  │
└─────────────────────────────────────────────────────┘
```

### 交互时序

```
1. Skill执行产生Token消耗
   │
   ├─→ TokenManager.store(sessionId, amount)
   │     ├─ 累加会话Token
   │     ├─ LRU淘汰检查
   │     └─ validate() → 按阈值发射事件
   │
   ├─→ SessionManager.addTokenUsage(sessionId, tokens)
   │     ├─ session.tokensUsed += numTokens
   │     ├─ 防抖持久化
   │     └─ checkBudget() → budget-warning事件
   │
   └─→ ModelSelector（监听TokenManager事件）
         ├─ token-warning-80 → _budgetConstrained = true
         ├─ token-warning-95 → _budgetCritical = true
         └─ token-exhausted  → _budgetExhausted = true

2. 下次模型选择时
   │
   └─→ ModelSelector.selectModel(skillId, context)
         ├─ _applyBudgetAdjustments(result)
         │     ├─ exhausted → 强制economy模型
         │     ├─ critical  → premium→standard, standard→economy
         │     └─ constrained → premium→standard
         └─ 发射 model-downgraded 事件
```

### 跨层事件传播

| 源头事件 | 传播路径 | 最终效果 |
|---------|---------|---------|
| `TokenManager#token-warning-80` | → ModelSelector._budgetConstrained | Premium模型降级为Standard |
| `TokenManager#token-warning-95` | → ModelSelector._budgetCritical | Premium/Standard降级为Economy |
| `TokenManager#token-exhausted` | → ModelSelector._budgetExhausted | 强制Economy模型 |
| `TokenManager#token-reset` | → ModelSelector预算标志重置 | 恢复正常模型选择 |
| `SessionManager#budget-warning` | → 外部监听器 | 日志/告警/UI更新 |
| `SessionManager#budget-config-changed` | → 外部监听器 | 阶段预算配置热更新 |

## Token估算方法

### 估算算法

Token估算在无法获取精确计数时使用以下启发式算法：

| 内容类型 | 估算公式 | 说明 |
|---------|---------|------|
| 英文文本 | `字符数 / 4` | 英文平均1 Token ≈ 4字符 |
| 中文文本 | `字符数 / 2` | 中文平均1 Token ≈ 2字符 |
| 混合文本 | 按语言比例加权 | 检测中文字符占比后加权计算 |
| 工具调用 | `200 ~ 500 Token/次` | 固定估算范围，含参数序列化开销 |

### 分类明细记录

通过`addBreakdown()`方法记录三类Token消耗：

```javascript
tokenManager.addBreakdown(sessionId, 'input', estimatedInputTokens);
tokenManager.addBreakdown(sessionId, 'output', estimatedOutputTokens);
tokenManager.addBreakdown(sessionId, 'toolCall', estimatedToolTokens);
```

查询分类明细：

```javascript
const breakdown = tokenManager.getBreakdown(sessionId);
// { input: 1000, output: 500, toolCall: 200 }
```

### 估算记录时机

| 时机 | 记录方式 | 说明 |
|------|---------|------|
| Skill执行后 | `/api/token/record` 端点 | HTTP接口记录，含全部分类 |
| 任务批次完成后 | `addTokenUsage()` | 会话级累加 |
| 会话结束前 | `store()` + `addBreakdown()` | 最终汇总 |

## 预算超支处理

### 三级阈值处理逻辑

#### 80%预警区（TOKEN_BUDGET_WARNING_RATIO = 0.8）

```
触发条件：session.tokensUsed / budget >= 0.8
触发位置：TokenManager.store() / set() → validate()
```

| 维度 | 处理逻辑 |
|------|---------|
| **TokenManager** | 发射`token-warning-80`事件，携带`{ sessionId, tokensUsed, budget }` |
| **ModelSelector** | 监听事件，设置`_budgetConstrained = true`；后续Premium模型降级为Standard |
| **SessionManager** | `addTokenUsage()`内部调用`checkBudget()`，发射`budget-warning`事件 |
| **外部系统** | 可监听事件触发日志记录、UI告警、Slack通知等 |

#### 95%危险区（TOKEN_BUDGET_DANGER_RATIO = 0.95）

```
触发条件：session.tokensUsed / budget >= 0.95
触发位置：TokenManager.store() / set() → validate()
```

| 维度 | 处理逻辑 |
|------|---------|
| **TokenManager** | 发射`token-warning-95`事件 |
| **ModelSelector** | 设置`_budgetCritical = true`；Premium→Standard，Standard→Economy |
| **SessionManager** | 发射`budget-warning`事件，`warning95: true` |
| **任务调度** | 暂停低优先级任务，仅保留关键路径任务 |

#### 100%耗尽区

```
触发条件：session.tokensUsed / budget >= 1.0
触发位置：TokenManager.store() → validate()
```

| 维度 | 处理逻辑 |
|------|---------|
| **TokenManager** | 发射`token-exhausted`事件；**store()直接抛出`BUDGET_EXCEEDED`错误** |
| **ModelSelector** | 设置`_budgetExhausted = true`；**强制所有请求使用Economy模型** |
| **SessionManager** | `checkBudget()`返回`exhausted: true` |
| **会话创建** | 新会话创建被拒绝 |
| **系统行为** | 暂停所有非关键任务，仅保留系统核心功能 |

### 预算恢复机制

当Token被清除（`clear()`/`clearAll()`）时，TokenManager发射`token-reset`事件，ModelSelector监听后重置所有预算约束标志：

```javascript
tokenManager.on('token-reset', () => {
  // ModelSelector内部：
  // _budgetConstrained = false
  // _budgetCritical = false
  // _budgetExhausted = false
  // 若之前处于约束状态，发射 budget-recovered 事件
});
```

## 模型降级链

### 降级决策算法

ModelSelector的`selectModel()`方法按以下优先级决策：

```
1. Skill映射查找 → _skillModelMap[skillId]
2. 预算降级检查 → _applyBudgetAdjustments()
3. 上下文调整   → _applyContextAdjustments()
   ├─ 重试升级：economy失败后升级到standard
   ├─ 简单任务降级：premium → standard
   └─ 会话成本预算：超过80%时premium → standard
4. 复杂度评分选择 → _selectByComplexity()
5. 默认模型兜底
```

### 模型层级体系

| 层级 | 默认模型 | 成本乘数 | 适用场景 |
|------|---------|---------|---------|
| **Premium** | gpt-4o, claude-3-opus, deepseek-v3 | 1.0 | 架构设计、深度调试、安全审计、深化推理 |

### 复杂度评分选择

当Skill不在映射表中时，根据`complexityScore`选择模型：

```
complexityScore >= 0.7  → Premium（fallbackChain[0]）
0.4 <= score < 0.7      → Standard（fallbackChain[1]）
score < 0.4             → Economy（fallbackChain[2]）
```

复杂度评分由四个因子加权计算：

| 因子 | 权重 | 信号关键词 |
|------|------|-----------|
| reasoning_depth | 0.30 | architecture, design, brainstorm, debug, analyze |
| output_length | 0.20 | document, implement, develop, refactor |
| error_sensitivity | 0.25 | security, deploy, production, critical |
| pattern_complexity | 0.25 | test, format, lint, review |

## 会话级Token追踪

### SessionManager Token相关方法

| 方法 | 签名 | 返回值 | 说明 |
|------|------|--------|------|
| `addTokenUsage` | `addTokenUsage(sessionId, tokens)` | `void` | 增加会话Token使用量 |
| `checkBudget` | `checkBudget(sessionId)` | `BudgetStatus` | 检查会话预算使用情况 |
| `getStats` | `getStats()` | `SessionStats` | 获取全局统计（含总Token用量） |

### BudgetStatus类型

```typescript
interface BudgetStatus {
  warning80: boolean;       // 使用率 >= 0.8
  warning95: boolean;       // 使用率 >= 0.95
  exhausted: boolean;       // 使用率 >= 1.0
  ratio: number;            // 使用比例（保留2位小数）
  sessionNotFound?: boolean; // 会话不存在时为true
}
```

### Token检查时机

| 时机 | 检查方法 | 检查内容 | 动作 |
|------|---------|---------|------|
| `addTokenUsage()` | `checkBudget()` | 会话Token使用率 | 达到阈值时发射`budget-warning`事件 |
| 会话创建 | 隐式（`MAX_SESSIONS`限制） | 活跃会话数 | 超过100个时淘汰最旧会话 |
| 阶段转换 | `advancePhase()` | 阶段合法性 | 非法转换抛出错误 |
| 配置热更新 | `_watchConfig()` | `token_budget`变更 | 发射`budget-config-changed`事件 |

### 会话Token生命周期

```
创建会话 → tokensUsed = 0
    │
    ▼
Skill执行 → addTokenUsage(sessionId, tokens)
    │         ├─ session.tokensUsed += tokens
    │         ├─ 防抖持久化（DEFAULT_DEBOUNCE_MS）
    │         └─ checkBudget() → budget-warning?
    │
    ▼
阶段转换 → advancePhase(sessionId, newPhase)
    │         └─ 持久化会话状态
    │
    ▼
会话过期 → TTL清理（每5分钟检查）
    │         └─ 超过SESSION_TTL_MS(24h) → 删除会话及磁盘文件
    │
    ▼
进程退出 → flush() → 所有待写入会话刷盘
```

### 防抖持久化机制

Token使用量变更后不会立即写入磁盘，而是通过`KeyedDebouncer`合并写入：

- **防抖间隔**：`DEFAULT_DEBOUNCE_MS`（默认值）
- **立即写入**：会话创建（`create`）、阶段转换（`advancePhase`）、Skill完成（`completeSkill`）时`immediate=true`
- **延迟写入**：`addTokenUsage()`、`recordAgentAction()`等高频操作使用防抖写入
- **关机刷盘**：`_onShutdown()`调用`flush()`确保数据不丢失

### 会话容量限制

| 参数 | 值 | 说明 |
|------|-----|------|
| `MAX_SESSIONS` | 100 | 内存中最大活跃会话数 |
| `SESSION_TTL_MS` | 86400000 (24h) | 会话TTL过期时间 |
| `MAX_COMPLETED_SKILLS` | 500 | 已完成Skill列表上限 |
| `COMPLETED_SKILLS_TRIM_TO` | 400 | 裁剪后保留数量 |
| `TTL_CLEANUP_INTERVAL_MS` | 300000 (5min) | TTL清理检查间隔 |
| `agentHistory`上限 | 500条 | 超出裁剪至400条 |

## 基础设施资源配额详解

### SharedConnectionPool（连接池）

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `maxConnections` | 10 | 最大并发连接数 |

**获取连接**：

```javascript
const { connection, error } = pool.acquire('conn-1', () => createConnection());
// 错误码：
//   POOL_SHUTDOWN  — 连接池已关闭
//   POOL_EXHAUSTED — 连接数已达上限
//   FACTORY_ERROR  — 工厂函数异常
```

**溢出处理**：当`activeCount >= maxConnections`时，`acquire()`返回`POOL_EXHAUSTED`错误，调用方需等待或重试。

**统计信息**：

```javascript
pool.getStats();
// { active: 3, maxConnections: 10, totalAcquired: 150, totalReleased: 147 }
```

### SharedLoadBalancer（负载均衡器）

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `strategy` | `'round_robin'` | 负载均衡策略 |
| `maxServices` | 100 | 最大可注册服务数 |

**支持策略**：

| 策略 | 说明 |
|------|------|
| `round_robin` | 轮询（默认，当前唯一实现） |
| `random` | 随机选择 |
| `least_connections` | 最少连接 |

**安全校验**：注册端点时自动过滤以下地址：

- `localhost` / `127.x` / `10.x` / `172.16-31.x` / `192.168.x`（内网地址）
- `::1` / `fe80::` / `fc00::`（IPv6内网）
- 非`http:`/`https:`协议
- `isBlockedHost()`黑名单主机

**溢出处理**：当`services.size >= maxServices`且服务名不存在时，`register()`静默忽略新服务。

### SharedServiceRegistry（服务注册中心）

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `maxServices` | 200 | 最大可注册服务数 |

**注册行为**：

- 服务名已存在时覆盖更新
- 达到上限且服务名不存在时静默忽略
- 元数据自动经过`sanitizeObject()`消毒处理（XSS/注入防护）

**查询方法**：

```javascript
registry.getService('my-service');  // 单个查询，不存在返回null
registry.listServices();            // 列出所有服务
```

### SharedFeatureFlags（特性标志管理器）

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `maxFlags` | 200 | 最大特性标志数 |
| `maxHistory` | 100 | 变更历史最大记录数 |

**变更历史**：使用`RingBuffer`存储，超出时自动覆盖最旧记录。

```javascript
flags.set('dark-mode', true, '用户偏好');
flags.isEnabled('dark-mode');        // true
flags.isEnabled('unknown', false);   // false（使用默认值）
flags.getStats();
// { totalFlags: 1, enabledCount: 1, disabledCount: 0, historySize: 1 }
```

### 资源配额与成本控制联动

当Token预算进入预警/危险区时，可通过特性标志关闭非关键功能以节省资源：

```
token-warning-80 → 设置 feature flag "premium-features" = false
token-warning-95 → 设置 feature flag "non-critical-tasks" = false
token-exhausted  → 设置 feature flag "system-essential-only" = true
token-reset      → 恢复所有 feature flag 到默认状态
```

### 告警事件汇总

| 事件 | 发射者 | 触发条件 | 建议动作 |
|------|--------|---------|---------|
| `token-warning-80` | TokenManager | 使用率 ≥ 80% | 日志记录、通知运维 |
| `token-warning-95` | TokenManager | 使用率 ≥ 95% | 模型降级、暂停低优先级任务 |
| `token-exhausted` | TokenManager | 使用率 ≥ 100% | 暂停所有任务、紧急扩容 |
| `token-reset` | TokenManager | Token被清除 | 恢复正常模型选择 |
| `budget-warning` | SessionManager | 会话预算达到阈值 | 日志记录、UI提示 |
| `budget-config-changed` | SessionManager | 预算配置热更新 | 重新评估当前任务预算 |
| `model-downgraded` | ModelSelector | 模型因预算降级 | 日志记录、通知用户 |
| `budget-recovered` | ModelSelector | 预算标志重置 | 恢复正常模型选择 |
| `session-evicted` | SessionManager | 会话因容量被淘汰 | 日志记录 |
| `session-expired` | SessionManager | 会话TTL过期 | 清理资源 |
