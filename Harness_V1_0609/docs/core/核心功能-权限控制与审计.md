# 核心功能-权限控制与审计

> 版本：2.73.4 | 模块：src/permission/ | 文件：rbac-enforcer.js, permission-guard.js, audit-logger.js

---

## 概述

权限执行引擎是Harness多Agent框架的安全核心，提供三层数据安全防护：基于角色的访问控制（RBACEnforcer）、文件操作权限守卫（PermissionGuard）、操作审计日志（AuditLogger）。三者协同工作，确保多Agent协作过程中的权限合规、数据安全和操作可追溯。

### 架构总览

```
┌──────────────────────────────────────────────────────────┐
│                    权限执行引擎                             │
├──────────────────┬──────────────────┬────────────────────┤
│  RBACEnforcer    │ PermissionGuard  │   AuditLogger      │
│  角色访问控制     │ 文件操作守卫      │   操作审计日志      │
├──────────────────┼──────────────────┼────────────────────┤
│  load()          │ checkFileWrite() │   log()            │
│  canExecute()    │ checkFileDelete()│   query()          │
│  getAgentModel() │ checkFileRead()  │   verifyIntegrity()│
│  startWatching() │ checkCommand()   │   getStats()       │
│  isHealthy()     │ acquireLock()    │   export()         │
│                  │ releaseLock()    │   getRecent()      │
│                  │ enforceFileWrite │   clear()          │
│                  │ enforceCommand   │   flush()          │
└──────────────────┴──────────────────┴────────────────────┘
         ↓                  ↓                    ↓
  .harness/agents/   .harness/permission/   .harness/audit/
  .harness/skills/   guard-state.json       audit-log.json
```

### 协作流程

1. Agent请求执行Skill → RBACEnforcer验证角色权限
2. Agent请求文件操作 → PermissionGuard检查路径安全、文件锁、系统文件保护
3. 所有权限决策 → AuditLogger记录审计日志（链式哈希保证不可篡改）

## RBACEnforcer — 角色访问控制

### 模块定位

RBACEnforcer基于`.harness/agents/`和`.harness/skills/`目录下的Markdown文件定义，验证Agent是否有权执行Skill，支持strict/recommended/optional三级执行级别和Skill执行顺序验证。

### 类定义

```javascript
class RBACEnforcer extends EventEmitter { ... }
```

通过`withShutdown`混入后导出。

### 构造函数

#### `new RBACEnforcer(projectRoot)`

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `projectRoot` | string | 是 | 项目根目录路径，必须为有效路径 |

**异常**：若projectRoot无效，构造函数即抛出错误。

### 核心方法

#### `load()`

从`.harness/agents/`和`.harness/skills/`加载权限定义。解析Markdown文件的frontmatter元数据，构建Agent-Skill权限映射。

**返回值**：`Object`

| 字段 | 类型 | 说明 |
|------|------|------|
| `agentsLoaded` | number | 成功加载的Agent定义数 |
| `skillsLoaded` | number | 成功加载的Skill定义数 |
| `errors` | number | 加载错误数 |
| `busy` | boolean | 是否正在加载中（重复调用时） |

> **v2.7.122 修复说明**：`load()` 返回值中 `busy` 字段现已保证始终存在。正常返回时为 `busy: false`，当检测到重复加载（已有加载进行中）时为 `busy: true`。此前 `busy` 字段仅在重复调用时才出现在返回值中，导致调用方无法可靠判断加载状态。

> **v2.7.122 Round 7 修复说明**：`load()` 现采用原子性更新策略。解析结果先写入临时变量，仅在全部解析成功后才统一替换内部状态（`_agentDefs`、`_skillDefs`、`_enforcementMap` 等）。若任一阶段出错，不更新任何状态，保持原有权限映射不变。此前部分解析成功时会直接更新对应状态，导致内部状态处于不一致的中间态。

加载策略：
- 若Agent和Skill均加载成功，全部替换
- 若仅Agent成功，仅替换Agent定义
- 若仅Skill成功，仅替换Skill定义
- 加载错误不超过200条

#### `canExecute(agentId, skillId)`

检查Agent是否有权执行指定Skill。

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `agentId` | string | 是 | Agent角色ID，最长128字符，不允许含`/\:*?"<>|` |
| `skillId` | string | 是 | Skill ID，最长128字符，不允许含`/\:*?"<>|` |

**返回值**：`boolean` — Agent是否有权执行该Skill

#### `getAgentModel(agentId)`

获取Agent定义中指定的模型名称。

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `agentId` | string | 是 | Agent角色ID |

**返回值**：`string` — 模型名称，未定义时返回空字符串

### 文件监控方法

#### `startWatching()`

启动文件监控，当`.harness/agents/`或`.harness/skills/`目录下的Markdown文件变更时，自动触发热重载。

使用`fs.watch`实现，防抖间隔1秒，冷却期由`DEFAULT_MIN_HEARTBEAT_MS`控制。单次会话最多重载100次，超出后暂停监控并进入冷却期。

**事件**：
- `watching-started`：监控启动
- `permissions-reloaded`：权限定义热重载完成
- `reload-stopped`：重载次数过多，暂停监控
- `watcher-resumed`：冷却期结束，恢复监控
- `reload-error`：重载失败

#### `stopWatching()`

停止文件监控，关闭所有watcher。

### Agent定义结构

从`.harness/agents/`目录的Markdown frontmatter解析：

| 字段 | 类型 | 说明 |
|------|------|------|
| `role` | string | Agent角色名称 |
| `skills` | string[] | 可用的Skill ID列表 |
| `auto_route` | boolean | 是否启用自动路由 |
| `tdd_enforced` | boolean | 是否强制TDD |
| `collaborates_with` | string[] | 协作的Agent列表 |
| `manages` | string[] | 管理的Agent列表 |
| `model` | string | 指定使用的模型 |
| `level` | string | Agent层级 |
| `permissions` | Object | 权限映射（仅保留合法键） |

合法权限键：`can_execute_skills`、`can_write_files`、`can_delete_files`、`can_execute_commands`、`can_modify_config`、`can_access_sessions`

### Skill定义结构

从`.harness/skills/`目录的Markdown frontmatter解析：

| 字段 | 类型 | 说明 |
|------|------|------|
| `skill_id` | string | Skill ID |
| `enforcement` | string | 执行级别：strict/recommended/optional |
| `depends_on` | string[] | 依赖的Skill列表 |
| `applicable_agents` | string[] | 适用的Agent列表 |
| `phase` | string | 所属阶段 |
| `priority` | number | 优先级 |

### 健康检查

#### `isHealthy()`

**返回值**：`boolean` — 未关闭且至少加载了Agent或Skill定义时返回`true`

### 事件

| 事件名 | 触发时机 | 事件数据 |
|--------|---------|---------|
| `load-warnings` | 加载过程中有错误 | `Array<{ phase, file, error }>` |
| `watching-started` | 文件监控启动 | `{ directories }` |
| `permissions-reloaded` | 权限热重载完成 | `{ eventType, filename, agentsLoaded, skillsLoaded, errors }` |
| `reload-stopped` | 重载次数过多 | `{ reason: 'too_many_reloads' }` |
| `watcher-resumed` | 冷却期结束恢复监控 | `{ reason: 'cooldown_expired' }` |
| `reload-error` | 重载失败 | Error对象 |

## PermissionGuard — 文件操作守卫

### 模块定位

PermissionGuard提供路径遍历防护、文件级锁、危险命令检测和确认过期机制，防止多Agent并发冲突和安全风险。所有文件操作必须经过PermissionGuard检查。

### 类定义

```javascript
class PermissionGuard extends EventEmitter { ... }
```

通过`withShutdown`混入后导出。

### 构造函数

#### `new PermissionGuard(projectRoot)`

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `projectRoot` | string | 是 | 项目根目录路径 |

构造时自动从`.harness/permission/guard-state.json`恢复锁和确认状态。

### 路径安全方法

#### `checkFileWrite(filePath, agentId)`

检查文件写入权限。依次验证：路径合法性 → 项目内路径 → 系统文件保护 → 文件锁冲突。

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `filePath` | string | 是 | 目标文件路径 |
| `agentId` | string | 是 | 请求写入的Agent ID |

**返回值**：`Object`

| 字段 | 类型 | 说明 |
|------|------|------|
| `allowed` | boolean | 是否允许 |
| `reason` | string | 拒绝原因（允许时为undefined） |

拒绝原因包括：
- 路径在项目外
- 系统文件只读（`.harness/agents/`、`.harness/skills/`、`.harness/rules/`、`.harness/workspace/`、`.harness/config.json`）
- 文件被其他Agent锁定

#### `checkFileDelete(filePath, agentId)`

检查文件删除权限。系统文件禁止删除，其他文件需人工确认。

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `filePath` | string | 是 | 目标文件路径 |
| `agentId` | string | 否 | 请求删除的Agent ID |

**返回值**：`Object`

| 字段 | 类型 | 说明 |
|------|------|------|
| `allowed` | boolean | 是否允许 |
| `requiresConfirmation` | boolean | 是否需要人工确认 |
| `reason` | string | 拒绝原因 |

已确认过的删除操作在过期窗口内无需再次确认。

#### `checkFileRead(filePath, agentId)`

检查文件读取权限。`.harness/data/`目录需要Agent ID验证。

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `filePath` | string | 是 | 目标文件路径 |
| `agentId` | string | 否 | 请求读取的Agent ID |

**返回值**：`Object` — `{ allowed, reason? }`

#### `checkCommand(command, agentId)`

检查命令是否安全，检测危险命令模式。

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `command` | string | 是 | 要执行的命令 |
| `agentId` | string | 否 | 请求执行的Agent ID |

**返回值**：`Object`

| 字段 | 类型 | 说明 |
|------|------|------|
| `allowed` | boolean | 是否允许 |
| `requiresConfirmation` | boolean | 是否需要人工确认 |
| `reason` | string | 拒绝原因 |

安全命令白名单：`ls`、`pwd`、`echo`、`cat`、`head`、`tail`、`wc`、`git status`、`git log`、`git diff`、`git branch`——这些命令无需确认。

危险命令模式（由`DANGEROUS_SHELL_PATTERNS`定义）直接拒绝。其他命令允许但需人工确认。

### 强制执行方法

#### `enforceFileWrite(filePath, agentId)`

强制执行文件写入权限检查，不允许时抛出`PermissionError`。

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `filePath` | string | 是 | 目标文件路径 |
| `agentId` | string | 是 | 请求写入的Agent ID |

**返回值**：`true`

**异常**：`PermissionError` — 错误码为`FILE_OUTSIDE_PROJECT`、`SYSTEM_FILE_READONLY`或`LOCK_CONFLICT`

#### `enforceCommand(command, agentId)`

强制执行命令安全检查，检测到危险命令时抛出`PermissionError`。

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `command` | string | 是 | 要执行的命令 |
| `agentId` | string | 是 | 请求执行的Agent ID |

**返回值**：`true`

**异常**：`PermissionError('DANGEROUS_COMMAND')`

### 文件锁方法

#### `acquireLock(filePath, agentId)`

获取文件锁。同一Agent可重入（最多10次续期），不同Agent互斥。

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `filePath` | string | 是 | 目标文件路径 |
| `agentId` | string | 是 | 请求锁的Agent ID |

**返回值**：`boolean` — 是否成功获取锁

锁超时后自动释放（由`DEFAULT_LOCK_TIMEOUT_MS`控制）。最大锁数量由`MAX_LOCKS`限制。

#### `releaseLock(filePath, agentId)`

释放文件锁。仅锁持有者可释放。

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `filePath` | string | 是 | 目标文件路径 |
| `agentId` | string | 是 | 释放锁的Agent ID |

**返回值**：`boolean` — 是否成功释放

#### `getLockHolder(filePath)`

获取文件锁的持有者。

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `filePath` | string | 是 | 目标文件路径 |

**返回值**：`string | null` — 锁持有者Agent ID，无锁或锁已过期返回`null`

### 确认管理方法

#### `recordConfirmation(agentId, action, target)`

记录人工确认操作。

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `agentId` | string | 是 | Agent ID |
| `action` | string | 是 | 操作类型 |
| `target` | string | 是 | 操作目标 |

**返回值**：`boolean` — 是否成功记录

确认记录上限5000条，超出时淘汰过期或最早的记录。

#### `isConfirmationValid(agentId, action, target)`

检查确认是否仍在有效期内。

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `agentId` | string | 是 | Agent ID |
| `action` | string | 是 | 操作类型 |
| `target` | string | 是 | 操作目标 |

**返回值**：`boolean` — 确认是否有效

#### `setConfirmationExpiry(ms)`

设置确认过期时间。

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `ms` | number | 是 | 过期时间（毫秒），最大1天 |

**返回值**：`this`

### 静态方法

#### `PermissionGuard.validateSessionId(sessionId)`

验证Session ID格式合法性（防路径注入），仅允许`[a-zA-Z0-9_-]`，最长64字符。

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `sessionId` | string | 是 | 待验证的Session ID |

**返回值**：`boolean`

### 健康检查

#### `isHealthy()`

**返回值**：`boolean` — 锁数量和确认数量未超过健康阈值时返回`true`

### 持久化

PermissionGuard通过防抖持久化机制将锁和确认状态保存到`.harness/permission/guard-state.json`：
- 使用`writeAtomic`确保写入原子性
- 定期轮询检查脏标记并持久化
- 启动时通过`JsonStoreRestorer`恢复状态
- 恢复时自动过滤过期的锁和确认

> **v2.7.122 修复说明**：持久化重试现已内置断路器机制，最大重试次数为5次（`_maxPersistRetries`），通过 `_persistRetryCount` 计数器追踪。当连续持久化失败达到上限时，停止重试并发射 `persist-error` 事件，防止在持续 I/O 故障时产生无限重试循环。

### 事件

| 事件名 | 触发时机 | 事件数据 |
|--------|---------|---------|
| `confirmation-recorded` | 确认被记录 | `{ agentId, action, target, confirmedAt }` |
| `persist-error` | 持久化失败 | Error对象 |
| `restore-error` | 恢复失败 | Error对象 |

## AuditLogger — 操作审计日志

### 模块定位

AuditLogger维护链式哈希的审计日志，确保操作记录不可篡改。每条日志包含时间戳、Agent、操作、目标、结果等字段，并计算SHA-256哈希形成链式结构。支持防抖持久化、完整性验证和查询过滤。

### 类定义

```javascript
class AuditLogger extends EventEmitter { ... }
```

通过`withShutdown`混入后导出。

### 静态属性

| 属性 | 类型 | 说明 |
|------|------|------|
| `AuditLogger.MAX_LOG_ENTRIES` | number | 最大日志条目数（默认10000） |

### 构造函数

#### `new AuditLogger(projectRoot, options)`

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `projectRoot` | string | 否 | 项目根目录，提供时启用持久化 |
| `options.maxEntries` | number | 否 | 最大日志条目数，默认10000 |

提供projectRoot时，自动从`.harness/audit/audit-log.json`恢复历史日志。

### 核心方法

#### `log(event)`

记录一条审计日志。自动添加时间戳、计算链式哈希。

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `event` | Object | 是 | 事件对象 |
| `event.agent` | string | 否 | Agent名称，默认DEFAULT_AGENT_NAME |
| `event.action` | string | 否 | 操作类型，默认'unknown' |
| `event.target` | string | 否 | 操作目标，默认空字符串 |
| `event.result` | string | 否 | 操作结果（'allowed'/'denied'），默认'unknown' |
| `event.reason` | string | 否 | 原因说明，默认空字符串 |
| `event.details` | string | 否 | 详细信息，默认空字符串 |
| `event.responsibility` | string | 否 | 责任归属（'ai-autonomous'/'human-approved'），默认'ai-autonomous' |

日志条目内部结构：

| 字段 | 类型 | 说明 |
|------|------|------|
| `timestamp` | string | ISO 8601时间戳 |
| `agent` | string | Agent名称 |
| `action` | string | 操作类型 |
| `target` | string | 操作目标 |
| `result` | string | 操作结果 |
| `reason` | string | 原因 |
| `details` | string | 详细信息 |
| `responsibility` | string | 责任归属 |
| `_seq` | number | 序列号 |
| `_hash` | string | SHA-256链式哈希 |

#### `verifyIntegrity()`

验证审计日志的链式哈希完整性。

**返回值**：`Object`

| 字段 | 类型 | 说明 |
|------|------|------|
| `total` | number | 总条目数 |
| `tampered` | number | 被篡改的条目数 |
| `tamperedIndices` | number[] | 被篡改条目的索引 |
| `valid` | boolean | 是否全部有效 |

恢复时若检测到篡改，自动截断到第一个被篡改条目之前。

#### `query(filter)`

查询审计日志，支持多维度过滤。

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `filter` | Object | 否 | 过滤条件 |
| `filter.agent` | string | 否 | 按Agent过滤 |
| `filter.action` | string | 否 | 按操作类型过滤 |
| `filter.result` | string | 否 | 按结果过滤 |
| `filter.target` | string | 否 | 按目标过滤 |
| `filter.responsibility` | string | 否 | 按责任归属过滤 |

**返回值**：`Array<Object>` — 匹配的日志条目

#### `getRecent(count)`

获取最近的N条日志。

| 参数 | 类型 | 必填 | 默认值 | 说明 |
|------|------|------|--------|------|
| `count` | number | 否 | 10 | 获取条数 |

**返回值**：`Array<Object>`

#### `getStats()`

获取审计日志统计信息。

**返回值**：`Object`

| 字段 | 类型 | 说明 |
|------|------|------|
| `total` | number | 总条目数 |
| `allowed` | number | 允许的操作数 |
| `denied` | number | 拒绝的操作数 |
| `byAgent` | Object | 按Agent统计的操作数 |
| `byResponsibility` | Object | 按责任归属统计的操作数 |

#### `clear()`

清空所有日志条目并立即持久化。

#### `export()`

导出日志为格式化JSON字符串。

**返回值**：`string`

#### `flush()`

立即将日志持久化到磁盘。

### 属性访问

#### `entries`

获取所有日志条目的数组副本（getter）。

**返回值**：`Array<Object>`

### 持久化机制

- 使用`createPersister`创建防抖持久化器
- 防抖间隔由`DEFAULT_PERSIST_DEBOUNCE_MS`控制
- 持久化路径：`.harness/audit/audit-log.json`
- 使用`writeAtomic`确保写入原子性
- 启动时通过`JsonStoreRestorer`恢复历史日志
- 恢复时验证必需字段和危险键过滤
- 恢复后自动执行完整性验证

> **v2.7.122 Round 7 修复说明**：恢复过程中现已新增逐条哈希完整性验证。每条恢复的条目在加入内存前，重新计算其 SHA-256 哈希并与存储的 `_hash` 字段比较。若检测到不匹配，立即截断到该条目之前，并发射 `integrity-violation` 事件。此前恢复时仅验证必需字段是否存在，篡改条目会被直接加载到内存中，直到显式调用 `verifyIntegrity()` 才能发现。

### 事件

| 事件名 | 触发时机 | 事件数据 |
|--------|---------|---------|
| `persist-error` | 持久化失败 | Error对象 |
| `restore-error` | 恢复失败 | Error对象 |
| `integrity-violation` | 检测到日志篡改 | `{ total, tampered, tamperedIndices, valid }` |

## 集成使用示例

### 完整权限检查流程

```javascript
const RBACEnforcer = require('./src/permission/rbac-enforcer');
const PermissionGuard = require('./src/permission/permission-guard');
const AuditLogger = require('./src/permission/audit-logger');

const projectRoot = '/path/to/project';

const enforcer = new RBACEnforcer(projectRoot);
enforcer.load();

const guard = new PermissionGuard(projectRoot);
const audit = new AuditLogger(projectRoot, { maxEntries: 5000 });

if (!enforcer.canExecute('task-worker', 'tdd-implement')) {
  audit.log({ agent: 'task-worker', action: 'skill-execute', target: 'tdd-implement', result: 'denied', reason: 'RBAC: skill not available' });
  throw new Error('Permission denied');
}

const writeResult = guard.checkFileWrite('/path/to/project/src/main.js', 'task-worker');
if (!writeResult.allowed) {
  audit.log({ agent: 'task-worker', action: 'file-write', target: '/path/to/project/src/main.js', result: 'denied', reason: writeResult.reason });
  throw new Error(writeResult.reason);
}

audit.log({ agent: 'task-worker', action: 'file-write', target: '/path/to/project/src/main.js', result: 'allowed' });
```

### 文件锁协作

```javascript
if (guard.acquireLock('/path/to/project/src/main.js', 'task-worker')) {
  try {
    guard.enforceFileWrite('/path/to/project/src/main.js', 'task-worker');
  } finally {
    guard.releaseLock('/path/to/project/src/main.js', 'task-worker');
  }
}
```

### 审计日志查询

```javascript
const deniedActions = audit.query({ result: 'denied' });
const workerActions = audit.query({ agent: 'task-worker' });
const recentActions = audit.getRecent(20);
const stats = audit.getStats();

const integrity = audit.verifyIntegrity();
if (!integrity.valid) {
  console.error(`检测到${integrity.tampered}条被篡改的日志`);
}
```

### 热重载监控

```javascript
enforcer.startWatching();

enforcer.on('permissions-reloaded', (data) => {
  console.log(`权限已热重载: ${data.agentsLoaded} agents, ${data.skillsLoaded} skills`);
});

enforcer.on('reload-stopped', () => {
  console.warn('重载次数过多，监控已暂停');
});
```
