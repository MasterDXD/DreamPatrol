# 核心功能-会话管理与检查点恢复

> 版本：2.73.4 | 模块：src/runtime/session/session-manager.js、src/runtime/session/checkpoint-manager.js

---

## 概述

会话管理子系统是Harness Engineering多Agent框架的运行时状态中枢，负责跟踪每个会话的当前阶段、已完成Skill、Token用量、Agent操作历史等核心状态。子系统由两个紧密协作的模块构成：

- **SessionManager** — 会话全生命周期管理，包括创建、持久化、TTL过期清理、阶段推进、Token预算追踪
- **CheckpointManager** — 检查点创建与恢复，支持增量保存、因果回滚、关机竞态安全处理

两者共同实现"进程重启后状态不丢失"和"任务失败后可恢复"两大容错目标。

## 核心概念

### Session生命周期

```
创建(create) → 活跃(active) → 过期(expired) / 完成(completed)
     ↑                              |
     └──── 恢复(restore) ←──────────┘
```

| 概念 | 说明 |
|------|------|
| **Session** | 一次完整的Agent协作会话，包含阶段、Skill、Token、Agent历史等状态 |
| **TTL** | 会话生存时间，默认24小时（MS_PER_DAY），超时自动清理 |
| **Phase** | 六阶段流程中的当前阶段，仅允许合法转换 |
| **Token Budget** | 会话级Token预算，80%预警、95%危险、100%耗尽 |
| **Checkpoint** | 会话状态的快照点，用于故障恢复和因果回滚 |
| **Debounced Persist** | 防抖持久化，合并短时间内的多次写入为一次磁盘IO |

### Session数据结构

```javascript
{
  id: string,                    // 会话ID，匹配 /^[a-zA-Z0-9_-]{1,64}$/
  currentPhase: string,          // 当前阶段（PHASES之一）
  completedSkills: string[],     // 已完成的Skill列表（最大500，裁剪至400）
  tokensUsed: number,            // 已使用Token数量
  status: 'active'|'completed'|'expired',
  createdAt: string,             // ISO格式创建时间
  lastActivityAt: string,        // ISO格式最后活动时间
  agentHistory: AgentAction[],   // Agent操作历史（最大500，裁剪至400）
  deepeningState: Object,        // 深化推理状态
  entropyState: Object,          // 熵状态（收敛检测）
  metadata: Object,              // 自定义元数据
}
```

### Checkpoint数据结构

```javascript
{
  id: string,                    // 检查点ID，格式 cp-{random}
  sessionId: string,             // 所属会话ID
  phase: string,                 // 快照时的阶段
  completedSkills: string[],     // 快照时的已完成Skill
  tokensUsed: number,            // 快照时的Token用量
  agentHistory: AgentAction[],   // 快照时的Agent历史
  causalWalSequence: number,     // 因果WAL序列号（用于回滚）
  metadata: Object,              // 自定义元数据
  createdAt: string,             // ISO格式创建时间
}
```

## SessionManager详解

### 会话创建

`create(sessionId)` 方法创建新会话，执行以下步骤：

1. **ID验证**：sessionId必须匹配`/^[a-zA-Z0-9_-]{1,64}$/`，不合法抛出`INVALID_SESSION_ID`
2. **重复检测**：若sessionId已存在且非恢复会话，抛出`SESSION_EXISTS`；若为恢复会话则覆盖
3. **容量检查**：活跃会话数超过`MAX_SESSIONS`（100）时，驱逐最久未活动的会话；驱逐进行中时抛出`EVICT_IN_PROGRESS`
4. **初始化**：设置初始阶段为`brainstorming`（PHASES[0]），Token用量为0，状态为`active`
5. **持久化**：立即写入磁盘（`immediate=true`）
6. **事件发射**：触发`session-created`事件

```javascript
const session = mgr.create('my-session');
// session.currentPhase === 'brainstorming'
// session.tokensUsed === 0
// session.status === 'active'
```

### 就绪状态

`get ready` getter属性指示SessionManager是否已完成初始化（包括会话恢复）：

- 返回`true`：构造函数已完成，所有会话已从磁盘恢复，可正常使用
- 返回`false`：初始化尚未完成（如异步恢复进行中）

```javascript
const mgr = new SessionManager('/path/to/project');
if (!mgr.ready) {
  console.log('SessionManager尚未就绪，等待初始化完成');
}
```

### 防抖持久化

SessionManager使用`KeyedDebouncer`实现防抖持久化，避免高频状态更新导致磁盘IO风暴：

- **常规更新**：在`DEFAULT_DEBOUNCE_MS`内合并多次写入为一次
- **关键操作**：`create`、`advancePhase`、`completeSkill`使用`immediate=true`立即写入
- **关机保护**：`flush()`方法在进程退出前强制刷盘所有待写入会话
- **原子写入**：使用`writeAtomic()`确保写入完整性，避免半写文件

```
状态变更 → _persist(session, immediate?)
  → immediate=true → 立即写磁盘
  → immediate=false → KeyedDebouncer延迟合并
       → DEBOUNCE_MS后执行 _writeToDisk()
            → writeAtomic() 原子写入 .harness/sessions/{id}.json
```

### TTL过期清理

SessionManager在构造时启动TTL清理定时器，每5分钟（`TTL_CLEANUP_INTERVAL_MS`）扫描一次：

```
TTL清理流程：
  遍历所有内存会话
    → 解析lastActivityAt时间戳
    → 时间戳无效(NaN)？→ 删除内存会话，发射session-expired事件
    → 超过TTL？→ 删除内存会话 + 异步删除磁盘文件，发射session-expired事件
```

- 默认TTL：`MS_PER_DAY`（24小时），可通过config.json的`session_ttl_ms`覆盖
- 定时器调用`.unref()`，不阻止进程退出
- 磁盘文件删除为异步操作，失败仅记录debug日志

### 会话恢复

进程重启后，SessionManager从`.harness/sessions/`目录恢复会话：

**同步恢复**（`_restoreSessionsSync`，构造时调用）：
1. 读取sessions目录下所有JSON文件
2. 验证会话有效性（`_isValidRestorableSession`）
3. 有效条件：status为active、非测试ID、时间戳有效、未超过TTL
4. 修复字段类型（`_ensureSessionFieldTypes`）
5. 标记`_restored=true`（允许create时覆盖）

**异步恢复**（`_restoreSessionsAsync`，可选）：
- 同步恢复的异步版本，适合启动性能敏感场景

**测试ID过滤**：以下前缀开头的sessionId不会被恢复：`test-`、`sess-`、`deepening-test-`、`phase-`、`token-`、`budget-`等20+个前缀。

### 阶段推进

`advancePhase(sessionId, newPhase)` 方法推进会话阶段：

1. **同阶段检查**：目标阶段与当前阶段相同则直接返回
2. **合法性验证**：通过`PHASE_TRANSITIONS_SET`检查转换是否允许
3. **状态更新**：更新currentPhase和lastActivityAt
4. **持久化**：立即写入磁盘
5. **事件发射**：触发`phase-change`事件
6. **上下文注入**：若已注入PhaseContextInjector，自动注入新阶段上下文
7. **自回归上下文**：通过`AR.inject()`记录阶段转换到自回归上下文

合法的阶段转换规则：

```
brainstorming        → requirement-analysis
requirement-analysis → architecture-design, brainstorming（回退）
architecture-design  → module-development, requirement-analysis（回退）
module-development   → integration-testing, architecture-design（回退）
integration-testing  → deployment, module-development（回退）
deployment           → integration-testing（回退）
```

### Token预算追踪

`addTokenUsage(sessionId, tokens)` 方法记录Token消耗：

1. **参数验证**：tokens必须为非负有限数，否则抛出`INVALID_TOKEN_USAGE`
2. **累加**：`session.tokensUsed += numTokens`
3. **预算检查**：调用`checkBudget()`获取当前预算状态

`checkBudget(sessionId)` 返回预算状态：

| 字段 | 说明 | 阈值 |
|------|------|------|
| `warning80` | 80%预警 | `tokensUsed / budget >= 0.8` |
| `warning95` | 95%危险 | `tokensUsed / budget >= 0.95` |
| `exhausted` | 预算耗尽 | `tokensUsed / budget >= 1.0` |
| `ratio` | 使用比例 | 保留2位小数 |
| `sessionNotFound` | 会话不存在 | `boolean`，会话未找到时为`true` |

当达到任一预警阈值时，发射`budget-warning`事件。

### 配置加载与NaN防护

SessionManager在加载config.json时对数值型配置项进行严格的NaN防护：

```javascript
// token_budget：确保为非负整数，NaN或负数回退为0
raw.token_budget = Math.max(0, Math.floor(Number(raw.token_budget)) || 0);

// max_sessions：范围限制[1, 1000]，NaN回退为100
raw.max_sessions = Math.max(1, Math.min(1000, Math.floor(Number(raw.max_sessions)) || 100));

// session_ttl_ms：最小值为DEFAULT_SESSION_TTL_MIN_MS（1分钟），NaN回退为MS_PER_HOUR
raw.session_ttl_ms = Math.max(DEFAULT_SESSION_TTL_MIN_MS, Math.floor(Number(raw.session_ttl_ms)) || MS_PER_HOUR);
```

防护策略：
- `Number()` 将任意类型转为数值
- `Math.floor()` 确保整数
- `|| defaultValue` 处理NaN（`Math.floor(NaN)` → NaN → falsy → 回退默认值）
- `Math.max()` / `Math.min()` 限制合法范围

### 配置热重载

SessionManager通过`fs.watch()`监听config.json变更：

- **防抖**：500ms内合并多次变更事件
- **验证**：新配置的token_budget必须为非负数，否则忽略
- **事件**：配置变更触发`config-reloaded`事件
- **阶段预算变更**：若`phase_budget_allocation`发生变化，额外触发`budget-config-changed`事件
- **错误重试**：watcher出错后指数退避重试（500ms~120s），最多10次

### 深化推理状态

SessionManager为每个会话维护深化推理状态（`deepeningState`）：

```javascript
{
  totalIterations: number,           // 总迭代次数
  totalDeepeningExecutions: number,  // 总深化执行次数
  bestQualityScore: number,          // 历史最佳质量分数
  convergenceHistory: Array,         // 收敛历史（最大200，裁剪至150）
  agentAffinities: Object,           // Agent亲和力映射
}
```

- `recordDeepeningIteration(sessionId, data)` — 记录一次深化迭代
- `recordDeepeningConvergence(sessionId, data)` — 记录一次收敛事件
- `getDeepeningState(sessionId)` — 获取深化状态（深拷贝）

### 熵状态追踪

`updateEntropyState(sessionId, priorRichness)` 方法追踪会话的信息熵变化：

- 首次调用：记录`firstMessageRichness`作为基准
- 后续调用：若当前为`low-entropy`且之前非`low-entropy`，递增`convergenceTurns`
- 发射`entropy-updated`事件

### 优雅关机

SessionManager通过`withShutdown`混入实现优雅关机：

1. **刷盘**：`flush()`强制写入所有待持久化会话
2. **销毁防抖器**：`_persistDebouncer.destroy()`
3. **清理定时器**：停止TTL清理定时器
4. **关闭Watcher**：关闭配置文件监听器
5. **释放引用**：清空CausalDataBus、PhaseContextInjector、AR上下文
6. **移除信号处理器**：清理SIGINT/SIGTERM监听器

可通过`registerShutdownHooks()`注册进程信号处理器，实现进程退出前自动关机。

## CheckpointManager详解

### 检查点创建

`create(sessionId, data)` 方法创建检查点：

1. **参数验证**：sessionId必须为非空字符串且匹配`/^[a-zA-Z0-9_-]+$/`，长度不超过128
2. **ID生成**：使用`generateId('cp-')`生成唯一检查点ID
3. **时间戳单调性**：确保新检查点的时间戳严格大于上一个（`_lastTimestamp`），避免时钟回拨导致排序异常
4. **容量控制**：检查点数量超过`MAX_CHECKPOINTS`（50）时，驱逐最旧的检查点
5. **持久化**：同步写入磁盘

```javascript
const cp = cpMgr.create('my-session', {
  phase: 'module-development',
  completedSkills: ['brainstorming', 'requirement-analysis'],
  tokensUsed: 50000,
  agentHistory: [...],
  causalWalSequence: 42,
  metadata: { reason: 'pre-refactor' },
});
// cp.id === 'cp-xxxx'
// cp.createdAt === ISO时间戳
```

### 检查点恢复

`restore(checkpointId)` 方法恢复检查点，返回恢复数据（不修改任何会话状态）：

```javascript
const restored = cpMgr.restore('cp-xxxx');
// {
//   phase: 'module-development',
//   completedSkills: [...],
//   tokensUsed: 50000,
//   agentHistory: [...],
//   causalWalSequence: 42,
//   metadata: { reason: 'pre-refactor' },
//   restoredFrom: 'cp-xxxx',
//   restoredAt: '2026-05-25T10:00:00.000Z',
// }
```

恢复数据需由调用方应用到SessionManager，CheckpointManager本身不直接修改会话状态。

### 因果回滚恢复

`restoreWithCausalRollback(checkpointId, causalDataBus)` 方法在恢复检查点的同时回滚因果数据：

1. 调用`restore()`获取恢复数据
2. 若causalDataBus已连接且`causalWalSequence > 0`，调用`causalDataBus.rollbackToSequence()`
3. 将回滚结果附加到返回数据的`causalRollback`字段

这确保检查点恢复后，因果数据总线的状态与检查点快照一致，避免因果不一致。

### 增量保存与磁盘同步

`_persist()` 方法实现检查点的磁盘同步：

1. 确保checkpoints目录存在
2. 遍历内存中的所有检查点，逐个`writeAtomic`写入
3. 扫描磁盘文件，删除内存中已不存在的检查点文件（清理孤立文件）

异步版本`_persistAsync()`使用`Promise.all`并行写入和删除，提高大容量场景下的性能。

### 关机竞态处理

CheckpointManager通过`_shutdownStarted`标志防止关机期间的竞态条件：

```javascript
_onShutdown() {
  if (this._shutdownStarted) return;   // 防止重复关机
  this._shutdownStarted = true;
  this._persist();                      // 同步刷盘
  this._checkpoints.clear();            // 清空内存
}

async shutdownAsync() {
  if (this._shutdownStarted) return;   // 同一标志位
  this._shutdownStarted = true;
  await this._persistAsync();           // 异步刷盘
  this._checkpoints.clear();
}
```

- 同步关机（`_onShutdown`）：由`withShutdown`混入触发，适合SIGINT/SIGTERM信号处理
- 异步关机（`shutdownAsync`）：显式调用，适合优雅关机流程
- 两者共享`_shutdownStarted`标志，确保只有一个路径执行刷盘，避免数据损坏

### 检查点查询

| 方法 | 说明 |
|------|------|
| `get(checkpointId)` | 获取单个检查点（深拷贝） |
| `list(sessionId?)` | 列出检查点，按创建时间降序排列，可选按sessionId过滤 |
| `getLatest(sessionId)` | 获取指定会话的最新检查点 |
| `remove(checkpointId)` | 删除检查点，返回是否成功 |

| 配置项 | 类型 | 默认值 | 说明 |

| 常量 | 值 | 说明 |
|------|-----|------|
| `MAX_SESSIONS` | 100 | 最大活跃会话数 |

| `MAX_COMPLETED_SKILLS` | 500 | completedSkills最大长度 |
| `COMPLETED_SKILLS_TRIM_TO` | 400 | 裁剪后保留长度 |
| `TTL_CLEANUP_INTERVAL_MS` | 300000 (5分钟) | TTL清理扫描间隔 |
| `DEFAULT_DEBOUNCE_MS` | 来自constants | 防抖持久化延迟 |
| `DEBOUNCE_MS` | 来自constants | 防抖持久化延迟（静态属性） |
| `generateSessionId()` | Function | 生成唯一会话ID（静态方法） |

### CheckpointManager内部常量

| 常量 | 值 | 说明 |
|------|-----|------|
| `MAX_CHECKPOINTS` | 50 | 最大检查点数量 |
| `SAFE_ID_RE` | `/^[a-zA-Z0-9_-]+$/` | 安全ID正则 |

## 使用示例

### 基本会话管理

```javascript
const SessionManager = require('./src/runtime/session/session-manager');

const mgr = new SessionManager('/path/to/project');
mgr.registerShutdownHooks();

mgr.on('phase-change', (evt) => {
  console.log(`阶段变更: ${evt.from} → ${evt.to}`);
});

mgr.on('budget-warning', (evt) => {
  console.log(`预算预警: ${evt.budget.ratio * 100}%`);
});

const session = mgr.create('my-session');

mgr.completeSkill('my-session', 'brainstorming');
mgr.advancePhase('my-session', 'requirement-analysis');
mgr.addTokenUsage('my-session', 5000);

const budget = mgr.checkBudget('my-session');
console.log(budget);
// { warning80: false, warning95: false, exhausted: false, ratio: 0 }

mgr.shutdown();
```

## 与其他子系统的交互

### 与SkillRouter交互

SessionManager为SkillRouter提供`completedSkills`列表，SkillRouter据此过滤已完成的Skill，避免重复执行。同时，SkillRouter的匹配结果通过`completeSkill()`反馈给SessionManager。

```
SkillRouter.match({ completedSkills: session.completedSkills })
  → 过滤已完成Skill
  → 执行匹配的Skill
  → SessionManager.completeSkill(sessionId, skillId)
```

### 与PhaseOrchestrator交互

PhaseOrchestrator通过SessionManager的`advancePhase()`推进阶段，SessionManager验证转换合法性。PhaseOrchestrator在检查阶段完成条件时，读取SessionManager的`completedSkills`判断所需Skill是否已完成。

```
PhaseOrchestrator.advanceToNext()
  → 检查当前阶段Skill完成条件
  → SessionManager.advancePhase(sessionId, nextPhase)
  → PhaseContextInjector.injectForPhase(newPhase)
```

### 与TokenManager交互

SessionManager的`addTokenUsage()`是Token追踪的入口，TokenManager可订阅`budget-warning`事件实现全局Token管控。`checkBudget()`的返回值供上层决策是否降级模型或暂停任务。

```
Token消耗 → SessionManager.addTokenUsage()
  → checkBudget() → { warning80, warning95, exhausted }
  → 发射 budget-warning 事件
  → TokenManager 订阅并执行降级/暂停策略
```

### 与CausalDataBus交互

SessionManager通过`attachCausalDataBus()`接入因果数据总线。每当Skill完成时，通过`_publishCausalOutput()`将完成事件发布到CausalDataBus，形成因果链。CheckpointManager的`restoreWithCausalRollback()`则利用CausalDataBus的`rollbackToSequence()`实现因果回滚。

```
SessionManager.completeSkill()
  → _publishCausalOutput(skillId, session)
  → CausalDataBus.publishOutput(skillId, { sessionId, phase, ... })

CheckpointManager.restoreWithCausalRollback()
  → CausalDataBus.rollbackToSequence(causalWalSequence)
```

### 与AgentRuntime交互

SessionManager通过`recordAgentAction()`记录Agent操作历史，供AgentRuntime追踪Agent行为。`getPreviousSessionContext()`为AgentRuntime提供跨会话的上下文延续能力。

### 与ContextCompressionEngine交互

当Token使用率达到压缩阈值时，ContextCompressionEngine读取SessionManager的会话状态（currentPhase、completedSkills）进行上下文分类和压缩决策。
