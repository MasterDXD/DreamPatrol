### SDD集成层依赖链

SDD（Specification-Driven Development）集成层横跨4个子系统，通过7个模块实现规格驱动的开发流程管控。

#### 主依赖链：规格验证门禁

```
EvidenceVerifier (Gate)
  │ specification_verified 证据类型
  │ 规格验证通过后方可进入下一阶段
  ▼
PhaseOrchestrator (Workflow)
  │ spec gate 阶段门禁
  │ 检查规格资产完整性后允许阶段转换
  ▼
ContextCompressionEngine (Context)
  │ spec asset compression protection
  │ 压缩时保护规格资产不被丢弃或过度摘要
  ▼
SkillRouter (Skill)
  │ spec-driven routing
  │ 基于规格语义匹配和路由技能
```

#### 规格资产生命周期链

```
MemoryStore (Thought)
  │ spec asset lifecycle
  │ 规格资产的持久化存储与检索
  ▼
DocFreshnessGuard (Quality)
  │ spec liveness tracking
  │ 检测规格文档与实现代码的同步状态
  │ 过期规格触发更新提醒
```

#### 独立模块：源码依赖图验证

```
ConfigCausalValidator (Causal)
  │ source code dependency graph
  │ 验证源码依赖关系的因果一致性
  │ 独立于主链，由基础设施层直接支撑
  ▼
SharedInfrastructure
  EventBus
  SQLiteStore
```

#### SDD模块与子系统归属

| 模块 | 子系统 | SDD职责 |
|------|--------|---------|
| EvidenceVerifier | Gate | specification_verified 证据类型，规格验证门禁入口 |
| PhaseOrchestrator | Runtime/Workflow | spec gate，阶段转换时的规格完整性检查 |
| ContextCompressionEngine | Runtime/Context | spec asset compression protection，压缩时保护规格资产 |
| SkillRouter | Runtime/Skill | spec-driven routing，基于规格语义路由技能 |
| MemoryStore | Runtime/Thought | spec asset lifecycle，规格资产持久化与检索 |
| DocFreshnessGuard | Runtime/Quality | spec liveness tracking，规格文档新鲜度检测 |
| ConfigCausalValidator | Runtime/Causal | source code dependency graph，源码依赖因果验证 |

## 循环依赖检测

当前架构无循环依赖。依赖方向严格遵循：
```
应用层 → 运行时层 → 深化层 → 基础设施层 → 权限层 → 工具层
```

SDD集成层作为横切关注点，不引入新的垂直依赖方向，而是沿现有层次横向贯穿。SDD模块间的依赖遵循从门禁（Gate）到路由（Skill）的单向链路，不构成循环：

```
EvidenceVerifier → PhaseOrchestrator → ContextCompressionEngine → SkillRouter
MemoryStore → DocFreshnessGuard
ConfigCausalValidator（独立，无SDD内部依赖）
```
