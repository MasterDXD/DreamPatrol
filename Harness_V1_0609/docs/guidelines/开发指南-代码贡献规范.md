## 二、模块开发规范

### 2.1 TDD强制流程（RED-GREEN-REFACTOR）

框架强制执行TDD开发流程，所有模块开发必须遵循以下步骤：

1. **RED阶段**：先编写失败的测试
2. **GREEN阶段**：编写最小实现使测试通过
3. **REFACTOR阶段**：重构代码，保持测试通过

```javascript
// TDDGate会检查以下条件：
// 1. 测试文件必须先于实现文件存在
// 2. 测试必须先执行（RED）
// 3. 实现代码后执行（GREEN）
// 4. 覆盖率必须达到阈值（默认80%）
```

### 2.2 六阶段开发流程

1. 需求探索 → 2. 需求分析 → 3. 架构设计 → 4. 模块开发 → 5. 集成测试 → 6. 部署上线

### 2.3 模块模板

新模块应遵循以下模板：

```javascript
'use strict';

const { EventEmitter } = require('events');
const { validateProjectRoot } = require('../utils/constants');
const debug = require('../utils/debug-logger');

class MyModule extends EventEmitter {
  constructor(projectRoot, options = {}) {
    super();
    validateProjectRoot(projectRoot, 'MyModule', require('../errors').HarnessError);
    this._projectRoot = projectRoot;
    this._options = Object.assign({}, DEFAULT_CONFIG, options);
    this._initialized = false;
  }

  // Attach模式依赖注入
  attachDependency(dep) {
    this._dep = dep;
    return this;
  }

  // 核心业务方法
  async execute(task, options) {
    if (!this._initialized) {
      throw new require('../errors').HarnessError('INIT_FAILED', 'Module not initialized');
    }
    // ... 实现
  }

  // 健康检查
  isHealthy() {
    return this._initialized;
  }

  // 优雅关闭
  shutdown() {
    this._initialized = false;
    this.emit('shutdown');
  }
}

MyModule.DEFAULT_CONFIG = {};

module.exports = MyModule;
```

### 2.4 依赖注入模式（Attach模式）

框架核心模块采用Attach模式进行依赖注入，支持链式调用：

```javascript
goalExecutor
  .attachSessionManager(sessionManager)
  .attachPlanPersistence(planPersistence)
  .attachDeepeningOrchestrator(deepeningOrchestrator)
  .attachSubagentExecutor(subagentExecutor)
  .attachThoughtRetrieverCycle(thoughtRetrieverCycle)
  .attachCausalDataBus(causalDataBus);
```

Attach方法规范：
- 方法名以 `attach` 开头，后跟依赖名称
- 返回 `this` 支持链式调用
- 内部验证依赖对象是否具有所需方法
- 依赖缺失时不应抛出异常，而是在使用时优雅降级

### 2.5 事件驱动通信

模块间通过EventEmitter事件实现松耦合通信：

```javascript
// 发射事件
this.emit('goal-completed', { goalId, result, duration });

// 监听事件
goalExecutor.on('goal-completed', (data) => {
  sessionManager.recordAgentAction(sessionId, 'goal-executor', 'goal-completed');
});
```

事件命名规范：
- 格式：`模块名:动作名`（如 `agent:state-change`）
- 动作名使用kebab-case
- 全局事件在 `index.js` 的 `EVENT_FORWARD_MAP` 中注册转发

### 2.6 持久化规范

需要持久化的模块应使用 `DebouncedPersister`：

```javascript
const DebouncedPersister = require('../utils/debounced-persister');

class MyModule extends EventEmitter {
  constructor(projectRoot) {
    super();
    this._persister = new DebouncedPersister(
      path.join(projectRoot, '.harness/my-module/data.json'),
      () => JSON.stringify(this._data),
      { debounceMs: 200 }
    );
  }

  _schedulePersist() {
    this._persister.schedule();
  }

  async flush() {
    await this._persister.flush();
  }

  shutdown() {
    this._persister.shutdown();
  }
}
```

持久化路径规范：
- 数据目录：`.harness/<module-name>/`
- 文件格式：JSON
- 写入策略：防抖（200ms）+ 原子写入（tmp文件 + rename）
- 跨设备回退：rename失败时使用copyFile + unlink

### 3.6 性能优化规范

```javascript
// 1. 避免冗余JSON序列化
// BAD: 三次序列化
const cloned = JSON.parse(JSON.stringify(obj));
const size = JSON.stringify(cloned).length;

// GOOD: 一次序列化，复用结果
const serialized = JSON.stringify(obj);
const size = serialized.length;
const cloned = JSON.parse(serialized);

// 2. 循环外提取不变计算
// BAD: 每次循环都序列化
for (const req of reqs) {
  const resultStr = JSON.stringify(result).toLowerCase();
  if (resultStr.includes(req)) met++;
}

// GOOD: 提取到循环外部
const resultStr = JSON.stringify(result).toLowerCase();
for (const req of reqs) {
  if (resultStr.includes(req)) met++;
}

// 3. 使用Set替代Array.indexOf进行成员检查
// BAD: O(n)查找
const loaded = modules.filter(m => m.loaded).map(m => m.name);
items.map(m => Object.assign({}, m, { loaded: loaded.indexOf(m.name) >= 0 }));

// GOOD: O(1)查找
const loadedSet = new Set(modules.filter(m => m.loaded).map(m => m.name));
items.map(m => Object.assign({}, m, { loaded: loadedSet.has(m.name) }));

// 4. Map键使用字符串拼接替代JSON.stringify
// BAD: JSON序列化作为Map键
const key = JSON.stringify([agentId, action, target]);

// GOOD: 分隔符拼接
const key = agentId + '\0' + action + '\0' + target;

// 5. 命名常量替代魔法数字
// BAD: 硬编码数字
const timeout = config.timeout || 300000;

// GOOD: 命名常量
const DEFAULT_SUBTASK_TIMEOUT_MS = 300000;
const timeout = config.timeout || DEFAULT_SUBTASK_TIMEOUT_MS;

// 6. null安全访问
// BAD: 直接访问可能为null的对象属性
this.port = this.server.address().port;

// GOOD: 先检查null
const addr = this.server.address();
this.port = addr ? addr.port : this.port;
```

## 六、新增编码规范（v2.72.0 安全审计补充）

以下编码模式由安全审计发现，所有新代码必须遵循，已有代码应在重构时逐步修正。

### 6.1 falsy值守卫

使用 `== null` 代替 `!value` 检查可选参数，避免拒绝合法的falsy值（0、""、false）：

```javascript
// 错误：拒绝0、""、false等合法值
if (!task || !result) return false;
// 正确：仅拒绝null/undefined
if (task == null || result == null) return false;
```

### 6.2 限流检查顺序

先检查粗粒度限额（小时），再检查细粒度限额（分钟），避免计数器泄漏：

```javascript
// 正确顺序：先小时后分钟
if (!this._checkHourRate(agentKey)) return false;
if (!this._checkMinuteRate(agentKey, maxPerMinute)) return false;
```

### 6.3 模板插值消毒

用户提供的变量值在插入模板前必须消毒，过滤 `;`、`{`、`}`、`\` 等危险字符。

### 6.4 async调用处理

在同步方法中调用async方法时，必须添加 `.catch()` 处理未捕获的Promise拒绝。

### 6.5 令牌比较编码

SHA-256哈希比较必须使用hex编码而非UTF-8编码：

```javascript
// 错误：UTF-8编码hex字符串产生64字节
Buffer.from(tokenHash, 'utf8')
// 正确：hex编码产生32字节
Buffer.from(tokenHash, 'hex')
```

### 6.6 持久化重试上限

所有重试机制必须设置最大重试次数，防止无限重试。

### 6.7 setInterval unref()

所有非关键定时器必须调用 `.unref()` 防止阻止进程退出。

### 6.8 RGB值钳制

解析颜色时必须将RGB分量钳制到0-255范围。

### 6.9 零阈值处理

除法运算中阈值为0时应视为"无约束"（返回满分1），而非产生Infinity。

### 6.10 eval检测绕过

剥离注释和字符串时必须保留模板表达式 `${...}` 内容，防止eval检测绕过。

### 9.1 Agent文件结构

```markdown
---
role: my-agent
level: task
skills:
  - skill-1
  - skill-2
auto_route: true
tdd_enforced: true
collaborates_with:
  - domain-analyst
model: standard
permissions:
  allowed_tools:
    - read_file
    - write_file
    - search
  restricted:
    - file_delete
    - system_command
---

# Agent指令

## 角色描述
...

## 工作流程
...
```

### 9.2 Agent注册

将Agent文件放入 `.harness/agents/` 目录即可自动发现。RBACEnforcer会在load()时扫描该目录。

## 十二、验证命令参考

| 命令 | 说明 |
|------|------|
| `npm test` | 运行全部测试（test/**/*.test.js） |
| `npm run test:runtime` | 运行运行时核心测试 |
| `npm run test:deepening` | 运行深化推理测试 |
| `npm run test:gate` | 运行TDD门禁测试 |
| `npm run test:permission` | 运行权限控制测试 |
| `npm run test:hook` | 运行钩子执行器测试 |
| `npm run test:design` | 运行设计技能测试 |
| `npm run test:integration` | 运行集成测试+Web测试 |
| `npm run test:web` | 运行Web服务测试 |
| `npm run test:utils` | 运行工具模块测试 |
| `npm run validate` | 框架一致性检查 + 测试 |
| `npx eslint src/` | ESLint代码质量检查 |
| `node scripts/verify-api-docs.js` | API文档与代码同步验证 |
| `node harness-cli.js validate` | CLI快速验证 |
| `node harness-cli.js commands` | 列出所有斜杠命令 |
| `node harness-cli.js skills` | 列出所有技能及验证状态 |
| `node harness-cli.js memory-verify` | 验证记忆-代码一致性 |
| `node harness-cli.js antipattern-detect` | 运行反模式检测 |
