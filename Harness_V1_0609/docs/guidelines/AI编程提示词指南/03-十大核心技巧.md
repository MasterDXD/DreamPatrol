## 技巧1：角色提示（Role Prompting）

赋予AI特定专业角色，激活其特定知识域，获得更专业的输出。

**模板：**
```
你是一位资深的{语言/领域}开发者/专家。请为了{某个目标}来{执行任务}。
```

**示例：**
```
你是一位资深的Go语言开发者，专精于微服务架构。请审查这个HTTP中间件函数，
关注并发安全、性能瓶颈和错误处理。
```

**为什么有效：** 角色一旦固定，AI的语言风格与行动逻辑都会稳定很多。架构师写的代码 vs 初学者写的代码，质量天差地别。

**Claude官方强化：角色必须绑定场景**

仅指定角色不够——必须同时说明"在什么场景下干什么事"，如同给模型穿上"职业装"：

- ❌ "你是一位资深开发者"（太泛，AI不知道该用什么知识域）
- ✅ "你是一位资深Node.js开发者，在微服务架构项目中审查HTTP中间件的并发安全性"（角色+场景+任务三合一）

角色一旦绑定场景，AI的语言风格、知识域和行动逻辑都会稳定收敛。

**进阶：指定思维模型而非仅仅指定角色**

"扮演一个营销专家"太泛了。限定思维框架能得到更专业的回答：

- "请利用查理·芒格的'逆向思维'模型来分析这个商业计划的失败原因。"
- "请像史蒂夫·乔布斯在发布会演讲那样，介绍这个功能。"
- "请用SWOT-PESTEL复合框架分析新能源汽车行业。"

## 技巧2：明确上下文（Explicit Context Setup）

清晰框定问题，避免AI给出泛泛而谈、流于表面的回答。

**模板：**
```
问题是：{问题摘要}。代码如下。它本应{预期行为}，但现在却{实际行为}。这是为什么？
```

**示例：**
```
问题是：用户注册接口返回500错误。代码如下。它本应创建用户并返回201，
但现在却抛出TypeError: Cannot read property 'hash' of undefined。
这是为什么？
```

**为什么有效：** 提供了完整的"预期 vs 实际"对比，AI可以直接定位问题根源而非猜测。

**Anthropic官方建议：告诉AI"为什么"**

解释约束背后的原因，AI理解后表现更好：

- ❌ "NEVER use bullet points"
- ✅ "我偏好段落形式因为更易阅读和对话，bullet points太正式了"

## 技巧3：输入/输出示例（Few-Shot Prompting）

通过具体示例展示意图，引导AI准确理解需求。研究表明，3-5个高质量示例可使任务理解准确率突破90%。

**模板：**
```
当输入为{某个输入}时，这个函数应该返回{预期输出}。你能编写或修复这段代码吗？
```

**基础版：**
```
请根据以下示例对工单分类：
工单："无法重置密码" → 类别：账户访问
工单："上传文件时崩溃" → 类别：错误报告
工单："想升级到专业版" → 类别：销售咨询

现在请分类："APP闪退频繁"
```

**进阶版（包含思维过程的示例）：**
```
任务：判断评论情感。

示例1：
评论："书是破的，物流还慢。"
思考：用户提到产品质量差（破）和物流差（慢），整体情绪为负面。
标签：差评

示例2：
评论："价格实惠，质量也不错。"
思考：用户对价格和质量都表示肯定，整体情绪为正面。
标签：好评

现在请分析："包装一般，但东西还行"
```

**Claude官方强化：一个完美案例胜过千言万语**

Claude官方明确指出：将以前处理得非常完美的案例塞进提示词，效果比写一大堆文字好得多。这是因为：
- 案例提供了完整的"输入→思考→输出"链路，AI可以直接模式匹配
- 文字描述需要AI自行翻译成行动规则，存在理解偏差
- 实操建议：优先用1个完美案例替代3条规则描述，再用文字补充案例未覆盖的边缘情况

**关键原则：**
- 示例越相似，模型越准确
- 示例格式必须统一
- 包含"多样性+典型性"——既要有常规案例，也要包含边缘情况
- 2-3个示例为最优，超过3个收益递减（AI Wiki研究结论）
- 示例应展示完整模式（包括错误处理、日志、边缘情况），而非仅展示正常路径

## 技巧4：迭代式链条（Iterative Chaining）

将复杂大任务分解成连续的小步骤，避免因提示过于庞大或含糊而导致AI混乱。

**模板：**
```
第一步，生成组件的骨架代码。
下一步，我们来添加状态管理。
最后，处理API调用。
```

**示例：**
```
让我们分阶段实现认证系统：
1. 首先，搭建基础JWT认证（登录/注册）
2. 然后，添加刷新令牌轮换
3. 接下来，实现邮件密码重置
4. 然后，添加邮箱验证
5. 添加OAuth提供商（Google、GitHub）
6. 最后，实现2FA和RBAC
```

**为什么有效：** 每次迭代基于上一次输出，你可以在早期发现问题并引导AI朝正确方向前进。Builder.io称之为"Prompt → Review → Refine"循环。

**迭代节奏：**

```
初始脚手架 → 添加行为逻辑 → 处理边缘情况 → 性能优化 → 代码审查
     ↑                                              |
     └──────────── 发现问题则回退 ────────────────────┘
```

## 技巧5：模拟调试（Debug with Simulation）

让AI模拟代码的运行时行为，帮助发现隐藏很深的bug。

**模板：**
```
请逐行过一遍这个函数。每个变量的值是什么？代码最有可能在哪里出错？
```

**示例：**
```
请逐行模拟以下递归函数的执行过程，假设输入为 n=5。
每一步记录变量值和调用栈状态。代码最有可能在哪里出错？

function fibonacci(n) {
  if (n <= 1) return n;
  return fibonacci(n - 1) + fibonacci(n - 2);
}
```

**进阶：小黄鸭调试法（Rubber Ducking）**

```
我是这样理解这个函数功能的：它先检查缓存，如果命中就返回缓存值，
否则查询数据库并写入缓存。我有什么遗漏吗？这个解释能暴露出什么bug吗？
```

## 技巧6：功能蓝图（Feature Blueprinting）

借助AI主导的规划和脚手架能力，高效启动新功能的开发。

**模板：**
```
我正在构建{某个功能}。需求是：{几点核心需求}。技术栈是：{所用技术}。
请搭建出初始组件的脚手架，并解释你的选择。
```

**示例：**
```
我正在构建一个实时通知系统。需求是：
1. 支持WebSocket长连接
2. 消息持久化到数据库
3. 支持消息已读/未读状态
4. 支持离线消息推送

技术栈是：Node.js + Socket.io + PostgreSQL + Redis。
请搭建出初始组件的脚手架，并解释你的架构选择。
```

## 技巧7：重构指导（Code Refactor Guidance）

确保AI的代码重构与你的核心目标对齐，而不是进行随意的、不必要的修改。

**模板：**
```
请重构这段代码以提升{某个目标}，例如{可读性、性能、代码风格等}。
请用注释来解释你做了哪些更改。
```

**示例：**
```
请重构这个UserService类以提升可读性和可测试性：
1. 将大方法拆分为单一职责的小方法
2. 依赖注入替代硬编码
3. 改进变量命名
4. 保持逻辑不变
重构后，解释每处更改的原因。
```

**关键原则：** "保持逻辑不变"是最重要的约束——没有这句话，AI可能"自作聪明"地改变行为逻辑。

## 技巧8：约束锚定（Constraint Anchoring）

给AI设定明确的边界和限制，防止它"自由发挥"过度。

**模板：**
```
请避免使用{例如：递归}，并严格遵守{例如：ES6语法，不使用外部库}。
请为{例如：内存占用}进行优化。函数如下：
```

**示例：**
```
请避免使用递归，严格遵守ES6语法，不引入任何外部库。
请为内存占用进行优化，目标是在处理100万条数据时内存不超过50MB。
函数如下：
[paste code]
```

**为什么有效：** 约束反而改善AI输出——开放请求给AI太多选择，导致通用解决方案；有边界的约束产生聚焦的、可用的代码。

**常用约束清单：**

| 约束类型 | 示例 |
|---------|------|
| 语言/语法 | "使用ES6+语法"、"使用async/await而非回调" |
| 库/框架 | "不引入新的外部依赖"、"仅使用项目已有的lodash" |
| 性能 | "内存占用<50MB"、"响应时间<100ms" |
| 安全 | "不暴露密码哈希"、"输入必须消毒" |
| 风格 | "遵循现有代码风格"、"使用我们的Button组件" |
| 范围 | "只修改这个函数"、"不要改动其他文件" |

## 技巧9：思维链（Chain of Thought, CoT）

强制AI"慢思考"，在生成代码前先展示推理过程。OpenAI GSM8K测试显示，采用思维链的解题正确率达72.5%，远超直接回答的33.9%。

**模板：**
```
让我们一步步思考（Let's think step by step）。
```

**示例：**
```
请设计一个分布式限流算法。在写代码之前：
1. 先分析常见的限流策略（令牌桶、漏桶、滑动窗口）
2. 比较各策略在分布式场景下的优劣
3. 选择最适合的策略并解释原因
4. 列出需要考虑的边缘情况
5. 最后再写代码实现
```

**CoT的三种变体：**

| 变体 | 方法 | 适用场景 |
|------|------|---------|
| Zero-Shot CoT | 在提示末尾加"让我们一步步思考" | 简单推理任务 |
| Few-Shot CoT | 提供包含推理步骤的示例 | 格式/逻辑有明确要求 |
| Self-Consistency | 生成多个推理路径，选最常见答案 | 高可靠性要求的决策 |

**Claude官方强化：把人类思维过程写进提示词**

Claude官方建议：不要只说"让我们一步步思考"，而是把人类的完整思维过程写进提示词，告诉AI具体的思考步骤。这比泛化的CoT触发词准确率更高：

- ❌ "让我们一步步思考"（泛化，AI可能走偏）
- ✅ "请按以下顺序思考：1)理解需求的核心目标 2)识别所有约束条件 3)列出可能的方案 4)评估每个方案的风险 5)选择最优方案并解释原因 6)编写代码实现"（结构化思考模板）

结构化思考模板让AI的推理路径与人类专家对齐，准确率直线飙升。

## 技巧10：翻转提问（Flipped Interaction）

让AI先向你提问以收集必要信息，再给出方案。这是获取高质量定制方案的最强技巧。

**模板：**
```
我想实现{某个功能}。在你提供方案之前，请先问我3-5个问题，
以确保你完全理解我的需求。
```

**示例：**
```
我想实现一个文件上传功能。在你提供实现方案之前，
请先问我3-5个关键问题，以确保方案完全匹配我的需求。
```

**AI可能会问的问题示例：**
- 支持哪些文件类型？有大小限制吗？
- 需要断点续传吗？
- 文件存储在哪里？（本地/S3/OSS）
- 需要文件预览功能吗？
- 并发上传数量有限制吗？

## 关键要点

1. **角色提示是最基础的技巧**——几乎所有好提示都从角色开始
2. **约束锚定是解决最多问题的单一技巧**——Top 20排行榜中6个问题可用它解决
3. **思维链是复杂任务的利器**——准确率从33.9%提升到72.5%
4. **翻转提问适合需求不明确的场景**——让AI主动收集信息
5. **十大技巧可组合使用**——角色+约束+思维链是最强组合
