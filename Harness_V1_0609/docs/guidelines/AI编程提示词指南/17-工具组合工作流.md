# 工具组合工作流

> 来源：Claude高效使用沉淀开源项目。将多个提示词串联为自动化工作流，实现"单次提示→工具链"的升级。

## 概述

传统提示词工程是"一问一答"模式，但实际工作中许多任务需要多步骤、多格式的协同处理。工具组合工作流将多个提示词模板串联为端到端的自动化流程，大幅提升效率。

## 四大核心工具组合

### 1. Claude Code 优化器

**用途**：输入粗糙代码，自动优化结构、补全注释、修复BUG，同时生成代码说明文档。

**工作流步骤**：

```
步骤1：代码审查提示词
[Role] 资深代码审查员
[Goal] 识别代码中的质量问题、潜在BUG和性能瓶颈
[Input] 原始代码
[Process] 检查：命名规范/函数长度/错误处理/性能/安全性/可测试性
[Output] 问题清单（按严重度排序），每个问题附位置和修复建议

步骤2：代码优化提示词
[Role] 资深重构工程师
[Goal] 根据审查结果优化代码
[Input] 原始代码 + 问题清单
[Process] 按严重度从高到低修复；每个修复保持逻辑不变；添加必要注释
[Output] 优化后的完整代码 + 修改说明

步骤3：文档生成提示词
[Role] 技术文档工程师
[Goal] 为优化后的代码生成说明文档
[Input] 优化后的代码 + 修改说明
[Process] 包含：功能概述/接口说明/使用示例/注意事项
[Output] Markdown格式代码说明文档
```

**与项目集成**：可映射到 `code-review` → `refactor-code` → `documentation` 技能链。

### 2. 多模态内容转换器

**用途**：支持"文本→PPT大纲→短视频脚本→公众号文章"跨格式转换，保持核心逻辑一致。

**工作流步骤**：

```
步骤1：核心内容提取
[Role] 内容架构师
[Goal] 从源内容中提取核心逻辑、关键论点和数据支撑
[Input] 原始内容（任意格式）
[Process] 提取：核心论点(≤3个)/支撑数据/目标受众/调性要求
[Output] 结构化内容大纲（JSON格式）

步骤2：目标格式适配
[Role] {目标格式}专业策划
[Goal] 将内容大纲转换为目标格式
[Input] 结构化内容大纲 + 目标格式规范
[Process] 适配格式特点；保持核心逻辑不变；优化呈现方式
[Output] 目标格式内容

步骤3：质量校验
[Role] 内容质量审核员
[Goal] 确保转换后内容的核心逻辑与原始一致
[Input] 原始内容 + 转换后内容
[Process] 逐条比对核心论点；检查数据准确性；评估可读性
[Output] 校验报告 + 修正建议
```

**与项目集成**：可映射到 `ai-prompting` 技能的多步骤执行模式。

### 3. 会议纪要智能提炼器

**用途**：上传会议录音转写文本，自动提取决策点、待办事项、责任人、截止时间。

**工作流步骤**：

```
步骤1：信息提取
[Role] 会议记录专家
[Goal] 从转写文本中提取结构化信息
[Input] 会议转写文本
[Process] 识别：决策点/待办事项/责任人/截止时间/风险点/下次会议安排
[Output] 结构化提取结果（JSON格式）

步骤2：格式化输出
[Role] 行政效率专家
[Goal] 将提取结果转化为可直接同步的表格化纪要
[Input] 结构化提取结果
[Process] 按部门/项目分组待办；标注优先级；添加跟进提醒
[Output] Markdown表格格式纪要

步骤3：行动项追踪
[Role] 项目管理助手
[Goal] 生成可追踪的行动项清单
[Input] 表格化纪要
[Process] 为每个待办生成唯一ID；关联责任人和截止时间；设置状态追踪
[Output] 行动项追踪表（含ID/内容/责任人/截止时间/状态）
```

**与项目集成**：可映射到 `brainstorming` → `requirement-analysis` 技能链的辅助工具。

### 4. 竞品分析自动化工具

**用途**：输入竞品名称/链接，自动抓取核心功能、定价策略、用户评价，输出SWOT分析+差异化建议。

**工作流步骤**：

```
步骤1：信息收集
[Role] 市场研究分析师
[Goal] 系统化收集竞品关键信息
[Input] 竞品名称/链接列表
[Process] 收集：核心功能/定价策略/用户评价/技术架构/市场份额/近期动态
[Output] 结构化竞品信息表

步骤2：SWOT分析
[Role] 战略分析顾问
[Goal] 基于收集信息生成SWOT分析
[Input] 竞品信息表 + 自身产品信息
[Process] 分析：优势/劣势/机会/威胁；量化评估各维度；识别关键差异点
[Output] SWOT矩阵 + 关键发现

步骤3：差异化建议
[Role] 产品策略顾问
[Goal] 提出可落地的差异化竞争策略
[Input] SWOT分析 + 关键发现
[Process] 基于"可落地性×影响力"矩阵排序建议；预估实施成本和预期效果
[Output] 差异化策略清单（含优先级/成本/预期效果）
```

**与项目集成**：可映射到 `domain-analyst` Agent的 `brainstorming` → `architecture-design` 技能链。

## 工具组合设计原则

1. **三步法则**：每个工具组合遵循"提取→转换→校验"三步流程
2. **格式中立**：核心内容以JSON结构化表示，与具体输出格式解耦
3. **可组合**：工具组合之间可串联（如竞品分析→多模态转换→会议纪要）
4. **可回滚**：每个步骤独立输出，任一步骤失败不影响前序步骤结果

## 与Harness技能体系的映射

| 工具组合 | 映射技能链 | 适用Agent |
|---------|-----------|----------|
| Code优化器 | code-review → refactor-code → documentation | Analyst, Worker |
| 多模态转换器 | ai-prompting（多步骤模式） | Worker, Analyst |
| 会议纪要提炼器 | brainstorming → requirement-analysis | Lead, Analyst |
| 竞品分析工具 | brainstorming → architecture-design | Analyst |

## 反模式警告

| 反模式 | 说明 | 正确做法 |
|--------|------|---------|
| 一步到位 | 试图用单个提示词完成整个工作流 | 拆分为独立步骤，每步专注一个目标 |
| 无校验环节 | 跳过质量校验直接输出 | 始终包含校验步骤，确保转换一致性 |
| 格式耦合 | 提示词硬编码特定输出格式 | 使用JSON中间格式，最后一步适配目标格式 |
| 忽略上下文 | 每步独立执行不传递上下文 | 每步输入包含前序步骤的输出摘要 |
