# 模块07：上下文工程——比提示词更重要的事

> 所属层级：工程层 | 前置模块：[01-核心原则](01-核心原则.md) | 后续模块：[08-模型参数调优](08-模型参数调优.md)

---

> Anthropic 2025年提出：**Context Engineering（上下文工程）** 已成为与LLM协作中越来越重要的部分，提示词工程是其基础构建块。

---

## 7.1 上下文工程 vs 提示词工程

| 维度 | 提示词工程 | 上下文工程 |
|------|-----------|-----------|
| 关注点 | 如何写好单条指令 | 如何组织整个信息环境 |
| 范围 | 单次交互 | 完整工作流 |
| 核心问题 | "怎么问" | "给AI什么信息" |
| 包含内容 | 指令文本 | 指令+代码库+文档+历史+工具+配置 |

---

## 7.2 上下文提供的四个层次

```
┌─────────────────────────────────────────┐
│  Layer 4: 项目级上下文                    │  ← .cursorrules / CLAUDE.md
│  （编码规范、架构约定、团队偏好）            │
├─────────────────────────────────────────┤
│  Layer 3: 会话级上下文                    │  ← 对话历史
│  （之前的交互记录、已做出的决策）            │
├─────────────────────────────────────────┤
│  Layer 2: 任务级上下文                    │  ← @file / 代码片段
│  （相关文件、依赖关系、现有模式）            │
├─────────────────────────────────────────┤
│  Layer 1: 指令级上下文                    │  ← 当前提示词
│  （具体任务、约束、输出要求）               │
└─────────────────────────────────────────┘
```

---

## 7.3 上下文提供最佳实践

| 做法 | 示例 | 效果 |
|------|------|------|
| 引用具体文件 | "遵循 src/services/UserService.ts 的模式" | AI复用现有模式 |
| 提供相关代码片段 | 在提示中粘贴相关函数 | AI理解上下文 |
| 说明技术栈版本 | "Next.js 14 with App Router" | 避免版本不兼容 |
| 引用设计系统 | "使用我们的Card组件和design tokens" | 保持UI一致性 |
| 描述数据流 | "数据从API→Redux Store→Component" | AI理解架构 |
| 提供错误日志 | 粘贴完整的stack trace | 精准定位问题 |

---

## 关键要点

1. **上下文工程 > 提示词工程**——组织信息环境比写好单条指令更重要
2. **四层上下文模型**——项目级→会话级→任务级→指令级
3. **项目级配置是最高ROI的优化**——一次配置，每次对话自动生效
4. **引用具体文件是最有效的上下文提供方式**——比描述更准确
