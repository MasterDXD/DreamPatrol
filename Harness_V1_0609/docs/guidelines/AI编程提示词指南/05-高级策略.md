## 5.1 密度链（Chain of Density）

解决AI生成内容"车轱辘话多"或"空洞"的问题。

```
请为这篇文章写一段摘要。

接下来，请重写这段摘要3次。每次重写时，请找出原文中遗漏的1-2个重要实体
（人名、地点、概念），并将它们融合进摘要中，但不要增加摘要的总字数。
```

## 5.2 退步提示（Step-Back Prompting）

先让AI思考抽象原则，再解决具体问题。

```
首先思考：好的产品需求文档应包含哪些要素？
基于这些要素，为"智能家居语音控制系统"编写需求文档。
```

**编程场景示例：**
```
首先思考：设计一个高可用的缓存系统需要考虑哪些核心原则？
基于这些原则，为我们的电商商品详情页设计一个多级缓存方案。
```

## 5.3 情感提示（Emotional Prompting）

研究表明LLM对某些情感暗示有反应（可能与训练数据中高质量语料伴随严肃语境有关）：

| 情感提示 | 效果 | 适用场景 |
|---------|------|---------|
| "深呼吸，一步一步慢慢来。" | 显著提高逻辑题准确率 | 复杂推理任务 |
| "这对我职业生涯非常重要，请务必准确。" | 提高输出认真程度 | 关键代码生成 |
| "如果你做得好，我会给你$200的小费。" | 通常换来更详细的回答 | 需要深度分析 |
| "这个功能会影响数万用户，请确保安全。" | 增强安全意识 | 安全相关代码 |

## 5.4 使用XML标签结构化输入

Anthropic官方推荐使用XML标签来组织提示词的不同部分：

```xml
<instructions>
  请分析以下代码的性能瓶颈
</instructions>

<code>
  {粘贴代码}
</code>

<constraints>
  - 仅关注时间复杂度问题
  - 不考虑代码风格
  - 给出具体的优化数值预估
</constraints>

<output_format>
  以Markdown表格输出，包含列：[问题位置, 当前复杂度, 优化后复杂度, 优化方案]
</output_format>
```

**为什么XML标签有效：**
- 明确分隔指令与数据，防止混淆
- 有效防止提示词注入攻击
- 模型能更准确地定位各部分内容
- 支持嵌套结构，适合复杂任务

## 5.5 认知脚手架（Cognitive Scaffolding）

通过提供问题分析框架引导AI系统思考：

```
请用以下框架分析代码重构方案：
1. 当前问题（What）- 现状是什么
2. 根本原因（Why）- 为什么会这样
3. 解决方案（How）- 怎么解决
4. 风险评估（Risk）- 有什么风险
5. 验证方法（Verify）- 如何验证方案有效
```

**常用思维框架：**

| 框架 | 适用场景 | 结构 |
|------|---------|------|
| 5W1H | 问题分析 | What/Why/Who/When/Where/How |
| SWOT | 技术选型 | 优势/劣势/机会/威胁 |
| 第一性原理 | 架构设计 | 拆解到最基本事实→重新构建 |
| 逆向思维 | 风险评估 | 想象失败→反推原因→预防 |
| MECE | 需求拆解 | 互斥且完全穷举 |

## 5.6 自我一致性（Self-Consistency）

生成多个推理路径，选择最常见答案，提高可靠性：

```
请用3种不同的方法解决这个问题，然后选择最可靠的方案并解释原因：

问题：设计一个防止超卖的商品库存扣减方案

方法1：...
方法2：...
方法3：...

最可靠方案：___，理由：___
```

---

## 5.7 思维树（Tree of Thoughts）

并行探索多个解决方案路径，适合开放式问题：

```
请为以下问题生成3个不同的解决方案分支，每个分支评估可行性和风险，
然后选择最优路径深入展开：

问题：如何将现有的单体应用拆分为微服务？
```

---

## 关键要点

1. **密度链解决"空洞输出"**——递归压缩信息密度
2. **退步提示解决"缺乏深度"**——先想原则再想方案
3. **XML标签是Claude的最佳实践**——结构化输入的标准方式
4. **认知脚手架提供思考框架**——比单纯角色提示更深入
5. **自我一致性和思维树适合高可靠性场景**——多路径探索+选择
