## 14.1 提示词质量评估维度

| 维度 | 评估标准 | 权重 |
|------|---------|------|
| **准确性** | 生成的代码是否正确实现了需求 | 30% |
| **完整性** | 是否覆盖所有功能点和边缘情况 | 20% |
| **可运行性** | 代码能否直接编译/运行 | 20% |
| **一致性** | 是否遵循项目现有模式和风格 | 15% |
| **效率** | 是否有明显的性能问题 | 10% |
| **安全性** | 是否存在安全隐患 | 5% |

## 14.2 迭代优化流程

```
┌──────────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐
│  编写提示  │───→│  评估输出  │───→│  识别差距  │───→│  优化提示  │
│  v1      │    │  准确性?  │    │  哪里不好? │    │  v2      │
└──────────┘    └──────────┘    └──────────┘    └──────────┘
                                                     │
                    ┌──────────┐    ┌──────────┐      │
                    │  确认定版  │←───│  再次评估  │←─────┘
                    │  写入知识库│    │  满意了吗? │
                    └──────────┘    └──────────┘
```

---

## 14.3 A/B测试方法

```
同一任务，使用两个不同提示词版本，对比输出质量：

版本A："写一个排序函数"
版本B："写一个Python快速排序函数，接收List[int]，返回排序后的List[int]，
       包含类型注解，处理空列表和单元素列表"

评估维度：准确性 / 完整性 / 可运行性 / 代码质量
胜出者：版本B（所有维度均优于A）
优化方向：继续增加约束和上下文
```

---

## 14.4 提示词版本管理

| 版本 | 变更内容 | 效果 |
|------|---------|------|
| v1 | 基础提示 | 输出不可运行 |
| v2 | +技术栈约束 | 可运行但风格不一致 |
| v3 | +代码风格引用 | 风格一致但缺少边缘处理 |
| v4 | +边缘情况要求 | 完整可用的输出 ✅ |

---

## 14.5 提示词知识库

建议为团队建立提示词知识库，记录：

- **场景**：什么任务
- **提示词**：完整提示词文本
- **效果**：输出质量评分
- **注意事项**：什么情况下不适用
- **版本历史**：迭代记录

---

## 关键要点

1. **六维评估体系**——准确性权重最高（30%）
2. **迭代是提示词优化的核心**——v1→v2→v3→v4逐步完善
3. **A/B测试是科学优化方法**——对比而非猜测
4. **知识库是团队资产**——记录成功提示词，避免重复探索
