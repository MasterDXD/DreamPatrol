## 11.2 .cursorrules 最佳实践

```markdown
# 项目规则

## 技术栈
- 前端：React 18 + TypeScript 5 + Tailwind CSS 3
- 后端：Node.js 20 + Express + TypeORM
- 数据库：PostgreSQL 15 + Redis 7

## 编码规范
- 使用函数式组件和hooks，不使用类组件
- 使用async/await，不使用回调
- 所有函数必须有TypeScript类型注解
- 变量命名使用camelCase，常量使用UPPER_SNAKE_CASE
- 文件命名使用kebab-case

## 约束
- 不要引入新的外部依赖，除非我明确要求
- 不要使用any类型
- 不要生成TODO占位符，必须完整实现
- 遵循现有代码风格和目录结构
- 所有API端点必须有错误处理和输入验证

## 测试
- 使用Jest + React Testing Library
- 新功能必须包含单元测试
- 测试覆盖率目标：80%+
```

---

## 11.3 CLAUDE.md 最佳实践

```markdown
# 项目指南

## 架构
- 本项目采用Clean Architecture，分层为：domain/application/infrastructure/presentation
- 依赖方向：presentation → application → domain ← infrastructure

## 关键文件
- src/domain/entities/ — 领域实体
- src/application/usecases/ — 业务用例
- src/infrastructure/repositories/ — 数据访问
- src/presentation/controllers/ — API控制器

## 约定
- 修改domain层时，确保不引入外部依赖
- 新增API端点时，同步更新OpenAPI spec
- 数据库迁移文件放在 src/infrastructure/migrations/
```

---

## 关键要点

1. **项目级配置是最高ROI的优化**——一次配置，每次对话自动生效
2. **.cursorrules和CLAUDE.md是最重要的两个配置文件**
3. **配置内容应包含：技术栈+编码规范+约束+测试要求**
4. **架构约定和关键文件路径帮助AI理解项目结构**
