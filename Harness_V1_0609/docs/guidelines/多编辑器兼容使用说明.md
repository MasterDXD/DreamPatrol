# 多编辑器兼容使用说明

## 一、概述

Harness Engineering 多Agent框架已适配5款主流AI编辑器，核心框架规则完全一致，仅入口文件格式和位置不同。无论你使用哪款编辑器，都能获得相同的28-Agent、84-Skill、6阶段流程、16规则的完整框架能力。

### 适配编辑器一览

| 编辑器 | 入口文件 | 规则格式 | Agent切换 | Skill加载 | @include支持 |
|--------|---------|---------|----------|----------|-------------|
| **Claude Code** | `CLAUDE.md` | Markdown | ✅ 完整 | ✅ 完整 | ✅ 原生支持 |
| **Trae** | `.trae/rules/project_rules.md` | Markdown | ✅ 完整 | ✅ 完整 | ❌ 需手动引用 |
| **Cursor** | `.cursor/rules/harness-engineering.mdc` | MDC+Frontmatter | ✅ 完整 | ✅ 完整 | ❌ 需手动引用 |
| **GitHub Copilot** | `.github/copilot-instructions.md` | Markdown | ✅ 完整 | ✅ 完整 | ❌ 需手动引用 |
| **Windsurf** | `.windsurfrules` | Markdown | ✅ 完整 | ✅ 完整 | ❌ 需手动引用 |

## 二、各编辑器使用指南

### 2.1 Claude Code

**入口文件**：项目根目录 `CLAUDE.md`

**特点**：
- 原生支持 `@include` 指令，可自动加载 `.harness/` 下所有Agent和规则文件
- 文件内已内联完整框架规则，同时保留 `@include` 用于深度引用
- 无需额外配置，打开项目即自动生效

**使用步骤**：
1. 将框架文件复制到项目根目录
2. 用 Claude Code 打开项目
3. `CLAUDE.md` 自动被识别为项目规则
4. 在对话中直接使用框架指令

**示例指令**：
```
请作为Team Lead，阅读 requirements.md，按照六阶段执行流程启动项目开发。
```

**高级用法**：
- `@include` 指令会自动展开引用文件的内容
- 可在 `CLAUDE.md` 中添加项目特定的补充规则
- 修改 `.harness/` 下的文件后，Claude Code 会自动读取最新内容

---

### 2.2 Trae 编辑器

**入口文件**：`.trae/rules/project_rules.md`

**特点**：
- Trae 编辑器自动识别 `.trae/rules/` 目录下的规则文件
- 规则文件包含完整的框架规则（Agent体系、执行流程、全局规则、Skill参考）
- 支持在规则中引用 `.harness/skills/` 下的Skill文件

**使用步骤**：
1. 将框架文件复制到项目根目录
2. 用 Trae 编辑器打开项目
3. 编辑器自动加载 `.trae/rules/project_rules.md`
4. 在 AI 对话中使用框架指令

**示例指令**：
```
请作为Team Lead，按照 requirement-analysis Skill 分析项目需求
```

**注意事项**：
- Trae 不支持 `@include`，所有规则已在 `project_rules.md` 中内联
- 如需修改规则，直接编辑 `.trae/rules/project_rules.md`
- Skill文件仍位于 `.harness/skills/` 目录，AI可按需读取

---

### 2.3 Cursor 编辑器

**入口文件**：`.cursor/rules/harness-engineering.mdc`

**特点**：
- 使用 MDC 格式（Markdown + YAML Frontmatter）
- Frontmatter 中 `alwaysApply: true` 确保规则始终生效
- 支持按文件类型（globs）条件触发规则

**使用步骤**：
1. 将框架文件复制到项目根目录
2. 用 Cursor 编辑器打开项目
3. Cursor 自动识别 `.cursor/rules/` 目录
4. 在 Chat 或 Composer 中使用框架指令

**MDC Frontmatter 说明**：
```yaml
---
description: Harness Engineering 多Agent框架核心规则
globs:              # 留空表示所有文件类型都触发
alwaysApply: true   # 始终生效，不依赖文件匹配
---
```

**按文件类型触发规则（可选）**：
```yaml
---
description: Python模块开发规则
globs: ["**/*.py"]  # 仅在编辑Python文件时触发
alwaysApply: false
---
```

**示例指令**：
```
请作为Task Worker，按照 module-development Skill 开发用户认证模块
```

**注意事项**：
- 可在 `.cursor/rules/` 下创建多个 `.mdc` 文件，按需组织规则
- 如需按文件类型精细控制，拆分规则到不同 `.mdc` 文件并设置不同的 globs
- Cursor 也支持旧版 `.cursorrules` 文件（已弃用，建议使用新格式）

---

### 2.4 GitHub Copilot

**入口文件**：`.github/copilot-instructions.md`

**特点**：
- GitHub Copilot 在 VS Code 中自动识别此文件作为自定义指令
- 规则应用于 Copilot Chat 和代码补全建议
- 适合团队协作，规则随代码仓库版本控制

**使用步骤**：
1. 将框架文件复制到项目根目录
2. 确保 `.github/` 目录已创建
3. 用 VS Code + GitHub Copilot 扩展打开项目
4. Copilot 自动加载 `copilot-instructions.md`
5. 在 Copilot Chat 中使用框架指令

**示例指令**：
```
@workspace 请作为Domain Analyst，按照 architecture-design Skill 设计系统架构
```

**注意事项**：
- Copilot 的指令文件大小建议不超过 2000 行
- 当前文件已包含完整框架规则，无需额外配置
- 团队成员克隆仓库后即可获得相同的框架规则
- 可结合 `.github/CODEOWNERS` 管理规则文件的修改权限

---

### 2.5 Windsurf 编辑器

**入口文件**：`.windsurfrules`（项目根目录）

**特点**：
- Windsurf（原 Codeium）编辑器自动识别项目根目录的 `.windsurfrules` 文件
- 纯 Markdown 格式，无需 Frontmatter
- Cascade AI 助手自动应用规则

**使用步骤**：
1. 将框架文件复制到项目根目录
2. 用 Windsurf 编辑器打开项目
3. 编辑器自动加载 `.windsurfrules`
4. 在 Cascade 对话中使用框架指令

**示例指令**：
```
请作为QA，按照 integration-testing Skill 执行集成测试
```

**注意事项**：
- `.windsurfrules` 文件名固定，不可更改
- 修改规则后可能需要重新打开项目或重启 Cascade 对话
- Windsurf 也支持用户级全局规则（位于用户配置目录）

## 四、跨编辑器迁移指南

### 4.1 从一个编辑器迁移到另一个

框架的核心内容（`.harness/` 目录）在所有编辑器间完全通用，迁移只需确保对应的入口文件存在：

```
迁移检查清单：
☑ .harness/ 目录完整（agents/ + rules/ + skills/ + workspace/ + config.json）
☑ 目标编辑器的入口文件已创建
☑ requirements.md 已填写
☑ docs/ 目录结构完整
```

### 4.2 同时使用多个编辑器

框架支持同时配置多个编辑器的入口文件，它们互不干扰：

```
project-root/
├── CLAUDE.md                          # Claude Code 入口
├── .trae/rules/project_rules.md       # Trae 入口
├── .cursor/rules/harness-engineering.mdc  # Cursor 入口
├── .github/copilot-instructions.md    # Copilot 入口
├── .windsurfrules                     # Windsurf 入口
└── .harness/                          # 共享核心框架
```

**注意事项**：
- 所有入口文件引用同一个 `.harness/` 核心目录
- 修改 `.harness/` 下的文件对所有编辑器生效
- 各入口文件的内容保持同步（修改框架规则时需同步更新所有入口文件）

### 4.3 规则同步策略

当修改框架规则时，需同步更新所有入口文件：

| 修改位置 | 需同步更新的文件 |
|---------|----------------|
| `.harness/agents/*.md` | CLAUDE.md（自动@include）、其他4个入口文件（手动同步摘要） |
| `.harness/rules/*.md` | CLAUDE.md（自动@include）、其他4个入口文件（手动同步摘要） |
| `.harness/skills/*.md` | 所有入口文件的Skill参考列表 |
| `.harness/config.json` | 无需同步（所有编辑器直接读取） |

**简化同步方案**：核心规则变更时，优先更新 `.harness/` 下的源文件，然后运行以下同步流程：

1. 更新 `.harness/agents/` 和 `.harness/rules/` 中的源文件
2. CLAUDE.md 通过 `@include` 自动获取最新内容
3. 将变更摘要同步到其他4个入口文件的全局规则部分
4. 如有新增Skill，更新所有入口文件的Skill参考列表

## 六、常见问题

### Q1: 使用不同编辑器，框架功能会有差异吗？
核心功能完全一致。所有编辑器都能使用28个Agent角色、84个Skill、6阶段流程和16个规则。差异仅在于规则加载方式：Claude Code通过@include自动加载深度规则，其他编辑器通过入口文件中的内联规则获取核心框架内容，需要时可手动引用.harness/下的详细文件。

### Q2: 可以只保留一个编辑器的入口文件吗？
可以。如果你只使用一款编辑器，只需保留对应的入口文件即可。其他编辑器的入口文件不会影响你的使用，但也不会造成冲突。

### Q3: 修改规则后需要重启编辑器吗？
- **Claude Code**：新对话自动加载最新规则
- **Trae**：新对话自动加载最新规则
- **Cursor**：可能需要重新打开Chat会话
- **GitHub Copilot**：新对话自动加载最新规则
- **Windsurf**：可能需要重启Cascade对话

### Q4: 如何为新编辑器添加适配？
1. 在项目根目录创建该编辑器要求的规则文件位置
2. 将框架核心规则（Agent体系、执行流程、全局规则、Skill参考）写入该文件
3. 按编辑器要求的格式添加必要的元数据（如Cursor的MDC Frontmatter）
4. 测试规则是否被编辑器正确识别和加载

### Q5: 团队中不同成员使用不同编辑器怎么办？
所有编辑器的入口文件都可以提交到Git仓库，团队成员使用各自偏好的编辑器即可。核心框架（.harness/目录）是共享的，确保所有人遵循相同的开发规范。

### Q6: 入口文件内容过多会影响AI性能吗？
当前入口文件大小适中（约200行），不会影响AI性能。如果项目规则持续增长，建议：
- Claude Code：利用@include按需加载，CLAUDE.md保持精简
- Cursor：拆分为多个.mdc文件，按globs条件触发
- 其他编辑器：保持入口文件为核心规则摘要，详细规则放在.harness/目录下按需引用
