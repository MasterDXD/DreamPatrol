# 错误处理规范

## 1. 错误体系

### 1.1 HarnessError 基类

所有自定义错误必须继承 `HarnessError`（`src/errors/index.js`），基类提供：
- `code` — 错误码（ERROR_CODES 常量）
- `severity` — 严重级别（ERROR_SEVERITY）
- `httpStatus` — HTTP 状态码（HTTP_STATUS_MAP）
- `errorId` — 唯一错误ID
- `timestamp` — ISO时间戳
- `context` — 附加上下文
- `isRetryable()` — 是否可重试
- `toJSON()` — 序列化

### 1.2 子错误类

| 错误类 | 适用场景 | code 前缀 |
|--------|---------|----------|
| SessionError | 会话相关错误 | SESSION_ |
| PermissionError | 权限相关错误 | PERMISSION_ |
| TDDGateError | TDD门禁错误 | TDD_ |
| AgentError | Agent相关错误 | AGENT_ |
| DeepeningError | 深化推理错误 | DEEPENING_ |
| CausalViolationError | 因果不变量违反 | CAUSAL_ |
| PipelineError | 管道执行错误 | PIPELINE_ |
| HookError | 钩子执行错误 | HOOK_ |

### 1.3 使用规范

**必须使用自定义错误类的场景**：
- 公共API参数校验失败
- 业务逻辑错误（如状态转换非法、资源不存在）
- 门禁检查失败
- 因果不变量违反

**可以使用原生错误的场景**：
- 纯工具函数的参数类型错误（TypeError）
- 纯数值范围错误（RangeError）

**禁止**：
- 在已导入 errors 模块的文件中使用 `throw new Error()`
- 在 shutdown 状态检查中使用 `throw new Error('Shut down')`，应使用 `this.guardShutdown()`

## 2. 错误处理模式

### 2.1 安全执行

使用 `safeExecute` / `safeCall` 包装可能失败的操作：

```javascript
const { safeExecute } = require('../../utils/safe-execute');
const result = safeExecute(() => riskyOperation(), {
  fallback: defaultValue,
  label: 'ModuleName',
  method: 'methodName',
});
```

### 2.2 重试策略

使用 `RetryEngine` 处理可重试错误：

```javascript
const result = await retryEngine.execute({
  execute: () => operation(),
  replan: (errors) => alternativeOperation(errors),
  decompose: (errors) => subTasks(errors),
});
```

三级升级：RETRY → REPLAN → DECOMPOSE

### 2.3 熔断器

使用 `DeepeningCircuitBreaker` 防止级联失败：

```javascript
const result = await circuitBreaker.execute('service-name', () => operation());
```

三态模型：CLOSED → OPEN → HALF_OPEN

### 2.4 事件错误处理

EventEmitter 子类必须在构造函数中注册 error 自监听器：

```javascript
constructor() {
  super();
  this.on('error', function(err) {
    // 防止无监听器时进程崩溃
  });
}
```

发射错误事件时使用安全降级模式：

```javascript
try { this.emit('error', err); } catch (_emitErr) { this.emit('safe-error', err); }
```

## 3. 优雅关闭

### 3.1 ShutdownMixin

所有有状态模块必须使用 `withShutdown` 混入：

```javascript
const { withShutdown } = require('../../utils/shutdown-mixin');
class MyModule extends withShutdown(EventEmitter) { ... }
module.exports = { MyModule: withShutdown(MyModule) };
```

### 3.2 _onShutdown 规范

- 必须清理所有内部状态（Map/Set/Array）
- 必须调用 `this.removeAllListeners()`
- 异步清理必须返回 Promise
- 禁止重复设置 `this._shutDown = true`（shutdown() 已自动设置）

```javascript
_onShutdown() {
  // 1. 清理定时器
  if (this._timer) { clearTimeout(this._timer); this._timer = null; }
  // 2. 清理集合
  this._cache.clear();
  // 3. 异步操作返回 Promise
  const pending = this._flush();
  // 4. 最后移除监听器
  this.removeAllListeners();
  return pending;
}
```

## 4. 日志规范

- 使用 `debug-logger` 记录调试信息：`debug('Module', 'method', 'message', data)`
- 错误日志必须包含模块名和方法名
- 禁止在日志中输出完整的服务器文件路径
- 禁止在日志中输出密码、Token、API Key
