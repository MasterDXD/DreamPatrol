# 模块开发规范

## 1. 模块结构

### 1.1 文件命名

- 文件名使用 kebab-case：`my-module.js`
- 类名使用 PascalCase：`MyModule`
- 常量使用 UPPER_SNAKE_CASE：`DEFAULT_TIMEOUT_MS`

### 1.2 文件结构

```javascript
'use strict';

// 1. 依赖导入
const { EventEmitter } = require('events');
const { withShutdown } = require('../../utils/shutdown-mixin');
const { safeExecute } = require('../../utils/safe-execute');
const debug = require('../../utils/debug-logger')('MyModule');

// 2. 常量定义
const DEFAULT_OPTION = 100;

// 3. 类定义
/**
 * 模块描述
 * @extends EventEmitter
 * @mixin withShutdown
 */
class MyModule extends withShutdown(EventEmitter) {
  constructor(options) {
    super();
    // 4. 构造函数：null安全参数处理
    const opts = options ?? {};
    this._option = (typeof opts.option === 'number' && Number.isFinite(opts.option)) ? opts.option : DEFAULT_OPTION;
    // 5. error自监听器
    this.on('error', function(err) {});
  }
  // 6. 公共方法（含JSDoc）
  // 7. 私有方法（_前缀）
  // 8. _onShutdown 清理
  _onShutdown() {
    this._cache.clear();
    this.removeAllListeners();
  }
}

// 9. 导出（统一风格）
module.exports = { MyModule: withShutdown(MyModule) };
```

## 2. 构造函数规范

### 2.1 参数处理

```javascript
// 推荐：null安全
const opts = options ?? {};
this._value = (typeof opts.value === 'number' && Number.isFinite(opts.value)) ? opts.value : DEFAULT_VALUE;

// 禁止：直接访问可能为null的options
this._value = options.value ?? DEFAULT_VALUE; // options为null时崩溃
```

### 2.2 数值校验

```javascript
// 推荐：双重校验
(typeof opts.timeout === 'number' && Number.isFinite(opts.timeout) && opts.timeout > 0) ? opts.timeout : DEFAULT_TIMEOUT

// 不推荐：仅类型检查（不防NaN/Infinity）
typeof opts.timeout === 'number' ? opts.timeout : DEFAULT_TIMEOUT
```

## 3. 导出规范

### 3.1 统一导出风格

```javascript
// 推荐：对象包裹 + withShutdown
module.exports = { MyModule: withShutdown(MyModule) };

// 同时导出常量时：
module.exports = { MyModule: withShutdown(MyModule) };
module.exports.DEFAULT_OPTION = DEFAULT_OPTION;
```

### 3.2 注册到初始化器

新模块需在 `src/runtime/infrastructure/module-initializer.js` 中注册：

1. 添加 require 导入
2. 在 SIMPLE_MODULES 数组中添加条目
3. 如需配置，在 config.json 中添加对应配置键

## 4. 依赖注入

### 4.1 attach 模式

模块间依赖通过 `attach*()` 方法注入，而非构造函数参数：

```javascript
class MyModule {
  attachDependency(dependency) {
    this._dependency = dependency;
    return this;
  }
}
```

### 4.2 事件注册

事件转发在 `src/runtime/infrastructure/event-registrar.js` 中统一注册：

```javascript
_registerMyModuleEvents(ctx) {
  const myModule = ctx.instances.myModule;
  if (!myModule) return;
  this._registerListener(myModule, 'my-event', (data) => {
    ctx.eventBus.emit('my-module:my-event', data);
  });
}
```

## 5. 测试规范

- 测试文件放在 `test/` 对应子目录下
- 文件命名：`模块名.test.js`
- 使用 Node.js 内置测试运行器：`node --test`
