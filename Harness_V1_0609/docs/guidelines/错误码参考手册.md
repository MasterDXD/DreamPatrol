# 错误码参考手册

> 源码位置：[[src/errors/index.js]]
> 框架版本：2.73.4
> 错误码总数：85个 | 可重试错误码：7个

## 一、概述

HarnessError 是 Harness Engineering 多Agent框架的统一错误体系，所有运行时异常均通过标准化的错误码、严重级别和HTTP状态码进行结构化表达。本文档提供完整的错误码索引、分类说明及处理指南。

### 1.1 严重级别定义

| 级别 | 含义 | 处理要求 |
|------|------|---------|
| `critical` | 系统级致命错误，影响全局可用性 | 立即人工介入，阻断所有后续操作 |
| `error` | 功能级错误，当前操作失败 | 记录日志，通知上层调用方，触发容错机制 |
| `warn` | 警告级异常，操作可降级继续 | 记录日志，评估是否需要干预 |
| `info` | 信息级提示，非异常状态 | 记录日志即可，无需特殊处理 |

### 1.2 可重试错误码

以下错误码标记为可重试（`isRetryable() === true`），建议采用指数退避策略重试：

| 错误码 | 严重级别 | 典型场景 |
|--------|---------|---------|
| `AGENT_TIMEOUT` | error | Agent执行超时 |
| `PIPELINE_TIMEOUT` | error | 管道执行超时 |
| `TIMEOUT` | error | 通用超时 |
| `DEEPENING_CIRCUIT_OPEN` | warn | 深化推理熔断器开启 |
| `DEEPENING_RATE_LIMITED` | warn | 深化推理限流 |
| `AGENT_CAPACITY_EXCEEDED` | warn | Agent容量超限 |
| `SHUTDOWN_IN_PROGRESS` | warn | 系统关闭中 |

## 二、错误码分类索引

### 2.1 通用错误

| 错误码 | 严重级别 | HTTP状态码 | 描述 |
|--------|---------|-----------|------|
| `UNKNOWN` | error | 500 | 未知错误，无法归类到具体错误码时的兜底错误 |
| `INIT_FAILED` | critical | 500 | 系统初始化失败 |
| `CONFIG_INVALID` | critical | 500 | 配置文件无效或缺失 |
| `INVALID_INPUT` | warn | 400 | 输入参数校验失败 |
| `MISSING_FIELDS` | warn | 400 | 缺少必填字段 |
| `CANCELLED` | info | 499 | 操作已取消 |
| `INVALID_CALLBACK` | warn | 400 | 无效回调函数 |
| `MISSING_PARAMETER` | warn | 400 | 缺少必要参数 |
| `INVALID_TOOL_TYPE` | warn | 400 | 无效工具类型 |
| `INIT_TIMEOUT` | error | 504 | 初始化超时 |

#### UNKNOWN
- **描述**：无法归类的未知错误，通常由未捕获的异常转换而来
- **常见触发场景**：第三方库抛出非标准异常；`fromError()` 转换无 `code` 属性的普通 Error
- **建议处理**：检查 `context.originalStack`（非生产环境）获取原始堆栈；补充具体错误码分类

#### INIT_FAILED
- **描述**：框架或模块初始化阶段失败
- **常见触发场景**：数据库连接失败；配置文件解析异常；关键依赖加载失败
- **建议处理**：检查启动日志定位初始化失败的具体模块；验证配置文件格式和路径；不可重试，需修复后重启

#### CONFIG_INVALID
- **描述**：配置项校验不通过
- **常见触发场景**：`.harness/config.json` 格式错误；必填配置项缺失；配置值超出合法范围
- **建议处理**：运行 `node harness-cli.js validate` 验证配置；参照配置模板修正

#### INVALID_INPUT
- **描述**：用户输入或API请求参数不合法
- **常见触发场景**：API请求参数类型错误；必填字段为空；值超出允许范围
- **建议处理**：检查请求参数格式和类型；参照API文档修正输入

#### MISSING_FIELDS
- **描述**：请求中缺少必填字段
- **常见触发场景**：API请求缺少必填参数；表单提交时必填项为空
- **建议处理**：检查请求中是否包含所有必填字段；参照API文档确认必填参数列表

#### CANCELLED
- **描述**：操作被主动取消
- **常见触发场景**：用户主动取消操作；父任务取消导致子任务取消；超时前的主动取消
- **建议处理**：记录取消原因；清理已分配的资源；无需重试

#### INVALID_CALLBACK
- **描述**：传入的回调函数无效
- **常见触发场景**：回调参数不是函数类型；回调函数已被垃圾回收；回调注册时类型校验失败
- **建议处理**：确认回调参数为有效函数引用；检查回调函数签名是否匹配

#### MISSING_PARAMETER
- **描述**：缺少必要的函数或方法参数
- **常见触发场景**：调用方法时缺少必要参数；参数验证时发现必填参数为null/undefined
- **建议处理**：检查方法调用是否提供了所有必要参数；参照方法签名确认参数列表

#### INVALID_TOOL_TYPE
- **描述**：工具类型无效或不支持
- **常见触发场景**：注册了未知类型的工具；工具适配器类型不匹配
- **建议处理**：检查工具类型是否在支持列表中；确认工具适配器配置正确

#### INIT_TIMEOUT
- **描述**：模块或系统初始化超时
- **常见触发场景**：模块初始化耗时超过配置的超时时间；依赖服务启动缓慢导致初始化阻塞
- **建议处理**：增加初始化超时配置；检查依赖服务状态；优化初始化流程

### 2.2 会话错误

对应子类：`HarnessError.SessionError`

| 错误码 | 严重级别 | HTTP状态码 | 描述 |
|--------|---------|-----------|------|
| `SESSION_NOT_FOUND` | warn | 404 | 会话不存在 |
| `SESSION_EXPIRED` | warn | 410 | 会话已过期 |
| `SESSION_PHASE_INVALID` | warn | 409 | 会话阶段转换不合法 |
| `SESSION_BUDGET_EXCEEDED` | warn | 429 | 会话Token预算超限 |
| `BUDGET_EXCEEDED` | error | 429 | 全局Token预算耗尽（TokenManager） |

#### SESSION_NOT_FOUND
- **描述**：引用的会话ID在存储中不存在
- **常见触发场景**：使用已删除的会话ID；会话ID拼写错误；存储被清空后引用旧ID
- **建议处理**：创建新会话；检查会话ID是否正确

#### SESSION_EXPIRED
- **描述**：会话超过TTL有效期已自动过期
- **常见触发场景**：长时间未操作的会话被TTL回收；系统重启后会话状态丢失
- **建议处理**：通过 `CheckpointManager` 恢复最近检查点；创建新会话并从检查点继续

#### SESSION_PHASE_INVALID
- **描述**：尝试进行不被允许的阶段转换
- **常见触发场景**：从"需求探索"直接跳到"模块开发"（跳过架构设计）；在"集成测试"阶段回退到"需求分析"
- **建议处理**：检查 `PhaseOrchestrator` 定义的阶段转换规则；按顺序完成前置阶段

#### SESSION_BUDGET_EXCEEDED
- **描述**：会话Token消耗达到预算上限
- **常见触发场景**：长时间对话消耗过多Token；深化推理循环消耗超出预期
- **建议处理**：压缩上下文后继续（`ContextCompressionEngine`）；申请提高预算配额；切换到低价模型

#### BUDGET_EXCEEDED
- **描述**：全局Token预算已耗尽，TokenManager拒绝新的Token操作
- **常见触发场景**：`TokenManager.store()` 在全局预算使用率达100%时拒绝累加；多会话累计消耗超过全局预算上限
- **建议处理**：检查 `TokenManager.getStats()` 确认全局预算使用情况；申请提高全局预算（`setGlobalBudget()`）；切换到低价模型减少消耗；等待会话过期释放预算
- **Round 9 修复说明**：`TokenManager.store()` 新增预算耗尽检查，全局预算已用尽时拒绝操作并返回0，确保Token消耗不超过配置的预算上限

### 2.3 权限错误

对应子类：`HarnessError.PermissionError`

| 错误码 | 严重级别 | HTTP状态码 | 描述 |
|--------|---------|-----------|------|
| `PERMISSION_DENIED` | error | 403 | 权限拒绝 |
| `PERMISSION_SKILL_NOT_ALLOWED` | warn | 403 | Agent无权执行该Skill |
| `PERMISSION_FILE_PROTECTED` | error | 403 | 文件受保护禁止操作 |
| `PERMISSION_LOCK_CONFLICT` | warn | 409 | 文件编辑锁冲突 |

#### PERMISSION_DENIED
- **描述**：RBAC权限检查未通过，当前角色无权执行操作
- **常见触发场景**：Task Worker 尝试执行仅 Team Lead 可用的操作；未授权的API调用
- **建议处理**：检查 `RBACEnforcer` 的角色权限配置；确认当前Agent角色是否有权执行目标操作

#### PERMISSION_SKILL_NOT_ALLOWED
- **描述**：当前Agent角色不被允许执行指定Skill
- **常见触发场景**：QA Agent 尝试触发 `deployment` Skill；Task Worker 尝试执行 `architecture-design` Skill
- **建议处理**：检查Skill定义中的 `applicableAgents` 配置；通过 Team Lead 代理执行

#### PERMISSION_FILE_PROTECTED
- **描述**：尝试修改受保护的文件（如配置文件、规则文件）
- **常见触发场景**：修改 `.harness/config.json` 未通过审批；写入受保护目录
- **建议处理**：通过 `DeviationApproval` 流程申请偏差审批；使用 `workspace/staging/` 暂存区

#### PERMISSION_LOCK_CONFLICT
- **描述**：目标文件已被其他Agent锁定编辑
- **常见触发场景**：两个Agent同时修改同一文件；前一个编辑锁未正常释放
- **建议处理**：等待锁释放（默认TTL 60秒）；通过 `workspace/locks/` 查看锁持有者；紧急情况请求管理员强制释放

### 2.4 TDD门禁错误

对应子类：`HarnessError.TDDGateError`

| 错误码 | 严重级别 | HTTP状态码 | 描述 |
|--------|---------|-----------|------|
| `TDD_VIOLATION` | error | 409 | TDD门禁违规 |
| `TDD_NO_TEST` | error | 409 | 缺少测试用例 |
| `TDD_COVERAGE_LOW` | warn | 409 | 测试覆盖率低于阈值 |
| `TDD_PHASE_INVALID` | warn | 409 | TDD阶段不合法 |
| `EVIDENCE_INSUFFICIENT` | warn | 422 | 完成证据不充分 |

#### TDD_VIOLATION
- **描述**：违反TDD强制规则，在失败测试之前编写了实现代码
- **常见触发场景**：直接编写生产代码未先写测试；RED阶段测试未失败就进入GREEN
- **建议处理**：删除违规实现代码；先编写失败测试再重新实现

#### TDD_NO_TEST
- **描述**：提交的代码缺少对应的测试文件
- **常见触发场景**：新增模块未创建测试文件；测试文件命名不符合约定
- **建议处理**：为模块创建对应的测试文件；确保测试文件路径符合 `test/` 目录约定

#### TDD_COVERAGE_LOW
- **描述**：测试覆盖率低于框架要求的最低阈值（默认80%）
- **常见触发场景**：新增代码未补充测试；分支覆盖不充分
- **建议处理**：运行 `npm test -- --coverage` 查看覆盖率报告；补充缺失的测试用例

#### TDD_PHASE_INVALID
- **描述**：TDD循环阶段转换不合法
- **常见触发场景**：从RED直接跳到REFACTOR（跳过GREEN）；GREEN阶段测试仍然失败
- **建议处理**：严格遵循 RED → GREEN → REFACTOR 循环；确保GREEN阶段所有测试通过

#### EVIDENCE_INSUFFICIENT
- **描述**：Agent声称任务完成但未提供充分证据
- **常见触发场景**：`verification-before-completion` Skill验证失败；缺少测试运行结果；缺少构建成功证明
- **建议处理**：提供具体的测试通过截图或日志；提供构建成功输出；通过 `EvidenceVerifier` 检查证据完整性

### 2.5 Agent错误

对应子类：`HarnessError.AgentError`

| 错误码 | 严重级别 | HTTP状态码 | 描述 |
|--------|---------|-----------|------|
| `AGENT_NOT_FOUND` | warn | 404 | Agent不存在 |
| `AGENT_UNHEALTHY` | error | 503 | Agent健康检查失败 |
| `AGENT_TIMEOUT` | error | 504 | Agent执行超时 |
| `AGENT_CAPACITY_EXCEEDED` | warn | 503 | Agent容量超限 |
| `SKILL_NOT_FOUND` | warn | 404 | Skill不存在 |
| `SKILL_DEPENDENCY_MISSING` | error | 424 | Skill依赖缺失 |
| `DUPLICATE_STEP` | warn | 409 | 工作流步骤ID重复 |

#### AGENT_NOT_FOUND
- **描述**：引用的Agent ID在运行时中不存在
- **常见触发场景**：Agent已终止但仍被引用；Agent ID拼写错误
- **建议处理**：检查Agent注册表；确认Agent是否已正确初始化

#### AGENT_UNHEALTHY
- **描述**：Agent健康检查探针返回失败
- **常见触发场景**：Agent内部状态损坏；依赖服务不可用；内存溢出
- **建议处理**：检查 `HealthChecker` 的探针结果；重启Agent；检查依赖服务状态

#### AGENT_TIMEOUT
- **描述**：Agent执行超过配置的超时时间（默认20分钟）
- **常见触发场景**：任务过于复杂导致执行超时；Agent陷入死循环；外部API响应缓慢
- **建议处理**：拆分任务为更小子任务；增加超时配置；检查是否存在死循环（可重试）

#### AGENT_CAPACITY_EXCEEDED
- **描述**：Agent并发任务数达到上限
- **常见触发场景**：同时分配过多任务给同一Agent；任务队列积压
- **建议处理**：等待当前任务完成；将任务分配给其他Agent；增加Agent并发容量配置（可重试）

#### SKILL_NOT_FOUND
- **描述**：Skill路由器无法匹配到对应Skill
- **常见触发场景**：Skill文件被删除或移动；Skill ID拼写错误；Skill未正确注册
- **建议处理**：运行 `node harness-cli.js skills` 查看已注册Skill列表；检查 `.harness/skills/` 目录

#### SKILL_DEPENDENCY_MISSING
- **描述**：Skill执行所需的前置依赖未满足
- **常见触发场景**：前置Skill未执行；依赖的模块未安装；配置项缺失
- **建议处理**：检查Skill的 `dependencies` 定义；按顺序执行前置Skill；安装缺失依赖

#### DUPLICATE_STEP
- **描述**：工作流步骤ID重复，同一工作流中存在两个或以上相同ID的步骤
- **常见触发场景**：`WorkflowDAG` 添加节点时ID重复；`PipelineExecutor` 管道步骤定义重复；`DeepeningTaskScheduler` 任务ID冲突
- **建议处理**：检查工作流定义中的步骤ID唯一性；使用 `generateId()` 生成唯一步骤ID；修正重复ID后重新提交

### 2.6 管道错误

对应子类：`HarnessError.PipelineError`

| 错误码 | 严重级别 | HTTP状态码 | 描述 |
|--------|---------|-----------|------|
| `PIPELINE_TIMEOUT` | error | 504 | 管道执行超时 |
| `PIPELINE_BLOCKED` | warn | 403 | 管道被阻塞 |
| `PIPELINE_EXECUTION_ERROR` | error | 500 | 管道执行异常 |
| `SPRINT_ALREADY_RUNNING` | warn | 409 | Sprint已在运行中 |
| `INVALID_EXECUTION_MODE` | warn | 400 | 无效的执行模式 |
| `MODE_SWITCH_DISABLED` | warn | 409 | 模式切换已禁用 |

#### PIPELINE_TIMEOUT
- **描述**：PipelineExecutor 执行超时
- **常见触发场景**：管道步骤过多导致总时长超限；某个步骤卡住；外部服务响应慢
- **建议处理**：检查管道各步骤耗时；优化耗时步骤；增加管道超时配置（可重试）

#### PIPELINE_BLOCKED
- **描述**：管道执行被权限或业务规则阻断
- **常见触发场景**：TDD门禁阻断；权限检查未通过；人工审批门未通过
- **建议处理**：解决阻断条件（如补充测试、获取权限）；通过 `HumanApprovalGate` 完成审批

#### PIPELINE_EXECUTION_ERROR
- **描述**：管道步骤执行过程中抛出异常
- **常见触发场景**：步骤函数内部错误；数据格式不匹配；步骤间数据传递异常
- **建议处理**：检查错误上下文中的步骤信息；修复步骤函数逻辑；不可重试

#### SPRINT_ALREADY_RUNNING
- **描述**：尝试启动新的Sprint但已有Sprint正在运行
- **常见触发场景**：`SprintCycle` 在已有活跃Sprint时再次调用start；并发启动Sprint请求
- **建议处理**：等待当前Sprint完成或停止后再启动；检查Sprint状态

#### INVALID_EXECUTION_MODE
- **描述**：指定了无效的执行模式
- **常见触发场景**：`ExecutionModeManager` 接收到未注册的执行模式；模式名称拼写错误
- **建议处理**：检查执行模式是否在支持列表中；参照 `ExecutionModeManager` 配置确认可用模式

#### MODE_SWITCH_DISABLED
- **描述**：当前配置下不允许切换执行模式
- **常见触发场景**：在Sprint运行中尝试切换模式；配置中禁用了动态模式切换
- **建议处理**：等待当前Sprint完成后再切换；修改配置允许模式切换

### 2.7 深化推理错误

对应子类：`HarnessError.DeepeningError`

| 错误码 | 严重级别 | HTTP状态码 | 描述 |
|--------|---------|-----------|------|
| `DEEPENING_CIRCUIT_OPEN` | warn | 503 | 深化推理熔断器开启 |
| `DEEPENING_RATE_LIMITED` | warn | 429 | 深化推理请求被限流 |
| `DEEPENING_CONVERGENCE_FAILED` | warn | 422 | 深化推理未收敛 |
| `DEEPENING_CIRCUIT_BREAKER_OPEN` | warn | 503 | 深化推理断路器开启 |

#### DEEPENING_CIRCUIT_OPEN
- **描述**：深化推理模块的熔断器已开启，拒绝新请求
- **常见触发场景**：连续多次深化推理失败触发熔断；系统资源不足
- **建议处理**：等待熔断器半开状态后重试；降低深化频率；检查系统资源（可重试）

#### DEEPENING_RATE_LIMITED
- **描述**：深化推理请求频率超过限流阈值
- **常见触发场景**：短时间内发起过多深化请求；多Agent同时请求深化
- **建议处理**：降低请求频率；等待限流窗口重置；调整限流配置（可重试）

#### DEEPENING_CONVERGENCE_FAILED
- **描述**：迭代深化推理达到最大深度仍未收敛
- **常见触发场景**：任务复杂度过高；质量阈值设置过严；推理方向偏离
- **建议处理**：降低质量阈值；增加最大迭代深度；人工介入提供方向指引

#### DEEPENING_CIRCUIT_BREAKER_OPEN
- **描述**：深化推理断路器已开启，拒绝新的深化请求
- **常见触发场景**：深化推理模块连续失败触发断路器；系统资源不足导致断路器保护性开启
- **建议处理**：等待断路器进入半开状态后重试；检查系统资源状况；降低深化请求频率

- **常见触发场景**：`CausalConfigValidator` 模式校验失败；`param-validator` 参数校验失败

- **常见触发场景**：收到SIGTERM/SIGINT信号；手动触发关闭
- **建议处理**：停止提交新任务；等待当前任务完成或超时；`SHUTDOWN_IN_PROGRESS` 可重试（等待关闭完成后重启）

#### RESOURCE_EXHAUSTED

- **常见触发场景**：内存泄漏导致OOM；连接池耗尽；文件句柄泄漏
- **建议处理**：检查资源使用情况；释放未使用的资源；增加资源配额

#### RESOURCE_NOT_FOUND
- **描述**：请求的资源不存在
- **常见触发场景**：访问已删除的检查点；引用不存在的配置项
- **建议处理**：确认资源是否已被删除；检查资源ID是否正确

#### INVALID_STATE
- **描述**：操作与当前状态不兼容
- **常见触发场景**：在已终止的Agent上执行操作；状态机非法转换
- **建议处理**：检查当前状态是否允许该操作；重置状态后重试

#### CAPACITY_EXCEEDED
- **描述**：超出系统容量限制
- **常见触发场景**：超出 `capacity-config` 配额；队列长度超限
- **建议处理**：等待容量释放；调整容量配置；分流请求

#### CONNECTION_FAILED
- **描述**：网络连接建立失败
- **常见触发场景**：MCP服务端不可达；WebSocket连接断开；数据库连接失败
- **建议处理**：检查目标服务状态；检查网络配置；使用 `RetryEngine` 重试

#### SECURITY_VIOLATION
- **描述**：检测到安全违规行为
- **常见触发场景**：路径遍历攻击；XSS注入尝试；未授权访问敏感资源
- **建议处理**：立即阻断操作；记录审计日志；通知安全管理员；检查 `PermissionGuard` 和 `sanitizer` 配置

#### DEPENDENCY_CYCLE
- **描述**：检测到循环依赖
- **常见触发场景**：Skill依赖图出现环；`WorkflowDAG` 拓扑排序失败；模块初始化循环
- **建议处理**：检查依赖关系图；打破循环依赖；使用 `SkillTreeDAG` 的循环检测功能

#### PLUGIN_ERROR
- **描述**：插件加载或执行失败
- **常见触发场景**：插件代码存在语法错误；插件API版本不兼容；插件依赖缺失
- **建议处理**：检查插件代码；确认API版本兼容性；安装插件依赖

#### SNAPSHOT_ERROR / SNAPSHOT_STORE_ERROR
- **描述**：检查点快照创建或存储失败
- **常见触发场景**：序列化失败；存储空间不足；快照版本冲突
- **建议处理**：检查序列化数据格式；释放存储空间；使用增量快照减少体积

#### AUDIT_ERROR
- **描述**：审计日志写入失败
- **常见触发场景**：链式哈希校验失败；审计存储不可用
- **建议处理**：检查审计存储状态；验证哈希链完整性；不可忽略，需确保审计链完整

#### RETRY_EXHAUSTED
- **描述**：重试策略已耗尽所有重试次数
- **常见触发场景**：`RetryEngine` 达到最大重试次数（默认3次）；每次重试均失败
- **建议处理**：检查根本失败原因；增加重试次数或退避间隔；降级到备用方案

#### LOCK_TIMEOUT
- **描述**：等待文件锁超时
- **常见触发场景**：锁持有者未在TTL内释放；死锁
- **建议处理**：检查 `workspace/locks/` 中的锁状态；等待锁自动过期；紧急时强制释放

#### LOAD_BALANCER_ERROR
- **描述**：负载均衡器调度失败
- **常见触发场景**：所有后端Agent不可用；健康检查全部失败；权重配置错误
- **建议处理**：检查后端Agent健康状态；验证权重配置；启用故障转移

#### DATA_PIPELINE_ERROR
- **描述**：数据管道处理失败
- **常见触发场景**：数据格式转换错误；管道步骤异常；数据源不可用
- **建议处理**：检查管道步骤日志；验证数据格式；修复失败的管道步骤

#### NOTIFIER_ERROR
- **描述**：通知发送失败
- **常见触发场景**：通知渠道不可用；通知模板渲染失败；通知服务超时
- **建议处理**：检查通知渠道配置；验证模板格式；降级到备用通知渠道

#### EVENT_BUS_ERROR
- **描述**：事件总线发布或订阅失败
- **常见触发场景**：事件处理器抛出异常；事件队列溢出；订阅者不存在
- **建议处理**：检查事件处理器逻辑；增加队列容量；验证事件类型注册

#### STATE_MACHINE_ERROR
- **描述**：状态机转换失败
- **常见触发场景**：非法状态转换；状态机未初始化；并发状态修改冲突
- **建议处理**：检查状态转换规则；确保状态机已初始化；使用锁保护并发修改

#### TASK_SCHEDULER_ERROR
- **描述**：任务调度器执行失败
- **常见触发场景**：调度规则冲突；任务优先级配置错误；调度器内部状态异常
- **建议处理**：检查调度规则配置；验证优先级设置；重启调度器

#### METRICS_ERROR
- **描述**：指标采集或聚合失败
- **常见触发场景**：指标收集器异常；聚合计算溢出；存储写入失败
- **建议处理**：检查指标收集器状态；验证聚合配置；非关键路径，可降级继续

#### BACKPRESSURE_ERROR
- **描述**：背压控制触发，下游处理速度跟不上上游生产速度
- **常见触发场景**：事件生产速度超过消费速度；数据管道瓶颈；消费者阻塞
- **建议处理**：降低生产速率；增加消费者容量；启用背压缓冲区

#### PRIORITY_QUEUE_ERROR
- **描述**：优先级队列操作失败
- **常见触发场景**：堆结构损坏；优先级值非法；队列容量超限
- **建议处理**：重建优先级队列；验证优先级值范围；增加队列容量

#### POOL_SHUTDOWN
- **描述**：连接池已关闭，拒绝新的连接获取请求
- **常见触发场景**：系统关闭过程中调用 `SharedConnectionPool.acquire()`；连接池已被显式 shutdown
- **建议处理**：检查连接池生命周期状态；等待系统重启后重新获取连接；不可重试

#### POOL_EXHAUSTED
- **描述**：连接池中所有连接已被占用，无法分配新连接
- **常见触发场景**：并发请求数超过 `maxConnections` 配置；连接未正确释放导致泄漏
- **建议处理**：检查是否存在未释放的连接；增加 `maxConnections` 配置；等待现有连接释放后重试

#### FACTORY_ERROR
- **描述**：连接工厂函数执行失败，无法创建新连接
- **常见触发场景**：工厂函数抛出异常；目标服务不可达；认证失败
- **建议处理**：检查工厂函数逻辑；验证目标服务可用性；检查认证凭据

#### LIMIT_EXCEEDED
- **描述**：操作超出了配置的限制
- **常见触发场景**：请求频率超过限额；资源使用量超过配额；并发操作数超限
- **建议处理**：降低请求频率；申请提高限额；等待限额窗口重置

#### ACQUIRE_FAILED
- **描述**：从连接池获取连接失败
- **常见触发场景**：连接池中无可用连接且无法创建新连接；获取连接超时
- **建议处理**：检查连接池状态；增加连接池容量；等待连接释放后重试

#### INVALID_PLUGIN
- **描述**：插件格式或结构无效
- **常见触发场景**：插件缺少必要的导出接口；插件元数据格式错误；插件API版本不兼容
- **建议处理**：检查插件代码结构；确认插件API版本兼容性；参照插件开发规范修正

#### DUPLICATE_PLUGIN
- **描述**：尝试注册已存在的插件
- **常见触发场景**：同一插件ID被重复注册；插件热重载时未先卸载旧版本
- **建议处理**：先卸载已有插件再重新注册；检查插件注册逻辑避免重复

#### PLUGIN_INIT_FAILED
- **描述**：插件初始化失败
- **常见触发场景**：插件初始化函数抛出异常；插件依赖的服务不可用；插件配置错误
- **建议处理**：检查插件初始化日志；验证插件依赖和配置；不可重试，需修复后重新加载

- **常见触发场景**：输出数据格式不符合因果模式定义；输出值超出合法范围

## 三、HarnessError 类 API 文档

### 3.1 类层次结构

```
Error
  └── HarnessError
        ├── SessionError
        ├── PermissionError
        ├── TDDGateError
        ├── AgentError
        ├── DeepeningError
        ├── CausalViolationError
        ├── PipelineError
        └── HookError
```

### 3.2 构造函数

```javascript
new HarnessError(code, message, context)
```

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `code` | string | 是 | 错误码，来自 `ERROR_CODES` 枚举。若为空或非字符串，自动降级为 `UNKNOWN` |
| `message` | string | 是 | 人类可读的错误描述。若为空或非字符串，自动降级为 `'An unknown error occurred'` |
| `context` | object | 否 | 附加上下文数据。若非纯对象则自动降级为 `{}` |

### 3.3 实例属性

| 属性 | 类型 | 说明 |
|------|------|------|
| `name` | string | 错误类名，基类为 `'HarnessError'`，子类为对应类名 |
| `code` | string | 错误码标识（如 `'AGENT_TIMEOUT'`） |
| `message` | string | 人类可读的错误描述 |
| `errorId` | string | 唯一错误标识，格式 `err_{timestamp}_{random}` |
| `severity` | string | 严重级别：`'critical'` \| `'error'` \| `'warn'` \| `'info'` |
| `httpStatus` | number | 映射的HTTP状态码，未知错误码默认 `500` |
| `timestamp` | string | ISO 8601 格式的时间戳 |
| `context` | object | 附加上下文数据 |
| `stack` | string | 错误堆栈（继承自 Error） |

### 3.4 实例方法

#### `toJSON()`

返回结构化的错误JSON对象，用于API响应和日志记录。

```javascript
const err = new HarnessError('AGENT_TIMEOUT', 'Agent exceeded 20min limit', { agentId: 'worker-1' });
err.toJSON();
// {
//   error: true,
//   errorId: 'err_1748234567890_a3f2',
//   code: 'AGENT_TIMEOUT',
//   message: 'Agent exceeded 20min limit',
//   severity: 'error',
//   httpStatus: 504,
//   timestamp: '2026-05-26T10:30:00.000Z',
//   context: { agentId: 'worker-1' }
// }
```

注意：`context.originalStack` 在序列化时会被自动移除，防止敏感堆栈信息泄露。

#### `isRetryable()`

判断当前错误是否可安全重试。

```javascript
const err = new HarnessError('AGENT_TIMEOUT', 'Timeout');
err.isRetryable(); // true

const err2 = new HarnessError('SECURITY_VIOLATION', 'Violation');
err2.isRetryable(); // false
```

#### `toString()`

返回格式化的错误字符串。

```javascript
const err = new HarnessError('SESSION_EXPIRED', 'Session TTL exceeded');
err.toString(); // 'HarnessError: [SESSION_EXPIRED] Session TTL exceeded'
```

### 3.5 静态方法

#### `HarnessError.fromError(err)`

将任意 Error 对象转换为 HarnessError 实例。

```javascript
const nativeErr = new Error('Something went wrong');
nativeErr.code = 'STORAGE_ERROR';
const harnessErr = HarnessError.fromError(nativeErr);
// harnessErr.code === 'STORAGE_ERROR'
// harnessErr.context.originalName === 'Error'
// harnessErr.cause === nativeErr（非生产环境还包含 originalStack）
```

转换规则：
- 若 `err` 已是 `HarnessError` 实例，直接返回
- `code` 取自 `err.code`，无则降级为 `UNKNOWN`
- `message` 取自 `err.message`，无则降级为 `'An unknown error occurred'`
- `context.originalName` 始终包含原始错误类名
- `context.originalStack` 仅在非生产环境保留
- `cause` 属性指向原始错误对象

### 3.6 静态属性（子类引用）

## 四、错误处理最佳实践

### 4.1 错误创建

```javascript
const { HarnessError } = require('./src/errors');

// 推荐：使用具体子类
throw new HarnessError.SessionError('SESSION_EXPIRED', 'Session TTL exceeded', {
  sessionId: 'sess_123',
  ttl: 3600
});

// 避免：使用基类处理应归属子类的错误
// throw new HarnessError('SESSION_EXPIRED', '...'); // 不推荐
```

### 4.2 错误捕获与转换

```javascript
const { HarnessError } = require('./src/errors');

try {
  await riskyOperation();
} catch (err) {
  const harnessErr = HarnessError.fromError(err);
  logger.error('Operation failed', harnessErr.toJSON());

  if (harnessErr.isRetryable()) {
    await retryWithBackoff(riskyOperation);
  } else {
    throw harnessErr;
  }
}
```

### 4.3 API响应格式

```javascript
function handleError(err, res) {
  const harnessErr = HarnessError.fromError(err);
  const body = harnessErr.toJSON();

  if (harnessErr.severity === 'critical') {
    body.message = 'Internal server error';
    delete body.context;
  }

  res.status(harnessErr.httpStatus).json(body);
}
```

### 4.4 重试策略

```javascript
const { RETRYABLE_CODES } = require('./src/errors');

async function executeWithRetry(fn, maxRetries = 3) {
  for (let attempt = 0; attempt <= maxRetries; attempt++) {
    try {
      return await fn();
    } catch (err) {
      const harnessErr = HarnessError.fromError(err);
      if (!harnessErr.isRetryable() || attempt === maxRetries) {
        throw harnessErr;
      }
      const delay = Math.min(1000 * Math.pow(2, attempt), 30000);
      await sleep(delay);
    }
  }
}
```

### 4.5 审计日志集成

```javascript
const { AuditLogger } = require('./src/permission');

async function auditedOperation(context) {
  try {
    const result = await doOperation(context);
    return result;
  } catch (err) {
    const harnessErr = HarnessError.fromError(err);
    await auditLogger.log({
      action: 'operation_failed',
      errorCode: harnessErr.code,
      errorId: harnessErr.errorId,
      severity: harnessErr.severity,
      context: harnessErr.context
    });
    throw harnessErr;
  }
}
```

### 4.6 关键原则

1. **始终使用 `fromError()` 转换**：捕获第三方异常时，通过 `HarnessError.fromError()` 统一转换，确保错误结构一致
2. **优先使用子类**：根据错误领域选择对应子类（SessionError、PermissionError等），便于上层按类型捕获
3. **提供充分的 context**：在 context 中附加有助于排查问题的信息（如 sessionId、agentId、skillId），但禁止包含敏感信息（密钥、令牌）
4. **检查可重试性**：对可重试错误实现指数退避重试，避免对不可重试错误浪费重试资源
5. **严重级别驱动响应**：`critical` 级别错误必须立即告警；`error` 级别需记录并通知；`warn` 级别记录即可；`info` 级别可忽略
6. **生产环境安全**：`toJSON()` 自动移除 `originalStack`，API响应中 `critical` 错误应隐藏内部细节
7. **错误码不扩展**：新增错误码必须更新 `ERROR_CODES`、`ERROR_SEVERITY`、`HTTP_STATUS_MAP` 三张表，并在本文档同步更新
