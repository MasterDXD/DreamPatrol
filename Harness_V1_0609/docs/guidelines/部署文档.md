## 1. 环境要求

### 运行时依赖

| 依赖项 | 最低版本 | 说明 |
|--------|---------|------|
| **Node.js** | >= 18.0.0 | 框架核心运行时，需支持 `node --test` 内置测试运行器 |
| **npm** | >= 8.0.0 | 包管理器，随 Node.js 18+ 自带 |
| **better-sqlite3** | ^12.9.0 | 原生编译依赖，需 C++ 编译工具链 |

### 操作系统支持

| 操作系统 | 支持状态 | 备注 |
|---------|---------|------|
| Linux (x64) | ✅ 生产推荐 | Ubuntu 20.04+、CentOS 8+、Debian 11+ |
| macOS (x64/ARM64) | ✅ 开发推荐 | Apple Silicon 原生支持 |
| Windows (x64) | ✅ 开发支持 | 需 Visual Studio Build Tools |

### 编译工具链（better-sqlite3 原生模块）

- **Linux**：`gcc` / `g++` / `make`（通常通过 `build-essential` 安装）
- **macOS**：Xcode Command Line Tools（`xcode-select --install`）
- **Windows**：Visual Studio Build Tools（需 C++ 桌面开发工作负载）

### 硬件建议

| 配置项 | 最低要求 | 推荐配置 |
|--------|---------|---------|
| CPU | 2核 | 4核+ |
| 内存 | 2 GB | 4 GB+ |
| 磁盘 | 1 GB | 5 GB+（含日志和数据库） |
| 网络 | — | 出站 HTTPS（MCP HTTP模式、模型API调用） |

## 2. 安装步骤

### 2.1 获取代码

```bash
git clone https://github.com/harness-engineering/framework.git
cd framework
```

### 2.2 安装依赖

```bash
npm install
```

> better-sqlite3 会在 `npm install` 时自动编译原生模块。如编译失败，请确认已安装 C++ 编译工具链。

### 2.3 初始化项目

```bash
node harness-cli.js init
```

此命令创建以下目录结构：

```
.harness/
├── commands/          # 斜杠命令定义
├── skills/            # Skill模板（84个）
├── agents/            # Agent角色定义
├── sessions/          # 会话数据
├── knowledge/         # 知识库
├── workspace/
│   ├── staging/       # 待审核代码暂存区
│   ├── shared/        # 已审核代码共享区
│   └── locks/         # 编辑锁
├── checkpoints/       # 任务检查点
├── rag/
│   ├── documents/     # RAG文档
│   └── indexes/       # RAG索引
└── config.json        # 全局配置
```

同时生成 `.env.harness` 环境变量文件并更新 `.gitignore`。

### 2.4 验证安装

```bash
node harness-cli.js validate
node harness-cli.js status
```

## 6. 3步部署流程

### 步骤一：准备（8项检查）

| # | 检查项 | 验证方法 |
|---|--------|---------|
| 1 | Node.js版本 >= 18.0.0 | `node --version` |
| 2 | 依赖安装完整 | `ls node_modules/better-sqlite3` |
| 3 | .harness目录存在 | `ls .harness/config.json` |
| 4 | 配置文件有效 | `node harness-cli.js config show` |
| 5 | 环境变量配置 | 检查 `.env.harness` |
| 6 | 端口可用 | `netstat -tlnp | grep 3210` |
| 7 | 磁盘空间充足 | `df -h` |
| 8 | MCP服务器配置 | 检查 `mcp_servers` 配置项 |

### 步骤二：验证（5项验证）

| # | 验证项 | 命令 |
|---|--------|------|
| 1 | 框架验证 | `node harness-cli.js validate` |
| 2 | 健康检查 | `node harness-cli.js status` |
| 3 | Lint检查 | `npx eslint src/ test/ scripts/` |
| 4 | 测试通过 | `npm test` |
| 5 | 记忆一致性 | `node harness-cli.js memory-verify` |

### 步骤三：部署（4种策略）

| 策略 | 适用场景 | 停机时间 | 回滚方式 |
|------|---------|---------|---------|
| **Rolling** | 标准部署 | 零 | 逐实例回滚 |
| **Blue-Green** | 需要快速切换 | 零 | 切换流量回蓝环境 |
| **Canary** | 高风险变更 | 零 | 停止金丝雀发布 |
| **Recreate** | 不兼容变更 | 有 | 重新部署旧版本 |

```bash
# 标准部署流程
node harness-cli.js validate && npm test && node harness-cli.js dashboard --port 3210
```

## 10. 安全加固

### 10.1 API Token配置

```bash
# 生成安全Token
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"

# 配置环境变量
export HARNESS_API_TOKEN=<generated-token>
```

Dashboard服务器在启动时检查 `HARNESS_API_TOKEN` 环境变量，若未设置且 `NODE_ENV` 未指定，则自动设为 `development` 模式。

### 10.2 HTTPS设置

生产环境建议在Dashboard前部署反向代理（Nginx/Caddy）处理TLS终止：

**Nginx配置示例：**

```nginx
server {
    listen 443 ssl http2;
    server_name harness.example.com;

    ssl_certificate /etc/ssl/certs/harness.crt;
    ssl_certificate_key /etc/ssl/private/harness.key;
    ssl_protocols TLSv1.2 TLSv1.3;
    ssl_ciphers HIGH:!aNULL:!MD5;

    location / {
        proxy_pass http://127.0.0.1:3210;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    location /ws {
        proxy_pass http://127.0.0.1:3210;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
    }
}
```

**Caddy配置示例：**

```
harness.example.com {
    reverse_proxy localhost:3210
}
```

### 10.3 CORS策略

Dashboard服务器内置CSP nonce和速率限制。生产环境可通过反向代理添加CORS头：

```nginx
add_header Access-Control-Allow-Origin "https://your-domain.com" always;
add_header Access-Control-Allow-Methods "GET, POST, OPTIONS" always;
add_header Access-Control-Allow-Headers "Content-Type, Authorization" always;
add_header Access-Control-Max-Age 86400 always;
```

### 10.4 RBAC权限控制

框架通过 `RBACEnforcer` 实现基于角色的访问控制，支持三级执行模式：

| 级别 | 说明 | 行为 |
|------|------|------|
| `strict` | 严格模式 | 违规直接阻止 |
| `recommended` | 推荐模式 | 违规警告但允许 |
| `optional` | 可选模式 | 仅记录不干预 |

### 10.5 审计日志

审计日志通过 `AuditLogger` 实现，具备以下安全特性：

- **链式哈希完整性验证**：每条日志包含前一条的哈希，防止篡改
- **防抖持久化**：批量写入，防止高频操作导致IO瓶颈
- **查询过滤**：支持按时间、操作类型、Agent等维度过滤
- **保留策略**：默认30天，可配置

### 10.6 MCP安全防护

MCP客户端内置多层安全防护：

| 防护层 | 说明 |
|--------|------|
| 命令白名单 | 仅允许 `npx`/`uvx`/`cargo`/`dotnet`/`pnpm`/`yarn`/`npm`/`python`/`python3` |
| 危险参数过滤 | 阻止 `-e`/`--eval`/`-c`/`--command` 等代码注入参数 |
| SSRF防护 | 黑名单+模式匹配+DNS重绑定检测 |
| 环境变量消毒 | 过滤 `LD_PRELOAD`/`NODE_OPTIONS` 等危险环境变量 |
| Buffer限制 | stdio最大1MB、HTTP请求/响应体大小限制 |
