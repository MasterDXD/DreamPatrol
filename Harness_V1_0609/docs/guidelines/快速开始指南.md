### 执行流程

```
需求探索 → 需求分析 → 架构设计 → 模块开发(TDD) → 集成测试 → 部署上线
```

### TDD铁律

**NO PRODUCTION CODE WITHOUT A FAILING TEST FIRST.**
- RED：写失败测试
- GREEN：写最小实现
- REFACTOR：优化代码

### 完成验证

声称"完成了"不算完成，提供证据才算完成。每项交付物都需要通过verification-before-completion验证。


### Q: 解压后.gitignore不显示？

macOS/Linux下点号开头的文件默认隐藏，使用 `ls -la` 查看。

将 `.harness/` 目录和 `CLAUDE.md` 复制到现有项目根目录，按需调整配置。

### Q: 支持哪些AI工具？

支持任何能读取项目文件并理解Markdown指令的AI工具，包括Claude Code、Trae IDE、Cursor等。

## 最近修复的重要问题

> 以下为近期优化轮次中修复的关键缺陷，涉及运行时稳定性、资源泄漏和安全加固。

### 深化子系统（Deepening）

| 模块 | 问题 | 修复内容 |
|------|------|---------|
| ConvergenceDetector | 调用签名不匹配 | 修正 `detect()` 调用参数，确保与接口定义一致 |
| DeepeningPipeline | 关闭时子模块未清理 | `shutdown()` 现在逐一关闭所有子模块，防止资源泄漏 |
| DeepeningOrchestrator | 关闭期间无守卫 | 添加 `isShuttingDown` 守卫，避免关闭过程中新任务进入 |
| IterativeRefinement | 输入对象被意外变异 | 深拷贝输入数据，防止迭代过程中原始数据被修改 |
| TokenAwareDeepening | 迭代无上限 | 增加迭代次数上限，防止Token预算耗尽时无限循环 |

### 工作流子系统（Workflow）

| 模块 | 问题 | 修复内容 |
|------|------|---------|
| GoalExecutor | `shutdown()` 未返回Promise | 修正为返回Promise，确保关闭流程可被正确等待 |
| PipelineExecutor | AbortSignal 内存泄漏 | 清理未使用的AbortController引用，避免内存泄漏 |
| WorkflowDAG | 边修改非原子操作 | `addEdge()`/`removeEdge()` 改为原子操作，防止并发修改导致状态不一致 |
| HookHandlers | `this` 上下文丢失 | 绑定正确的 `this` 上下文，确保处理器内可访问实例方法 |
| RateLimitManager | 关闭时无守卫 | 添加 `isShuttingDown` 守卫，防止关闭期间新请求进入 |

### 门禁子系统（Gate）
